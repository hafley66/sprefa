`v5/` is a reactive incremental datalog engine over code facts, built 2026-05-21 in one session out of despair over v4. ~1430 lines Rust, **SQLite welded in (no store trait)**. Facts extracted via `scan` + `regex`/`ast`(tree-sitter)/`sg`(ast-grep)/`json` into SQLite; recursive rules lower to a SQL fixpoint (INSERT-until-zero-rows); **file-keyed `_prov(rel,path)` source retraction**; content-hash + **mtime fast-path**; **rayon par_iter + literal prefilter**.

Measured on the Linux kernel at `~/projects/ext/linux` (36,677 .c files): cold 5s / **133 MB peak RSS**, warm 0.85s / 61 MB. printk bench = the v4 linux-bench equivalent. Bench harness in `v5/bench/`, examples in `v5/examples/`.

SCC-condensed `reaches` **WIRED + committed** on branch `feat/v5-dl-engine` (commit ff74e93, 2026-05-21). Surface: `reaches(a,b) <- closure(calls).` (explicit, no auto-detect). `reaches` is now a SQL VIEW over per-edge condensation tables `scc_node_<edge>(name,comp,cyclic)` + `scc_edge_<edge>(comp_src,comp_dst)`; `src/scc.rs` holds Tarjan+condensed reach (lifted from the proof bin). Parity: identical 6508-row closure vs old recursive form; derived 305ms→7ms. Also landed: stratification guard (a derived rule reading a closure relation in its body now errors — closures rebuild after the fixpoint) + batch retraction (once per relation, not per path×relation).

KEY FINDING (E6): the recursive-CTE VIEW **cannot seed point queries** — SQLite builds the whole component-closure first, then filters. Fine on the small (megablob) condensation, **>30s on a deep one**. So seeded point queries (LSP call-hierarchy) must use Rust `scc::reaches_from` (µs), not the view.

RESOLVED CALL GRAPH **landed** (commit b379fff): `ast(...)` gained an optional end-line binding; `examples/callgraph-resolved.dl` resolves calls by the range join `s<=l<=e` (call-site inside caller's body span; free+method+scoped call sites) instead of file co-occurrence. Megablob (1 SCC of 79) shattered into real structure (v4/src: 1128 fns, 841 comps, max SCC 268). Caveat: method calls resolve by NAME only (every `new()` aliases every `fn new`) — precise resolution needs type info.

SEEDED RUST POINT-QUERY **landed** (commit 0bf2001): `reaches(src="x", dst=?)` routes to `scc::reaches_from` over an in-memory condensation cache (build_cond_cache per tick) instead of the view. Verified identical to the view (v4 reaches(run)=603 both ways); per-query 86ms (view) → 12µs (seeded). dst-pinned/both-pinned/both-free still use the view.

STRATIFIER **landed** (commit 2e3015a): `stratify()` builds the predicate dependency graph over derived rules (edge head→body, negative for `!body`), SCCs it via `scc::tarjan`, rejects negation inside a recursive cycle ("unstratifiable"), else assigns strata (negative edge ⇒ strictly higher) and `rebuild_derived` runs one positive fixpoint per stratum in order. Fixes latent unsoundness: `unused(n) <- def(n), !calls(_,n)` was only right because `calls` was declared first; now order-independent. Positive recursion stays one stratum. The earlier one-rule closure guard (check_stratification) stays as a complementary check (closure heads compute in a later phase than all derived strata).
