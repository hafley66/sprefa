# v9 scope: keep the traits, drop the cruft, shrink sqlite_ivm

## Decisions (Chris, 2026-10-21)

| decision | meaning |
| --- | --- |
| comptime is runtime | the compiler is a long-lived server: it settles a program, then keeps listening (http, fs, git, timer) and applies events as signed rows on its own engine |
| the app emitter is parked | "shed the compiler into a third-party app" (codegen of a separate runtime) waits until comp-runtime is solid |
| dogfood ryi | every inventory and refactor step reads the code through ryi first; a ryi gap is fixed in ryi |

## Comptime server sketch (type sigs; bodies are comments)

```rust
/// One per process. Every phase settles on `engine`; nothing re-homes rows.
struct Server {
    universe: Universe,
    engine: Dd,                         // the one process engine (P1 macro lib, P2 macrotime, P3 stdlib, P4 program)
    executors: Vec<Box<dyn IService>>,  // Once and Continuing
    held: Held,                         // answer rows per holder count
}
impl Server {
    /// Source text in, signed rows out: read, macrotime waves, lower, check, comptime rounds,
    /// all as +1/-1 on `engine` (a re-save retracts the old unit's rows).
    fn compile(&mut self, unit: Source) -> Delta;
    /// An outside event (http request, fs change, git ref move, timer) as signed rows.
    fn event(&mut self, rows: Vec<SignedRow>) -> Delta;
    /// `next` rules move rows to the following tick.
    fn tick(&mut self) -> Delta;
    /// A client read: `dl8 query` asks the server; one-shot = compile, settle, read, exit.
    fn read(&self, relation: RelId) -> Vec<Row>;
}
```

Instance timelines, storage and the order of reads and writes come after the decisions above.

## Performance discipline

First-guess performance claims have been wrong in this project (`held` "explodes": refuted;
query shortcut: lost rows). So every v9 step lands with a committed probe and a budget:

| probe | today |
| --- | --- |
| 200k answer rows, one rule (`dl8 query`) | 6.3 s, 1.10 GB peak |
| same, three families | 11.7 s, 1.45 GB |
| per-phase live heap (`--features alloc-ledger`, `memory_mark`) | learnings 4 table |

A change reports before and after, three runs each, plus an output parity sweep over every
fixture and example program (`dl8 query`, stdout equal).
