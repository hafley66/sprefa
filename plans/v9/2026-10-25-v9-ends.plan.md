## The ends

```
front            middle (pure)           back (stream)        store (relational)
Rust builder --> check + stratify -----> Engine: Dd    <----> Store: Sqlite
  Program          Plan                    step(event)          replay, write, query
                                               |
runtime: Core { engine, store, dict, services }  <-- wire: HTTP from TypeSpec (generated)
```

| end | input | output | trait | the one impl |
| --- | --- | --- | --- | --- |
| front | Rust calls | `Program` (names) | none yet (a text front plugs in later and returns `Program`) | Rust builder fns |
| middle | `Program` | `Plan` (ids, strata) | none: pure functions | `check`, `stratify` |
| back | `Plan`, `Vec<Change>` per event | `Delta` per event | `Engine` | `Dd` (DD 0.25.1, timely 0.31.0) |
| store | `Delta`, fresh dict bytes | stored rows, SQL answers | `Store` | `Sqlite` (rusqlite, bundled) |
| runtime | commits, service answers | deltas, query tables | `IService` | `Ryi` (call edges) |
| wire | HTTP | runtime calls | generated from `v9/schema/*.tsp` | axum server via `@hafley66/alloy-rs` |

## Type sigs

```rust
// _2_ir.rs: the program as written. Names, not ids. The Rust builder is the front.
pub enum Col { Text, Int }
pub enum RelKind { Base, Derived, Request { service: String }, Answer { service: String } }
pub struct Rel { pub name: String, pub cols: Vec<(String, Col)>, pub kind: RelKind }
pub enum Term { Var(String), Text(String), Int(i64) }
pub struct Atom { pub rel: String, pub args: Vec<Term> }
pub enum Builtin { Add, Lt, Neq }          // add(a, b, out); lt(a, b); neq(a, b)
pub enum Goal { Pos(Atom), Neg(Atom), Call(Builtin, Vec<Term>) }
pub struct Rule { pub head: Atom, pub body: Vec<Goal> }
pub struct Program { pub rels: Vec<Rel>, pub rules: Vec<Rule> }
// builder, lisp-shaped: one Rust call per lisp form
//   (rel edge (from text) (to text))     -> rel("edge", [("from", Text), ("to", Text)])
//   (rule (reach a c) (edge a c))        -> rule(atom("reach", [v("a"), v("c")]), [pos("edge", [v("a"), v("c")])])
//   (not (blocked a))                    -> neg("blocked", [v("a")])
//   (add n 1 m)                          -> call(Add, [v("n"), int(1), v("m")])

// _3_plan.rs: checked program. Pure; the only effect-free bridge between front and back.
pub type RelId = u32;
pub type Value = u64;                      // Text: Dict id; Int: i64 bits
pub type Row = Vec<Value>;
pub enum PTerm { Var(u32), Const(Value) }  // Var = slot in the rule's binding row
pub struct Stratum { pub rels: Vec<RelId>, pub recursive: bool, pub rules: Vec<usize> }
pub struct Plan { pub program: Program, pub rels: Vec<PRel>, pub rules: Vec<PRule>, pub strata: Vec<Stratum>, pub hash: u64 }
pub fn check(program: Program, dict: &mut Dict) -> Result<Plan, Vec<Diag>>;
// checks: unknown rel, arity, a var's column type agrees everywhere, range restriction (head vars
// and every Neg/Call input bound by an earlier goal, in written order), no rules into Base or
// Answer, Answer cols = its Request cols ++ answer cols, negation inside an SCC.

// _4_recipe.rs: which impl of each end. Pure parse; the env read lives in _1_effects.rs.
pub struct Recipe { pub engine: EngineKind, pub store: StoreKind, pub wire: WireKind }
pub enum EngineKind { Dd }  pub enum StoreKind { Sqlite }  pub enum WireKind { Http }
impl Recipe {
    pub fn parse(text: &str) -> Result<Recipe, Diag>; // "engine=dd,store=sqlite" ; ',' or ';', trims,
        // lowercases; unknown key/value or duplicate key -> Diag naming the allowed set;
        // missing keys take the default
    pub fn canonical(&self) -> String;               // "engine=dd,store=sqlite,wire=http", sorted
}
// env var V9_SYSTEM; unset = default recipe. Same text -> same canonical -> same system.
// The store records canonical recipe + plan hash; reopening with a different one is Diag::Mismatch.

// _5_ends.rs: the traits. Each impl is selected by enum dispatch from the Recipe.
pub type Event = u64;
pub type Diff = isize;
pub struct Change { pub rel: RelId, pub row: Row, pub diff: Diff }
pub struct Delta { pub event: Event, pub changes: Vec<Change> }   // consolidated, sorted
pub struct Bounds { pub max_rounds: u32 }
pub trait Engine {
    /// Base and Answer row changes in; every relation's changes at this event out.
    /// Err leaves the engine as it was before the call.
    fn step(&mut self, input: Vec<Change>) -> Result<Delta, Diag>;
}
pub trait Store {
    /// Base and Answer rows stored, with the dict entries they use.
    fn replay(&mut self, dict: &mut Dict) -> Result<Vec<Change>, Diag>;
    /// One event's delta, one transaction, one statement per table and sign.
    fn write(&mut self, delta: &Delta, fresh: &[(u64, &[u8])]) -> Result<usize, Diag>;
    /// Read-only SQL over the relation tables and their `<rel>_text` views.
    fn query(&self, sql: &str) -> Result<Table, Diag>;
}
pub enum Cadence { Once, Continuing }
pub trait IService {
    fn service(&self) -> &str;
    fn cadence(&self) -> Cadence;
    /// Every request change of one event at once.
    fn call(&mut self, requests: &[Change], dict: &Dict);
    /// Answer rows ready now (Answer rel changes); never blocks.
    fn poll(&mut self, dict: &mut Dict, out: &mut Vec<Change>);
}
pub enum Diag { /* named variants: Unknown, Arity, Type, Unbound, NegationCycle, FixpointLimit, Mismatch, Store, Service, Recipe */ }

// _8_runtime: Core owns everything; one thread owns it (timely worker is not Send).
pub struct Core { engine: AnyEngine, store: AnyStore, dict: Dict, services: Vec<Box<dyn IService>>, event: Event }
pub fn build(recipe: &Recipe, program: Program, db: &Path) -> Result<Core, Diag>;
impl Core {
    pub fn commit(&mut self, changes: Vec<(String, Vec<Cell>, Diff)>) -> Result<Delta, Diag>;
    // step -> write -> route request changes to services -> poll -> step again, at most
    // MAX_SERVICE_ROUNDS times per commit
    pub fn query(&self, sql: &str) -> Result<Table, Diag>;
    pub fn tick(&mut self) -> Result<Option<Delta>, Diag>;  // poll Continuing services
}
```

## Instance timelines

| instance | created | lives until |
| --- | --- | --- |
| `Program` | user Rust code | `check` consumes it (kept inside `Plan`) |
| `Plan` | `check` | `Core` drop |
| `Dd` worker, dataflow, input session | `build` | `Core` drop; one dataflow per plan |
| `Sqlite` connection | `build` via `_1_effects::open_db` | `Core` drop |
| `Dict` | `build`, refilled by `Store::replay` | `Core` drop |
| service | `build`, one per Request rel's service name | `Core` drop |

## Storage, reads and writes

1. `build`: open db, create tables (one per relation, INTEGER columns, `WITHOUT ROWID` primary key
   over all columns; `dict(id, bytes)`; `meta(recipe, plan_hash)`), check meta.
2. `replay`: Base and Answer rows to the engine at event 1; the delta is not written (derived
   tables already hold it).
3. `commit`: `engine.step` -> `store.write(delta, dict.take_new())` in one transaction -> services.
4. Uniqueness: one row per (relation, columns) in SQLite; DD multiplicity is consolidated to set
   semantics at every derived relation (`distinct`), so a stored row has diff +1 or -1 only.
