## 1. What breaks if this is wrong

| failure | consequence |
|---|---|
| `due` fires for an endpoint whose `rate_state.remaining <= stop_threshold` before `reset` | token banned by GitHub secondary rate limit |
| `over_budget` never clears (seconds vs minutes bug, `ghcache.dl6:195-204`) | zero polls forever after one stop |
| a 304 carries bytes, or a poll re-sends without `If-None-Match` | quota burned on unchanged data |
| `X-Poll-Interval` ignored (`ghcache.dl6:338-343`) | events endpoint polled faster than GitHub allows |
| two calls per endpoint per bucket (`ghcache.dl6` property 5) | double quota spend, page walk races |
| 404 streak never cools (`ghcache.dl6:370-413`) | a deleted repo is hit every bucket until reset |
| a tick over 10s | CLAUDE.md 10-second law; measured live at 18-45s today |

- `page_prev_etag` and `call_log.cache_hit` (`:672-684`)
- the `/http/get` executor (`sprefa-engine-rs/src/executors/http.rs`): header encode, `DL_GITHUB_API_BASE`, `DL_HTTP_CONCURRENCY`
- retention `keep(count(16500))` on `call_log` (`:667`)

## 3. The seam

One seam, already there: `DL_GITHUB_API_BASE` (`http.rs:45-56`) points the whole transport at a local listener. The program, the executors, the clock, and the one db stay real. Nothing scripted in a schedule; the listener answers by rule, so the assertions are counts over `ghcache_call_log` and `ghcache_due` read back from SQLite, never a byte diff of a tick log.

Every case:
1. start listener with a scenario name
2. `dl6 run v6/dl/ghcache/ghcache.dl6 --root <tmp with ghcache.toml> --in-memory` under `timeout`, `poll_interval_seconds` small
3. after N clock buckets, read `--final-tsv` rows, assert counts

Clock buckets are minutes (`clock_granularity(60)`); a case needing 3 buckets runs 3 minutes wall unless `DL_CLOCK_GRANULARITY` exists. It does not today; see section 5.

## 4. Cases

| case | listener behaviour | expected (counts) | why this case exists |
|---|---|---|---|
| steady 304 | every GET answers 304, ETag echoed | per bucket: `call_log` rows == `poll_endpoint` rows; `sum(bytes) where status=304` == 0; `cache_hit`==1 on all | property 4 and 5 of the README header; the whole point of caching |
| one-call-per-bucket | count requests received per path per bucket | listener count == 1 for every path in every bucket | property 5; page walk must not double-ask |
| stop threshold | `x-ratelimit-remaining: 50`, `x-ratelimit-reset: now+180s` on bucket 1 | buckets 2-3: `due` rows == 0, listener receives 0 requests; bucket 4: `due` > 0 | `over_budget` (`:198`) is the ban guard; the minutes/seconds bug lived here |
| warn stretch | `remaining: 300` (between warn 500 and stop 100) | `endpoint_period` == ceil(poll*stretch/60) for every non-discovery endpoint; polls land only on multiples | `rate_warm` arm (`:345`) is the only candidate that lengthens under pressure |
| server poll interval | events path answers `X-Poll-Interval: 300` | that path's `endpoint_period` == 5; other paths unchanged | arm `:338` must only slow, never shorten (property 3) |
| 404 cooloff | one repo path answers 404 every time | after 3 misses, path absent from `due` for 60 buckets; other paths unaffected | `endpoint_cooling` (`:406`) isolates a dead repo |
| restart replays ETags | run 2 buckets, kill -9, run 1 bucket against same db (not `--in-memory`) | first bucket after restart: every stored `poll_state_tag` path answers 304, bytes 0 | property 4: transport holds nothing, db is the state |
| graphql budget | POST answers `x-ratelimit-remaining` decreasing by 100 | `rate_state('graphql')` == last header value; `due(api_type='graphql')` empty once <= stop | REST and GraphQL are separate pools (`api_tier` `:178-181`) |
| retention | listener answers fast, run until > 16500 `call_log` rows | `count(*)` == 16500 exactly | `keep(count(16500))` `:667`; the prune SQL is only grep-checked in `gate.sh` today |
| tick wall | steady 304 with 32 endpoints, `DL_HTTP_CONCURRENCY` default | every `engine_tick_cost.wall_ms` < 10000 | 10-second law; live today: 18-45s |
| live smoke (hafley66) | real api.github.com, 2 buckets | bucket 2: `status=304` count >= `poll_endpoint` count - graphql; `over_budget` == 0; `open_pr` > 0 | the only leg that proves auth, org discovery, and real header spelling |

## 5. Untested, and why

- checkout / mirror_pr_heads: needs a git remote; `ghcacher_checkout_golden` covers the sha gate on the hermetic seam
- notifications: `sync_notifications=0` in the live config; no listener scenario until the user wants that endpoint
- bucket length: every case waits real minutes. A `DL_CLOCK_GRANULARITY` env on `executors/clock.rs` would make the battery run in seconds; not built, and it changes `clock_granularity(60)` in the program, so it needs the user in the room
- byte-identical tick logs: deliberately out; the six `v6/dl/ghcacher` goldens keep that job

## 6. Mock listener, build-vs-buy

| candidate | in tree | verdict |
|---|---|---|
| `wiremock` 0.6 | no | scenario state via `Mock::up_to_n_times` and `Respond` trait; sequence-aware; async only (tokio, already a dep) |
| `httpmock` 0.7 | no | standalone server binary too, so a bash gate can run it without Rust test glue; `Then::header` covers rate headers |
| `axum` | yes (`Cargo.lock:191`) | already linked for `serve`; a 60-line router with a `Mutex<Scenario>` counts requests per path per bucket; zero new deps |
| hand `TcpListener` | n/a | rejected: header parsing is the thing under test |

Pick `axum` unless the per-path request counting wants `httpmock`'s `hits()`; decide at implementation.
