# docs-from-comments recon: reference docs generated from repo comment nodes

## Context

Read-only reconnaissance. Scope is ONE dl6 program that joins (a) `surface/5`
construct rows from the registry, (b) comment nodes extracted from the corpus,
(c) golden examples, and emits per-construct reference markdown through a host
template. Zero implementation, zero fixture edits, zero decisions on user
forks. This document names the receipts and states the open question; the
visual twin (`2026-08-10-docs-from-comments.PLAN.visual.human.unga.md`) carries
the same result without citations.

The SYNTAX.md surface table is already generated by a Prolog one-shot that is
NOT a dl6 rail and does NOT read comments: `1_emit_registry_docs.pl` reads
`registry.pl`'s `surface/5` and `cli_command/3` and regenerates the section
between `BEGIN/END generated surface/5 table` markers in place
(`v6/prolog/compile/1_emit_registry_docs.pl:18-38`, `:205-223`, `:244-252`).
Any new docs rail must not duplicate that: the reference-docs rail is per-construct
prose + worked example, orthogonal to the flat signature table.

The comment-node verdict rules the shape this rail must reuse: route (b2) for
the grammar fact plus route (c) for the marker hit plus an in-language join
(`plans/2026-07-29-comment-node-verdict.md:46-57`), the 57 text-operation call
sites moved into host templates with zero in-language text ops
(`:16-21`), and per-marker sh-host marker capture
(SLOT-MARKER-CAPTURE, `:134-167`, `:366`).

## Decisions

1. ATTACHMENT: use a marker convention captured by a per-marker sh host,
   joined to `surface/5` by construct name/arity; do NOT use preceding-decl
   span attachment. Rationale and fork in section 1.
2. SOURCES: dl6, Rust and prolog all ship in phase 1. Prolog is extractable
   with the existing extractor. A14 is NOT forced by this rail; present as a
   fork only (section 2).
3. JOIN SHAPE: three-way join keyed on construct signature (name/arity),
   `surface/5` row joined to a grammar-witnessed marker capture joined to a
   golden-flex example row (section 3).
4. RENDER: devlog.dl6 is the closest existing rail to copy (ordinal +
   group_concat fold + write host); self-map.dl6 is the fallback (section 4).
5. GATE: checked-in artifact with the SYNTAX.md marker-section pattern, plus
   byte-idempotency and sabotage receipts (section 5).

Rejected alternatives: porting the SYNTAX.md Prolog generation to dl6 (it is
not a rail and reads no comments); a preceding-decl span attachment (invites
the A14 trailing ambiguity and cannot reliably name the construct); extending
the extractor to tokenize doc markers in Rust (refused by the
`std/suppress.dl` policy law restated in the verdict `:162-167`).

## 1. ATTACHMENT

Question: which comment-node technique binds a comment run to the construct it
documents: preceding-decl, section-header, or marker?

The lab's technique inventory gives three marker-based techniques, all graded
or ported by the verdict (`plans/2026-07-29-comment-node-verdict.md:338-348`):

| technique | capture | grammar witness | v6 home |
|---|---|---|---|
| 3 README(anchor) | anchor + prose | `readme_note(...) <- readme_text(...), comment_node(...)` | `v6/dl/fixtures/comment-readme-rail.dl6:18-19` |
| 4 LANG-JUNCTION(slug) | slug + meaning | same join shape | `v6/dl/fixtures/comment-lang-junction-rail.dl6:18-19` |
| 1 ARCH JSON markers | payload + hierarchy | same join shape | verdict `:238-240` |

None of the seven attaches a comment to the NEXT declaration. Marker capture is
the only one whose attachment can NAME the construct: the marker body carries
the construct signature, which is the join key to `surface/5`.

Preceding-decl is rejected: golden-flex's own construct-naming comments do not
sit immediately above the named decl (the `norm/1` narrative is in the header,
`v6/dl/fixtures/golden-flex.dl6:118-135`, while the citing rule is
`display_key` at `:337-338`). A span-based "comment above the decl" join also
re-opens the trailing-comment question (section 2). Section-header is useful as
a GROUPING wrapper, not an attachment: golden-flex's `═══` headers partition
constructs into domains (value plane, json axis, shell host, level rules,
aggregate heads, edge rules, `v6/dl/fixtures/golden-flex.dl6:173,192,277,288,355,398`).

Recommendation: a `LANG-JUNCTION`-style `docs:` marker convention in the
comment body, captured by the per-marker sh host (SLOT-MARKER-CAPTURE answer
(a), `plans/2026-07-29-comment-node-verdict.md:365`), carrying the construct
signature, joined to `comment_node` for the grammar witness. This needs zero
new constructs and reuses the graded technique-4 shape
(`v6/dl/fixtures/comment-lang-junction-rail.dl6`).

USER FORK (state, do not decide): whether to author `docs:` markers into
golden-flex.dl6 (a fixture edit) or match the existing loose prose signatures
in a host. The former is exact but edits the golden; the latter reads the
existing corpus with no edit but needs the host to tolerate prose drift. The
plan below assumes a marker but does not choose which source carries it.

## 2. SOURCES

dl6 `#` comments (the fixtures) and Rust are proven by the verdict's parity run
(`plans/2026-07-29-comment-node-verdict.md:313-316`, 745/745 on Rust). Markdown
is the one real extractor hole (SLOT-EXTRACTOR-WAIVER,
`plans/2026-07-29-comment-node-verdict.md:364`), irrelevant here because the
docs sources are code files.

Prolog % comments ARE extractable with the existing extractor. No phase-1
scope-down is needed. Two receipts:

- `v6/sprefa-extract/src/lang/mod.rs:12` and `:36-44` register `PrologSource`
  in `sources()`; `v6/sprefa-extract/src/lang/prolog/_0_source.rs:666-669`
  matches `.pl`/`.pro`/`.prolog`, parses with `tree-sitter-prolog`
  (`_0_source.rs:19-23`), and `project_cst` (`_0_source.rs:116-142`) walks every
  named node, so `--family cst` over a `.pl` file emits `comment` nodes.
- The verdict's dogfood corpus was `v6/prolog/**/*.pl` itself; receipt-scale
  landed 5,939 comment rows through the served engine
  (`plans/2026-07-29-comment-node-verdict.md:350-356`). The verdict names prolog
  a v6-only capability (`:351-356`), meaning there is no v5 leg to grade, not
  that prolog is out of scope.

A14, the open question: does a comment span/bind see TRAILING comments
(`code(); // note`), which would collapse v5's two waiver rules into one?
`plans/2026-07-29-hosts-extraction-verdict.md:447` records it open, gated on
`slot_comment_span_trailing_bind`; `plans/2026-07-27-extraction-spellings.md:536-539`
states the behavior claim a bind would have to deliver.

Does this rail FORCE a decision? No. Doc comments are leading by convention in
every source the rail reads: golden-flex `#` blocks lead their rel/rule
(`v6/dl/fixtures/golden-flex.dl6:311-314` precedes `heirloom` at `:314`), rust
`///` leads, prolog `%` leads. Whether a trailing comment belongs to the span
never changes WHICH comment documents a construct when attachment is
marker- or preceding-decl on the leading side. So A14 stays open. If a future
rail ever attached by trailing span, that is the fork; this rail does not take it.

## 3. JOIN SHAPE

Three-way join, keyed on construct signature (name/arity). Each construct cited
is a live `registry.pl` row (`v6/prolog/compile/registry.pl:70,84,159,171-177,197`).

Registry row -> construct rel (surface/5 read today, self-map.dl6:170-173;
host shape self-map.dl6:94-96):

```
sh sm_surface(path: text, digest: text)
  -> (record: text, functor: text, arity: text, axis: text, status: text) =
  `: {digest}; swipl -q -l "$SELF_MAP_FACTS" -g main -t halt -- {path}`.

rel construct(functor: text, arity: text, axis: text, status: text).
construct(functor, arity, axis, status) <-
  source(path, digest), sm_surface(path, digest, 'surface', functor, arity, axis, status).
```

Comment fact (route b2 host, comment-readme-rail.dl6:8-11):

```
sh comment_fact(path: text, digest: text) -> (line: int, kind: text, comment_text: text) =
  `: {digest}; "$DL_EXTRACT_BIN" --family cst {path} | python3 "$DL_COMMENT_NODE" comments {path}`.

rel comment_node(path: text, digest: text, line: int, kind: text, comment_text: text).
comment_node(path, digest, line, kind, comment_text) <-
  file(path, digest), comment_fact(path, digest, line, kind, comment_text).
```

Marker capture -> grammar witness (SLOT-MARKER-CAPTURE (a) + the verdict's
suppressed shape, `plans/2026-07-29-comment-node-verdict.md:52-56`):

```
sh doc_marker(path: text, digest: text)
  -> (line: int, name: text, arity: int, doc_text: text) =
  `: {digest}; python3 "$DL_POLICY_MARKERS" docs {path}`.

rel doc_note(path: text, line: int, name: text, arity: int, doc_text: text).
doc_note(path, line, name, arity, doc_text) <-
  doc_marker(path, line, name, arity, doc_text),
  comment_node(path, digest, line, kind, comment_text).
```

The decision row: registry signature joined to the witnessed note. `arity` is
the int identity both sides already carry; the join is an equality on (name,
arity):

```
rel doc_source(name: text, arity: int, axis: text, status: text, doc_text: text).
doc_source(name, arity, axis, status, doc_text) <-
  construct(name, arity, axis, status),
  doc_note(path, line, name, arity, doc_text).
```

Golden example: the worked code. golden-flex is parsed as a source that reads
itself (the self-map precedent reads this file's own rel graph,
self-map.dl6:15-18,110-116). The example row is the golden-flex rule/rel
falling in the same section as the witnessed note, tagged by name:

```
rel golden_cst(path: text, line: int, code_text: text).
golden_cst(path, line, code_text) <-
  source(path, digest),
  cst_fact(path, digest, line, kind, code_text), kind == 'rel'.
```

The full three-way join assembles the per-construct source row:

```
rel ref_row(name: text, arity: int, axis: text, status: text,
            doc_text: text, example_text: text).
ref_row(name, arity, axis, status, prose, example) <-
  doc_source(name, arity, axis, status, prose),
  golden_cst(path, example_line, example),
  section_covers(path, example_line, name).
```

`section_covers/3` (a comment run/region that binds a construct to its section,
reusing the run-boundary coalescing of `v6/tsv2/goldens/comment_rail_golden/0_comment_rail_golden.dl6:205-232`)
is the one join whose exact spelling depends on the ATTACHMENT fork (section 1).
Every construct used compiles against the shipped registry: `sh`, `rel`,
`source`, `comment_node`, `group_concat` (`v6/prolog/compile/registry.pl:173-174`),
`coalesce` (`:70`), `not/1` (level-body antijoin, golden-flex.dl6:297-303).

## 4. RENDER

The 57-sites finding means all text assembly lives in the host template or the
render plane (verdict `:16-21`). The closest existing rail to copy is
`v6/dl/fixtures/devlog.dl6`: a ledger host emits rows
(`devlog.dl6:26-28`), decode/spread fans out (`devlog.dl6:52-53`), rules build
`devlog_line(ordinal, line)` rows (`devlog.dl6:139-193`), the document is one
`group_concat(..., '\n', ordinal)` fold (`devlog.dl6:195-196`), and the sole
output effect is a `write_devlog` host writing DEVLOG.md (`devlog.dl6:198-202`).

self-map.dl6 is the fallback and adds one thing devlog lacks that reference
docs want: per-section map_line folds and a `write_arch_map` host writing a
checked-in file (`self-map.dl6:692-700`, `:702-707`; the Mermaid text plane
`self-map.dl6:303-433` is not needed for prose reference docs).

Recommendation: copy devlog.dl6's structure, add self-map.dl6's per-section
`map_line`/fold/checked-in-write pattern. The render plane is:

```
rel ref_line(section: text, ordinal: int, line_text: text).
rel section_text(section: text, text: text).
section_text(section, group_concat(line_text, '\n', ordinal)) <-
  ref_line(section, ordinal, line_text).
rel ref_doc(document: text).
ref_doc(document) <- section_text('registry', body),
  document := concat([body, '\n']).
```

## 5. GATE

Generated docs become a checked-in artifact with a working rail. Two patterns
exist and both are the answer at different granularity:

- SYNTAX.md marker-section pattern: the generated region sits between
  `BEGIN/END generated` markers and is regenerated in place, hand-owned prose
  preserved outside (`1_emit_registry_docs.pl:18-38`, `:244-252`). SYNTAX.md is
  git-tracked.
- self-map whole-file pattern: the entire doc is generated and must be
  byte-stable; a staleness gate diffs committed vs regenerated, and sabotage
  receipts prove the rail discriminates (`self-map.sh` determinism + sabotage,
  `v6/tsv2/scripts/self-map.sh:24-58`).

Recommendation: whole-file regenerate-and-byte-diff per the self-map precedent,
with the SYNTAX.md marker-section only if a human-owned header must survive
regeneration. Gate = run the rail's one-shot, `git diff --exit-code` on the
doc; failure means stale. Add the sabotage receipts (a fake `surface/5` row,
a renamed golden-flex construct) so the rail flips red on drift, per
`self-map.sh:24-58`.

## Verification

1. The reference doc's generated section for a construct byte-matches a
   hand-expected inline snippet for three chosen constructs (one sugar, one
   guard, one aggregate).
2. `git diff --exit-code` on the doc after a second run: byte-identical
   (idempotency).
3. Sabotage: append a fake `surface/5` row -> the doc changes; revert -> the
   doc returns byte-identical (self-map precedent).
4. A14 remains open and un-decided; the rail runs without a trailing-span
   bind.
5. No fixture edits: the rail reads golden-flex and the corpus read-only.
