## 1. What v2 was

The pitch never changed from v1:

> You touch 30 repos a week. You `cd` into one, grep for a string, find it references something in another repo, `cd` there, grep again... That loop eats hours every day.

v1, the fifteen crates at the repo root, answered as a batch indexer: `sprefa scan` walked every repo with rayon and bulk-flushed rows into SQLite for `sprefa sql` to join. The root `CLAUDE.md` puts the split plainly: `crates/` is the v1 system, "Still functional but not where new features land." v2 kept the store and threw away the control flow. Where v1 had a monolithic lowering pass and an analyzer that guessed at errors, v2 made the op the unit of everything: it owns its parser, diagnostics, hover, completions and effects, and the framework only holds `Arc<dyn Op>`. `README.goals.md` calls the result a cursor pipeline "that happens to write SQL rows, issue shell effects, and rewrite code". NOTES.md: "The store is the thing." The payoff was an editor: v2 opened with LSP foundations on day one and closed with a daemon serving `/run` over SSE and `/lsp` over WebSocket.

## 2. The language

Files end in `.sprf`. A file is semicolon-terminated statements; a statement is ops chained with `>`; braces fork into arms that union; `$NAME` binds a capture and becomes a column. The file stem is the namespace: `infra.sprf` writes `infra__image_data`.

A rule over a git tree, `v2/examples/g1_fns.sprf`:

```sprf
rule(pub_fn) {
  > repo($R) > rev($V) > fs(**/*.rs)
    > ast[rust](pub fn $NAME($$$ARGS) { $$$BODY })
};
```

A scan pointer, from `v2/tests/scan_pointer_runtime.rs`. `$$repo(...)` claims the matched string names a repo; the checker later confirms it or warns:

```sprf
rule(svc) {
  > repo(consumer) > rev(main) > fs(**/services.yaml)
    > json({ image: { repository: $$repo($R) }, name: $NAME })
};
```

Dogfooding, from `self_check.sprf`, which held the README to the code:

```sprf
rule(lsp_tag) {
  fs(crates/sprf-lsp/src/main.rs) > ast[rust](("$TAG", $$$_))
};

rule(readme_tag) {
  fs(**/README.md) > md(### Selector tags) > line(re:`$TAG\()
};
```

Three pattern systems shared one matcher: `$` segment captures that stop at separators, `re:` regex with `$NAME` rewritten to a named group, and plain globs. `&.$X` desugared to `cursor_ref(.$X)` and rebased the cursor onto a captured value, so a string field could be parsed as its own document. `check(name) { SELECT ... }`, the second statement type, returned violation rows and exit code 1, and stayed v1-only.

## 3. The engine

One crate, five binaries: tokio streams outside, git2 and tree-sitter and ast-grep-core underneath, sqlx over SQLite behind.

```d2
direction: down

source: ".sprf source" { shape: page }
parse: "host_parse\n_8_parse.rs"
lower: "Operator::parse\nper-op lowering"
tree: "Pipeline tree\nOp | Seq | Fork | Switch"
run: "Pipeline::run\nBoxStream<Arc<[Cursor]>>"

ops: "ops/" {
  drivers: "repo  rev  fs"
  content: "json  md  ast  line  marker"
  rebase: "cursor_ref  &.CAPTURE rebase"
}

readers: "readers/ 3-layer stack" {
  git: "GitBlobReader (git2)"
  wt: "worktree + path index"
  buf: "buffer overlay + parse cache"
}

store: "SqliteStore\nper-rule _data table + views"
demand: "scan-check demand loop\nClaimed -> Verified | Missing"

out: "consumers" {
  cli: "sprefa CLI"
  lsp: "DocSession\nhover / completion"
  srv: "sprefa-server\n/run SSE  /lsp WS"
}

source -> parse -> lower -> tree -> run
run -> ops
ops -> readers: bytes
run -> store: rows
store -> demand
demand -> run: grow config, re-run
run -> out
```

Storage kept v1's layout: repos, revs, files and interned strings as a backbone, plus one `_data` table per rule where each capture becomes twin `{col}_ref` and `{col}_str` columns under a view. Scan-pointer captures got three more, so cross-repo joins had real foreign keys.

Evaluation was a fixpoint over configuration. Walker ops stamped content-side captures `Claimed`; the checker flipped them to `Verified` or `Missing` against the known repo and rev sets; the demand loop fed the missing values back into the config and re-ran every pipeline until the config stopped growing, with no incremental view maintenance anywhere. Incrementality lived one layer down: a content-hash skip set, a parse cache keyed by blob oid, a string interner, and a SQLite path index over provisioned worktrees.

Three files carry the design. `v2/src/_5_op.rs`: Op trait, Pipeline enum, OpCtx. `v2/src/_8_parse.rs`: the tolerant host parser shared by LSP and CLI. `v2/src/analysis.rs`: DocSession, the span index that turns a cursor run into hover and completion.

## 5. Why it ended

Feature work stopped on 2026-04-17. Of the last fifteen commits, nine are perf and two are docs about perf: rayon on ast and fs ops, parallel exprs, a blob-oid fast path, a parse cache, a string interner, a worktree path index to kill a 14-second filesystem wall, a chrome-trace span log, a file-size cap.

The last two share a timestamp, 00:04 on 2026-04-18: a bench over four reader shapes and three parse shapes on swc, then a rewrite of `v2/CLAUDE.md` whose message is the verdict:

> CLAUDE.md was a LAWS-OF-MIN manifesto with trait-design theorizing on top of a Reader/Store N+1 diagnosis that the bench only partially confirms.

What replaced it:

> A loop of N iterations should do O(1) expensive work, not O(N).
>
> biome, ripgrep, swc, ast-grep all use rayon work-stealing, not tokio, on the scan hot path.

v2 was tokio streams end to end, with `join_all` over per-file futures and a `Mutex<git2::Repository>` in the inner loop. The bench priced that shape at 3x. Fixing it meant moving the seam, and the seam was the Op trait. BOARD.md at the pin is thirteen lines, every one a v1 leftover.

Two days later, v3 landed as a new top-level workspace:

| commit | date | subject |
|---|---|---|
| `620c466a4` | 2026-04-20 | feat(v3): land effect-runtime crate + three-domain bench suite |
| `0cce4e57e` | 2026-04-20 | docs(v3): restore session doc for perf+plugin synthesis |
| `8e45c7874` | 2026-04-20 | feat(v3): cancellation + ArcSwap registry + PureEffect cache layer |
| `e9d78851a` | 2026-04-20 | feat(v3): rxRust adapter + oxc parse bench over DefinitelyTyped |
| `520f9b956` | 2026-04-20 | v3 is cookin |

That commit is a ~600 line framework core plus three benchmark domains, measured on the linux kernel: 63,482 files, 1.34 GB. It found a 6x lever v2 never had: ast-grep's fixed-string prefilter, 20.7s down to 3.64s. v2 ended because the bench said the runtime shape was wrong, and changing the shape was cheaper in a new workspace beside it.
