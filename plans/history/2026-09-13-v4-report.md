## 1. What v4 was trying to be

You called it "Prime time" in `human-goals.md`: "master 2 queue system, pure render and effects and pausing, unlock lsp workflows, unlock userland sprf string node querying woith ast-grep ops, fully understand lang lowering and runtime semantics." MAIN.md opened with the five-line mental model: everything is a tree, a cursor, two queues, layered, dogfoodable. The change from v3 was structural. v3's `server` crate had grown to 5425 lines with a 2166-line `backend.rs`, and the evolution log names the move plainly: "v2 had the right shape (thin CLI + daemon + stdin/stdout proxy); v3 merged the daemon into a monolithic server. v4 recovers v2's clarity." So v4 kept v3's effect runtime and tree-sitter host grammar, deleted the old `Op` trait and the parallel `MutationStore`, pulled the nested-DSL parser out as a standalone `cst` library, renamed tag to fact, and pointed everything at one `FactStore` whose row `_id` is the blake3 of its own fields. MAIN.md's four layers: DSLs, pipe ops, facts and rules, generations and diff, cross-layer composition rejected at lower time.

## 2. The language

Files ended in `.sprf`. A program declared relations with `rule(:name, COL?, ...)`, then wrote pipes read left to right: source, pattern DSLs in backticks, relation write, optional effect. `TERM?` bound a term, bare `TERM` read one, `${TERM}` spliced it into a string, `?` after a relation name read it back, `not(...)` was the anti-join.

```
# v4/examples/dev-rust-panic-map.sprf
rule(:panic_sites, FS?, LO?, HI?);

fs
  > glob`**/*.rs`
  > read
  > ast(:rs)`panic!($$$ARGS)`
  > panic_sites(FS, LO, HI)
  > lsp_warn(:panic_site)`panic! call at ${FS}:${LO}`;
```

```
# v4/examples/json-extract.sprf
rule(:people, NAME?, AGE?);

`{"name":"ada","age":37}`
  > json`{ name: $NAME, age: $AGE }`
  > people(NAME, AGE);
```

```
# v4/examples/rule-sink-fact.sprf
rule(:words, WORD?);
rule(:echo_words, WORD?);

`alpha beta`
  > split(WORD?)` `
  > words(WORD);

words?(WORD?)
  > echo_words(WORD);
```

Ops at the pin: `fs repo rev path read glob re ast ast_yaml json comment split term term_bind where not sh sh! rule fact render render_markdown collect write_file write_cursor print void`, plus `lsp_error / lsp_warn / lsp_info / lsp_hint / lsp_hover`.

## 3. The engine

One Rust crate, `v4/`, three helper crates beside it, v3's `effect_runtime` still linked by path. Storage was SQLite behind a `FactStore` trait; four days before the pin the default became an in-memory SQLite connection (`7b58db963`).

Evaluation had two doors, chosen per rule body by `compile/fuser.rs`. If every step was pure or a relation read, the body compiled to one fused `INSERT ... SELECT`, joins and `NOT EXISTS` included. If any step streamed bytes, it ran as `effect_runtime` Components over cursor batches. Recursion looped fused SQL to quiescence under a hard round cap, strata ordered so a negated relation finished before its complement was read. Incrementality was real but partial: rows carried SUPPORT triples per derivation witness, DRed retraction dropped conclusions whose reason was gone, and recursive closures recomputed per run by default.

Open three files: `src/compile/fuser.rs`, `src/fixpoint.rs` with `src/stratify.rs`, `src/runtime_graph.rs`.

```d2
direction: down

src: ".sprf source" {shape: document}

parse: "front end" {
  ts: "tree-sitter-sprefa\nhost grammar"
  cst: "cst/ nested DSL zones\nre  glob  json  ast  comment"
  walk: "compile/walk.rs\nbinding graph + stratify"
}

fuse: "compile/fuser.rs\nclassify every step" {shape: hexagon}

react: "reactor" {
  memo: "memo.rs\nMEMO_DEPS content memo"
  rg: "runtime_graph.rs\nmounted queries, wake keys"
  watch: "git_watch.rs / ghcache\ndirty sources"
}

out: "sinks" {
  cli: "sprefa-run rows"
  lsp: "LSP diagnostics + hovers"

}

src -> parse.ts -> parse.cst -> parse.walk -> fuse
fuse -> sqlpath: "all steps pure"

react.watch -> react.rg -> react.memo -> fuse: "re-run only dirty owners"
```

## 4. What it could do by the end

61 test files, 43 `.sprf` examples, a VS Code extension, an LSP binary, a daemon. The recursion milestone in `v4/docs/README.md` says what had just landed then: "you can write transitive closure / reachability / a reactive state machine directly in `.sprf`, run it against a persistent `--fact-db`, edit the source, re-run, and the answer re-converges." Cycle detection became a query shape, `reaches?(N?, N)`. That doc's framing: "sprf stopped being 'match + project' and became a recursive deductive query language."

## 5. Why it ended

The last 15 commits are a language finishing itself: `not(rule?(args))` emitting `NOT EXISTS` in fused SQL, a tier-0 audit sweep, the in-memory SQLite default, two N+1 fixes with budget tests, then the docs commit that closed the day. Nothing there reads like a project about to stop.



What stopped it sits in the perf file and the next day's chat log. Retraction made the incremental run 2.57x slower than the cold run: the memo keyed at the rule-graph layer while the scan re-walked the whole tree anyway. The v5 session measured the rest, recursive `reaches` at 197 seconds, the entire cost of a tick. Your words in that log: v4 was "over-built, unreadable", the "effect_runtime / cons-as-op / callable-as-value sprawl", and it "grew past what one person could hold in their head". The fix you named was to melt it into something small and comprehensible, and what paid for the rewrite was SCC condensation turning those 197 seconds into 1.4ms.

v5 landed the next day as one commit, `42b8f1348`, "reactive datalog-over-code engine + SCC-condensed reaches proof": about 1430 lines of Rust, SQLite welded in with no store trait, the Linux kernel in 5s cold and 0.85s warm at 133 MB peak. The four after it wired SCC into the engine, resolved calls by body-span range join, seeded `reaches_from`, stratified derived rules.

## 6. What survived

- The model: relations, rules, stratified negation, recursion to a fixpoint, retraction keyed by source file. v4's SUPPORT triples became v5's `_prov`, and that line runs to today.
- SQLite as the store, rows keyed by a content hash.
- The extractors: regex, tree-sitter, ast-grep, JSON dotpath, still how facts get made in v5 and v6.
- The Linux kernel as the bench, peak RSS as the number that matters.
- The LSP ambition, still unfinished in v6.
- Gone: `.sprf` pipe syntax, cursors, the effect runtime, the two-queue render/flush model, the VS Code extension. v5 opened with `rel` declarations and `head <- body`; v6 and v7 still spell it that way.
- Unknown here: whether any `cst` DSL code reached v5's parser.
