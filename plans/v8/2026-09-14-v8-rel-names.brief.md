## 1. Job
`dl8 compile` prints a `program` object that `dl8 eval` reads without any test-side rebuilding: rules, seeds, and a `names` map from declared relation name to relation ref. The SQLite store names a served or declared relation's table by its declared name. The two test helpers that today rebuild that object by hand are deleted in favour of the library function.

## 5. Design (decided)
Type signatures first.
```rust
// v8/src/_6_eval/_6_json.rs
/// The runtime program as `dl8 eval` reads it: `{"rules", "seeds", "names"}`.
/// `names` maps every relation declared by name in the root graph to its ref.
pub fn program_to_json(u: &Universe, checked_datalog: TermId) -> Result<Value, String>;
//   walk root_graph edges (: (module M) Name (ref R) _) exactly as the test's module_names does;
//   rules and seeds come from datalog_program args 1 and 2 through the existing rule/call JSON writers.

// v8/src/lib.rs, struct Compile gains nothing; compile_cli adds one key:
//   out.insert("program", program_to_json(&u, compiled.runtime_program)?)
//   absent (null) when runtime_program is the empty list (a failed compile).

// v8/src/_9_runtime/_1_sqlite.rs
/// Table for one relation: its declared name when the program carries one,
/// else `rel{id}_a{arity}`. Names are validated: [A-Za-z_][A-Za-z0-9_.]* and quoted.
fn table_for(&self, rel: TermId, arity: usize) -> String;
//   names arrive through IRowStore::open(program, names: &HashMap<String, TermId>)
//   and are written into the relation dictionary table as a `name TEXT` column, UNIQUE.
```
- `dl8 eval` accepts EITHER the bare program object OR the full compile output (it already does `value.get("program").unwrap_or(&value)`); keep that, and the tests stop rebuilding.
- The four test helpers named in section 4 are deleted; each test passes the compile output file straight to `dl8 eval`.
- Instance lifetime: the names map lives in `SqliteRowStore` for the process, set once at `open`.
- Storage: `relation` dictionary gains `name TEXT UNIQUE NULL`. Row tables keyed as today. No composite TEXT keys (`.claude/skills/sql-relational-design`).
- Reads and writes: `open` upserts dictionary rows by id, sets name where known; `commit_rows` resolves table names through `table_for` once per relation per tick, never per row.
- Uniqueness: two relations with the same declared name in one program is a `Diagnostic` `duplicate_relation_name`, returned from `program_to_json`, exit 1.
