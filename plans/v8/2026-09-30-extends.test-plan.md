# Test plan: `Extends` / `ExtendsAll` (structural check, returns the source)

Shape under test (user 2026-09-30: "doesnt extends return the type if it succeeds"):

```
(Extends:
   (* (source: type)
      (contract: type)
      (return: type)))

(<- (Extends ?Source ?Contract ?Source)
    ...
    (not (missing_field ?Source ?Contract)))
```

## What breaks if wrong

- A type passes a contract it does not meet: user code (`fixtures/extract/main.dl7:16`,
  `fixtures/openapi/todo.dl7:20`, `tsi_project/0_contract.dl7:14`) accepts bad input.
- A valid type fails: codegen drops a real implementation.
- Every product is checked against every contract: quadratic comptime. Only asked pairs
  may be checked.
- Engines disagree: the IR and sqlite paths ship different answers from rust.

## Units under test

`missing_field`, `Extends`, `ExtendsAll` prelude rules; kernel demand (which pairs get
checked); all five engines (rust, dd, sqlite, ir:dd, ir:sqlite).

## Cases

Declarations used below:

```
(Named:
   (* (name: str)))

(Aged:
   (* (age: int)))

(User:
   (* (name: str)
      (age: int)))
```

## Untested, and why

- Sums as source or contract (`A | B extends C`): not designed. TS distributes over unions,
  Go has no unions. Needs a user decision before a test can say what is right.
- Case 9 has two answers until the user picks invariant (Go) or covariant (TS) fields.
- Method-like members (functions as fields): dl7 has no function-typed columns yet.
