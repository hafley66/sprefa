# Brief: make comptime on ir:sqlite fast

Base: local main `9abdf5e33`. ir:sqlite is the default engine and the only comptime path.

## Numbers today

| measure | old Rust evaluator | ir:dd | ir:sqlite |
|---|---|---|---|
| `dl8 build std/tsi_registry_emit.dl7` | 0.16 s | 5.5 s | 7.7 s |
| full suite | 203 s | 319 s | 479-496 s |

## Goal

`dl8 build std/tsi_registry_emit.dl7` under 1 s on ir:sqlite and ir:dd, byte-identical output
(`cmp` against `~/projects/hafley-rs/crates/hafley_scm/src/read/tsi/registry.rs`). Full suite on
ir:sqlite under 250 s.

## Method

1. Measure before guessing: `hafley-observe` spans exist (`settle spans`, `ir install install_ns`);
   use them, `RUST_LOG`, or `samply`/`cargo flamegraph` if installed. Write the top 10 costs with
   numbers to `plans/v8/2026-10-02-ir-speed.findings.md` before changing code.
2. Fix the largest costs first. Candidates seen so far, unverified: per-round reinstall, per-effect
   settle rounds, term dictionary round-trips (dl8 Universe <-> engine dictionary), the
   `doc.join` fold copying the accumulator (O(n^2)), SQLite statement count per settle.
3. Make all edits, `cargo check -j 4` while editing, then test once; re-run failures by name; final
   full run per engine.

## Laws

- One cargo process at a time. `uptime` first; wait if load > 12. `-j 4`. `--test-threads=1`.
- `sqlite_ivm` is a gitignored symlink: `ln -s /Users/chrishafley/projects/sqlite_ivm sqlite_ivm`.
  If sqlite_ivm needs changes: clone it inside your worktree
  (`git clone /Users/chrishafley/projects/sqlite_ivm .boop-worktrees/sqlite_ivm`), branch
  `perf/comptime`, point the symlink at the clone, report the branch.
- No new kernel relation without stopping to report with dl7 examples. No language change.
- No recursion added. No eager string structure. No silent fallbacks. No `json_*(` SQL.
- Plain `cargo`. No book edits. Never `git commit -n`. No merge, no push.
- Goldens only via `oracle/refreeze.py` and the regen script.
- Scoped green commits. End messages with
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
