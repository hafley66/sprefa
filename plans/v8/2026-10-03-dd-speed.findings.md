## Inside ir:dd (temporary `ivm_dd` debug spans: operators, build ns, settle ns, epochs, steps)

| call | IR nodes | timely operators | install ms | settles (ms) |
|---|---|---|---|---|
| macro library compile (comptime of `macrotime/`) | 1072 | 8679 | 91-96 | 23 |
| unit expansion 1 (2 waves, one session) | 1076 | 8708 | 84-88 | 101-107, 25 |
| unit expansion 2 | 1072 | 8679 | 82-88 | 31 |
| unit expansion 3 | 1069 | 8657 | 83-95 | 26-33 |
| unit expansion 4 | 1065 | 8628 | 84-95 | 91-98 |
| comptime (2 rounds, one session) | 3401 | 27399 | 45-46 | 140-153, 130-136 |

- Six installs. Each `expand_terms` call builds a fresh `IrSession`
  (`src/_1_macrotime/_4_expand.rs:121`), so the four unit expansions never share a dataflow.
  Their IRs differ only in constructor and `__ir_prewarm_*` relations: `ir_lower::lower`
  derives constructor relations from the seed terms (`src/_6_eval/_9a_ir_lower.rs:2140`).
  The pre-IR dd engine at `63c33b94e` reused one dataflow for all macrotime calls
  (`dd dataflow reuse reused=true`).
- Eight timely operators per IR node. Two of them are the `observe` inspect taps:
  `ivm-dd` sets `taps = Some(..)` for every install
  (`sqlite_ivm/crates/ivm-dd/src/2_dd.rs:862`), so every node's output rows are cloned into a
  `Vec<DdTap>` and consolidated in a `BTreeMap` per settle only to fill `Counters`.
  dl8 reads those counters only in `dl8 eval` (`src/bin/dl8.rs:487`).
- Experiment, taps off (env-gated hack, reverted): operators 8679 -> 6409 and 27399 -> 19851;
  install 85 -> 64 ms and 45 -> 33 ms; settles 101 -> 48-53, 98 -> 35, 140 -> 74, 133 -> 52 ms.
  Whole build 1.41 -> 0.95 s, same bytes.
- Macrotime install cost is superlinear in operators (8.7k operators: 85 ms; 27k: 45 ms). The
  macrotime IR has a 16-relation LetRec; timely's reachability `Builder::build` sorts
  `((Location, usize), Antichain<Product>)` for the nested scope (sampled hottest frame in
  install).
- Settle time is timely scheduling: `schedule` / `propagate_pointstamps` are most of each
  worker's samples; operator count drives it. Epochs per settle 1-4, steps 11-738.
- Joins: 364 of 1072 macrotime nodes, 1026 of 3401 comptime nodes. Each join arranges both
  inputs separately (two key-extraction `flat_map`s, two arrangements, the join, a map).
  Unions fold binary `concat` (n-1 operators per n inputs).
- Term transport is small: `intern_terms`, `intern_text` each round-trip the worker channel
  once per call; samples under 1%. No per-row lock contention; the interner is an `Rc<RefCell>`
  on the worker thread.

## Main thread (sampled CPU, taps-off run)

About 229 ms of main-thread CPU, of which IR glue: `ir_lower::lower` 30 ms over six calls,
`stratify` 18 ms, `snapshot_closure` 29 ms, `decode_terms` 8 ms, `fold_generic_row_groups` 11
ms. The rest is the dl8 front end (`lower_compiler_units` 50 ms, `reify_terms` 21 ms,
`check_datalog` 13 ms, read 8 ms) that the old Rust build also runs.

## Consequence for the target

The main thread alone (front end plus IR glue) is about 0.23 s of CPU. A 0.25 s build would
leave about 20 ms for six DD installs and eight settles. The levers below are ranked by
measured or projected savings.

| lever | measured / projected | where |
|---|---|---|
| no taps unless counters are asked for | -0.45 s measured | ivm-dd install mode, dl8 `IrSession` |
| one macrotime session across unit expansions | up to 3 installs (~190 ms after taps) | `_1_macrotime/_4_expand.rs`, `_8_driver/_2_macro.rs` |
| n-ary union via one `concatenate` | operator count | ivm-dd `union` |
| share arrangements of one input on one key | operator count, install, step | ivm-dd `join` |

## After (`perf/dd-speed`, sqlite_ivm `perf/dd-speed`)

Changes, all in `sqlite_ivm/crates/ivm-dd/src/2_dd.rs` unless named:

1. `Engine::install_unmeasured` (`ivm-engine/src/1_rel.rs`, default `install`); `Dd` implements
   it without node taps. dl8 `IrSession` (macrotime, comptime) installs unmeasured;
   `run_fresh` (`dl8 eval`, frontiers, live) keeps measured counters.
2. LetRec scope leaves through one tagged output and one `partition`, so timely's reachability
   summary covers one scope output instead of one per recursive relation.
3. Body nodes that read no recursive relation are lowered once outside the LetRec scope and
   entered (`independent_inputs`); only frontier nodes are entered.
4. Join inputs arranged once per `(stream, key columns)` and shared; the row concatenation runs
   inside `join_core`.
5. `union` is one `concatenate`.
6. Output rows accumulate from the settled deltas into a `BTreeMap` per output; outputs carry no
   arrangement.
7. `dd install` / `dd settle` debug spans (target `ivm_dd`): operators, build ns, epochs, steps.

| call | operators before | after | install ms before | after |
|---|---|---|---|---|
| macro library compile | 8679 | 4242 | 91-96 | 13-15 |
| unit expansions (4) | 8628-8708 | 4221-4255 | 82-95 | 7-17 |
| comptime | 27399 | 14541 | 45-46 | 30-43 |

| build | engine | real s | max RSS | load |
|---|---|---|---|---|
| after | ir:dd | 0.62, 0.54, 0.61 | 129-148 MB | 7.8-8.1 |
| after | ir:sqlite | 2.88, 2.90, 2.81 | 305-312 MB | 8.1-8.3 |

Output `cmp`-identical on every run. ir:sqlite runs the same code path (default
`install_unmeasured` is `install`).

Remaining ir:dd time at load 8: macrotime settles about 180 ms over six settles, comptime
settles about 115 ms (the first one takes 740 timely steps: LetRec rounds), installs about
100 ms, main-thread front end plus IR glue about 230 ms of CPU. The 0.25 s target needs the
DD share near zero; the next lever is the comptime LetRec round count and per-step progress
tracking, then the main thread (`ir_lower::lower` runs `stratify` twice per call;
`snapshot_closure` sorts every row with `Universe::cmp`).
