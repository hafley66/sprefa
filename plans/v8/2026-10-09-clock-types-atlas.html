Why any of this

Most dl8 programs read a file once and write a file once. Today every one of them runs through differential dataflow (DD), the engine built for inputs that keep changing. That is the overhead. The fix: before running, label every relation with when its rows can change. If nothing upstream is live, run plain loops. Only the live part needs DD.

// most dl8 programs look like this: one value, then complete
of(readFile("node-types.json")).pipe(map(parse), filter(isNamed))   // → just array.map/filter

// only this shape needs real incremental machinery: never completes
fromEvent(watcher, "change").pipe(scan(applyDiff, index))         // → kept state + deltas (DD)

Weights (the "rings")

Every row carries a weight. The weight type says what the row means. v6 called these rings; "weight type" is the plain name.

weightvaluesaddinga row meansRxJS twinDD Rust type
Btrue / falseORis it there nowBehaviorSubject<Set>Present
N0, 1, 2 …+, never below 0how many timesan append-only ReplaySubject countu64
Z… −1, 0, +1 …+, negatives allowedhow it changedSubject<{added, removed}>isize
before: a imports b          after: a no longer imports b
B (state)   before = true          after = false
Z (change)  this tick = −1         (one removal)
N (log)     import_events = 1      (logs never go down)

Only Z can say "removed". not X asks "is X absent right now", which is a B question, so negation reads B and never Z.

Clocks and delays

A clock says which tick a relation's rows belong to. A delay (v6: grade) is how many ticks a read moves you.

clockmeaningRxJS twin
Ticknowthe current emission
Prev<C>one tick before C (pre, grade −1)pairwise()'s first element
Inner<C>inside a recursion that finishes within Cexpand() until nothing new, synchronously

Lustre's rule: two things combined in lockstep must share a clock. In RxJS terms, zip(now$, now$.pipe(pairwise())) lines up values from different ticks: legal in RxJS, a type error in Lustre and in the Rust probe below.

The v6 formula

Source: v6/prolog/3_clock_check.pl and the role table v6/prolog/compile/registry.pl:206. Every read inside a rule body is a dependency edge carrying a weight type, a sign and a grade.

how a rule readsweightsigngrade
plain read (level_read)B+0
not (level_absence)B−0
fires on add (edge_trigger)Z+0 or 1, by writer
fires on remove (edge_departure)Z−1
latest (edge_sample)Bstate0
pre (edge_pre)Bprevious−1
clock(R) = origin + sum of grades along a path from an input to R

reject when:
  1. two paths to R give different sums           (clock_path_conflict)
  2. a cycle has total grade 0 through Z          (unconstructive_clock_cycle: an event triggers itself)
allow:
  3. a cycle of positive B reads with grade 0     (an ordinary fixpoint inside one tick)

The same rules as datalog (Prolog spelling)

% every input starts at offset 0; a read moves the offset by its grade
offset(R, 0) :- input(R).
offset(To, N) :- offset(From, M), dep(From, To, _Weight, _Sign, Grade), N is M + Grade.

% rule 1: two different offsets for one relation
clock_path_conflict(R, A, B) :- offset(R, A), offset(R, B), A < B.

% rule 2: a zero-grade cycle that goes through a Z read
self_trigger(R) :- cycle_through(R, z, 0).

And as SQL, for the SQL-brained

WITH RECURSIVE offset(rel, n) AS (
  SELECT rel, 0 FROM input
  UNION
  SELECT d.to_rel, o.n + d.grade FROM offset o JOIN dep d ON d.from_rel = o.rel
)
SELECT rel, MIN(n), MAX(n) FROM offset GROUP BY rel HAVING MIN(n) <> MAX(n);  -- conflicts

A real checker needs a cap on n: a cycle with grade +1 makes the recursion count forever. v6 bounds it by the number of grade-1 edges (3_clock_check.pl:556).

Same rules, many languages

The same five rules in every language that can say them. Each tab ends with how to read it as TypeScript.

import { BehaviorSubject, Subject, zip, of, pairwise, withLatestFrom, expand, EMPTY } from "rxjs";

const edges$   = new BehaviorSubject<Set<string>>(new Set());   // weight B
const changes$ = new Subject<{ added: string[]; removed: string[] }>(); // weight Z

zip(edges$, edges$.pipe(pairwise()));            // lockstep now + previous: RxJS allows it
changes$.pipe(withLatestFrom(edges$));           // `latest`: read B at a Z event
of(seed).pipe(expand(next => next.size ? of(step(next)) : EMPTY)); // recursion to a fixpoint

Reading: RxJS checks none of the five rules. Every mistake in the other tabs is legal here and shows up at runtime as wrong values.

pub struct B; pub struct Z;                       // weights
pub struct Tick; pub struct Prev<C>(PhantomData<C>); pub struct Inner<C>(PhantomData<C>);
pub struct Rel<R, C>(PhantomData<(R, C)>);

pub trait Finished {}                             // clocks whose rows are done
impl Finished for Tick {}
impl<C: Finished> Finished for Prev<C> {}      // Inner<C> deliberately has no impl

fn join<R, C>(l: &Rel<R, C>, r: &Rel<R, C>) -> Rel<R, C>           // same weight, same clock
fn pre<R, C>(now: &Rel<R, C>) -> Rel<R, Prev<C>>                 // one tick back
fn negate<C: Finished>(set: &Rel<B, C>) -> Rel<B, C>              // B only, finished only
fn iterate<C>(seed: &Rel<B, C>,
              step: impl FnOnce(&Rel<B, Inner<C>>) -> Rel<B, Inner<C>>) -> Rel<B, C>

iterate(&edges, |inner| negate(inner));
// error[E0277]: the trait `Finished` is not implemented for `Inner<Tick>`

Reading: <R, C> is TS generics; reusing the same letter on both arguments is what forces "same clock". C: Finished is C extends Finished. Probe with passing tests: plans/v8/probes/clock_types/.

Reading: {n : Nat} is an implicit generic that is a number, so Rel w (n + 1) does real arithmetic in the type. A theorem is a type whose value is a proof; sorry means "unproven". This is the only family that can state rule 1 at all.

data Weight = B | Z

data Rel : Weight -> Nat -> Type where
  MkRel : Rel w n

pre : Rel w n -> Rel w (S n)        -- S n = n + 1
pre MkRel = MkRel

join : Rel w n -> Rel w n -> Rel w n
join MkRel MkRel = MkRel

Reading: Haskell syntax with types that take values: Rel : Weight -> Nat -> Type means "Rel takes a weight and a number and gives a type". S n is the successor, n + 1.

node counter(tick: bool) returns (n: int);
let
  n = 0 -> pre(n) + (if tick then 1 else 0);
tel

-- rejected, a cycle with no delay:
n = n + 1;

-- rejected, two clocks in one expression:
m = n + (x when tick);

Reading: a -> b is "a on the first tick, b after" (startWith). pre(n) is last tick's n (pairwise). x when tick is a stream on a slower clock (filter, but tracked in the type). The original clock calculus; Vélus is a Lustre compiler proven correct in Coq.

counter :: HiddenClockResetEnable dom => Signal dom Int
counter = register 0 (counter + 1)

-- rejected, two clock domains in one expression:
mixed :: Signal Fast Int -> Signal Slow Int -> Signal Fast Int
mixed a b = a + b

Reading: Haskell to hardware. Signal dom Int is a stream of ints on clock dom; register 0 x is pre with an initial value. Mixing domains is a type error: the v6 rule, shipping in chips.

count :: (Reflex t, MonadHold t m, MonadFix m)
      => Event t () -> m (Dynamic t Int)
count clicks = foldDyn (\_ n -> n + 1) 0 clicks

Reading: Haskell FRP. Behavior t a is weight B (the current value), Event t a a change stream (Z-like), Dynamic t a both, like a BehaviorSubject. t is the timeline, a phantom type that keeps two apps' events apart. foldDyn is scan that yields a BehaviorSubject.

def reach(edges: List[(Int32, Int32)]): Vector[(Int32, Int32)] =
    let db = inject edges into Edge/2;
    let rules = #{
        Path(x, y) :- Edge(x, y).
        Path(x, z) :- Path(x, y), Edge(y, z).
    };
    query db, rules select (x, y) from Path(x, y) |> List.toVector

Reading: a JVM ML-family language with Datalog as a first-class value: #{ … } is a program you pass around. Flix checks stratification of negation at compile time, and its effect system marks functions that do IO. Closest living cousin of dl8.

:- pred path(int::in, int::out) is nondet.
path(X, Y) :- edge(X, Y).
path(X, Z) :- edge(X, Y), path(Y, Z).

:- pred lookup(string::in, int::out) is semidet.   % zero or one answer

Reading: Prolog with types. ::in/::out are modes (which arguments are known). det = exactly one answer, semidet = zero or one, nondet = any number. That determinism label is the same idea as dl8's once/stratum/live label: the compiler picks the code shape from it.

fun read-index(path : string) : <io,exn> index
  parse(read-text-file(path))

fun pure-count(xs : list<int>) : total int
  xs.length

Reading: the part after : lists effects: <io,exn> touches the world and may throw; total touches nothing. dl8's labels are effect rows for relations: once is "reads the world at start", live is "reads it forever".

Live edges: CSP, backpressure, AsyncAPI

Only the live corner needs any of this. Each formalism covers one part:

CSP

Every live input is a channel. A sender blocks when the channel is full. In Rust: tokio::sync::mpsc::channel(64), bounded.

Backpressure

DD takes one batch per frontier. The producer waits on send().await, so nothing piles up in memory. RxJS has no real backpressure, only lossy throttle/buffer.

Rx vocabulary

map, filter, scan, combineLatest (join, one clock), withLatestFrom (latest), pairwise (pre), expand (recursion).

AsyncAPI

The contract per channel: name, message schema (the row type), direction, capacity. Generated from dl8's live declarations; its message types become the Rust structs on the channel.
let (tx, rx) = tokio::sync::mpsc::channel::<Vec<(Row, isize)>>(64); // bounded: CSP
watcher.for_each(|batch| async { tx.send(batch).await.ok(); });         // waits when full
while let Some(batch) = rx.recv().await {                               // one batch per frontier
    input.advance_to(next_tick); input.extend(batch); worker.step_while(|| probe.less_than(&next_tick));
    sqlite.write_batch(&output_delta)?;                                 // one transaction per frontier
}

What types cannot check

Rule 1, "every path to a relation has the same total delay", is a fact about the whole graph. A type checker sees one expression at a time, so only proof languages (Lean, Idris) can state it, and only with a hand-written proof. dl8 is already a datalog engine, and the rule is three lines of datalog over the dependency rows. So the split is:

  • dl8's clock checker owns whole-graph rules (path sums, cycles) and gives readable errors.
  • Generated Rust carries weight and clock as types, so rustc backstops the local rules.
  • Haskell, Lean, Clash, Reflex, Flix, Mercury, Koka are references for shapes, not targets.
