## Cut 1: one effect trait

`v8/src/_7_effect.rs` holds `Slice`, `Never` and `reduce_then_apply`, mirroring
`hafley-games/crates/redux/src/0_slice.rs` without depending on it. The four
sinks each became a `Slice` impl:

| slice | State | Event | Output | Effect |
|---|---|---|---|---|
| `_6_eval::Evaluate` | `Store` | `(&mut Universe, &Program)` | `Closure` | `Trace` |
| `_1_macrotime::Expand` | `Vec<TermId>` (the rows) | `(&mut Universe, &MacroProgram)` | three row lists | `Wave` |
| `_4_comptime::Rounds` | `RoundState` | `RoundInput` | `Result<RoundOutcome, Stop>` | `Round` |
| `Drive` (lib.rs) | `Universe` | `&Path` | `Result<Compile, Stop>` | `Event` |

The trait has no `Context` GAT, so each impl carries the lifetime on a
`PhantomData` marker type and the borrows ride in `Event`. The one real payoff
outside the shape: `rounds/10` and its `#[allow(clippy::too_many_arguments)]`
are gone, replaced by `RoundInput` for the read-only side and
`RoundState::seeded` for the frozen lists. `lower`, `check` and `reify` got no
`Effect = Never` impl, because none of them takes an `fx` parameter today and
adding one would change signatures the brief told me not to churn.

Net cost: **+113 lines.** The brief said keep it and report the number.

`reduce_then_apply` has exactly one call site, `expand_terms`, which buffers the
waves of one expansion and replays them to `fx` afterwards. That is
behaviour-preserving: nothing else writes to stderr between the first and last
wave of a single `expand_terms` call.

Every function over 90 lines, and then every function over 70, split at a
repeated shape rather than at an arbitrary line.

| function | what was lifted |
|---|---|

| `syntax_seeds` 95 | the inverse table: `seed_shape` names each graph row's relation and per-argument tag (`ref`/`const`/`raw`/`text`), `seed_cell` applies one tag. Eight match arms became one loop. |

| `finish_compile` 94 | `phase(name, run, counts)` runs one phase inside its span and emits its stderr line; `macro_phase` is the one phase whose event fires on the stopping path too, and it was duplicated verbatim in `compile` and `compile_project`. `lower_units` carries the project-graph install. |
| `rounds` 116 | `merged_sorted`, `decide` (sink plus log, three call sites), `round_limit_diagnostic`, `stable_outcome`, and `round_closure` returning `Result<Result<Pass, RoundOutcome>, Stop>` so the two early-outs leave the loop body. |

| `assemble::index` 87 | `index_row` over a `Scratch` of buckets. |
| `reify::node` 81 | `source_row` and `form_node`. |

Two `#[allow(clippy::too_many_arguments)]` waivers retired: `rounds` and
`unit_path_claim`.

Ordering safety: `Universe::cmp` is structural (`_6_eval/_0_term.rs:154`,
compounds by arity, then name, then arguments), so term-id allocation order does
not reach any output. Where a lift reordered pushes, a `prolog_sort` always
follows. Where it reordered interning, the interning order was preserved by hand
anyway.

## Cut 3: `return vec![]` early-outs

14 of the 16 sites were the `match x { Some(v) => v, None => return vec![] }`
chain inside `Kernel::solve`, and they went out with the cut-2 split of that
function: `nil_row`, `cons_row`, `edge_ref_row`, `intern_row` and `int_row` all
return `Option<Vec<TermId>>` and use `?`, and `solve` wraps once.

One site stays: `_2_lower/_2_declare.rs:281`, `constructor_relations`, where
`if kind != "product" { return vec![]; }` is a single guard on a `&str`, not an
`Option` chain. Rewriting it as a `try_` function would add lines and read
worse.

## Cut 4: row copies

`Universe::args::<N>(id, name) -> Option<[TermId; N]>` copies a known functor's
arguments into a stack array, so the caller can keep mutating the universe
without a heap row per read. Nineteen sites of
`u.functor(x).map(|(n, a)| (n, a.to_vec()))` became one call each, one line
shorter and one allocation lighter:

| file | reads converted |
|---|---|
| `lib.rs` | `dl7_project/2` |
| `_4_comptime/_5_finish.rs` | `rule/2`, `relation/3` x2 |
| `_4_comptime/_3_assemble.rs` | `goal/2`, `variable/2`, `literal/2` |
| `_4_comptime/_2_rounds.rs` | `call/2` x2, `rule/2`, `checked_goal/2` |
| `_4_comptime/_7_sources.rs` | `module_basement/2`, `basement_program/2` x2, `root_graph/2`, `pending_edge/4`, `datalog_program/3`, `relation/3` |
| `_8_driver/_2_macro.rs` | `dl7_unit/5` |

Four more copies removed where a borrow already sufficed:

- `assemble::node_family` iterated `named.get(family).clone()` and
  `by_rel.get(&rel).cloned()`. The second is a deep copy of every row of the
  family, once per relation; both are gone.
- `check::collect_variables` cloned the argument vector at every level of a
  recursion over every term.
- The macrotime wave loop rebuilt `Program { rules: rules.clone(), seeds }` per
  wave. The rule cone is fixed for the whole expansion, so the `Program` is
  built once and only `seeds` is replaced. Up to 64 deep clones of a
  `Vec<Rule>` per expansion, gone.
- `atom_of_text` and `text_of_atom` cloned a whole `Term` to match on it; a
  `Sym` is `Copy`.
- `aggregate_rows` cloned each proof to build its group key; the proofs are
  owned by the loop, so the key takes the proof by value.

### What stayed, and why

| site | reason |
|---|---|
| `_6_eval/_5_evaluate.rs:212,593` `row.to_vec()` | `Vec<Vec<TermId>>` is the memo and store row shape and the oracle's row order. Off limits. |
| `_6_eval/_5_evaluate.rs` `rules_by_rel[&rel].clone()` | a `Vec<&Rule>` shallow copy; `self` is mutably borrowed by the `solve` recursion inside the loop. |
| `_6_eval/_5_evaluate.rs` `memo` key and value clones | the memo is re-entrant: a recursive call with the same key reads the rows found so far, so the returned rows cannot be a borrow. |
| `prolog_sort(u, rows.to_vec())` (2 sites) | `prolog_sort` sorts in place and takes the `Vec` by value; a slice overload would copy inside instead. |
| `u.functor(x).map(\|(n, a)\| (n.to_string(), a.to_vec()))` (10 sites) | these dispatch on the functor name through a `match` whose arms intern into the universe, so the name has to outlive the immutable borrow. `args::<N>` only applies when the functor and arity are known before the read. |
| `_2_lower/_0_cx.rs::replace` | recurses while mutating the universe; the name and arguments must be owned across the recursion. |
| `Cx`, `Assembled`, `Checked` field clones in `_6_json.rs`, `_4_emit.rs`, `_5_finish.rs` | each builds a new owned value whose source is still live. |
| `output_dependency_closure`'s `relations.clone()` | the fixpoint's working copy of the previous round. |

## Deviations from the brief

1. **`lib.rs::compile` does not call `reduce_then_apply`.** With `State =
   Universe` and `Effect = Event`, buffering would hold every `Wave` and `Round`
   until the whole compile finished and then print them all after the five
   `dl8::phase` lines. That is a visible change to `--trace` stderr ordering, and
   "identical behaviour" outranks the call site. `Drive::reduce` is called
   directly; `expand_terms` carries `reduce_then_apply`.
2. **`lower`, `check` and `reify` got no `Effect = Never` impl.** The brief said
   only if it needs no signature change elsewhere. None of the three takes an
   `fx` parameter, so an impl would have meant inventing one.
3. **The line count grew.** Stated up front rather than buried.
