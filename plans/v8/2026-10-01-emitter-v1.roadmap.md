## Fork for L4: caret vs the standing decision

`CLAUDE.md` "User decisions still in force": "Caret is namespacing only, off the demo path", and
snippets use "no `^` unless namespacing". The 2026-10-01 chat proposed `^` as the pass-through
edge for decorations:

```
(Named:
   (* (^shape:
         (* (name: str)))
      (check: Extends)))
```

Options:
- a. Lift the standing decision: `^` marks the pass-through (return) edge for decorations.
- b. Keep caret namespacing-only; pass-through uses the existing generic `return` edge:
  ```
  (Decorated:
     (* (Shape: type)
        (Checker: any)
        (return: Shape)))

  (Named:
     (Decorated
        (* (name: str))
        Extends))
  ```
  The walk follows `return`; `Checker` is read as a column of the instance.
- c. No decorations on contracts: checker chosen by `(checker_of Named Extends)` or at the bound
  site only (L1 already falls back to this).

## Decided 2026-10-01: L4 = a, the eigo

User picks a. Caret used as the pass-through edge is named the **edge insect glaive operator
(eigo)**. Target: decorators as identity types, TS twin `type Deco<Type> = Type;`: following a
decorated edge lands on the `^` target; the other edges on the minted node are decorations.
Listed with the other caret uses in `CLAUDE.md`.

## Decided 2026-10-01: walk reads edge_snapshot; userland names shadow kernel names

- L1 = option B: no `type_bind`; candidate/fails/fails_at read `edge_snapshot` directly. Saved
  snapshot 2,520,581 bytes (measured), under the 3,145,728 budget.
- User: "just shadow userland edge name symbols". A user declaration named like a kernel relation
  (`field`, `node`, `product`, `body`, `effect`, ...) shadows the kernel name inside that module
  instead of colliding. Compiler name-resolution change; goes with L2 (call) since both touch how
  a goal's relation position resolves. dl7 example for the brief:

  ```
  (field:
     (* (form: type)
        (label: str)))

  (<- (required ?Form ?Label)
      (field ?Form ?Label))
  ```
  resolves `field` to the user product (arity 2), not a kernel relation.
