dl8: checking values against types

Context page for plans/v8/ZONE.md. Source of every claim: plans/v8/2026-10-11-generics-trace.md.

Waiting on you: OK to build steps 1 and 2 below. A column declared int that gets a non-int value is silently stored as generic terms today. The fix reports it, one row per column, and a dl7 rule decides if that is an error.

4 · The fix: let storage layout report what it already knows

raw_columns (src/_6_eval/_9a_ir_lower.rs:1241) decides per column whether it can store bare i64. It already looks at every seed (:1271) and propagates int-ness through rules (:1281). On "a" it sets the column to term storage and says nothing.

today

seed.value declared int, saw "a"
  → stored as term ids
  → no report

proposed

column_layout(seed, value,
  declared: int, stored: term,
  witness: "a")

One row per column. 10 seeds or 1M seeds: still 1 row.

Judging stays in userland, per language:

; prelude
(<- (column_type_mismatch ?Relation ?Column ?Declared ?Witness)
    (column_layout ?Relation ?Column ?Declared term ?Witness)
    (primitive_layout ?Declared))
storage classbuiltlanding in it proves
raw i64yes · ecfb51a7eevery value is an int
text dictionarynoevery value is a string
term of type node Tnoevery value's intern row names T or a variant
term, anyyes · fallbacknothing; the witness says why
