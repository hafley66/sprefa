# v8 `_6_eval` API

1. Signatures, hand-written kernel
2. Signatures, emitted per program
3. Bodies as comments
4. Instance lifetimes
5. Storage layout, read/write sequence, uniqueness
6. `sqlite_ivm` as the second `Storage`

No `close`, no `Final`. `evaluate` returns nothing; the `Store` it was given is the result.
Negation safety is a check in `_3_check` (a `not` reads only a lower stratum), not a wrapper type.

## 0. As built, `v8/src/_6_eval/` (2026-09-12)

Measured against v7 `evaluate/4` on 32 frozen fixtures (`v8/oracle/eval/*.json`): 17 hand
programs plus every `evaluate/4` call the v7 compiler makes for `0_minimal`, `2_partial`,
`14_syntax_macros`, `15_standard_plus`. Facts that differ from sections 1 to 5:

| fact | where |
|---|---|
| rules are data at runtime, so the kernel interprets `Rule { head, body, vars }`; emitted rule structs (section 2) are for runtime programs later | `_1_program.rs` |
| rows are `Box<[TermId]>` over one hash-consed term arena; a cell is any Prolog term | `_0_term.rs` |
| kernel constructors (`cons`, `intern`, `edge_ref`) mint terms during evaluation; termination is the program's responsibility, as in v7 | `_4_kernel.rs` |
| SWI standard order as measured: Number < String < `[]` < Atom < Compound; closure sorted by it | `_0_term.rs` `cmp` |
| a positive goal on a derived relation with a bound argument also runs that relation's rules top-down under the bindings (v7's tabled `proves/2` reaches rows that free-head bottom-up cannot). Demanded rows are used, never stored | `_5_evaluate.rs` `demand` |
| aggregate bodies match stored rows only, no kernel functions, no demand (`completed_body_holds/2`) | `Eval.tables_only` |
| `intern` requests become rows of `ref(kernel(intern))` at the end of each round | round loop |
| an aggregate diagnostic ends evaluation with an empty closure, as v7 | `evaluate` |
| transport is JSON: int, `{"a":..}`, `{"s":..}`, array, `{"f":..,"args":[..]}`, `{"v":..}`, `{"count":..}` | `_6_json.rs`, `oracle/eval/json_terms.pl` |

Timing, release build, whole `dl8 eval` process including a 1.3 MB JSON parse: 5 to 53 ms per
compiler evaluate call. v7 spends 2.4 s compiling `2_partial.dl7` end to end (8 evaluate calls).

## 1. Kernel, `v8/src/_6_eval/types.rs`

```rust
pub struct Atom(pub u32);      // Copy Eq Hash. minted by Universe only, before evaluate
pub struct RelId(pub u32);
pub struct RuleId(pub u32);
pub struct RowId(pub u32);     // position in a table, insertion order

pub struct Universe { pub names: Vec<String> }            // Atom(i) <-> names[i]
impl Universe {
    pub fn intern(&mut self, s: &str) -> Atom;             // called by _2_lower, never by a rule
    pub fn name(&self, a: Atom) -> &str;
}

pub trait Relation: Copy + Eq + Hash {
    const ID: RelId;
    const ARITY: usize;
    fn col(&self, i: usize) -> Atom;
}

pub trait Storage<R: Relation> {
    fn insert(&mut self, row: R) -> bool;                  // true = new
    fn frontier(&self) -> RowId;                           // first row of the current delta
    fn advance(&mut self) -> usize;                        // frontier = len; returns delta len
    fn delta(&self) -> &[R];                               // rows[frontier..]
    fn total(&self) -> &[R];                               // rows[..]
    fn seek(&self, col: usize, a: Atom) -> &[RowId];       // index probe, one per column
    fn get(&self, id: RowId) -> R;
}

pub struct MemTable<R: Relation> {
    pub rows: Vec<R>,
    pub seen: HashSet<R>,
    pub frontier: usize,
    pub index: Vec<HashMap<Atom, Vec<RowId>>>,             // len == R::ARITY
}
impl<R: Relation> Storage<R> for MemTable<R> { /* section 5 */ }

pub enum Mode { Full, Delta }                              // first round of a stratum, then Delta

pub trait Rule {
    fn id(&self) -> RuleId;
    fn head(&self) -> RelId;
    fn fire(&self, store: &Tables, mode: Mode, out: &mut Sink);   // Tables and Sink are emitted, section 2
}

pub struct Program {
    pub universe: Universe,
    pub rules: Vec<Box<dyn Rule>>,
    pub strata: Vec<Vec<RuleId>>,                          // SCC order from _0_stratify
}

pub enum Trace {
    Round { stratum: u32, round: u32, new: usize },
    Fire  { rule: RuleId, candidates: usize, new: usize },
}

pub struct Rounds(pub u32);

pub fn evaluate(p: &Program, store: &mut Tables, fx: &mut impl FnMut(Trace)) -> Rounds;
```

## 2. Emitted per program, `v8/out/<program>/tables.rs`

Ancestor: `v7/src/3_emit/1b_dbsp_rust_emitter.pl`. The emitter reads `CheckedProgram` and writes:

```rust
// one struct per rel
#[derive(Copy, Clone, Eq, Hash, PartialEq)]
pub struct Edge { pub x: Atom, pub z: Atom }
impl Relation for Edge { const ID: RelId = RelId(0); const ARITY: usize = 2; fn col(&self, i: usize) -> Atom { [self.x, self.z][i] } }

pub struct Path { pub x: Atom, pub z: Atom }
impl Relation for Path { /* same shape */ }

// the store: one field per rel, no map lookup by name anywhere
pub struct Tables {
    pub edge: MemTable<Edge>,
    pub path: MemTable<Path>,
}

// the sink: one Vec per head rel, drained by evaluate after each rule
pub struct Sink {
    pub path: Vec<Path>,
}
impl Sink { pub fn drain_into(&mut self, t: &mut Tables) -> usize; }   // sum of insert()==true

// one struct per rule, join order fixed by the emitter
pub struct PathStep;                                       // path(X,Z) :- path(X,Y), edge(Y,Z).
impl Rule for PathStep {
    fn id(&self) -> RuleId { RuleId(1) }
    fn head(&self) -> RelId { Path::ID }
    fn fire(&self, t: &Tables, mode: Mode, out: &mut Sink) {
        let left = match mode { Mode::Full => t.path.total(), Mode::Delta => t.path.delta() };
        for p in left {
            for id in t.edge.seek(0, p.z) {                // index on edge.x
                let e = t.edge.get(*id);
                out.path.push(Path { x: p.x, z: e.z });
            }
        }
    }
}

pub fn program() -> Program;                               // universe, rules, strata baked in
```

Termination: `insert` can only add, `Atom` cannot be minted after `program()`, so `rows.len() <= |universe| ^ ARITY` per table and `new == 0` arrives.

Semi-naive correctness for a two-body rule: the `Delta` round must join `delta(path) x total(edge)` plus `total(path) x delta(edge)` when both rels are in the stratum. The emitter writes one `fire` arm per body position that belongs to the current stratum; rels from lower strata are read as `total` only.

## 4. Lifetimes

| instance | born | dies | owner |
|---|---|---|---|
| `Universe` | `_2_lower` interning | end of `compile` | `Program` |
| `Program` | `program()` in the emitted crate, or `_4_comptime` building it from `CheckedProgram` | end of `compile` | caller |
| `Tables` | caller seeds it before `evaluate` | caller reads it after; it IS the output | caller |
| `Sink` | start of each rule firing | `drain_into` | `evaluate` |
| delta slice | `advance` | next `advance` | borrowed from `MemTable` |
| `Trace` value | `fx` call | consumed by `_8_trace` | none |

`evaluate` is called once per fixpoint phase: `_1_macrotime` with the macro `Program` over syntax-graph tables, `_4_comptime` with the prelude+user `Program` over lowered tables. Two `Tables` types, emitted separately, one kernel.

## 5. Storage layout, sequence, uniqueness

Per `MemTable<R>`:

| field | layout | written | read |
|---|---|---|---|
| `rows` | `Vec<R>`, `RowId` = index | `insert`, append only | `delta`, `total`, `get` |
| `seen` | `HashSet<R>` | `insert` | `insert` |
| `frontier` | `usize` | `advance` | `delta` |
| `index[c]` | `HashMap<Atom, Vec<RowId>>` | `insert`, append only | `seek` |

Sequence per round: every rule `fire` (reads only) -> `drain_into` (writes `rows`, `seen`, `index`) -> `advance_all` (writes `frontier`). No read of a table happens while it is written, so `fire` takes `&Tables` and `drain_into` takes `&mut Tables`; the borrow checker enforces the phase split.

Uniqueness: `seen` on the full row. `index` entries are appended only for rows where `seen.insert` returned true, so `index[c][a]` never holds a `RowId` twice. `RowId` is unique by construction (`rows.len()` at insert).

Formerly-quadratic paths carry COUNT tests: `Trace::Fire.candidates` per rule per round is the statement count. A rule whose `candidates` grows with `total` instead of `delta` after round 1 is a defect.

## 6. `sqlite_ivm` as the second `Storage`

`~/projects/sprefa/sqlite_ivm` (README, "Supported query shapes"): recursion is "unary reachability: anchor UNION distinct one recursive equijoin edge step". One rel, one recursive step. Multi-rel SCCs and rules with two recursive body atoms fall outside it.

| use | fits | how |
|---|---|---|
| compile-time evaluation (`_1_macrotime`, `_4_comptime`) | no, in-memory `MemTable` | none |
| emitted runtime program, non-recursive rels | yes | `CREATE VIRTUAL TABLE <rel> USING sqlite_ivm('<rule as SELECT>')`, maintained on source INSERT |
| emitted runtime program, single-edge recursion | yes | the recursive CTE shape the README names |
| emitted runtime program, wider recursion | no | `Storage<R>` over a plain table: `("__id" INTEGER PRIMARY KEY, <cols>, UNIQUE(<cols>))`, `delta` = `WHERE __id > :frontier`, `seek` = one index per column, loop driven by `evaluate` |

`Storage<R>` is the seam. `MemTable` and `SqliteTable` both implement it; `Tables` is emitted with whichever field types the target asks for. Fork for the user: whether the emitted runtime uses `sqlite_ivm` views where they fit and `SqliteTable` elsewhere, or `SqliteTable` everywhere with `sqlite_ivm` as a later swap.
