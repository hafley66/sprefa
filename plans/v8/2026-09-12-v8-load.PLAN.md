## 2. Build vs buy: where the TSI row types come from

The wire the loader reads is signed JSONL written by
`v6/sprefa-extract/src/tsi/sink.rs`; its Rust row types live in
`v6/sprefa-extract/src/tsi/types.rs` (125 lines: `RunOut`, `FactOut`,
`WitnessOut`, `CoverageOut`, `DiagnosticOut`, `Arg`, `Mode`, `Method`).

Measured on this machine, 2026-09-12, `cargo build` debug profile:

| candidate | crates in graph | clean build | incremental after touching its own lib | target dir |
|---|---|---|---|---|
| dl8 today | 35 | 9.36 s | 0.41 s | 245 MB |
| (a) path-depend on `sprefa-extract` | 253 | 58.89 s | 2.84 s | 2.1 GB |
| (b) redeclare the row shapes inside `_0_load` | 35 | 9.36 s | 0.41 s | 245 MB |
| (c) new shared crate holding only the row types | 36 | ~9.4 s | 0.41 s | ~245 MB |

Crate counts: `cargo tree --prefix none -e normal | sort -u | wc -l` in each
tree. Build times: `/usr/bin/time -p cargo build` with a fresh
`CARGO_TARGET_DIR`, then `touch src/lib.rs` and rebuild.

Candidate by candidate.

**(a) path-depend on `sprefa-extract`.** Measured, not dismissed: 58.89 s
clean and 2.84 s incremental for the extract lib ALONE, before dl8 compiles a
line. The cost is not the 125 lines of `types.rs`; it is the crate's front
ends, which the loader never calls: `oxc_allocator/parser/ast/ast_visit/span/
syntax/semantic/resolver` at 0.135, `ast-grep-core/language/config` at 0.38,
`syn` with `full`+`visit`+`extra-traits`, `proc-macro2` with
`span-locations`, `ignore`, and the `tree-sitter-dl6` grammar workspace member
(`v6/sprefa-extract/Cargo.toml:28-80`). It also fights the two `[workspace]`
tables: `v6/sprefa-extract/Cargo.toml:4` declares its own workspace with
`members = [".", "tree-sitter-dl6"]`, and `v8/Cargo.toml:1` declares another.
A path dependency across that boundary either dissolves one workspace or
duplicates the lock. At 68 s clean and 2.1 GB of target, dl8 stops being a
tree you can iterate in, and the user's standing "no merging of crates" holds
anyway. REJECTED on the 10 s incremental floor.

**(c) a new shared crate for the row types.** Costs one crate, near zero build
time, and is the right answer the day a SECOND consumer of the wire exists in
Rust. Today there is one (this lane). Creating it now means editing
`v8/Cargo.toml`, which this lane does not own, and minting a crate whose only
job is to be depended on once. Correct later, premature tonight. DEFERRED, and
the note belongs to the user's open fork on how separate dl8 and
sprefa-extract should be.

**(b) redeclare the shapes from the JSONL the loader reads.** PICKED. What v7
decodes is not `types.rs`; it is six record kinds and five argument shapes,
`0c:214-283`, 70 lines of Prolog. Rust redeclaration of the same is roughly
the same size and is a port of `0c`, not a copy of `types.rs`: a field
`types.rs` carries but `0c` never reads must stay unread for parity. Build
cost unchanged: 9.36 s clean, 0.41 s incremental, both under the 10 s law.

The measured numbers stay in this table for whoever revisits the fork.

## 3. Pure and impure halves

Each loader is two functions. Everything past the byte edge is pure over owned
data: slices in, values out, no `Path`, no `std::fs`.

| impure edge (`_6_read.rs`) | pure half |
|---|---|
| `read_tsi_stream(path) -> io::Result<Vec<String>>` | `load_tsi_lines(u, origin, &[String]) -> Loaded` |
| `read_source_fact_files(&[PathBuf]) -> Vec<(PathBuf, io::Result<String>)>` | `load_source_fact_texts(u, &[(TermId, &str)]) -> Loaded` |
| `read_dir_tree(root) -> io::Result<Vec<PathBuf>>` | `install_project_graph(u, project, &[TermId], &[TermId]) -> Installed` |

`read_dir_tree` exists because `install_project_graph/6` consumes a
`dl7_project(Root, Units)` term that v7 builds from a directory walk in
`2_compiler.pl:267` `load_dl7_project/4`; the walk itself belongs to the read
lane, so the edge here only lists `.dl7` paths under a root and is driven by
the one impure-edge test.

No effect survives the split. Per the brief's redux shape, all three pure
halves would carry `Effect = Never`, which is the same statement as "returns a
value". A `Slice` trait with a `Never` effect type would therefore have three
impls that never emit, and the repo law is no trait unless two impls exist
tonight that need one. No trait is declared; the purity claim is carried by
the signatures, which take `&[T]` and return owned values.

## 4. Representation: one arena, terms only

Every row, basement, origin and diagnostic is a `TermId` in the
`v8/src/_6_eval/_0_term.rs` `Universe`, the same choice
`v8/src/_2_lower` made. Three consequences.

1. `sort/2` is `Universe::cmp` (`_0_term.rs:154`, SWI standard order) followed
   by dedup on `TermId`, which is exact because the arena is hash consed
   (`_0_term.rs:63`).
2. The JSON transport is already written: `term_to_json` / `term_from_json`
   at `v8/src/_6_eval/_6_json.rs:22` and `:56`, byte-identical to what
   `v8/oracle/eval/json_terms.pl:3-12` writes from v7.
3. No row struct exists to drift from the Prolog. A decode is a pattern match
   on a compound, e.g. `extract_fact(_, 'tsi.primitive', [id(Id), atom(Class)])`
   at `0c:433`.

Where v7 walks a list with `member/2` inside a `findall/3` whose result is then
`sort/2`ed, the port may index, because the sort erases the order. Where the
`findall/3` result is NOT sorted the iteration order is reproduced exactly.
The unsorted findalls in the subject are `0c:325-335`
(`tsi_environment_for_owner`, both `Relations` and `Reservations`),
`0c:678-682` (`comptime_relations` `Relations`) and `0c:523-527`
(`argument_identities` `Arguments`).

## 5. Port notes per module

### 5.1 `0b_filesystem_grapher.pl` -> `_1_project.rs`

`install_project_graph/6` (`:17`) is all-or-nothing: any diagnostic leaves
`Basements` and `Origins` untouched (`:38-39`), and `project_graph/6` zeroes
nodes, edges and origins when a diagnostic fired (`:52-54`).

Path predicates are the only external calls, and every one of them is a pure
string operation on a `/`-separated atom:

| predicate | port | note |
|---|---|---|
| `relative_file_name/3` (`:72`) | `_0_paths.rs` | `filesex.pl:163-175`: `absolute_file_name` both sides, split on `/`, drop the common prefix, `to_dot_dot/3` |
| `directory_file_path/3` (`:147`) | `_0_paths.rs` | `filesex.pl:206-217` |
| `file_name_extension/3` (`:117`) | `_0_paths.rs` | split at the last `.` after the last `/` |
| `file_directory_name/2` (`:156`, `:163`) | `_0_paths.rs` | SWI builtin |
| `file_base_name/2` (`:161`) | `_0_paths.rs` | SWI builtin |
| `atomic_list_concat/3` (`:115`, `:119`) | plain `split`/`join` | |

`absolute_file_name/2` is where the one impurity hides: for a relative input
it prepends the process CWD. Measured with swipl 10.0.2:

```
absolute_file_name("/a/b/../c/./d.dl7", A)  ->  '/a/c/d.dl7'
absolute_file_name("/a//b/d.dl7", A)        ->  '/a/b/d.dl7'
absolute_file_name("rel/x.dl7", A)          ->  '<cwd>/rel/x.dl7'
absolute_file_name("/a/b/", A)              ->  '/a/b/'   (trailing slash kept)
```

The port takes `cwd: &str` as an explicit argument; the CLI passes
`std::env::current_dir()`, the oracle cases pass the case root. That keeps the
pure half pure and reproduces the behavior.

Segment semantics, `semantic_segment/2` (`:122-130`): a leading run of decimal
digits followed by `_` and a non-empty rest is stripped, so `0_src` names
`src`. Both parts must be non-empty; `_x` and `0_` keep their raw spelling.
`segment_actual_name/4` (`:154-157`) then recovers the ON-DISK spelling by
counting back up the source file's own directory chain, which is why the
`pending_edge` label is semantic while the directory owner path is literal.

`unique_claims/2` (`:176-187`) runs AFTER `sort/2` (`:45`), so it collapses
claims that differ only in `SourcePath`, keeping the first in standard order.
`indexed_claims/5` (`:189-199`) then assigns each owner a dense run starting at
0, resetting whenever the owner changes from the PREVIOUS claim (`:201-204`),
which is well defined only because the list is sorted by owner first.

### 5.2 `0c_extract_loader.pl` -> `_2_wire.rs`, `_3_identity.rs`, `_4_graph.rs`

**Lines.** `read_line_to_string/2` strips a trailing `\r\n` as well as `\n`
and yields the final partial line of a file with no terminator. Verified on
swipl 10.0.2 against `a\r\nb\n\n  \t \nc`, which reads as
`"a", "b", "", "  \t ", "c", end_of_file`. `blank_line/1` (`:128-130`) is
`normalize_space` to the empty string, so `"  \t "` is a skip.

**Protocol.** `finish_stream_rows/5` (`:91-99`) voids the WHOLE stream when any
`extract_protocol(V)` row has `V =\= 1`; rows already decoded are discarded and
the only diagnostic left is `tsi_protocol(V)`.

**Record dispatch.** `decode_known_record/5` (`:204-212`) tries
`decode_record/3` first, then `foreign_record/1` (`:145-200`, 56 names), then
files `malformed_record(Record)`. Order matters: `fact` is a TSI record, so a
malformed `fact` line is a diagnostic and not a skip
(`test/4_extract_loader.test.pl:202-210` pins this with a sabotage receipt).

**Acceptance.** `accepted_fact/3` (`:298-307`) prefers a semantic witness whose
run is the newest complete run for that relation, else a syntax witness with
no complete semantic claim at all. `newest_complete_run/4` (`:340-345`) is
vacuously true when nothing claims completeness, so every semantic run stands.

**Owner.** `stream_owner/2` (`:398-410`) sorts `Run-owner(Tool, Scope)` and
takes the last, i.e. the highest run number; `none` for no rows at all and
`missing_run` for rows without a run.

**Identity.** `identity_map/5` (`:416-429`) layers primitives over base
identities and then runs at most `identity_passes(16)` (`:68`) replacement
passes for `tsi.called` applications. The primitive list is APPENDED IN FRONT
(`:420`), and `identity_of/3` is `memberchk` (`:545-546`), so a wire id that is
both a primitive class and a declared type resolves to the prelude product and
contributes no node (`graph_nodes/4` at `:581-589` filters through
`loader_identity/2` at `:599-603`).

`replace_identities/3` (`:536-541`) `exclude`s EVERY entry for the id, then
pushes the new one on the front, so after a pass an id has exactly one
identity.

`argument_identities/4` (`:513-529`) closes an argument list only when it holds
no `tsi.value_argument`, its positions are dense from 0 (`:531-534`), and every
argument id already resolves; the `length/2` pair at `:528-529` is the "every"
check.

**Edges.** `graph_edges/4` (`:609-626`) sorts `claim(Owner, Position, Label,
Target)`, drops a second claim on the same owner+label with a
`tsi_duplicate_edge_label` diagnostic (`:628-641`), then assigns the dense
per-owner index (`:643-655`). The wire `Position` orders the claims and is then
discarded.

**Relations.** `relation_names/3` (`:691-704`) keeps registry relations that
are NOT graph relations (`:54-64`), and files `tsi_unknown_relation` for a
relation outside the 39-row registry (`:15-50`).

**Install.** `install_tsi_graph/6` (`:363-394`) never voids: a diagnostic skips
its row and the rest still becomes a basement (`:358-359`).

### 5.3 `0d_source_fact_loader.pl` -> `_5_source.rs`

`load_source_fact_files/3` (`:33-37`) sorts both rows and diagnostics, so all
duplicate logical rows from several query engines collapse. Each file is one
JSON array of protocol-1 envelopes (`:87-115`); a non-array root files
`source_fact_root_not_array` (`:61-62`), and a single bad envelope files
`malformed_source_envelope(Position)` and keeps the rest (`:74-79`).

`json_term/2` (`:261-278`) normalizes a JSON value into a typed, key-sorted
term so object-key order cannot change parse or query identity. `text/1` for
strings, `integer/1`, `number/1`, `boolean/1`, `null`, `array/1`, `object/1`
with `sort/2`ed pairs.

`install_source_fact_graph/6` (`:285-296`) is total: it always produces one
basement for `module(source_intelligence)`, always empty origins, always an
empty diagnostic list. Its relation order is `source_relation/2` clause order
(`:14-27`, 14 rows) because `findall/3` at `:299` preserves it.

## 6. Oracle

`v8/oracle/load/dump_load.pl` wraps all eight exported predicates with
`wrap_predicate/4`, the pattern of `v8/oracle/lower/dump_lower.pl:29-44`, and
writes one JSON case per distinct call. Terms use
`v8/oracle/eval/json_terms.pl`. `swipl` needs `--` before positional args.

Driven by, in one `v8/oracle/load/freeze.sh` run:

| driver | reaches |
|---|---|
| `compile_dl7_project_rows/6` over `v7/test/fixtures/tsi_project` and `v7/examples` | `install_project_graph`, `install_tsi_graph`, `tsi_expression_environment` |
| `v7/test/4_extract_loader.test.pl` | `load_tsi_stream`, `accepted_rows`, `install_tsi_graph` |
| `v7/test/5_source_fact_loader.test.pl` | `load_source_fact_files`, `install_source_fact_graph` |
| `v7/test/8_source_query.test.pl` | `load_tsi_stream` |
| `v7/test/2_module_system.test.pl` | `install_project_graph` |
| `v7/applications/dl6/` | `install_project_graph` at project scale |

`load_tsi_stream/3` and `load_tsi_text/3` collapse to one pure function over
already-read lines; the case carries the origin term (`file path` atom or the
atom `memory`) and the lines, so the two v7 entry points differ only in that
term. The dump reads the file itself to record the lines.

Paths inside dumped rows are rewritten to a `/CASEROOT` prefix in BOTH input
and expected, so the JSON is machine independent and the transformation is a
pure prefix substitution that the loader logic cannot observe.

Cases are deduplicated byte-identically before commit. The committed set stays
under 6 MB; `v8/oracle/load/status.json` records what was checked but not
committed and every diagnostic code not reachable from a committed case, with
its throw site.

`v8/tests/_5_load_oracle.rs` runs `dl8 load <case.json>` as the real binary
(`env!("CARGO_BIN_EXE_dl8")`) over every committed case and asserts byte
equality of the canonical JSON plus the exit code, the shape of
`v8/tests/_3_lower_oracle.rs:42-91`. One case drives the impure edge over a
committed directory under `v8/oracle/load/cases/`.

## 8. Forks

Behavior kept as v7 has it; the alternative is written down and not built.

**Fork 1. A unit outside the project root is not detected when the root and the
unit share no deep prefix.** `outside_project_root/1` (`0b:110-112`) tests the
relative path for `..` or a `../` prefix, and `relative_file_name/3`
(`filesex.pl:190`) drops the LAST segment of its second argument because it is
documented to take a FILE, not a directory (`filesex.pl:134-161`). Measured:

```
relative_file_name('/a/b2/x.dl7', '/a/b', R)   ->  R = 'b2/x.dl7'
relative_file_name('/a/b/c/x.dl7', '/a/b', R)  ->  R = 'c/x.dl7'
relative_file_name('/a/x.dl7', '/a/b', R)      ->  R = 'x.dl7'
relative_file_name('/x.dl7', '/a/b/c', R)      ->  R = '../../x.dl7'
```

Row 1 is a file that is NOT under the root, accepted as if it were, and its
first segment `b2` becomes a directory product under the root. Row 3 is the
same defect one level up. v7's own call site passes a DIRECTORY as the second
argument (`0b:72`, `CanonicalRoot`), which is the documented misuse. What I
would do: pass `Root` with a terminating `/`, which `filesex.pl:150-153`
documents as the directory form, and the three rows above become
`'../b2/x.dl7'`, `'c/x.dl7'`, `'../x.dl7'`. That changes which projects compile
and is a language-shaped decision, so it is the user's call. Code keeps v7.

**Fork 2. Fifteen of the sixteen identity passes are usually dead, and the
cap is silent when it is not enough.** `application_identities/4`
(`0c:490-498`) stops early when a pass resolves nothing (`:493-494`), so the
cap only bites on a chain of applications deeper than 16. When it does bite,
the unresolved results surface as `tsi_called_unresolved` (`0c:561-568`) and
nothing says the cap was the reason. What I would do: file a distinct
`tsi_application_cap(Passes)` diagnostic when the last pass still resolved
something. Not built; the code keeps the silent cap and the 16 from `0c:68`.

**Fork 3. `install_source_fact_graph/6` has no production caller.**
`load_source_fact_files/3` and `install_source_fact_graph/6` are exported and
tested (`test/5_source_fact_loader.test.pl`) but no `v7/src/**` file calls
them; the source-fact envelope shape is therefore pinned only by the test and
by `v6/sprefa-extract/tests/fixtures/source_facts/1_expected.json`. Ported in
full anyway, because deleting an export is not a port. Flagged so the
comptime lane knows the wiring is absent, not broken.

**Fork 4. `source_fact_read_error(Error)` cannot be byte-portable.** `0d:48-53`
catches ANY exception from reading and decoding a file and puts the raw SWI
exception term in the diagnostic. Measured on swipl 10.0.2:

```
missing file   error(existence_error(source_sink, "/no/such/file.json"), _)
bad JSON       error(syntax_error(json(illegal_json)),
                     stream(<stream>(0x60000393c000), 1, 2, 2))
```

The first carries an unbound variable, so the row is not ground and the
downstream `must_be(ground, Rows)` at `0d:288` would throw. The second carries
a stream handle address. Neither is a value another runtime can reproduce. The
port emits `source_fact_read_error(existence_error(source_sink, Path))` for a
missing or unreadable file and
`source_fact_read_error(syntax_error(json(illegal_json)))` for a root that does
not parse, and `v8/oracle/load/status.json` carries the row with the throw
site. What I would do in v7: narrow the `catch/3` to the read and decode
errors it means, and name them with codes of its own. Not built.

**Fork 5. A duplicate JSON object key is a hard error in SWI and a
last-wins in serde_json.** `atom_json_dict/3` raises
`error(duplicate_key(a), context(system:dict_create/3, _))`, measured. In
`0c:122` that exception is caught and becomes `tsi_line(_, _, not_json)`; in
`0d:57` it becomes `source_fact_read_error(...)`. serde_json keeps the last
value and reports no error. Detecting it needs a custom deserializer over
every object. Not built; `status.json` carries the row. No fixture in the
corpus has a duplicate key.

---

**Fork 6. A non-integer JSON number has no term in the v8 arena.**
`json_term/2` (`0d:263`) maps a JSON float to `number(Float)`. The arena at
`v8/src/_6_eval/_0_term.rs:18` carries `Int`, `Atom`, `Str` and `Compound` and
no float, and that file belongs to the eval lane. The port therefore fails the
envelope, which surfaces as `malformed_source_envelope(Position)` rather than a
`number/1` term. No number in the 57 frozen cases and none in
`v6/sprefa-extract/tests/fixtures/source_facts/1_expected.json` is a float or
outside `i64`, verified by a scan. What I would do: add a `Float` term to the
