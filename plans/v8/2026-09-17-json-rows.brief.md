## 1. Goal

`(fs.json ?Path ?Root)` reads a JSON file into `:` rows under one root node.
JSON is not a second value world (dl6 `rulings.pl:79`,
`plans/2026-07-27-json-arm.md`): an object is a level of `:` edges, an array
is a `cons` chain, a scalar is an `intern` of its primitive, null is `none`.

## 3. Before / after

Before: `fetch_json` returns the body as one text value (`_3_executors/fetch_json.rs:1-2`);
`term_from_json` (`_6_eval/_6_json.rs:26`) reads the transport encoding
(`{"a":..}`, `{"s":..}`, `{"f":..,"args":..}`), not arbitrary JSON.

After, `todo.json`:

```json
{"title": "x", "n": 3, "tags": ["a", "b"], "owner": null, "meta": {"v": 1}}
```

```
(fs.json "todo.json" ?Root)

(: ?Root title <intern text ["x"]>              0)
(: ?Root n     <intern int [3]>                 1)
(: ?Root tags  <cons "a" (cons "b" nil)>        2)
(: ?Root owner none                             3)
(: ?Root meta  <m>                              4)
(: <m>   v     <intern int [1]>                 0)
```

Every array element is itself an `intern` of its primitive (or a node for an
object). Keys keep document order as the index; no sorting (the graph carries
order, dl6 sorted because it stored text).

Then in a program:

```
(fs.json "todo.json" ?Doc)
(<- (todo_title ?T) (fs.json "todo.json" ?Doc) (: ?Doc title ?V ?_) (intern_snapshot text ?Args ?V) (cons ?T ?_ ?Args))
```

or by dot once `?Doc` is bound in a seed: `doc.meta.v`.

## 4. Null and absence

```
{"owner": null}   ->   (: root owner none 3)     present, null
{}                ->   no edge labelled owner     absent
```

`none` is a prelude node `(: none (*))`, the zero-column product, declared in
`prelude/0_constructors.dl7` beside `Option`. `(Option T)` inhabitants are `T`
values or `none`. Present-null and absent are two graphs; RFC 7396 sections 1
and 2 are spellable (`v6/prolog/conformance/fixtures/json_patch_fold.pl:128-144`
is the conformance case to port as a probe).
