# Plan: json aggregation heads + json scalar fns

dl stays flat in storage; nesting is OUTPUT built by SQLite's own json functions
(bundled SQLite 3.45 via libsqlite3-sys 0.28 — json core since 3.38, `ORDER BY`
inside aggregate since 3.44, both available). Composition is by stratification, no
new value model.

## 1. Type signatures

### ast.rs
```rust
// AggFn gains two variants; the object form is TWO-ARG.
pub enum AggFn { Count, Sum, Min, Max, JsonGroupArray, JsonGroupObject }

impl AggFn {
    pub fn parse(s: &str) -> Option<AggFn>   // + "json_group_array"/"json_group_object"
    pub fn sql(self) -> &'static str          // + "json_group_array"/"json_group_object"
    pub fn fixed_out(self) -> Option<Type>    // JsonGroup* => Some(Type::Text)
    pub fn is_two_arg(self) -> bool           // JsonGroupObject => true, else false
}

pub struct Rule {
    // ...
    pub aggs: Vec<Option<AggFn>>,
    // Parallel to `aggs`: the SECOND argument of a two-arg aggregate
    // (json_group_object(key, VALUE) — the value expr). `None` at every other
    // slot. Empty when the head carries no aggregate (mirrors `aggs`).
    pub agg_args2: Vec<Option<Term>>,
}
```
`terms[i]` holds the aggregate's FIRST arg (the key for the object form), `agg_args2[i]`
holds the second (the value). Output column i = the built json text.

## 2. Pseudo-code

### parse head_atom (parse.rs ~437)
```
is_agg = ident followed by '(' AND AggFn::parse(ident).is_some()
if is_agg:
    f = AggFn::parse(name)
    '('
    arg1 = term()
    if f.is_two_arg():  ','  arg2 = term();  agg_args2.push(Some(arg2))
    else:               agg_args2.push(None)
    ')'
    terms.push(arg1); aggs.push(Some(f))
else:
    terms.push(expr()); aggs.push(None); agg_args2.push(None)
// end: if no aggs, clear aggs AND agg_args2.
```

### lower agg SELECT expr (lower.rs ~350)
```
for (i, term) in head.terms:
  match aggs[i]:
    Some(f):
      arg = term==Wild ? "*" : term_sql(term)
      match f:
        Sum             => "COALESCE(SUM(arg), 0)"
        Count/Min/Max   => "F(arg)"
        JsonGroupArray  => Wild? bail; else "json_group_array(arg ORDER BY arg)"
        JsonGroupObject => v = term_sql(agg_args2[i]); "json_group_object(arg, v ORDER BY arg)"
    None: group.push(term_sql(term))
```

### term_sql Call json arms (lower.rs ~98)
```
"json_object" if args.len()>=2 && args.len()%2==0 => "json_object(a1, a2, ...)"
"json_array"  if !args.is_empty()                 => "json_array(a1, ...)"
"json"        if args.len()==1                    => "json(a1)"
```

### source-rule head refusal (typecheck check_rule_types top)
```
if rule.is_source():
  for term in head.terms: if term is Call w/ name in {json,json_object,json_array}: error "json-in-source"
  for agg in aggs: if agg in {JsonGroupArray, JsonGroupObject}: error "json-in-source"
```

## 3. Instance lifetimes

Nothing stateful added. `Rule.agg_args2` lives exactly as long as the parsed `Rule`
(program AST, rebuilt per load). No engine field, no meta table, no cache. The json
build happens inside SQLite at each `rebuild_derived` INSERT..SELECT — no Rust-side
state.

## 4. Storage / reads / writes / determinism

- Storage: unchanged. Head rel is an ordinary derived table with a Text column
  holding the json string. Feeds downstream rules by stratification (agg forces a
  higher stratum via the existing `has_agg()` edge in `stratify`/`stratify_diags`).
- SQL emitted:
  - `json_group_array(x)` -> `json_group_array(<x> ORDER BY <x>)`
  - `json_group_object(k, v)` -> `json_group_object(<k>, <v> ORDER BY <k>)`
  - `json_object(k1,v1,...)` -> `json_object(<k1>, <v1>, ...)`
  - `json_array(x1,...)` -> `json_array(<x1>, ...)`
  - `json(x)` -> `json(<x>)`
- DETERMINISM: `ORDER BY` inside the aggregate makes array/object element order a
  pure function of the group's rows, so the rel's content digest is stable tick to
  tick (no spurious daemon rebuild). Verified by a unit test asserting the bundled
  SQLite accepts `ORDER BY` in an aggregate call; if it ever regresses, the fallback
  is a windowed ordered subquery (documented, not shipped).
- Uniqueness: the agg SELECT is `INSERT OR IGNORE` like today's aggs; the whole json
  string is the value, no NULL-dedup concern (json_group_array of an empty group is
  `'[]'`, never NULL).
