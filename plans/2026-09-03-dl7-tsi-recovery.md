# DL7 TSI recovery boundary

## Context

The checked-out branch is `feature/dl7-source-intelligence` at
`f24ece60e` before the local changes recorded below. PR 689 contains the
executable Rust syntax path:

```text
Rust source
  -> Extract TSI JSONL
  -> DL7 TSI loader
  -> deterministic DL7 declarations
  -> owned generated region
  -> Soopy check or apply
```

The separate branch `feat/dl7-tsi-render` at `65bc6d070` contains later work.
It is preserved as evidence and is not an integration source. Its final diff
combines an approved empty-product spelling with dotted-atom semantics and a
global Go primitive prelude expansion that received no decision gate.

The compiler-effect target remains unimplemented. Its established contract is
that DL7 userland derives grounded effect calls, a current host dispatches those
calls, and returned observation rows enter another compiler fixpoint round.
Possible hosts include the current SWI compiler, the Rust runtime, and a later
emitted DBSP program. The transport and host language do not determine the
userland relation contract.

## Decisions

1. `()` is the DL7 source spelling for the empty product and empty tuple type.
   Extract may continue to call this primitive class `unit` on the TSI wire.
2. Type names retain their written spelling. The Rust type renderer emits `()`
   for the source name `()`.
3. This arc adds no dotted-atom parsing, dotted-path lookup, module lookup, or
   checker interpretation based on punctuation inside an atom.
4. PR 689 remains the executable oracle for Extract, TSI loading, rendering,
   owned-region replacement, and Soopy staging.
5. The Fable branch is not merged wholesale. Changes are recovered by named
   behavior and independently tested.
6. Go TSI rows remain source facts. This plan adds no global Go-named products
   to the DL7 prelude.
7. Compiler effects begin with userland relation signatures and host-neutral
   row shapes. Subprocess, C ABI, socket, and in-process dispatch remain
   transport candidates until the relation contract and lifecycle are fixed.
8. Output effects remain staged through the existing Soopy boundary. A compiler
   observation cannot directly mutate a source file.

Instance lifetime and storage:

1. The reader creates an ordinary `form([])` node for each written `()`.
2. Lowering resolves that node within the current owner for one compilation.
3. The prelude owns one `()` product node for the compiler process.
4. Each accepted TSI primitive id classified as `unit` resolves to that prelude
   node while the stream basement is installed.
5. The renderer writes `()` into generated bytes without storing an alias.

Read, write, and uniqueness sequence:

1. Read `form([])` or TSI class `unit`.
2. Read the current owner or prelude edge table.
3. Reuse the single matching `()` identity.
4. Write graph references or rendered bytes.
5. Existing duplicate-binding checks retain responsibility for uniqueness.

## Task 2: freeze the compiler-effect row contract

The first review artifact contains signatures and data shapes only. It adds no
dispatcher and changes no compiler call site.

Provisional host-neutral signatures:

```text
effect_call(
  effect_id,
  driver,
  operation,
  arguments,
  provenance
)

effect_observation(
  effect_id,
  relation,
  tuple,
  provenance
)

effect_failure(
  effect_id,
  code,
  detail,
  provenance
)
```

Body pseudocode:

```text
derive grounded effect_call rows from ordinary userland rules
freeze and sort calls at the end of compiler generation N
deduplicate by effect_id
dispatch calls absent from the accepted receipt set
validate observations against the declared relation arity
add observation rows to generation N + 1
repeat until compiler rows and accepted receipts are unchanged
```

Instance lifetime:

- an `effect_call` belongs to one logical compilation and may survive compiler
  generations inside it;
- an accepted observation remains available to every later generation of that
  compilation;
- a host process may outlive a compilation, while process lifetime remains
  outside the logical identity;
- output intentions survive until the final staged-output phase and never enter
  the observation dispatcher.

Storage, reads, writes, and uniqueness:

1. Compiler rows are the source of grounded calls.
2. A receipt table is read by `effect_id` before dispatch.
3. The host writes an observation batch or one named failure for that id.
4. The compiler validates and interns returned tuples.
5. Equal logical calls must produce one `effect_id` independent of row order,
   host process id, transport, or retry count.
6. Conflicting successful batches for one `effect_id` produce a diagnostic and
   add no observations.

Open items requiring review before hollow code:

- the exact DL7 declarations for arguments, tuples, and provenance;
- which relation declares a driver and its accepted operation shape;
- whether a returned tuple names its target relation directly or through a
  declared output edge;
- the stable identity inputs for source revisions and mutable worktrees.
