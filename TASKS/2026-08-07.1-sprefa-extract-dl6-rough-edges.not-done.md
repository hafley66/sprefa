# Sprefa-extract and DL6 rough edges

## Sprefa-extract

- Output is heterogeneous JSONL. `match`, `capture`, diagnostic, and summary records share one stream. Consumers must filter on `record` before projecting typed columns. Feeding the stream directly into DL6 caused `NULL` values in numeric capture columns.

- Related captures are emitted as separate rows. Reconstructing one logical AST match requires joining by query ID plus `match_start` and `match_end`.

- Syntax variants require separate patterns. `useState<T>(...)` needed a different pattern from `useState(...)`.

- Broad patterns overmatch. `$WRITER($NEXT)` captured constructors and unrelated calls alongside setters. Authority detection needs relations between declarations, bindings, references, and call sites.

- Captures provide byte spans. Rules requiring line and column information need source indexing or a span-to-line pass.

- Logical identity remains downstream work. The extractor can report:

  ```text
  nodes
  nodesSignal initialized from nodes
  nodesSubject initialized from nodes
  ```

  Grouping these into one authority belongs in a DL6 relation or join.

- Two query languages are exposed:

  ```text
  --ast-pattern      ast-grep patterns
  extract query      Tree-sitter queries
  ```

  Query packs do not currently hide that split behind one reusable named specification.

## DL6

- There are two language surfaces:

  ```text
  v6/prolog/compile/parse_dl.pl   full DL6 parser
  v6/dl/grammar/dl.langium       narrow TypeScript MVP grammar
  ```

  Native CST syntax exists in the Prolog compiler:

  ```dl
  cst(file_path, blob_digest, ts) {
    (comment) @comment_text
  }
  ```

  The TypeScript server rejected that syntax, along with `bind`, tuple host output declarations, and other fixtures from the full language.

- The native CST compiler path exists across:

  ```text
  v6/prolog/compile/parse_dl.pl
  v6/prolog/0_ast_expand.pl
  v6/prolog/0_program_check.pl
  v6/prolog/1_host_expand.pl
  v6/prolog/print_dl.pl
  ```

  `native_ts_query_term` also reaches generated TSV2 code. The remaining verification target is the production runtime executor for the generated `tree_sitter` host plan.

- Host response projection trusts row shape too far. The test passed heterogeneous sprefa-extract records into a typed host response and crashed with:

  ```text
  numeric NULL in rel '__resp_extract' column 'start'
  ```

  Missing fields should become rejected rows or diagnostics before relation insertion.

- A host ingestion error terminates the server's top-level subscription. A malformed lint query can stop unrelated processing.

- Builtin relation schemas are implicit and strict:

  ```text
  file(path, content_hash)
  diag has 9 columns
  ```

  Redeclaration produced late SQL errors such as `no such column b0.content_hash`. Partial positional `diag` heads produced binding errors.

- Persisted databases retain incompatible relation schemas after program changes. A fresh database was required during the lab.

- HTTP EDB insertion requires:

  ```json
  { "rows": [["path", "digest"]] }
  ```

  A single row object without `rows` was accepted as an empty batch, which made a failed setup appear successful.

- Native CST captures have compiler-specific binding rules. Head variables must correspond to capture names, excluding special source-position fields. The checks exist, but the contract is currently discovered through fixtures and compiler diagnostics.

## Target pipeline

```text
file relation
  -> native DL6 cst(...) clause
  -> tree_sitter host demand
  -> typed capture relation
  -> joins grouping React, Signal, and RxJS ownership
  -> diagnostic relation
```

The runnable TypeScript MVP forced this path during the lab:

```text
DL6 shell host
  -> sprefa-extract CLI
  -> jq record filtering
  -> typed response relation
```

That path exposed the row-shape crash and bypassed the native CST compiler path.

## Follow-up: diff subscription counting

The Instant canvas-composition worktree exposed one input-shape requirement for the proposed static rule:

- `git diff` contains tracked additions only. The canvas implementation was untracked, so a rule fed only unified diff text reported no green-code call sites while the source tree contained the implementation. A repository rule needs the union of tracked added lines and complete untracked files.

Observed counts on 2026-08-07:

```text
Instant canvas-composition added implementation: 0 .subscribe(...) calls
react-dock-and-flow model source:              1 terminal .subscribe() call
```

The library subscription is the model lifetime in `packages/react-dock-and-flow/src/1_model.ts`; the model returns `dispose()` which unsubscribes it. React and canvas callers write events through `model.events.$(...)` and read state through signal access.
