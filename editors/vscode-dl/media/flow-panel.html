Default view: a filesystem-snippet listing where every row is a node and edges are bracket arcs in the side gutters.

click a rowpin (same pin set as canvas; folder/file rows pin too)

BOM table

The BOM table preset (.dl/bom.dl) adds a right-aligned numeric band to each part row: members (direct children), fan-in (where-used), fan-out (depends-on), weight (a callable's span lines). Sort chips reorder siblings by any column (fan-in descending by default = most depended-on first). A collapsed group's band shows its subtree totals.

query contract

Columns are positional, read left to right — extra columns are ignored.

node queryid, label?, kind?, file?, line?, parent? (id repeats as label when absent; parent nests a node under another node's row in list view)
edge querysrc, dst, kind? (src/dst are node ids)

Edges whose src/dst id has no matching node row are dropped and counted in the pill.

Customwhatever SQL is in the two boxes below; editing either box switches here automatically
Layers (discovered)checkbox list of every rel_<name>_node + rel_<name>_edge pair the daemon's schema exposes; toggle one or more to UNION ALL them into a composed graph. Column names bind to roles by name (id/sym→identity, label/name→display, kind→chip, file/path→fs-tree, line→jump, parent→nesting). Write a .dl declaring foo_node(sym,name,kind,file,line) + foo_edge(src,dst,kind), click ↻, and it appears — no preset edit, no SQL

troubleshooting

  • no such table: rel_X — the running daemon isn't serving a .dl program that references X; check what's loaded.
  • "linked only" hides nodes with no kept edges (isolated nodes); toggle it off to see everything the node query returned.
