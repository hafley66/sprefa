# pipeline: pain points surfaced during min-demo

Friction that appeared while writing the ~160 LoC across `_0_cursor.rs`,
`_1_op.rs`, `_2_pipeline.rs`, and the 6 passing tests. Ranked by how
much they force a design move versus staying additive.

## Severity 1 — forces a design move before more ops land

### 1.1 `type Slot` versus object-safe `Box<dyn Op>`

The natural spelling of the Op trait is:

```rust
trait Op {
    type Slot: Any + Send + Sync = ();
    async fn pipe(&self, ctx: &RtCtx, c: Cursor) -> Vec<Cursor>;
}
```

`Pipeline::Op(Box<dyn Op>)` rejects it — object safety forbids
associated types on trait objects. Either:

- **A. Split metadata trait.** `trait OpMeta { type Slot; const NAME: &str; }`
  as a companion; `impl Op for T where T: OpMeta` generated by a macro.
  Op stays object-safe; OpMeta powers the pipeline typechecker at LSP
  parse time.
- **B. Monomorphize Pipeline per composition.** Pipeline becomes generic
  over its op tree; codegen drives it from `.sprf` at Rust-compile time.
  Works for bench harnesses and embedded sites; runtime-parsed
  pipelines still need the dyn path.

Until this is decided, slot read/write stays TypeId-keyed (`c.put_slot<T>`
/ `c.get_slot<T>`), with no static verification that a reader has a
writer upstream. Pipelines that break the contract fail at runtime
inside `ReadStampOp::expect`.

### 1.2 `get_slot::<T>()` returns `Arc<T>`, authors fight the deref-move

Test surface for reading a slot back:

```rust
out[0].get_slot::<Stamped>().map(|a| (*a).clone())  // needs T: Clone
```

The author-facing readout wants one of:

- **Return `Option<&T>` bound to cursor lifetime.** Removes clone cost,
  ties access to cursor borrow; problematic across await points.
- **Require `T: Clone` on the slot and return `Option<T>`.** Ergonomic;
  forces a bound on every slot-typed payload.
- **Return a `SlotGuard<T>` wrapper** that derefs to `&T` and exposes a
  `to_owned()` method. Mid-weight; lets authors choose per call.

Current shape (`Arc<T>`) is the rawest one; it was chosen so Fork-arm
clone stays a refcount bump, but the read ergonomics at the op site are
bad and showed up immediately in the tests. Pick the shape before the
second real op lands.

### 1.3 Slot lifecycle is a *contract*, not enforced by types

`rebase()` clears slots per the contract, but `pub content` and
`pub byte_range` are accessible on `Cursor`, so an op can mutate them
directly and bypass rebase. A `ParsedTree` left in a slot then points
at stale bytes. Options:

- Privatize `content` / `byte_range`; force mutation through `rebase`
  and `narrow` only.
- Keep public, add a `content_version: u64` bumped on rebase; typed
  slot wrappers include a version tag and assert match on read.
- Do nothing, rely on discipline. Cheap now; pays later.

## Severity 2 — new machinery needed, fits the trait shape

### 2.1 Per-cursor `pipe` signature vs v2's batch-prefetch pattern

`v2/src/ops/_9_ast_grep.rs:279-400` prefetches bytes for N cursors and
rayon-maps. That pattern depends on the op seeing the full batch. The
v3 FINDINGS.md §5.2 answer: push batching into the *effect* layer (one
`ctx.put::<ReadBytesBatch>(Vec<path>)`). Works for read and scan. It
does not cover ops whose decision is cross-cursor (group-bys, joins,
top-k). A follow-up slice needs a `pipe_batch(Vec<Cursor>) ->
Vec<Cursor>` method for that class, with per-cursor as the default.

### 2.2 Fork input materialization cost

Current runner clones the full `Vec<Cursor>` per arm. v2's shape is
`BoxStream<Arc<[Cursor]>>` with a broadcast channel (per
`project_v2_runner_parallelism`). The streaming shape is the next
slice once the concrete trait stabilizes; for now N × arms cursors
live in memory simultaneously.

### 2.3 Path tagging timing

Runner appends `PathSeg::Op` *after* receiving `Vec<Cursor>` from
`pipe`. An op that wants to emit a diagnostic referencing its final
path can only reference its *input* path, not its output. Fix is to
pass the would-be-leaf seg into `pipe` as context, or to expose a
`ctx.path_preview()` helper. Trivially additive.

## Severity 3 — additive, no trait impact

### 3.1 `#[allow(non_snake_case)]` on every `_N_name` module

The numeric-prefix file convention (per CLAUDE.md) collides with
rustc's `non_snake_case` lint on module names. Three annotations in
`lib.rs` take care of it. Lint-level shim rather than design friction.

### 3.2 No initial-cursor source

Tests construct `Cursor::new(Arc::from(bytes))` directly. A `Source`
trait (or a `Pipeline::Source(Box<dyn Source>)` variant) is required
for real pipelines driven by `.sprf`-declared fs-glob/repo/rev inputs.

### 3.3 Captures only has `SpanBacked` shape

`Capture { name, byte_range }` covers the common case. `CaptureKind`
trait (SpanBacked / Synthesized / cross-repo / …) is a follow-up; the
current shape parks the extension point as `Vec<Capture>` and a
single struct.

### 3.4 No `Diagnostic` surface on `RtCtx`

Ops cannot emit soft errors. `effect_runtime::RtCtx` has no
`emit_diag` hook yet. Additive; doesn't affect Op or Pipeline shape.

### 3.5 No cancellation token on `pipe`

Mirrors FINDINGS.md §8 "Cancellation propagation through the plugin
surface." Same token that lands on `RtCtx::put` flows into `Op::pipe`
as a `CancellationToken` arg, or via `ctx`.

## Deferred (explicitly out of this slice, recorded for traceability)

- Scan pointers (`$$sigil`) and the demand loop — pipeline-layer
  concern; drives re-run, needs `ResultStore` writes.
- Sub-lang registration (ast_grep / regex / sql / sem) — hangs off Op
  via a metadata trait; doesn't alter Pipeline shape.
- Writer/effects split with approval prompts — covered by
  `BoundedBatched` wiring in `effect_runtime`; op code is `ctx.put` and
  nothing more.
- ParseSite / content-contract PATH-A (slot-cached bytes) / PATH-C
  (reader fallback) — ops already have PATH-B via `c.active()`;
  PATH-A is a slot read, PATH-C is an effect call. Both fit without
  trait changes.

## Recommended next slice (narrowest)

Close Severity 1.1 and 1.2 in one move:

1. Add `trait OpMeta { type Slot; const NAME: &str; }` as a separate
   companion; provide a macro that derives `Op` from an `OpMeta +
   pipe_inner` pair.
2. Switch `get_slot` to `Option<T>` with `T: Clone`, or to a
   `SlotGuard<T>` wrapper — whichever the first real op prefers after
   one round.

Everything else holds.
