## Problem/Context
- Two planes share the graph: cascade (Z-set, `cx_row`/`cx_dep`, prune=weight≠0) and
  reconcile (salsa-in-SQL, `rx_memo`/`rx_dep`, prune=digest-moved). Open question was
  whether collapsing them into one `g_node(key,weight,digest,changed_at,verified_at)`
  + `g_edge(src,dst)` saves storage (the "Collapsed" layout) vs the split pair.
- `Layout { Split, Collapsed }` + `stamp(db, layout)` + `RelStore::attach_with` were
  added (Epic 1) to measure it. `measure_storage` (resident corpus) and
  `measure_storage_scaled(layers,width)` (streaming, heap≈0) load the benchgraph
  corpus under each layout, checkpoint WAL, read main-file bytes.
- The v6 law: Rust heap ≈ 0 (state on disk, RSS = page cache). So a multi-GB corpus
  must be STREAMED, not held resident — `measure_storage_scaled` does this (keys by
  monotonic global id; `parents_of(g,width)` reproduces `gen_multi`'s node+edge counts
  exactly, proven by a shape-parity test).

## Solution/Approach
- **Measurement (Epic 1, done):** streaming generator + WAL-checkpoint byte count.
  Calibrated trend was stable across two orders of magnitude; ran the literal ~5 GB point.
- **Verdict — collapse REJECTED on storage:**
  - 1,602 nodes: collapsed/split = 0.94 (collapsed wins — pure fixed table-overhead)
  - 300K nodes: 1.046 · 2M nodes: 1.046 · **82M nodes / 5.66 GB: 1.040** (+234 MB)
  - The 4 dead value columns per `g_node` (digest/changed_at/verified_at) cost more
    than the second table+index saved, at every scale past the fixed-overhead regime.
  - Per-unit: ~21.6 B/element split, ~22.6 collapsed.
- **Pivot — namespace-generic, NOT a shape change.** The split pair is the one shape.
  Make it stampable/runnable multiple times independently in one db.
- **Mechanism is FORCED to a name prefix (not SQLite schema-qualify/ATTACH):** TEMP
  working tables (`cx_frontier`, `cx_next`, …) live in `temp.` and CANNOT be
  qualified to an ATTACH'd schema, so schema-qualify cannot disambiguate the per-store
  working set. Prefix is the only namespace covering it. Not a fork.
- **`GraphNs`** (declared in `relstore`, lib.rs): 14 fields — every persistent table,
  index, and TEMP working-table name — built by `GraphNs::new(prefix)` (prepended
  verbatim; `"b_"` for a namespace, `""` for the live default). `Default::default() =
  new("")`. Referenced by the mind's `GraphStorePlan` so it compiles; not yet used by
  the engine.

## Key Insights
- Collapse loses on storage at every scale that matters (+4%); the small-corpus win was
  fixed table-overhead from the extra empty `rx_*` tables.
- SQLite TEMP tables can't be schema-qualified → prefix is the FORCED namespace mechanism.
- `parents_of(g, width)` is a pure function (no resident structure) → multi-GB corpus
  streams with heap≈0, satisfying the v6 law.
- Streaming keys by monotonic global id is storage-faithful (byte cost is
  key-VALUE-independent); the multi-relation `tag*STRIDE+local` keying is a
  correctness-test concern, not a storage one. (Resident `measure_storage` and scaled
  differ in absolute bytes due to key-order b-tree fill, but Split-vs-Collapsed stays
  comparable within each path.)
- The per-tuple-reconcile granularity unlock was collapse's REAL aim — it does not
  require collapse; measure it on the split shape.
