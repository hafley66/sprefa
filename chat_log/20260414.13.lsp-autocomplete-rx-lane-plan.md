## Problem/Context
User correction earlier in parent session: partial evaluation must fall out of the existing runner, not a parallel `scan_partial` universe. "Min entity, low entropy." Additional refinement this session: LSP is read-only (Writer NoOp, _write ops short-circuit), so a tolerant/fragment parser is safe at runtime. Two parse doors (strict compile-time, tolerant LSP runtime), one runner. Resolves the `rev(ma|` dead-end where span_ix had no entry.

Verification discipline: the LSP logic in analysis.rs is pure of tower. Integration testing must happen at the `DocSession::complete_in_paren(source, pos) -> Vec<CompletionSuggestion>` boundary in cargo tests. The tower bin is thin glue — final manual smoke in an editor is only the finale, not the correctness gate.

## Solution/Approach
Split the work into four parallel lanes + two gates, expressed in rx-operator shape.

Lanes (parallel):
- switch_map_parse$ — add tolerant parse mode for LSP ctx, synthesize fragment op in span_ix for in-progress syntax like `rev(ma|`. Strict parser untouched.
- merge_map_runner$ — extract `run_pipelines(&[(Arc<str>, Pipeline)]) -> RunReport` core from `ensure_run` in analysis.rs. ensure_run becomes one caller; complete_in_paren becomes the other.
- map_rewrite_pipeline$ — pure helper `truncate_and_substitute(p: &Pipeline, at: &[usize], wildcard: Arc<dyn Op>) -> Pipeline` handling Op/Seq/Fork variants per span_ix op_path encoding.
- tap_lsp_glue$ — wire `session.set_workspace_root(...)` into open_or_replace in sprefa_v2_lsp.rs.

Joins:
- pure_core$ = combineLatest(A,B,C) → rewrite `complete_in_paren` to resolve op_path from span_ix, call truncate_and_substitute with wildcard_instance, call run_pipelines with singleton rewritten pipeline, harvest RunReport.cursors_by_rule[rule], map through wildcard_op.witness(), dedup, filter by partial, cap 1000.
- Gate 1 — integration$: cargo test at DocSession boundary with cases for repo/rev/fs paren completion + `rev(ma|` tolerant parse. No tower involved. This is the correctness gate.
- tap_lsp_glue$ attaches after integration is green.
- shadow_teardown$ = filter(merge_map_runner.extracted).tap(delete scan_partial, seed_cursors).ignoreElements() — runs in parallel once the runner extract provides the reuse point.
- Gate 2 — final_smoke$ = zip(tap_lsp_glue$, shadow_teardown$) → human opens .sprf, types `repo(|`, eyeballs real values. Finale only.

Topology:
```
  A ─┐
  B ─┼─▶ pure_core ─▶ integration$ ─▶ tap_lsp_glue ─┐
  C ─┘                                              │
                                                    ├─▶ final_smoke
  B ──────────────────▶ shadow_teardown ────────────┘
```

Subagent assignments (one-shot spawn, all four in parallel when starting next session):
- agent_A — switch_map_parse: parser + synthetic span_ix entry
- agent_B — merge_map_runner: analysis.rs ensure_run → run_pipelines
- agent_C — map_rewrite_pipeline: truncate_and_substitute
- agent_D — tap_lsp_glue: bin/sprefa_v2_lsp.rs workspace_root wiring
- main thread — writes pure_core (complete_in_paren rewrite), integration test cases, shadow_teardown cleanup, final smoke

## Key Insights
- Two parse doors, one runner. LSP's read-only guarantee (Writer NoOp, _write short-circuits) makes tolerant parse safe. Saved as project_v2_parse_modes.md in memory.
- Integration test at the DocSession boundary is the correctness gate, not an editor smoke. tower bin is thin glue — pure core proves itself in cargo.
- rx-operator shape is the right abstraction for sequencing: switchMap/mergeMap/map/tap name the lanes; combineLatest is the gate; zip is the finale; ignoreElements is the "fire side effect, signal done, emit nothing" pattern for teardown.
- Shadow teardown is gated on merge_map_runner$ emitting — the runner extract is what creates the reuse point that makes scan_partial obsolete.
- final_smoke is one editor session, not a verification tool. Use it only after integration is green and tower is wired.
