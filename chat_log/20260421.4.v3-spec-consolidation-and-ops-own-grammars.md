Three intertwined rips this session:

1. Purge `$$` ans-ref sigil from the v3 surface. Scan-pointer becomes
   an ordinary op taking a bound term; `Cursor.last_bound` stays as the
   mechanic (the bash `$?` equivalent), but no user-facing `$$` syntax.

   (`v3-unified-language-locks.md`) and parse-facing spec (`parse.md`)

   re / json / ast / sh are all ops with paren-or-brace bodies, each
   shipping its own `grammar.js` + `highlights.scm` + optional

   pattern surface. `$NAME` inside a pattern body is a first-class
   term_ref CST node in the op-owned injected sub-tree.

   impl point (§1.5 layout, §1.6 dep DAG, §1.7 op partition rules,

## Problem/Context

### Why kill `$$`

User realized `$$` was the wrong abstraction. It promoted the implicit
binding (bash `$?`) into user-visible syntax. Annotate-by-reference
doesn't need a sigil — it's just an op that reads `cursor.last_bound`.
The previous session had added `$$` + `AnsRefOp`; this session ripped
it back out. `last_bound` the *field* is kept because the mechanic is
useful (scan-pointer ops, tag-ops get ergonomics).

### Why merge locks into parse.md

Three source-of-truth docs for the same language:
`v3-unified-language-locks.md`, `parse.md`, and
`v2/docs/_b_v3-unified-language.md` (teaching doc). Locks and parse.md
had ~40% overlap and several direct contradictions around `$$` and
scan-pointer. User directive: "spec as source of truth, only 1."

Chose `v3/crates/sprefa_parse/parse.md` as the canonical location
because (a) user moved it there mid-session from `sprefa/src/`,
(b) living next to the code reduces drift, (c) teaching doc stays as
companion essay.

### Why ops-own-grammars (§14 rewrite)

Earlier in session I sketched "patterns are string literals with
host-owned sort" — user corrected: that doesn't deliver LSP hover on
`$NAME` inside a pattern because the string is opaque to the tree.
Next sketch: "HoleExtractor trait per op" — user re-corrected: that's
v2's `binds_captures` + `hover_capture` contract reinvented; plus the
engines natively know their own captures (regex named groups,
ast-grep metavars, json walker fields).

User's final shape: str/glob/re/json/ast/sh are all ops, paren/brace
bodies, no string literals for patterns. `$NAME` inside is a
term_ref CST node because each pattern sub-grammar emits term_ref
identically. LSP hover works by dispatching via node kind. Every op
is self-contained (grammar + queries + Rust impl in one folder).
Dogfood endpoint: sprf rule regenerates sub-grammar crates from op
declarations.

### Why §1 crate layout

User: "how do we handle the crate layout for partitioning this logic
cleanly." Spec needed an architectural section so impl work could
reference it per step. Landed partitioning rules + rejected
alternatives so future re-entries don't re-litigate.

## Solution / Approach

### Pattern op surface (§14)

One-line summary: **patterns are ops, holes are term_ref nodes,
sub-grammars live in op folders, build-script wires it all up,
framework has zero pattern-DSL-specific code.**

Key insight: tree-sitter **injection queries** let the host grammar
point at a child node and say "parse that range with this other
language." LSP walks both trees seamlessly. Carveouts `${...}` inside
a pattern body produce carveout_expr nodes in the injected tree,
which the host LSP dispatcher routes back to host hover — recursion
falls out for free.

Shared-token coherence: every pattern grammar spreads a shared JS
fragment defining `term_ref` + `carveout_expr` identically. Build-script
greps for the spread to prevent drift. No external C scanner (300-line
tree-sitter scanners rejected as over-engineered for a two-token
surface).

### Crate partitioning (§1)

All pattern ops in one `pipeline` crate. Each op is a folder
(`src/ops/<name>/`). `pipeline/build.rs` is the single codegen driver:
walks folders, runs `tree-sitter generate`, compiles, writes
`op_languages.rs` + `tree-sitter-sprefa/queries/injections.scm`.

`injections.scm` is the only committed generated file — it lives with
the host grammar crate (so external consumers get it alongside the
parser) but is written by pipeline's build.rs (which knows the op
registry). No cyclic dep because tree-sitter-sprefa doesn't consume
the injections file at parse time.

Ops promote to their own crate when >5kloc or when a third-party
plugin; default is co-located in pipeline.

## Key Insights

1. **`last_bound` is the mechanic; `$$` was a mistake.** Scan-pointer
   and annotate-by-ref ops read `cursor.last_bound` directly; the
   author never writes `$$`. Removing the sigil simplifies the
   grammar without losing the ergonomics.

2. **Patterns are ops, not string formats.** Putting the DSL body
   inside `()` instead of `""` gives `$NAME` a first-class CST node
   (term_ref) which makes LSP hover a free consequence of tree
   structure. No string-scanning phase, no HoleExtractor trait, no
   core-patterns crate — just one trait slot (`language()`) and the
   existing `binds_captures` / `hover_capture` v2 contract.

3. **Tree-sitter injection queries are the production-proven shape.**
   Markdown-inside-code-fence is the same mechanism. Pattern grammars
   are just injected languages named by op name.

4. **Shared tokens via Node `require`, not external scanner.**
   tree-sitter external scanners are 300-line C state machines — way
   over-engineered for two tokens (term_ref + carveout_expr). Shared
   JS fragment + build-script drift-grep beats it on every axis.

5. **Spec is reference material, not narrative.** Merging locks into
   parse.md means every impl point has one place to cite. Seven-part
   TOC puts foundations first, grammar second, semantics third —
   reading order maps to build order.

6. **One `pipeline` crate for built-in ops.** Each op is a folder.
   Co-location is the default; promotion to own-crate only for plugin
   or >5kloc. Ten-crate explosion avoided.

7. **`injections.scm` ownership split**: file lives in
   tree-sitter-sprefa (ships with parser distribution), written by
   pipeline's build.rs (knows op registry). No cycle because
   tree-sitter-sprefa doesn't consume it at parse time.

8. **Carveout recursion in pattern bodies falls out of tree
   structure.** Every pattern grammar emits `carveout_expr` nodes via
   the shared rule; LSP dispatcher matches by kind and recurses back
   to host grammar hover. Zero extra machinery.

## Open Questions

1. **`str(...)` body: verbatim bytes or atom sequence?** Grammar rule
   for `str` needs to decide whether whitespace/punctuation are
   preserved literally or tokenized like other slot bodies. Leaning
   verbatim (one big string_fragment node) so `str(hello world !)` is
   literal bytes.

2. **Ops with brace bodies vs paren bodies for patterns.** `ast[lang]
   { ... }` uses brace; most others (str/glob/re) use paren. Should
   the injection registry key on op name (current spec) or on
   (op_name, slot_kind)? Current: op name, with op declaring one
   primary pattern slot. Multi-pattern-slot ops (e.g. `link(:kind,
   glob_pattern, re_pattern)`) need more thought.

3. **`#[sprf_pattern_op]` proc-macro arg shape.** Current sketch just
   takes `name = "glob"`. Might need `slot = "paren"|"brace"`, or
   separate attrs for language + highlights paths. Decide at macro
   crate creation time.

4. **Build ordering.** `pipeline/build.rs` writes
   `tree-sitter-sprefa/queries/injections.scm`. If pipeline depends
   on tree-sitter-sprefa (for compiled host parser), does tree-sitter-sprefa
   see the updated injections on its next build? Answer: yes, because
   injections.scm is runtime-consumed only. But cargo's dep graph
   needs checking. May need `rerun-if-changed` triggers.

5. **Where does `sprefa_macros` crate live?** Proc-macro crates can't
   be part of the same crate as consumers. Needs a new workspace
   member at `v3/crates/sprefa_macros/`. Confirm Cargo
   `resolver = "2"` handling.

6. **`tree-sitter-cli` as build-dep.** Running `tree-sitter generate`
   at build time means either shelling out to a system-installed
   binary (unreliable) or vendoring the CLI as a Rust dep
   (`tree-sitter-cli` crate). Latter is heavier but deterministic.

7. **Injected tree lifetime through Pipeline.** Each `InjectedTree`
   holds an `Arc<Tree>`. When lowering produces `Pipeline::Op(Box<dyn
   Op>)`, the op captures its own `Arc<Tree>` + node path (per
   Session 20260421.3 decision). Still the right shape for pattern
   ops.

    ```js
    });
    ```
    (strategy: accept any bytes; term_ref inside is parseable but
     `compile()` rejects it → `pattern/str-forbids-hole` diag)

  - `queries/highlights.scm`:
    ```scheme
    (str_byte) @string
    (term_ref) @error
    ```

  - `mod.rs`:
    ```rust
    use sprefa_macros::sprf_pattern_op;
    use crate::pattern_op::{PatternOp, CompiledPattern};

    #[sprf_pattern_op(name = "str")]
    pub struct StrOp;

    impl PatternOp for StrOp {
        fn compile(&self, tree: &Tree, bytes: &[u8]) -> Result<CompiledPattern, Vec<Diagnostic>> {
            // walk tree; if any term_ref node, emit pattern/str-forbids-hole
            // else return CompiledPattern::Str(Arc<str>)
        }
        fn binds_captures(&self, _tree: &Tree) -> Vec<Arc<str>> { Vec::new() }
        fn pattern_pipe<'a>(&'a self, _ctx: &'a RtCtx, c: Cursor) -> BoxFuture<'a, Vec<Cursor>> {
            Box::pin(async move { vec![c] })  // str is inert; just flows
        }
    }
    ```

- **Rationale**: str's role is mostly diagnostic. It validates the
  build pipeline end-to-end with minimal matcher code.

### Step 4 — `pipeline/build.rs` codegen driver (~200 LoC)

- **File**: `v3/crates/pipeline/build.rs` (new)
- Responsibilities:
  1. Walk `src/ops/*/grammar.js` → `Vec<(op_name, grammar_path)>`
  2. For each: run `tree-sitter generate` via `std::process::Command`
     or `tree-sitter-generate` crate; output `OUT_DIR/ops/<name>/parser.c`
  3. `cc::Build` per op: compile `parser.c` + optional `scanner.c`
     into separate static libs; link each
  4. Emit `OUT_DIR/op_languages.rs`:
     ```rust
     use tree_sitter::Language;
     extern "C" { fn tree_sitter_sprefa_str() -> Language; /* per op */ }
     pub fn language_of(name: &str) -> Option<Language> {
         match name { "str" => Some(unsafe { tree_sitter_sprefa_str() }), _ => None }
     }
     pub fn highlights_of(name: &str) -> Option<&'static str> {
         match name {
             "str" => Some(include_str!("../src/ops/str/queries/highlights.scm")),
             _ => None,
         }
     }
     ```
  5. Regenerate `v3/crates/tree-sitter-sprefa/queries/injections.scm`:
     one `#match?` block with an alternation of op names
  6. Grep each `grammar.js` for `...shared($)`; `panic!` if missing

- **Cargo.toml**:
  ```toml
  [build-dependencies]
  cc = "1"
  tree-sitter-generate = "…" # or shell-out to CLI
  ```

- **File**: `v3/crates/pipeline/src/lib.rs` (modify)
  - add `pub mod op_languages { include!(concat!(env!("OUT_DIR"), "/op_languages.rs")); }`

- **Rationale**: single codegen driver. Adding ops later = new folder,
  nothing else.

### Step 5 — injected-tree support in `sprefa_parse`

- **File**: `v3/crates/sprefa_parse/src/ast.rs` (modify)
  ```rust
  pub struct ParsedSource {
      pub host: Arc<Tree>,
      pub pipes: Vec<Pipe>,
      pub injected: Vec<InjectedTree>,
  }

  pub struct InjectedTree {
      pub host_node: Arc<ParseSite>,
      pub language_name: Arc<str>,
      pub tree: Arc<Tree>,
  }
  ```

- **File**: `v3/crates/sprefa_parse/src/parse.rs` (modify)
  - after host parse, walk for `op_invocation` nodes; look up language
    via an injectable function (sprefa_parse can't depend on pipeline;
    take `&dyn Fn(&str) -> Option<Language>` as an arg to `host_parse`)
  - for each, parse the paren body with `set_included_ranges`
  - collect into `Vec<InjectedTree>`

- **Design note**: sprefa_parse stays leaf. Caller (pipeline or
  runtime) supplies the language-lookup closure. Default is "no
  injection" which preserves existing behavior.

### Step 6 — `glob` op (real matcher)

- **Folder**: `v3/crates/pipeline/src/ops/glob/` (new)
- Grammar accepts: literal segments, `**`, `*`, `?`, `term_ref`,
  `carveout_expr`
- `compile()` walks tree: literal → `Segment::Bytes(b)`, `**` →
  `Segment::DoubleStar`, `*` → `Segment::Star`, `term_ref` →
  `Segment::Hole { name }`, carveout → `Segment::Computed(pipeline)`
- `binds_captures` walks for term_ref kind, returns `Vec<Arc<str>>`
- `pattern_pipe`: for incoming cursor, walk fs (or use existing fs op?
  design open); emit one cursor per match with captures bound

### Step 7 — `re` op

- Grammar: literal, char_class, quantifier, alternation, group,
  named_group, term_ref, carveout_expr
- `compile()` rewrites tree to standard regex string: `term_ref` →
  `(?P<NAME>.*?)`; `named_group` passes through; carveout → a synthesized
  regex-escape of carveout bytes (TBD — carveout inside regex body is
  advanced)
- Use `regex` crate for actual matching
- `binds_captures` collects both `term_ref` names and native
  `named_group` names

### Step 8 — tests

- Per-op unit tests in `pipeline/src/ops/<op>/mod.rs`
- Integration test `pipeline/tests/pattern_ops.rs`:
  - `str(hello world)` → one cursor, no captures
  - `str(hello $NAME)` → parse error `pattern/str-forbids-hole`
  - `glob(**/$DIR/file.txt)` → matches, binds `DIR`
  - `re(TODO\($WHO\))` → matches, binds `WHO`
  - `re((?<W>\w+))` → native capture surfaces as `W`

- CI lint: `cargo build -p pipeline && git diff --exit-code
  tree-sitter-sprefa/queries/injections.scm` catches drift

### Risk table

| risk | mitigation |
|---|---|
| `tree-sitter-cli` as build-dep is heavy | option: commit per-op `parser.c` like tree-sitter-sprefa already does; build.rs only orchestrates `cc` |
| proc-macro hygiene with `include_str!` paths | use `CARGO_MANIFEST_DIR`-relative paths in the macro expansion |
| shared/tokens.js drift between ops | build.rs grep-assert + error-on-miss; CI enforces |
| injections.scm merge conflicts (multi-author) | make it deterministic (sorted op names) so regeneration is stable |
| tree-sitter Language lifetime — static vs dyn | use `tree-sitter-language` crate's `LanguageFn` pattern (already how tree-sitter-sprefa binds) |
