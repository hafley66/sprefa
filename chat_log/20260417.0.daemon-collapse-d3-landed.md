## Locked decisions from this session
1. **tower-lsp bridge over WebSocket** — preferred over hand-rolled JSON-RPC dispatch. `tokio::io::duplex` is the seam; tower-lsp thinks it's talking to stdin/stdout.
2. **`<memory>` sentinel** — `source_path: None` → `FilePath(Arc::from(Path::new("<memory>")))`. Workspace still resolves via `workspace_hint` fallback (cwd).
3. **`sprefa stop` is the canonical shutdown** — POST /shutdown trips cancel_root. SIGTERM now handled too. SIGINT already worked. No more `pkill`.
4. **LSP smoke stays in Rust** — WebSocket + Content-Length reframing is painful to script; `tests/lsp_smoke.rs` already covers the Backend path via stdio. Daemon-backed LSP smoke lands in Rust when D5 ships auto-spawn.
5. **Smoke dogfoods sprefa itself** — no external `ext/sem` dependency. `_1_run.sh` runs g1_fns.sprf against the sprefa repo root.
6. **Legacy `sprefa-v2-lsp` binary kept** — until D5 reshapes the Rust smoke for daemon mode.

## Open critical issue — BLOCKS NEXT SESSION
**Smoke runtime is 38 seconds.** `bash tests/smoke/_9_all.sh` takes `real 0m38.344s`. User flagged this immediately as unacceptable. Must debug in next round before anything else.

Hypotheses to test (do not fix yet):
1. `_1_run.sh` runs g1_fns.sprf against the whole sprefa repo across every branch (test/3, test/2, master, HEAD, etc). ast-grep over N branches × M files compounds. `sprefa-v2` CLI was presumably faster because it worked against one repo with one rev. Check how many (repo, rev) combos get enumerated.
2. SqliteStore.open runs DDL/migrations on every server start. Per-script teardown + restart pays that cost twice. Time `SqliteStore::open_memory` vs full-path; consider `--no-store` for smokes.
3. sprefa repo Rust scan pulls in crates/ (v1 code) and v2/. Non-rs files still hit the fs op filter but .rs fans out wide. Maybe scope the smoke fixture narrower.
4. `start_server` polls 100ms × up to 50 = 5s startup budget. If it reliably takes 1s that's fine, but measure.
5. Parallelism: ast-grep might not be parallelized across files in v2 yet. Worth checking the runner.

Measurement plan for next session:
- Time each smoke script individually.
- Add `--verbose` or `--timings` to `sprefa run` that emits per-op wall-clock.
- Check if the server is re-reading .git objects on every run.
- Compare to `cargo run --bin sprefa-v2` on the old path (before D1) — pre-commit `0c843a2^` — to separate "daemon overhead" from "ast-grep wall time".

Rust tests run in <1s each; the 38s is near-certainly end-to-end I/O, not test harness. The existing lsp_smoke.rs takes ~0.6s for a full stdio roundtrip including subprocess spawn, so subprocess startup isn't the bottleneck.
