# Session: v3-hover-snapshots-and-single-lowering-pathway

## Goal
Pin LSP hover behavior with snapshot tests for ast/json ops, then
collapse the LSP/CLI/HTTP duplicated lowering into a single lazy
pathway shared off `DocSession`.

## Current State
All 18 server lib tests green. 4 hover snapshots landed
(`hover_snapshot_{json,ast}_{op_name,capture_inside_body}`). The synth
re-parse path in backend is gone; `Pipeline::Op` now holds
`Arc<dyn Op>` instead of `Box<dyn Op>` so a single lowered op can back
both the hover render and pipeline run. Branch
wip/kitchen-sink-react-hook-fix, no commit yet (user is compacting).

## Problem/Context
User reported: `crates/server/fixtures/ast_grep_smoke.sprf` hover shows
"failed to lower" but no red diagnostics. Investigation surfaced two
issues stacked:

1. **Diagnostic gap.** Three diag channels exist; only two reach LSP:
   - parse errors → `parse_errors_to_lsp` → publishDiagnostics ✓
   - binding diags → `binding_diags_to_lsp` → publishDiagnostics ✓
   - op body diags from `registry.build_from_node` → dropped on the floor
     except in sprefa-run's stderr print at bin/sprefa-run.rs:229,237.
   `render_enriched_hover` was the only consumer that noticed, and only
   to swallow them and emit `_pipeline lowering failed_`.

2. **Synth re-parse bug.** `lower_plan_keeping_ops` was synthesizing
   `format!("{}({})", op.name, op.body)` and re-parsing through
   `host_parse`, then re-lowering. The synth dropped bracket-args, so
   `ast[rust](...)` round-tripped as `ast(...)` and `from_values`
   rejected it (no language). The synth-re-parse existed because
   `PlannedOp` was a String-only value so it could be snapshotted out
   of the mutex without `Tree` lifetime ties.

Architectural diagnosis: hover, sprefa-run, and any future HTTP driver
all want the same call — `registry.build_from_node(name, inv.node(),
src.as_bytes(), &mut diags)` — but only sprefa-run was making it
against the original CST. Hover took a synth detour, with all the
attendant rebase math (`RebasedOp` wrapper) and per-grammar-field
band-aids (bracket_args was the first; brace_slot would have been the
next).

## Solution/Approach

### Phase 1 — pin the hover behavior with insta snapshots
- Added `insta = "1"` as dev-dep on server crate.
- 4 snapshot tests in `backend.rs::tests` using helper `enriched_at(src,
  byte_offset)` that builds DocSession + hover_plan + render. Empty
  Config + ConfigSource::CwdFallback → fully deterministic markdown.
- First run captured the bug verbatim (`_pipeline lowering failed_`).

### Phase 2 — band-aid (later reverted as part of phase 3)
- Added `PlannedOp.bracket_args: String` field + `bracket_args_text`
  helper in session.rs; synth became
  `format!("{}{}({})", name, brackets, body)` and synth_paren_origin
  shifted by brackets length. Bug fixed in isolation; user noted this
  was an LLM invention not aligned with intent and asked for the real
  architectural answer.

### Phase 3 — single lowering pathway, lazy
- `Pipeline::Op(Box<dyn Op>)` → `Pipeline::Op(Arc<dyn Op>)`. Cascaded:
  - pipeline/tests/pipeline.rs: 8 sites `Box::new` → `Arc::new`
  - server/bin/sprefa-run.rs:233: `Pipeline::Op(op)` → `Pipeline::Op(Arc::from(op))`
- `DocSession.lowered: OnceCell<Vec<Vec<LoweredOp>>>`
  - `LoweredOp { name, op: Option<Arc<dyn Op>>, diagnostics:
    Vec<PatternDiagnostic>, byte_range, paren_origin }`
  - `pub fn lowered_pipes(&self) -> &[Vec<LoweredOp>]` — `get_or_init`
    over `lower_all_pipes(&self.parsed, source.as_bytes(), &registry)`.
    This calls `registry.build_from_node` over the original
    `inv.node()` exactly like sprefa-run does. No synth, no rebase.
  - `on_source_change` resets the OnceCell.
- `HoverPlan` collapsed to `{ pipe_idx, focus_name, focus_step,
  pipe_len, hover_offset }` — indices only, no string copies.
- backend.rs hover handler snapshots `Vec<LoweredOp>` slice
  (`session.lowered_pipes()[plan.pipe_idx][..=plan.focus_step].to_vec()`)
  out of the mutex. Cheap — each entry is an Arc clone.
- `render_enriched_hover` signature: `(plan, lowered: &[LoweredOp],
  config, config_source, registry)`. On any slot with `op = None` it
  surfaces the actual diagnostics from `slot.diagnostics` instead of the
  old generic failure line — diagnostic gap is half-closed for hover
  even before publishDiagnostics is wired.
- Deleted: `PlannedOp` struct, `bracket_args_text`, `paren_body`,
  `paren_body_origin` helpers, `lower_plan_keeping_ops` (~70 LoC),
  `RebasedOp` wrapper struct + impl (~25 LoC). Net negative diff.

### Snapshot updates
- ast hover snapshots flipped from "_pipeline lowering failed_" to the
  full enriched form with **Focused capture: $N** section + empty
  cursor table (no seeds in test).
- json snapshots unchanged.

## Key Insights
- Three diagnostic channels exist; the third (op body diags from
  `registry.build_from_node`'s `&mut diagnostics`) silently dies. Hover
  is the only consumer that ever noticed and it just printed
  "_pipeline lowering failed_". LSP publishes nothing about it.
- The synth re-parse in `lower_plan_keeping_ops` was a value-type
  workaround for the mutex-snapshot pattern in `Backend::hover`. Once
  `Arc<dyn Op>` exists in the type system, snapshot can carry the Arc
  out cheap and the synth has no purpose.
- `PlannedOp.bracket_args` (the first attempted fix) was per-grammar-
  field whack-a-mole. Brace slots, future grammar fields would each
  need similar stitching. The architectural fix removes the surface
  entirely.
- `registry.build_from_node` returns `Box<dyn Op>` today; we
  `Arc::from(box)` at call sites. Std lib has
  `impl<T: ?Sized> From<Box<T>> for Arc<T>` so this is zero-overhead.
  Could promote the registry return type if the friction grows.
- `std::cell::OnceCell` is `Send` (when T: Send) but not `Sync`. That's
  fine here because `DocSession` lives behind `tokio::sync::Mutex`, so
  &self access is exclusive via the guard. Don't need `OnceLock`.
- `Op: Send + Sync + Debug + 'static` super-trait at
  pipeline/src/_1_op.rs:44 — required for `Arc<dyn Op>: Send`.
- `crates/sprefa/` is excluded from the v3 workspace
  (v3/Cargo.toml exclude). It's the v2-style tree kept for
  cherry-picking. v3 active line is pipeline + server + sprefa_parse +
  effect_runtime + tree-sitter-sprefa + spine + sprefa_macros.
- Hover end-to-end render snapshot tests pin behavior cheap: empty
  Config + ConfigSource::CwdFallback → no on-disk paths in output, no
  seed rows, no actual file reads. Future hover edits will surface in
  diff form.
- Cache hit ratio telemetry from prior session's perf work (CacheLayer
  on RtCtx) still applies; LSP `hover` builds a fresh RtCtx per seed
  per call so the cache is a no-op for hover. LSP daemon mode sharing
  RtCtx is still the open path for cache hits.

## Open Questions
- Wire LoweredOp.diagnostics into the publishDiagnostics adapter? It's
  a small adapter following the binding_diags_to_lsp shape. Severity
  question: WARNING (binding's choice) or ERROR? Lower failures break
  the run, so probably ERROR.
- Should sprefa-run also pull from DocSession.lowered_pipes()? Pro:
  truly one call site. Con: sprefa-run grows a DocSession dep, and CLI
  invocations don't benefit from caching since they're single-shot.
  Probably leave as-is.
- registry.build_from_node Box → Arc return type: small win, modest
  blast radius (call sites in registry.rs's own internals + sprefa-run
  + lower_all_pipes). Defer.
- Snapshots' "no cursors emitted" branch: with empty seeds. When test
  config grows real seeds we'd lose determinism. The fix is to make
  seed-table optional or stub the FsListFiles effect. Cross that bridge
  when reached.
