## Key findings

### 1. Perf probe — three levers, one big one

Measured on linux kernel (63,482 .c/.h, 1.34 GB, pattern
`printk($$$)`, 16,627 matches).

| Lever | Result | Source |
|---|---|---|
| Topology (rayon walk-parallel vs crossbeam hopp-v2) | wash within noise | `v2/examples/throughput_probe_v2.rs` `--topology` axis |
| jemalloc global pin | wall flat, RSS −27% | `tikv-jemallocator` |
| `Pattern::fixed_string()` + `str::contains` pre-CST | **6× speedup**, 20.7s → 3.64s at W=8 | `ast-grep/crates/cli/src/utils/mod.rs:157-160` |

Match counts bit-identical across configurations. sprefa probe with
the prefilter passes ast-grep CLI (15.7s → 3.64s, 4.3× ahead).

### 2. v3 plugin surface

`v3/crates/effect_runtime/src/lib.rs` (~140 LoC):

```rust
trait EffectKind: Send + 'static {
    type Response: Send + 'static;
    fn payload_bytes(&self) -> Option<usize> { None }
    fn response_bytes(_r: &Self::Response) -> Option<usize> { None }
}

trait Batcher<E: EffectKind>: Send + Sync + 'static {
    fn run(&self, req: E) -> BoxFuture<'static, E::Response>;
}

ctx.put::<E>(req) -> BoxFuture<E::Response>
```

Registry keyed by `TypeId::of::<E>()`. One `Box<dyn Any>` cell lives
inside `TypedEntry<E, B>`, invisible to op authors.

### 3. Four batcher topologies

| Batcher | Queue | Concurrency | Coalesce | Use for |
|---|---|---|---|---|
| `Passthrough` | absent | caller task | absent | batch handler fanning internally |
| `WorkSteal` | absent | rayon | absent | pre-collected bounded input |
| `BoundedWorkSteal` | tokio mpsc(cap) | rayon | absent | CPU effects under streaming ops — v3 default |
| `BoundedBatched` | crossbeam bounded(cap) | W threads | opportunistic drain | amortizing I/O (sqlite, git, RPC) |

Per-kind bounded inbox gives backpressure; slow kind A stalls only
emitters of A.

### 4. Plugin perf affirmed

| Path | W=8 p50 | Note |
|---|---|---|
| probe walk-parallel (raw par_iter) | 3.64s | baseline |
| v3 per-file via `BoundedWorkSteal` | 4.17s | +14% = 8.4µs/item plugin tax |
| v3 batch via `Passthrough` + par_iter | 3.65s | parity, within noise |

Rule of thumb: batch emission when op knows the input set up front;
per-file emission for streaming arrivals (watcher, LSP change).

### 5. sqlite write leg

1.55M rows, 59MB db.

| Stage | Wall p50 | Throughput |
|---|---|---|
| Scan only (regex extract) | 1.74s | 890k hits/s |
| Scan + plugin emit, no-op writer | 1.73s | 896k (plugin overhead = noise) |
| Full pipeline | 2.04s | 758k rows/s |

Isolated sqlite insert: ~5M rows/sec via multi-value `INSERT (…)` in
512-row chunks, `prepare_cached`, BEGIN/COMMIT per coalesced batch,
PRAGMA stack: WAL, synchronous=OFF, cache=256MB, mmap=1GB,
page_size=8192, temp_store=MEMORY, locking_mode=EXCLUSIVE.

### 6. git blob walk — shell-out beats git2 2.1×

Linux HEAD tree, 93,866 blobs, 1.59 GB.

| Path | Wall p50 | MB/s |
|---|---|---|
| git2 `odb.read(oid)` per blob under Mutex | 4.20s | 360 |
| `git ls-tree` + `git cat-file --batch` pipe | 1.98s | 765 |

Implication: `GitBlobReader` behind `ReadBytes` defaults to shell-out
for bulk walks; git2 stays for random access and writes.

### 7. Core telemetry

`v3/crates/effect_runtime/src/telemetry.rs` (~210 LoC). Per-`ctx`
ring buffer of `Span{ effect_type, start_ns, wall_ns, payload_bytes,
response_bytes }`. Every `ctx.put` opens at entry, closes at reply.
`ctx.telemetry().summary()` prints:

```
effect       count    p50    p95    p99   mean  total_MB   wall  MB/s_wall
```

MB/s computed over the actual wall window (`max(start+wall) −
min(start)`) so concurrent puts report aggregate throughput.

Replaced all hand-rolled measurement in the three benches; numbers
reproduce within noise:

| Workload | Custom harness | Telemetry |
|---|---|---|
| ast-grep batch | 3.65s / 368 MB/s | 3.82s / 350 MB/s |
| ast-grep per-file | 4.17s / 322 MB/s | 4.18s / 321 MB/s |
| git2 | 4.20s / 360 MB/s | 4.20s / 361 MB/s |
| shell-out | 1.98s / 765 MB/s | 1.96s / 773 MB/s |

## Prior art (completed)

Full writeup: `v3/docs/PRIOR_ART.md`. Ten projects ranked by shape-
match. Closest combined shape:

- **Haxl** (Haskell 2014) — `DataSource` + `PerformFetch` variants
  (`SyncFetch` / `AsyncFetch` / `BackgroundFetch`) — per-kind topology
  in the trait surface.
- **tower** (Rust) — `Service<Req>` + `Layer` composition.
- **batched-fn** (Rust) — drain-and-coalesce reference for
  `BoundedBatched`.

Combined design **does not exist as a single crate in Rust**. That
gap is the `effect_runtime` positioning.
