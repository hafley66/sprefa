## The enum arc, in order

### 1. Nullary variant emitted invalid SQL

`content_key_positions(0, [])` handed a fieldless variant an EMPTY key list,
which `lower.pl` turned into `PRIMARY KEY ()`. A syntax error in both SQLite
builds. `compile_dl6` returned 0 and printed `wrote`; the program died at boot.

```
sqlite3 3.43   Error: in prepare, near ")": syntax error
tsv2 runtime   BOOT FAILED: LibsqlError: SQLITE_ERROR: near ")": syntax error
```

No fixture caught it because every existing variant has at least one field.

Fix: `content_key_positions(0, [1])`. Identity is normally the CONTENT, so the
key skips position 1; with no content, the id carries it.

`Option<T>` then worked end to end for the first time:

```
tick 1  +maybe_text_some(1,"hello")  ->  described(1,"hello")     tag(1,some)
tick 2  +maybe_text_none(2)          ->  described(2,"<empty>")   tag(2,none)
tick 3  -maybe_text_some(1,"hello")  ->  described  -(1,"hello")  tag -(1,some)
```

**Door spelling trap**: surface text needs `none()`; bare `none` is a parse
error at the paren. The parser then yields the bare ATOM, so a term fixture
writes `none`. Writing `none()` in a term fixture crashes `=..` with
`domain_error(compound_non_zero_arity)`.

### 2. An enum name refused as a column type

```prolog
rel grade(ripe(sugar: int) ; green(days: int)).
rel picked(id: int, g: grade).      % column_type_unknown
```

Root cause is phase order. `type_decl/2` is what makes a name usable in column
position, and both doors mint it before enum expansion runs:

```
text door   parse_dl.pl:834  normalize_relation_value_decls, during the parse
term door   fixture writes   type_decl(Name, Specs) literally
both meet   compile.pl:169   materialize_reference_target_rels -> col_type
enums run   compile.pl:168   ONE LINE EARLIER, and nothing re-runs the minting
```

Chris ruled `g: grade` means ANY variant.

**The fix moved twice.** A flash lane put it in `compile.pl` per my brief; that
passed every compile-side scenario and failed the oracle, because
`conformance/engine.pl:547` calls `expand_program/3` directly and never runs
`compile.pl`. The seam is `0_enum_expand.pl`, inside expansion phase 10, the one
place both doors share.

**The encoding also moved.** First attempt retargeted `g: grade` to
`ref(grade_tag)`. The tag rel is DERIVED, and a reference column's arrival
normalizes into an arrival for its target, so the target took rows from both
its own tag rules and the nested ingress:

```
got   [grade_tag(401,ripe), grade_tag(401,ripe)]
want  [grade_tag(401,ripe)]
```

Final shape: an enum column carries the INSTANCE ID as plain `int`, and reading
a variant is an ordinary join on the tag rel. The fixture asserts the join and
the retraction, not a stored round trip.

### 3. Dots onto an arm

`grade.ripe(id, sugar)` now compiles and resolves to `grade_ripe`.

`1_expansion.pl:84` already handed `EnumContext` to every non-ast phase, and
`expand_dot_in_context/3` discarded it with a `_`. It now resolves
`rel_path([Enum, Variant], Args)` against that context before
`refuse_rel_path_rule` runs, using the ref `enum_context/2` reports so the
spelling cannot drift from what expansion minted.

Arity is part of the match. Wrong count, unknown arm, and any non-enum path all
still refuse.

## The refusal law, and why it exists

Chris, verbatim: *"any refusal u see is truely not my edict, please fight it and
ask... wouldnt this be a rational thing to have and we just got lazy."*

Measured from `plans/2026-08-01-refusal-inventory.md`:

| --- | --- |
| inventoried decisions | 248 |
| decided by an agent, not Chris | 152 (61%) |
| carrying `evidence: none` | 155 (63%) |
| **named refusals** | **101** |
| of those, agent-decided AND unmeasured | **72 (71%)** |
| of those 72, marked cheap to re-open | 65 |

Row N-024, the one I spent the session tracing:

```
decision  Compiler refuses `column_type_unknown` (column type unknown)
decided   agent-verdict
evidence  none
reopen    S
```

The stated reason is the name of the refusal. Tracing it found a phase-order
accident.

Landed as a standing law in `CLAUDE.md` above "Comments are not the language":
**a refusal is a hypothesis, never an edict.** Never report one as a language
limit; trace it to the throw site and say whether it encodes a real
impossibility or unfinished work.

Also worth keeping: of 308 manifest fixtures, 97 sit in the `unsupported`
bucket, but 63 by name are fixtures whose JOB is to prove a refusal, and most of
the remaining 34 are too. Genuine gaps are roughly 8.

## Three times I was wrong today

1. **`g: grade_tag` refusing is not a defect.** I called it "the giveaway" that
   this was a bug. Naming the derived tag rel must keep refusing, because a
   reference column's arrival normalizes into an arrival for its target.
   Corrected in the lab doc and the scenario board.

2. **"The engine bans source vs derived" is false in v6.** I quoted `CLAUDE.md`
   as a code fact in PR #38's rationale. Zero refusals in `analyze.pl` or
   `0_program_check.pl` name source or derived, and `conformance/engine.pl` has
   no bail site. `git blame` put the line at c4869c17, **2026-06-13**, about
   **v5's** `rebuild_derived` doing a full `DELETE FROM rel`; that symbol exists
   only in v5 `tests/it/*.rs`. The 2026-08-02 turbo-minimize (1549 -> 133 lines)
   dropped the reason, so it read as universal. Chris caught it. The line is now
   scoped to v5.

3. **`bus dispatch` is not a message verb.** Detail below.

Filed from #2: `derived_rel_as_reference_target_duplicates`, unbuilt. Wiring a
derived rel as a reference target SILENTLY returns a duplicated row. A silent
wrong answer is worse than a ban. Wanted: a named refusal when a column type
names a rel that any rule heads, plus a fixture. Chris: design the fix later.

## The dot routing map

The parser splits on syntactic position, before any phase runs.

| what you write | slot | term | fate |
| --- | --- | --- | --- |
| `Rec.a.b` | value position | `dot_get` nest | `decode(Rec, {a: {b: Leaf}})` |
| `Enum.variant(...)` | functor position | `rel_path([E,V], Args)` | resolved to the variant rel, NEW today |
| `mod.rel(...)` | functor position | `rel_path(Segments, Args)` | refused, `module_path_unresolved` |
| `x . y` spaced, `1.5`, statement `.` | neither | | not a dot route |

`module_a.some_rel.case_name(id, note)` parses CLEAN into
`rel_path([module_a, some_rel, case_name], [Id, Note])` and dies at
`0_dot_expand.pl:67`. The module resolver is a placeholder holding the slot;
`0_dot_expand.pl:29` says "There is no module half in scope".

Neither dot route touches `__rel`. The module route is where that lookup
belongs.

## agentio: the new cli recon

Chris wants ONE cli, Rust or Go, normalizing every harness's session data behind
one struct, exposed three ways like `ast-grep`: linkable lib, TS/napi binding,
bash binary. `bus` keeps the waits and becomes a consumer. Other consumers:
`instant`'s message side panel, a files-touched panel, anything shelling to
`cass`.

Hard requirement, verbatim: *"i want live as possible time reading things so i
can immediately know the agent edit/call/read etc. graphs"*. `cass` is
disqualified for that path because it is eventual.

Two opus lanes ran. Both docs are in `~/projects/claude-research/plans/`.

### Prior art, `2026-08-08-agentio-prior-art.md`, 820 lines, 91 candidates

### The questions that block the design

1. Is opencode in scope for v1? It is 14 of the 19.8 GB and the one gap in
   `agent-session`.
2. Session-shaped or event-shaped IR? Adopting their crate then inverting the
   shape is avoidable friction, and the requirement is events.
3. Is a subagent a session? Claude says no, opencode and codex say yes.
4. What is `seq` in the unified struct? Line index for three harnesses, wall
   clock for one.
5. Does the cli own writes or only reads?
6. Is `~/.claude/sessions` acceptable as a source given it is undocumented
   harness internals?
7. Keep cass for history or reclaim 17.67 GB?

## Lane mechanics, bus, and what broke

Two flash lanes ran on `openrouter/deepseek/deepseek-v4-flash-0731`:
`enumtype` (delivered a working compile-side fix at the wrong seam, then
correctly REPORTED the oracle failure verbatim instead of working around it)
and `catalogtype` (still running at session end; took `emit_ts.pl` outside its
stated file ownership).

**bus verb confusion, corrected in the skill** (`claude-research` commits
`9fa4ce1`, `1a7ac29`):

| verb | what it does |
| --- | --- |
| `bus lane` | register AND spawn; the first-contact verb |
| `bus dispatch` | spawn a tmux session running `--cmd`; ALWAYS calls `tmux new-session`; never a message |
| `bus hail` | put a message in a mailbox |
| `bus adopt` | rewrite registry metadata for a running process |

My errors: omitted `--harness opencode` so both lanes registered as `claude`
(fixed with `adopt`), then tried `dispatch` as a message verb and got
`duplicate session`. `opencode run` is ONE-SHOT, so a second pass is a NEW spawn
carrying `-s <sessionID>`, gated on the first exiting.

`bus lane --harness claude` is BROKEN: it builds `claude -m 'opus'` and `-m` is
not a claude flag (`--model` is). Both planning lanes died instantly with rc=1.
`--help` short-circuits flag validation, which is why my check passed. Ran them
as native opus subagents instead. **Unfixed.**

Rail gap fixed in passing: the comment budget was grading `compile/out/*.ts`,
emitter output whose banner no edit can shrink. Emitter directories joined the
exempt list beside `*fixture*` and `*golden*`.
