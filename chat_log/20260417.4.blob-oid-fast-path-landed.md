## Goal
Land #2 from the perf backlog: Reader::blob_oid fast path so ParseCacheReader can skip bytes reads on duplicate blobs across revs. Queue was 2 → 4 → 3 (blob_oid → persistent parse cache → interning).

## Problem/Context
Content-hash dedup (blake3) was already in place from session 3, but still required a bytes read + hash per primary slot. 242 of 442 blobs in g4 are duplicates across the 4 revs — those reads are wasted when git can name the blob by oid cheaply.

## Solution/Approach

### Reader trait default (v2/src/_3_reader.rs)
```rust
fn blob_oid(&self, _repo, _rev, _fs) -> BoxStream<'static, Option<[u8; 20]>>
{ Box::pin(stream::once(async { None })) }
```
Default None means MemReader/BufferOverlay inherit without boilerplate and the ParseCacheReader short-circuit falls through to bytes+blake3 with no extra roundtrip.

### GitBlobReader override (v2/src/readers/_2_git.rs)
open_repo → tree_oid (cached revparse) → `tree.get_path(rel).id()` → `Oid::as_bytes()` into `[u8; 20]`. Mutex-gated like bytes() but no blob read.

### BufferOverlay override (v2/src/readers/_3_buffer.rs)
If a buffer exists for `(repo, rev, path)`, return None. Dirty buffer means the blob oid no longer names the content, so force the cache onto the bytes+hash path. Correctness under LSP edits.

### ParseCacheReader new oid-keyed slot (v2/src/readers/_4_parse_cache.rs)
Added `by_oid: RwLock<HashMap<OidKey, Slot>>` alongside existing `by_hash`. Inside primary slot's `get_or_init`:
```
oid = inner.blob_oid(...).next().await.flatten();
match oid {
  Some(o) => oid_slot.get_or_init(|| read bytes + parse).await,  // skips blake3
  None    => existing blake3 path (bytes + hash + hash_slot),
}
```
Two maps instead of tagged enum — oid keys are 20 bytes vs 32, collision-free by construction (sha1 of blob).

## Key Insights

### Why per-parse time went up while wall dropped
`record_parse` measures wall clock per parse inside spawn_blocking. Before the oid path, each primary slot init did `bytes → blake3 → secondary hash_slot → parse`, a 100–500 us preamble that spread parse arrivals over time. After, `blob_oid` is fast, so parses arrive at spawn_blocking in a tighter burst. N parses on M cores with N > M means each parse's wall stretches. Sum of per-parse walls went 167 → 400+ ms but run_pipeline wall went 211 → 133 ms. Parses now ~3x parallel instead of ~0.8x. Pay the per-task latency tax, collect the parallelism rebate.

### Default-None Reader method avoids N+1
Key design point: the oid fast path is a single short-circuit inside ParseCacheReader::parsed, not a wrapper layer. Readers that can't answer (MemReader, dirty BufferOverlay) inherit the default None and the caller falls through to the bytes+hash path in the same async block. No extra stream op per read for non-git readers. One virtual call returning None is the whole cost.

### Two OnceCells chained = two shareReplay(1) gates
Primary slot dedups concurrent callers for same `(repo, rev, path, kind)`. Secondary (oid or hash) dedups across identities that resolve to the same blob. First caller through both gates does real I/O and parse; everyone else awaits the same resolved Arc<ParsedTree>.

### Workspace vs server terminology clarified
`WorkspaceCtx` (v2/src/server/_1_workspace.rs:20) = one workspace root's bundle of Config + CheckoutLocator + Reader + BufferOverlay. Server holds a `WorkspaceRegistry` by root. Separate from the daemon/LSP/CLI collapse — that's about process shape (one server, thin shells). WorkspaceCtx is per-root data inside that server. Intern table scopes to WorkspaceCtx lifetime = drops on root reload.

### Measurement discipline
Default profile in smoke scripts is debug. `SPREFA_PROFILE=release bash tests/smoke/_2_many_rules_timed.sh` is the right invocation for perf numbers. 5083 ms "regression" was a debug run, not a real regression.
