# Session: syn-rewriter-kitchen-sink

## Goal
Replace span-based string surgery for Rust module rewrites with syn AST parsing. Prove end-to-end with a live watcher test on the sprefa repo itself.

## Current State
All changes committed (aaa4623). 439 tests pass. Live proof succeeded: `mv types.rs _0_types.rs` with watcher running rewrote 14 files across the workspace, `cargo check` passed clean.

## Problem/Context
1. Grouped imports (`use crate::{types::Foo, ast}`) shared overlapping spans in the DB. Span-based replacement destroyed files by replacing `crate::{types::Foo` with `crate::_0_types::Foo`.
2. `mod_parent_candidates` produced `src/lib.rs` instead of `crates/rules/src/lib.rs` for workspace crates, so the planner never found the parent module file.
3. Inline qualified paths (`crate::types::Rule` in fn signatures) and paths inside macros (`matches!(s, sprefa_rules::types::SelectStep::File { .. })`) were invisible to both the DB and the old rewriter.
4. 400+ unit tests all passed on toy single-crate inputs and caught none of these bugs.

## Solution/Approach
- `sprefa_rs::rewrite_module_refs()`: parses source with syn, three visitor layers:
  1. `collect_use_ident_spans`: walks `UseTree` nodes for use statements (handles grouped imports by visiting each ident individually)
  2. `PathVisitor` (syn::visit::Visit): walks every `Path` node in the AST for inline qualified paths
  3. `MacroTokenVisitor` + `scan_token_stream`: tokenizes macro arguments with proc_macro2 to find paths syn sees as opaque TokenStreams
- Planner produces `RustRewrite` structs instead of span-based `Edit`s for Rust files
- `rewrite::apply()` takes both `&[Edit]` (JS/TS) and `&[RustRewrite]` (Rust)
- `mod_parent_candidates` takes `repo_root` parameter, strips to repo-relative paths
- Cross-crate scoping: any file with RS_USE refs mentioning the moved crate gets queued

## Key Insights
- syn cannot parse inside macro arguments (they are opaque TokenStreams). proc_macro2 tokenization recovers path structure from macro bodies.
- Grouped imports in syn share prefix_start across all items in UseTree::Group. Each item needs its own ident span for independent rewriting.
- The DB scopes which files to parse (avoids parsing every .rs in the repo). syn does the actual surgery.
- Workspace crate paths in the DB include the crate directory prefix (e.g. `crates/rules/src/lib.rs`), which all path-matching code must account for.
- `visit_item_use` in the PathVisitor must delegate to `collect_use_ident_spans` (not skip) to catch `use` statements inside function bodies.
