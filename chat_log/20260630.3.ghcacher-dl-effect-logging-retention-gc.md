## Problem/Context
- ghcacher-in-dl already EXISTED (gh-cache.dl + 3 variants, sh/clock/jsonp/
  change_log/effect_log, live-tested). What was missing: a debug/log mode and
  SQLite maintenance.
- "Without recompiling the world" = 3 levers, none touch Rust: (1) edit
  gh-cache.config.json -> scan is reactive -> hot-reload watch set under daemon;
  (2) dl --load-once <(query.dl) against the warm cache.db; (3) new entity = rel
  + one json/jsonp rule, hot-loaded via --load.
- Subsystem mapping: daemon = service; <root>/.dl or --db cache.db = store (rel_*
  tables, any SQLite reader); change_log = SSE feed; effect_log = call_log;
  clock(N,b) = poll interval/rate cap.

## Solution/Approach
src/effect.rs (the extracted drain runtime):
1. DL_TRACE logging. spawn_stdout: debug `spawn` (rendered cmd via preview()) +
   `result` (exit, bytes). drain_effects: info per-response (kind, head, args =
   digest key, status = first response slot => 200-vs-304 visible) + "draining
   effects n=N" summary. NOTE tracing writes to STDOUT; [daemon] lines to stderr.
2. gc_done_effects (end of drain_effects): the ONE effect leak. A cadence-
   bucketed sh poll queues a fresh done row every clock bucket forever. Reclaim
   done READ rows older than DL_EFFECT_RETAIN_TICKS (default 256). KEEP Mutate
   (sh!) done rows (persisted done = exactly-once guard) + Stream rows. Safe
   because buckets only move forward (old bucketed Read can't recur) and re-firing
   a Read is defined-harmless. Reads cur_tx from _carry_meta directly (private
   current_tx lives in engine module, not reachable from effect.rs).
