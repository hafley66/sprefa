## Problem/Context
v3 has tree-sitter + LSP + multiple injected sub-grammar ops (re, glob via grammar.js; json via hand-rolled brace_parse; ast via borrowed ast-grep-core). Each op author touches ~11 trait seams + a registry + custom paren parsing. v4 wants to extract this substrate so:
- Adding a new DSL is turnkey (least possible code per op)
- Three implementation strategies coexist: TS-backed grammar.js, hand-rolled, borrowed engine
- Path is canonical: every node addressable via `Path` (Arc<[Box<dyn PathItem>]>) doubling as cache key
- Cache invalidation = cascading `delete_prefix` by Path
- No DD; SQLite store abstracted, MemStore in-lib
- No tower-lsp lock-in; lsp-types only

User pushback through the session: avoid sycophancy, avoid over-abstraction, no Seg/Segment naming, push diagnostics through sink not collect (fatal returns Err(Diag), non-fatal pushes), `dyn` for PathItem extension, NO DD anywhere.

## Solution/Approach
Lib surface: 5 types, 3 traits, 2 free functions, codegen helper, MemStore.

**Traits:**
- `Dsl` — id + compile(body, diags) → Result<Box<dyn Compiled>, Diag> + injection_grammar() + lsp()
- `Compiled` — declared_captures + match_into(target, target_off, sink) + emit_path_items(builder)
- `DslBodyLsp` — one trait, ~13 default-empty methods covering body-pure LSP features (hover, diagnostics, semantic_tokens, folding, symbols, selection, highlights, inlay, links, formatting, prepare_rename, rename, color)

**Types:**
- `Path = Arc<[Box<dyn PathItem>]>`, `PathItem` open trait with dyn_hash/dyn_eq/render/kind_tag/as_any
- Lib-shipped items: `Index(u16)`, `Name(Arc<str>)`, `Field { kind_id, idx }`, `Body` ($)
- `PathKey(Path)` — wrapper providing PartialEq/Eq/Hash via erased methods
- `Doc { doc_id, source, tree, injected: Vec<Injected>, version }`
- `Injected { dsl_id, host_path, host_off, tree, source, injected }` (recursive)
- `Located { doc_id, path, host_off, dsl_id, node, trail: Vec<Path> }`

**Diagnostics convention:** fatal → `Err(Diag)`, non-fatal → push through `&dyn DiagSink`. Sinks: BufferSink (collect), LogSink, SilentSink. Conversion via `cst::lsp::shift::diags_to_lsp(host_src, host_off, &diags)`.

**Resolve algorithm:** path is segment runs separated by `Body` items. Each run before a Body is matched literally against `Injected.host_path` of an active child. After a Body, navigate within that injected sub-tree by `Field` items. Repeats for nested injections.

**Cross-DSL "join":** Not in lib. Sprf's cursor capture-bag is the join. Lib owns the CaptureRow contract; consumer pumps rows into bag.

## Key Insights
- **Path-as-URI is the spine, not a side feature.** Every node in the tree-of-trees (git/fs/cst/json/runtime cursor) gets a Path via PathItem composition. Cache key = Path. Invalidation = `delete_prefix`. The HTML mockup in `human-goals.md` is the actual spec.
- **Three DSL strategies must coexist.** Forcing tree-sitter for everything is wrong: json's brace_parse is 16KB of hand-rolled walker; ast wraps ast-grep-core. The lib can't presume `Dsl::language() -> tree_sitter::Language`. Use `Dsl::compile(body, diags) -> Result<Compiled, Diag>` with optional `injection_grammar()`.
- **Cross-DSL "join" is not real.** It's a name-keyed bag on the cursor + lazy `materialize_template` from v3's `value.rs:154`. The lib owns the CaptureRow contract; the bag lives sprf-side.
- **One trait beats N small traits for DslBodyLsp.** Reviewer wanted per-feature splits; pushed back: 13 default-empty methods on one trait vs 13 trait impls + 13 storage slots in registry. Default-empty wins on greppability + boilerplate.
- **Box<dyn Any> in ParsedBody rots.** Earlier draft put `ParsedBody::Custom(Box<dyn Any>)`; reviewer flagged it becomes the API. Fix: push requests directly onto the DSL (`fn hover(&self, body, byte)`) and let DSL cache parsed body internally.
- **fatal vs non-fatal diag split.** `Result<T, Diag>` for binary success/fail with one explanation; `&dyn DiagSink` for the noisy "many things to report" channel. Lib ships BufferSink/LogSink/SilentSink.
- **Path stability across reparse not solved in v1.** Sibling insertion at lower index shifts every later index. Mitigation deferred (anchor-relative + content fingerprint). Cache prefix-evicts on any edit in touched subtree. Revisit if hit rate suffers.
- **The plan went through 4 review passes** (initial Plan agent → Plan agent reshape → adversarial code-reviewer agent → user pushback on path-as-URI). Each pass shrunk and sharpened the surface; final lib is much smaller than first draft.
- **The "one test that maximizes coverage" shape is shared fixture + many asserts.** A single `cst_dogfood.rs` test with one multi-DSL document and ~15 assertions exercises every trait method + every PathItem kind + every offset transformation + recursive injection + cache prefix-evict + UTF-16 math. Order: write the harness with MockDsl first; each real DSL port = "make assertion N green with real impl swapped in."

## Open Questions
- ast extension scope: ship vanilla ast_grep_core wrap (sprf-blind, ~250 LoC), or include sprf's `${X}` carveout overlay (adds ~700 LoC, leaks sprf assumptions)? Default decision: vanilla; sprf adds overlay later as wrapper Dsl.
- json LSP scope: minimum dogfood = diagnostics + document_symbols + folding_ranges. Skip rename/format/color (real json LSPs are 1000s of LoC).
- Codegen: commit `parser.c` (matches v3, fast clean builds, ~5 KB diff per regen) vs `tree-sitter generate` in build.rs (slower, no commit churn). Default: committed parser.c.
- Highlights helper API: should `highlights_to_semantic_tokens` take a pre-compiled `tree_sitter::Query` or compile from string each call? Probably pre-compiled, registered via DSL setup.
- Should `Registry` be in the lib at all, or just leave it to consumers? Plan listed it; I'd ship a minimal one for the dogfood test to use.
