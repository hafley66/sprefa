### 2. Respawning problem + fixes
User ran `dl --tray` — daemon exited on "program file changed" because:
- FSEvents delivered residual CREATE events from file setup (mkdir+write
  before daemon start). Tried: 1s grace (insufficient), mtime comparison
  (won't work with atomic-save editors).
- Editor touching tray-smoke.dl fired continuous MODIFY events.

Fixes applied:
- `program_in_paths` refined to exact-match on canonicalized program_files
  (was: any .dl under .dl/).
- `no_respawn` field: tray mode sets it true, watcher ignores program-edit
  exit. Added `reload_program()`: re-parse + typecheck + swap Mutex<Program>
  + tick_full. Parse errors log and keep old Program.
- `prog` field changed from `Program` to `Mutex<Program>` to enable hot 
  reload. All tick_full/tick_paths/handle_request sites updated.

### 3. tree-sitter-dl grammar
User: "go tree sitter route please" — write tree-sitter grammar for .dl.
Created v5/tree-sitter-dl/ crate with grammar.js (378 lines), Rust bindings
(lib.rs), build.rs, tests.

Grammar covers:
- rel/brand/anchor declarations
- rules/facts, queries, gen_rule, use_decl
- body items: atoms, negated atoms, builtins (scan/sg/match/ast/json/cmd)
- terms: identifiers, strings, interp_strings, regexes, scheme_literals,
  type_tags, arithmetic, function calls, unary minus
- Comparisons: =~, !~, ==, !=, <, >, <=, >=, =~*, !~*, =

Grammar holes:
- def_template: `def NAME(params) <- body.` not yet supported. No examples
  use it; `def(...)` everywhere is regular rule with `def` as rel name.
  Requires tree-sitter to distinguish `def NAME(...)` from `def(...)`
  (same issue as `use` and `gen` clashes; resolved for those via ordering).
- 2 examples have MISSING "." errors (rails.dl, rails-call-kind.dl) —
  minor edge case, parse is otherwise valid.

Tested: 28/30 examples parse clean. 4 Rust tests pass (parses_ban_example,
parses_simple_rule, recovers_from_missing_paren, parses_scan_and_sg).

## Key Insights
- The daemon accept loop must be off-main for macOS tray (CFRunLoop/NSApplication
  requires main thread). This was the cleanest restructure.
- Mutex<Program> hot-reload is a real feature now, not deferred. Reload on
  program-file change works; parse failures keep the old Program.
- tree-sitter grammar for .dl is feasible at ~400 lines. The hard parts are
  keyword clashes (def/gen/use vs rule names) and tree-sitter's missing-token
  recovery interfering with precedence.
- 30 example files make a good conformance test suite; 28/30 pass.
