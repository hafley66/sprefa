## Solution/Approach
### T10 GitReader wiring (v2/src/bin/sprefa_v2_lsp.rs)
- `resolve_reader(uri) -> (Arc<BufferOverlay>, Arc<Config>, Option<PathBuf>)`:
  1. Walk up for .sprefa.toml → ConfigLocator::from_toml_file → GitBlobReader
  2. Walk up for .git → InMemoryLocator::new().with_repo(slug=basename, root, ["HEAD"]) → GitBlobReader
  3. Fallback MemReader
- Returns workspace_root path for hover link rewrite.
- `make_config_from_locator(loc)` populates Config.repos/revs from locator output (seeds rule.pipe).

### Arm-bleed fix: evidence-site filter in hover_match
Framework already pushes OpEvidence { op_name, parse_site, matched, capture } per cursor at `_5_op.rs:85`. Hover_match functions ignored it.
Fixed in repo/_1_repo.rs, rev/_2_rev.rs, fs/_3_fs.rs, json/_5_json.rs (hover_capture too): filter cursors by `c.evidence.iter().any(|ev| ev.op_name == NAME && ev.parse_site.as_ref() == site)` before collecting values.

### Absolute byte_range fix
Root: `host_parse_arm_brace(&brace.src, ...)` parses substring, `parse_op` set `byte_range: inv_start..*i` = substring-relative. Runtime lowering used these; LSP byte→line conversion landed at file top.
- Added `host_parse_arm_brace_abs(src, file, parent_path, base_offset)` in _8_parse.rs.
- `host_parse_inner` takes `base_offset`, adds it to every `byte_range` on bracket/paren/brace slots and ParseSite.
- Wired at `_0_rule.rs:72` (rule body) and `_10_registry.rs:81` (framework default-fork arms), both pass `brace.byte_range.start` (which is already absolute because the outer parse is absolute).
- In analysis.rs `build_spans_for_invs`, wrapped `inv.parse_site` into `abs_site` with `byte_range: source_offset + range` before storing in SpanKind::MatchSite / passing to scan_paren_tokens — so span_ix's stored ParseSite matches runtime-lowered OpEvidence.parse_site via PartialEq.

### repo(*) diag
Added `RepoDiag::NoOp` mirroring `RevDiag::NoOp`. Code `repo/no-op-glob`, severity Error.

### Diag dedup in publish
LSP-side: dedup (code, byte_start, byte_end) tuples, emit one Diagnostic per key with `(×N)` message suffix for stacked counts. json/no-match severity dropped to Hint so VS Code doesn't show yellow underline on informational per-file misses.

### Partial walker match (v2/src/walk/_3_walker.rs walk_object_entries)
- row_fields loop: missing key_hits → `continue` (was `return vec![]`). next_templates swap only if non-empty.
- descents loop: missing key_hits → `continue`. Track `any_descent_produced`. If all descents fail, fall back to emitting row_templates through `rest` so row_field captures survive.
- Two new regression tests: `object_partial_match_missing_descent_still_emits`, `object_partial_match_missing_row_field_still_emits`. Old `required_key_missing_kills_object` → `missing_row_field_tolerated_as_partial` with inverted expectation.

### Hover path rewrite
- fs_path_md simplified to `` - `path` ``.
- LSP `rewrite_hover_paths(md, workspace_root)` scans `- \`X\`` lines; if `workspace_root/X` exists on disk, rewrites to `- [`X`](file:///abs/path)`.
- SessionEntry stores workspace_root; hover handler post-processes via `rewrite_hover_paths`.

## Key Insights
- Arm-bleed: Fork runs all arms against same input buffer; downstream pools merge all arm outputs. Hover over an arm-specific op sees cursors from OTHER arms unless you filter by evidence.parse_site == this-site. Framework already emits that evidence; ops just weren't using it.
- Absolute-offset discipline: any re-entering parser on a brace substring must accept a base_offset and apply it everywhere (slot byte_ranges AND ParseSite.byte_range). Otherwise runtime diags land at wrong line.
- PartialEq on Arc<ParseSite>: Arc ptr equality won't suffice if analysis and runtime construct distinct Arcs. Content equality via derived PartialEq works only when byte_ranges match. Must canonicalize to absolute in BOTH paths.
- Walker partial semantics: v1 was all-or-nothing; v2 now tolerant. Missing entry = skip, don't bail. Row_fields unchanged when all_miss (preserve template); descents fall back to emitting row_templates when all descents fail — that's how $PKG_NAME-only-rows survive alongside $DEP-only-rows.
- `- `relpath`` backtick bullets are a lingua-franca format that the LSP can post-process into file:// links centrally; ops don't need to know workspace root.
- Diagnostic dedup belongs at the LSP publish edge, not the DiagSink. Ops emit per-cursor truthfully; LSP collapses for display.
- Op trait has survived. Surface can now grow in parallel.

## Post-session note: fs/json no-match diag design

User flagged: "no red diagnostics on fs no match still, or on json no match etc."

Current state:
- `json/no-match` was dropped to Hint severity this session to stop yellow-flood across per-file misses. Dedup in publish collapses (×N) hits into one marker but still Hint.
- `fs/no-match` does not exist. fs emits zero cursors silently when glob matches nothing for a (repo, rev).

Design gap: partial misses (some files matched, some didn't) should stay quiet/Hint. Total misses (site produced zero rows ANYWHERE) deserve Warn/Error because the rule is factually inert.

Plan for next session:
1. Add `fs/no-match` — emit per (repo, rev) cursor when `reader.files(...)` returns empty; severity Warn.
2. Reshape `json/no-match`: aggregate at run end, not per-cursor. If the json site produced zero rows across all candidate files (over all repos/revs), emit one Warn. If it produced some rows, demote per-file misses to Hint.
3. Rule-level check: after pipeline drain, if rule emitted zero rows total, emit a rule-level `rule/empty-result` Warn at the rule name site.

Requires a run-end hook that ops can use to emit aggregate diagnostics. Today DiagSink is per-cursor fire-and-forget.
