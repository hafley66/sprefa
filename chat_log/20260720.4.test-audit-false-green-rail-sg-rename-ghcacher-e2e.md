## Key Insights
- **PER-ROOT DBs BLOCK CROSS-REPO (user raised, unresolved).** Daemon registers a root PER DIRECTORY, so instant/smashy/sprefa are 3 separate SQLite files. Verified: sprefa's root db has exactly ONE repo (`SELECT DISTINCT repo` -> `sprefa`), while every rel carries `repo` as a first-class column and `scan("*")` fans across config repos. The multi-repo machinery is built and unused. **Killer detail: `_strings` is PER-DATABASE, so interned ids are dictionary offsets local to each db — id 4711 in two dbs are unrelated strings. You cannot ATTACH and join; every id-valued column is meaningless across the boundary.** Same defect class as salt_rev: an identifier whose meaning depends on hidden context. Cross-repo today requires all repos scanned into ONE root's db via config, which per-directory registration fights. Architecture decision, not a patch. "Dense dictionary ids" (ledger item 1a) is the prerequisite.
- **Router stale-rel bug — the one genuine release concern.** `retraction_props.rs:499`, `#[ignore]`d with a reproducing seed IN the attribute string. From the file's own comment (465-482): when a call-family input rel (e.g. `_call_def`) is EMPTY on the tick that first populates the router memo, `Ctx::scan` records no per-row deps, so the memo footprint OMITS it. Later inserts never trigger a rerun of `call_def`/`call_name`/`call_def_rev` and THE PUBLIC REL STAYS STALE. Seed persisted in `tests/proptest-regressions/retraction_props.txt`, which proptest scopes to the FILE not the test — the non-ignored 20-case sibling at :487 shares the strategy and may already replay it.
- **Salt: removed from src (0 hits), and live dbs SELF-HEAL by accident.** `extract_digest_key` = `format!("extract:{:032x}:{family}:{rev}", exe_stamp())` — the binary stamp namespaces skip-state, so a new binary does exactly one cold rebuild. That keying exists to stop daemon/CLI digest ping-pong, NOT to handle id-derivation changes; it covers this by luck. What does NOT self-heal: 314,892 orphaned `_strings` rows (~15MB), because **`_strings` has no GC**.
- **The salt's bigger twin is still live, just silenced.** `mint_sym` (`typegraph/mod.rs:390`, `format!("{file}::{kind}::{name}")`) — previously 26.6% of `_strings` bytes vs salt_rev's 36.4%. D's rail caught it, then GRANDFATHERED it: `composite_key_baseline("src/graph/typegraph/mod.rs", 4)`. Not fixed, quiet.
- **Audit totals, 1,532 tests**: OK 1,484 / FALSE-GREEN 22 / SKIPPED-PROBLEM 2 / ENV-GATED 15 / NOT-A-TEST 8 / REDUNDANT 1 / STALE 0.
- **22 FALSE-GREENs, one shape**: early exit on a missing external tool with NO `#[ignore]`. `oracle_go.rs`/`oracle_ts.rs` module docs state this as INTENTIONAL — the documented rationale IS the anti-pattern.
- **sg vs match, the receipt**: same rail, same intent. `match` (line regex) found ZERO — not even the incident that motivated it (spans 3 lines). `sg` pattern `"return;"` found 39, catching every FALSE-GREEN all five auditors named independently. sg also parses structurally so it sees inside `#[cfg(test)]`, which `call_def` does NOT (between src/ast.rs:548 and :650 the only call_def row is `SpliceMode.tag` at :643 — the 617-test unit layer is invisible to ANY call_def-based rail).
- **sprefa CANNOT structurally refactor its own language.** No `dl` grammar for ast/match_ast; `.dl` files are reachable only by line regex. `--move` is a Rust/TS/Kotlin symbol mover. So on the day we established "AST not regex", the tool can't AST-match the language it's written in. That's why the rename wasn't `dl --move`.
- **Rail gap, not papered over**: `const_value.rs:153` is `Err(_) => {}` — an EMPTY arm. No `return` for arm 2; arm 1 counts the `Ok` branch's asserts as covering the test. Needs per-path assertion reachability.
- **ONE `match_line` legitimately survives** in the rail: arm 3 predicates on the TEXT CONTENT of an `#[ignore]` reason. sg matches `#[ignore = $REASON]` but METAVARIABLES ARE NOT EXPORTABLE (outputs = line/col/end_line/end_col/id only). Real engine gap; metavar outputs would close it.
- **gh-cache.dl real defects found via the old repo's scenario list**: (a) the 3-line `status\netag\nbody` stdout protocol silently JOINS a body containing a newline (`tr -d '\n'`) — `"weird/multiline\nname"` -> `"weird/multilinename"`, now asserted as a known-gap canary; (b) `fetch` never passes `--paginate`, so list endpoints beyond page 1 silently truncate. (c) `pull_request` retraction was CHECKED AND IS FINE — plain derived rule over `resp_current`, retracts for free.
- **~/projects/ghcacher (116 tests) is a TEST ORACLE for the rewrite.** `MockGhClient` records `Vec<(String,String)>` of calls (not a bare counter); `assert_eq!(mock.graphql_call_count(), 1, "expected 1 batched GraphQL call, got {}")`; `== 0` for no-work paths; persisted `call_log` with `cache_hit`. CRUCIAL: its fallback `.unwrap_or((200, json!([])))` RECORDS THE CALL FIRST then falls back. sprefa's 404 masked AND never recorded. Rule: ALWAYS RECORD, then fall back.
- **gh-cache request digest is `(head_rel, kind, {ep, prev})` with NO bucket salt** (`src/effect.rs:508-653`), so once an (ep, prev) pair resolves it never re-fires on any later bucket. "N per bucket" is really "N once, ever, per distinct (ep, prev)".
- `effect_log` dedups by request digest, so it CANNOT count actual shell executions (a requeued+rerun request collapses to one row). Counting must happen at the point of execution.
- `_write_ledger` gap: `resp`'s writes happen off-tick in `drain_effects` and never land under their own name, since that table only flushes from inside `tick()`.
- `CLOCK_LOCK` (tests/it/clock_lock.rs) is a std Mutex that POISONS on panic, cascading PoisonError onto siblings — turns one honest failure into four misleading ones. Pre-existing.
- `src/activity.rs` `SLOT` global static races under the default harness; that is what "load-sensitive" meant for `lifecycle_round_trips`.
- Agent A's blind spot is the general lesson: file-ownership splits that stop concurrent agents colliding are ALSO what let a design inversion land with its own spec test stranded in an unowned file.
- Recurring pattern worth naming: an agent making a test "robust" by smoothing over an unexpected signal (the 404 fallback) is indistinguishable from suppressing evidence. Happened 3x today.
