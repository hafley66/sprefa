## Key Insights
- r?(A?) desugars to r?(<col0>: A?): LHS is the relation's declared column by position, RHS is your term name; "same" only when col0 is literally named A. `?` in call-arg = OUTPUT projection (destructure target), bare = INPUT constraint. Shared term name across TWO reads = the join (fuser ON r1=r2); `?` says project, repeated NAME says join.
- Negation needs `sql WHERE NOT EXISTS` because a bare r?() is ALWAYS a semi-join (flow-per-match); there is no bare spelling for "drop if any match" (antijoin). Positive joins implicit; negation must be asked for. (v4/docs/v4-cond-recursion-negation.md is authoritative.)
- SQL maps: TermBind->SELECT r.col AS T; TermRead->WHERE r.col=input.T; proposed intra-row->WHERE r.colB=r.colA (residual filter, simplest valid SQL -- current lowering emits invalid input.N); shared term->JOIN ON; negation->NOT EXISTS; recursion->INSERT OR IGNORE looped.
