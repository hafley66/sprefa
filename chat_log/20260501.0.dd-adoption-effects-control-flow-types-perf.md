## Solution/Approach
Reach mental-model alignment on:

1. **Three thread pools, three jobs.** Rayon parses (CPU-bound, no state), timely runs the dataflow (single-thread sync per worker), tokio dispatches effects (I/O, mostly idle). Coordinated via push + oneshot channels, never .await on a CPU pool thread.

2. **Scope, sinks, probe.** Scope = the dataflow graph, built once. Sinks = inspect_batch, where DD records exit into the runtime. Probe = frontier observer, the outer loop's "round done?" thermometer. Daemon loop = `{push deltas, advance_to(T+1), flush, step_while(probe<T+1), drain sinks}`.

3. **Pure operators, three impurity seams.** Input seam = rayon → InputSession.update_at. Output seam = inspect_batch → channel. Effect seam = tokio dispatch. Pure core in between. Operator closures must be deterministic, total, side-effect free, time-pure, captures-only-from-build-time. Replay determinism follows.

4. **Retractable effects via collections.** Three regimes: (1) idempotent terminal (publish_diag with set semantics — already works), (2) debounced commit (effect_pending Collection, commit at frontier T+K, retract within window = free cancel), (3) paused yield (mirror SubjectRegistry as DD collections, antijoin against resolved + upstream + timed_out). 

5. **State only for state effects, parsing stays out.** Pure deterministic work runs BEFORE InputSession on rayon. State (yield, debounce, retract) lives INSIDE DD as Collections. Pure cached effects (read, list) stay in effect_runtime as PureEffect. The InputSession is the dam.

6. **Events as gen-only via auto-retract.** Default impl: +1 at T, scheduled -1 at T+1 by runner. Within-time fan-out gives "all consumers see all emits at T regardless of arrival order" for free. Multi-hop event chains take 1 gen per hop. Iterate scope reserved for explicit cascade blocks; require parse-time acyclicity check.

7. **No keywords.** next/await/if are ops in the registry. await lowers to join_map(events_e, ...) — same shape as `tag?`. if lowers to filter+pipe+concat over Pipe-valued args — block syntax just sugar for synthetic Pipe values.

8. **Sugar reform.** TERM → term(:TERM), TERM? → term?(:TERM), "..." → str("..."), /.../ → re("..."), g'...' → glob("..."), ast'...' → ast("..."). `${...}` only inside DSL string carveouts.

9. **Higher-order = rules with value params.** Two regimes: (A) literal call args → lower-time substitution, one subgraph per call site (common case); (B) row-bound args → re_dyn-style runtime per-row dispatch with LRU-cached compiled patterns. Static analysis is just "syntactic literal-detection at call sites."

10. **Light lattice types.** bytes ⊑ string ⊑ tokens ⊑ tree(grammar) ⊑ graph. Each op declares required input level. Walk-and-check at lower time. No inference. No unification. Cheapest possible types.

11. **Tiered DD memory at 500-repo scale.** Strategy 4: DD holds metadata + Arc<str> IDs + relational graph; SQLite holds canonical string content; trigram index for bulk grep that doesn't need retraction. Realistic live RSS 5–8 GB on 50 GB source. Strategy 3 (custom Trace) reserved for measurement-forced cases. Compaction starting policy: K_GENS=5, M=10.

## Key Insights
- `put` is `push`. Same monotone primitive. Effect_runtime's verb and DD's InputSession.update_at are the same shape.
- Three thread pools all default to consuming all cores. Oversubscription is the failure mode. Tokio = N/4, rayon = N/2, timely = N/2 is one realistic split.
- "Render → commit → effect" maps directly: dataflow walk → step_while returns → inspect_batch sinks fire.
- Set semantics + retraction is what makes auto-clearing diagnostics fall out for free. The current sprefa relation_store has set semantics WITHOUT retraction; that's the gap DD closes.
- Frontier `step_while(probe<T+1)` is the principled version of the homegrown RAII-writer-share + seal_waiters mechanism. Replace, don't extend.
- DD operators are CPS-free. Rule body is a linear pipe. await is just a join, not a continuation. Hence no keyword needed.
- The ONE place keywords would pay off is nonlinear control inside rule bodies (try/catch/race/multi-await). Sprefa doesn't have that, so don't add grammar.
- DD's iterate is the only cyclic operator. Default to NOT using it. Reserve for cascade blocks with parse-time acyclicity check.
- Compaction is the only memory tool DD gives you. Set policy explicitly. K_GENS=5, M=10 is a reasonable starting point.
- Higher-order = rules with Value-typed params. Lower-time substitution for literal calls is the common case and gives single-graph performance. Row-bound dispatch is the escape hatch.
- re/glob/ast are capture-producing pipe ops, NOT config values. Position-polymorphism is rejected. One name per shape.
- Filter-to-zero diag = runtime per-op emission counter + non-negation flag. Not parse-time.
- For 500-repo scale: don't put raw strings in DD trace. Strategy 4 (tiered: DD metadata + IDs, SQLite content, trigram for grep) is the design recommendation, gated by the pinned perf test.
