## Pivots and decisions

- **Layer 2 caching = "cache everything for now"**. Don't gate on `is_pure`
  yet. Marker stays on the trait for later. Probe = body[0]'s probe()
  walks fs + blake3-hashes each file. Layer-2 hash folds in sorted
  (path, hash) entries.

- **SqliteStore on-disk**: WAL mode, synchronous=NORMAL. Default path
  `$HOME/.cache/sprefa/v4.db`. open_memory still available for tests.

- **Sh purity split**: `Sh` is author-declared pure (emit_lines, filter,
  capture) — cacheable. `ShBang` is the impurity escape hatch (side
  effect; cmd run, stdout dropped, cursor passes through). One op type,
  two structs. Cache ops can rely on the marker.

- **OpCache redesigned mid-session**. Started as Vec<Cursor> per cache
  key (replay on hit). User pushed back: "the determinism argument is
  to avoid having them in memory all the time." Switched to skip-on-hit
  HashSet<[u8;32]> of seen keys. Hit = drop input, run nothing, emit
  nothing. Position contract: OpCache must sit upstream of a sink;
  in-pipeline aggregators see nothing on warm runs.

- **RepoFromTerm = value-driven Repo**. Per input cursor, treats
  cursor.get(term) as a repo root. Walks it, emits REPO+FS cursors,
  preserves parent terms. Composes with `Sh::emit_lines("find ...")` to
  auto-discover repos from disk.

- **fact = rule with empty body**. Unification surfaced near end of
  session. `Rule::declare(&store)` ensures sink schema upfront, no
  drive needed. `declare_fact(...)` is now sugar over
  `Rule::new(name, vec![], name, cols).declare(store)`.

### Layer 3 OpCache

```rust
pub struct OpCache {
    inner: Arc<dyn Op>,
    seen:  Arc<Mutex<HashSet<[u8;32]>>>,
    hits:  AtomicU64,
    misses: AtomicU64,
}
impl OpCache {
    pub fn wrap(inner: Arc<dyn Op>) -> Arc<Self>;  // panics if !is_pure
}
```

`cursor_lineage_hash(c)` = blake3 of cursor.terms (sorted (k=v) pairs).
`cache_key = blake3(op_ident | lineage)`.

Run loop: partition input batch into hits-dropped vs misses-batch.
Run inner ONCE on the full miss batch (preserves rayon parallelism).
On output, mark all miss keys as seen. Hits → discarded. Cursors NOT
held in memory.

### Kernel baseline (v4-bench --cache)

Linux kernel checkout via symlink to v2's fixture (~2GB, 36k .c, 63k
walked). Pattern `printk($$$)`, 8 workers, release build.

```
                  wall  emitted    cache(hits/misses)   RSS
─────────────  ───────  ───────  ─────────────────────  ─────
no cache       4.612s    16627                     —/—  161 MB
cold (cache)   4.607s    16627                  0/63482  202 MB
warm trial 2   0.236s        0              63482/63482  202 MB
warm trial 3   0.188s        0             126964/63482  212 MB
```

- Cold-with-cache overhead: zero (4.61 ≈ 4.61).
- Warm wall: 0.19s, just Fs walking + 63k HashSet lookups.
- Warm emits 0 matches by design. Read aggregates from the store.
- HashSet 32-byte * 63k = 2 MB true cache footprint.

Initial Vec<Cursor> design was 24.5s cold (5.3× regression) before user
correction: "should not be doing anything other than calling ast-grep
63k times". Switched to skip-on-hit HashSet.

### ChannelHub + Next / NextQ / Close

buf=1024. Lagged consumers skip-and-continue (counter). Senders never
auto-close; explicit Close drops the hub-held sender → recv returns

## What is NOT in POC (deferred, sequenced)

- **Layer 1** whole-run gate (one global probe, gates all rules). Saves
  N walks for N rules over the same corpus.
- **Persistent OpCache** seen-set in sqlite (survives process restart).
- **Lineage propagation** past AstNm/Re. Downstream pure ops should fold
  input cursor's CONTENT_HASH into output lineage. Today only the
  source-stamp is in the lineage chain.
- **switchMap reactive driver** in effect_runtime (LSP-shaped burst
  cancellation).
- **Cycle / deadlock detection** for channel graph. Today: bounded
  buffer + Lagged-skip + explicit Close. No static analysis.
- **Multi-rule parallel driver**. Rules run sequentially via
  drive_rule_cached today. Concurrent producer/consumer rules across
  separate drives need this for full channel utility.
- **on-disk SqliteStore connection pool** (single Mutex<Connection>).
- **RuleBody enum → Rule unification** (still on the master list;
  GroupCount/Filter/Antijoin still in the enum).
- **git_log / git_blame ops**: explicitly deferred. Same shape works
  today via Sh::emit_lines + Re. Bake recipes into .sprf when the
  parser arrives, not in rust.

## Open questions for next session

1. **Layer 1 gate shape**. One global probe per drive; hash includes
   rule chain identities + the union of all rules' source ops' probes.
   On match, skip everything. Where does the prior-run hash live —
   in-memory across drives, or in `_sprf_run_state` table in sqlite?

2. **Lineage propagation**. AstNm/Re stamp CONTENT_HASH on every emit,
   but downstream pure ops (Re after AstNm, FactRead) don't FOLD the
   input lineage into the output's lineage. For Layer 3 to be
   meaningful past the first pure op, downstream ops need a
   `lineage_stamp()` helper that XORs/concatenates input cursor's
   CONTENT_HASH chain with their own ident.

3. **Multi-rule concurrent driver**. drive_rule_cached is sequential.
   Channels are most useful when producer-rule and consumer-rule run
   concurrently in the same process. Cleanest shape: a `drive_rules`
   that takes Vec<Rule> + RuleStateCache and tokio::spawns each.

4. **Persistent OpCache**. The HashSet currently lives in process
   memory. Survives across rule drives, dies on restart. Persist to a
   `_opcache_seen` sqlite table for cross-process reuse? Eviction
   strategy = LRU with bounded row count, or TTL?

5. **Channel deadlock observability**. No-progress diag emitted by
   NextQ when recv has been pending > N seconds with zero events.
   Default off; opt-in via NextQ::watch(timeout).

6. **switchMap driver**. Reactive mode: file-watcher → invalidate
   relevant rules → cancel in-flight Layer-2 work → restart. The
   Layer-2/3 caches are the load-bearing piece that makes this safe;
   without OpCache, switchMap restart is a CPU furnace.
