## Key Insights
- TextMate grammar had rule-declaration regex expecting `rule name(` but actual syntax is `rule(name) {` -- grammar never matched real files
- The old re: sugar delimiter-lookahead was too clever: $CRATE before / expanded to [^/\s]+ which matched `fs(**` from code examples. Fixed character class [a-zA-Z0-9._/-]+ covers all practical cases.
- eval help examples like `sprefa eval 'json({...})'` were broken -- parse_sprf expects rule/check statements. Added auto-wrapping.
- json() with segment captures ("crates/$PKG") extracts cleanly from structured data. Using line(re:) on TOML/JSON is fighting the tool.
- marker() solves the stray-match problem: line(re:) on full README files matches code examples. Bounded regions make extraction precise.

## Open Questions
- md() pattern syntax for code blocks with content capture -- triple-backtick delimiters in patterns need escaping or a different notation
- marker() comment syntax detection -- need to map file extensions to comment styles (html: <!-- -->, rust: //, yaml: #, etc.)
- Should marker() be a tag or a modifier on existing tags? `marker(name) > line(...)` vs `line[marker:name](...)`
