# Session: dl-scip-turnkey-multilang-ux

## Goal
Make SCIP (compiler-backed `scip_*` relations) turnkey in `dl` across Rust + other langs. This doc is
written from a REAL end-user friction session: an agent just walked the full "turn SCIP on" path on a
gdext/godot Rust workspace (github.com:hafley66/kneeman `rust-sim/`) and hit every sharp edge. Each
friction below is a thing that actually tripped the flow. Turn them into a backlog.

## Current State (what works today)
- Syntactic scanners (`match`/`ast`/`sg`/`json`) are embedded, in-process, rev-addressable:
  `scan(".", "<git-rev>", glob, path, rev)` reads a blob from git at any rev, no checkout. Turnkey.
- SCIP is IMPORT-only: `src/scip_import.rs` reads `$SPREFA_SCIP_INDEX` or `root.join("index.scip")`;
  `src/rels/scip.rs` reload-gates on `index.scip` appearing in the changed set. Relations light up:
  `scip_def`, `scip_ref`, `scip_edge`, `scip_fn_edge`, `scip_callee_type`, `scip_name`.
- Generation is a bare recipe: `just oracle-index` = `rust-analyzer scip . --output {{repo}}/index.scip`.
- Verified live on rust-sim: 92,019 defs / 146,028 call edges / 50,066 typed symbols; feature-envy
  filtered to smash_core surfaced the move-to-method candidates precisely (take_jump / try_ground_action
  / reduce_next_state drilling into Fighter) and DROPPED the regex-graph false positives (record,
  tick_hit_cd) because SCIP knows those are already methods. So the payoff is real; the ONBOARDING is
  the problem.

## Problem/Context — the friction, in the order it bit
1. DISCOVERY: nothing in `dl --help` points to SCIP. Learned the mechanism only by reading the justfile
   + grepping `src/`. There is no `dl scip` / `dl index` subcommand. The knowledge lives in prose (skill)
   and a recipe.
2. GENERATION is external + manual: user must know to install `rust-analyzer`, know `scip` is the format,
   know the exact flag. Zero of that is discoverable from `dl`.
3. --root PATH-JOIN GOTCHA (silent failure, the worst kind): the index must be generated in the same dir
   used as `--root`, or SCIP paths (`src/...`) don't join and every `scip_*` rule returns EMPTY with no
   error. Only knowable from a justfile comment. This silently looks like "SCIP found nothing" instead of
   "you pointed --root at the wrong dir."
4. 154MB ARTIFACT, NOT gitignored: `rust-sim/index.scip` was 154M and `.gitignore` had no entry. A naive
   `git add -A` would commit it. `dl` should never let the user footgun a 100MB+ blob into their history.
5. REV ASYMMETRY not surfaced: syntactic facts are any-rev; SCIP is CURRENT-TREE-ONLY (rust-analyzer
   indexes files on disk, cannot index a git blob). A user who writes `scip_fn_edge` under
   `scan(".", "<old-rev>", ...)` gets silently-empty results. Nothing warns them.
6. SILENT DEGRADE: no index => dl falls back to the syntactic callgraph with NO notice. The user believes
   they have compiler precision and does not. (`extract.rs`: "empty when no index.scip is present, so the
   syntactic path carries.")
7. STALENESS: reload-gate only re-imports when index.scip CHANGES, but the file only changes when the user
   re-runs the indexer. No freshness signal; a 20-commits-stale index answers confidently and wrong.
8. FIRST-RUN COST SURPRISE: `rust-analyzer scip` took ~2 min and produced 154M with no progress. Had to
   background it. No estimate, no progress, no "this is slow the first time" warning.
9. MULTI-LANG MATRIX is entirely on the user: rust->rust-analyzer, ts->scip-typescript,
   py->scip-python, go->scip-go, kotlin/java->scip-java, c/c++->scip-clang. A polyglot workspace needs
   several indexers, each installed + invoked + merged. Today: manual, undocumented.

## Solution/Approach — proposed turnkey surface
- `dl index` (new subcommand): detect language(s) from the tree (Cargo.toml / tsconfig.json / go.mod /
  pyproject / pom.xml / CMakeLists), map to the right SCIP indexer, check it's installed (offer/emit the
  install command if not), run it with progress, and place the index where auto-load finds it. For a
  polyglot workspace, run each and merge/co-load.
- STORE OUT OF TREE: default output to a cache path (`.dl/index.scip` or under `target/`/XDG cache), and
  if it must live at `--root`, auto-append to `.gitignore`. Never leave a naked 154M blob in the worktree.
- `dl doctor` (new subcommand): one screen -- langs detected, indexers installed?, index present + how
  fresh (commits behind HEAD), path-join sanity (do index paths share a prefix with --root?), and the
  scip_* row counts. Turns every silent failure above into a visible line.
- STATUS LINE on every run: `scip: 146k edges (fresh)` vs `scip: none -> syntactic fallback` vs
  `scip: STALE (23 commits behind)`. Kills friction #6/#7/#3 at once.
- PATH-JOIN GUARD: on load, if no `scip_*` path shares a prefix with any scanned path, WARN loudly
  ("index generated under X, --root is Y; keys will not join") instead of returning empty.
- REV GUARD: if a program reads a `scip_*` rel while a `scan` in scope pins a non-WORK rev, warn that SCIP
  only covers the working tree (optionally offer `dl index --rev <rev>` that worktrees + indexes that rev).
- FRESHNESS GATE: compare index mtime/oid vs HEAD; `dl index --watch` or daemon hook to regenerate on
  material change so "run whenever" becomes true for SCIP too.
- INSTALLER HELP: `dl index` prints the exact install line per missing indexer (rustup component add
  rust-analyzer / npm i -g @sourcegraph/scip-typescript / etc.), or `dl index --install`.

## Key Insights
- The asymmetry is fundamental and must be TAUGHT, not hidden: syntactic facts are git-native
  (blob-addressable, any rev, in-process); SCIP facts are compiler-native (working tree only, external
  pass). Users' mental model is "it should just run whenever" -- true for the scanners, structurally
  false for SCIP. Turnkey = make the boundary loud, not invisible.
- Every friction here is a SILENT failure (empty results, wrong-dir, stale, committed blob). The cheapest
  huge win is converting silence to a visible status line + `dl doctor`. Precision without a freshness/
  presence signal is a footgun, not a feature.
- SCIP's value is proven (146k resolved edges; method-vs-freefn disambiguation the regex graph can't do).
  The blocker is 100% UX/onboarding, not capability.
- Token economics for agents (from the smash refactor that spawned this): a one-shot within-file grep beats
  authoring dl; dl wins on REUSE (standing rail), CROSS-FILE/REV, and PRECISION grep fakes badly. Turnkey
  SCIP moves the break-even earlier by removing the setup tax -- that is the whole point.
