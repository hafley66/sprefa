## Problem/Context
v1 relied on `serde_json::Value` + `span_fallback.rs` re-finding spans via text
search. Fragile on repeated keys, wrong on yaml/toml. v2 fix: parse per-ext with
tree-sitter, walk through a shared DataNode trait. Captures get real byte
ranges from tree-sitter nodes directly.

Row-split semantics is the new v2 behavior (v1 was implicit cross-product that
happened to be invisible for single-capture-per-entry rules):
  - `{a: {x: $A}, b: {y: $B}}`  → 2 rows (A only; B only)
  - `{users:[{name:$N, age:$AGE}]}` → 1 joined row per user
Rule: Object{entries} entries w/ value = `[Leaf]`/`[LeafPattern]` are row_fields
(cross-product into one row template); everything else is a descent (concat,
each descent's rows augmented w/ row_template bindings).

## Solution/Approach (for #8 json op)
The json op is the last blocker before real-world dogfood:
  1. Parse the op's brace body (`json({...})`) into the local SelectStep AST
     via new `v2/src/walk/_4_brace_parse.rs` — port of v1
     `crates/sprf/src/_2_pattern.rs::parse_json_body`. Keep ScanAnnotation
     sidecar vec. Return `(Vec<SelectStep>, Vec<ScanAnnotation>)`.
  2. Lower to `Vec<CompiledStep>` once at rule-compile time via existing
     `compile_steps`. Annotations ride alongside on the op struct.
  3. Op body (runtime): dispatch by ext; if `cursor.file` is None,
     enumerate files in `cursor.repo/cursor.rev` via Reader, filter by exts
     [json/yaml/yml/toml]. Read bytes, `parse_by_ext`, `walk()`, emit one
     cursor per MatchResult (cursor.captures += row).
  4. Diagnostics: see #9.

### Annotation syntax — v2 divergence from v1
v1 used bare `repo(...)`/`rev(...)`/`repo.norm(...)`/`rev.norm(...)` as inline
annotation wrappers at value position, e.g.:
```
json({ repository: repo.norm($REPO), tag: rev.norm($TAG) })
```
v2 adds `$$` sigil for annotations (syntactic density — `re:` regex prefix,
glob literals, etc. leave no clean namespace for bare identifiers). v2 form:
```
json({ repository: $$repo.norm($REPO), tag: $$rev.norm($TAG) })
```
Grammar tightens: annotation wraps a **capture var only**, not a pattern:
```
annotation = "$$" ("repo"|"rev") (".norm")? "(" "$" SCREAMING ")"
```
Parser behavior:
  - `$$kind(...)` → expect `$NAME` inside; reject anything else with diag
    `json/annotation-requires-capture`
  - emit: one `SelectStep::Leaf { capture: Some("REPO") }` at that position
    + one `ScanAnnotation { var: "REPO", kind: Repo|Rev, norm: bool }` into
    sidecar
  - v1's `push_scan_annotations` recursive walk-over-inner goes away —
    parser emits annotation directly when it sees the form.

### Why ScanAnnotation stays (vs my earlier `$$`-capture idea)
- v1 semantics are "capture AND annotate same token." Not separable.
- Scan annotations feed Pass A (discovery) via
  `Reader::unscanned$(table, col, ScanKind, norm)` → seed cursors for
  unscanned (repo, rev) tuples. Plumbed in when sqlite store lands.
- Shared across all body-taking ops (json/yaml/toml now; line/marker later).
  Parser lives in `walk/_4_brace_parse.rs` = base lang function, not per-op.
- DO NOT introduce `SelectStep::ProvenanceCapture` variant; that was wrong.
  Walker stays annotation-unaware. Annotation is pure metadata on the op.

## Key Insights
- Object{entries} row-split rule is simple: `is_row_field` = entry value is
  `[Leaf{...}]` or `[LeafPattern{...}]`. Everything else concats. Tested
  against both user-stated cases; both pass.
- v1 "cross-product" was never visible in practice because v1 rules always
  had 1 capture per subtree. v2 makes the correct behavior explicit.
- `Capture` struct stays op-agnostic: `{text, path, byte_start, byte_end}`.
  `path` field is just a string; each op fills w/ its own addressing scheme
  (jq for data ops, node-kind path for ast-grep op later).
- DataNode is NOT the abstraction for ast-grep — ast-grep has its own
  tree-sitter consumer (ast-grep-core). What they share is the upstream
  `Reader::parsed(file, lang) -> ParsedTree` cache, not the walker.
- No `$THIS` magic binding. User names every capture explicitly. Cleaner
  schema, no reserved names.
- sqlite columns = TEXT always. NULL for both row-split gaps and json-null
  (acceptable ambiguity; add `_is_null` sidecar column later if needed).
  Subtree captures store compact-JSON string.
- Naming collision: v2 already had `Capture` in `_0_types.rs`; walker uses
  `WalkCapture`. Needs reconciliation when op wiring lands (probably rename
  the old Capture or merge definitions).
