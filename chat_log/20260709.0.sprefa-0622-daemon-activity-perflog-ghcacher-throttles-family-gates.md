## Problem/Context
- Daemon `status`/`ping` only reported tick_count/settled — no "what's it doing right now."
- Fans spinning every 5 min at scale: the `checkout(repo,branch,pr_heads)` sink did `jobs.par_iter()` (git fetch+reset across ALL repos on ALL cores) every tick it had rows, behind an `every(300)` clock = all-core storm every 5 min.
- All .dl files merge into ONE Program (`lib.rs:101` prepare_paths → load_program_set flattens); every tick runs the union. `use` is a parse-time text splice, not a module boundary. module/spine extract families returned `Ok(true)` unconditionally + wholesale-rebuilt every tick they were `used` → forced all dependents to re-derive on clock-driven full ticks even with zero file changes. type/call/dataflow/doc already self-skip via per-rev digests (`moved_extract_revs`).
- User's hard rule: "no pushing till some form of efficiency on program isolation." Picked D (dirty-gate families) before C (program groups). C deferred.

## Solution/Approach
- **Activity slot** (`src/activity.rs`, new): process-global `Mutex<Activity>` OFF the eng lock; Phase enum (Idle/ColdTick/Declare/Reconcile/ParseExtract/Derived/Operators/Effects/Query); set/detail/begin_tick/end_tick/snapshot. `ping` emits `activity:{phase,detail,program,tick,elapsed_ms}`; `dl daemon status` prints a `doing <phase> <detail> (X.Xs, tick N)` line. Phase markers wired in tick_report + daemon tick_full/tick_paths/cold-tick/poll_tick. Caught live: `doing reconcile 1 changed path(s) (0.2s, tick 2)`.
- **Perf log** (`src/perflog.rs`, new): append-only JSONL at `<root>/.dl/perf.jsonl`, default ON. `phase` record per transition (driven from activity::set/end_tick, zero new instrumentation points) + `tick` record per tick (kind, files, derived{strategy,rebuilt}, changed_rels, effects_inflight, total_ms). DL_PERF_LOG=0 off / =<path> redirect. raw File = each write visible to tail -f immediately. **CRITICAL FIX:** perflog must NOT create `<root>/.dl` — skips when dir doesn't exist (one-shot in fresh dir); daemon creates `.dl/` before cold tick so it logs from tick 1.
- **ghcacher throttles** (`src/engine/mod.rs` run_checkout_sweeps): DL_CHECKOUT_WIDTH=2 dedicated rayon pool (`.install()`); DL_CHECKOUT_MIN_SECS=300 per-repo fetch gate (static `Mutex<HashMap<slug,Instant>>`, throttled repos surface `checkout_done` `skip` row); DL_RAYON_THREADS global cap (init_thread_pool at cli::run startup); DL_NO_FETCH kill switch unchanged.
- **D — family gates:** module gets a real per-rev input digest folding FILES+MANIFESTS (`module_input_digest`, `extract:module:<rev>` key) since reconcile doesn't track manifests — `refresh_module_rels` now `Result<bool>`, returns false when no rev moved. spine is `corpus_gated()` (new trait method, default false, spine=true) → tick loop skips when `!recon.changed && !any_rel_empty(rels)`. any_rel_empty helper added. type/call/dataflow/doc untouched (scip-coupled).
- **sweep_gone_revs fix:** added "module" to the digest-prefix deletion list (`extract.rs:625`) — a gone rev must take its `extract:module:<rev>` digest with it or the gate skips repopulating wiped outputs (the diag_mute regression).
- **dl update:** added line to SUBCOMMANDS_HELP (cli/mod.rs); update.rs calls `setup::refresh_after_update` post-install → wire_global (re-writes SKILL_MD everywhere) + reinstall VSCode ext only if `vscode_extension_installed()` (opt-in preserved). Project repos: prints hint to re-run `dl setup --project`. MCP has no on-disk wiring.
- **perf_facts.rs** (new, 9 tests): cold/warm-no-change/incremental-1-file/comment-only-digest-skip/source-rule-fallback/derived-edit/timing-ceiling/module-skipped-on-warm/spine-skipped-on-warm. Proves the recompute contract per command path via `last_derived_rebuilt` (now set by tick_paths too, was only tick_report).

## Key Insights
- The families split: type/call/dataflow/doc self-skip via per-rev digest (`moved_extract_revs`) AND depend on scip → can't gate on file content alone. module/spine were the dumb ones (unconditional Ok(true) + wholesale rebuild). module input = files+manifests (reconcile ignores manifests → must self-digest, not gate on recon.changed). spine input = pure file content → safe to corpus-gate on recon.changed.
- Digest gates are unsound if outputs can be wiped independently of inputs. sweep_gone_revs wipes rev-twin rels when a rev leaves _file; the `extract:<family>:<rev>` digest MUST be deleted in the same sweep or the next tick's gate matches a wiped output and skips repopulating. module was missing from the sweep's family list because it historically had no digest.
- perflog default-on writing to `<root>/.dl/perf.jsonl` was creating `.dl/` as a side effect of one-shot runs → broke the discover test ("explicit program must not create .dl/") and wasted tokens on another machine. Fix: perflog skips when `.dl/` doesn't exist; daemon creates `.dl/` before the cold tick.
- ghcacher storm = par_iter (all cores) + every(300) cadence. Network+disk bound → 2-wide is as fast as full-core. 300s/repo gate kills the 5-min storm.
- Reactivity is NOT atrocious at the derived layer (affected_derived scoping, pinned by perf_facts) — the cost is the SOURCE/EXTRACT phase on full ticks where every family refreshes. D attacks that; C (program groups) is the full fix for independent programs.
