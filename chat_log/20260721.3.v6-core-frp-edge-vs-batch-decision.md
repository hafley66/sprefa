## Solution/Approach (the FRP debate — the crux)
- v5 GROUNDING (read from src/engine/family/): a "Family" IS the op = pure
  `Family::derive(&self, ctx, out)`; `Ctx::scan` = tracked read at RELATION granularity
  (the "hook"); `FamilyRouter` = MobX/SolidJS `computed` reconciler (reruns families
  whose input RELS changed); `register_family!`/inventory = OPEN op registration;
  source_prepare.rs `jobs.par_iter()` -> bounded `sync_channel` = rayon batch +
  backpressure ALREADY. So v5 is family-grained reactive memo + batched extraction, NOT
  streams-first. User: streams-first would shatter the rayon batch (the DataLoader trap
  the CLAUDE.md warns of). v3 was all about batching; v5 stratifies by family so ast-grep
  maximally runs rayon.
- User's critique: v5 reactivity is CRUDE ("ultra mid", "turbo fucked us") = groupBy +
  immediate rerun, no throttle/buffer/distinct. FIX (still simple Rx, not ambition):
  watch.deltas -> buffer(tick) -> groupBy(family) -> auditTime/debounce ->
  distinctUntilChanged(digest) -> mergeMap(deriveFamily). Lives in the runtime TRIGGER
  layer; the family derive fn stays a pleasant sync fn.
- MY CLAIM (the thing to prove w/ the lab): FRP the EDGE, batch the CORE.
  pain x payoff matrix: CORE (calculus/fixpoint/Family::derive/cascade/SQL) is batch-
  relational -> FRP = MAX Rust pain (lifetimes + Send/Sync on every rel row, fights
  rayon+rusqlite; Node<'r> can't cross Send; rxRust Local/Shared hell) x LOW payoff (v5
  proves batch). EDGE (watch/git/clock/user sources + the buffer/throttle/groupBy trigger
  + demand) is genuinely event-streams -> BOUNDED pain (owned events, dozen operators) x
  MAX payoff (the operators you want live here). => FRP-core is masochism; FRP-edge is
  where FRP is good in Rust AND the right dojo to master it.
- User (loves FRP, wants to master it in Rust) is reconsidering whether to just do the
  whole core in streams, and asked me to PROVE the lopsidedness with a lab rather than
  assert it.
- Lib build-vs-buy for the edge: rxRust (gaps + Local/Shared pain), futures::Stream +
  StreamExt (pull/backpressure-native, fewer operators), hand-rolled push-pull
  (native-observable). Recommended prototyping the trigger on futures::Stream first;
  core never depends on the choice.

## Key Insights
- v5 ALREADY is a reactive memo engine (FamilyRouter = MobX/Solid computed) + rayon batch
  + bounded-channel backpressure. Just crude: no throttle/buffer/distinct.
- FRP pain x payoff is lopsided: core = max pain/min payoff, edge = bounded pain/max payoff.
- The trigger pipeline IS an FRP program (json-rx shape) = the correct home for FRP.
- Pull primitive + invalidation-as-push + backpressure = Salsa. Dot-access = join =
  Souffle interning + Datomic navigation. 4 kinds closed / ops open = React.
