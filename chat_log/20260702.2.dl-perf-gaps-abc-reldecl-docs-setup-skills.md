## Key Insights
- @async/@stream response rels are written by the OFF-TICK drain; the moment
  the full tick stopped rebuilding everything on any change, their
  dependents went stale (etag stuck at etagA in gh_cache). Any future
  attribution refactor must keep the `async:<rel>` content digest.
- e2e GOTCHA: reconcile's fast path is (mtime SECS, size) — a same-second
  same-byte-length rewrite is INVISIBLE; tests must change content length
  (bit both new tests' first drafts).
- The exe (len,mtime) stamp in extract digests makes "rebuilt dl re-extracts"
  automatic — no version-salt discipline needed; dev rebuilds invalidate.
- extract:type digest reuse: doc's digest folds the stored extract:type
  value instead of re-hashing type_entity rows (O(1), order-dependent on
  type running first — both tick paths already do).
- The autogen README table doubled as the doc-text fidelity oracle for the
  consolidation: regen + empty git diff proved 65 moved strings identical.
- Digest-skip is persistent (cross-process; one-shot reruns benefit), the
  fact cache is in-memory (daemon changed-tick benefit); they compose.
