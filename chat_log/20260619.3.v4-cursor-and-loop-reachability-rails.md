## Problem/Context
Two long-running threads came to a head this session.

The rails thread: `.dl/rails.dl` is sprefa dogfooded on itself via a
PostToolUse hook (`dl --check`). The conn-outside-db rule was regex-only
(`match(/\.conn\(\)/)`) joined path-scoped (`changed(p)`). Every touch on
`engine.rs` fired 41 warnings because every `.conn()` line in a touched file
warned, regardless of whether the site was actually a per-row-write risk.
The regex couldn't distinguish `.conn().execute(` inside a `for` loop (real
risk) from `.conn().prepare(` (read-side, no risk) or `.conn().execute_batch(`
(schema DDL, no risk).

The ingestion thread: v4 had a CST framework (`v4/src/cst/dsls/{markdown,sql,
sql_where}/`) that built tree-sitter grammars on the fly. v5 has hardcoded
front-ends per language (syn for Rust, tree-sitter for Kotlin, oxc for TS).
The user's framing: "if it can be parsed, it goes into the soup of possible
shitty graphs." Currently v5's soup is three langs deep; the vision is any
tree-sitter grammar.

## Solution/Approach
Three slices shipped, plus a plan for the fourth (big).

### S1: nest composition gate (`ab907eb`)
The prior session shipped `nest(call_id, loop_id, depth, collection)` but the
composition test was uncommitted. The test builds a 3-fn chain (`go` calls
`middle` inside a doubly-nested loop, `middle` calls `leaf`) and asserts
`direct_cost(middle, 2)` holds plus `call_reaches(middle, leaf)` carries the
depth across a call hop. Engine restricts unpinned closure reads in rule
bodies, so the transitive join splits: `direct_cost` rule (no closure in body)
+ `call_reaches` closure as its own query + the Rust-side join. Same shape as
`rust_lift_closes_transitively`.

### S2: write_cursor port (`e02192f`)
v5's `gen` already had two targets: `File` (path template) and `Splice`
(line-region replace between comment markers). The port adds `Cursor`:
`gen(:mode, p, lo, hi, "tmpl")` with mode in `{replace, append, prepend,
wrap}`. Offsets are byte-accurate; in real use they come from the ref spine
(`ref(id, _, p, lo, hi)`). Implementation:
- `ast.rs`: `SpliceMode` enum + `GenTarget::Cursor { mode, path, lo, hi }`
  variant (with `Hash` for the accumulator key).
- `parse.rs`: `gen_rule` peeks `Tok::Colon` to dispatch the 5-arg form before
  falling back to the existing 2/4-arg parser.
- `typecheck.rs`: `Cursor` arm for typed-path-literal normalization.
- `engine.rs`: `Cursors` accumulator (sibling of `Splices`); `Cursor` arm in
  `run_gen`; new `apply_cursors` fn that groups regions per file, applies
  right-to-left by `lo`, dispatches on mode.
- `tests/gen_op.rs`: 5 gate tests, one per mode plus right-to-left ordering.

### S3: graph-aware conn rule (`bb66389`)
`.dl/rails.dl` rewritten. The regex `match(/\.conn\(\)/)` stays as the SEED
(finding call sites syntactically is fine); the BADNESS moves to a graph
property:

```dl
conn_fn(fn, p, l) <- match(/\.conn\(\)/), call_site(fn, "conn", p, l).
loop_hot_fn(fn)   <- nest(call_id, _, _), df_node(call_id, "call_res", _, fn).
loop_reachable_fn(fn) <- loop_hot_fn(fn, _).
loop_reachable_fn(fn) <- loop_reachable_fn(prev), call_pair(prev, fn).
diag(p, l, "warn", "conn-loop-reachable", ...) <-
    conn_fn(fn, p, l), loop_reachable_fn(fn), changed(p).
```

The engine blocks unpinned `closure(call_pair)` reads in rule bodies, so the
transitive close runs as recursive derived rules over `call_pair` on the
semi-naive fixpoint. For a call graph of hundreds of fns the cost is
negligible.

### S4 (deferred, the big plan): CST ingestion layer
The thread that didn't land: a generic ingestion path so any tree-sitter
grammar becomes a relation source. Markdown, YAML, TOML, Python, Go, the
comment regions of any lang — all should feed the soup the way Rust/Kotlin/TS
already do. Then "track docs/suspects/plans from outside the codebase"
becomes a `.dl` rule against parsed output, not a marker convention or a
builtin. See Tasks.

## Tasks
- [ ] (next, big) **CST ingestion layer**: a registry under `v5/src/ingest/`
      that takes any tree-sitter grammar and emits relations. First customers:
      markdown (headings, paragraphs, code blocks, links), comment regions
      (generalizing `v5/src/comment.rs`), and the existing Rust/Kotlin/TS
      extractors refactored onto the same trait.
- [ ] (medium) **`changed_line(path, line)`** builtin rel. Recipe queued in
      `sprefa-v5-new-builtin-rel` skill: parse `git diff -U0 HEAD` hunk
      headers `@@ -a,b +c,d @@`. Kills the path-scope noise on the conn-loop
      rule and every other line-level rail.
- [ ] (medium) **Add an `id` output column to the `match` op** so spine
      captures feed `gen(:mode, ...)` end-to-end. Today `BodyItem::Match`
      emits only `line`; the cursor port's gate tests use literal offsets
      because the spine integration isn't wired.
- [ ] (medium) **Drift-detection in `apply_cursors`** (port from v4's
      `WriteCursorComponent`): re-hash the file on disk, skip the splice if
      it changed since intern. Pairs with the `id` column above.
- [ ] (small) **`--builtins-md` emitter**: add `doc: &'static str` to `RelDecl`
      and `Col`, populate from the `///` const comments, one markdown file
      enumerating every builtin family. Started this session, reverted as a
      misread of "docs" — the user wanted the CST-layer ingestion, not a
      generator. The emitter is still useful as a low-cost inventory.
- [ ] (small) **Tighten loop-hot to "directly called from a loop-call-site"**
      instead of "fn contains any call in a loop". Today's conn-loop rule
      fires on every per-tick one-shot in `tick`'s call tree because they're
      transitively loop-reachable. The tighter signal needs
      `loop_entry_fn(fn) <- nest(call_id, _), df_node(call_id, "call_res",
      _, caller, p, l), call_site(caller, callee_text, p, l),
      call_name(fn, callee_text).` Then `loop_reachable_fn` closes from
      `loop_entry_fn` over `call_edge` instead of from `loop_hot_fn`.
- [ ] (queued from prior) extend `Db` to expose `prepare`, `query_row`,
      `execute_batch` so the remaining `.conn()` sites have an alternative.
      The conn-loop warnings are the worklist for this.

## Key Insights
- The `.conn()` rule's regex was never wrong; the rule's PREMISE was wrong.
  It assumed `.conn()` = bad, but the Db seam doesn't expose `prepare`/
  `query_row`/`execute_batch`, so most calls have no alternative. The real
  signal was always graph reachability (per-row writes inside loops), not
  syntax. Regex is fine for the SEED; the BADNESS lives in the graph.
- sprefa's body ops already cover most of v4's pipeline ops:
  - `comment(open[, close])` ✅
  - `write_file` + `render.markdown` ✅ subsumed by `gen`
  - `write_cursor` ✅ this session (`gen(:mode, ...)`)
  The real v4-to-v5 gap is the CST ingestion layer, not the operators.
- The engine's closure-in-body restriction forces a shape choice: either
  pin a literal (per-seed queries, impractical when seeds are dynamic) or
  use recursive derived rules over the base edge. Recursive rules run on the
  semi-naive fixpoint, which is slower than `closure()`'s SCC-condensed
  reachability but fine for a call graph of hundreds of fns.
- The "docs as second-dimension comments" idea is a free outcome of the CST
  layer, not a feature. Once markdown/comments/langs are relation sources,
  "track suspects/plans/docs" is a `.dl` rule, not a marker convention.
- The unifying trade across the session: resolve STRUCTURE up front
  (graph property, ingestion trait), VALUES at query time (per-call
  offsets, per-grammar relations). Same trade the prior session identified
  for soundness/Big-O/scaling.

## Open Questions
- CST layer trait shape: does `TypeLang` generalize, or does ingestion need a
  different trait (`IngestLang`?) because markdown/comments don't have
  entities/call-sites?
- Tree-sitter grammar discovery: ship a curated set in the binary, or accept
  grammar config files at runtime (v4's `cst/build/grammar_walk.rs` compiled
  grammars on the fly)?
- Should `changed_line(p, l)` come before or after the CST layer? The conn
  rule's noise fix is changed_line; the vision is CST. They're orthogonal.
- Loop-entry vs loop-hot (the small task above): does the tighter signal
  match the user's mental model of "per-row write risk"?
- Should `gen` get a `:on=NAME` capture-name form like v4's `write_cursor`?
  v5's spine doesn't expose a coord-space equivalent; the spine already uses
  byte offsets, so the named-capture case may not apply.
