## Solution/Approach
PerfKind follows the RelKind checklist skill. Gotchas discovered while
building: (a) a family deriving from other rels' state must EXCLUDE its own
rels or the self-diff oscillates; (b) NEVER COUNT(*) a closure-head rel in a
refresh — closure heads are SQL VIEWS and counting one materializes the full
closure (hung a tick for minutes; fixed by skipping sqlite_master type='view'
names). The merge bug surfaced because perf-rails.dl's usage line (`dl
prog.dl rails.dl`) didn't work — help text promised the merge, code comment
admitted "only the daemon merges multiple positionals today", silent drop.

## Key Insights
- Telemetry-family gotchas: self-exclusion (rel_count must not count itself
  or the self-diff never settles) and never scanning a closure VIEW inside a
  refresh (COUNT(*) materializes the closure — dogfood hang found it).
- stmt_ms semantics: refresh runs in the source phase, so it serves the
  PREVIOUS rebuild's timings; a one-shot CLI reports on the 2nd run over the
  same db; the daemon on every tick after its first. rel_count similarly lags
  one tick for derived rels. Documented as contract, tested as such.
- Multi-file merge was a silent-drop bug in EVERY one-shot mode; resolve_programs
  now takes &[String]; explicit multi-file runs stay in-process (daemon serves
  its own loaded set — programs.len()<=1 gate at each *_via_daemon call).
- `git commit` in a repo with a pre-staged index sweeps it; the surgical fix
  is `git reset --soft HEAD~1` then `git commit -- <path>` (partial commit
  leaves the rest of the index intact).
- Skills scope rule (memory feedback_backprop_repo_scope): repo-specific ->
  repo files; backprop only for cross-repo/tool-general. sprefa skill edits
  now happen in assets/<name>.skill.md.
- The claude-research sprefa-dl skill had silently forked from the repo's
  tracked assets/sprefa-dl.skill.md (pre-lift paths, missing the
