**`trace_dep` — the persisted verifying trace.** Corrected schema (first draft stored
repeated rel-name TEXT; user caught it — that is the exact mistake the `_strings` autopsy
was about):
```sql
CREATE TABLE rel_id (id INTEGER PRIMARY KEY, name TEXT UNIQUE);  -- ~330 rows, DENSE
CREATE TABLE trace_dep (
  key      INTEGER NOT NULL,   -- rel_id, 1-2 byte varint
  dep_key  INTEGER NOT NULL,
  dep_hash BLOB    NOT NULL,   -- blake3 TRUNCATED to 8 bytes
  PRIMARY KEY (key, dep_key)
) WITHOUT ROWID;
CREATE INDEX trace_dep_by_dep ON trace_dep(dep_key);
```
Two queries: wake-set `SELECT DISTINCT key FROM trace_dep WHERE dep_key = ?`; verify
`SELECT dep_key, dep_hash FROM trace_dep WHERE key = ?`. Recursion gets SCC granularity
(SCC ids also dense ints). Sizing: dense ids + WITHOUT ROWID + 8-byte digest ~= 6KB for
602 edges; the TEXT draft ~= 36KB plus a duplicated index.

## Key Insights
- Interning exists but is re-offered wholesale every tick. Measure the ACCEPT rate, never
  the offer rate — 99.99% of the work was re-proving known facts.
- Dense small ints beat hash-valued StringIds for any closed set: hash ids are 8 bytes and
  defeat SQLite varint encoding. Applies to rel names, SCC ids, and (still open) `_strings`
  itself — that is diet Direction 1a, the largest remaining engine lever.
- Causality is not reconstructable from periodic samples, on principle. Cost sampling and
  argument recording are different logs and both are needed.
- A pure junction table with a composite PK must be WITHOUT ROWID or you pay the key twice.
- Median wake-set of 3-of-255 is the receipt that justifies a cold/demand tier at all.
- Heuristic name-based graphs are WANTED alongside SCIP — SCIP at 500 repos does not fit a
  dev laptop. The architectural answer is to move SCIP + AST + per-language parsing behind
  one pure module, keeping both tiers.
