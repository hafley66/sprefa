## Solution/Approach
ModuleResolver trait (THE design, dissolves the expression-layer problem):
```rust
pub trait ModuleResolver: Send + Sync {
    fn lang(&self) -> &'static str;                       // "rust","ts"
    fn edges(&self, file: &str, content: &str, cx: &ProjectCx) -> Vec<ModuleRef>;
}
pub struct ModuleRef { specifier: String, kind: String, target: Resolution, line: u32 }
pub enum Resolution { File(String), External(String), Unresolved(String) }
pub struct ProjectCx<'a> { root: &Path, files: &HashSet<String> /* + manifest cache */ }
```
Registry maps lang->&dyn ModuleResolver (like ts_lang/sg_lang arms). Engine calls edges() during reconcile, writes 3 relations as facts: module_import_raw(file,rev,specifier,kind,line), module_edge(src,dst) [Resolution::File], module_unresolved(file,specifier,reason). Then reaches(a,b)<-closure(module_edge). RustResolver=rs_path.rs rehoused; TsResolver=resolve.rs build_resolver rehoused. Resolution math in Rust (Path::parent free) so NO .dl expression layer needed.

## Key Insights
- THE trait dissolves the outer-opus crux: "fat .dl Rust resolution" would need a NEW expression layer (Term has no Call variant: ast.rs:61; constraint is rigid term-op-term parse.rs:230; two evaluators term_sql lower.rs:108 + eval_cmp engine.rs:1300 + SQLite UDF). Putting resolution in Rust (the trait) means path math uses Path::parent for free, .dl never needs dir()/join().
- REV SOUNDNESS BUG (outer opus, applies to shipped Stage 1): refresh_builtin_rels sets file.rev to the RESOLVED rev — WORK stays "WORK" but git revs become 40-char SHA (resolve_rev engine.rs:291). So file(_,"WORK",b,_) returns EMPTY on git-rev queries; literal "HEAD" never survives. MUST thread rev as a VARIABLE from the import fact: file(_, rev, dst, _). Tests run on WORK so won't catch it. The trait/op fixes this by writing rows keyed by the file's actual rev.
- decomp options drawn for user: (1) dir() function=precise but opens expression layer/scope-creep risk; (2) ~ suffix operator=cheap but reintroduces basename aliasing (the 268->7 problem); (3) bind dir at extraction=precise+cheap. Trait supersedes ALL THREE (math in Rust).
- TS needs NO tree-sitter ast arm; sg.rs sg_lang already maps ts/tsx/js to ast-grep; oxc parses TS itself. ts_lang (engine.rs) only has rust+c, irrelevant for module graph.
- oxc_resolver: usable but a SECOND unsynchronized fs-cache; per-tick cache invalidation (changed tsconfig/added file) is a FIRST-CLASS requirement, not afterthought; double-stat outside engine hash discipline.
- diet-SCIP spectrum: grep < module-graph(this)+call-graph(shipped) < SCIP(symbol-level,compiler). Layers 1+2=the cheap 90%; layer 3 (per-symbol bind, v4 feat/reify entity graph) = the hard 10% SCIP pays a compiler for. This gives "which file/pkg depends on which across rs+ts + blast radius", NOT "which exact foo does this bind to".
- TWO opus reviews earlier this session converged: top finish-pick was COLUMN SPANS (shipped 4c071de). build_cond_cache double-builds (engine.rs 372/479 dup rebuild_closures 825) + builds-when-no-pinned-closure-query = real waste; fix = dedup + skip-when-unused, NOT "cache across ticks" (unsound w/o invalidation). __src='' all-zero-derived-digest TRAP (engine.rs:708) latent if digest-skip ever extended to derived rels.
- digest skip = v4 Replay short-circuit at RELATION granularity (NOT v4 row-granular MEMO_DEPS = the RAM trap). Two digests (per-relation source-hash XOR = Axis A; per-edge-set = Axis B) are the whole scaling story.
- k8s-apply mental model confirmed correct: .dl=desired-state manifest, tick=reconcile loop, fs/git=observed, SQLite=etcd, LEVEL-triggered (hash diff) + edge-triggered wakeup (fs event). SQL-UDF model: load-once wires program (stratify/closure_map/auto_indexes/affected_derived), tick runs the wired graph.
