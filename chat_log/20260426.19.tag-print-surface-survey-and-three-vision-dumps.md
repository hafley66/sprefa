## Key Insights
- print op: PrintOp::from_values accepts Atom or Str as prefix, emits cursor.active() via PrintEffect (print.rs:39, 99). NOT a template renderer.
- str op: writes to typed StrValue slot (cursor.put_slot), NOT active bytes. Consumed by downstream source ops via ArgSpec slot reads. str>print does not print the template body.
- tag classification (tag.rs:118-139): bound = Atom/Str/Int/Float + TermMode::Read; unbound = TermMode::Unbound; mixed = error tag/mixed-mode; op = error tag/op-arg-unsupported. First arg must be Atom (bag name).
- tag? variants (TagPredicateOp): all-bound→Probe (strict), mixed→Join (datalog filter+project), all-unbound→Query (drain+subscribe).
- ${X} carveout_expr is value-position only. Pipe steps must be op_invocation. Grammar separation is intentional.
- `;` distributes parent step as Fork. NOT a statement separator. Two top-level pipes go on separate lines.
- Tag = dynamic per-cursor relation writes (streaming during drain). Rule = static-dynamic compiled table sink. Both needed.
- Run-hash for deterministic output naming should match OpCache::cache_key composition (blake3 over config_source || seed_roots || pipeline_source).
