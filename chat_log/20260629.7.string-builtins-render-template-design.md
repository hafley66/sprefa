## Solution/Approach
PARKED DESIGN (do not build without fresh user pull): a trailing-block render form
  gen("path")`...template...`   ( ) and backtick adjacent )
with ${var} holes and nested ${ iter => `line` } map directives. Desugars to ONE whole-file
query: UNION of arms, each arm tagged with an integer-array sort key from its position in the
template nesting (line-ordinal always a key slot); ORDER BY key gives correct nested
interleaving. Flat tables = depth-1 case. Pure compile-time sugar; one engine capability =
explicit sort key on whole-file gen rule.

## Key Insights
- gen holes are render-time {var} (tmpl_holes/render_tmpl post-query), NOT SQL-time ${var}
  (Term::Interp). Block could reuse render_tmpl unchanged.
- Lexer backtick scan (lex.rs:83-96) is raw scan-to-first-backtick, no nest/interp; ${}
  scan (lex.rs:138) is scan-to-first-} no brace depth. Nested template needs depth-aware
  scanner; minimal-ripple route = activate nesting ONLY on ${ (existing ast_yaml backtick
  bodies use $X not ${}, so unaffected).
- Flat gen(:append) rules provably CANNOT interleave nested loops (heading-per-group then
  items): rules concat whole-rule-at-a-time. Nesting needs a template-block value somewhere.
- Trio of Sonnet opinions (compiler-eng / lang-designer / minimalist-purist) UNANIMOUS on:
  integer-array sort keys never stringified; aggregate-hole = general join(expr,sep) not
  template magic; rendering belongs IN the language (no host to defer to; fixpoint already
  separates compute/emit). SPLIT on syntax (2 paren'd vs 1 trailing-block; user chose
  trailing) and on desugar target (2 union-direct vs 1 doc_node+flatten; pick union -
  doc_node adds a flatten op + relation convention = MORE core, conditional sections already
  expressible in map body).
- doc_node(id,parent,ord,text)+flatten(doc_node) is the rejected alternative (circular: tree
  IS the output, nobody queries it).
