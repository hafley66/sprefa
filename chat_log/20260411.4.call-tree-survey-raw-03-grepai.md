# grepai Call-Tree Survey

## grepai

- **language:** Go 1.24.2
- **runtime:** Standalone CLI binary (also MCP server, daemon mode)
- **build:** go build with build tags (treesitter optional); cross-compile via Makefile
- **license:** MIT
- **store:** GOB (Go binary format) encoding
- **store_file_path:** `.grepai/symbols.gob` per project; workspace config at `~/.grepai/workspace.yaml`
- **schema_shape:** GOB-serialized SymbolIndex{Symbols map[string][]Symbol, References map[string][]Reference, CallGraph []CallEdge, UpdatedAt time.Time, Version int}
- **extractor:** Dual-mode: RegexExtractor ("fast") + TreeSitterExtractor ("precise" when treesitter build tag enabled)
- **languages_supported:** Fast mode: Go, JS, TS, JSX, TSX, Python, PHP, Lua, C/C++/C++, Zig, Rust, Pascal. Precise mode (tree-sitter): Go, JS, JSX, TS, TSX, Python, PHP, C#, F# (via smacker/go-tree-sitter bindings)
- **locals_resolution:** Syntactic + Scoped. Tree-sitter extracts receiver types for Go methods (fieldByName "receiver"), parent-chain walk for containing function (lines 868–912 extractor_ts.go). Regex mode uses regexes with receiver-aware method matching (lines 103–141 extractor.go). No cross-file semantic resolution.
- **call_edge_model:** Direct only. CallEdge{Caller, Callee, File, Line, CallType}. Extracted from Reference{CallerName, SymbolName, ...} during SaveFileWithContentHash (lines 194–203 store.go). Supports call_expression (JS/TS/Go/Python), invocation_expression (C#), application_expression (F#), member_expression (JS/TS property reads/writes).
- **call_order_preserved:** Yes. References and Symbols include Line and Column fields; tree-sitter nodes expose StartPoint().Row/Column (line 681–682 extractor_ts.go). Store maintains CallGraph as ordered slice.
- **branch_path_preserved:** Yes. File field on Symbol, Reference, CallEdge. No branch-level segregation; workspace mode merges multiple project stores.
- **cross_file_resolution:** No semantic cross-file. Caller/callee matching is name-based lookup in symbol index (LookupSymbol by name, LookupCallers/LookupCallees by SymbolName). MCP server aggregates across workspace projects (trace.LoadWorkspaceSymbolStores, handleTraceCallersFromStores line 1112–1130 server.go).
- **query_surface:** MCP tools: grepai_trace_callers, grepai_trace_callees, grepai_trace_graph, grepai_refs_readers, grepai_refs_writers, grepai_refs_graph. CLI: `grepai trace callers|callees|graph`, `grepai refs readers|writers|graph`. JSON + toon (token-efficient) output formats.
- **interop:** MCP server (mark3labs/mcp-go), stdio-based. Can be embedded as library (trace, store packages public). No WASM.
- **incremental:** Yes. File watcher (fsnotify) debounces changes (watcher.go). Content-hash caching (SaveFileWithContentHash line 176). Symbol store persists to single .gob file. Index updates via SaveFile delete+re-add per-file (lines 169–212 store.go).
- **loc_approx:** ~60K Go lines total. trace/ ~2.8K, store.go 556, extractor_ts.go 943, mcp/server.go ~1500, cli/mcp_serve.go extensive.
- **core_files:** `/trace/trace.go` (types), `/trace/store.go` (GOBSymbolStore), `/trace/extractor.go` (RegexExtractor), `/trace/extractor_ts.go` (TreeSitterExtractor), `/mcp/server.go` (MCP surface), `/watcher/watcher.go` (file watch + debounce), `/cmd/grepai/main.go` (entry point)
- **call_extraction_mechanism:** Tree-sitter call node visits in walkNodeForReferences (line 657–700 extractor_ts.go). Pattern matching: call_expression | invocation_expression (Go/JS/TS/Python/PHP) → funcNode = ChildByFieldName("function"/"expression") → extract name and caller via findContainingFunction (line 868–912). Special case: application_expression for F# (line 703–745). Member expressions for JS/TS property reads/writes (lines 689–693, 751–799).
- **partial_tree_support:** No. Full parse required; tree.RootNode() → recursive walk (lines 70–88 ExtractSymbols, 636–654 ExtractReferences). Single-pass extraction via ExtractAll (line 915–924).
- **unique_ideas:** (1) Dual extractor modes (regex fast vs tree-sitter precise) selectable at index time. (2) Workspace concept: multi-project symbol stores merged at query time (trace.LoadWorkspaceSymbolStores). (3) Refs graph for non-call property/data usage (read/write kinds). (4) MCP-native: tools exposed directly to Claude Code, Cursor, Windsurf. (5) Debounce-batched file watch (pending map, timer-flush). (6) Content-hash incremental caching (GetFileContentHash). (7) Optional receiver field for method resolution (Go-specific).
- **wasm_embeddable:** No CGO (tree-sitter bindings require C, optional treesitter build tag).
- **stdin_stdout_friendly:** Yes. MCP server operates over stdio. CLI outputs JSON or toon format. No streaming; full result buffered.

## Analysis

### Tree-Sitter Call Node Visits

grepai uses smacker/go-tree-sitter for precise mode. The extractor walks the parse tree recursively:
- Entry: TreeSitterExtractor.ExtractReferences (line 636, extractor_ts.go) parses file into tree, calls walkNodeForReferences on root.
- Walker: walkNodeForReferences (line 657) iterates each node's children (lines 696–699) and checks nodeType for language-specific call patterns.
- Call node detection:
  - **Go/JS/TS/Python/PHP**: nodeType == "call_expression" OR "invocation_expression" (line 664). Extracts callee name from ChildByFieldName("function"/"expression") (lines 665–673).
  - **F#**: nodeType == "application_expression" (line 703, walkFSharpCalls). First child is the function being called (lines 713–721).
  - **JS/TS property access**: nodeType == "member_expression" triggers extractMemberAccessReference (lines 689–693, 751–799) to track property reads vs writes via parent assignment check.

### Caller Context Resolution

All call references include CallerName via findContainingFunction (line 675, 733, 789):
- Traverses up parent chain until a function_declaration/method_declaration/constructor_declaration is found (line 902).
- For F#, searches for function_or_value_defn or method_or_prop_defn (lines 874–898).
- Returns function name from ChildByFieldName("name") or "<top-level>" if no enclosing function (line 911).
- Syntactic scope only; no semantic inter-procedural analysis.

### Trace Callers / Callees Implementation

MCP handlers (mcp/server.go):
- **handleTraceCallers** (line 1065): Calls store.LookupCallers(symbolName) → returns all Reference rows where SymbolName matches (store.go line 280–289).
- **handleTraceCallees** (line 1243): Calls store.LookupCallees(symbolName, file) → iterates CallGraph edges where Caller == symbolName (store.go line 292–306).
- Cross-workspace: LoadWorkspaceSymbolStores (workspace.go line 12–53) loads per-project GOBSymbolStore, aggregates results (handleTraceCallersFromStores line 1112–1139).

Both use name-based lookup only; resolution band is **lexical + name matching**. No semantic type checking.

### Storage Format: GOB

Location: .grepai/symbols.gob (config.GetSymbolIndexPath)
Struct (store.go lines 25–29):
```
type gobSymbolData struct {
  Index             SymbolIndex
  FileIndex         map[string]bool
  FileContentHashes map[string]string
}

type SymbolIndex struct {
  Symbols    map[string][]Symbol
  References map[string][]Reference
  CallGraph  []CallEdge
  UpdatedAt  time.Time
  Version    int
}
```

Persistence: gob.Encoder/Decoder (lines 78, 150); atomic write via temp file + rename (line 161 store.go).
Per-file updates: DeleteFile (line 215) removes all symbols/references for a file, SaveFile re-adds (line 170).

### Resolution Band

- **Lexical**: Symbol names extracted from source (regex or tree-sitter AST).
- **Syntactic**: Tree-sitter parse order, parent chain walk for scope (lines 868–912).
- **Scoped**: Method receiver types stored (Go struct field "Receiver", line 30, 134 trace.go); no cross-module scope resolution.
- **Semantic**: None. No type graph, no import path resolution, no generic specialization.

### Extensibility Seams

1. **SymbolExtractor interface** (trace.go line 122–137): Pluggable extractors. Two implementations: RegexExtractor, TreeSitterExtractor. Build tag treesitter gates precise mode.
2. **SymbolStore interface** (trace.go line 140–185): Pluggable persistence. Currently only GOBSymbolStore. Could add SQL store, cloud backend.
3. **MCP tool registration** (mcp/server.go line 166–350): registerTools() adds tools dynamically. New trace types can be added by new mcp.NewTool() + handler.
4. **Language pattern registry** (trace/patterns.go): Map-based language pattern registration. New language support via new languagePatterns entry.
5. **Build tags**: treesitter optional (extractor_ts.go has //go:build treesitter). Fast mode always available.

### MCP Server Surface

Registered tools (mcp/server.go lines 166–350):
- grepai_search (semantic search + RPG context)
- grepai_trace_callers
- grepai_trace_callees
- grepai_trace_graph (both callers + callees with depth)
- grepai_refs_readers, grepai_refs_writers (property/state usage)
- grepai_refs_graph
- grepai_index_status
- grepai_list_workspaces
- grepai_list_projects
- grepai_rpg_* (RPG semantic layer)

Each tool has compact/full output modes, JSON/toon format option, workspace/project context parameters.

### Call Order and Source Preservation

- **Line/Column**: Reference and Symbol both store Line + Column (trace.go lines 43–44, 98–101).
- **tree-sitter**: StartPoint().Row + Column extracted (line 681–682).
- **Order in store**: CallGraph is []CallEdge slice, maintains insertion order (line 70 trace.go). Query returns slice in order (LookupCallers returns all matching refs).
- **Branch preservation**: File field on every entity; no git branch tracking at index level (workspace mode merges across projects).

### Incremental Indexing

Watcher (watcher.go):
- fsnotify-based file system events (line 32).
- Debounce with pending map + timer (lines 39–41). flush() aggregates events (line 209).
- Events emitted as EventCreate/Modify/Delete/Rename (lines 16–23).

Store incremental:
- SaveFileWithContentHash (line 176 store.go) accepts contentHash, deletes old entries for file, adds new.
- GetFileContentHash (line 551) returns stored hash; indexer can skip unchanged files.
- No delta/patch support; full file re-index on change.

### Missing Semantic Features

- No import resolution (Go import paths, JS/TS module resolution).
- No type graph or property type inference.
- No generic/template specialization tracking.
- No call-site context binding (overload resolution only by name).
- No inter-procedural data flow.

### Precision Trade-offs

**Fast mode (regex)**:
- Quick on large codebases.
- Handles common patterns reliably.
- Misses edge cases (complex syntax, comments, nested generics).
- No syntax tree context for scope disambiguation.

**Precise mode (tree-sitter)**:
- Full AST guarantees syntactic accuracy.
- Handles all language syntax correctly.
- Still lexical/name-based resolution (no semantic cross-file).
- Requires CGO + build tag; slower on huge files.
