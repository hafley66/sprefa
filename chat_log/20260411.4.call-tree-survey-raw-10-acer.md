## Analysis

### Preprocessor/Generator Seam

The architectural seam is the `PreprocessResult` dataclass (/Users/chrishafley/projects/ext/ACER/src/acer.py:29-31):

```python
@dataclass
class PreprocessResult(Generic[UniqueMKey, NonUniqueMKey, MDV]):
    method_dict: Dict[UniqueMKey, MDV]
    unique_dict: Dict[NonUniqueMKey, List[UniqueMKey]]
```

**Preprocessor side** (/Users/chrishafley/projects/ext/ACER/src/acer.py:33-59):
- Parses all files once to tree-sitter roots via `files_to_roots()` (/Users/chrishafley/projects/ext/ACER/src/acer.py:38-53)
- Implements `preprocess(files) -> PreprocessResult` (abstract, user-implemented)
- Extracts method definitions and builds two dicts:
  1. `method_dict`: Full unique method signature (e.g., package.class.name(params)) → AST Node
  2. `unique_dict`: Ambiguous lookup key (e.g., method_name only) → List of full keys that match

Example from JavaNR (/Users/chrishafley/projects/ext/ACER/examples/Java/JavaNR/NR.py:33-85):
- Scans for method_declaration, constructor_declaration nodes
- Extracts class container, method name, formal parameter signature
- Builds MethodKey = (FullType, method_name, param_tuple)
- `unique_dict[method_name]` collects all overloads

**Generator side** (/Users/chrishafley/projects/ext/ACER/src/acer.py:110-220):
- Receives `PreprocessResult` via `generate(files, entry_points_or_calc_function)` (/Users/chrishafley/projects/ext/ACER/src/acer.py:229-233)
- Implements three abstract methods:
  1. `_seek_call_sites(caller: Node) -> Sequence[Tuple[Optional[AnalysisContext[UniqueMKey]], Node]]` — finds call site AST nodes within method body
  2. `_resolve_call_site(call_site: Node, caller_key) -> Tuple[List[NonUniqueMKey], List[UniqueMKey]]` — resolves call site to potential callees
     - Returns both "real keys" (exist in method_dict, added to deque) and "fake keys" (implicit methods, not analyzed further)
  3. `_resolve_caller(caller: Node) -> UniqueMKey` — converts caller AST node to unique method key (optional)

Call resolution flow (/Users/chrishafley/projects/ext/ACER/src/acer.py:182-220):
1. For each method in entry points, invoke `_seek_call_sites(caller_node)`
2. Enqueue (AnalysisContext, call_site_node) pairs into AnalysisDeque
3. For each dequeued call site:
   - If context lacks caller_key, invoke `_seek_caller()` + `_resolve_caller()` 
   - Invoke `_resolve_call_site()` to get real/fake callees
   - For real keys: look up in `unique_dict` to expand to all matching methods
   - For fake keys: record edges without analysis (implicit methods)
   - For any new callee not yet visited (checked via `visited: Set[int]`), re-enqueue its call sites

### Data Flow

File I/O → Preprocessor.preprocess() → PreprocessResult → Generator.generate() → CG dict → text file

The seam enforces:
1. **Definition vs. Use separation**: Preprocessor catalogs all definitions; Generator finds uses
2. **Lazy analysis**: Only methods reachable from entry points are analyzed (AnalysisDeque avoids full-program traversal)
3. **Pluggable resolution**: NonUniqueMKey is user-chosen. NR uses method_name only. SCHA uses (class_shorthand, method_name, param_count).
4. **Visited tracking**: node.id stored in set to prevent re-analysis of same call site across contexts

### How New Languages Are Added

1. Add tree-sitter grammar to init_tree_sitter.py (/Users/chrishafley/projects/ext/ACER/init_tree_sitter.py:12-27)
   - Clone tree-sitter-{lang} repo
   - Add to Language.build_library() call (currently Python, Java, C++)
2. Create subclass of Preprocessor[UniqueMKey, NonUniqueMKey, MDV]
   - Implement preprocess() to extract method definitions and populate method_dict, unique_dict
   - Use tree_sitter_utils functions to traverse AST (find_all_children_of_types, find_first_child_of_type, etc.)
3. Create subclass of Generator
   - Implement _seek_call_sites() to find call site nodes in a method body
   - Implement _resolve_call_site() to map call site to potential callee keys
   - Optionally implement _seek_caller(), _resolve_caller() for context-sensitive analysis

Example: JavaSCHA extends JavaNR (/Users/chrishafley/projects/ext/ACER/examples/Java/JavaSCHA/SCHA.py:89-161):
- Adds inheritance hierarchy tracking in models_cache
- Overrides unique_dict to use AlmostKey = (FullType, method_name, param_count) instead of just method_name
- In preprocess(), synthesizes inherited methods into subclass entries

### Source-Order Preservation

Not preserved. The output is a set-based adjacency list (Dict[UniqueMKey, Set[UniqueMKey]]), which discards order. Call order within a method is not tracked; only the fact that a caller invokes a callee is recorded.

### Storage Format

In-memory: `Dict[UniqueMKey, Set[UniqueMKey]]` (line 19 of acer.py)
On-disk: Text file, one edge per line: "caller_key->callee_key"
Example output from JavaNR (/Users/chrishafley/projects/ext/ACER/examples/Java/JavaNR/NR.py:130-136):
```
(MethodKey).__str__() -> (MethodKey).__str__()
```

### Interop Model

Loosely coupled via:
1. **AST node passing**: Generator receives tree-sitter Node objects from Preprocessor-populated method_dict
2. **Key stringification**: Output uses NamedTuple.__str__() to serialize method keys
3. **No structured interchange**: No JSON/protobuf; preprocessor output is directly referenced by generator (both in same Python process)

### Visitors for External Analysis

User-implemented via:
- Metrics dataclass (e.g., SCHAGenerator.metrics in /Users/chrishafley/projects/ext/ACER/examples/Java/JavaSCHA/SCHA.py:241-247)
- Post-generation iteration over res dict to write edges

No built-in visitor pattern; users write analysis as post-processing.
