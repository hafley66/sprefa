## Problem/Context
Five distinct work units, each closing a documented gap:

### 1. Examples gap (audit finding)
Prose docs (README, lsp.md, rails.md) were already current with session 9
features. But split/replace, def_target/hover, and call_kind had tests +
prose with NO runnable `examples/*.dl`. The gen FILE-sink form
(`parse.rs:534`, `engine.rs:3590-3608`) existed but had zero example
usage (both gen-* examples used splice form). auto-doc.dl filled this.

### 2. Lazy-indexer scan coupling (footgun surfaced while writing examples)
`type_entity`/`call_def`/`call_kind` populate ONLY over files a `scan`
rule in the program pulls in. Programs referencing type_entity without
a scan get zero rows. Both `lsp-def-target.dl` and `auto-doc.dl` carry
an `index_over` scan rule for this reason; comment in each explains why.

### 3. docs/lsp.md def_target pattern bug (found while writing example)
The documented pattern `def_target(name, f, l, "fn") <- type_entity(_, name, "function", _, f, l)`
mis-routes methods to the "type" catch-all because methods have
kind="method" not "function". New example uses `=~ /function|method/`
regex routing; docs/lsp.md snippet still wrong if user wants to sync.

### 4. Pre-existing lexer UTF-8 bug (surfaced via auto-doc output)
Em-dash in gen template rendered as `ââ`. Root cause: `lex.rs:137`
(string body) and `lex.rs:166` (regex body) pushed each byte via
`b[i] as char`, which independently Latin-1-promotes each byte of a
multibyte UTF-8 sequence and double-encodes it. Plain `? x("em—dash")`
also mojibaked. Fixed both arms to slice runs of boring bytes via
`src[start..i]`. Pre-existing bug, not introduced by session 9.

### 5. Daemon mode (user-raised architecture question)
User asked: "are we running as daemon in background with file watchers?
basically gradle design but also it should be lsp/cli daemonizable like
v4, i dont want a fuck load of bins lol". v5 currently has one binary
with foreground mode flags (--watch, --lsp, --check) that don't compose:
no shared warm cache, no IPC, no daemon discovery. v4 had separate
sprefa-daemon / sprefa-lsp / sprefa-run bins (explicitly NOT what user
wants). User progressively expanded scope across three turns:
- gradle-style single bin + menu bar tray (mac), cross-platform
- dashboard UI: active files, request log (cli vs lsp vs watcher, full
  vs incremental), db explorer
- resolved-paths panel + interaction history + anim as UI host +
  "ultimate code interaction helper for both self and AI" vision

### S2: UTF-8 lexer fix
Two `else` arms changed from byte-at-a-time to slice-runs:
- string body (lex.rs:137): batch bytes until next `"`/`\`/`$`, push
  `src[start..i]` to `cur`
- regex body (lex.rs:166): batch bytes until next `/`/`\`, push
  `src[start..i]` to `s`
Escape cases (`\X`) untouched; `\` is 0x5c and never appears in UTF-8
continuation bytes, so escape byte is always ASCII. Three regression
tests cover string literal, regex body, interpolation chunks.

## Key Insights
- The lazy type/call-graph indexers (type_entity, call_def, call_kind,
  df_node, loop_over, nest, etc.) populate ONLY over files some rule's
  `scan` pulls in. This is the "pay only for what you reference" rule
  in action, but it's a real footgun: programs that reference type_entity
  without a scan get zero rows, silently. Two of three new examples
  carry an `index_over` scan rule to bridge this. Worth a README sentence.
- docs/lsp.md's def_target pattern is wrong for methods: kind="method"
  ≠ "function", so methods fall through to the catch-all "type" rule.
  The fix is `=~ /function|method/` regex routing, which doubles as a
  demo of the unified `=~ /.../` literal.
- The lexer UTF-8 bug was pre-existing and orthogonal to session 9
  work; it surfaced only because auto-doc.dl's template had an em-dash.
  `b[i] as char` is the smoking gun anywhere in a byte loop over UTF-8
  source. The fix pattern (slice runs of boring bytes via `src[start..i]`)
  applies to any similar byte-loop reader. Same idiom likely exists in
  modgraph.rs, datapath.rs, lsp.rs (all flagged by grep for `as char`-
  adjacent patterns but not investigated).
- The gen FILE-sink form existed in engine.rs and parse.rs but had
  zero example coverage. The two gen-* examples are splice-form (in-
  place between markers). auto-doc.dl is the first to show end-to-end
  file generation from indexer output — the "auto doc actually doc'ing"
  shape.
- Daemon plan architecture: separate anim process talking to the dl
  daemon over the same local socket CLI/LSP use. This unifies all
  clients (CLI, LSP bridge, dashboard, analytical views) as peers.
  Removes the existing --watch + --lsp double-tick pathology (two
  processes fighting over cache.db).
- macOS tray requirement is `LSUIElement=true` in Info.plist (accessory
  mode): status item top-right, no Dock icon, no cmd-tab entry. This is
  the user's "menu bar not shift-tab" requirement. Requires `.app`
  bundle packaging.
- Dashboard vision expanded across turns: started as 3 panels (active
  files, request log, db explorer), grew to 4 (resolved paths), then
  to the broader "ultimate code interaction helper" framing where
  anim hosts BOTH the operational dashboard AND the analytical views
  (hotspots, blast radius, call/type/module graphs) that today exist
  only as one-shot .dl programs.
- The req log is the unified interaction history: cli requests, lsp
  requests, watcher ticks, manual --changed, all in one ring buffer +
  persistent jsonl spill. This is the "see our interaction history in
  the app" requirement.
- Tray crate choice: tray-icon (tauri team, pure Rust, no Gtk dep).
  Dashboard host: anim (existing React/Vite/d2 stack). Not wry inside
  the dl binary — anim is a separate process, opened by the tray menu.
