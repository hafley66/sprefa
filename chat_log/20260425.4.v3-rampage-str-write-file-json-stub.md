## Solution/Approach

### str polarity inversion (sprefa-6sh)
str is now a **raw-DSL paren body op**, not a value-list op. Lowering:
walk host CST `op_invocation` paren slot, slice literal-byte gaps around
`term_ref`/`carveout_expr` child ranges. `str(hello ${X} world)` →
`Lit("hello ") + Term(X) + Lit(" world")`. Bare bytes — punctuation,
whitespace, identifiers — are all literal. The only structural carveouts
are `${NAME}` (Read) and `$NAME` (term_ref). `${NAME?}` and `$NAME?`
(Unbound) rejected with `term/unbound-not-allowed-in-str`. Sub-pipe
carveouts (`${ op() }`) rejected with `str/no-pipe-carveout`.

Runtime: substitute Read terms from `cursor.captures`, concatenate,
stash result into `StrValue` slot for downstream source ops.

Polarity locked: **re/glob/comment MINT bindings; str CONSUMES bindings.**

### write_file(<path>) op (sprefa-5h0)
First non-print MutationEffect-shape op. Path arg accepts:
- `Value::Str` / `Value::Atom` — literal path
- `Value::Term { Read }` — bound capture's bytes as path
- `Value::Op` — sub-op evaluated at runtime, `StrValue` slot read
  (idiomatic: `write_file(str("dir/", ${X}, ".out"))`)

`Value::Term { Unbound }` rejected. WriteFileEffect carries
`(path: Arc<Path>, bytes: Arc<[u8]>)`. Sinks: `Disk` (creates parents,
returns `Result<(), Arc<str>>`) and `Buffer` (test-side capture).

Cursor flows through unchanged; write happens via batched effect.

### OpCtor::from_paren_node escape hatch (sprefa-1je)
The mechanism that made str's DSL body possible. Added to `OpCtor`:
```rust
fn from_paren_node(
    inv_node: Node<'_>,
    src:      &[u8],
) -> Option<Result<Self, Vec<PatternDiagnostic>>> { None }
```
Default returns None. Ops override to take ownership of CST walking
(bypassing `lower_paren_slot`'s bare-ident diagnostics).

Registry gains `build_from_node`: unified pipe-step builder that tries
node-factory first, falls through to pattern path (re/glob via
`compile_pattern`, wrapped via `ArcOpAdapter` for Box<dyn Op>), falls
through to value path (`lower_paren_slot` + `from_values`).

`sprefa-run.rs` and `backend.rs` lowering collapsed to single
`build_from_node` call. Pre-existing 175 baseline tests still pass.

- json gets a sub-grammar (grammar.js + parser.c regen) for the brace

- Or: json uses `OpCtor::from_paren_node` (the escape hatch landed this
  session) to walk host CST and run the v2 `parse_body` byte parser
  directly. Simpler — no parser regen.

## Key Insights
- The "raw paren body" need (str's case) didn't require a sub-grammar
  + parser regen. `from_paren_node` taking the host CST `op_invocation`
  Node is enough — the host grammar already parses term_refs and
  carveouts inside any paren slot, the lowerer just slices literal bytes
  in the gaps. Same mechanism will work for the brace-walker json port.
- Pattern-op-at-pipe-step was actually broken (registry.build only
  consults factories, not pattern_factories). The new `build_from_node`
  fixes this in passing — pattern ops at pipe-step now compile via
  sub-grammar and wrap into Box<dyn Op> via `ArcOpAdapter`. No tests
  exercise this yet but the path is now correct.
- jq-path is structurally weaker than the brace walker for the
  verification harness. Multi-capture nested patterns
  (`{ deps: { $K: { version: $V } } }`) are the actual harness shape;
  jq's "single value at path" model fans out cursor-per-element but
  doesn't capture key/value pairs together.
- ast-grep's `${VAR}` sugar mechanism (token-run + synthetic
  `$SPRFSLOTN` metavar + named regex) is the trickiest part of the v2
  op. Worth a focused design session before the port lands.
