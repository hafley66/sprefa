## Key Insights
- `ast_yaml(path, rev, :lang, `<RuleCore yaml>`, line, col, end_line, end_col)` = ast-grep RELATIONAL rule (pattern/inside/has/not/any). parse.rs:561 -> run_ast_yaml (sg.rs:80). `sg(...)` is PATTERN-ONLY (run_sg). ast_yaml supersets sg. `_` discards an output positional.
- Rust test-mod detection via ast-grep: `not: inside: {kind: mod_item, has: {field: name, regex: '^tests?$'}, stopBy: end}`. The `#[cfg(test)]` attribute is a SIBLING of mod_item (not a child), so `has` can't see it — anchor on the mod NAME instead. All real .unwrap() in mod tests get excluded; grep-counting text (18) overcounts vs ast-grep call matches (12, comments/strings excluded).
- `dl examples` is ALREADY productionized: build.rs::embed_corpus -> EMBEDDED_EXAMPLES/EMBEDDED_STD (include_str!), src/corpus.rs run() intercepted in main.rs like `setup`. `--show NAME` prints body from binary (trims .dl). Also powers embedded `use "std/..."` fallback (frontend.rs). Reinstall REQUIRED after editing an example (embed baked at build time).
- `dl setup` was fully non-interactive pre-this-session. `setup` and `examples` are subcommands intercepted in main.rs (raw.first()==Some("setup"/"examples")) BEFORE clap's flat positional parser.
