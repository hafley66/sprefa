### S2: Phase 1 daemon
Architecture decisions:
- **Wire codec** (`src/rpc.rs`, ~200 lines): JSON-RPC 2.0 over
  Content-Length framing, same as LSP. Typed `Request`/`Response`/
  `RpcError` envelopes. Frame reader slices ASCII headers byte-by-byte
  (no UTF-8 issue — headers are ASCII per spec). 6 unit tests.
- **Daemon module** (`src/daemon.rs`, ~600 lines): `Daemon` struct
  with `Mutex<Engine>`, `AtomicU64` tick count, `AtomicBool` shutdown,
  `Mutex<Vec<PathBuf>>` last_changed_paths, `Mutex<Vec<Arc<Mutex<UnixStream>>>>`
  subscribers. Threads:
  - Main: `UnixListener::accept` loop, spawns thread per connection.
  - Watcher: notify recommended_watcher + 150ms debounce + cfg/git
    dir watch; dispatches to tick_full (cfg/git/program change) or
    tick_paths (file change). Program edit exits for respawn.
  - Idle: 30min default (DL_DAEMON_IDLE_SECS overrides); checks every
    30s; on expiry cleans up + exits process.
- **Socket**: `<root>/.dl/daemon.sock` (mode 0600, std::os::unix::net).
  Windows named-pipe swap deferred (plan said mac-first).
- **PID file**: `<root>/.dl/daemon.pid` (pid\nstart_secs\nprog\n).
- **RPC methods**: ping, query, diag, definition, hover, subscribe,
  shutdown. query uses new `Engine::run_queries_capture` returning
  `QueryResult{rel, columns, rows}` (extracted `query_one_sql` from
  existing `run_query`; foreground path unchanged).
- **Spawn-if-missing**: `ensure_daemon(root)` connects, pings; if
  fail, spawns `dl --daemon --root X` detached (stdio to
  `<root>/.dl/daemon.log`), poll-connects with backoff (10/20/40/
  80/160/320/500ms capped; 5s total).
- **Auto-attach gate** (`enabled_for(root)`): daemon manages a
  workspace only when `<root>/.dl/` exists. Without it, in-process
  (the same gate discovery mode uses). This means tests pass without
  per-file `DL_NO_DAEMON=1` env edits — only the `.dl/`-having
  workspaces get the daemon.
- **Auto-attach in lib.rs**: `run_file` / `run_check` try daemon path
  first when `enabled_for(root) && db_path.is_none()`; fall back to
  in-proc with stderr warning on failure. Discovery mode (no
  positional) defaults db to `<root>/.dl/cache.db` regardless; with
  daemon on, main.rs also defaults db to cache.db for --lsp/--check/
  --diag-json so the LSP process reads the daemon's WAL updates.
- **LSP integration** (`src/lsp.rs`): best-effort subscriber thread
  (not a true RPC bridge — that's Phase 4 v2). Spawns when
  `enabled_for(root)`. Sends `subscribe` RPC; reads framed
  notifications forever; each diag_changed forwards through the LSP
  connection.sender as a synthetic `dl/diagChanged` Notification.
  Main loop matches the synthetic method and triggers re-publish.
  Reuses the existing `publish(connection, eng, root, only_abs)`
  per-path API.
- **CLI** (`src/main.rs`): `--daemon` foreground, `--stop` retire,
  `--no-daemon` opt-out. `DL_NO_DAEMON=1` env equivalent.
- **Tests** (`tests/daemon.rs`, 3 tests): ping/query/diag/shutdown
  round-trip via raw socket; --stop flag; DL_NO_DAEMON=1 opt-out.
- **Known limits**: shutdown exits the process directly (accept loop
  is blocked on incoming(); graceful wake via self-pipe is v1.2
  polish); unix-only socket.

### S3: Targeted publish (phase 1.1)
- Daemon tracks `last_changed_paths: Mutex<Vec<PathBuf>>`. tick_full

- `broadcast_diag_changed` includes paths in params.

## Key Insights
- The auto-attach gate (`enabled_for(root)` = `<root>/.dl/` exists)
  was the key design choice that kept existing tests working without
  per-file env edits. The same gate discovery mode uses. Tests
  without `.dl/` skip the daemon entirely; tests with `.dl/` + `--db`
  pass db_path=Some and skip the daemon path that way.
- `_prov` already gives file-scoped incremental DB updates; the v1
  daemon's full-broadcast publish was the mismatch. v1.1 aligned the
  publish layer with `_prov`'s granularity: one file in → only that
  file's diag rows out (to the editor).
- The shutdown-via-exit hack (std::process::exit(0)) is a real v1
  shortcut. The accept loop blocks on `listener.incoming()`; a
  shutdown flag set in another thread doesn't wake it. Clean fix:
  self-pipe trick or `set_nonblocking(true)` + periodic flag check.
  Defer to v1.2.
- A `.dl` program file edit kills the daemon for respawn (v1
  simplification). Hot reload is the v1.2 polish — the engine can
  re-parse mid-flight, but the daemon's parsed Program is held
  immutably in `Arc<Daemon>`.
- LSP integration is "push-only" not a true RPC bridge. The LSP
  keeps its own engine, opens the daemon's cache.db (WAL multi-
  reader), subscribes to diag_changed, re-publishes on push. Saves
  still trigger the LSP's own tick (redundant with daemon's watcher
  tick but correct). Phase 4 v2 removes the LSP's own ticking and
  routes every LSP message through daemon RPCs.
- The synthetic `dl/diagChanged` Notification<custom> trick lets the
  subscriber thread signal the main loop without naming the
  crossbeam_channel crate — the existing `connection.sender` carries
  the message. lsp_server re-exports Sender/Receiver but not the
  select macro; I added crossbeam-channel as a direct dep for the
  type, but the synthetic-notification trick avoids needing select.
- The v1 socket is std::os::unix::net (zero new deps, mac-first
  per plan). Named-pipe support is a mechanical cfg swap when
  needed; interprocess was considered and rejected for v1 to keep
  the dep tree lean.
- Engine `query_one_sql` skips the closure-cache optimization; the
  SQL view fallback is correct. Daemon query RPC pays the SQL cost
  for path queries on large graphs; acceptable for v1.
