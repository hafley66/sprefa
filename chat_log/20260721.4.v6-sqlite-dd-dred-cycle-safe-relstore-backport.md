## Problem/Context
- Started in v6/labkit (a big rusqlite measurement harness). Built bespoke sqlite engines
  there (reach_inc = counting DAG, reach_dred = cycle-safe, cascade = store cascade copy,
  DdReach/DdBfs oracles, gun allocator, sqlmem). User got FRUSTRATED: I reinvented the
  store's proven cascade as a worse twin, asserted dd handles cycles WITHOUT testing, was
  too verbose, and splintered off from config we already had.
- CORE PROOF (examples/cycle_probe): cut the anchor of cycle 1->2->3->1. counting=4 WRONG
  (phantom cycle), DRed=1 correct, dd=1 correct, oracle=1. So: counting is wrong on cycles;
  DRed and dd are correct. dd verified, not asserted.
- Two "its": (1) cycle CORRECTNESS = algorithm choice (counting wrong, DRed/dd right, not
  universal). (2) wavefront COST when Δoutput large = UNIVERSAL lower bound |Δoutput|; dd
  pays in RAM (resident, gun wall), sqlite on disk (bounded). Only escape = demand-driven
  laziness (salsa: don't materialize whole answer).
- Store config we'd forgotten in labkit: WAL + synchronous=NORMAL + temp_store=MEMORY, one
  txn per cascade. Applying it to labkit DRed: 2001->1275ms dense 200k, and the fake
  constant 2.8MB sqlite heap became real (grows with working set) — 2.8MB was just the
  default ~2MB page cache, NOT the data (data on disk; RSS is truer).

## Solution/Approach
- DRed = Delete-and-Rederive (Gupta-Mumick-Subrahmanian): on delete, over-delete the
  forward cone (tentatively unreach, cycles included), then rederive any cone node still
  reachable from a surviving anchor. Dead cycle has no anchor -> stays dead. Correct on any
  graph. Cost ∝ cone size (dense SCC -> O(reachable), the wavefront wall).
- Backport uses the store's (tag,id)->key = rel*STRIDE+row dense encoding (E1, already the
  chosen design per chat_log/20260721.2). cascade already takes (tag,id) so it's ALREADY
  generic over relations; RelStore is the facade + naming lift off cx_.
- Harness for the real code lives IN the store (sqlx), NOT labkit (rusqlite) — depending on
  store from labkit would link two bundled sqlite C libs and fail.

## Key Insights
- counting Z-set retraction (the OG store cascade) is correct ONLY on acyclic support
  graphs; cycles self-sustain (phantom). DRed fixes it; dd is correct by construction.
- wavefront cost is a universal lower bound |Δoutput|; no engine beats it if you materialize
  the full answer. dd pays in resident RAM (gun wall), sqlite on disk (RAM bounded).
- SQLite "2.8MB constant" = default page-cache cap, not data size. temp_store=MEMORY + TEMP
  working tables + real cache_size is the store config that makes it fast AND honest.
- The (tag,id)->dense key IS the generic mechanism; cascade was already relation-generic.
- assert bug: must seed the wavefront from seeds regardless of current alive state (an
  already-alive root still pushes into newly-added dead children).
- reconcile dirty() must be dep-based frontier (d.changed_at > s.verified_at), NOT self
  changed_at>verified_at (which drops out on verify and never reaches downstream). Lazy
  frontier + verify-moves-changed_at = early cutoff.
