## Problem/Context
Prior session locked the x5b design in the bd card + parse.md §14.5m. Thesis: cursor[] -> cursor[] is the one IO contract. Value::Pattern + Value::Pipeline should collapse into Value::Op(Arc<dyn Op>). PatternValue trait and concrete matcher structs (GlobPattern/RegexPattern/JsonPattern/AstPattern) should fold into their ops' compiled state. Consumers should call capability methods on Op (try_raw_regex / materialize_with / bound_captures) instead of downcasting.

## Key Insights
- The unification happens at the TRAIT tier, not the ENUM tier. Removing Value variants is necessary but not sufficient. The capability surface on Op is what lets consumers inspect without caring about the concrete type.
- Fusion over wrapper: GlobOp IS the compiled glob, not a holder of a GlobPattern. This only worked because GlobPattern and GlobOp had near-identical shape. Fusion keeps one type per op, one file per op, one place for compilation logic.
- The sprf_pattern_op macro is now out of step: it generates an impl Op that delegates pipe to PatternOp::pattern_pipe, but the fused ops need to drive apply_identity_pattern from their own state. Hand-rolling impl Op for GlobOp/ReOp was cleaner than extending the macro to delegate 3 capability methods. Macro still lives in sprefa_macros but has no current consumers; deletable when confirmed.
- Default GlobOp/ReOp instances (never-matching regex, empty template) exist only because PatternOp::binds_captures takes &self — the resolver probes captures before compilation. Could be made static in a future pass.
- The two-door registry (OpFactory for value-path, PatternOpFactory for sub-grammar-compile path) was preserved intentionally. Collapsing it requires OpLowering + DefaultLowering, which is Pass B. Current shape works for 10 ops; unification pays off when ops diverge in lowering needs (tag).
- Op: Debug was additive-safe. Every concrete op type either already had it or took a single #[derive(Debug)] line.

## Open Questions
- Value::Term: survives Pass A as sugar-distinct. Resolver ergonomics want the syntactic distinction. If Pass B or later surfaces a reason to fold it into Value::Op(term_op), revisit.
- ArgSpec refinement: no per-slot "must-be-bulk-collapsible" discriminant yet. Consumers check op.try_raw_regex().is_some() inline. Fine until this shape shows up in >3 places.
- Should compile_str(src) helper in ops/glob/mod.rs stay? It's used by rev/repo/fs from_source paths (tests + direct construction). Pass B's OpCtor may absorb this.
