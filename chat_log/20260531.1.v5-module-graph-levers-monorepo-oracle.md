## Problem/Context
First-cut audit (empirically confirmed) found the module graph only handled single-crate
Rust + single-tsconfig TS. Real gaps proven by running dl: multi-crate `crate::` collision
(crateA's `use crate::foo` resolved to crateB's foo), cross-crate `use other::` dropped as
External, regex matched use/mod in comments AND string literals (modgraph.rs's own test-string
literals produced a phantom modgraph.rs->lib.rs edge), #[path], nested braces, raw idents,
per-package tsconfig, workspace package.json fallback, dynamic import(), and Cargo dependency
RENAME (`renamed = { package = "real" }` — `use renamed::` produced NO edge).

## Solution/Approach
modgraph.rs rewritten to be monorepo-aware:
- strip_noise(content, rust): byte-offset-preserving scrubber. Rust blanks strings+chars
  (lifetime-safe `'` heuristic) + raw strings + nested block comments; TS blanks comments
  only but tracks strings/templates. Kills phantom edges from use/import in comments/strings.
- RustCrates registry built from Cargo.toml (parse_cargo via the `toml` crate — toml::from_str,
  NOT str::parse::<Value> which silently fails in toml 1.1): per-crate `crate::` namespace
  (fixes collision), file->owning-crate by src-root prefix, cross-crate `use othercrate::`,
  and (code_name -> real_pkg) RENAMES from [dependencies]/[dev-]/[build-].
- #[path = "x"] mod override (one-level, deduped vs convention scan via handled-names set).
- expand_use recursive brace expansion a::{b::{c,d},e}; raw idents r# stripped.
- TsResolver: TsconfigDiscovery::Auto + resolver.resolve_file(importing_file, spec) — KEY:
  resolve() ignores Auto, only resolve_file discovers per-file tsconfig. Workspace package.json
  fallback (bare specifier -> package.json name -> dir/index probe). Interpolated import(`${}`)
  -> Unresolved("dynamic") not silently dropped.
- Engine collect_manifests(rev, files): reads Cargo.toml/package.json above the file set per rev
  (rev-correct via read_content) into ProjectCx. Self-edges (src==dst) dropped at insert.
- module_unresolved gained a `line` col -> examples/lint-imports.dl turns unresolved refs into
  `error` diagnostics through the shipped diag/--check/--lsp path (broken-import linter).
Custom-fact composition (demonstrated, zero engine change): module relations are plain queryable
relations; user builds their own `dep` edge relation = union(module_edge + custom-extracted) MINUS
negated suppressions, then `reaches(a,b) <- closure(dep)`. Two amendment levels: (1) .dl rules
(union/negate/join — "these files link to those"); (2) new ModuleResolver in Rust (a whole
resolution algorithm / new language).

## Key Insights
- module_edge/module_import/module_unresolved are QUERYABLE relations, not sealed output. Custom
  facts compose via additive datalog rules (union) + negation (subtract) + close over YOUR relation,
  not module_edge. Zero engine code. This is the answer to "amend custom facts into auto db".
- oxc resolve() ignores TsconfigDiscovery::Auto; MUST use resolve_file(importing_file, spec).
- toml 1.1: str::parse::<toml::Value>() returns Err on a valid Cargo.toml; use toml::from_str.
- rustup `rust-analyzer` proxy is a STUB ("Unknown binary"); real binary at
  ~/.vscode/extensions/rust-lang.rust-analyzer-*/server/rust-analyzer. `rust-analyzer scip <path>
  --output <out>` emits a protobuf SCIP index in ~2s on a tiny crate; SymbolRole::Definition=1.
- SCIP oracle aggregation: symbol defined in doc B, referenced (role != Definition) in doc A => edge A->B.
  Our diet module_edge should be a SUBSET (precision check); recall < 1 on real code (method/type refs = SCIP's hard 10%).
- diet recall hole: intra-crate `use crate::nowhere::X` degrades to the crate root (lib.rs) via
  longest-prefix — can't distinguish typo from a symbol defined in lib.rs without symbol resolution.
  So broken-import linting is reliable for `mod` decls + TS relative imports, NOT intra-crate use typos.
- cfg-gated mods: emitting all is CORRECT for a static dep graph (want all possible edges) — a feature, not a gap.
- What exists in Rust to use: toml/toml_edit (manifest model, have toml), cargo_metadata/guppy/krates
  (authoritative resolved Cargo graph, subprocess+network, not in tree), syn (full AST, already transitive
  2.0.117), tree-sitter-rust (error-tolerant, already a direct dep + wired via run_ts), oxc_parser/oxc_ast
  (TS import AST), oxc_resolver (have), rust-analyzer scip + scip crate (have, oracle).
