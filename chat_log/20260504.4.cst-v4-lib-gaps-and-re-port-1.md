## Key Insights
- **`cc` must live in BOTH `[dependencies]` and `[build-dependencies]`.** The lib's `cst::build::grammar_walk` uses cc::Build, and v4/build.rs also needs cc independently. `include!`-sharing source between the two requires no `//!` inner doc comments in the included file (they error at non-module positions).
- **tree-sitter 0.24 QueryMatches is a `streaming_iterator::StreamingIterator`, not std::Iterator.** Calling `.next()` requires `use streaming_iterator::StreamingIterator;` and yields `Option<&Item>` (no `for` loop). Forgetting this gives the `&dyn Compiled doesn't implement Debug` red herring earlier (different bug, similar surface).
- **`Box<dyn Compiled>` doesn't impl Debug.** `.unwrap_err()` on `Result<Box<dyn Compiled>, Diag>` requires Debug on the Ok variant for the panic message. Use `match` instead of `unwrap_err()` to assert errors.
- **Capture-name resolution should fall back through dotted suffixes recursively.** `string.regexp` → look up `string.regexp` (miss) → strip `.regexp` (unknown suffix, no mod added) → look up `string` (hit, return STRING). `function.builtin` → strip `.builtin` (recognized → push DEFAULT_LIBRARY mod) → look up `function` (hit). Implementation walks `rfind('.')` in a loop.
- **v3's parser.c per-grammar comes with its own copy of `tree_sitter/{alloc,array,parser}.h` headers.** These must be copied alongside parser.c — they're transitive includes resolved via `include_str!`-style relative path. Copying parser.c alone fails with `'tree_sitter/parser.h' file not found`.
- **Surgical staging via copy/swap works for clean separation.** `cp src/lib.rs /tmp/work.rs && git show HEAD:v4/src/lib.rs > tmp/head.rs && build_surgical > src/lib.rs && git add src/lib.rs && cp /tmp/work.rs src/lib.rs`. Index gets surgical, working tree retains POC.
- **The `dyn` `PathItem` registry needs each lib-shipped item explicitly handled in `clone_item`.** Adding a new item (`Index`, `Name`, `Field`, `Body`) means updating the `clone_item` match arms in path.rs and locate.rs.
- **User pushback pattern repeats.** First "only yours" → surgical mode → "just merge it in idc" → broad mode → "lol no". Same shape as session 0's reviewer iterations (4 passes on the design plan). Means: do not assume one signal lands the boundary; explicit, scoped scope-question is safer than another reset.
