KEY ARCHITECTURAL DISTINCTIONS established this session:
- TWO-LAYER split: SOURCE layer (fact extractors: scan/match/ast/sg/json + sh +
  later llm -- new primitives allowed DELIBERATELY) vs COMPOSITION layer
  (rules/joins/closure + the use/def/lint frontend -- FROZEN, sugar only, lowers
  to existing BodyItems). The frozen-IR rule governs COMPOSITION; source layer can
  grow a primitive when there's a real effect. `sh` is a source op, not sugar.
- SIX-SLOT TAXONOMY (the wall that catches every idea so none sprawls into a new
  runtime): (1) source ops, (2) rules/queries [FROZEN], (3) coordinate types,
  (4) LSP affordances, (5) edit sinks, (6) ORACLES [SCIP/RA precision-recall gate].
  Every feature = exactly one slot. go-to-def = 2+3+4 measured by 6 (touches most
  slots -> why it's the idea-fountain).
- REACTIVE/REDUX IDENTITY: sprefa is a reactive/redux interaction language on the
  SYNC-TICK datalog core. store=facts, action=input delta, reducer=rule,
  subscriber=LSP publish, dispatch=THE TICK. LSP is the first interaction app.
  Reactivity LADDER rungs 0-3: TARGET=rung 1 (incremental dependency-reachable +
  digest-skip closures). REJECT rung 2 (differential dataflow) and rung 3 (async
  parked-wake queue/owner-subscribe) = the v3/v4 trap. Two redux's: redux-as-
  PROGRAMMING-MODEL (good, sync-tick) vs redux-as-ASYNC-RUNTIME (the trap). Chris
  wants to WORK IN the model, doesn't need the async scheduler.
- PAUSABLE/ASYNC STATE = a persisted state ROW (interaction(id,status,...))
  advanced by rules each tick, NOT coroutines/continuations. INVARIANT (from perf
  agent): "no rule may schedule a tick" -- every wake is an external action. The
  moment a rule self-schedules a wake, you've rebuilt v4's parked queue.

DELIVERED (commit 4b5056b): built exactly that.
- ClosureCache gains `digest:[u8;32]`. Engine gains `closure_cache:
  HashMap<String,ClosureCache>` (cross-tick) + `pub recondensed: usize` counter.
- build_cond_cache -> refresh_cond_cache(&mut self, edges, dirty:&HashSet<&str>):
  edge NOT in dirty + cached -> reuse (zero work, no scan); dirty but
  edge_content_digest unchanged -> reuse (skip Tarjan); dirty + digest moved ->
  recondense (Tarjan, bump recondensed). edge_content_digest = XOR-fold blake3 of
  (c0,c1) rows (order-independent, set table).
- run_query drops the `cache` param, reads self.closure_cache.
- tick: dirty = all edges if rebuilt_all else none. tick_paths: dirty = aff_edges
  (need_full -> all). Source-rel digest prune already at tick_paths:783 catches
  comment/same-line edits BEFORE the edge is marked dirty.
- Bench tests/closure_incremental_bench.rs: synthetic call-chain corpus (fn fK{
  fK+1() }), cold tick then replay edits, assert on recondensed counter.

PROVE-OR-KILL RESULT (clean timing, query removed from bench prog):
  N= 30  cold  74ms (1 recond) | same-line edit 15.2ms (0 recond) | topology edit 15.0ms (1 recond)
  N=300  cold 465ms (1 recond) | same-line edit 19.4ms (0 recond) | topology edit 23.5ms (1 recond)
- PROVE: edits not moving call edges recondense 0 graphs at N=30 AND N=300 (corpus-
  independent on the counter); real topology change recondenses exactly 1. The
  per-keystroke closure tax is KILLED. rung-1 is REAL for the LSP/per-keystroke
  regime -- no DD, no parked queue needed for live editing on one repo.
- HONEST CAVEATS: (a) same-line edit wall grew 15->19ms for 10x corpus (~4ms O(N)
  residual) = the NEXT bottleneck = reconcile_sources re-enumerates ALL files
  every tick (the "full re-resolve every tick" residual). THAT is the 500-repo
  batch lever, not closures. (b) line-COUNT-changing edits shift line-based fndef
  spans -> rows change -> recondense fires even w/o topology change (span
  fragility, exactly as the historical agent predicted; single-char/same-line is
  free, add/remove-line pays one recondense).

## Key Insights
- rung-1 closure caching = corpus-independent on the COUNTER (0 recond for non-
  topology edits at 10x corpus). The fix: cross-tick memo gated by affected-set
  THEN content-digest. Source-rel digest prune (tick_paths:783) is what makes
  comment/same-line edits never mark the edge dirty.
- The 500-repo BATCH regime is a DIFFERENT problem than the LSP regime: batch lives
  in `tick` (no incremental path); the lever is reconcile re-enumeration +
  rev_index O(S*K), NOT closures. Don't conflate the two regimes.
- The frozen-IR wall already failed once (v4 had the identical guardrail). The
  thing that makes THIS time different is empirical discipline: prove rung-1 with a
  bench before building substrate -- which we just did, and it held.
- Phase C (LSP) is the rewrite-#6 vector. The instant the tick goes async/worker-
  thread, "edits mid-tick" forces the durable parked-wake queue back. Keep tick
  inline + "no rule schedules a tick".
- go-to-def with shadowing needs recursion-INTERSECT-negation, which stratification
  bans (engine.rs:327). The headline resolution feature is NOT free under "zero new
  eval semantics" -- it's either capped at single-pass or it's a named IR extension.
- Honest perf framing: rule-based resolution is "good-enough, MEASURED" (RA oracle
  0.86/0.83), blended with SCIP where a compiler index exists. Not parity.
