# sprefa Evolution Log — v1 → v2 → v3 → v4

## Context

User wants a comparative log across four versions to analyze how the project evolved at each jump. Earlier in this session a coverage matrix was produced; below is the deeper companion narrative. Four parallel Explore agents read each version's historical artifacts (NOTES, BOARD, README.goals, TASKS, docs/, diagrams/, examples/, chat_log/, llm-notes, smoke tests, commits, beads). Each answered the same eight questions so transitions are comparable.

This document has two halves:

1. **Per-version narratives** — what each version was, shipped, dropped, added, attempted, and why it gave way.
2. **Jump table** — v0→v1, v1→v2, v2→v3, v3→v4 deltas keyed by concept.

## v1 — Cross-codebase semantic-grep + rename engine

Archive: `~/projects/sprefa-archive-20260428/` (root, not the `v2/` subdir).

### Mission framing
A SQLite-backed correlation engine for "every interesting string in a codebase as a ref." From `readme-old.md`: "Rename a symbol, every reference updates. It's 2026. Across files, across repos, across languages. No LLM, no datacenter — a pre-built index and a graph traversal after ripping regex on filesystems and ASTs." `NOTES.md` (2026-04-14) deepens it: "User programs a customizable rule-set of import/export relationships across repos. Runtime sics the whole crate tree on the fleet and records sigil'd pointers across repo boundaries. The store is the thing." The mental model was Datalog-for-code, not a rename tool. Pre-v1 inheritance was external prior art (ripgrep, fzf, ast-grep) and the conceptual unification "filesystem + AST + structured data are all trees."

### Shipped state at archival
- 15 production crates (`cache`, `cli`, `config`, `extract`, `index`, `js`, `rs`, `rules`, `scan`, `schema`, `server`, `sprf`, `sprf-lsp`, `tests`, `watch`).
- 295+ snapshot tests passing.
- Scanning: oxc (JS/TS), syn (Rust), JSON/YAML/TOML rule engine with destructured tree match.
- Watcher: filesystem event debounce, content-hash file-move detection, declaration-rename diff via 64-byte span proximity, import-path rewrite (Rust `crate::`/`self::`/`super::` aware).
- SQLite schema: `repos`, `files`, `strings` (FTS5 trigram), `refs` with byte spans, `matches`, `match_links` with eight link predicates (norm_eq, norm2_eq, target_file_eq, same_repo, stem_eq, ext_eq, dir_eq, and).
- `.sprf` DSL with CSS-style selector chains, JSON destructuring, `link()` declarations, cross-rule references with DAG topo ordering.
- `sprefa-lsp` with arm-braced fork grammar, absolute-offset evidence, partial-match semantics, op-owned diagnostics.

### Mid-flight pivots within v1
- **Link-rules DSL** (2026-03-30/31): JSON predicate format → `.sprf` text syntax with function notation. Made rules hand-copyable.
- **Scan-pointer tri-state** (2026-04-14): `verified: Tri` (Claimed / Verified / Missing) — provenance stamped *forward-pass* during streaming, not as a second pass.
- **Op-trait family reshape** (2026-04-14, "LOOSE"): Began moving toward ops owning their own annotations and grammar slots; never landed in v1.
- **Reactive execution model** (2026-04-12, dump): Sketched RxJS-style mergeMap/ReplaySubject topology in CoffeeScript pseudocode. Influenced v2 but not landed in v1.

### Net-new in v1
- Tri-state provenance stamping (forward-pass).
- Span-preserving JSON destructuring with ancestor-capture carry-forward.
- File-metadata link predicates (`stem_eq`, `ext_eq`, `dir_eq`).
- Declarative tree-walk rule engine (`key`, `key_match`, `any`, `parent_key`, `array_item`, `leaf`, `object`).

### Attempted but unlanded
- `sh()` / `sh_mut()` / `sh_batch()` shell-integration tags with allow-lists — fully spec'd in NOTES, never built.
- Codegen validation (enum exhaustiveness, marker-bounded write-back).
- `let` bindings + bash `$1`/`$2` positional args.
- BOARD red column: cross-file rule references, watermarking via rowid high-water, LSP via tree-sitter, pluggable tree sources, CSS DOM mapping, static type-graph layer.

### v1 → v2 trigger
Not a defect. The 2026-04-14 NOTES tail records: "After the arm-syntax + absolute-offset + evidence-site-filter + partial-match pass, the LSP surface finally reflects real semantics. Foundations feel sound. Other ops can now parallelize because the op surface has been stress-tested." The user chose to bet on a redesigned runtime: one `Op` trait with `pipe(input$, ctx) -> output$`, deferred batched writes, ops as first-class registries, raw SQL inside ops instead of a query compiler.

## v2 — Stream-based, effect-routed, provenance-first engine

Archive: `~/projects/sprefa-archive-20260428/v2/`.

### Mission framing
From `README.goals.md` §1: "sprefa is not a query tool bolted on a rewriter — it is a cursor pipeline that happens to write SQL rows, issue shell effects, and rewrite code." §23 nailed the invariants: "No sync fs/git calls anywhere except the initial repo/rev seed read. SQL stays behind the storage trait. Forever. Ops never write direct — they emit cursors; sinks buffer and call `write_*` in bulk. No cursor-batch streams; scalar streams with sink-side buffering." v2's complaint about v1 was architectural: mixed concerns, batch-sync file reads, monolithic ~1500 LoC `_3_lower.rs`, tightly coupled extractor logic.

### Shipped state at archival
- Type spine: `Cursor`, `SprfPath`, `ParseSite`, `Capture`, `RunEvent`, `Diagnostic` trait, all IDs.
- Trait boundaries (`_2_reader.rs`, `_3_writer.rs`, `_5_op.rs`): `Reader`, `Writer`, `Operator`, `Op`, `Pipeline` enum.
- Parser (`_8_parse.rs`, 42.7 KB): host parse with balance-aware scanner, `$NAME`/`$$sigil`/`${rule.$VAR}` classification, `&.` desugar to `cursor_ref`.
- Registry with lispy aliases (fs, fs?, !fs, fs.absent), two-pass lower (pre_register → parse).
- DAG + cross-refs: Kahn topo sort, cycle detection, `expand_xrefs` adapter.
- Seven ops landed: `rule`, `repo`, `rev`, `fs`, `read`, `json`, `cursor_ref`.
- Reader/Writer decorator infra, `LoggingReader`/`LoggingWriter`, `effect_log` first class.
- `NoopStore` + stub `MutationHandler`, `AutoApprove`.
- Cargo.toml: 66 deps including tokio, sqlx, tower-lsp, ast-grep-core, tree-sitter, axum, rayon.

### Mid-flight pivots within v2
- **Phase boundary** (CLAUDE.md): Phase 1 = reactive scan parity with biome/oxc (landed). Phase 2 = mutator/write-effects/approval (next).
- **Capture DSL unification** (`docs/_0_term-language.md`): debate over `$NAME` vs `${NAME}`, `$$repo` vs scan-pointer-as-op, recursive pipeline inside `${...}`. Five open questions, deferred as exploratory.
- **Term rename**: "capture" → "term"; lowercase = op, UPPERCASE = term. Casing-as-syntax collapsed five prior distinctions.

### Inherited from v1
- Backbone schema: `repos`, `revs`, `files`, `rev_files`, `strings` (FTS5 trigram), `refs`.
- Per-rule table shape (`{ns}__{rule}_data`) with id PK, capture FK pairs, views.
- `sprf_norm()` UDF, normalize layer.
- Scan targets, demand-scanning loop.
- JS/TS/Rust extractors via the `Extractor` trait.

### Dropped from v1
- Guessing analyzer (`crates/sprf/src/analyze.rs`) → replaced by per-op `Diagnostic` impls with exact byte ranges.
- Monolithic lowerer (`_3_lower.rs`, 1498 LoC) → per-op `Operator::parse` factories.
- LSP `find_pattern_at_position()` → per-op `hover_at()` delegation.
- Pluggable multi-target sinks (JSON/NDJSON/summary) — committed to SQL only.
- Query-dialect compiler (`SCOPE_*.ts` sketches) — moved to raw SQL in ops.
- Reactive RxJS streams as runtime — moved to effect-routed deferred writes.
- Module namespace via ATTACH DATABASE → per-rule tables.

### Net-new in v2
- `BoxStream<'static, Cursor>` scalar-stream model (one tuple flowing, batching at sinks).
- `SprfPath` / `ParseSite` two-coordinate system: parse_site for click-to-definition, runtime path_hash for awk routing.
- Implicit pattern branching (one cursor → N leaves, OR semantics, opt-in `$join_by` AND merge).
- `Reader`/`Writer` trait split returning `BoxStream`.
- `effect_log` decorator middleware, audit-trail first class.
- Cycle prevention via `run_visits` table keyed on `(run_id, op_id, path_hash, cursor_hash)`.
- Config-as-hot-signal: content_hash bump → diff → restart only affected pipelines.
- `Diagnostic` as trait object, op-owned.
- `RunEvent` enum as sole public output.
- `TaskGuard<T>` drop-aborts for reparse cancellation.
- Mutations approval flow: `AutoApprove` / `InteractiveCli` / `LspPromptBridge`.
- Three-bin trinity (daemon + cli + lsp stdio↔WS proxy).

### Attempted but unlanded
- `SqliteStore` body (Layer 5 in TASKS).
- `InitCursors` expansion via `ResultStore` cross-ref seeding.
- `$join_by` op runtime.
- `Pipeline::Switch` (marked `unimplemented!()` at `_5_op.rs:201`).
- Recursive pipeline inside `${...}` ("the frame" idea, five load-bearing open questions).
- Absence/negation flags (`$fs[absent]`, `$json[absent]`, `$ast[absent]`).
- `$check` SQL rewrite, `$include` glob resolution.
- Shell + rewrite safety (allow-lists, code-lens approvals).
- Backpressure + watermarks (`buffer(N).drop_oldest_on_overflow()`, `RunEvent::Backpressure`).
- LSP token dogfood bootstrap (`$marker` + `$render` generating tokens).

### v2 → v3 trigger
v2's full trait stack + effect-runtime integration was a multi-phase undertaking. v3 chose to parallelize: ship narrower-but-complete ops against a simpler architecture, learn what rules the engine would actually run before committing to v2's full machinery. v3 README confirms: "v3 is the active line; the v2 crate in the sibling `v2/` directory still runs but new work lands here." Use-case-first replaced bottom-up.

## v3 — Use-case-driven runtime with effect_runtime substrate

Live: `/Users/chrishafley/projects/sprefa/v3/`.

### Mission framing
v3 unified what v2 had split. From `llm-notes.md` 1–45: nesting was overloaded in v2 (scalar vs stream vs reactive modes claimed to be three pathways), when in reality all three are emission profiles of the inner `pipe`. v3 collapsed them under a single `flat_map_unordered` operator. v2 had also conflated caching with call-site flags; v3 made caching intrinsic to op purity. The parser was rebooted around tree-sitter host grammars with injected sub-grammars, replacing v2's monolithic surface.

### Shipped state today
- 17 green smoke tests `_1_run.sh` through `_j_write_cursor_replace.sh`:
  - core: fs/repo/rev binding + filtering, rule brace-bodies, comment/print, fs glob nested-arg, rev atom filtering
  - patterns: json brace bodies, ast-grep, json/toml interop
  - relations: tag MVP (INSERT) + tag predicates (SELECT-with-join), rule arity polymorphism, rule self-recursion
  - control: fork, LSP hover/diagnostics on AST nodes, rev working-tree mode, AST/YAML parity, write_cursor splice
- LSP (`sprefa-lsp`) + CLI (`sprefa-run`) + VS Code extension shipped.
- 8 crates: `effect_runtime`, `pipeline`, `server`, `spine`, `sprefa`, `sprefa_macros`, `sprefa_parse`, `tree-sitter-sprefa`.
- 25 ops in pipeline crate.
- FactStore unified (commit 2bda022).
- Legacy trait Op ripped (commit 3d78f7a).
- FactRead anti-join (commit 2dbf7d6).

### Mid-flight pivots within v3
- **Term-receive collapse** (parse.md §18, §6): `[]` receiver syntax unified argument dispatch. Two-arg form retired; receiver always LHS, arg always RHS.
- **Scan-pointer-as-op** (parse.md §12, llm-notes 872–920): `$$` sigil + `ScanPointerRef` class retired. Scan pointers became ordinary ops reading `cursor.last_bound`.
- **FactStore unification** (commit 2bda022): MutationStore merged into `FactStore<R: Row>` — single state surface.
- **Trait Op rip** (commit 3d78f7a): Legacy single-trait dispatch deleted; v2 (effect_runtime) is the only path.
- **simple_ops.rs deletion** (commit 6ce9b20): Granular per-op tests collapsed into substrate_ops.

### Inherited from v2
- Cursor stream + op-pipe-flat-map (now unified).
- ParseSite + SprfPath two-coordinate system at the tree-sitter level.
- Effect routing + per-op batching.
- Registry-dispatch pattern.
- React-mental model imported wholesale (component=op, props=cursor terms, fiber.key=lineage_hash, render=pipeline drain, commit=fact writes).

### Dropped from v2
- ParseSite walk-index triad (BraceChild | ParenChild | PatternLeaf) — tree-sitter's named-child indices replaced it (parse.md 447–450: "the previous v2 triad is retired. Tree-sitter owns the walk").
- v2 `CursorRef` class family — absorbed into `&.field` receiver rebase syntax.
- Reader/Writer trait split — collapsed under one effect description model.

### Net-new in v3
- `effect_runtime` as a dedicated parse-agnostic crate.
- Host tree-sitter grammar with injected sub-grammars (glob, regex, ast, json) via `#match?` + `injections.scm`.
- Fact / relation-tag tier (`tag(:r, $X, $Y)` → SQL-shape observable relations).
- `sprefa_macros` proc-macro derive crate for op-pattern derivation.
- Differential-dataflow proofs prototyped — parked with conclusion "DD's only remaining win is incrementally updating an in-memory aggregate; for sprf's debounced-commit / indexed-query / settled-state workload, recompute on commit beats incremental."

### Attempted but unlanded
- Draft write-architecture smoke tests `_l_write_aggregate.sh` through `_r_multi_file_multi_match.sh` — designed but not running.
- Differential-dataflow gating — parked.
- OpCache decorator + liveness pass — deferred.
- Closure analysis for hoisting pure subtrees to SQL.

### v3 → v4 trigger
Around 2026-05-04 (`chat_log/20260504.9`), v3's `server` crate hit a wall: 5425 LoC total, `backend.rs` alone 2166 LoC mixing LSP dispatch + state mutation + diagnostic publishing. `run.rs` 995 LoC. `session.rs` 754 LoC right shape, wrong crate. Ops scattered alongside types/effects/registry, multiplying rebuild costs. The reactive-render mental model collided with the queue-based state-machine design needed for backend pluggability (Mem, Sqlite, future Postgres). Architectural decay forced a workspace partition. v4 is the recovery of v2's structural clarity while keeping v3's substrate gains.

## v4 — Eleven-crate partition, generic Provider/Transport, two-libs floor

Live: `/Users/chrishafley/projects/sprefa/v4/`. Branch `wip/kitchen-sink-react-hook-fix`.

### Mission framing
v4 diagnosis (`llm-notes.md` 877–887): architectural decay, not algorithmic failure. v2 had the right shape (thin CLI + daemon + stdin/stdout proxy); v3 merged the daemon into a monolithic server. v4 recovers v2's clarity, keeps v3's substrate.

### Shipped state today
- **cst lib** (v4/src/cst): four DSLs (re, glob, json, ast), 80 tests dogfood-green, ~250-line README.
- **effect_runtime unification**: MutationStore deleted (commit 2bda022). `FactStore<R: Row>` is the single state backbone. Each insert mints content-derived `_id = blake3(canonical_fields)`. Uniform `Event::Dirty { domain, key }`. `FactRead::anti(...)` for negation (commit 2dbf7d6).
- **Legacy trait Op retirement** (commit 3d78f7a): 22 old impls + `drive_with` + ChannelHub + OpCache deleted; lib.rs 2697 → 963 LoC.
- **app_host candidate crate** (parallel work): generic `App<S, D>` over Store + Dispatch (assoc-typed Action/Reply/Error). `tower::Service` adapter. `InProcess<S,D>` and `DaemonProxy<D>` Transport choices. Daemon wire: 4-byte LE length prefix + bincode + `WireResponse<R>`. `serve_unix` Unix-socket per-connection spawner. 6/6 tests green. task_local CTX.
- **v4-bench** (Linux): 63k file corpus, baseline 4.161s, reconcile 3.980s, warm-share 0.273s. Path-collision and tail-sync-cap fixes landed.

### Mid-flight pivots within v4
- **11-crate partition locked** (`llm-notes.md` 783–960):
  - libs: `cst`, `effect_runtime`
  - core: `sprefa_parse`, `sprefa_types`, `sprefa_ops`, `sprefa_compile`, `sprefa_main`
  - shells: `sprefa-cli`, `sprefa-lsp`, `sprefa-http`
  - bench: `v4-bench`
  - load-bearing rule: shells import only `sprefa_main`.
- **Three-door → two-door registry**: `OpFactory::Values | OpFactory::Pattern{dsl, build}`. Cross-rule references live in the fact store, not as a third door.
- **Slots dropped → cursor.content[byte_range] only**: PATH A/B/C unified.
- **"tag" → "fact"** (memory `feedback_no_tag_use_fact.md`).
- **"substrate" / "regime" banned** (memory `feedback_terminology_substrate.md`, `feedback_word_regime.md`).
- **MutationStore deletion** (2bda022).
- **Cancellation reframed** as `unmount(instance_id)` deletes-by-tag.
- **One smoke test** instead of granular per-op test sprawl (memory `feedback_one_smoke_test.md`).

### Inherited from v3
- `effect_runtime` crate (Component, Pipe, expand driver, batch_cap + tail-sync + rayon par_render, Memoize + PriorChildIndex reconcile).
- Host tree-sitter grammar (artifacts now folded into `sprefa_parse` build.rs).
- React mental model.

### Dropped from v3
- trait Op + drive_with.
- MutationStore.
- Three-door registry.
- "tag" terminology.
- `simple_ops.rs`.
- Slots semantic typing.
- Separate libs/grammar crate.

### Net-new in v4
- `cst` as pure lib (extracted from nowhere, four DSLs, no sprf knowledge).
- `App<S, D>` generic over Store + Dispatch with `tower::Service` adapter.
- Daemon transport wire format (length prefix + bincode + WireResponse).
- `task_local CTX` carrying `Arc<SprefaContext>`.
- Component/expand rxjs shape (BehaviorSubject-per-Component locality, not global redux store; render-on-subscribe, Arc<Component> sharing).
- Laplace mental model: `lower = ℒ{·}`, `runtime = ℒ⁻¹{·}`. CaptureSlot=pole, op=H(s), Chain=∏H, Fork=ΣH, AcceptsMode=stability check. One equation: `c(t) = ℒ⁻¹{ ⊗_𝓡 ⨁_rules R(s) }`.
- Two-libs decohesion floor (cst + effect_runtime are the only generic libs; everything else sprf-specific).
- `gen_id` row column → free redux DevTools time-travel.

### In-flight / partial
- `lower/op_def.rs` four-slot OperatorDef refactor: build broken; `str.rs` / `rule.rs` / `fact_read.rs` still call old surface.
- ~22 ops to port from v3 to `sprefa_ops`.
- `sprefa_main` extraction from v4/src/lib.rs not started (lib.rs at 2683 LoC).
- Three Dispatch enums (CliDispatch/LspDispatch/HttpDispatch) only sketched.
- `SqliteFactStore` impl pending; only `MemFactStore` shape in tests.
- Streaming Reply (BoxStream) framing open.

### What's next (chat_log 20260505.2 task list)
1. Store impls in `effect_runtime` (~500 LoC).
2. SprefaHandler routing run/query/lsp_request, scoping CTX (~400 LoC).
3. Three Dispatch enums + adapters (~650 LoC).

5. Bench stays green; two deferred perf TODOs (FsComponent walk thread ~200ms, Cursor content_hash cache).
