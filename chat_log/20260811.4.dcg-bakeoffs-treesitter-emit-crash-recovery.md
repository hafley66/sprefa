## Key Insights
- **DCG notation was the whole win**: the file hand-threaded S0..S20 through
  every clause, exactly what `-->` generates via term_expansion. Fable's first
  commit did nothing else and cut 14k chars. Also why "DCG no smaller than
  classic" (46698 vs 46563) measured the wrong thing.
- **Compressing the parser makes it LESS emittable**: same generator, 108
  clauses/34 translatable at 29534 vs 103/32 at 26473; ratio 2.74 -> 2.96.
- **Round 1's emit FAIL was an artifact** (user caught it: "sounds like lab is
  not finished"). Round 2 proved all three skipped techniques work: registry
  precedence -508 chars, four-row char classes -169, separator specialization
  -37, 14 specializations, ratio 2.96 -> 1.68, and the emitted grammar builds
  (`tree-sitter generate` rc=0). Classification went 0 -> 8 EMITTED-IDENTICAL.
- **The final NO is an editor-vs-compiler boundary, not a parser defect**:
  what stays hand-written is CST node boundaries, field names, comment
  retention (the parser DISCARDS comments; an editor must keep them), escape-
  preserving tokens, and error recovery. A compiler's parser never carried any
  of it. 2767 chars.
- **A refused registry row can hide a fully-built feature**: json_object/2 said
  `refused` while analyze.pl:1678 and level_eval.pl:36/230/294-298 (including
  the dup-key throw) were already implemented. Two lines of work, not an arc.
- `json('json_object_dup_key')` is an ERROR-RAISING expression, not a sentinel:
  the text is not valid JSON so SQLite fails the statement. Verified against
  sqlite3 directly; comment added before merging.
- flash4-0731 went 3-for-3 with clean trees and green parity given a tightened
  brief. Its earlier zero-commit death was an openrouter monthly key cap
