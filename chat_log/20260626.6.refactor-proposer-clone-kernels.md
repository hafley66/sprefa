## Solution/Approach
- **Unifying frame**: every kernel = a feature-sequence per region + a matcher
  on that sequence. Verbatim = (raw-line, exact-equality); the only thing that
  differs between kernels is the feature extractor (and, for the stats variant,
  the similarity function). `matching_runs<T>: Eq+Hash` is the kernel-agnostic
  matcher; swap the extractor.
- **Signature inference** (the proposer's other half): scope-aware tree-sitter
  walk for free vars. Validated against a 2-fn oracle (bind_whole_match_span,
  bind_match_op) whose real params are known -> exact-set match. Ported python
  -> Rust (propose.rs) with the oracle reproduced as a Rust test.
- **AST-shape**: normalize CST leaf stream (ident->ID, lit->LIT, keep punct/
  keywords), drop comments by source-text check, run matching_runs. Catches
  renamed-var dup verbatim misses.
- **Symbol-shape**: CST leaf ⨝ SCIP occurrence. Surfaced occ_spans from
  scip_import (the data existed, was coarsened to file-level scip_ref). Each
  ident normalizes to its resolved SCIP moniker (opaque `local N` -> ID).
- **Commit hygiene**: when engine.rs held two concerns (parse_file refactors +
  proposer wiring), split via snapshot + reverse-the-additive-wiring-edits,
  committing each concern separately. Wired propose_extract through the full
  builtin checklist (const/decls/rels_used/guard/declare_builtins/refresh/both ticks).

## Key Insights
- **Unifying frame**: proposer = (feature extractor, similarity function). The
  verbatim detector is (raw-line, exact-equality); AST-shape swaps the extractor;
  the stats variant swaps the matcher for a score. matching_runs<T> is reusable.
- **symbol-shape (1067) < ast-shape (1294)**: the CST⨝symbol join is a strict
  refinement (regions referencing different entities no longer match) -> the
  join works, not just noise.
- **RA locals are opaque**: SCIP emits `local N` for params/lets, so per-var
  types fold to `ID`. symbol-shape resolves only types/fns/methods/globals. Full
  per-expression type-shape needs type inference SCIP doesn't expose.
- **Interfacing prize needs type normalization**: currently different types =
  non-match. To surface trait opportunities (two DIFFERENT types operated on
  identically), match `Vec<X>`/`Vec<Y>` as the same shape. That's the next extractor.
- **Gain over-ranks short high-frequency shapes**: RelDecl declaration boilerplate
  dominates the top (2 lines x 29 occ). Length-weighted ranker or min-token
  threshold would rebalance toward substantial consolidation candidates.
- **Reward signal validated only for EXACT consolidations** (97% vs LOC's 50%).
  Whether extracting a 0.87-similar near-dupe is reward-positive is UNMEASURED.
  Going fuzzy widens the proposal set into unvetted territory.
- **"Materialized dump" is the wrong shape**: a proposer that stores every
  proposal unranked is a lister, not a recommender. Ranking (a-priori reward)
  is the missing piece for "recommend the NEXT move."
- **Don't reimplement the engine in python**: the algorithm prototypes fast in
  python, but the deliverable must be a sprefa builtin reusing ts_lang. The
  python bought quick validation (oracle), then ported.
- **Splitting engine.rs**: when one file holds two concerns and the recent edits
  are purely additive, snapshot -> reverse the additive edits -> commit ->
  restore -> commit. Clean per-thing history without interactive add.
- **SCIP occurrence spans were coarsened away**: scip_import parsed full
  (sl,sc,el,ec) per occ but only emitted file-level scip_ref. Surfacing occ_spans
  is the unblock for any CST⨝semantic join (type-shape, and more).
- **index.scip regenerates in ~8s** via `just oracle-index` (= `rust-analyzer
  scip . --output ../index.scip`); gitignored. Required for the symbol kernel.
