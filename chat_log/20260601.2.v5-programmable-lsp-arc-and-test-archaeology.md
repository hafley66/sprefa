## Problem/Context
The recurring doubt: sprefa has been rebuilt 5x. v1/v2 (archive) shipped the
actual product (watch -> detect move/rename -> cascade-rewrite imports, JS/TS +
Rust, write to disk). v3 (68k LOC) and v4 (58k LOC) each chased a more
sophisticated reactive/relational RUNTIME (effect_runtime/Haxl; then
differential-dataflow-ish FactStore/runtime_graph/durable-queue) and NEVER
re-shipped the refactor product. v5 (6k LOC) fled to datalog "out of desperation"
to escape language design; SQLite-welded, datalog -> SQL fixpoint. v5 correctly
killed the bloated runtime but ALSO cut the three things that made the product
usable. Chris's exact words: "lsp is fucked and authoring things and their
predictable performance is also fucked."

CORRECTION Chris made to my framing: v3/v4 ops were the INTENDED programming
surface (compose ops like React.js from the Rust side), NOT accidental bloat. So
"freeze the engine" was wrong. And auto-refactor is nice-to-have/must-be-
achievable, NOT the headline. The REAL product is a PROGRAMMABLE LSP: author a
rule like "no unwrap in code reachable from app/main.tsx inside an effect",
surface as a live warning AND block commit via husky-type hook.

## Solution/Approach
THE COMMITMENT (the spine of everything): datalog is the FROZEN IR
(ast::Program{items: Vec<Item>}, Item=Rel|Rule|Query, BodyItem closed enum).
Ops RETURN as a COMPILE-TIME authoring frontend that LOWERS to it. Nothing
replaces the SQL fixpoint. Non-negotiable: an op/template adds ZERO new
evaluation semantics; if it can't lower to existing BodyItems it doesn't go in.
That single rule is the wall against the language-design rabbit hole that caused
the v5 flight. This resolves "reassess datalog": datalog was right AS EVALUATION;
the mistake was deleting the authoring surface WITH the runtime.

Key finding that de-risks the whole arc: the canonical product is ALREADY
EXPRESSIBLE in v5 today (closure + sg/ast + diag + --lsp + --check all exist).
Capability is NOT the gap. The gap is purely 3 quality axes, each tracing to
something v5 over-cut:
- Authoring: datalog = flat global rel namespace, copy-paste, no reuse/library.
  (v3/v4 ops were the composition surface.)
- LSP: lsp.rs is 164 LOC, didSave-only (TextDocumentSyncKind::NONE), diag-squiggle
  only, no hover/code-action/completion, tick runs inline on the message loop.
  (v3 had hover/semantic-tokens/completions/binding-graph warnings.)
- Perf: closures (reaches) rebuild WHOLE-RELATION every affected tick
  (engine.rs rebuild_closures + scc.rs full Tarjan; SQLite recursive CTE not
  delta-maintained). Per-keystroke cost scales with corpus, not edit.
  (v4's differential runtime_graph WAS incremental closure maintenance.)

THE PLAN (pinned at v5/plans/2026-06-01-programmable-lsp-ops-frontend-arc.md):
- Phase 0: lowering-contract.md (1 doc, no code) -- the guardrail.
- Phase A (KEYSTONE): ops authoring frontend + lint std-lib. New src/frontend.rs:
  SurfaceItem{Core(Item)|Use(Import)|Def(RuleTemplate)|Lint(LintDecl)};
  parse_surface(toks)->Vec<SurfaceItem>; expand(items,&mut ModuleLoader)->Program
  (resolve `use` imports w/ diamond-dedup, inline `def` templates w/ alpha-rename
  to __<tpl><n>_<var>, desugar `lint` via fixed macro table). Three surface
  constructs ONLY: use, def, lint. std lib: std/callgraph.dl, std/reachable.dl,
  std/lints.dl. Ships the product on CLI via existing --check (no perf/LSP needed
  for CLI gate). Wiring: run_file/run_check/run_lsp swap parse::parse for
  expand(parse_surface(..)). Backward compatible (core .dl parses identically).
- Phase B (pure engine, zero lang risk): incremental closures. Cache the SCC
  condensation on Engine across ticks (ClosureCache{by_edge: HashMap<edge,
  CachedCondensation{edge_digest,cond,names}}>); skip rebuild_closures when the
  edge-relation digest is unchanged (RIDES existing
  plans/2026-05-30-relation-digest-skip-plan.md). Honest, NOT full incremental
  SCC: most keystrokes don't change call-graph EDGES -> skip entirely (O(0)); pay
  one bounded condense only when topology moves. Cost becomes bimodal/predictable.
- Phase C (rides A+B): real LSP on the op surface. DocStore (incremental
  didChange sync), TickScheduler (debounce+coalesce, decouple tick from msg loop),
  Engine::locate_at(path,byte) for hover (query _where_bytes ref-spine JOIN
  relations), diag_to_code_action (ties to refactor.rs splice). Declare
  change:INCREMENTAL, hoverProvider, codeActionProvider.
- Auto-refactor: PARALLEL off-critical-path track. Port archive
  crates/watch/src/change.rs (delete+create-by-content_hash -> Move; ref-diff ->
  Rename) + js_path.rs (TS path math; Rust side exists in rspath.rs) + wire
  detection into the --move splice path so --watch rewrites automatically.
- Order 0->A->B->C. Not-a-6th-rewrite property: B/C/refactor are ADDITIVE to v5's
  6k core; A is a frontend that lowers INTO it. SQL fixpoint stays.
- SINGLE GATE DEMO for the whole arc: open a real repo, author unwrap-reachable-
  from-main-inside-effect in ~5 composable lines, squiggle live as you type
  (sub-100ms), husky blocks the commit. Anything not advancing this demo is the
  substrate bias re-asserting; cut it.

## Key Insights
- The bias, NAMED: every generation generalized the WRITE side one level higher
  (effect runtime -> datalog -> SQL fixpoint; WriteFileEffect -> write_cursor ->
  splice_file) and NEVER ported the two concrete product pieces v1/v2 shipped:
  (1) move/rename DETECTION, (2) per-language path RECOMPUTATION. v3 AND v4 both
  built a UNIVERSAL "splice any bytes into any byte-range with approval+drift"
  primitive and never instantiated the specific import-rewrite. The elegant
  mechanism, never the dumb working instance. v5 over-corrected: cut the bloated
  runtime AND the authoring surface + LSP + incremental-closure.
- Authoring vs evaluation are SEPARABLE axes that got conflated. Keep v5 datalog
  EVALUATION; put ops back as an authoring FRONTEND that lowers to it. "Move the
  graph up" but as a LOWERING TARGET, not a runtime.
- Perf fix is honest+small: skip closure rebuild on unchanged edge digest. Don't
  attempt full incremental SCC (research-grade). Bimodal cost is the win.
- The product is already EXPRESSIBLE; only quality (author/LSP/perf) is missing.
- Commit-kind convention Chris wants (this session onward): conventional type in
  subject + a `Kind:` line in body. Perf sub-classified: algo perf / db perf /
  syscall perf / mem perf / parse perf. Non-perf: correctness / feat / docs /
  refactor / test.
