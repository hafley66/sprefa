## Problem/Context
User correctly identified that the kernel work was a spiral into the wrong goal.
The kernels catch duplicate code blocks — the least interesting question in code
analysis. The interesting questions are about TYPE participation, coupling,
coincidence, and structural soundness. These are answerable with sprefa's
existing relations (type_entity, type_edge, scip_ref, call_edge, etc.) but
nobody has written the dl recipes yet.

The broader vision is a "multitool soup" — every analysis technique as a Rust
module or dl recipe, composing through the relation layer. Not a focused product.
A personal power tool that "soupifies all the magic spells" the user has learned.

## Key Insights
- **The kernel spiral was the wrong goal.** 3 sessions deep on CST-level dup
  detection when the interesting analysis is at the type/module/graph level.
  The kernels work (6/7 validated hits) but they're one ingredient, not the soup.
- **Precision signal discovered**: proposals backed by ≥1 structural kernel
  (tree/cfg/cgraph/ddg) are real. Proposals backed only by recall kernels
  (ast/ngram/symbol/verbatim) are test noise. The structural kernels see through
  test wrappers to the different bodies inside.
- **SCIP is a precision filter**: symbol kernel shrinks 15-40% vs ast and kills
  ALL >10param noise on every file. The semantic join eliminates extraction-
  infeasible proposals automatically.
- **Rust type_edge is structural-only**: field/variant/impl/generic. No param/
  returns/uses edges (TS-only). Signature participation needs type_sig.
- **Anti-unification is the unifying technique**: exact match (isomorphism),
  rename-erasure (alpha-equiv), and generalization (LGG/anti-unification) are
  the same operation at different thresholds. Plotkin's LGG on type trees finds
  missing generics.
- **"Canonical minimality" in code** maps to TurboMQ (edge-ratio optimal
  partition), Rent's rule (empirical power-law shape check), and design rules
  (Baldwin-Clark). All need the graph relations sprefa already produces.
- **The multitool framing**: every technique is a relation producer/consumer.
  dl engine is the composition layer. No ingredient knows about others. They
  share the relation namespace. Recipes are named queries. The query tool lets
  you write new ones.
- **MCP dropped** from immediate scope.
