## Key Insights
- **Dual-layer ops**: pipeline-side Component (no DSL/CST/source-text) + compile-side OperatorDef wrapper (slot specs, parse_dsl, lower). User's mental model: "language adaptor wraps lowered ops." `parse_dsl` per-op enables op-owned DSL grammar.
- **Four-slot model locked**: `op[flow](args)\`dsl\`{block}`. `[flow]` = single Value (defaults to &.value). `(args)` = list of Values split by `,`. `` `dsl` `` = exactly one DSL body, op-owned grammar. `{block}` = sub-pipe.
- **Precedence**: `>` higher than `,`. `(a > b, c > d)` = two args, each is its own pipe.
- **Inline-pipe**: walker re-runs host_parse on slot.raw; recursive walk_pipe wraps as Value::Pipe. Diag spans rebased per seam.
- **Probe path**: RenderCtx is not generic over N (77 sites); threading probe via RenderCtx would force genericization. Lane E threaded via LowerCtx::probe + SpannedComponent wrapper instead. Wrapper overrides dispatch only — catches Emit/Many/Yield uniformly via queue.enqueue interception.
- **QueueBackend bound relaxation**: from `Send + Sync + 'static` → `Send + Sync`. Existing call sites unaffected (Arc<dyn ...> defaults 'static).
- **FactStore unified**: crate::Store deleted (-737 LOC). v2_ops::Fact* dupes deleted; fact::FactRead/Write are canonical.
- **Min file rule**: pipeline.rs and lower/ops.rs each one file. Don't split ops into per-file modules. Three files of types/registry/value stay separate (op_def, ctx, registry, value).
- **ghcacher sqlite is the source of truth** for repos. sprf reads via `fact_read(:gh_branches, ${REPO?}, ...)`. No sprefa-side config of repos.
- **Reactive crawler example fully sprf**:
    fact_read(:gh_branches, ${REPO?}, :main, ${SHA?})
    > rev(${SHA})
    > tree(:**/*.rs)
    > ast `import ${MODULE}`
    > rule(:cross_repo_imports, ${REPO}, ${MODULE}, ${FS})
- **Editor install loop**: `cd v4/editors/vscode && ./install.sh` (puts sprefa-lsp on PATH, compiles TS, installs extension). Reload window.
- **sprefa-run CLI**: `cargo run --bin sprefa-run -- examples/hello.sprf`. Diag format: `path:line:col:sev:code: msg`. VS Code problem-matcher regex matches. tasks.json default = "sprefa-run: current file".
- **Lane C took 6 min cold compile** (tower-lsp + tokio + transitive tree-sitter graph via effect_runtime/ast-grep). Not stuck — first compile only.
- **app_host is parallel chat** — never touch v4/app_host/ from this chat. User owns daemon work elsewhere.

## Next Session Plan: app_host integration

The v4 stack we built ships in-process. v4/app_host (208 + 221 LOC) is a generic Provider/Service/Transport scaffold sitting unused. Integration buys: shared FactStore + parsed-doc cache + probe buffer across binaries, and daemon-readiness without binary rewrite (flip `InProcess` → `DaemonProxy` transport).

### app_host shape (already-built, reading-only)

`v4/app_host/src/lib.rs` — generic, no sprf knowledge:
- `trait Store` — Diff/Tx/Row/Query/Write/Slice; write/read/subscribe
- `trait Dispatch` — Action/Reply/Error per shell
- `trait Handler<S, D>` — `dispatch(&store, action) → reply`
- `App<S,D>` — owns store + handler
- `AppService<S,D>` — `tower::Service<Action, Response = Reply>`
- `trait Transport<D>` — InProcess (today) | DaemonProxy (in daemon.rs, Unix socket)
- task-local `CTX: Arc<dyn Any>` — for ambient context inside handlers

pub struct SprfDispatch;
impl Dispatch for SprfDispatch {
    type Action = SprfAction;
    type Reply  = SprfReply;
    type Error  = SprfError;
}

pub enum SprfAction {
    Run               { path: PathBuf },
    LspOpen           { uri: Url, text: String, version: i32 },
    LspChange         { uri: Url, text: String, version: i32 },

    GetInlayHints     { uri: Url },

pub enum SprfReply {
    RunOk          { facts: Vec<(Arc<str>, usize)>, diags: Vec<Diag> },

    InlayHints     (Vec<lsp_types::InlayHint>),

#[derive(thiserror::Error)]

    UnknownUri,

}

pub fn build_in_process_app() -> Arc<App<SprfStore, SprfDispatch>> { ... }

### why this is the right next step

- closes the dangling subtree (v4/app_host has 429 LOC sitting unused)
- shared cache eliminates redundant parse/walk on every LSP request
- daemon-ready: switching transports is a one-line change in the binaries
- prerequisite for the ghcacher → FactStore bridge — that bridge becomes a long-lived task feeding `SprfAction::ExternalEvent` actions into the App
- prerequisite for the sprf-native cross-repo crawler — without a shared App, there's no way to react to external events while LSP is also driving the same FactStore
