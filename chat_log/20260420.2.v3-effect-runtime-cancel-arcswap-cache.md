## Problem/Context

Session `20260420.0` landed the effect_runtime crate with four batcher
topologies, telemetry, and the teaching doc in `v3/docs/FINDINGS.md`.
The queued followups discussed read-only effects needing cancellation,
a way to hot-swap handlers (config reload / LSP), and caching for pure
reads. The question "does read/write need to split in the trait
hierarchy" resolved to: no — both are `EffectKind`; a `PureEffect`
subtrait tags read-like effects with a cache key and domain; writes
call `ctx.invalidate_domain(DOMAIN)` after committing.

## Solution/Approach

Five discrete edits landed in `effect_runtime`:

1. `EffectKind` unchanged. New `PureEffect: EffectKind` subtrait with
   `type Key: Hash + Eq + Clone + Send + Sync`, `const DOMAIN: &str`,
   `fn cache_key() -> Self::Key`.

2. `Batcher::run` signature bumped to
   `fn run(&self, req: E, cancel: CancellationToken) -> BoxFuture<…>`.
   Existing batchers accept the token and ignore it (drop-cancellation
   via Rust's normal future-drop is sufficient for WorkSteal /
   BoundedWorkSteal / BoundedBatched / Passthrough — CPU work runs to
   completion, the reply channel drops; cooperative CPU interruption
   is left to op-author work functions that can read a clone of the
   token).

3. Registry moved from `Arc<HashMap<TypeId, …>>` to
   `Arc<ArcSwap<HashMap<TypeId, …>>>`. `RtCtx::rebind::<E>()` and
   `RtCtx::rebind_domain_aware::<E>()` do RCU-style atomic insert.
   `RtCtxBuilder::register_domain_aware::<E, B>` registers a batcher
   that also implements the new `DomainInvalidate` trait so
   `ctx.invalidate_domain(d)` can walk it.

4. `CacheLayer<E: PureEffect>` moka-backed. Wraps an inner
   `Batcher<E>`; on hit returns the Arc'd stored response; on miss
   forwards with the same `CancellationToken`, stores, returns.
   `DomainInvalidate::invalidate_domain(d)` drops the whole moka
   cache when `d == E::DOMAIN`. Tracks hits/misses via `AtomicU64`;
   `stats() -> CacheStats { hits, misses, entries }` with
   `hit_ratio()` convenience. `Clone` impl (all-Arc internals) so the
   harness can register one clone via `register_domain_aware` and
   hold a second clone for stats reads.

5. `RtCtxBuilder::register_pure::<E, _>(cap, inner)` sugar = build
   `CacheLayer::new(cap, inner)` + `register_domain_aware`. ~8 LoC.

Cancellation surface on `RtCtx`:
- `root_cancel: CancellationToken` owned by ctx.
- `put(e)` internally creates `root_cancel.child_token()`.
- `put_with_cancel(e, token)` for caller-supplied tokens.
- `cancel_all()` cancels the root.
- `root_cancel()` returns a clone for shutdown listeners.

## Key Insights

- **Read/write split is not a trait split.** One bit (`IS_PURE` via
  the presence of a `PureEffect` impl) plus a domain tag covers cache
  eligibility, invalidation, and ordering-against-writes concerns. No
  separate hierarchy needed.
- **Caller-drop is the dominant cancellation path.** Threading a token
  into `Batcher::run` is cheap and gives CPU-bound work a way to
  cooperate; but callers dropping the put future already cancels
  correctly at the coordination layer (rayon runs to completion and
  the oneshot reply drops).
- **Userland caching is the default; framework sugar unlocks 1-liner
  caching.** Option 2 of the caching-location question landed:
  `register_pure` covers the happy path, `register_domain_aware` +
  hand-rolled `CacheLayer` for bespoke configs, and userland keeps
  control for negative caching / partial caching / prewarm.
- **Perf parity held across the signature bump.** Per-put hot path is
  now `ArcSwap::load` (RCU pointer deref) + HashMap lookup; same big-O
  and measurements land within noise of `20260420.0`.
- **CacheLayer memory cost is small.** ~1.1 KB/entry amortized
  (moka bookkeeping + response Arc) at `u64` response size; scales
  with actual payload size for larger responses.

## Bench A/B Measurements

Cache A/B bench (synthetic `ScanBlob { id }` pure effect, 2000 blobs
× 16 KB × 5 passes, W=8):

| pass | cache=off | cache=on | hit_ratio (cum) |
|---|---|---|---|
| 1 | 15.9 ms | 12.5 ms (miss) | 0.000 |
| 2 | 13.2 ms |  2.9 ms        | 0.500 |
| 3 | 12.3 ms |  3.0 ms        | 0.667 |
| 4 | 12.0 ms |  2.7 ms        | 0.750 |
| 5 | 12.0 ms |  2.9 ms        | 0.800 |

Warm-pass speedup ≈ 4.3×. RSS delta = +2.3 MB end-of-run.
