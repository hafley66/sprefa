## Problem/Context
User was lost on what the merged work buys. Walked it through: a type
= a decl-only `rule(:T, cols)`; `resolve_dot` 3-step; chained dots
carry `col_type` forward; bad field = loud `lang/dot-miss`. Honest
verdict surfaced: the merged half is a **compile-time schema lint
only** — decl-only rules have zero rows, nothing stamps `.ty` from an
`ast` match (task #4 parked), runtime is empty. User then redirected:
the real goal is NOT a tree-sitter type dump; it is a cross-file
entity/import graph (stack-graphs / SCIP stanzas, module resolution
emulation, type flow across files when no macro; `syn` acceptable).
Then the architectural question: `Value` is `Atom|Pipe`; to express
operators/rules (callables) as values and have a rule-type point at
another rule-type, the enum must widen — did the model corner itself?

## Solution/Approach
- No corner: types are NOT Values. A type = FactStore schema + a
  `col_types` name-edge map. Type→type ref = a string edge, resolved
  lazily per hop (cycles safe). `Value.ty` is `Option<Arc<str>>` = a
  name, never a Value.
- Callable-as-value design: add ONE variant
  `Callable(CallableRef{kind:Op|Rule, name})`, ref by name only, no
  embedded def/closure.
- User's collapse: **application IS a Pipe.** `apply(callable,args)` =
  lower to one Component, wrap in the existing `Pipe` variant — reuses
  `Registry::lower` (Op) and the resolve_dot/project path (Rule). No
  4th concept; output side already exists. No curry → arity-exact, zero
  partial-application state (removes the grammar-slotting pain).
- One OPEN worm recorded: a self-referential `Callable(Rule)` vs the
  merged recursion engine (owner-subscribe, `main` 37bb93a5) — confirm
  no double-fire when unparked.
- All decisions captured in `plans/2026-05-18-callable-value.md` and in
  memory (`project_cross_file_entity_graph`,
