# Phase 1 Plan — Scan Pointer Runtime

## Goal
Stamp captures with scan pointer + tri-state during forward pass. Feed Missing/Claimed back into runner to drive another scan pass (v1 `unscanned_*` pattern). Close the demand-scan loop.

## Data Model

`v2/src/_0_types.rs`:

```rust
pub enum Tri { Claimed, Verified, Missing }

pub struct Capture {
    // existing fields...
    pub scan_pointer: Option<Arc<str>>, // e.g. "repo", "rev", "fs"
    pub verified: Tri,                   // default Claimed when scan_pointer set, else Claimed (unused)
}
```

Tri defaults meaningful only when `scan_pointer.is_some()`. Captures w/o scan pointer ignore `verified`.

## Stamping (forward pass)

Forward pass = op writes field at capture creation. No second sweep.

- `ops/_1_repo.rs` — RepoMode::Bind: after resolving repo name from Config, when inserting Capture → `scan_pointer=Some("repo")`, `verified=Verified`.
- `ops/_2_rev.rs` — mirror for `"rev"`.
- `ops/_3_fs.rs` — mirror for `"fs"`.
- Walker ops — any ScanAnnotation in walker pattern: extracted Capture stamped `scan_pointer=annotation.sigil_field`, `verified=Claimed`. Applies to json today; line / ast-grep when they land. Centralize stamping in walker driver, not per-op, so line/ast-grep inherit.

## Checker Pass

`v2/src/_12_result_store.rs` or new `_13_scan_check.rs`:

- Walk ResultStore rows post-pipeline.
- For each Capture with `scan_pointer=Some(p)` and `verified=Claimed`:
  - Look up known set for `p`: `"repo"` → `Config.repos`, `"rev"` → `Config.revs`, `"fs"` → fs scan set.
  - If value ∈ known → flip to `Verified`.
  - Else → flip to `Missing`, emit `scan-pointer/unverified` Warn.

## Demand-Scan Loop (the working part)

`ResultStore::unscanned() -> Vec<(scan_pointer, value)>`:
- Query all Captures where `verified == Missing`.
- Group by `(scan_pointer, value)` dedup.

Runner loop:
1. Run pipeline pass N.
2. Run checker pass.
3. Call `store.unscanned()`.
4. If empty → done.
5. Else → add each `(p, value)` to Config (repos/revs/fs set), run pass N+1.
6. Stop after fixed-point or iteration cap (e.g. 8 passes, error if exceeded).

New pass re-reads scan-pointed content; previously Missing captures now hit known set → flip Verified.

Runner lives in `v2/src/_11_runner.rs` (or wherever pipeline drive). Edit: wrap single-pass call in loop + Config extension.

## Storage Gate (FK write)

Deferred from Phase 1 but design locked:
- SQLite writer skips `X_repo_id`/`X_rev_id` FK column when `verified != Verified`.
- `X_str` always written. `X_verified` enum column written.
- Missing rows land, FK null, warn diag attached.

## Delete

- `Operator::scan_pointers()` `read: fn(&Cursor)` fn slot: check if any runtime code reads it. If not → delete, keep only `sigil` + declaration. Forward-pass stamping makes `read` vestigial.

## Tests

`v2/tests/scan_pointer_runtime.rs`:
- Repo bind → Capture stamped repo + Verified.
- Rev bind → rev + Verified.
- Json walker, value ∈ Config.repos → Verified after checker.
- Json walker, value ∉ Config → Missing + Warn diag.
- Demand loop: start Config with 1 repo, walker claims 2 others → after loop, 3 repos scanned, all Verified.
- Iteration cap: cyclic claim explosion → error after N passes.
