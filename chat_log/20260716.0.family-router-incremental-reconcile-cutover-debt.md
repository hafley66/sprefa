## Solution/Approach
- The reactive loop had dep capture + memo but render was a full reload_rel, so a
  RETRACTED input row was silently rebuilt, never retracted. Built the missing half:
  - Storage::retract_rows(table, cols, rows): one row-value DELETE ... WHERE (cols) IN
    (VALUES ...), no per-row loop (src/storage.rs).
  - RowDelta{retracted, inserted} + reconcile(old, new): diff by type-tagged tuple key
    (row_key) because Value doesn't derive Hash/Eq (src/engine/family/mod.rs).
  - FamilyRouter::react_deltas(db, changed): rerun affected families, return each one's
    RowDelta vs its memo, update memo (src/engine/family/router.rs).
  - Rail family_router_retracts_output_row_on_input_retraction proves it end-to-end.
- Separately fixed the 4 red it-tests (Sonnet agent found root cause): NOT mis-set bounds
  — four fixture/test .dl programs used `match(path,rev,/./,line)` (one source-stage row
  per CHARACTER) on a never-read `seen` trigger, burning the 64MB/1M-row global budget.
  Fix = bare scan (one row per file). 4th test (perf_stress_c) was a separate non-UTF-8
  read crash in parse_file/read_content, fixed by is_invalid_utf8 skip-to-empty.

## Key Insights
- The family engine does NOT canonicalize or reduce code for the call family. Writing
  "owned tables + project" is strictly MORE code than "direct write", and the resolution
  logic (resolve_callee/resolve_caller, ~150 lines) CANNOT be deleted — it populates the
  owned tables the families read. Even a full cutover won't net-reduce production LOC here.
- The family engine relocates SQL, doesn't eliminate it: Ctx::scan is raw format!("SELECT
  ...") — 11 bespoke-sql sites inside the "abstraction". 584 raw SQL sites total in src/.
- Incremental render (retraction) is coherent ONLY when the family path is the SOLE writer.
  Under the current additive/two-writer model (legacy writes, flip overwrites) an
  incremental delta double-writes. So the reconcile mechanism is built + proven but gated
  on the cutover to go live. This is a hard coupling, not a wiring detail.
- rel-level skip only fires when a change touches a table some families read and others
  don't. call_name/_call_def is the disjoint input that makes the skip real on site-only edits.
- The 4 "bounds" perf failures were wasteful fixture queries (match(/./)=per-char rows on
  an unused `seen` trigger), NOT a mis-set limit or engine bug. The cap was correct.
- Two latent bugs surfaced only because the work made these paths actually run:
  refresh_call_rels_delta held an immutable cache borrow across a borrow_mut (panic on
  cache miss), and parse_file aborted the whole tick on the first non-UTF-8 file.
- Value = enum{Text(String),Int(i64),Null}, derives neither Hash nor Eq — diff must key
  rows by a type-tagged string (i/t/n prefix) to avoid Int(0)/Text("0")/Null collisions.
