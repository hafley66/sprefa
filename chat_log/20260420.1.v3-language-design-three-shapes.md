## Design arc across the session

Seven iterations of the term/grammar shape, each shrinking surface
while surfacing a load-bearing invariant.

### Iteration 1: casing-as-syntax locked
First-character case disambiguates: UPPER = term/capture, lower =
op/rule-name. Confirmed existing convention from v2. Locked.

### Iteration 2: injection driver generalized
`recurse_generic.rs` drops the three hardcoded injection branches in
`recurse.rs`, replaces with `GrammarSpec { lang, injections: Query }`
registry. Supports `@injection.content`, `@injection.language`
dynamic, `#set! injection.language` static, `#match?` predicates.
Zero framework code edits to add a grammar; register one entry + one
scm string. Matches nvim-treesitter/helix/zed contract.

### Iteration 3: Lispy collapse (attempted, then reverted)
Proposed `(name) = expr` abstraction form to collapse rule decl and
capture decl into one syntactic slot. User flagged: "hmmm" on the
paren overload, then directed to read v2 files. v2 actually uses
`rule(name) { body }` with rule as an op. Reverted. Captures stay
as `$NAME` in walker bodies; rules stay as `rule(name)` op calls.
The Lispy insight (one env, one resolver) survives; the Lispy
binding syntax does not.

### Iteration 4: value tier
Five scalar literal kinds: string (five quoting forms:
`"..."`, `'...'`, `"""..."""`, `r"..."`, `r#"..."#`), number,
boolean, atom (`:name`), null. Regex and glob stay as ops taking
string args (no dedicated `/.../ ` literal). Capture types stay
framework-internal via `SlotKey<T>`; authors never write types.

### Iteration 5: colon atoms (optional, not mandatory)
`:name` is an explicit atom literal. Useful where bare ident would be
ambiguous. v2 uses implicit atoms in op slot positions (`ast[rust]`
passes the atom `rust`); explicit `:` form is opt-in disambiguation.
User earlier proposed colon-prefix for rule refs (`${:rule.$V}`);
that form is retired. Rule refs stay bare `${rule.$V}`.

### Iteration 6: `>` overload problem
`>` is pipe composition at top level. Inside a carveout,
`${rule.$V > $NEW}` used `>` for rename — two meanings, one symbol.
User flagged "cant have special op > op forms, that breaks
compositions." Decision: `>` stays pure as pipe; rename inside a
carveout needs a different symbol. Candidates: `as`, `->`, `=>`,
`:>`. Preference noted for `->` but not locked.

### Iteration 7: three composition shapes
User surfaced the cleanest framing via an example:
```
rule(X) > A > (B > C) > { > D; > E; > F; } > G;
```
Three shapes, three distinct delimiters:

| shape | delim | meaning |
|---|---|---|
| 1-1 pipe | `A > B` | serial flow |
| nesting | `(A > B > C)` | grouped sub-chain, precedence + reuse |
| 1-m fork | `{ > A; > B; > C; }` | parallel arms, union downstream |

Rule as chain-starter op: `rule(X) > chain;` — brace-wrapper dropped
from v2's `rule(X) { > chain }`. Brace `{...}` now means fork
exclusively (outside op slot positions). Chain is first-class;
rule, grouping, fork are three syntactic forms that compose anywhere
in a chain.

## Cursor semantics worked out

### What xref does to the cursor
`${rule.$V -> $NEW}` (using `->` as placeholder rename operator):

| cursor field | behavior |
|---|---|
| fs / repo / rev / content / byte_range / slots / parent | unchanged |
| captures | grows by one: `captures["NEW"] = Capture { value, byte_range, kind }` |

The assigned value is the sub-grammar's decoded form of the node at
the hole position. For a JSON string node, the string content. For
regex, the match text. For ast-grep metavar, the matched subtree's
span + kind.

Xref is a filter on the cursor stream plus a capture write. Cursor
either continues with the new binding or drops.

### Contrast with cursor rebase
| operator | changes | purpose |
|---|---|---|
| `${rule.$V -> $NEW}` | captures grow | filter + bind |
| `&.$X` | content + byte_range narrow | re-enter sub-value as fresh input |
| `&.fs` / `&.repo` / `&.rev` | byte_range or field-set | structural rebase |

## Scan sigils revisited

User proposed: scan sigils `$$repo($R)`, `$$rev($T)` are redundant
with the op name that names a cursor field. Re-frame as an op-level
capability:

- **Core ops** (`repo`, `rev`, `fs`) map 1-to-1 to cursor struct
  fields. Their capture args in walker bodies imply scan-seeding
  without needing `$$` prefix.
- **User ops** can opt in by declaring a cursor slot of their own
  and flagging it scan-seedable.
- The privilege is structural (cursor struct layout), not syntactic
  (sigil class).

Three routes for spelling scan-seed:
1. Position-is-enough: core-op capture in walker body auto-seeds
2. Annotation on capture: `$R:scan`
3. Dedicated registration op: `> scan_seed(:repo, $R)`

Decision deferred. The principle (scan-seeding is a field-level
capability, not a syntactic class) is the load-bearing piece.

## "Remove norm, make it an op over cursor.content"

Generalizable rule:
> Any transformation expressible as "read cursor field X, write cursor
> field Y" lives as an op. Special syntax earns its keep only when
> the transformation cannot fit that shape.

Absorbs norm, trim, decode, encode, slug, hash, indent, dedent as
regular ops. No dedicated syntax for any of them.

## v2 vs v3 table (summary)

Full table in transcript. Highlights:

| aspect | v2 | v3 |
|---|---|---|
| rule decl | `rule(name) { > chain }` brace wraps | `rule(name) > chain;` flat chain |
| nested rule | brace nesting | fork arms with rule-headed leader |
| pipe | `A > B` | `A > B` |
| grouping | via outer rule brace only | `(A > B > C)` standalone |
| fork | brace + `;` arms (inside rule brace) | `{ > A; > B; }` exclusively |
| op brace slot | op-owned | op-owned, must follow op ident |
| stmt terminator | `;` optional | `;` required at top level |
| cross-rule ref | `${rule.$V}` | `${rule.$V -> $NEW}` (rename optional) |
| `>` overload | pipe + rename | pipe only |
| scan sigil | `$$repo($R)` | folded into op args / field annotation |
| evidence | none | tap-before-filter tables |
| check ops | none | check / assert / witness |
| higher-order ops | none | ops take op-values via env resolution |

## Key insights

- **Rule is a label-op, nothing more.** Top-level `rule(X) > chain;`
  creates absolute path X. Nested `rule(X)` inside a fork arm
  creates a relative path under the parent. Same op, same syntax,
  position decides scope.
- **Three composition shapes, three distinct delimiters.** `>` for
  pipe, `(...)` for grouping, `{ > A; > B; }` for fork. One
  symbol per job.
- **`>` is cursor composition. Nowhere else.** Any other use of
  `>` inside expressions breaks composition. Rename and projection
  inside a carveout use a different symbol.
- **Scan-seeding is a cursor-field capability, not a sigil class.**
  Core ops (repo, rev, fs) privileged because they map to cursor
  fields. User ops earn the same privilege by declaring slots.
- **Content transforms are ops.** Norm, trim, decode, encode, slug,
  hash, indent, dedent. No dedicated syntax for any.
- **Xref opens questions.** User's closing message flagged that
  xref touches more than the in-flight cursor: potentially the
  rule's capture hash and the downstream cursor's content. Next
  session resolves.
