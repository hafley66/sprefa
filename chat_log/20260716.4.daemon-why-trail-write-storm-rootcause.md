## Solution/Approach
Content-digest skip at every write seam + honest change propagation + settle ignores self-inflicted bookkeeping:
- engine/mod.rs rows_content_digest(cols, rows, scope): per-row blake3, wrapping-add fold (order-independent, duplicate-sensitive), count+cols+scope in final hash. refresh_rel → Result<bool>, skips reload when digest matches `rows:{rel}` in _reldigest AND live COUNT(*) == encoded.len() (guards external deletes e.g. sweep_gone_revs). refresh_rel_for_revs same with rev-scoped COUNT + revs folded into digest.
- type_rels.rs + dataflow.rs: rows_changed |= each write; type gates rebuild_legacy_type_rels on it; both return honest bool.
- rels/scip.rs + rels/catalog.rs: rows_changed |= ORs (was unconditional true).
- RelKind::bookkeeping() (PerfKind, QueryLogKind override true) + rels::is_bookkeeping_rel(); is_settled treats bookkeeping like timer rels (tick.rs). NOTE: first attempt parked bookkeeping out of the rebuild scope entirely — broke perf_woes it-test (slow-rule rails must stay live) — reverted to settle-only exclusion; rails re-derive on one trailing tick.
- call.rs: call_flip_moved Cell<bool> on Engine (signature change would break 10 test sites); flip_call_rels_via_router sets it (cold reload or non-empty delta); refresh_call_rels returns it.
- daemon.rs poll_tick: activity::end_tick() after drain (why-trail read "effects drain" forever).
