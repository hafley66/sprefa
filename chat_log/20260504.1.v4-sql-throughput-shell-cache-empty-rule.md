## What landed

### v4_bench: sqlite-mem / sqlite-disk / sqlite-fast wired

`--store mem|dd|sqlite-mem|sqlite-disk|sqlite-fast`. Insert mode now
calls `store.commit` (Sqlite needs it; mem/dd no-op). Switched to
`FactWrite::new("matches", &["FS","CONTENT_HASH","LO","HI"])` so sqlite
gets ensure_schema upfront. `--commit-every N` now applies to Insert
mode too (was Full-only). Trial-1 wipes the on-disk db so cold cost is
deterministic across runs.

### SqliteStore::open_path_fast

PRAGMA bundle for cache-grade durability:
- page_size=8192 (set before any DDL)
- journal_mode=MEMORY
- synchronous=OFF
- locking_mode=EXCLUSIVE
- temp_store=MEMORY
- cache_size=-65536 (64 MB)

Loses pending writes on crash. Correct when the sqlite is a derived
cache (LSP / scanner) rebuildable from the source corpus + Layer-2
hashes. Matrix below shows 2.3× speedup over default WAL+NORMAL.

### SqliteStore::commit hot path

- Multi-row VALUES (?,?,?,?), (?,?,?,?), … in chunks. CHUNK env knob
  via `SPREFA_SQLITE_CHUNK` (default 500). Capped at 32000/ncols to
  stay under SQLITE_MAX_VARIABLE_NUMBER.
- prepare_cached per chunk SQL — same SQL for all full chunks of a
  fact, only tail differs, so cache hot.
- Bind `Option<&str>` directly (was Option<String>); skips per-cell
  String allocation. ~1.5M allocations saved at 366k rows.
- Per-fact span `v4::Sqlite::commit::write` includes bytes_in.
- Phase spans: `commit::lock`, `commit::begin`, `commit::write`,
  `commit::txn`. The bind+VDBE work shows up as `write`; the actual
  sqlite final commit (page write / checkpoint) shows up as `txn`.

### Empty-body Rule = passthrough (the unification)

Three semantics now coexist:
- `Rule::new(name, vec![], name, cols).declare(store)` — declaration
  only (was already there). Ensures schema, never drives.
- `drive_rule_cached(empty_body_rule, ...)` returns `RuleRunOutcome::Skipped`
  early, after calling `rule.declare`. No more no-op drive.
- `drive_rule_with_input(rule, seed, h, cap)` — caller-driven path.
  Prepends `Seed::new(seed)` upstream of the body. Empty body collapses
  to `[Seed > FactWrite]`. Empty rule echoes inputs into its sink.

`Rule::is_passthrough()` exposes the body.is_empty() check.
`Rule::into_chain_with_seed(seed)` builds the seed-fed chain.

### Shell caching

`Sh` is_pure=true ⇒ wraps cleanly under `OpCache`. Same skip-on-hit
contract as AstNm. Five tests in tests/sh_cache.rs:
- wrap doesn't panic
- cold pass: 3 cursors → 3 misses → 3 shell invocations
- warm pass: same 3 cursors → 3 hits → 0 invocations, 0 emits
- distinct lineage = miss again (verified by touchfile count)
- EmitLines warm-skip: cold emits N children, warm emits 0
- ShBang refused (is_pure=false) — should_panic

## Results

Workload: linux fixture (~63k .c files), 8 workers, release build.

### Baseline (16,627 matches — `printk($$$)`)

| store         | wall (median 3-trial) | commit  | RSS    |
|---------------|-----------------------|---------|--------|
| bare (no store) | 3.79s              | —       | 291 MB |
| mem           | 3.89s                 | 875ns   | 268 MB |
| dd            | 3.83s                 | 13µs    | 268 MB |
| sqlite-mem    | 3.74s                 | ~6ms    | 295 MB |
| sqlite-disk   | 3.86s                 | 13.6ms  | 276 MB |
| sqlite-fast   | ~3.85s                | ~10ms   | ~280 MB |

All within 100ms of bare. AstNm dominates the wall (~3.5s parse on this
corpus), store cost is tail noise.

### Heavy pattern (366,307 matches — `if ($COND)`)

3-trial median total wall (AstNm-dominated, store cost is the delta):

| store         | wall median | RSS    |
|---------------|-------------|--------|
| mem           | 19.02s      | 913 MB |
| dd            | 20.37s      | 865 MB |
| sqlite-mem    | 20.24s      | 1081 MB |
| sqlite-disk   | 20.83s      | 822 MB |
| sqlite-fast   | 21.03s      | 1014 MB |

Store-axis cost (single-trial commit phase telemetry):

| store        | commit total | write   | txn     | lock + begin | rows/s |
|--------------|--------------|---------|---------|--------------|--------|
| mem          | 875ns        | —       | —       | —            | —      |
| dd           | 13.9µs       | —       | —       | —            | —      |
| sqlite-mem   | 141.7ms      | 140.2ms | 1.5ms   | 8.8µs        | 2.59M  |
| sqlite-disk  | 447.6ms      | 312.7ms | 134.8ms | 8.0µs        | 818k   |
| sqlite-fast  | 238.9ms      | 138.8ms | 100.1ms | 7.4µs        | 1.53M  |

Read:
- `write` = chunked-execute loop (bind + VDBE step + WAL/page write
  if sync per execute happens).
- `txn` = txn.commit() — final fsync / page-cache flush.
- sqlite-disk `write` (313ms) is 2.2× sqlite-fast `write` (139ms) and
  sqlite-mem `write` (140ms). The WAL fsync inside execute is the
  difference; sqlite-fast hides in mem speed for the bind loop.
- sqlite-disk `txn` (135ms) ≈ sqlite-fast `txn` (100ms); both flush
  page cache. fsync at sync=NORMAL adds ~35ms.
- sqlite-fast bind loop ≡ sqlite-mem bind loop. The remaining 100ms
  in `txn` is the cost of dirty pages eventually hitting OS write
  buffers, no way around it without a pure mem store.

PRAGMA bundle delivers 1.87× over WAL+NORMAL on this workload.

### CHUNK sweep (sqlite-fast, 366k rows)

| CHUNK | commit | write | txn |
|-------|--------|-------|-----|
| 100   | 228ms  | 113ms | 115ms |
| 500   | 268ms  | 135ms | 133ms |
| 1000  | 272ms  | 142ms | 130ms |
| 2000  | 229ms  | 132ms | 97ms |
| 4000  | 282ms  | 140ms | 142ms |
| 8000  | 304ms  | 142ms | 162ms |

Single-trial, noisy. Sweet spot ~100. Beyond ~2000, prepare-cache miss
on tail + larger param vectors hurt more than they help. Default left
at 500 (balanced; survivable on tiny corpora).

### commit-every sweep (sqlite-disk, default WAL+NORMAL, 16k rows)

| commit-every | commits | mean per commit | total commit | total wall |
|--------------|---------|-----------------|--------------|------------|
| 0 (one shot) | 1       | 13.6ms          | 13.6ms       | 3.79s      |
| 16           | 2       | 7.3ms           | 15.7ms       | 3.82s      |
| 4            | 5       | 2.8ms           | 14.0ms       | 3.91s      |
| 1            | 17      | 1.3ms           | 22.0ms       | 3.97s      |

Per-tx fixed cost ~800µs even at sync=NORMAL. Many small commits eat
compound wall under reactive (LSP-shaped) workloads. The PRAGMA bundle
helps here too but durability story flips.

## N+1 audit

- ensure_schema: once at FactWrite::run start. Not per row.
- insert_many: one Mutex<HashMap> acquire per batch (16 acquires for
  16627 rows or 366k rows; cap=64, batch=4096). Linear in batch count,
  not row count.
- prepare_cached: one cache hit per chunk for full chunks (same SQL),
  one tail prepare. 366k/500 = 733 chunks ⇒ 1 unique prepare + 732
  cache hits + 1 tail prepare.
- bind: one Option<&str> per cell, no allocation, single Vec<&dyn ToSql>
  per chunk.

No N+1 paths.
