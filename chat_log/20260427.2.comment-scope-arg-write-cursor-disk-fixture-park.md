## Solution/Approach

### comment scope-arg
Sift Value::Term { mode: Unbound, name } out of the marker slice in CommentOp::from_values. Multiple unbound terms = comment/multiple-scope-terms. A bound ${SCOPE} (Read mode) at this slot = comment/scope-term-must-be-unbound (the term names a binding site, not a reference). Region struct extended with inner_start/inner_end. paired_regions stack frame extended with marker-line span (byte_start, byte_end) so inner_start = (open.byte_end + 1).min(src_len), inner_end = close.byte_start.max(inner_start). Sequential mirrors the same shift. Outer cursor still narrows to outer range (markers included); SCOPE capture lives alongside, byte_range = inner.

### WriteRangeSink::Disk
Read existing file → splice_bytes(existing, range, new, mode) → write back. Mutex<()> per sink for read-modify-write atomicity within a drain. byte_range OOB returns Err (don't corrupt on misaligned capture).

## Key Insights
- The carveout opener `${...}` is hard-coded in tree-sitter-sprefa/grammar.js as a literal `${`. Multi-metavar `$$${X?}` (3 leading $) does not tokenize today. This is a real grammar gap, distinct from the wrong `${$$$X?}` form (3 $ inside the braces) that some old fixtures had. Fix is grammar-side: extend carveout_expr opener to seq($._dollars_open, '{', body, '}') with _dollars_open = token(choice('$', '$$$')). Parser regen required after grammar.js edit.
- After render's rebase, cursor.content swaps to synthesized bytes but captures retain their original-content byte_ranges. SpanBacked captures become "dangling" with respect to the new content but remain semantically meaningful as on-disk pointers — that's exactly what write_cursor relies on. Anywhere that does `&c.content[cap.byte_range]` after render must clamp/fallback or panic on OOB. Caught one such site (print_row); audit other code that indexes content by capture range.
- Comment op's inner range computation must handle edge cases: open marker on last line with no trailing newline (byte_end == src.len(), inner_start clamped to src_len), back-to-back markers (close immediately after open, inner range degenerates to start..start which is fine — write_cursor :replace splices at point).
- Workspace `[profile.dev.package."*"]` only matches non-workspace packages. This is what we want — workspace members (the code we iterate on) stay opt-level=0 for fast incremental builds; everything else (tree-sitter, ast-grep, syn, serde-json, etc.) runs at release optimization.
- cargo sweep --time 0 = wipe everything (older than 0 days = older than now). Use --time 1 or --stamp/--file. Memory saved to prevent recurrence.
