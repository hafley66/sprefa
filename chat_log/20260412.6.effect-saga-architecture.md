# Session: effect-saga-architecture

## Goal
Design an effect-based saga architecture for sprefa where operations produce JSON diff descriptors rather than executing immediately, enabling redux-saga style detached read/write/producer daemon/coroutine patterns with full durability in the database.

## Current State
NOTES.md contains designs for:
- sh() with four forms (sh/sh_mut/sh_batch/sh_mut_batch)
- Three-phase scan architecture (extract → shell → checks+codegen)
- Pending cuts side channel for gated shell execution
- Reactive execution model (rxjs/observable based)
- Self-rendering codegen via comment scopes
- Cross-rule refs as live streams

The user clarified sprefa's core identity: "super refactor" = treating codebases as live circuits that can be rewired. Refactoring ops are first-class effects alongside shell/check/codegen.

## Problem/Context
Current design has side effects happening inline during scan. Need:
1. Detached execution (effects produced now, executed later/conditionally)
2. Durability (effects survive process restart)
3. Audit trail (complete history of what was proposed/approved/applied)
4. Composition (effects can depend on other effects)
5. Safety (circuit breakers, rollback, approvals)

## Solution/Approach

### Effect Descriptor Protocol
All operations produce Effect structs rather than executing:

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum Effect {
    // Phase 1: Pure reads (always allowed)
    FsGlob { pattern: String, base: PathBuf },
    FsRead { path: PathBuf },
    AstParse { language: String, content: String },
    
    // Phase 2: Shell (gated by allow list)
    ShellExec {
        pattern: String,
        inputs: Vec<InputRow>,
        allowed_patterns: Vec<String>,
        timeout_ms: u64,
        mutating: bool,
    },
    
    // Phase 3: Checks (pure, depend on prior phases)
    SqlCheck {
        query: String,
        expected_empty: bool,
    },
    
    // Phase 3: Codegen (writes)
    CodegenRender {
        source_query: String,
        target_file: PathBuf,
        template: String,
        marker_start: String,
        marker_end: String,
    },
    
    // Phase 4: Refactoring (structural code changes)
    RefactorTransform {
        id: String,
        description: String,
        targets: Vec<TargetRange>,
        template: TransformTemplate,
        safety_check: SafetyLevel,
        estimated_impact: ImpactReport,
    },
    
    // Phase 4: FS Writes (codegen/refactor result)
    FsWrite {
        path: PathBuf,
        content: String,
        range: Option<ByteRange>,
        backup_first: bool,
        source_effect: EffectId,
    },
}
```

### Four Phase Architecture

| Phase | Effect Types | Gating | Examples |
|-------|--------------|--------|----------|
| 1. Extract | FsGlob, FsRead, AstParse | None (pure) | fs(), json(), ast() |
| 2. Shell | ShellExec | Allow list | sh(), sh_mut() |
| 3. Check | SqlCheck, Assert | None (pure) | check() blocks |
| 4. Refactor | RefactorTransform, FsWrite | Explicit approval | refactor(), codegen() |

### Effect Journal (Durability)

Effects stored in SQLite following existing Store trait pattern:

```sql
CREATE TABLE effects (
    id TEXT PRIMARY KEY,           -- effect:{type}:{rule}:{timestamp}
    type TEXT NOT NULL,            -- shell_exec, refactor_transform, etc
    phase INTEGER NOT NULL,        -- 1, 2, 3, 4
    status TEXT NOT NULL,          -- pending, approved, running, completed, failed, rolled_back
    
    -- Serialized effect descriptor
    descriptor TEXT NOT NULL,      -- JSON
    
    -- For dependency ordering
    depends_on TEXT,               -- JSON array of effect IDs
    
    -- Lifecycle timestamps
    proposed_at TEXT NOT NULL,     -- ISO8601
    approved_at TEXT,
    started_at TEXT,
    completed_at TEXT,
    
    -- Result tracking
    result TEXT,                   -- JSON: stdout, diff, error, etc
    rollback_of TEXT,              -- reference to effect this rolls back
    
    -- Metadata
    rule_name TEXT,                -- which rule produced this
    file_path TEXT,                -- target file (if any)
    safety_level TEXT              -- pure, reversible, destructive
);

CREATE INDEX idx_effects_status ON effects(status);
CREATE INDEX idx_effects_phase ON effects(phase);
CREATE INDEX idx_effects_rule ON effects(rule_name);
CREATE INDEX idx_effects_file ON effects(file_path);
```

### Daemon/Coroutine Architecture

```
Producer Coroutines → Effect Bus → Consumer Coroutines

Producers (always running):
- fs_watcher (inotify/fsevents)
- git_hook_listener
- lsp_change_stream
- demand_scan_trigger

Effect Bus (channels):
- Phase 1: Extract effects → always execute
- Phase 2: Shell effects → gated
- Phase 3: Check/Codegen → depends on phase 2
- Phase 4: Refactor → explicit approval

Consumers (react to approved effects):
- ShellExecutor (gated by ACL)
- CheckRunner (pure, re-runs on data change)
- CodegenRenderer (writes with atomic swap)
- RefactorApplier (circuit breakers, rollback)
```

### Saga Pattern: Effect Lifecycle

```rust
// 1. PRODUCE (during scan/rule evaluation)
fn produce_effect(effect: Effect) -> EffectId {
    let id = generate_id();
    let record = EffectRecord {
        id: id.clone(),
        status: Status::Pending,
        proposed_at: now(),
        descriptor: serde_json::to_string(&effect),
        ..Default::default()
    };
    store.insert_effect(record);
    
    // Auto-approve if matches allow list
    if auto_approve(&effect) {
        approve_effect(&id, ApprovalSource::AutoAllowList);
    }
    
    id
}

// 2. APPROVE (CLI, LSP hover, or auto)
fn approve_effect(id: &EffectId, source: ApprovalSource) {
    store.update_status(id, Status::Approved);
    EFFECT_BUS.send(ApprovedEffect { id: id.clone(), source });
}

// 3. EXECUTE (consumer coroutine)
async fn execute_effect(id: &EffectId) {
    store.update_status(id, Status::Running);
    
    let effect = store.get_effect(id);
    let result = match effect {
        Effect::ShellExec(params) => execute_shell(params).await,
        Effect::RefactorTransform(params) => apply_refactor(params).await,
        Effect::FsWrite(params) => atomic_write(params).await,
        // ...
    };
    
    store.complete_effect(id, result);
    
    // Trigger downstream effects
    if result.is_ok() {
        notify_dependents(id);
    }
}

// 4. ROLLBACK (on failure or explicit request)
fn rollback_effect(id: &EffectId) -> EffectId {
    let original = store.get_effect(id);
    let rollback = create_rollback_effect(&original);
    let rollback_id = produce_effect(rollback);
    
    store.update_status(id, Status::RolledBack);
    rollback_id
}
```

### Refactor Effects (The "Super" in Super Refactor)

```rust
pub enum TransformTemplate {
    // Pattern-based (ast-grep style)
    AstReplace {
        language: String,
        pattern: String,
        replacement: String,
    },
    
    // Structured (rust-analyzer style)
    Structured {
        kind: RefactorKind,  // rename, extract, inline, move
        params: serde_json::Value,
    },
    
    // Custom sprf template
    Template {
        source: String,  // with $CAPTURES
    },
}

pub enum SafetyLevel {
    Pure,        // Reordering imports
    Reversible,  // Rename (can undo perfectly)
    Destructive, // May lose info (inline with comments)
}
```

Example refactor rule:

```sprf
rule(deprecated_foo_usage) {
  fs(**/*.rs) > ast[rust](
    CallExpression { function: "deprecated_foo", arguments: $ARGS }
  )
};

refactor(migrate_to_foo_v2) {
  source: deprecated_foo_usage
  description: "Replace deprecated_foo with foo_v2"
  template: ast_replace[rust] {
    pattern: "deprecated_foo($$$ARGS)"
    replacement: "foo_v2($$$ARGS, { legacy: true })"
  }
  safety: reversible
  auto_apply: false
};
```

Produces effect:


### CLI for Effect Management

```bash
# List all pending effects
sprefa effects --pending

# List pending shell cuts
sprefa cuts                    # short for: effects --type shell_exec --pending

# Approve effects
sprefa approve <effect-id>
sprefa approve --pattern "npm view *"      # approve all matching
sprefa approve --all-safe                  # approve all reversible/safe

# Preview refactor
sprefa refactor --preview migrate_to_foo_v2

# Apply effects
sprefa apply <effect-id>
sprefa apply --all-safe                    # apply all safety: pure/reversible

# Daemon mode (auto-apply safe, queue destructive)
sprefa daemon --auto-apply-safe --notify-on-destructive

# Rollback
sprefa rollback <effect-id>

# Replay from journal (time travel)
sprefa replay --from 2026-04-12T10:00:00 --to 2026-04-12T11:00:00

# Debug: why was this effect produced?
sprefa debug --effect <id>     # shows rule, inputs, cursor state
```

### Store Trait Extension

```rust
pub trait EffectStore: Store {
    fn insert_effect(&self, record: EffectRecord) -> Result<EffectId>;
    fn get_effect(&self, id: &EffectId) -> Result<Effect>;
    fn update_status(&self, id: &EffectId, status: Status) -> Result<()>;
    fn complete_effect(&self, id: &EffectId, result: EffectResult) -> Result<()>;
    
    // Query methods
    fn list_pending(&self, phase: Option<Phase>) -> Result<Vec<EffectRecord>>;
    fn list_by_rule(&self, rule_name: &str) -> Result<Vec<EffectRecord>>;
    fn list_by_file(&self, path: &Path) -> Result<Vec<EffectRecord>>;
    fn get_pending_cuts(&self) -> Result<Vec<EffectRecord>>;
    
    // Dependency tracking
    fn get_dependents(&self, id: &EffectId) -> Result<Vec<EffectId>>;
    fn are_dependencies_met(&self, id: &EffectId) -> Result<bool>;
}
```

## Key Insights
1. **Effects are data, not actions**: Everything produces JSON-serializable descriptors
2. **Durability by default**: Effects go to DB immediately, survive crashes
3. **Four phases**: Extract (pure) → Shell (gated) → Check (pure) → Refactor (approved)
4. **Super refactor**: Refactoring is just another effect type with safety levels
5. **Live circuit**: Daemon keeps effects flowing, applies safe ones, queues risky ones
6. **Time travel**: Full effect journal enables replay, rollback, audit
7. **Circuit breakers**: Global safety limits prevent runaway refactors
