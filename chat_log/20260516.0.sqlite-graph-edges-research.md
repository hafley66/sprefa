## Problem/Context
Sprefa already runs graph-shaped state through SQLite:
- Durable queue: self-referential parent_id tree, recursive-CTE subtree delete already correct (sqlite_queue.rs:794), orphan-safe seed.
- Fact store: wide-row runtime_node / runtime_edge / runtime_dirty, content _id, FK into sprf_strings.
- In-mem mirror: RuntimeEdge{from_id,to_id,label_id,generation}, RUNTIME_DIRTY worklist.
- PRAGMA profiles Safe/Bench/UnsafeBench at fact_store.rs:521.
Every hot edge query filters by edge_kind_id FIRST (incoming_edges, supported_rows_for_owner, edges_where), so kind is dead weight as a leading index column.

## Solution/Approach
Keep single runtime_edge table. Use partial indexes per edge kind to keep each kind's index narrow without physical partitioning, without dynamic DDL, without UNION-of-tables in recursive CTEs:
  CREATE INDEX edge_sub_to   ON runtime_edge(to_uri_id)             WHERE edge_kind_id = <subscribe>;
  CREATE INDEX edge_sup_from ON runtime_edge(from_uri_id, label_id) WHERE edge_kind_id = <support>;
  CREATE INDEX dirty_cover   ON runtime_dirty(owner_uri_id, source_uri_id, generation);
Physical partition (dynamic tables like rule-output in run.rs:811-930) was analyzed and rejected: only wins for O(1) epoch DROP GC, costs cross-kind reachability (Card E path-invalidation) becoming UNION-of-N-tables in the recursive CTE arm.

## Key Insights
- Sprefa queue cascade is correct as-is (recursive CTE pattern B, no FK dependency). Do NOT add ON DELETE CASCADE there.
- SQLite has NO CYCLE clause (Postgres 14+/Oracle only). Cycle-safety = UNION set semantics or UNION ALL + delimiter-wrapped path NOT LIKE guard.
- Self-ref FK ON DELETE CASCADE: needs per-connection PRAGMA foreign_keys=ON (rusqlite queue path does NOT set it; sqlx paths do) AND an index on the child FK column (SQLite auto-indexes parent key, not child -- #1 cascade perf cliff).
- closure.c / transitive_closure vtab = zero-schema-change C-speed walk over adjacency edges, candidate for deferred Card E.
- Partial indexes = logical partition of index space without physical sprawl; SQLite auto-selects when constant predicate matches the index WHERE.
- Recursive CTE has no stats; planner can't estimate fan-out; keep recursive join trivially indexable. RETURNING does not surface cascade-deleted rows.
