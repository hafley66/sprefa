## Solution/Approach
Design rulings this session (all written into the plan file):
- sh family = read/mutate/stream axis: `sh`=Read (cached/deduped/at-least-once/retry),
  `sh!`=Mutate (idem-key + 2-phase claim, exactly-once), `sh*`=Stream.
- json/jsonp: NOT jsonpath-as-standard, NOT inline jq (D-7). Engine json/jsonp are
  tree-sitter-walked => SPAN-LOCATED (join ref spine, rewritable). Split by SOURCE:
  files (located, keep dotted `a.b.*`) vs response bodies (push extraction to shell-side
  `gh -q`/`jq`/`aws --query`, emit @tsv). A row = a stdout line => array fan-out == stream.
- Widening (Phase 1b): json/jsonp source becomes a Term (not just file+rev); `collect(var)`
  aggregate effect = provider-native batch-by-id (github nodes(ids:[]), aws --instance-ids,
  gcp --filter, git cat-file --batch). One round trip / one rate-limit hit / one process.
- Router STRUCK; native http (Phase 5) demoted to optional delegate-wrapper (HttpThenShell)
  because bulk graphql deletes the connection-reuse argument. Curl/gh cover etag/304 via the
  @next carry (cache on the tx spine, NOT curl --etag-save sidecar files).
- Streaming (Phase 4): three temporal forms = every(N) clock / @async req-resp / @stream
  subscription. Two flavors: polled (every+@async+`changed<-prev x now`) vs native (sh* over
  tail -f/--watch/--paginate). reader-thread + @next cursor. `? rel --follow` = output tail.
- GENERALITY: provider knowledge lives ONLY in the sh template string. git/jfrog/aws/gcp are
  template strings, zero Rust each. Not GitHub-specific.

The change_log punchline: it's DERIVED, not written:
  changed(repo, was, now, at) <- star_prev(repo,was), star_count(repo,now), was!=now, now_ms(at).
