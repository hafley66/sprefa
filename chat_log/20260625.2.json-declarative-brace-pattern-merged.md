## Key Insights
- **Binding model:** `lower.rs::body_sql` (line 66) only handles Pos/Neg/Cmp;
  source ops run in `engine.rs::parse_file` binds-expansion. Head vars resolve
  from the bind map (engine.rs ~4750; ~4751 "head var unbound" is the de-facto
  capture/head-mismatch error). So the json arm just inserts each capture under
  its name; no lower.rs change.
- **Scheme carrier:** `lex.rs:210` requires the scheme word be in `desc::is_scheme`.
  `lex_scheme_body` bare form tracks `()[]{}` balanced — so `q:{ $k: $v }` (incl.
  nested) lexes as ONE Tok::Scheme. `parse.rs:758` lifts Tok::Scheme→Term::PathLit.
- **scan + WORK:** scan ALREADY defaults rev to WORK in 3-ary `scan(glob,path,rev_out)`
  (parse.rs:335-337). WORK is a magic string `"WORK"` in ~30 engine sites, not an
  enum. Downstream ops take rev as the var scan binds (named once).
- **Key matching:** bare reads to first `:` (trimmed); quoted `"..."` for keys with
  `:` or to force literal. Classified: `$SCREAMING`→Capture, glob chars→Glob, else
  Exact. Literal `$ref` MUST be quoted. No `\"` escape yet.
- **Conjunctive limit:** multi-entry requires ALL keys Exact AND ALL values be
  `Leaf{capture:Some}` (shallow). Nested/capture in multi-entry → no match (T1/T3).
- **Dogfood scope:** gen-doc-index.dl splices v5's `//!` first lines + md titles
  into its own file (converges on rerun); auto-doc.dl writes a reference from
  type_entity; gen-type-table.dl splices a fanout census. All MANUAL (`dl examples/
  ...`), NOT daemon-driven. The README op table is hand-maintained (no gen rule → T20).
  gen-doc-index reads only `//!` line 1, so a stale summary updates only when line
  1 changes (T21).
- Pre-commit hook warns on unwrap-budget (non-blocking).
