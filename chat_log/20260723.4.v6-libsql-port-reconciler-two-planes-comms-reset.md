## Key Insights
- TWO PLANES in engine.ts: cx_* (cascade/aliveness: cx_row(key,weight)+cx_dep; assert=forward weight=1 propagate, retract=counting weight-decrement acyclic, retract_dred/_scc/_cte=cycle-safe DRED over-delete-cone+rederive) vs rx_* (reconcile/memo: rx_memo(id,digest,changed_at,verified_at)+rx_dep(reader,read); salsa red-green). They are INDEPENDENT; retraction != invalidation.
- MEMORY: all working sets (frontier/next/cone/alive/hits) are TEMP tables under temp_store=MEMORY (engine.ts:114), moved by INSERT...SELECT/UPDATE inside SQLite. Rows NEVER enter JS heap. retract_dred_cte runs entirely in SQLite C (2 recursive CTEs, one batch, zero round-trips). Host heap only holds: seed keys (IN-clause literals, O(#changed)), one scalar count/round (O(1)), propagate's dirty_set:Set<number> (O(#dirty rel IDs, not rows)), per-node dep_digests:bigint[] (O(fan-in)). Host = O(dirty IDs + changed seeds), independent of fact count.
- reconcile order: mark_changed(bump changed_at) -> dirty()(one-hop frontier: readers where read.changed_at>reader.verified_at) -> propagate(ascending-id topo sweep: pop min, fetch dep digests, recompute, verify). verify EARLY CUTOFF: if digest unchanged, changed_at not bumped, readers not enqueued, sweep halts.
- retract_dred_cte (:436) is the opt over retract_dred (:363): round-loop -> 2 set-at-once CTEs.
- libsql intMode is CLIENT-GLOBAL (vs better-sqlite3 per-statement safeIntegers); port set intMode:"bigint" globally + Number() at 32 number-use sites; digest paths never coerced (golden byte-parity is the gate).
- libsql local transaction() hands the connection to the txn object and opens a NEW connection for the next plain call -> wipes :memory:/TEMP state. Forced the 5-site txn drop.
