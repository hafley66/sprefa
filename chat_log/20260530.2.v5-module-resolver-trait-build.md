## Architecture (as built)
- Resolution math in Rust (trait), so `.dl` never needs an expression layer.
- 3 reserved built-in relations: `module_import(file,rev,specifier,kind,line)`,
  `module_edge(src,dst)` [the 2-col closure edge], `module_unresolved(file,specifier,reason)`.
- Declared every tick; populated by `refresh_module_rels` ONLY when `module_rels_used(prog)`
  (resolution parses every file → lazy). Runs per-rev over the `_file` set after
  `refresh_builtin_rels`. In `tick_paths`, module rels join `changed_source_rels` so
  incremental ticks re-derive + re-close.
- `RustResolver`: `mod foo;` → FS-convention child file; `use crate/self/super::..` →
  resolve_to_absolute + longest module-path prefix that is a file. Ports file_to_mod_path +
  resolve_to_absolute from v1/v2 watch::rs_path.
- `TsResolver`: regex specifiers → oxc_resolver.resolve(dir, spec) → strip root → File|External.
- `reaches(a,b) <- closure(module_edge)` spans rs+ts union in one relation.

file's own `"use crate::..."` test-string literals = the documented regex-in-strings corner.

## Diet corners (documented in the plan, by design)
- regex extraction matches use/mod inside comments AND string literals (false positives).
- use-edge resolves to the parent-module file, not the exact item (symbol-level = SCIP's 10%).
- `#[path]` overrides not honored (rare).
- re-reads each file's content every refresh (reconcile already hashed it).
- cross-rev: edges resolved within one rev; module_edge merges path pairs across revs.

## Key Insights
- The trait dissolved the expression-layer crux: Term has no Call (ast.rs:61); putting
  resolution in Rust means Path::parent for free, .dl never needs dir()/join().
- `_file` is only populated by source-rule scans, so a module-graph program MUST include a
  scan to seed the file set (the established built-in-file pattern). The resolver reads
  content for files in `_file`.
- module_edge being a 2-col built-in lets the EXISTING closure machinery (declare_closure /
  rebuild_closures reading self.rels.get(edge)) work with zero new code.
- oxc_resolver 11.20 API: tsconfig is `Option<TsconfigDiscovery>`, Manual(TsconfigOptions{..}).
  Static regex cells must be std::sync::OnceLock (Sync), not std::cell::OnceCell.
