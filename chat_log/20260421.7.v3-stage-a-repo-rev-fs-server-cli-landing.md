## Solution / Approach

### Cursor fields as state, not captures

Repo/rev/fs carried as first-class Cursor fields mirrors v2
(`v2/src/_0_types.rs:267`). `&.repo` / `&.rev` / `&.fs` already parse
in the host grammar; projection semantics pending but the data
channel is in place.

### CaptureKind split for external-state bindings

`repo($R)` binds a cursor field (repo slug) that has no span inside
`cursor.content`. Representing that as `CaptureKind::Synthesized`
(with bytes inline on the capture) keeps Pattern::apply's binding
resolution uniform: `collect_bindings` always calls
`Capture::bytes(content)`, which dispatches on kind. Span-backed
captures read from content; synthesized captures read their own
inline value. `materialize_for` + read-mode regex stays working
regardless of which producer op wrote the upstream binding.

### FileSource trait over effect routing (for now)

The v3 posture says reads are effects. Wiring a full
`FsListFilesEffect` EffectKind + Batcher registration was out of
scope for Stage A. FsOp takes `Arc<dyn FileSource>` directly on the
op instance, matching v2's `Reader.files` mental model. Effect
routing is a later fold (tag: project_v3_effect_runtime_split
already in memory).

### Inline lowerer in CLI, no registry yet

`sprefa-run::lower_op` is a string-match on `inv.name` returning
`Box<dyn Op>`. Four ops today: repo, rev, fs, void. No `OperatorRegistry`,
no `ProgramCtx`, no lowering diag surface beyond `PatternDiagnostic`.
This is the thing to generalize once scan-loop/DAG land.

### Shell smoke over rust integration

`tests/smoke/_1_run.sh` matches v2's pattern. Drives the real binary,
asserts stdout shape with grep. Rust integration tests would duplicate
the CLI glue; shell gives one source of truth.

### Next session (ranked)

#### 1. Lift v2's init_cursors (high priority)

`v3/crates/sprefa/src/init_cursors.rs` (v2 carryover) builds the seed
cursor set from `Config.repos` × `Config.revs` × `Config.sprf_files`.
Port shape to v3: take a `Vec<(repo, rev)>` pairs list + an
`Arc<dyn FileSource>`, emit `Vec<Cursor>` with repo/rev set. sprefa-run
currently hardcodes one seed (basename(root), HEAD); a real init
supports multi-repo.

#### 2. Operator registry + lowerer

Replace `sprefa-run::lower_op` string-match with a v3
`OperatorRegistry`. Study v2's `_10_registry.rs` shape but target
v3's `Op` trait (no `Operator` factory split, no `witness`, no
`hover_self`). Minimum: `HashMap<Arc<str>, fn(&OpInvocation, &str,
&ProgramCtx) -> Result<Box<dyn Op>, Vec<PatternDiagnostic>>>`. Same
lowerer fn then feeds both the CLI and the LSP DocSession.

#### 3. Rule syntax — rule(name) { pipe; pipe; }

v2 examples (`g1_fns.sprf`, etc.) gate on `rule(pub_fn) { ... }`.
Host grammar already parses the brace slot. Lowering: emit each pipe
inside the brace as an independent pipe under a name. Printer gains
`rule <name> — N rows` header so smoke scripts can pin on it
(v2-compatible). sprefa-run currently prints `pipe 0 — N rows`; rule
name is only in ast node, not threaded through.

#### 4. Glob `**` semantics fix

Current grammar treats `**` as a segment between explicit slashes.
`src/**/*.rs` therefore misses `src/foo.rs` (only one separator). v2
using globset has the ripgrep-style `**` = "zero or more segments
including adjacent separators" behavior. Two fixes:
(a) grammar change: `**/` and `/**` lower to optional separators;
(b) segment lowering: `**` lowered to `(?:[^/]+/)*[^/]*` instead of
`.*`. Option (b) is cheaper — no grammar regen.

#### 5. scan_loop + DAG port

`v3/crates/sprefa/src/scan_loop.rs`, `dag.rs`, `scan_check.rs` are
the fan-out control plane from v2. Port file-by-file against v3
shapes. The `check_scan_pointers` body has to be rewritten against
v3's `Capture` model (SpanBacked vs Synthesized) because v2's Tri +
CaptureKind + ScanPointer triple do not exist here.

#### 6. FsListFilesEffect batcher

Wire FsOp through an EffectKind + Batcher as the v3 doctrine
demands. Back the batcher with a `Box<dyn FileSource>` handle. Cache
per-(repo, rev) listings so multiple fs call-sites in the same run
amortize the walk.

#### 7. Arg-spec on Op trait

Land `fn arg_spec(&self) -> &[ArgSpec] { &[] }` on the Op trait. Let
the lowerer consult it per slot, produce typed `Value`s. This is the
bridge to true `fs(re(...))` bulk dispatch (via
`Pattern::as_raw_regex`).

#### 8. LSP hover

DocSession grows past the parse layer. Dispatch by node kind at hover
position: `op_invocation` → op's registry-supplied hover;
`term_ref` → binding graph; `carveout_expr` → recurse. Needs
`ParseSite` / result store plumbing.

#### 9. Config + TOML resolution

v2 had `.sprefa.toml` with repos + revs. Port once rule syntax
lands so examples can declare their workspace without relying on
`sprefa-run --root`.

#### 10. HTTP / WebSocket transport

v2 `server/_5_transport_http.rs` + `_4_transport_lsp.rs` duplex
bridging. Deferred until stdio LSP proves stable in VS Code.

## Key Insights

1. **Cursor fields beat captures for external state.** repo/rev/fs are
   carrier state: they identify where a cursor is scoped, not what it
   matched. Capture machinery expects content spans. Trying to squeeze
   repo slug into a SpanBacked Capture forces a synthetic content
   rewrite (ruins downstream ops that read bytes). Fields + a tiny
   CaptureKind::Synthesized escape hatch is the minimum shape.

2. **The v2 carryover sprefa crate will not unexclude as a unit.**
   Its public API leaks v2 parse/op types that no longer exist. Treat
   it as reference material. Every file ports as a rewrite, not a
   copy. File-by-file is fine; crate-as-a-whole is not.

3. **Inline lowerer is the right Stage-A shape.** Deferring
   OperatorRegistry until scan_loop / DAG land kept the CLI under
   200 LoC. The registry fold will happen once there are more than
   four callers (LSP, CLI, rule-body, test harness).

4. **Shell smoke > rust integration for CLI-shaped tests.** One
   source of truth. v2 did this for `_1_run.sh` through `_4`; v3
   should keep the pattern as each new capability lands.

5. **Pattern::apply's read mode works across capture kinds for free.**
   The `Capture::bytes` indirection means a pattern can see a
   synthesized-bound term (repo/rev) and a span-bound term (regex
   named group) in the same cursor without the pattern op caring
   which is which. Confirmed by all 121 tests green.

6. **Glob `**` semantics need work.** Current grammar-segment-based
   lowering misses single-level matches. Low-cost fix in the op's
   segment lowerer (`**` → `(?:[^/]+/)*[^/]*`). Not blocking smoke
   because the smoke fixture avoids the `**/ + segment` pattern.

7. **FsOp taking Arc<dyn FileSource> directly is sufficient for
   Stage A.** Effect routing is philosophically correct for v3 but
   adds zero capability for the smoke surface. Park it until
   there's a caching or reactive use-case that actually benefits.

## Open Questions

1. Should RepoOp bind mode write SpanBacked over cursor.content =
   repo bytes (rebase-shaped) or Synthesized (current)? Synthesized
   wins today because downstream ops expect cursor.content to
   survive unchanged. Revisit once `&.repo` rebase semantics land.

2. Should the inline lowerer in sprefa-run live in `pipeline` or
   `server`? Moving to pipeline makes it callable from DocSession
   too. Leaving in server keeps pipeline free of sprefa_parse
   reverse-dep. Tie goes to pipeline because the registry is the
   obvious home for an op catalog.

3. Does rule body syntax need two levels (outer rule name + inner
   pipes) or can each pipe inside a rule collapse to a flat
   `Pipe::name = Some(rule_name)`? v2 treated rules as containers
   with an evidence table; v3 may be able to flatten.

4. Is `.git`/`target`/`node_modules` hardcoding in DiskFileSource
   acceptable, or should it read `.gitignore`? gitignore port is
   a fold once the `ignore` crate enters the deps.

5. Should the smoke script fail loud on unknown-op-skip warnings?
   Current shape silently ignores skipped ops. Useful during
   bring-up; drop to strict once rule+ast are in.
