## Problem/Context

User asked whether the typed-Yield<S> backbone gives us
rule(:a, ${X?}, ${Y?}) and SQLite-at-end. LLM initially over-engineered
with OpEvent::RuleExit + invocation_id frames. User course-corrected
several times:
1. Rule body terminal cursors ARE the exits — no special hook
2. Brace presence (not bound/unbound) discriminates definition vs query
3. Rule-as-relation (table) is the model; rules backed by SQLite
   for cross-run memoization via cursor content-hashing
4. Tag and rule should share storage but stay distinct ops
5. Final lock: `?` op suffix as push/pull inversion sigil

The conflict cell was `tag(:r, $X, $Y)` (all-bound, no body, pipe):
write OR predicate? Resolved by introducing `?` suffix that inverts
push (raw) → pull (`?`).

## Solution/Approach

### Locked dispatch table

**Tag (BehaviorSubject of rxjs — hot, replay):**
| Spelling | Semantic |
|---|---|
| `tag(:r, $X, $Y)` (all bound, raw) | WRITE row |
| `tag?(:r, $X, $Y)` (all bound, ?) | PREDICATE strict |
| `tag?(:r, $X, ${Y?})` (mixed, ?) | DATALOG JOIN — filter+project |
| `tag?(:r, ${X?}, ${Y?})` (all unbound, ?) | QUERY drain |

**Rule (Observable of rxjs — cold, lazy):**
| Spelling | Semantic |
|---|---|
| `rule(:foo, ${X?}, ${Y?}) { body }` (top-level, body) | DEFINE |
| `foo($X, $Y)` (pipe, all bound) | CALL — body runs, exits stream |
| `foo?(...)` | PREDICATE/JOIN/QUERY over exit bag |

Tag has no rule-body slot. Rule definitions use `rule` keyword;
calls use bare name. `?` suffix inverts push→pull on both. Mixed
allowed only on pull side; raw push side requires all-bound.

User decisions locked this session:
1. No nullary tag (kill cell 7); nullary rule call OK as `foo()`.
2. `?` strictly inverts next vs query.
3. Code-share between tag and rule: whoever lands first.
4. All rules lazy by default (cold Observable).
5. Recursion: don't disallow in impl, don't test/optimize yet.
6. No shadowing: rule name colliding with stdlib op = lower error.
7. Forward refs: two-pass lower (collect names, then resolve calls).

### Architecture (unified storage, divergent push)

```
RelationStore  (rename TagStore)
  bags:   HashMap<Name, Bag>
  bodies: HashMap<Name, Arc<Pipeline>>   # None entry = plain tag bag

Bag
  rows:    Vec<Row>
  waiters: HashMap<Key, Vec<SubjectKey<RelationWake>>>   # KEYED (was Vec)

RelationWake : SubjectKind { type Payload = Row; }       # was TagWake

WriteEffect / WriteBatcher                                # was Tag-prefixed
```

Pull-side ops (shared by tag? and <ruleName>?):
- ProbeOp { name, key_args, mode: Static | Reactive }
- JoinOp  { name, bound_args, project_holes }
- QueryOp { name, holes }

Push-side ops (divergent):
- WriteOp { name, row_args }                — tag-only
- DefineOp { name, body }                    — rule-only, top-level
- CallOp { name, arg_terms }                 — rule-only, pipe; runs body, terminal cursors auto-write to bag (reuses WriteEffect path)

## Key Insights

1. **`?` op suffix as push/pull inversion is the keystone.** Without
   it, the cell-8 conflict (all-bound no-body pipe = write or predicate)
   has no clean answer. With it, raw = push side, ? = pull side, and
   the classification (bound/mixed/unbound) only matters for ?-forms.
   The `?` inside `${X?}` (term mode) and the trailing `?` on op name
   are different syntactic positions; no parser conflict.

2. **Tag = BehaviorSubject (hot/replay), Rule = Observable (cold/lazy).**
   The rxjs framing snaps the model into place. Tag is manually
   nexted; rule is a closure that runs lazily per call. Both back
   into the same materialized row store on the pull side.

3. **Brace presence (not bound/unbound) discriminates def vs call.**
   Rule definition is top-level + body block + all-unbound carveouts
   declaring params. Definition without body, or body without
   top-level, are both errors.

4. **Body terminal cursors ARE the exits — no OpEvent::RuleExit hook
   needed.** The lower path wraps rule body's tail in a sink that
   pushes terminal cursors as rows into the rule's bag. Same
   WriteEffect path tag-write uses. Auto-fires keyed wakes.

5. **Two-pass lower handles forward refs trivially.** Pass 1 collects
   all rule definitions and registers names. Pass 2 lowers pipe
   bodies, resolving bare-name calls against the registered set. No
   binding-graph topology gymnastics needed.

6. **Code share: storage + pull-side identical; only push diverges.**
   ProbeOp/JoinOp/QueryOp/WriteOp are name-parametric and used by
   both tag and rule surfaces. Only CallOp is rule-specific (look
   up body, run it, sink exits). About 80% of the runtime code is
   shared.

7. **Cardinality explosion is the load-bearing open question.**
   QueryOp fans out per row; downstream pipes get N×M cartesian
   work. Same for JoinOp on multi-row matches. Levers (bounded
   flat_map, aggregate sink, terminal-only restriction, bound prefix)
   all enumerated; none picked. Backburner until perf rerun forces it.

## Open Questions

1. **Cardinality explosion**: which lever for query/join fan-out? User
   said "yes idk how to solve that yet". Defer until concrete usage.

2. **Column identity for keyed wakes**: when ProbeOp registers a
   waiter under (X, Y), what makes the key? Full row identity? A
   declared key prefix? Inferred from probe shape? Defer to bd5/kcl.

3. **Recursion semantics**: not disallowed in impl. Cycles in the
   call graph compile fine but runtime needs Reactive probe /
   pending-join to not deadlock. No tests/optimization yet.

4. **Cursor content-hash for SQLite memoization**: stable hash over
   (sprf_path, captures, repo, rev, byte_range, content fingerprint).
   Defer to a later card; this session ended before it got concrete.

5. **LSP hover for parametric rules**: surface mapped (def site, call
   site, param site each have different surfaces). Mechanism is
   binding-graph extension + telemetry queries. Card 1uf (P2) tracks
   it. User flagged it as a worry but agreed mechanism is sound.

6. **Mixed-mode datalog join semantics in detail**: e.g. JoinOp's
   exact projection rule when multiple rows match. Fan out per row
   is the default; aggregation alternatives backburned.
