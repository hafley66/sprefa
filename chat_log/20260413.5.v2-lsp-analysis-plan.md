# Plan: v2 LSP via 4-layer split

## Context

LSP must handle unsaved buffers. Prior sessions nearly drifted into a sqlite-store-is-the-interface design that collapsed existing specs. Correct layering (per `project_v2_wt_overlay` + `project_v2_effects_split`):

- Reader stack has 3 layers bottom-up: `GitBlobReader` → `WorkTreeOverlay` → `BufferOverlay`.
- Reads are pipe ops. Writes are deferred effects flushed after pipeline drains.
- **Dry-run = skip flush phase.** This is how LSP runs pipelines read-only.

Sqlite store is orthogonal — persistence for CLI cross-session / cross-process visibility. Not a hover prerequisite.

## Four Layers

### Layer 1 — Op Trait (static + per-op)

Pure functions. No LSP crates. Unit-testable with fake Row inputs.

```rust
trait Operator {          // factory side
    fn completion_item(&self) -> CompletionItem;
}
trait Op {                // per-pipeline-instance side
    fn hover_self(&self) -> Markdown;
    fn hover_capture(&self, cap: &str, rows: &[Row]) -> Markdown;
    fn hover_match(&self, span: SpanId, matches: &[Match]) -> Option<Markdown>;
}
```

Render contracts:
- `repo` capture: slug list.
- `rev` capture: rev name list.
- `fs` capture: per-path, markdown link `[path](file://...)` if exists on disk.
- `json` capture: jq path + scalar preview.
- Non-captured match on same ops: same renderer, no var name header.
- Cross-ref `${rule.$VAR}`: parser produces `SpanKind::CrossRef(rule, var)`, analysis layer resolves target op, delegates to `hover_capture`.

Lives: `v2/src/ops/*.rs`.

### Layer 2 — Framework Core (pipeline + reader + parse)

Existing module, two additions:

1. `BufferOverlay` Reader layer (3rd in stack).
2. `Pipeline::run(flush: bool) → RunReport`. `flush=false` = dry-run for LSP.

`RunReport`:

```rust
struct RunReport {
    rows:    HashMap<RuleName, Vec<Row>>,
    matches: HashMap<OpId, Vec<Match>>,
    diags:   Vec<Box<dyn Diagnostic>>,
    span_ix: HashMap<SourceSpan, (OpId, SpanKind)>,
}
```

Row carries `origin_span` per cell.

Lives: `v2/src/`.

### Layer 3 — Analysis (new, thin, non-LSP)

Interactive-consumer state. Zero LSP crates. Testable in plain `cargo test`.

```rust
struct DocSession {
    parse_tree: Ast,
    span_ix:    SpanIndex,
    buffer:     BufferHandle,    // writes into Reader layer 3
    last_report: Option<RunReport>,
}
impl DocSession {
    fn on_text_change(&mut self, new_bytes: Bytes);
    fn ensure_run(&mut self);                      // if stale, pipeline.run(flush=false)
    fn hover_at(&mut self, pos: BytePos) -> Option<Markdown>;
    fn completions_at(&self, pos: BytePos) -> Vec<CompletionItem>;
    fn diagnostics(&self) -> &[Box<dyn Diagnostic>];
}
```

Lives: `v2/src/analysis.rs` (new).

### Layer 4 — LSP Bin (wire + lifecycle only)

```
v2/src/bin/sprefa_v2_lsp.rs
  tower-lsp dispatcher
  HashMap<Url, DocSession>
  did_open/change/save  → DocSession.on_text_change + ensure_run
  hover(params)         → utf16→byte, DocSession.hover_at, wrap MarkupContent
  completion(params)    → DocSession.completions_at, wrap proto
  publishDiagnostics    → DocSession.diagnostics, wrap proto
  position translation  (utf16 code units ↔ bytes)
  URI ↔ repo/path       (via CheckoutLocator)
```

## Line Test (which layer each duty belongs to)

| Duty                              | Exists w/o LSP? | Layer |
|----------------------------------|-----------------|-------|
| running pipeline                 | yes, CLI        | core  |
| rendering capture values         | yes, future CLI explain | op trait |
| cached run result                | only interactive consumers | analysis |
| tracking open documents          | only interactive consumers | analysis |
| cursor byte-range lookup         | only interactive consumers | analysis |
| utf16 ↔ byte position math       | NO, LSP quirk   | LSP bin |
| publishDiagnostics JSON-RPC      | NO, LSP proto   | LSP bin |

Smell: hover logic inside `impl LanguageServer` = drift up. utf16 math inside `DocSession` = drift down.

## Implementation Order

1. **Op trait additions + per-op render** (Layer 1). All 6 ops get `hover_self`, `hover_capture`, `hover_match`, `completion_item`. Tests: unit tests per op w/ fake Row inputs.
2. **BufferOverlay + flush flag** (Layer 2). New Reader layer; Pipeline::run gains `flush: bool`. Tests: read through buffer wins over WT wins over blob; pipeline with flush=false produces no side effects.
3. **RunReport span_ix build-out** (Layer 2). Rows/matches emit w/ origin_span; framework accumulates span_ix during run. Tests: run a json pipeline, assert span→(OpId, SpanKind) mapping.
4. **DocSession** (Layer 3). Tests: load .sprf + doc content, hover_at returns expected markdown for capture/cross-ref/op-name positions.
5. **LSP bin** (Layer 4). Tests: smoke test via tower-lsp client harness OR manual `npx @vscode/test-cli` verification.

Parallelization: steps 1 and 2 are disjoint → two sonnet agents simultaneously. Step 3 blocks on 2. Step 4 blocks on 1+3. Step 5 blocks on 4.

## Non-goals this arc

- sqlite store (separate track, unblocks cross-process but not hover).
- line() / marker() / ast-grep ops (ops freeze per prior directive).
- Effect-queue write path (needed for `$wt` writes, not for LSP read).
- CheckoutLocator daemon variant.
