## Problem/Context
User screenshot showed v3/crates/server/fixtures/ littered with smoke-test sqlite artifacts (ast_grep_smoke.db, comment_smoke.db, etc.). Source: sprefa-run.rs:185 and :295 unconditionally fell back to default_out_db(file) when cfg.run.out_db was None, co-locating the .db with each fixture .sprf.

User then asked: "change cursors after this op hover in lsp, to be not a list of lists, but a list of tables, hard to read for my monkey brain" — render_cursor_block emitted a 2-col table per cursor; user wanted ONE wide table per capture-signature group.

## Solution/Approach
sprefa-run.rs:
- main() resolves out_db: explicit --out wins; else allocate $TMPDIR/sprefa_run_<pid>_<nonce>.db and stash that path in auto_out_db.
- After rt.block_on returns, if auto_out_db is Some, call rm_db_triplet(p) to remove .db + .db-shm + .db-wal.
- L2 disk-cache attach (line 184) + SQL drain (line 295) restored to unconditional — out_db is always Some now.
- default_out_db helper deleted (dead).
- process::exit failure paths skip cleanup (process::exit doesn't run destructors), but those .dbs land in $TMPDIR which the OS reaps. Acceptable per original complaint scope.

tests/smoke/_b_rule_arity.sh: changed to pass --out via mktemp + trap cleanup. The smoke needs to sqlite3-query the .db so it must own a known path. Other smokes get the auto-tmp behavior implicitly.

backend.rs render_cursor_block → render_cursor_tables(cursors, start_index, root, focus_capture):
- Group cursors by capture-name signature, preserving first-seen order.
- For each group: emit one markdown table; columns = `# | file | bytes | match | $cap... | last_bound`; rows = individual cursors.
- Focused capture column header bolded with ▶ marker.
- Multiple groups get a `_Group N of M (rows; captures: ...)_` divider.
- Drops _SprfPath_ from hover output (kept tables narrow; can re-add as a footer if needed).
- Test call sites updated; assertions loosened to the new wide-table shape (column headers vs per-row labels).
- Snapshot tests still pass — they covered the zero-cursor "_(no cursors emitted)_" case, didn't hit the new render path.

## Key Insights
- Process::exit terminates without unwinding — Drop guards do not run. For mid-execution cleanup, refactor to Result-bubbling. For end-of-run cleanup, rt.block_on return + explicit call works.
- $TMPDIR on macOS is reaped by launchd/tmpcleaner periodically. Leaving rare-failure .dbs there is preferable to polluting the project tree.
- Snapshot tests that hit only the metadata header (op doc, pipe position, body grammar, config table) won't catch render-body changes downstream of "_(no cursors emitted)_". Adding a populated-cursor snapshot test would lock the wide-table format.
- Grouping by capture-signature gives stable column counts per table without one-cursor-per-table noise. Cursors with the same capture set group cleanly; pipelines with diverging captures get N small tables, not one ragged super-table.
