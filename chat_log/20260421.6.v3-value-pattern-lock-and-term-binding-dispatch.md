## Problem / Context

Phase 1 (prior session) landed ops-own-grammars with `CompiledPattern { Arc<dyn Any> }` + `.downcast::<CompiledGlob>()` at every consumer. User explicitly dislikes Rust runtime downcasting as an inspection mechanism. The tension surfaced when discussing how `fs(re(...))` should let `fs` yank the raw `Regex` for bulk ripgrep dispatch — `dyn Any` works but feels wrong. User pushed through multiple framings (pure Pipeline, pattern-as-value, op-as-arg) until we landed on: Value category with Pattern as a variant, ArgSpec on Op slots, closed enum match at lower time.

A secondary tension: `pattern_pipe` semantics. My initial framing split glob (anchored filter) vs re (find-all scan) as per-op A/B. User corrected: glob lowers to anchored regex at compile time; both glob and re then use the same `find_iter`-style body. Arity is fixed by the compiled regex source, not by the op. This collapsed into `Pattern::apply` as one uniform body.

A third tension: `$NAME` inside a pattern body is dual. User raised "patterns having terms" — holes are inputs or outputs depending on upstream binding state. This forced the template + cached-regex + materialize_for shape. Write mode when unbound; read mode (substitute upstream-bound bytes as regex-escaped literal) when already bound.

A fourth drift: I kept writing `fs(:repo=$R, **/*.rs)` as if kwargs existed. They don't. User redirected: repo/rev are first-class Cursor FIELDS (v2 shape — `_0_types.rs:267`). Nothing goes in the paren except the pattern. repo/rev/fs are dedicated ops (v2 `ops/_1_repo.rs` exact pattern: `repo(glob)` filter, `repo($R)` bind). fs only takes a pattern.

## Solution / Approach

1. **One concept at the value tier: Pattern is first-class.** Atoms, strings, ints, terms, patterns, pipelines all live in `Value`. The op's `arg_spec` declares what each slot expects; the lowerer coerces at lower time so runtime never downcasts.

2. **Pattern as `(template, cached_regex, anchors)`.** Template is source-of-truth; cached regex is the fast path for the common all-unbound case. `materialize_for` rebuilds for the read-mode case. The projection model collapses Glob/Regex into the same shape (`as_raw_regex` returns `Some`) and leaves room for Json (gron flattening) and Ast (breadcrumb prefilter + structural confirm) as non-identity variants sharing the same `apply` body.

3. **Term dispatch via cursor.captures.** Pattern checks each declared hole against the incoming cursor's captures. Bound → read mode, literal substitution, no new capture. Unbound → write mode, named group in the regex, new capture emitted on output cursor.

4. **Cursor fields for repo/rev/fs, v2-native.** Not captures. fs/repo/rev ops read these; they are projected out via `&.repo` etc. at the cursor_ref layer. Landing order for next session: Cursor-struct fields first, then RepoOp/RevOp/FsOp.

## Key Insights

1. **`dyn Any` for pattern inspection is a smell.** Three independent Sonnet reviews converged on the same fix: close the algebra at the value layer, pattern-match there. `CompiledPattern { Arc<dyn Any> }` was a Phase-1 expedient that couldn't survive the fs(re(...)) bulk-dispatch pressure.

2. **Per-op arity is the wrong axis.** Both glob and re are `Cursor -> Vec<Cursor>` with find-all semantics. Glob's anchoring is encoded in the compiled regex (`^…$`), not in the op's pipe body. The pattern's source string carries the shape. `Pattern::apply` is one body.

3. **Terms in patterns are input-or-output, decided per apply.** Not at compile. Not at lower. Per cursor, via its `captures` map. This is what unlocks "upstream `tag(:repo, $R)` feeding downstream `fs(**/$R/*.rs)`" cleanly without a special-case plumbing layer. Template + cached regex + materialize_for is the minimum shape that supports it.

4. **v2 had the repo/rev answer already.** Cursor fields, not captures. `&.repo` already in the v3 grammar. The pattern op `repo(...)` is two-mode (filter OR bind) over the same paren body — v2 `_1_repo.rs:71-86` via `classify_token`. I had been drifting into kwarg-syntax fantasies; the correct port is direct.

5. **`fs` is strictly one-slot.** A pattern. Anchor info lives in the cursor (first-class fields, not captures). The paren never carries kwargs. This aligns surface ergonomics with the stream-tier mental model: ops transform streams; the cursor is the context.

6. **Pipeline-as-Value collapses lazy and eager.** Any op invocation at arg position becomes `Value::Pipeline`. Any pattern op at arg position becomes `Value::Pattern`. The surface is identical; the lowerer reads the outer op's `ArgSpec` per slot and routes. rxjs aesthetic at the surface, LINQ expression-tree introspection under the hood.

7. **Bulk escape hatch is `as_raw_regex`.** One predicate per Pattern variant. Consumers (future fs, fzf) do a single enum match to get the raw `Regex` and hand it to a bulk backend. No trait indirection, no `dyn RegexProvider`, no ceremony.

## Open Questions

1. Should `Op::arg_spec` be a `&[ArgSpec]` or a richer `SlotSpec` struct that also carries name + doc + default? Simple slice suffices for Phase 1 but richer shape helps LSP completion and hover. Defer until a second consumer shows up.

2. Should `Pattern::apply` cache `materialize_for` outputs in an LRU keyed by bindings-set? Current impl rebuilds per cursor. One reasonable step-up; zero-config default is fine for now. Measure before deciding.

3. Non-UTF-8 bytes bound to a term in read mode — currently `materialize_for` errors. Reasonable default (binary bytes don't escape into regex safely). Confirm before production-izing.

4. When `cursor.repo` is empty (no upstream `tag(:repo, ...)`), does fs walk the physical working tree, or does it error? v2's stance: empty is the default-physical anchor. Reuse.

5. Should `#[sprf_pattern_op]` emit `compiled_pattern()` + `OnceLock<Pattern>` field automatically, or do ops always write it themselves? Autopromote when a second op needs it.

6. `ArgSpec::Any` (both `Pattern` and `Pipeline` acceptable) — does the lowerer try `Pattern` first or `Pipeline` first? Current plan says "Pattern first, fall back to Pipeline". Lock when arg_spec machinery actually runs.

7. Hover dispatch for a Pattern at arg position vs pipe-step position — different surfaces? Spec §14.6 doesn't split. Handle when LSP layer lands.
