### Substrate API additions
- `QueueBackend::cascade_delete(root: QueueId) -> u64` — default no-op; Mem/Sqlite/Hybrid override. Seeds on `id = root OR parent_id = root` so descendants are found even when root is already popped (the typical Memoize-on-evict shape).
- `MemoCache::Entry` gains `source_row_id: Option<QueueId>`.
- `MemoCache::invalidate_domain` / `invalidate_input` now return `Vec<QueueId>` of evicted source_row_ids (was bare counts).
- `CacheCascadeListener` — bus listener that holds cache + queue; on Dirty, evicts entries and cascade_deletes their downstream subtrees.
- `attach_cache_to_bus_with_queue(cache, bus, queue)` helper.
- `PriorChildIndex` — new module. `HashMap<Vec<u32>, Vec<(ContentHash, QueueId)>>` keyed by row.path. `diff_children(prior, new)` returns `ChildDiff { doomed_ids, kept, added_idx }` with multiset semantics.
- `Memoize::with_prior_children(idx)` — opt-in B2 reconcile.
- `Memoize::dispatch` — now batched-aware: pre-classifies hits/misses, dedupes identical inputs within a batch, calls `inner.render_batch` once for unique misses, spreads results back. Preserves inner's tier-2 work (was bypassing it before — found via bench, 0 matches against AstNm).

Sub-slice ordering for fine-grain invalidation:

- (b) Memoize source_row_id + CacheCascadeListener — bookkeeping + bus wiring. cascade fires on Dirty.
- (c) PriorChildIndex + B2 reconcile — per-position child tracking + multiset diff. Opt-in.

Bench wiring (commit ce39eea) immediately found a regression: `Memoize::dispatch` was calling `self.inner.render` directly, bypassing `render_batch`. Fixed by restructuring dispatch to pre-classify hits/misses, batch-dedupe identical inputs, issue ONE inner.render_batch call.

## Key Insights
- **Cascade contract.** `cascade_delete(root)` must work even when `root` itself has been popped — by the time invalidation fires, the producing row is long gone. Sqlite CTE seed = `id=root OR parent_id=root`. Mem BFS works without the seed condition because frontier check uses parent_id matching.
- **Cascade depth limit.** Cascade only catches descendants whose `parent_id` chain is still in the queue. For lineage past intermediate-popped rows, lineage propagation (a `root_render_id` column propagated by splice_into) would be needed. Not done in this slice — fine for the LSP/watch model where descendants ARE still parked.
- **B1 vs B2 source identity.** B1 = MemoKey = `h(ident, input)`. B2 = `row.path`. B1 entry IS the slot, dies on cache eviction → loses prior children. B2 has separate index, survives cache turnover. Position-stable identity is the React-key shape.
- **Reconcile is opt-in within opt-in.** Memoize itself is opt-in (caller wraps a Component). PriorChildIndex is opt-in beyond that (`with_prior_children`). The unmemoized hot path (current ast-grep substrate baselines) is exactly the same code as before. Zero regression risk.
- **Memoize MUST preserve inner.render_batch.** AstNm and most useful tier-2 Components do their work in render_batch (par_render). Naive per-row dispatch breaks them. Bench caught it before commit. New shape: pre-classify, dedupe identical inputs in batch, ONE render_batch call for unique misses, spread results.
- **Reconcile-with-share is for incremental, not scan.** When `expand()` starts with an empty queue (scan mode), the kept-children optimization wrongly assumes downstream is alive. Trial 2+ produces 0 downstream rows. For LSP/watch where parks persist, kept = correct. Documented on with_prior_children.
- **Per-child blake3 cost is real but bounded.** biome 33k matches: reconcile cold +14MB RSS over baseline, wall time within noise. Cursor-level hash memoization (Cell<Option<[u8;32]>>) is the next defensive move if linux-scale shows regression.
- **Wide-table fact insert.** Each declared table gets its own SQL table; columns are FK ids into `sprf_strings`. Schema persists in `sprf_fact_schemas` so reopens work without re-declare. Identifier validation prevents SQL injection from user-supplied table/col names.

## Open Questions
- Should `Cursor::content_hash` cache its result on the Cursor itself? Cursor is shared via Arc, so interior mutability (Mutex / OnceCell) needed. Pays for itself only if same cursor flows through multiple hash boundaries. With Memoize on tier-2 Components, the input cursor is hashed once per dispatch. Not currently a hotspot.
- Does the `RenderCtx` need `parent_row_id`? Memoize's tier-3 dispatch reads row.id directly, so no. Adding it would only matter for tier-1-only Memoize wrappers. Deferred.
- Reconcile re-render trigger: who pushes the source row back onto the queue when bus invalidates? In LSP this would be the watch loop seeing a file change → bus dirty + re-feed source. Not the substrate's job. Document at integration time.
- Lineage propagation beyond direct children (`root_render_id` column on QueueRow): worth adding when a use case demands cascade past popped intermediates. Not needed today.
