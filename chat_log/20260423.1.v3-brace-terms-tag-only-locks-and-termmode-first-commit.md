## Key Insights
- The 3-mode trait axis (EnumByDefault/ByRequest/FilterOnly) was spurious — BindingGraph handles universal writer-resolution + per-op arg well-formedness handles the bespoke cases (rev rejects bare call). Nothing new to file.
- `$${...}` lex-level distinction from `${...}` kills the context-sensitive grammar problem for sh interpolation. One sigil pair, one tokenizer pass.
- Tag is op-owned (internal HashMap<Name, BehaviorSubject<ArgTuple>>); dropping the "label registry" core concept simplifies wait-set to cursor-local only.
- `is` primitive dies into tag — replay IS the append-log. Two primitives collapse to one.
- Rule exit-cursor collection needs invocation_id, not just rule_name (multi-call + recursion). OpEvent::RuleExit variant carries {cursor, rule_name, invocation_id}.
- Fork arm Subject identity: Arc-shared (fork-clone clones the Arc, not the Subject). That's how lineage coupling works.
- sh template MUST have all `$${X}` bound at call — BindingGraph rejects unbound inside shell strings; can't run a command with holes.
- Bootstrap vs live for tag: cold-store queried synchronously by new subscribers, live Subject for future emits only. Avoids 80k-row replay storm + avoids re-firing sh side-effects on subscribe.
- eq/neq are bound-only terminals — inequality has no enumerate mode; accepted as fundamental asymmetry with tag/rule.
- Openapi drift scan walks cleanly through the new surface; missing primitives are all filed as cards.
- Arg-pipes get their own SprfPath sub-tree (`<op>/arg[N]/...`) with value-indexed enumeration segments for memoization stability; single-arm fork stays at runtime identity to preserve arm visibility.
- User wants to get to performance/ast-grep combos and repo discovery via tags after the grammar/runtime/tag/sh/sqlite closeout lands.
- Code landing order: r6k+9lt → 4iv → 126 → bsa (in-mem) → 3rf+sh → diw → gag → 4m7.5.1 → q39 → kitchen-sink fixture+test.
