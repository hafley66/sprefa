## Key Insights
- doc_comment.line == the DECLARATION line (so it joins type_entity), NOT the
  doc-block start line. The ref spine exposes no doc-start line, so you cannot
  bound the doc block above the decl in pure dl -> the precise "decl changed but
  doc block did not" lint is not expressible today; stale-doc ships the correct
  coarse form (every changed documented decl) and documents why.
- Data-driven scan binding pollution: resolve_scan_bindings (engine/mod.rs:1555)
  pulls EVERY Pos/Neg/Cmp body atom into lower_gen over the repo/rev sel_vars.
  A single extra Pos atom that references scan OUTPUTS (e.g. file(r,rev,path,c)
  or a strip_prefix on the scanned path) breaks resolution -> "no repo/rev
  resolved", 0 files. match() atoms are EXCLUDED (different BodyItem variant), so
  scan(r,..,p,rev), match(p,rev,..) works but scan(r,..)+file(r,..) does not.
  Fix pattern: keep the data-driven scan rule to ONE binder atom (repo(r,_,_) or
  the user rel), OR avoid data-driven scan entirely — scan("*") fans over all
  config repos and populates the builtin file(repo,rev,path,content) which
  ALREADY carries the repo per row, so downstream joins are plain derived rules.
- phantom-deps false-positive taxonomy: (1) domain-shaped STRING LITERALS
  (k8s annotations "app.kubernetes.io/name") — fixed with an END-ANCHORED import
  regex ^\s*(alias )?"path"\s*(//...)?$ so only a bare import line matches, not
  a map key / annotation with code around the quote; (2) MONOREPO nested modules
  — fixed by scanning **/go.mod (matches root too) not just "go.mod", so a file
  under docker/ is covered by docker/go.mod's module id. 11564 -> 5417 rows,
  self-imports 0. Residual honest: replace-directive-only modules read as phantom.
- config table is [[repos]] (plural), not [[repo]] — cost a debug cycle in the
  vendored-drift sandbox.
- CLI runs prime tick + run tick = 2 ticks (lib.rs:187 needs_prime for
  scan_has_var_coords || is_repo_sink). A 3-hop demand chain needs 3 ticks, so
  some data-driven examples only fully converge under the daemon (pin-skew's TEST
  drives 3 manual ticks for this reason).
- The examples-index in README is AUTOGEN by gen-reference.dl from each .dl's
  FIRST comment line; regen, never hand-edit (feedback_never_edit_autogen_zones).
  The hand-picked highlights table ABOVE the markers IS hand-editable.
- spine normalize in a pure-dl program = lower(replace_re(t,"[^A-Za-z0-9]","")),
  the user-space equivalent of _strings.norm (the cross-lang casing/template
  bridge).
