## What landed

`feat/dl6-generic-rel-arrow` (4 commits) and `fix/rust-callf-def-scope-owner`

### 2. Ground truth, both ecosystems
- `v6/dl/deadcode/fixtures/deadcrate/` + `ground-truth.sh` vs **rustc dead_code**
- `v6/dl/deadcode/fixtures/deadjs/` + `ground-truth-js.sh` vs **knip 6.32.2**
- Every fixture file is labelled with what BOTH tools must say. Both gates
  sabotage-tested: the Rust one by making `dead_pub.rs` live, the JS one by
  making `index.ts` call `shelvedOne`. Both went red on the right row.
- The rail runs on TypeScript UNCHANGED. sprefa-extract emits the same
  node/site records for `.ts`, so no rule needed porting.
- The two oracles are blind in opposite directions, which is why both exist:
  rustc cannot see a `pub` item in a lib crate; knip cannot see a module that
  IS imported but whose exports nothing calls.

### 3. The rail was WRONG and the gate caught it
`soopy/src/_3a_files.rs` was reported dead against **19 live calls** to
`snapshot`. Cause: a receiver call carries no `callee_path` and only 24% of
sites carry one, so `unique_name` as a liveness guard can never mark an
ambiguous name live. Dropping the guard produces the opposite defect
(`chat.rs` really is dead and goes silent). Now three buckets, ambiguity named
rather than guessed: `rail_dead_module`, `rail_unproven_module`,
`rail_unreachable_module`. hafley-rs: 0 dead, 14 unproven, 0 false positives.

Also: roots now come from `cargo metadata` (9 entry points) instead of one
hand-typed `main.rs` making the other eight read as dead. The def-class plane
(free/inherent/trait, owner spans, qualified calls) is DELETED: every class
reached the same rule. Six hosts to three.

### 4. `sh` is gone from the extract and soopy paths
- `SoopyFilesExecutor` replaces the `files` host's `sh -c` + `mktemp` + `paste`
  + second `ls-files` with `soopy::enumerate`.
- Three extract hosts were missing from `.adapters.json`, so they spawned the
  48MB binary through `sh -c`, 246 times a run, and failed `is_applicative` so
  the runner could not group them. Sidecar fixed.
- `ShellExecutor` now carries `warn_span!("sh_spawn")` and `linked_twin_for`
  warns by name when a command a linked executor answers reaches the shell.
- **sh_spawn count: 0.**

### 5. The engine had NO tracing at all
No dependency, no span. That is why three guesses in a row were wrong
(extraction 0.14s of 8.7s, decode 0.09s, a memo that never hit once). Added
`tracing` + `tracing-subscriber`, spans on drive_tick / host_collect /
host_run / extract / read_blob / project / soopy_files / sh_spawn, stderr only,
silent unless `RUST_LOG` asks. **This is what found every real cause.**

    RUST_LOG=sprefa_engine_rs=info emit_rust_harness <prog> <sched> --live-hosts

### 6. cfg(test) defs are marked and subtracted
`record=cfg_scope family=call span={start,end} cfg=<predicate>`, emitted ONLY
for guarded defs so no golden moved. Predicate split on non-word characters and
compared whole: `any(test, feature="x")` matches, `feature="testing")` does not.
Needed a `registry.pl` row because `host_input_contract` is keyed on hardcoded
host NAMES (**ARCH.pl D1**) -- every new host name costs a registry edit.

### 7. Failure ledger
- **53.** A content address the object database has never seen. `git hash-object`
  over a worktree file is a valid address for content never staged; `read_blob`
  treated the miss as a hard stop and the rail died on any unstaged edit. Now
  falls back to the worktree and RE-HASHES it.
- **54.** A silent fall-back to `sh` for a command a linked twin already answers.
