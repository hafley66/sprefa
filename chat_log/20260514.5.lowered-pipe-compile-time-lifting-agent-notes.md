# Lowered Pipe Compile-Time Lifting Notes

Date: 2026-05-14

Source: side-agent design pass on common compile-time op lifting and pipe rewrites.

## Summary

Add a small lowered-pipe IR between `walk_op` and final `Pipe::extend`.

Current adjacency is lost in `v4/src/compile/walk.rs`, where each op lowers to `Pipe<Cursor>` and is immediately appended. A lowered IR lets optimization inspect siblings, children, and op kinds before materializing into runtime components.

## Proposed IR

```rust
// v4/src/compile/lower/optimize.rs

pub struct LoweredPipe {
    pub ops: Vec<LoweredOp>,
}

pub struct LoweredOp {
    pub name: Arc<str>,
    pub span: ByteRange,
    pub chain_pos: usize,
    pub pipe: Pipe<Cursor>,
    pub children: Vec<LoweredPipe>,
    pub kind: LoweredKind,
}

pub enum LoweredKind {
    Builtin,
    CapsTerm,
    RuleWrite { table: Arc<str> },
    RuleTableQuery { table: Arc<str> },
    RuleApplyWrite { table: Arc<str> },
    RuleBodyCall { table: Arc<str> },
}

pub struct Rewrite {
    pub consume: usize,
    pub emit: Vec<LoweredOp>,
}

pub trait RewriteRule {
    fn apply(&self, ctx: &LowerCtx, ops: &[LoweredOp], at: usize) -> Option<Rewrite>;
}

pub fn optimize_pipe(ctx: &LowerCtx, pipe: LoweredPipe) -> LoweredPipe;
pub fn materialize_pipe(pipe: LoweredPipe) -> Pipe<Cursor>;
```

## Walk Integration

Insert the lowered phase in `v4/src/compile/walk.rs` around the current pipe lowering path:

```rust
let lowered = walk_lowered_pipe(p, reg, ctx, diags)?;
let lowered = optimize_pipe(ctx, lowered);
Some(materialize_pipe(lowered))
```

Keep the public function:

```rust
walk_pipe(...) -> Option<Pipe<Cursor>>
```

Add internal lowered functions:

```rust
walk_lowered_pipe(...) -> Option<LoweredPipe>
walk_lowered_op(...) -> Option<LoweredOp>
```

`walk_op` becomes `walk_lowered_op` internally and returns `LoweredOp`.

Recursive block lowering and inline/subpipe lowering should call the lowered form first, optimize recursively, then materialize only when the current `OperatorDef::lower` still needs a `Pipe<Cursor>`.

## Probe Wrapping

Move probe wrapping out of `walk_op` before optimization.

Current wrapping happens before return in several `walk.rs` branches. If wrappers stay there, downcasts and concrete matching against `SqlQueryComponent` and `FactWrite` become brittle.

Two acceptable paths:

- Move wrapping to final materialization.
- Make wrappers delegate a stable component description API.

## Rewrite Rule: SQL Terminal Fact Write

Existing support is already present in `v4/src/sql.rs`:

- `SqlQueryComponent` has `terminal_fact`.
- `SqlQueryComponent::with_terminal_fact_write(...)` exists.
- SQL dispatch already writes terminal rows.

Suggested helper signatures:

```rust
fn sql_component(op: &LoweredOp) -> Option<&SqlQueryComponent>;
fn fact_write_component(op: &LoweredOp) -> Option<&FactWrite>;

pub struct SqlTerminalFactWriteRule;

impl RewriteRule for SqlTerminalFactWriteRule {
    fn apply(&self, ctx: &LowerCtx, ops: &[LoweredOp], at: usize) -> Option<Rewrite>;
}
```

Match:

```text
SqlQueryComponent, then FactWrite with assignments == None
```

Emit one `LoweredOp` containing:

```rust
SqlQueryComponent::with_terminal_fact_write(fact.store.clone(), fact.table.clone())
```

First version should skip `FactWrite::projected(...)`, because `FactWrite` carries assignments that current `TerminalFactWrite` does not preserve.

## Rewrite Rule: Adjacent SQL Lift

Match two adjacent `SqlQueryComponent`s where:

- both are simple `SELECT`;
- both preserve `input.__cursor_idx`;
- the second references only `input`.

Suggested signature:

```rust
pub fn try_lift_adjacent_sql(
    left: &SqlQueryComponent,
    right: &SqlQueryComponent,
) -> Option<(String, Vec<String>)>;
```

Emit one SQL component:

```sql
WITH __sprf_sql0 AS (
  <left.sql()>
)
<right.sql() with first FROM input rewritten to FROM __sprf_sql0 AS input>
```

Referenced tables are the union of both components.

Keep this string-based and conservative unless a SQL parser is added.

## Rewrite Rule: Subpipe Fold

Run recursively before parent materialization:

```rust
pub fn optimize_child_pipes(ctx: &LowerCtx, op: &mut LoweredOp);
```

Initial folds:

```text
empty child pipe -> empty Pipe
single child pipe with no structural wrapper -> child pipe
child pipe followed by parent rewrite -> parent sees child LoweredPipe metadata
```

This gives lower-time rewrites access to adjacent siblings plus child shape without changing sprf syntax or `OperatorDef::lower` immediately.

### SQL Terminal Fact Fusion

```rust
let src = r#"
  rule(:out, OP?);
  `getUser` > split(OP?)`!`
    > sql`SELECT input.__cursor_idx, input.OP FROM input`
    > rule(:out);
"#;

let pipe = lower_one(src);
assert_eq!(count_kind::<SqlQueryComponent>(&pipe), 1);
assert_eq!(count_kind::<FactWrite>(&pipe), 0);
let sql = only_sql(&pipe);
assert!(sql.has_terminal_fact_write());
```

Requires one of:

- `FactWrite::describe() -> Some(self)`
- fallback to `component.kind().contains("FactWrite")`

### Adjacent SQL Lift

```rust
let src = r#"
  `x`
    > sql`SELECT input.__cursor_idx, input.value FROM input`
    > sql`SELECT input.__cursor_idx, upper(input.value) AS value FROM input`;
"#;

let sql = only_sql(&lower_one(src));
assert_eq!(count_kind::<SqlQueryComponent>(&pipe), 1);
assert_snapshot!(sql.sql());
```

Inline snapshot should assert the CTE shape, not runtime rows.

### Subpipe Fold Unit Test

Construct `LoweredPipe` directly with a parent op carrying one child `LoweredPipe`, call `optimize_pipe`, and snapshot a small debug shape:

```rust
assert_snapshot!(shape(&optimized), @r#"
parent
  child: [sql]
"#);
```

This avoids relying on parser syntax while pinning parent/child visibility.

## Risks

- Probe wrapping before optimization hides concrete components.
- `FactWrite::projected` needs assignment preservation before `sql > projected FactWrite` can fuse.
- SQL lifting is only safe under strict guards.
- Arbitrary SQL composition needs a parser or SQLite validation pass.
- Current `OperatorDef::lower` takes already materialized child `Pipe<Cursor>`. Parent-aware lower decisions require either optimizer-side replacement or a later trait extension.

## First Pass Boundary

Keep the first pass optimizer-side:

- no sprf syntax change;
- no public lowering trait change;
- preserve `walk_pipe(...) -> Option<Pipe<Cursor>>`;
- add internal lowered IR;
- run conservative rewrites;
- materialize to the existing runtime pipe after optimization.
