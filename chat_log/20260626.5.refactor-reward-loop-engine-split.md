validated deterministically. This session pivoted off the prior
"name-signal" work onto a measurable REWARD SIGNAL for refactors
(structural de-dup vs raw LOC), generalized it, and started refactoring
sprefa's own engine.rs through the loop, ending on an extract-function
proposer whose signature-inference gap was identified.

## Problem/Context
User wants sprefa to recommend refactor moves, measured deterministically
("manual Q-learning like a madman"), not bespoke. Five questions answered
this session: (1) does the name-signal work? (found + fixed the collision
bug). (2) is there a measurable reward? (structural beats LOC). (3) does it
generalize? (3 repos, yes). (4) apply to our own code? (parse_file split).
(5) simplest "propose a refactor" to try first? (extract-function of
verbatim blocks; signature inference is the gap). Identifier-repetition was
explicitly retired as "a meme, not the thesis." User flagged mid-session
that the "Q-learning/reward/policy" narrative was over-jargoned; I
plain-grounded it as "measure before/after, write it down."

## Solution/Approach
- **Collision fix**: `display_names()` keyed by `(relative_path, symbol)`
  not bare symbol; per-doc scoping. (Verification caught my own mistake:
  `cargo install` writes `~/.cargo/bin/dl`, I run `./v5/target/debug/dl` —
  different binaries; "post-fix" runs used a stale binary.)
- **Reward harness**: pure git+python. Measures at parent→commit: LOC Δ,
  within-file fn-name dup-excess, type-def count, cross-type-method dup.
  Pass/fail = reward sign matches commit-message intent.
- **Generalization**: harness takes repo root as `argv[1]`; ran on
  sprefa/ripgrep/serde (cloned to /tmp).
- **Trait-aware detector**: cross-type-method "duplication" in
  typegraph.rs/modgraph.rs is ALREADY trait-factored (`TypeLang`,
  `ModuleResolver`) — the post-refactor state, not a smell. Recalibrated:
  detector must skip trait-bound methods. v5/src has little genuine
  consolidation opportunity left; the high-gain axis is god-fn SPLIT
  (parse_file 108 locals).
- **parse_file split**: iter1 consolidate verbatim span-id block,
  iter2 extract Match arm. `push_span` closure's guard inlined faithfully.
- **Extract-function proposer**: windowed-hash + maximal-extension block
  finder works; free-var heuristic via regex is noise; real Rust scope
  analysis (tree-sitter) needed for the signature.

## Key Insights
- **display_name collision**: RA local monikers are opaque "local N"
  PER-DOCUMENT; keying display_names by bare symbol collapses all docs to
  one entry (last write wins), manufacturing false cross-fn co-occurrence.
  Inflated every count ~5x (label_span's 96 fns was phantom). Fixed by
  (path,symbol) keying. Single-doc unit tests missed it.
- **cargo install ≠ target/debug/dl**: `cargo install` writes
  `~/.cargo/bin/dl`; I run `./v5/target/debug/dl`. "Post-fix" runs used a
  stale 16:27 binary until the 17:08 `cargo build --bin dl` rebuild.
- **LOC = 96% reward for splits, 23% for consolidations.** Consolidations
  grow boilerplate (generics, trait plumbing) while removing duplication;
  LOC counts bytes, not dup removed.
- **Structural beats LOC 97% vs 50%** across 3 repos/30 refactors for the
  consolidation class. Each lexical signal ~73% alone; combined (fn-dup OR
  type-def OR cross-type-method) → 90-100%.
- **Lexical ceiling ~90%; residue is semantic.** Collapse-into-a-generic
  (commit 635de156) ADDED type-defs (+22); needs AST/semantic similarity,
  not name/type counts. That's the SCIP-per-rev bridge's job.
- **Commit-level granularity conflates concerns.** 635de156's cross-type-
  method Δ was +2 because the commit mixed the collapse with unrelated
  impls. Per-symbol/per-hunk reward is cleaner than per-commit.
- **Measurement > commit-message label.** Tuple #2 (a93aa08): claimed
  "8→1 impls"; measured 8→2. Deterministic tool caught the over-claim.
- **Trait-aware detector required.** Cross-type-method dup where a trait
  already binds the methods is the POST-refactor state, not a smell. v5/src
  is already trait-factored on this axis → genuine consolidation surface is
  small; the high-gain axis is god-fn SPLIT.
- **Extract-function proposer**: verbatim-block detection is cheap and
  works; signature inference is the real proposer and regex can't do it
  (mixes vars/types/methods) — needs tree-sitter scope analysis. Body +
  call sites are mechanical once the signature is known.
- **Pure-aggregate-head engine bug**: `count(x)` with no group-by var in the
  head returns 0 or unaggregated rows. Hit 3× (n_clusters, n_pairs,
  head_seed_calls). Workaround: add a literal group key or read raw row
  counts.
- **"Q-learning" framing was oversold**: reduces to "measure before/after,
  write it down." No ML. User called out the jargon; plain-grounded it.
- **opencode permission**: `/tmp` friction solved by adding
  `external_directory: {"*": "ask", "/tmp/**": "allow"}` to the GLOBAL
  config (`~/.config/opencode/opencode.json`); narrow rule last (last match
  wins). Requires opencode restart.
