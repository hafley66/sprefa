## Problem/Context
Effects went through eight spellings in a day (Effect/Clock/Policy, mode, host, Host annotation + Key-as-mode, want, effect+rule, effect+cons+free, effect+partial application). ## Solution/Approach (settled, in PR #741)
- No annotation. Any relation is settable from outside. The runner names what it serves: `dl8 eval --serve a,b`.
- `(effect ?Relation ?Application)`, two columns, written on EVERY evaluation of a goal on a served relation, hit or miss (interest, not miss). Gone when no rule evaluates the goal. Loading = effect and no data row. `(tick)` with nothing bound is a source.
- Pattern = interned application via kernel `intern`, `none` at unbound positions; read back with `(intern_snapshot rel ?Args ?App)` then `cons`.
- `effect`, `int_add` in `KERNEL_RELATIONS`; `kernel_arity` deleted; v7 four-item `Host`, `Hosted`/`HostPort`, fixtures 8 and 11 deleted; `v8/oracle/refreeze.sh` regenerates goldens from dl8 (v7 parity released by Chris).
- `Key` on a column = replacement identity (v6 `key(1)`), unrelated to requests; lands with retraction (task 3).
- Aggregates stay programmable (task 10): `term_lt`, `Fold` constructor (Partition, Order, Step, Seed), `linear(Step)` facts for sqlite/dbsp lowering, macros over Fold with the Rust fold as fast path.
- Store decisions: ints only in keys; one table per product, typed columns; commit per tick; two tables per served relation `"rel.pending"`/`"rel.settled"` with `aborted_at`; dictionary release via the share rules, ids never reused. Open: relation names are absent from the runtime program, #742 uses `rel<id>_a<arity>`; carry names through program JSON.
