## Solution/Approach
Markdown-authored decks. Architecture = "one cursor, many lenses" (user's own tree-viz-omega north star): a frame is a moment, a panel is a lens, stepping is time. ONE animation primitive: keyed-FLIP (matched keys slide, new fade in, gone fade out) — code keys on tokens (shiki-magic-move), graphs on node ids (d2), fs on paths, git on shas. Build pipeline `bin/build-frames.mjs` parses markdown -> frames.json + renders d2 -> svg; Vite plugin live-reloads on save.

## Key Insights
- Authoring format = the interface; AI never hosts the renderer in context, just the markdown schema. Markdown DSL (fenced code + fenced d2, no JSON escaping) was the key token-cost win.
- Auto-cycle coloring (Tarjan in build) + a d2 "kit" of named classes (fn/relation/type/module/sink/dead/hub/ghost) = author writes `a -> b` + one-word class, never style blocks. The `helper` node = the dead function from the running example (defined, never called); made `dead` class dashed/dim so it reads as dead.
- sql-graph fence (node:sqlite, zero deps, read-only) is the dl seam — decoupled, robust to dl core churn since the query lives in the deck not the tool.
- code: source-spans pull real files (dogfooded scc.rs Cond struct); anchor: binds code token <-> graph node (v1 of "point at code, watch graph"); deck linter (npm run check) gives AI compiler-style errors.
- FS-as-graph-but-shown-as-fs-app falls out for free: fstree and graph lenses read the same data, toggle projection.
- User's prior art: tree-viz-omega (repo-minimap.html = FLIP tree+minimap+change-cursor; d2-explorer.py = d2 group collapse/reflow; WISHLIST = the cursor+projections north star). The animator IS the missing timeline/narration layer for that vision.
