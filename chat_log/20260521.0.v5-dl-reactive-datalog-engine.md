# Session: v5-dl-reactive-datalog-engine

## Goal
Melt the over-built, unreadable v4 (effect_runtime / cons-as-op / callable-as-value sprawl) into a small, embeddable, reactive datalog engine over code facts ("v5/dl"): SQLite-backed, bounded peak RSS, file-watch incremental, with patterned extraction (ast-grep / tree-sitter / regex / json) and recursive datalog queries.

## Current State
v5 is BUILT and WORKING (~1430 lines Rust, clean release build). Ran on the real Linux kernel (~/projects/ext/linux, 36,677 .c files): cold 5s / 133 MB peak RSS, warm 0.85s / 61 MB. Has: lexer/parser (hand-written), AST, SQL lowering with var-unification (joins, anti-joins via NOT EXISTS), recursive fixpoint, source/derived split, file-keyed `_prov(rel,path)` retraction, content-hash + mtime fast-path, rayon par_iter + literal prefilter, `--watch` event-driven targeted reconcile, git-rev (resolve-to-SHA, blob-OID change detect, rev-aware checked types). Builtins: scan, match(regex), ast(tree-sitter query), sg(ast-grep pattern), json(dotpath). Examples + bench harness (printk = v4 linux-bench equivalent) + justfile. Research doc + a 7-chapter teaching book (ch0 = reflective "calmer frame"). Throwaway v5cozokuzu/ comparison crate (cozo/kuzu both currently unbuildable/unusable). Two experiments DONE this session: E1 (measured the derived-recompute gap: reaches recursion = 197s, the entire cost) and E4 (SCC-condensed reaches PROVED: 197s -> 1.4ms, ~130,000x; reachability queries 7us from condensed form; verified correct vs naive). Standalone proof in v5/src/bin/scc_reach.rs.

## Problem/Context

The despair lifted exactly when a small thing (v5) ran and was comprehensible. Mood tracked comprehension/traction, not project quality.

## Solution/Approach
Weld SQLite (no store trait). Drop the effect runtime entirely; the language IS datalog lowered to SQL. Source rules read files (scan + extractor) and are retracted by file via _prov; derived rules (joins/anti-joins/recursion) are recomputed wholesale today. NEXT: make recursive `reaches` SCC-condensed (Tarjan -> condensed DAG -> counting is sound on a DAG -> never materialize the Theta(V^2) closure). This turns 197s wholesale recompute into ~1.4ms, KEEPING the simple "recompute derived each tick" model (recompute the SCC structure, not the expanded closure). Glean's ownership-set model = _prov extended through the derivation DAG (the surgical-incremental upgrade). Zoekt = mmap+trigram (storage seam to borrow). Souffle = batch rules backend to graduate to later. cozo/kuzu/glean not embeddable-usable; reimplement the ideas.

## Key Insights
- COUNTING breaks on cycles (self-support lie) but is SOUND on a DAG -> condense each cycle (SCC) first, then counting works. This is the unlock.
- Differential dataflow / DBSP keep RAM-resident arrangements -> wrong for a peak-RSS obsession. Motik B/F is exact but also resident. The RSS-frugal path = SCC-condensed on SQLite (IncQuery IncSCC) + don't store E+, reconstruct on demand.
- Glean's ownership sets == user's _prov, extended through the derivation DAG. User independently rebuilt Glean's source-layer half. Glean is BSD-3 (usable) but Haskell-server (not embeddable) -> reimplement the idea.
- Bounded RSS = durable index on disk, only working set resident (SQLite page cache / mmap; RocksDB LSM; Zoekt mmap shards). 133MB over the kernel matched only by Zoekt/Glean, by zero embeddable code-graph tools.
- Measure before build: E1 corrected the guess "derived is cheap" -> right for joins (339ms), wrong for recursion (197s); narrowed E4 to one rule.
- Working pattern for the user: when stuck/low, build the smallest thing that RUNS, not more analysis. Verify/run, don't assert. Check LATEST lib versions (defaulted stale on ast-grep + kuzu, got caught). Be scaffolder/critic, keep the architecture in his head.
- Over-abstraction is ambition (seeing too many futures), not ignorance; fix = rule of three, not "learn more". v5 welds SQLite = the safety on.
