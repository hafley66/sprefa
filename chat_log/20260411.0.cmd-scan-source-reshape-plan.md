# cmd_scan source reshape plan (v2)

date: 2026-04-11
branch off: `wip/kitchen-sink-react-hook-fix`
new branch: `wip/source-driven-cmd-scan`
executor: sonnet-4.6 autonomous

supersedes v1 (same file, earlier draft). v1 oversold perf gains that rayon already provides inside `sprefa_index::extract.rs`. v2 repositions the work as a correctness + code-health fix with a small pipelining win.

---

## why (5 reasons, ordered by severity)

| # | severity     | problem                                                                                  | site                                |
| - | ------------ | ---------------------------------------------------------------------------------------- | ----------------------------------- |
| 1 | **bug**      | `cmd_scan` ignores `config.sources` → source-only configs scan zero repos silently       | `crates/cli/src/main.rs:634`        |
| 2 | **bug**      | discovery `repo_map` lookup is literal-name only → refs written with normalized names (`service_auth`) never resolve to config entries (`auth-service`), silently dropped | `crates/cli/src/main.rs:705,735` |
| 3 | code health  | discovery loop is 5 nested `for`s + two magic numbers (`MAX_OUTER_ROUNDS=10`, `MAX_LEVEL_ITERATIONS=10`) | `crates/cli/src/main.rs:711-800`    |
| 4 | minor perf   | `unscanned_rev_pairs` fires `round × level × iter × pair` times per scan (~100+ sqlite roundtrips on real configs) | `crates/cli/src/main.rs:723-733`    |
| 5 | trivial      | HEAD detection opens git2 twice per repo (head shorthand + tree walk)                    | `crates/cli/src/main.rs:662`        |

secondary reasons (consistency, not correctness):

- `cmd_daemon`, `cmd_watch`, `cmd_serve` all take `config.repos` directly (lines 1145, 1155, 1195) → they share the same "source configs ignored" bug but for different user flows
- the explicit `cmd_daemon:1232` repeats the inline HEAD-shorthand detect pattern

---

## rayon already exists; grug adjust expectations

rayon is **already** used at the right layer: `crates/index/src/extract.rs:6,37,114` parallelizes per-file + per-blob extraction via the global rayon pool. each `Scanner::scan_rev` / `scan_repo` call already saturates cores during its extraction phase.

consequence: running N `scan_rev` tasks concurrently at the CLI layer means N rayon passes competing for the same global pool. beyond ~2× cores, context-switch tax dominates.

**decision**: level-A concurrency cap = **2** (fixed small constant). this buys pipelining (task A's sqlite flush overlaps task B's extract) without oversubscribing level-B rayon. do not expose this as a config knob yet.

## target shape (cmd_scan)

```
load_cfg, init_db, Arc::new(build_scanner)

registry = Registry::new()
queue    = VecDeque<(usize, RevSpec)>

pushers::from_config_repos(cfg, only, &mut reg, &mut q)
pushers::from_sources     (cfg, only, &mut reg, &mut q)?    ← fixes reason #1
pushers::from_db_cache    (store, only, &mut reg, &mut q)?  ← catches orphaned repos

bail_if_empty()

loop {
  let batch = drain(&mut queue)
  if batch.is_empty() break

  stream::iter(batch)
    .map(|(idx, rev_spec)| async move {
      let cfg = registry.snapshot(idx)
      let (rev, is_head) = resolve_rev_spec(&cfg.path, &rev_spec)?
      if is_head { scanner.scan_repo(&cfg, &rev).await }
      else       { scanner.scan_rev (&cfg, &rev).await }
    })
    .buffer_unordered(2)
    .collect::<Vec<_>>()
    .await
    |> accumulate totals, log per-result

  specs = scanner.scan_pair_levels.iter().flatten().map(ScanPairSpec::from).collect()
  if specs.is_empty() continue
  for (name, rev) in store.unscanned_rev_pairs_bulk(&specs).await?:   ← fixes #3,#4
    let idx = registry.resolve(&name)?  ← alias-aware, fixes #2
    if cfg.rev_excluded(&rev) or already_scanned(idx, &rev) continue
    queue.push_back((idx, RevSpec::Literal(rev)))
}

print totals
run check blocks (unchanged)
```

`detect_head_shorthand` and `resolve_rev_spec` fuse the two git2 opens into one (fixes #5).

```rust
struct ScanReport {
    idx: usize,
    rev: String,
    result: sprefa_scan::ScanResult,
}

/// Resolve a RevSpec to a concrete rev string plus whether this rev is
/// the current HEAD (for scan_repo vs scan_rev dispatch). Fuses the two
/// git2 opens from the old code path (reason #5).
fn resolve_rev_spec(
    repo_path: &str,
    spec: &crate::registry::RevSpec,
) -> anyhow::Result<(String, bool)> {
    use crate::registry::RevSpec;
    let repo = git2::Repository::open(repo_path)
        .map_err(|e| anyhow::anyhow!("open {}: {}", repo_path, e))?;
    let head_shorthand = repo.head().ok()
        .and_then(|h| h.shorthand().map(str::to_string));
    match spec {
        RevSpec::Literal(s) => {
            let is_head = head_shorthand.as_deref() == Some(s.as_str());
            Ok((s.clone(), is_head))
        }
        RevSpec::Head => {
            let s = head_shorthand
                .ok_or_else(|| anyhow::anyhow!("no HEAD at {}", repo_path))?;
            if s == "HEAD" { anyhow::bail!("detached HEAD at {}", repo_path); }
            Ok((s, true))
        }
    }
}

/// Level-A concurrency cap. Each scan_rev call drives a rayon pass inside
/// sprefa_index::extract which already saturates cores. Keep this small
/// (2) so one task's sqlite flush can overlap another task's extract
/// without oversubscribing the rayon global pool.
const MAX_SCAN_PARALLELISM: usize = 2;
```

- wrap `Scanner<S>` in `Arc` after `build_scanner(...).await?`
- wrap `Registry` in `Arc` after pushers run

## pitfalls + mitigations

1. **Scanner clone semantics**. `build_scanner` returns `Scanner<SqliteStore>`. wrap in `Arc<Scanner<_>>` after construction; closures in `buffer_unordered` need `Arc::clone(&scanner)`. if `SqliteStore` isn't `Clone`, this is fine — `Arc<Scanner>` shares immutably.

2. **`unscanned_rev_pairs_bulk` SQL shape**. do NOT invent the SQL. read the existing `async fn unscanned_rev_pairs` in `sqlite_store.rs` first, then mirror each subquery. the existing function is ground truth for column names (`rev_files.rev_name`, `repos.name`, `sprf_norm(...)`).

3. **SQL injection via identifier interpolation**. `ScanPairSpec.table` + column names are interpolated into the query string (sqlx doesn't bind identifiers). use a strict `validate_ident(s)` helper: non-empty, ASCII alphanumeric or underscore only. call before interpolation. any other shape → error early.

4. **`from_sources` branch name drift**. if user sets `source.default_branch = "main"` but the discovered repo's HEAD is `master`, `scan_rev("main")` fails (nonexistent rev). this is a **preexisting toml-side bug** — same thing happens if a user writes `revs = ["main"]` in a repo with a `master` branch. do NOT fix in this PR. document in commit message, flag as follow-up.

5. **git default branch name drift in STEP 10 test**. force `git -c init.defaultBranch=master init` explicitly so the test is deterministic regardless of system git config.

6. **`only_repo` + source normalization mismatch**. if user passes `--repo auth_service` but the discovered dir is `Auth-Service`, the literal filter in `from_sources` misses. first pass: literal-match only. normalized `--repo` matching is a follow-up.

7. **daemon serial Phase 1**. STEP 8 deliberately keeps Phase 1 serial — the `upsert_repo_rev` after each scan is sequencing-sensitive. do not drop in `buffer_unordered` here without auditing the upsert path.

8. **detached HEAD in `from_sources`**. a discovered dir that's in detached-HEAD state returns `shorthand() == "HEAD"`. `resolve_rev_spec` errors on this. skip + `tracing::warn!` is acceptable; do not panic.

9. **rayon oversubscription**. `MAX_SCAN_PARALLELISM = 2` is the load-bearing constant. do not raise it to `num_cpus` — `sprefa_index::extract` runs rayon internally, a cap of cores means `cores × cores` workers at peak.

10. **orphan lsp files**. current git status shows `crates/sprf-lsp/src/{completion,context,db,hover,workspace}.rs` as untracked. DO NOT touch; unrelated draft. STEP 8 does not enter that crate.

## behavior invariants (must remain true across the refactor)

- same rules fire on same files, same rows written, same tables populated
- rev-glob semantics unchanged (explicit patterns from `RepoConfig::rev_list()`)
- `RepoConfig::rev_excluded` applied before every scan push (pushers AND feedback)
- `scan_repo` dispatches for checked-out HEAD; `scan_rev` for everything else
- `only_repo` filter still works (applied at push time, literal-match)
- check blocks run post-loop, same ordering, same SQL
- `scanner_hash` idempotency (sha-gated rescan) untouched; lives in `scanner.scan_*` internals
