## Problem / Context

User corrections that shaped the direction:

1. **`.norm` grammar flip** — initial ask was `$$repo`, `$$repo_norm`, `$$rev`, `$$rev_norm` (underscore, no dot). Mid-edit the user noticed the deeper smell: core grammar should not name ops at all. Parse-provenance should not contain `match "repo" | "rev" | "fs"`. That coincidence is the op set leaking into core.

2. **Provenance as `ln -s`** — provenance is the symbolic-link operator of this language. Captures are edges forward (`$X` binds a witness for downstream use). Cross-refs (`${rule.$X}`) are edges sideways into another rule's ResultStore. Provenance (`$$repo($R)`) is an edge backward/inward to an existing cursor facet. All three are "bind a value into a capture"; they differ only in source.

3. **Ops own everything** — not just diagnostics (existing `feedback_op_owns_everything.md`), but state, config reducers, read intents, write effects, schema, and annotations. Core is a thin spine: registry, scheduler, effect bus, host parser, DAG, path tagging.

4. **Str-universal vs typed-slot** — user floated the redux/rxjs framing where everything is `HashMap<Arc<str>, Arc<[Arc<str>]>>`. Scalar is len-1 list. Cursor is a store of str-lists, ops marshal to typed views at use site. Runs into marshal tax for tree-sitter handles, byte content, parsed JSON.

5. **Hybrid codegen shape** — agents converged on: typed struct fields for first-class ops (generated via marker()/render() harvest of per-op slot declarations) + `HashMap<Arc<str>, Arc<dyn Any + Send + Sync>>` escape hatch for dynamic/plugin slots. Marshal tax is zero for codegen path, ~1ns for dyn Any downcast.

6. **Reads/writes are because of operators** — this session's closing refinement. Each op declares its own family of read intents and write effects. Not a central `enum ReadIntent`. Each op gets its own static enum (e.g. `RepoOp::Read { LsRemote, LsTree }`). Since ops are static (known at compile time until wasm bridge), associated types become viable — no `Arc<dyn Op>` constraint for this particular slot of the trait.

7. **Static-first, wasm-later for dyn** — commit to all-static ops for the foreseeable. The trait family methods that require assoc-types (read intents, write effects) can use assoc-types because the pipeline can monomorphize over a closed op set. Dynamic plugin ops come via a wasm boundary where the ABI is fixed and untyped by design.

## Solution / Approach

### Trait family (static ops, assoc-typed where useful)

```rust
pub trait Operator {
    // Parse-time / registration-time
    fn name(&self) -> &'static str;
    fn schema(&self) -> OpSchema { OpSchema::default() }
    fn projections(&self) -> &'static [Projection] { &[] }
    fn completion_item(&self) -> CompletionItem;
    fn parse(&self, inv: &OpInvocation, pctx: &mut ProgramCtx)
        -> Result<Pipeline, Vec<Box<dyn Diagnostic>>>;
    fn init_config(&self, slot: &mut ConfigSlot, inv: &OpInvocation) {}
}

pub trait Op: Send + Sync {
    // Per-cursor work. Runtime-dispatched today via Arc<dyn Op>.
    fn name(&self) -> &'static str;
    fn pipe(&self, input: BoxStream<'static, Cursor>, ctx: OpCtx)
        -> BoxStream<'static, Cursor>;

    // Per-cursor read intents (static op set → assoc type ok later).
    // For the dyn Op path, erase to Arc<dyn ReadIntent>.
    fn reads(&self, c: &Cursor) -> Vec<Arc<dyn ReadIntent>> { vec![] }

    // Per-cursor write effects. Collected post-pipe, drained at barrier.
    fn effects(&self, c: &Cursor) -> Vec<Arc<dyn Effect>> { vec![] }
}
```

Each op owns its own `ReadIntent` and `Effect` enum locally. No central variant list. The `dyn ReadIntent` / `dyn Effect` traits carry whatever dispatch methods the reader and effect bus need (`kind`, `key`, `execute`).

### Cursor shape — hybrid

```rust
// GENERATED by sprf codegen from per-op `// sprf:cursor_slot` decls.
pub struct Cursor {
    // Framework spine (hand-written, stable):
    pub run_id:   RunId,
    pub path:     SprfPath,
    pub evidence: Vec<OpEvidence>,
    pub captures: HashMap<Arc<str>, Capture>,

    // Codegen output (one field per first-class op):
    pub repo_state: RepoState,
    pub rev_state:  RevState,
    pub fs_state:   FsState,
    // ...

    // Plugin / dynamic escape hatch:
    pub slots: HashMap<Arc<str>, Arc<dyn Any + Send + Sync>>,
}
```

Codegen replaces a marker region; file is committed so rust-analyzer indexes it. Bootstrap: hand-written Cursor is the fixed point; codegen must regenerate byte-identical before cutover.

### DOM-validator grammar (schema)

```rust
pub struct OpSchema {
    pub allowed_parents:  &'static [&'static str],
    pub allowed_children: &'static [&'static str],
    pub arity:            Arity,
}
```

`lower_rules` validates the pipeline tree against schemas at parse time. Diags anchored at child's parse_site. Unlocks position-accurate LSP completion and declarative op-tree diagrams.

### Reads as declarative intent

Op emits `ReadIntent` values; runner plans/batches/dedupes/retries. Mockable at `Reader::dispatch(Arc<dyn ReadIntent>) -> BoxStream<ReadResult>` surface. No per-op mock boilerplate. Auto-coalescing when 500 cursors want the same blob. Op body only handles transform logic once data arrives.

### Writes as deferred effects

Symmetric to reads. `Op::effects(&Cursor) -> Vec<Arc<dyn Effect>>` collected post-pipe, drained at DAG-level barrier (existing Kahn levels in `_11_dag.rs`). Effect listeners are also ops. Closes the redux/rxjs loop.

### Side-effect taxonomy (react-query framing)

- **Reads** = queries: idempotent, cacheable, retry-able, parallelizable. Still syscalls with ordering constraints. `pipe` hosts them today; intent-descriptor move separates declaration from execution.
- **Writes** = mutations: serialized, flushed at barrier, reviewable. Live on the effect bus (Layer 5).
- **Read-audits** (last-read-at stamps, telemetry) are not mutations but still effects on external state. Route through effect bus with a `ReadAudit` variant the op declares locally.

## Key Insights

- Core grammar must never match on op names. Any `match "repo" | "rev" | ...` in core is a coupling smell. Ops register; core dispatches. This applies to the parser (provenance), walker brace parser, and anywhere else op names appear in central match arms.

- `ln -s` framing unifies captures (edges forward), cross-refs (edges sideways), and provenance (edges inward) into one "bind a value into a capture" primitive. One adapter (`expand_xrefs`) with a pluggable `SeedSource` enum covers all three. Provenance is same-cursor projection; cross-ref is other-rule row; capture is in-stream witness.

- Assoc types kill `Arc<dyn Op>` object safety; enum-over-variants (`enum Slot { Repo, Rev, ... }`) hits the central-enum violation; dyn Any downcast is ~1ns but ergonomically poor. Codegen of typed Cursor fields is the only path with zero dispatch cost and no central-enum tax. The "enum" becomes the generated struct layout, checked by the Rust compiler at build time.

- Static-first commitment is load-bearing. With no runtime-loaded ops, assoc types on `Op::Read` / `Op::Effect` become viable because pipeline storage can monomorphize. If/when wasm plugins arrive, they use a separate dyn-erased trait with a fixed wire ABI — the static path stays static.

- Reads are queries (react-query shape), writes are mutations. Both live on the effect bus with different semantics. Reads can coalesce/parallelize/retry; writes serialize and flush at barrier. Ops declare intent; runner schedules. Ops never call `tokio::spawn` or `buffer_unordered` directly.

- Rust's `BoxStream` already blends sync+async in the rxjs cold-observable shape. A ready item polls `Poll::Ready`; a syscall polls `Poll::Pending`. Downstream ops are oblivious. Hot sharing (multi-subscribe across rules) needs explicit `broadcast::channel` wrapping in the runner — op code stays cold.

- Marshal tax reality: pure str-universal HashMap cursor works for spine ops (repo/rev/fs) and string captures, breaks for tree-sitter handles, `Arc<Bytes>` content, and parsed JSON. Hybrid (codegen typed slots + `Arc<dyn Any>` HashMap escape hatch) is what both exploration agents converged on from opposite entry points.

## Open Questions

- `Arc<dyn Op>` vs generated `enum PipelineOp { Rule, Repo, Rev, ... }` for pipeline storage. Static enum unlocks assoc-typed `Read` / `Effect` but churns every pipeline-construction site. Bridge: keep `Arc<dyn Op>` and erase read/effect intents to `Arc<dyn ReadIntent>` / `Arc<dyn Effect>`. Revisit if the erasure cost shows up in profiling.

- Codegen conflict detection when two ops declare the same slot name. Needs diag at build time with both declaration sites.

- Circular slot type dependencies across op files. Rare but possible. Codegen must topo-sort or diag.

- LSP completion under schema validation: today LSP doesn't consult `Operator::schema()`. Wiring needed for position-accurate completion.

- DAG-level effect barrier: when exactly does the effect bus drain? End of each rule's pipeline? End of each Kahn level? End of the full run? Affects cross-rule-dependent write ordering.

- Read-intent dedup key shape: `(kind, repo, rev, glob)` for git reads; what for sh() and custom readers? Each intent type declares its own key via `fn key(&self) -> u64 { hash(&self) }` — but requires Hash impls per intent type.

- Provenance norm variants (`repo_norm`, `rev_norm`) are sibling projections, not a modifier grammar. Concrete question: does `RepoOp` register one projection with a normalizer lambda, or two projections with pre-computed state? Prefer two projections — the normalized form is pre-computed at slot-fill time (in `RepoOp::pipe` or the seeder), read-side is just a field access.

## Addendum: RTK slice analogy — plugin-ability as north star

User refinement late-session: each op is a Redux Toolkit (RTK) slice. RTK enforces a locality discipline — every slice declares its own state shape, its own reducers, its own selectors, its own async thunks, in one file. `configureStore({ reducer: combineReducers({ users: usersSlice.reducer, ... }) })` is the "monomorphization" step: a static registration list composes the slices into one store shape. Redux "forces" this because JS has no compile-time type-family aggregation — the reducer map is the combinator.

Same constraint applies in Rust for the reasons established above (assoc types kill dyn, central enums violate op-owns-everything, marshal tax is real for pure-str). Codegen of the Cursor / Config / PipelineOp aggregates is the `combineReducers` equivalent. Each op file is a slice. The codegen pass is the `configureStore` call.

**Plugin-ability = adding a slice = additive-only change.** Drop a new `v2/src/ops/_N_foo.rs` with its `// sprf:cursor_slot` and `// sprf:config_slot` markers; run codegen; the aggregate types regenerate with a `foo_state` field and a `foo` config slot. Nothing central edited. Registry picks up the factory via the existing `OperatorRegistry::register` path. This is what RTK's `createSlice` ergonomic achieves via JS's dynamic object composition; Rust gets there via text-level codegen.

**Runner = store dispatcher + reactive middleware.** Routes read intents (queries), drains write effects (mutations), schedules DAG levels, manages broadcast for hot-sharing. Ops do not care about timing, batching, dedup, retry, or backpressure — those are runner policy. Ops declare; runner routes.

**Cross-op references (actions between slices).** RTK slices reference each other's actions by type string (`"users/fetchAll.fulfilled"`); any reducer can listen. In sprf, cross-ref (`${rule.$X}`) and projections (`$$repo`) are the analogous cross-references: one op's output becomes another op's input by stable name. The ResultStore is the "subscribed selector" layer. The DAG is the static dependency graph the runner uses to schedule.

**Where the analogy helps design:** when sketching a new trait method on `Op`, ask "would RTK put this on the slice or in the store config?" If slice → trait method with default. If store → runner concern, stays out of the op file. Keeps the line clean.

**Where the analogy stops:** RTK is JS + Immer; mutations to state are in-place under the hood with structural sharing. Rust needs explicit `Arc<T>` or `im::HashMap` for that shape. Cursor clones in Fork broadcast are the moral equivalent of a state selection — they need to be cheap. Current `HashMap<Arc<str>, Capture>` clone is ~80-150ns per cursor at 5 captures. Revisit `im::HashMap` (HAMT, O(1) clone) if profiling shows Fork broadcast hotspot.

**North star restated:** slice-locality + codegen-combinator + runner-as-routing-middleware. That's the plugin-ability contract. Static-first today (no wasm), wasm bridge later for true drop-in external ops. Until then, adding an op is: write file, run codegen, done.
