## Solution/Approach
**Daemon-stateful-revs (d30e39a):**
- Meta tables in `ensure_meta`: `_program(path PK,hash,mtime,loaded_at)`, `_repo(slug PK,root,url,registered_at)`, `_ref((repo,name) PK,oid,observed_at)`, `_rev_log(id,repo,name,old,new,at)`.
- Engine methods: `save_program_meta`/`save_repos_meta` (plural wipe+insert seam), `observe_ref` (git rev-parse name → compare `_ref` cursor → persist + append `_rev_log`; returns `Option<(old,new)>`), `files_changed_between` (git diff old..new ∩ `_file` path index), `refresh_daemon_rels` (pub; projects the 3 tables into query rels).
- Query rels `program`/`head`/`rev_advanced` via `daemon_rel_decls()` + `DAEMON_RELS` const; declared in declare_builtins, reserved-name-guarded, refreshed in tick+tick_paths when `daemon_rels_used`, in schema RPC. `unix_secs()` helper added near `mtime_secs`.
- Daemon: cold tick calls save_repos_meta+save_program_meta; watcher ALWAYS watches `.git` of self+every config repo (`watch_git` closure, `git_dirs` vec); a `.git` move routes to `on_git_event` (observe HEAD + program rev literals via `watched_ref_names`, diff, broadcast `rev_advanced` JSON-RPC notification — DETECT+EMIT, NO re-tick) and `continue`s past tick branches; hot-reload/discovery re-persist `_program`; config change re-persists `_repo`; new `status` RPC dumps programs/repos/refs/recent advances.
- Tests `tests/daemon_stateful_revs.rs` (2 green): observe_ref advance tracking, files_changed_between, query-rel projection, reserved-name guard. NOTE `_file` only populated by a `scan` source rule (not by joining builtin `file`), so the test program must scan.

## Key Insights
- `_file(repo,path,rev)` is the file-path index; `repo` slug = nearest-.git basename; WORK = on-disk working tree (read_content rev=="WORK" → fs::read; else git_batch_read at the commit).
- pathstyle = `Term::PathLit{scheme,body,span}` lexed as `Tok::Scheme` (lex_scheme_body: fenced backtick OR bare with balanced ()[]{}). v5 lexer has NO bare {}/[ ] tokens — so declarative json should ride PathLit, not new brace tokens (which collide with contested cons/{} grammar).
- Style: never per-row writes (insert_rows/refresh_rel/plural seam); engine MAY use std::time; one rel = one rule kind; no provenance/substrate/load-bearing/regime identifiers.
- Repo-qualified syms (364de80): call_site.caller/call_name.sym are repo-qualified (`{repo}::file::kind::name`), but dataflow rels (df_node.fn/loop_over.fn/allocates.fn) stay BARE — a join across them needs a containment bridge (replace/split string fns, only parse on RHS of `var = expr`).
