# Stream-of-Lists Design Memo

Scope: evaluate whether the v2 `Op::pipe` signature should move from
`Stream<Cursor>` to `Stream<Arc<[Cursor]>>` or to a hybrid batch-with-id.

## 1. Three pipe signature alternatives

### (A) Today: `BoxStream<'static, Cursor>`

```
rev(HEAD)   fs(**/Cargo.toml)              repo(myorg/*)
   |              |                              |
   |  C0 ────▶    |                              |
   |          fan-out                            |
   |              ├── C0a (fs=a/Cargo.toml) ─▶   | keep
   |              ├── C0b (fs=b/Cargo.toml) ─▶   | keep
   |              └── C0c (fs=c/Cargo.toml) ─▶   | DROP (repo mismatch)
   |              |                              |
                  ▼                              ▼
           stream: [C0a, C0b, C0c]        stream: [C0a, C0b]
```

Every cursor is a scalar item in the stream. Fan-out uses `.then().flatten()`
(`ops/_3_fs.rs:213-243`, `ops/_5_json.rs:294`). Filters use `.filter()`
(`ops/_1_repo.rs:156`). The three siblings C0a/b/c have no group identity
once they enter the stream.

### (B) Proposal: `BoxStream<'static, Arc<[Cursor]>>`

```
rev(HEAD)           fs(...)                  repo(myorg/*)
   |                   |                          |
   | [C0] ──▶      fan-out → one batch            |
   |                   ▼                          |
                 [C0a, C0b, C0c] ──▶ per-elem filter
                                              ▼
                                    [C0a, C0b]   (same batch, shorter)
```

One batch per upstream fan-out point. Filters shrink the batch in place;
maps rewrite in place; fan-out ops emit one `Arc<[Cursor]>` per input
cursor instead of N scalars. Empty batches become `Arc<[]>` and are
either dropped or propagated as "this seed produced nothing".

### (C) Hybrid: `BoxStream<'static, CursorBatch>` with identity

```
struct CursorBatch {
    origin: BatchId,          // u64, minted at fan-out site
    parent: Option<BatchId>,  // for nested fan-outs
    cursors: Arc<[Cursor]>,
}
```

```
fs emits:                      repo filter:              json walker:
  batch{id=7,                    batch{id=7,                for batch{id=7}:
    parent=None,                   parent=None,               walker yields rows
    cursors=[C0a,C0b,C0c]}          cursors=[C0a,C0b]}        nested batch{id=42,
                                                                parent=7,
                                                                cursors=[rowA,rowB]}
```

Every batch carries a stable id. Downstream ops that need to group (e.g.
"these three json rows all came from the same Cargo.toml") read
`origin`/`parent`. Filters preserve `origin`; fan-out mints a new
`origin` and records the `parent`.

## 2. Implicit forking semantics

Pattern: `json({a:{x:$X}, b:{y:$Y}})` against `{"a":{"x":1},"b":{"y":2}}`.

The walker today (`walk/_3_walker.rs:540-563`, `row_split_siblings_in_separate_subtrees`)
emits two rows, one binding `$X`, one binding `$Y`. These are siblings
from the same file.

| Model | Downstream sees | Group identity |
|-------|-----------------|----------------|
| (A)   | two separate cursors interleaved with every other file's cursors | lost; must reconstruct via `cursor.fs + cursor.rev` |
| (B)   | one `Arc<[Cursor]>` of length 2 per file | preserved by list-membership |
| (C)   | one batch `{origin=walker_site_N, parent=fs_emit_M, cursors=[...]}` | explicit; downstream can `group_by(origin)` without touching cursor state |

(A) needs a composite key (`repo, rev, fs, parse_site`) to recover
group identity. (B) encodes it positionally inside one stream item,
which works as long as no op in between breaks the batch apart. (C)
names the group, which survives re-chunking.

## 3. Downstream consequences

### `Op::witness(c: &Cursor) -> Option<Arc<str>>`

Per-cursor label used for `OpEvidence`. Under (B) it becomes
`witness_all(&[Cursor]) -> Vec<Option<Arc<str>>>` or stays per-cursor
and is mapped across the batch by the framework. Under (C) same, plus
the evidence entry can record `origin`.

### `hover_capture(&self, cap, cursors: &[Cursor])`, `hover_match(&self, site, cursors: &[Cursor])`

Already slice-shaped (`ops/_1_repo.rs:122,136`, `ops/_3_fs.rs:152,166`,
`ops/_5_json.rs:121,139`). Under (B) the LSP-side aggregator would either:
flatten batches back to a flat slice (trivial, loses grouping), or change
the trait to `&[&[Cursor]]`. Flattening is fine for hover today because
hovers already re-group by `(fs, rev)` manually.

Under (C) hovers gain a `by_origin()` helper: the json op's
"group siblings from the same file match" becomes a one-liner instead
of the current `flat_map(|c| c.evidence.iter()...)` dance
(`ops/_5_json.rs:141-152`).

### Per-cursor diagnostics

`json/no-match` fires per file (`ops/_5_json.rs:255`), `fs/no-match`
fires per seed (`ops/_3_fs.rs:222`). Both are already batch-aligned:
"this input cursor expanded to N outputs, and N was 0". Under (B) each
input batch produces one output batch; the diag fires when the batch is
empty. Under (C) same, but with `origin` attached to the diag for
cross-referencing back to the input.

### Evidence appending

`cursor.evidence: Vec<OpEvidence>` is leaf-first, append-once per op
traversal (`_0_types.rs:126`). Under (B) every cursor in a batch still
gets its own evidence appended; no change. Under (C) the evidence entry
can include the `origin` id so LSP grouping is cheap.

## 4. Future operators

**md (markdown path enumeration).** Natural fan-out: one file produces
N sections or N headings. Same shape as fs. (B) and (C) both fit
cleanly. (C) wins only if downstream ops need to say "all headings
from the same document" without consulting `cursor.fs`.

**ast-grep.** Multi-match per file, and metavariables often fork inside
one file. Example: `match($X)` on a Rust file with 8 match expressions
yields 8 cursors. Under (A) these are 8 scalars. Under (B) one batch of
8. Under (C) a batch with `origin=ast_grep_site_K, parent=fs_emit_M`
and siblings are grouped by origin.

The fork problem is sharper here: if you write
`ast_grep({ fn $F() { $X } })` and $F binds to "foo" in 3 matches and
"bar" in 2 matches, are those 5 cursors one batch, two batches, or
five? (B) gives you the raw list. (C) lets ast-grep choose its
grouping: one batch per file, one batch per $F value, etc.

## 5. Migration cost

Inventory of `pipe` impls under `v2/src/ops/`:

| Op | Shape today | Class under (B)/(C) |
|----|-------------|---------------------|
| `_1_repo.rs` | filter or map on scalar | mechanical rewrap: `batch.iter().filter(...)` |
| `_2_rev.rs`  | filter/map/expand over rev list | fan-out → batches cleanly |
| `_3_fs.rs`   | `then().flatten()` fan-out | **genuinely benefits**: one batch = one (repo,rev) seed |
| `_4_rule.rs` | seed producer | seed batch of size 1 per (repo,rev,rule) |
| `_5_json.rs` | `then().flat_map(stream::iter)` | **genuinely benefits**: one batch per file, walker rows already grouped |
| `_6_line.rs`, `_7_xref.rs` (and friends) | per-cursor map | mechanical rewrap |

Nothing in the current op inventory needs to *break* a batch mid-stream.
The closest case is the xref join, which consumes a cursor and emits
zero or more joined cursors; that's still a per-input fan-out.

## 6. Recommendation

Pick **(C), hybrid with batch identity**, but implement it as a thin
shell over (B): start by moving the signature to `Arc<[Cursor]>`, and
add an `origin: BatchId` alongside once the second op (ast-grep or md)
demands group-identity that can't be reconstructed from cursor state.

Key insight driving the pick: the walker already produces grouped
output (`WalkOutcome { rows }`), and the json op immediately flattens
that grouping into the scalar stream
(`ops/_5_json.rs:273-294, flat_map(stream::iter)`). Every downstream
consumer that wants the grouping back pays a re-group cost by composite
key. (B) preserves the grouping for free at the boundary; (C) names it
so it survives re-chunking.

Would change the pick to (B)-only if: batch identity turns out to be
unused outside the json/ast-grep row-split case, or if `BatchId`
bookkeeping contaminates every op's `pipe` body. Would fall back to
(A) only if the batch-level empty-drop semantics collide with
partial-eval LSP needs (a truncated pipeline mid-batch wants to emit
each cursor individually so the wildcard tail can fan them out
independently).
