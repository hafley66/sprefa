# Session: v2-grammar-paths

## Goal
Stand up `rule` / `repo` / `rev` end-to-end with the v2.1 grammar (no `$`
prefix, `>` pipe, `;` distributes-parent), wire framework path-tagging on
cursors, and fix brace re-parse to use `ParseSeg::BraceChild`.

## Outcome

- `rule(demo) { repo(myorg/*) > rev($V); repo(other/*) > rev($V); }` parses,
  lowers, runs, writes 4 rows into `__demo` table.
- Each cursor carries a SprfPath like
  `[Op(repo,step=0), Op(rev,step=1), ForkArm(0), Op(rule,step=0)]`.
  Order is leaf-first (last seg = innermost wrapper). Document later if it
  bites; identity + set are correct.

## Grammar locked (v2.1)
```
program := stmt*
stmt    := chain ';'?
chain   := op ('>' op)*
op      := IDENT ('[' bracket ']')? ('(' paren ')')? ('{' brace '}')?
brace   := stmt*
```
- `#` line comments
- `$NAME` / `$$prov` / `${rule.$V}` are leaf tokens classified by ops
  (host parser never looks at them)
- `>` lowers to `Pipeline::Seq` within a chain
- `;` between pipes inside a brace lowers to `Pipeline::Fork` (distribute
  parent — each pipe runs against parent's cursor stream, results unioned;
  v1's "monomorphization" semantics, renamed)
- single-pipe brace = that pipe directly, no wrapper
- top-level statements: each becomes its own Pipeline (caller composes)

## Key decisions / discoveries

- **No `$` prefix on op names.** v1 syntax restored. `$NAME` etc. live only
  inside paren content, not at the op level.
- **Pipe vs Pipeline naming.** `Pipe` = parser-time `>`-chain of
  `OpInvocation`. `Pipeline` = runtime tree (`Op | Seq | Fork | Switch`).
  Renamed from `Statement` after user pushback ("call it pipe since it's
  rx coded").
- **Brace `;` = distribute-parent (Fork).** All pipes share the parent's
  cursor stream, results unioned. Schema = union of all captures across all
  pipes; missing captures → NULL columns. Wide-with-NULLs.
- **Framework owns SprfPath.** Ops never touch `cursor.path`. Pipeline::Op
  wraps with `Op{name,parse_site,step}`; Pipeline::Fork wraps with
  `ForkArm{index, parse_site}`; Pipeline::Seq passes through, threads step
  index. Order is leaf-first (post-emit append).
- **Pipeline::Fork carries `ForkBranch { parse_site, pipeline }`.** Arm
  identity = first op's parse_site (which is `<rule>/BraceChild[N]/...`
  thanks to brace re-parse).
- **Brace re-parse uses BraceChild.** New `host_parse_brace(src, file,
  parent_path)` takes the enclosing op's parse_path; emitted child
  ParseSites are `<parent>/BraceChild[N]/...`. Top-level `host_parse` still
  uses `Top[N]`.
- **Op-owned diagnostics.** Per `feedback_op_owns_everything`, RuleDiag,
  RepoDiag, RevDiag live in their own op modules. No central enum. Code
  strings like `"rule/missing-name"`, `"repo/bad-arg"`.
- **Reader/Writer surface fully restored.** Earlier mistake of
  trait-trimming for scope was reverted; methods unused this pass are
  `unimplemented!()` in MemReader/MemWriter.
- **Path-tagging direction.** Currently leaf-first (post-emit append). Pure
  prepend or top-down threading would give root-first but require either
  reordering inner-op ordering or threading `parent_path` into Op::pipe
  (violates "ops never touch path"). Leaving as-is; document convention.

## Soft spots / deferred

- **Path order.** Leaf-first today. If routing needs root-first, switch to
  top-down `parent_path` threading (clean but requires Op::pipe param OR
  inverting the wrapping point).
- **`Pipeline::Switch`.** `unimplemented!()`. `ChannelSelector::PathSegment`
  + `path_hash_static` are the building blocks for path-routed switching.
- **Branch-provenance column.** Rows don't carry which Fork arm produced
  them. Either add `pipe_index INTEGER` (read from `PathSeg::ForkArm`) or
  let users query a `path_str` debug column. Defer until real check rules
  need it.
- **`unused field RuleOp.name`.** Carried for diagnostics later; will
  silence when first used.
- **`fs` op + file-reading Reader methods.** Trait surface exists, mem impl
  panics. Next session.
- **Top-level multi-pipe behavior.** `lower_rules` puts each top-level
  pipe in its own `Pipeline`. The Runner / CLI decides how to compose
  (independent rule definitions, no Fork at the top).
