## Problem/Context
Previous session proved parse cache alone made g4 slower (484→624 ms) because parse ran synchronously on tokio worker and 4 concurrent exprs all missed the cache together. Fix: tokio::sync::OnceCell per cache slot + spawn_blocking for parse. First caller parses, others await.

flush_batch was 2800 sequential SQL roundtrips per run (per-string + per-repo + per-file + per-row INSERTs, each with its own SELECT). 61 ms / 294 ms = 21 % of wall.

GitBlobReader revparsed per bytes() call — 441 redundant revparses. Mutex<Repository> still serializes all blob reads.

Content dedup: 4 revs × mostly-identical blobs = 242 duplicate parses. blake3 of bytes → by-hash OnceCell catches them.

## Solution/Approach

### mergeMap expr levels (_7_init_cursors.rs)
- `InitInputs` gained `expr_levels: Option<Vec<Vec<usize>>>`. None → sequential (one per level), preserves analysis.rs + test semantics.
- Extracted `drain_one_expr` helper; outer loop spawns one tokio task per expr in level, `join_all` waits level, then advances.
- `server/_3_run.rs::build_expr_levels` builds levels from `outcome.pctx.rules` via `_11_dag::build`. Unnamed exprs fold into level 0. Cycle → one-per-level fallback; analysis.rs already diags the cycle.

### Parse cache (readers/_4_parse_cache.rs, new)
- Two-level OnceCell: primary slot keyed by (repo, rev, path, kind); secondary keyed by ([u8;32] blake3, kind).
- Primary slot loads bytes once; hashes; looks up secondary. Hit → reuse tree without parse. Miss → parse (inside spawn_blocking) and insert by hash.
- Payload is `Arc<AstGrep<StrDoc<SupportLang>>>` downcast from `Arc<dyn Any + Send + Sync>`.
- `parse_payload_sync` exposed `pub(crate)` so MemReader can implement `parsed()` too (tests need it).
- Wrapped workspace.reader in ParseCacheReader inside run_pipeline.

### ast op (ops/_9_ast_grep.rs)
- `prep_cursor` takes `lang`, PATH C calls `reader.parsed()`, stashes `Arc<AstGrep>` in `Prep.cached_grep`.
- `process_one` skips local parse when cached_grep is Some. PATH B (byte_range slice) still parses locally in rayon.
- `lang_to_kind(SupportLang)` → ParserKind.
- Both parse paths (rayon local + spawn_blocking cache) call `record_parse(len, t0)`.

### GitBlobReader revparse cache (readers/_2_git.rs)
- `trees: Mutex<HashMap<(String, String), Oid>>`.
- `tree_oid(repo_slug, rev, &repo)` — cached revparse_single → peel_to_commit → tree_id.
- `open_repo` now takes &str, no Arc::from allocation on lookup.
- bytes / bytes_range / files all go through `tree_oid` → `find_tree(oid)`.

### Bulk flush_batch (store/_2_sqlite.rs)
- Strings: one `INSERT INTO strings VALUES (?,?,?),…  ON CONFLICT(value) DO NOTHING` per 400 chunk, then one `SELECT id, value FROM strings WHERE value IN (?,…)`. Match Arc<str> back by string eq.
- Repos: same pattern with ON CONFLICT(name).
- Files: bulk INSERT with ON CONFLICT(repo_id, path, content_hash) (schema already has the 3-col unique). SELECT by (repo_id, path) IN ((?,?),…).
- Rows: per-expr `push_values` with `rows_per_chunk = 30_000 / cols_per_row`, capped 1000. Each expr single-INSERT today (cols × rows < 15k).
- Used `sqlx::QueryBuilder::<sqlx::Sqlite>`.

### Tic-toc (always on)
- `PARSE_COUNT / PARSE_NS / PARSE_BYTES` atomics in parse_cache module; `record_parse(len, Instant)` at every parse site (cache path + ast PATH B local).
- `parse_stats_snapshot()` swap-returns (count, ns, bytes) and resets.
- `run_pipeline` prints a `[timing] parses … 199 files, avg N us, KB` line before stream_total / run_pipeline TOTAL.
- `init_cursors` prints `[timing] flush_batch N ms (rows across exprs)` when SPREFA_TIMING set.

### Smoke helper
- `v2/tests/smoke/_2_many_rules_timed.sh` starts the server with `SPREFA_TIMING=1` in its env (regular `_2_many_rules.sh` sets it on the CLI, which has no effect), dumps `[timing]` lines after the run. Keeps the user from approving ad-hoc `bash -c` invocations for measurement.

## Key Insights

- **mergeMap by itself barely moves debug** (6125→5278 ms) because CPU is saturated; release (580→484 ms) shows the overlap gain. Tokio + rayon share cores; N parallel CPU-heavy tasks on an N-core box = N×slower per task, so total ≈ slowest, not sum/N. Parallel wins come from IO overlap + dedup.
- **OnceCell is load-bearing** for parse cache. Without it, concurrent miss = all callers parse. RxJS analogy: Subject.shareReplay(1) over a lazy observable — first subscriber triggers, others attach.
- **Content-hash dedup is orthogonal to path-slot dedup.** Path slot: within one (repo,rev,path) one parse. Hash slot: across paths with identical blobs, one parse. g4 went 441→199 parses — about half the files unchanged across 4 revs.
- **Reader::parsed() existed but was unimplemented on MemReader + GitBlob.** ParseCacheReader wraps them and populates. Tests were passing MemReader directly and hit unimplemented!() — fix was to delegate MemReader::parsed() to the same parse_payload_sync. Two call paths, one parser.
- **sqlx QueryBuilder.push_values + ON CONFLICT … DO NOTHING + WHERE IN SELECT** is the clean bulk-upsert pattern. One chunk = two roundtrips (insert + select) regardless of row count. SQLITE_MAX_VARIABLE_NUMBER is 32766 on modern builds but 999 on older; chunk defensively at ~400 values.
- **tree_oid cache lives inside GitBlobReader, not a separate wrapper.** Putting it on the reader itself avoids a second layer of wrapping for the server Reader stack (which is already blob → WT overlay → buffer → parse cache). Four wrappers vs five is a readability win; the cache is intrinsic to how a git-backed reader should work.
- **Parse payload = `Arc<AstGrep<StrDoc<SupportLang>>>`.** AstGrep is Send+Sync (verified by compiler). Downcast from Arc<dyn Any + Send + Sync> is the cheap-enough generic escape hatch; per-kind payload typing can land later if another op starts downcasting.
- **Tic-toc should be always on, not feature-gated.** One AtomicU64 fetch_add per parse is nanoseconds; cost of "I wonder if we parsed X" is minutes of wiring + rebuild every time. PARSE_COUNT/NS/BYTES now always record; only the eprintln is behind SPREFA_TIMING. Snapshot resets between runs.
- **Revparse in a bare git repo is cheap** (~0.05 ms), which is why the cache saved only ~23 ms — it's the mutex serialization, not revparse CPU, that actually gates bytes(). The proper fix is an N-handle pool.

## Open Questions
- N-handle pool size K: num_cpus? fixed 4? Or promote to odb().read() path after tree resolution? Need a benchmark with K=1,2,4,8 to pick.
- blob_oid as Reader trait method — changes MemReader's signature too. Default impl returning None + override on GitBlobReader is cleanest, but adds a method to every impl. Worth it when cross-rev is the workload shape.
- Interning strategy: Workspace-held `ArcInterner<str>` or a global `string_cache::DefaultAtom`? The former scopes to a workspace reload, the latter is process-wide and never frees.
- Persistent parse cache: how to key across runs? (repo slug, blob oid, kind) is immutable — LRU on disk would reuse between LSP reparses. Cost: serialize AstGrep tree, which ast-grep-core doesn't expose; falls back to re-parsing from bytes keyed on oid. Reader-level oid fast path solves this too.
