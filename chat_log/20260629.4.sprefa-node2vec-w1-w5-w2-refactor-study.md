## Key Insights
- node2vec rides closure/scc seam; W1 copies their ConditionCache.digest guard.
- DAEMON HIJACK: a running `dl --daemon` makes ad-hoc `dl prog --root .` return
  the daemon's OWN loaded program (saw `? diag` for unrelated programs). Always
  use --no-daemon for exploration runs.
- call_edge is a RESERVED builtin name; name your call-graph rel `cedge`.
- VALIDATION KILLED the scatter metric: reordering engine.rs by name-family makes
  caller<->callee distance WORSE (median 18 -> 60, ~random 80). The file is
  already laid out by CALL LOCALITY (3x better than random placement). "Gather by
  name" would hurt. A metric must beat random AND not worsen call-distance.
- The self-call graph is a DAG (0 multi-member SCCs) -> cuts won't break cycles.
- impl core has NO cheap balanced cut (~35% of call traffic crosses any), and
  64% of that is just tick/tick_paths calling outward = a facade boundary.
- THE WINNER: signature-shape buckets (receiver,#args,return) expose latent
  TRAITS. 19 rel families each have X_rel_decls + X_rels_used + refresh_X_rel
  (~60 methods, 106 hand-written self.refresh_* dispatch calls) = one `RelKind`
  trait + 19 impls + a registry loop. Plus `BodyOp` (scc/node2vec/closure evals)
  and sub-structs (repos/closure_cache/gen_journal/rev_cache from field coupling).
- REFRAME: node2vec pass-1 "refresh_* supercluster" I dismissed as "same role"
  WAS the RelKind trait. same role = same trait; wrong frame (split) hid it.
- Cross-file: generated ast_builder.rs scatter 3.6 (control), sqlite3.c 90%
  naming coverage, script.js scatter 32.8. Low coverage (<=25%, world-info.js
  20%) is the ONLY regime where the embedding earns its keep.
