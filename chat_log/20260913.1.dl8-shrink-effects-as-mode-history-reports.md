## Solution/Approach
Effects design converged (nothing built):
- An effect is a relation with a mode and no producing rule = external relation. Two lines: `(: fetch_json (* (: url text) (: body json)))` + `(mode fetch_json (url))`. No `Effect` keyword, no clock column, no `Host` template, no probe. Pending rows = input-only rows, settled rows = full rows (names: pending/settled). Watchers and intervals are external relations with no inputs (`fs_change`, `tick`). Runner binds names like `Kernel::of`.
- Cancellation is retraction: a child `want` row derives from the parent's settled row; parent replaced -> cascade retracts -> runner aborts. switchMap/mergeMap = derivation + keys; only `exhaust` and `concat` need a policy word. Nesting = scope column = parent key. Reconciler = the `apply` half of `reduce_then_apply`, state `HashMap<(Kind, Scope), Vec<Key>>` + task handles, one module in dl8, the only impure component.
- rx operators as rule shapes (map/filter/merge/expand/scan/combineLatest/takeUntil/finalize/share -> existing v6/v7 constructs); expand = recursive rule under semi-naive; sequence semantics via `seq` index when needed. Library = term store + fixpoint + mode checker + reconciler + prelude; dl8 is the first three.
- dl8 lacks retraction (monotone by design); runtime needs delete-rederive (v6 `lower.pl:4517`) or signed rows: a lab decides.
- Anti-unification (lgg) as prelude rules over cons/intern, holes interned so repeated clashes share a hole; distance = hole count or subtree sizes. Pattern/Capture (full names) = tree-sitter-style query term that is also a template (match forward, build backward).
- Term store today: Int, Atom, Str, Compound; floats and bools missing; null never enters storage (v6 ruling 2026-07-30), absence = no row, `Option` in prelude.
