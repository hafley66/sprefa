# runtime_graph.rs audit + canonical shape

Audit target: `v4/src/runtime_graph.rs` @ 1688 LOC. Branch `main`. Read-only.

## TL;DR

- Today: 4 node kinds, 3 edge kinds, 4 aux types, ~25 public verbs, 1688 LOC
- Three primitives have **zero** non-test call sites: `ActiveEdge`/`replace_active_child`/`active_child`, `edge_values`, `VisibleDelta` (returned then dropped)
- `OutputNode` is only declared from `mounted_query.rs:402`; the type adds nothing over an `Arc<str>` URI
- The runtime is one bipartite Owner-Source graph plus a row-support graph with the same backing table; the rest is bookkeeping that can collapse onto subscribe+support+retract
- Canonical proposal: 2 node kinds (Owner, Table), 2 edge kinds (Subscribe, Support), 1 aux (Continuation), ~600-900 LOC

## `RowNode` vs `OutputNode` distinction

| Site | Loadbearing? | Note |
|------|--------------|------|
| `v4/src/runtime_graph.rs:106` | `RowNode` def | has extra `row_key` field |
| `v4/src/runtime_graph.rs:100` | `OutputNode` def | identical fields minus `row_key` |
| `v4/src/runtime_graph.rs:420` | `declare_row` builds RowNode + MEMBER_OF edge to table | row_key participates in URI |
| `v4/src/runtime_graph.rs:1206` | `row_node` reads back | row_key reconstructed from INPUT_KEY column |

**Verdict:** `OutputNode` is a Table; `RowNode` is a Row. They share the URI/uri_id shape and live in the same `RUNTIME_NODE` table distinguished by `node_kind_id` ("output" vs "row"). The Rust types are redundant decoration. Row identity is `row_key` = blake3(table_uri ‖ cursor_codec(payload)). The MEMBER_OF edge from row to table is what makes a row "belong" to a table.

The distinction is **decorative** in Rust but **loadbearing** in the schema: queries filter on `node_kind_id`. Canonical shape: keep the kind column, drop the Rust types.

## 2.2 Lifecycle of a rule firing

Source S becomes dirty (e.g. file change, table insert):

```
  caller                runtime_graph                      facts (durable)
  ------                -------------                      -----
  dispatch_source_wake
       |
       +--> declare_source(uri, g)  ----------------------> RUNTIME_NODE [+]   (idem)
       |
       +--> dispatch_dirty
              |
              +--> runtime_value_dirty(S, g) -------------> RUNTIME_VALUE [+]  (ephemeral)
              |
              +--> dispatch_wake(S, value, g)
                     |
                     +--> append_source_event ------------> RUNTIME_EVENT [+]  (durable until consumed)
                     |
                     +--> incoming_subscribe_edges(S)     [read]  RUNTIME_EDGE
                     |       for each (owner, edge):
                     |           record_edge_value -------> RUNTIME_EDGE_VALUE [upsert]
                     |
                     +--> enqueue_jobs_for_unconsumed_events
                              for each event * each sub:
                                  insert_job ------------> RUNTIME_JOB [+]    (pending)

  GraphReplayRunner.drain()  (later, separate call)
       |
       +--> pending_jobs ----------------------------------> RUNTIME_JOB [read]
       |
       +--> for each job:
              continuation_for_owner ----------------------> RUNTIME_CONTINUATION [read]
              re-run pipe with replay cursor (effect_runtime)
                  -> may insert row facts (RUNTIME_NODE row kind)
                  -> may call replace_supports
                        -> RUNTIME_EDGE [+/-]  (SUPPORT edges)
              mark_job_done -----------------------------> RUNTIME_JOB [upsert state=done]
              if last job for event:
                  mark_event_consumed ------------------> RUNTIME_EVENT [upsert consumed=1]
```

Durable: NODE, EDGE, CONTINUATION (across process restart).
Ephemeral within a generation: EVENT (until consumed), JOB (until done), VALUE, EDGE_VALUE.
Dead path: ACTIVE edges (no source writer), DIRTY kind (constant defined, no writer).

# Phase 3: Canonical shape proposal

## Target shape

```
   2 node kinds:        Owner       Table
   2 edge kinds:        Subscribe   Support
                        owner->table        owner->row
                                            (Row is a Cursor under Table)

   1 aux:               Continuation  (owner_id -> {pipe_hash, instance_id, depth, cursor})

   wake signal:         dirty bit on Subscribe edge, no separate VALUE/EDGE_VALUE/EVENT/JOB tables
                        (replay queries: SELECT owner FROM subscribe WHERE dirty)

   row identity:        (table_uri, blake3(cursor_codec(row_payload)))
                        Rows live inside the fact-store, not as separate nodes.

   commit boundary:     FactStore::insert_batch + FactStore::delete_matching
                        Only these methods are non-pure; everything else is reads + diffs.
```

Total: 2 + 2 + 1 = 5 schema objects (down from 4 + 3 + 5 = 12).

## Per-deletion recovery

### Deleting `ActiveEdge` (switchMap)

Today:
```
replace_active_child(owner, "active-inner", child_a, gen=1)
replace_active_child(owner, "active-inner", child_b, gen=2)
  -> retract_owner_runtime(child_a) recursively
  -> ACTIVE edge swapped
```

Canonical:
```
// switchMap chooses which inner pipe is "live".
// The parent owner re-renders on its own dirty signal and emits a
// support set for table T. The inner child IS the parent's render,
// not a separate owner. switchMap reduces to:
//
//   parent_render():
//     value = read(subscribe_edge.value)
//     inner_rows = inner_pipe(value)        // pure call
//     replace_supports(parent_owner, T, inner_rows, gen)
//
// retraction of old inner is automatic: replace_supports diffs old
// vs new and emits the retracted set.

// If "child owner" identity matters for blame/debug, encode the
// previous-vs-current child as a column on the support row's payload
// or a tag on the Subscribe edge label. No ACTIVE edge needed.
```

### Deleting `RuntimeValue` / `EDGE_VALUE`

Today: each subscribe edge stores the last-seen value as a row in `RUNTIME_EDGE_VALUE`.

Canonical: values travel with the wake call and are read fresh from the source-of-truth at render time. For `read(path)` the source-of-truth is the filesystem (or the file fact table). For a table subscription, the source-of-truth is the table itself. No copy in the runtime graph.

If a pipe truly needs cached value (combineLatest), store it in the **fact-store** under a derived table, not in the runtime graph. The cache is a Subscribe edge whose label points to that derived table.

### Deleting `RuntimeEvent` + `RuntimeJob`

Today: two ephemeral tables tracking (source_change -> owner_reaction).

Canonical: one boolean `dirty` column on each Subscribe edge.

```
wake(source_uri):
  UPDATE runtime_edge
     SET dirty = 1, dirty_gen = :gen
   WHERE kind = 'subscribe' AND to_uri_id = :source_uri_id

drain():
  loop:
    let owners = SELECT DISTINCT from_uri_id
                   FROM runtime_edge
                  WHERE kind = 'subscribe' AND dirty = 1
    if owners.empty: break
    for owner in owners:
      re-render owner from continuation
      UPDATE runtime_edge SET dirty = 0 WHERE from_uri_id = owner

  // Equivalent to today's drain loop but no separate JOB/EVENT tables.
```

The 1:N event:job structure today is gone: each subscribe edge is its own dirty flag, no parent event row.

### Deleting `VisibleDelta`

Today: returned from `replace_supports`, mostly thrown away.

Canonical: `replace_supports` returns nothing. Callers that need the delta query the fact-store directly. If a hot path needs the per-call delta, return it; otherwise drop the type.

### Deleting `OutputNode` and `declare_output_table`

Today: a Rust wrapper around a table URI plus a row in `RUNTIME_NODE` with kind=output.

Canonical: just a `&str` (or `Arc<str>`) URI. No node row. The table is whatever fact-store table the SUPPORT edge's label points to. Existence of the table is established by the fact-store schema, not by an entry in `RUNTIME_NODE`.

### Deleting `RowNode` / `declare_row` / `MEMBER_OF`

Today: row identity = blake3(table_uri ‖ cursor_codec(payload)), stored as a node + MEMBER_OF edge.

Canonical: row identity = same hash, but row lives in the fact-store table directly. The SUPPORT edge points to a `(table_uri, row_hash)` pair, not a separate Row node. `MEMBER_OF` is implicit (row exists in table => member of table).

## Recursive queries / fixed-point

The user wants transitive closure / network-shape queries. Substrate-level shape:

```
// A recursive rule's body is its own pipe. The pipe subscribes to the same
// table it writes into. The drain loop already handles this: when render
// writes new rows to T, the wake on T sets the rule's own subscribe edge
// dirty, the next drain iteration re-runs the rule, etc.
//
// Termination: drain iterates until no owners are dirty.
// Cycle detection: optional per-owner generation counter; bail if
// re-firing same owner > N times in one drain cycle (today's
// `for _ in 0..8` cap at runtime_replay.rs:24 is the rough version).
//
// Lattice convergence: rely on row identity (hash of payload). If a rule
// re-derives the same row, the SUPPORT edge upsert is idempotent.
// Diff in replace_supports gives the inserted/retracted sets without
// double-counting.
```

This is materially weaker than DD/timely (no semi-naive evaluation, no incremental on the recursive frontier), but it composes with the existing drain loop and fits the constraint "no DD".

For operators that need a fixed point inside a single tick (RxJS `expand`, transitive closure within one wake), the operator is responsible for looping itself before returning to the drain. The drain only sees the outermost owner.

# Phase 4: React/JSX framing

| React concept | Canonical equivalent | Confidence |
|---------------|----------------------|------------|
| Component | Owner (one rule body invocation tied to an input_key) | high |
| Props | Subscribe edges + their source URIs | high |
| Render | Owner's body firing -> emits support rows | high |
| JSX child | nested rule call -> child Owner with parent linkage in `owner_uri` | high |
| Reconciler diff | `replace_supports` diff of old vs new SUPPORT edges | high |
| Commit phase | `FactStore::insert_batch` + `FactStore::delete_matching` on the SUPPORT edge changes | high |
| useEffect | wake handler -> dirty bit -> drain re-renders owner | medium; effects in React run **after** commit, here the dirty signal is **before** the next render |
| useState | `RuntimeContinuation` per owner (pipe_hash + instance_id + depth + input cursor) | medium; this is closer to a resumable closure than React state |
| Suspense | owner with no continuation written yet, paused before its render runs; drain skips owners with missing continuation | low; today drain just bails on `continuation_for_owner` returning None at `runtime_replay.rs:138`. A real Suspense would need a "waiting for X" tag |
| Concurrent / time slicing | `drain` loop with iteration cap (`for _ in 0..8` at `runtime_replay.rs:24`) | low; cap is fixed, not budget-driven |
| Keyed children | row_key = hash(payload) gives stable identity across re-renders | high; matches React's `key` prop semantics |
| Error boundary | none today; would need a per-owner error sink | n/a |
| Fragment | the support set itself; multiple rows from one render is the default | high |
| Portal | a render writes SUPPORT edges to a table outside its owner's normal output | n/a; nothing prevents this today |

Shaky mappings:
- **Suspense**: today's "pausable/resumable" is the continuation row, not a deferred render. To get React-style Suspense (component throws a Promise, parent renders fallback) you would need a `RUNTIME_OWNER_STATE` column with values `{ready, waiting_on(source), errored}`. Proposed: rename `RuntimeContinuation` to `OwnerState`, give it a status field. Then Suspense = `status=waiting_on(X)` + parent renders fallback row set.
- **useState**: continuation stores the *replay input*, not arbitrary local state. If a pipe needs scratch state across re-renders, it has to round-trip through the fact-store. That is OK if the user accepts "all owner state is durable", which the React framing implies (renders are pure).
- **Concurrent mode**: a real time-sliced render would yield mid-pipe and resume; today the 8-iteration cap is an outer-loop budget, not a per-render budget.

# Appendix A: Schema diff

## Today

```sql
RUNTIME_NODE(node_uri_id, node_kind_id, ast_uri_id, parent_uri_id, input_key, source_hash, mode_id, generation)
RUNTIME_EDGE(edge_uri_id, edge_kind_id, from_uri_id, to_uri_id, label_id, generation)
RUNTIME_VALUE(value_uri_id, value_key, kind_id, payload, state_id, generation)
RUNTIME_EDGE_VALUE(edge_uri_id, label_id, value_uri_id, generation)
RUNTIME_EVENT(event_uri_id, source_uri_id, value_uri_id, consumed, generation)
RUNTIME_JOB(job_uri_id, event_uri_id, owner_uri_id, state, generation)
RUNTIME_CONTINUATION(owner_uri_id, pipe_hash, instance_id, depth, input_cursor, generation)
```

## Canonical

```sql
RUNTIME_NODE(node_uri_id, node_kind_id, ast_uri_id, parent_uri_id, input_key, source_hash, mode_id, generation)
RUNTIME_EDGE(edge_uri_id, edge_kind_id, from_uri_id, to_uri_id, label_id, generation,
             dirty BOOL DEFAULT 0, dirty_gen INTEGER DEFAULT 0)
RUNTIME_CONTINUATION(owner_uri_id, pipe_hash, instance_id, depth, input_cursor, status, generation)
                                                                                  ^^^^^^ Suspense
```

Three tables instead of seven. The dirty bit on EDGE is what replaces VALUE+EDGE_VALUE+EVENT+JOB.

# Appendix B: Operator expressibility check

| RxJS op | Today | Canonical |
|---------|-------|-----------|
| `combineLatest` | 2 subscribe edges + 2 EDGE_VALUE rows, render reads both | 2 subscribe edges, render reads both source tables (or a cache table) |
| `switchMap` | ACTIVE edge + retract_owner_runtime recursion | replace_supports diff gives retraction; inner pipe is pure call inside parent render |
| `scan` | EDGE_VALUE = last accumulator | derived fact-store table containing (input_hash, acc); next render reads it |
| `merge` | N subscribe edges, render emits union | same |
| `share` / `multicast` | natural: SUPPORT edges from N owners can point to the same Row | same |
| `expand` (recursive) | recursive subscribe to own output table | same; drain loop iterates until quiescent |
| `take(N)` | render counts in continuation | continuation gets a counter field |
| `debounce` | none today | needs a per-edge timestamp + drain policy |
| `withLatestFrom` | EDGE_VALUE on the "from" stream | snapshot read of the source table |

Every shape representable today is representable canonically. `debounce` is new functionality in both.
