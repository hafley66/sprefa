# Session: dl MCP lattice + @yield channel projection

## Goal
Program MCP (and HTTP/SSE/WebSocket) handlers in dl. Lattice `merge(MaxBy(prio))`
decides dispatch; a new `@yield` temporal modifier drains head rows to a transport
channel (Rust-side `Channel` trait) instead of SQLite. Reuses the already-built
`@async` / `@next` / `@stream` temporal substrate.

## Terminology
- **EDB** = Extensional Database. Base facts given to the engine as input before a
  tick (source rels, `@next` carry loaded at tick start, `@async` responses landed
  by the off-tick drain).
- **IDB** = Intensional Database. Relations derived via rule heads during the fixpoint.
- A rel is one or the other depending on whether rules write its head.

### SQLite gotcha resolved
Bundled SQLite 3.43.2 parses `FROM t ON CONFLICT` as a join (ON = join condition),
so the UPSERT clause failed with `near "DO": syntax error` when a rule body had no
WHERE. Fix: always emit a WHERE — `WHERE 1` when the body has no constraints — so
the SELECT body closes before `ON CONFLICT`. Confirmed via sqlite3 CLI: the trailing
WHERE disambiguates and the upsert parses.

## Existing temporal substrate (already built, do NOT rebuild)

| construct | status | where |
|---|---|---|

Lifecycle today: tick converges → `@async` bodies emit request rows to
`pending_effect` → drain runs them off-tick → responses land back as EDB next tick.
`@next` stages head rows into `carry_<rel>` at tx+1. `@stream` opens long-lived
`sh*` sources that fan rows into the head rel across ticks.

## The gap (direction + channel binding, not temporal semantics)

| pattern | existing | gap |
|---|---|---|
| 1→1 request/response | `@async` (outbound: fire exec, response lands next tick) | inbound not covered |
| 1→N streaming source | `@stream` (inbound: long-lived source → head rows across ticks) | outbound not covered |
| state carry across ticks | `@next` | works, transport-agnostic |
| 1→N streaming response to a channel | ❌ | `@yield` territory |

`@yield` is the outbound dual of `@stream`: the head rel is a channel sink, not a
logical predicate. Each tick the rule produces head rows, and the drain pushes them
to the bound channel (HTTP response, SSE event, WebSocket frame, JSON-RPC response
or progress) instead of into SQLite. The rule stays alive across ticks until it
signals completion (closing the response).

## Projected code shapes

### Layer 1: Channel trait (pure Rust, the carrier) — `src/channel.rs`

```rust
pub trait Channel: Send {
    fn send(&mut self, frame: &Frame) -> Result<()>;
    fn try_recv(&mut self) -> Result<Option<Frame>>;
    fn close(&mut self) -> Result<()>;
}

pub enum Frame {
    Rpc(RpcMsg),    // JSON-RPC stdio: request/response/progress
    Sse(Event),     // HTTP SSE: named event + data chunk
    Ws(WsMsg),      // WebSocket: text/binary frame
    Http(HttpResp), // plain HTTP: status + body
}

// concrete: StdioChannel, HttpChannel, SseChannel, WsChannel
// the only thing that varies is frame encoding + read/write syscalls
```

### Layer 2: dl program shape (the handler logic)

```dl
-- EDB: inbound requests, injected by engine pre-tick
rel recv(id: int, method: text, params: json).

-- dispatch lattice: competing handlers, MaxBy(prio) wins per id
rel route(id: int, result: json, prio: int) key(id) merge(MaxBy(prio)).

route(id, {"pong": true},        100) <- recv(id, "ping", _).
route(id, {"tools": [...]},      100) <- recv(id, "tools/list", _).
route(id, {"error": "unknown"},    1) <- recv(id, method, _), !known(method).

-- channel sink: yielded to transport, not stored
rel send(id: int, result: json) @yield.
send(id, result) <- route(id, result, _).
```

Two rels, clean split: `route` does lattice dispatch (already built), `send` does
channel yield. The bridge rule is a plain join.

### Layer 3: streaming (1→N)

```dl
rel stream(id: int, event: text, data: json) @yield.

-- body reads from @stream source (inbound long-lived),
-- head yields each chunk to channel (outbound)
stream(id, "token", chunk) <- recv(id, "subscribe", params),
                              source_chunk(params, chunk) @stream.
```

`@stream` (inbound source) composed with `@yield` (outbound sink). The temporal
lifecycle is already built; `@yield` adds the drain target.

### Layer 4: `@yield` in the engine

```rust
// src/ast.rs
pub enum Temporal {
    Next,    // carry to tx+1 as EDB
    Async,   // fire exec off-tick, response lands next tick
    Stream,  // long-lived inbound source → head rows across ticks
    Yield,   // NEW: head rows drained to channel, not stored
}
```

```rust
// src/engine/tick.rs — yield drain runs post-fixpoint, parallel to @async drain:
// after tick converges:
//   1. @next carry staging (existing)
//   2. @async request emission (existing)
//   3. NEW: @yield drain
//      SELECT * FROM rel_<yield_rel>
//      for each row: map id → ChannelHandle, push Frame
//      DELETE FROM rel_<yield_rel>   (yielded rows are transient)
```

Yielded rows are not stored. Transient: produced by the rule head during the
fixpoint, drained to the channel, deleted. Key difference from `@next` (stored in
carry) and ordinary IDB (stored in the rel table).

### Layer 5: completion signal (open question)

Three options:

```dl
-- (a) explicit done marker: a sentinel row signals channel close
rel send(id: int, result: json, done: int) @yield.
send(id, result, 0) <- route(id, result, _).          -- more coming
send(id, null,    1) <- route(id, _, _), !more(id).    -- close

-- (b) empty tick = done: N consecutive ticks with no yield rows → close
--    no dl syntax, engine detects quiescence on the yield rel

-- (c) channel-level: the transport itself signals (HTTP response ended,
--    SSE client disconnected, WebSocket closed). Rust drain checks
--    channel liveness before next tick.
```

(c) is cleanest for MCP: JSON-RPC is 1→1 so every response is a close. SSE/WebSocket
need (a) or (b). The carrier decides; dl doesn't need to know.

### Layer 6: MCP server entry (pure Rust, phase 1) — `src/mcp.rs`

```rust
pub fn run_mcp(engine: &mut Engine, program: &Program) -> Result<()> {
    let chan = StdioChannel::new(stdin(), stdout());
    loop {
        // 1. poll channel for inbound request
        if let Some(Frame::Rpc(req)) = chan.try_recv()? {
            // 2. inject as EDB: INSERT INTO rel_recv VALUES(req.id, req.method, req.params)
            engine.inject_recv(req)?;
            // 3. run fixpoint tick
            engine.tick()?;
            // 4. drain @yield rels to channel
            engine.drain_yields(&chan)?;
        }
        // 5. drain @async effects (existing)
        engine.drain_effects()?;
    }
}
```

No dl-authored handlers yet — the dl program defines `recv`/`route`/`send` and the
Rust loop drives it. The lattice dispatch and yield drain are already in the engine.
The only new engine machinery is the `@yield` drain and the `inject_recv` EDB bridge.

no `@yield` yet. The dl program writes responses to an ordinary IDB rel
`send(id, result)` and the Rust loop reads it post-tick and pushes to the channel.
`@yield` becomes sugar that automates the read+delete. Ship that, then add `@yield`
once the `send` rel shape is proven.

## Design decisions deferred to user
1. `@yield` as a new `Temporal` variant vs. overloading `@stream` with a direction
   flag. Temporal lifecycle is shared; the only real difference is whether the drain
   writes to SQLite (logical) or to a transport handle (side-effect).
2. Completion signal: (a) sentinel row, (b) empty-tick quiescence, (c) channel-level.
   MCP 1→1 wants (c); SSE/WebSocket 1→N want (a) or (b).
3. Channel binding: a column in the head rel (`yield(req_id, chunk)`) that the Rust
   drain maps to the transport, vs. a rel-level annotation marking it as a channel
   sink.
