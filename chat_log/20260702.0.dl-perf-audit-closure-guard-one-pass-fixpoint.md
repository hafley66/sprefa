The three fixes, all measured before/after on examples/flow-interproc.dl over
this repo (release, --no-daemon, --profile, scratch db):
1. ONE-PASS NON-RECURSIVE STRATA (src/engine/mod.rs rebuild_derived +
   new rel_components helper before `type Bind`): stratify() groups by
   negation depth, so a stratum holds acyclic chains; rel_components splits a
   stratum's rules into rel-level dependency components via scc::tarjan
   (adj head->body; ascending comp id = dependencies first — tarjan completes
   reachable SCCs first), recursive = multi-rel SCC or self-edge (tracked
   separately, tarjan doesn't flag self-loops). Acyclic component = each rule
   executes ONCE; only recursive components run the delta loop. Kills the
   structural 2x (every non-recursive statement used to run twice just to
   observe delta=0). SQL strings now lowered once per component, not per pass.
2. CLOSURE-QUERY GUARD (run_query + closure_query_max_edges knob near
   tick_log_ms): any `?` on a closure head that would fall through to the SQL
   VIEW is refused loudly when the edge rel exceeds DL_CLOSURE_QUERY_MAX_EDGES
   (default 20k, 0 disables), with the pin hint in the message. LIMIT does NOT
   short-circuit the view (UNION + recursive CTE evaluate before first row;
   measured >10s for LIMIT 5) so the guard is a COUNT(*) check up front, not a
   row cap. Plus new run_reaches_pair: both-pinned closure query = existence
   probe via the seeded condensation walk (reaches_from + contains), never the
   view. print_query_result extracted from run_query.
3. EQUALITY SYM BRIDGE in examples/flow-interproc.dl + examples/taint.dl:
   new derived rel call_edge_bare strips the leading repo qualifier ONCE per
   call_edge row (replace_re(q, "^[^:]*::", "")), so every df_node.fn join is
   plain equality (indexable) instead of the per-PAIR unindexable
   replace(qual,bare,"")!=qual suffix test (~25M evals). Unresolved external
   callees (no repo prefix) strip to themselves and never match — same rows.
   flow-interproc's bridge is 4-ary (cb,eb,cq,eq) because sink_callee /
   flow_node_type need the qualified sym back; taint.dl's is 2-ary.

## Key Insights
- stratify() groups by NEGATION DEPTH not SCC — one stratum holds long acyclic
  chains, and the old fixpoint loop re-ran every statement in it until global
  delta=0: every expensive non-recursive rule structurally paid 2x.
- tarjan(adj head->body) completes dependency SCCs first => ascending comp id
  is dependencies-first evaluation order; self-loops need separate tracking
  (comp size 1 is NOT proof of non-recursion).
- LIMIT does not short-circuit the closure VIEW: the top-level UNION + the
  recursive CTE materialize before the first row emits (measured >10s LIMIT 5
  on 471k edges). Guards must refuse BEFORE evaluation, on input size.
- Constraints don't push into a recursive CTE either — a BOTH-pinned closure
  query through the view pays full materialization too; route it through the
  condensation walk (run_reaches_pair).
- The unindexable-join smell: a cmp predicate computed from columns of TWO
  different body atoms (replace(a.x, b.y, ...)) forces per-pair evaluation over
  the cross product. Rewrite as a row-local computation in its own rel + an
  equality join (call_edge_bare). ~25M evals -> 2.5k.
- Sym spaces: call_edge/type_sig syms are repo-qualified (repo::file::kind::name),
  df_node.fn is bare (file::kind::name); repo slug never contains "::" so
  replace_re(q,"^[^:]*::","") is a safe row-local bridge.
- Measurement inverted the static ranking: read-the-code said families were
  the risk; the profile said derived-layer join shape. But BOTH were right —
  cold tick = derived, warm tick = families (515ms of a 1.56s no-change tick).
- DD-for-the-dependency-graph already exists in this engine: affected_derived
  (mod.rs:1120) is dirty-propagation over the rule graph (tens of nodes,
  microseconds) — DD would add machinery to save nothing. Tuple-level DD =
  the FactStore/support machinery v5 deliberately removed; still right.
- dl-detectability of these hazards: the 2x pass and view materialization are
  engine-semantic (profiling only), but cardinality blowups (flow_edge 471k
  from 55 files), slow statements, and unpinned-closure-query program shapes
  are all rail-able IF tick telemetry/program reflection become builtin rels.
