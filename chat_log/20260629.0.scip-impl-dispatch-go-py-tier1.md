## Problem/Context
v5 dl engine, reactive Datalog-over-code, SQLite-welded, rev-aware. Prior arc

## Solution/Approach
Step 1 — scip_impl(impl, iface) loader: read SCIP SymbolInformation.relationships
is_implementation (doc.symbols + index.external_symbols). SCIP_RELS 7->8.
Step 2 — bench/flow/dispatch_flow.dl (renamed from kotlin_flow.dl, language-blind):
spec_op -> interface entry (scip_name match + iface target of scip_impl) -> dispatch
edge calls(iface,impl)<-scip_impl(impl,iface) UNION scip_fn_edge -> recursive reach
-> op_path -> multi_op (on >=2 op paths, o1!=o2).
KEY: closure(calls) is REJECTED when read from a rule body unpinned (multi-source
gap is real). Worked around by writing reach as EXPLICIT recursion (reach(a,b)<-
calls(a,b); reach(a,b)<-calls(a,m),reach(m,b)) which is freely joinable. So
multi-source reachability already exists in the language, just not via closure().
Then proved on REAL tools: installed scip-go + scip-python, built Go/Python
fixtures (interface/ABC + impl + shared httpExec helper + openapi.yaml). Both
indexers emit METHOD-LEVEL is_implementation. Query finds httpExec on both op paths.

  satisfaction included). That hop is invisible to occurrence/ref graphs — only the
  compiler index carries it.
- Real Python monikers exposed a loader bug hand-built indexes hid: param symbols
  `getPet().(id)` contain '(' but end ')' not ').'; old contains('(') fn-def test
  mis-registered params as enclosing fns -> body call attributed to param ->
  dispatch dead-ends. Fix: is_callable_def keys on `).` terminal. RA/scip-go inline
  params so only Python was bitten. Vindicates verify-on-real-tools over hand-built.
- closure() builtin = pin-one-endpoint-to-literal only; explicit recursion is the
  multi-source-seeding form. Same pairs, freely joinable.
- Adding a language to the FLOW surface = 1 fixture + 1 runtime-skip oracle, ZERO
  engine changes (the param fix was a latent bug, not new-lang work).
