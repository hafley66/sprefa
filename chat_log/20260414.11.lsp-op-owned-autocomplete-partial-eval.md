# Session: lsp-op-owned-autocomplete-partial-eval

## Goal
Add op-owned LSP autocomplete to sprefa v2 so each op describes its own suggestions inside its paren/brace slot. Initial target: repo/rev/fs completions visible in the editor.

## Current State
- **Committed**: `72ad39f` hover restoration (grouped output + file:// links) + scan-loop follow-ups.
- **Uncommitted / in-flight**: trait scaffolding for completion + wildcard_instance mostly landed; `scan_partial` was written as a PARALLEL SHADOW PATH and must be deleted. Refactor to reuse the existing runner via Pipeline truncate+substitute is the next move.
- Lib builds green; LSP bin had a mut-borrow error after completions_at took &mut self (bin edit was started, rejected mid-way).

## Problem/Context
User's core correction: "why cant we make it so that the runner is partial by default... the whole thing is supposed to be reactive and partial falls out from that." I was building `scan_partial` with its own seed_cursors + fresh config + fresh MemWriter alongside the existing `run_scan_loop` + `Pipeline::run`. Wrong. Partial eval should emerge from running a TRUNCATED + SUBSTITUTED Pipeline through the SAME ctx/config/reader.

User principle: "min entity, least entity, keep entropy low." Saved as feedback_min_entity.md.

Earlier architectural alignment:
- DocSession is a READ-MOSTLY cache/client. Today the daemon is in-process (so "read" = function call); tomorrow daemon is a separate process and DocSession holds an RPC stub. Same API.
- ResultStore is the in-memory precursor to daemon SQLite store.
- Buffers never write. Writer is NoOp during LSP runs. Ops suffixed `_write` short-circuit under LSP ctx (convention).
- Stable identity is a separate track (tier 0=byte_range session-local, tier 1=structural_path keystroke-stable, tier 2=SCIP-style commit-stable, tier 3=semantic cross-codebase).
- 3-layer Reader stack (Blob/WT/Buffer via CheckoutLocator) is the substrate for EntityId cross-layer matching.
- Completion kind should be `kind_hint: Option<Arc<str>>` (free-form op-authored tag), not a central enum. No CompletionKind enum.

## Solution/Approach

**Design that's agreed:**
1. Wildcards legal in repo/rev. Drop `repo/no-op-glob` and `rev/no-op-glob` Error diags (DONE). Future: `repo/heavy-match` Warn at runtime when output exceeds 5000.
2. ONE new slot on Operator: `fn wildcard_instance(&self, parse_site: Arc<ParseSite>) -> Option<Arc<dyn Op>>`. Returns a matches-everything instance.
3. Completion flow:
   - locate_paren_op(source, pos) → textual find of enclosing op name + partial (DONE).
   - Use span_ix (or pipeline walk) to resolve op_path for the enclosing op.
   - REWRITE the rule's Pipeline: replace target op with wildcard_instance, truncate Seq downstream.
   - Call `run_pipelines(&[(rule_name, rewritten_pipeline)])` — the SAME runner core currently inside ensure_run.
   - Harvest `RunReport.cursors_by_rule[rule]` = the wildcard op's output.
   - Map each cursor through `wildcard_op.witness()`, dedup, filter by partial, cap at 1000.

**Concrete refactor to do next:**
1. DELETE `scan_partial` + `seed_cursors` from `src/_14_scan_loop.rs`.
2. Extract `ensure_run` core in `src/analysis.rs` into `fn run_pipelines(&self, pipelines: &[(Arc<str>, Pipeline)]) -> RunReport`. `ensure_run` becomes a caller that passes `self.pipelines`. Completion calls with a singleton rewritten pipeline.
3. Add Pipeline rewrite helper: `truncate_and_substitute(p: &Pipeline, at: &[usize], wildcard: Arc<dyn Op>) -> Pipeline`. Handles Op/Seq/Fork variants.
4. Rewrite `complete_in_paren` in analysis.rs to:
   a. Find op_path via span_ix OpName entry whose range lies just before the located open paren.
   b. Build rewritten pipeline.
   c. Call run_pipelines.
   d. Harvest witnesses.
5. Fix LSP bin: `completion()` handler needs `get_mut` + maps CompletionSuggestion to tower-lsp CompletionItem with kind_hint mapping.
6. `kind_from_hint` helper in bin: "op"→Function, "repo"→Module, "rev"→Reference, "fs"→File, etc.

## Key Insights
- **Min entity / low entropy**: extract and reuse, never build parallel shadow paths. Reactivity/partial-eval falls out of running truncated inputs through the same runner.
- **DocSession is a client, not a computer**: holds cache mirror + RPC stub. Today's in-process runner is tomorrow's daemon RPC. The API doesn't change.
- **Completion = hover-before-value-exists**: both are filtered views of the cursor collection. One substrate.
- **Wildcard_instance is the only new Op slot needed**: framework handles splicing, running, harvesting.
- **Kind is free-form Arc<str>**: no central enum. Bin does best-effort icon mapping, falls back to generic.
- **Future vision mentioned**: doc assembly via queries + reverse-index hover from comment-authored notes. Requires stable EntityId (structural path), which is a separate track, not a prerequisite.
- **Writer invariant**: LSP ctx = no writes. Buffers never persist to store. Ops ending `_write` short-circuit in LSP mode (convention, not yet enforced).

## Open Questions
- When op at cursor doesn't parse (e.g. mid-typing `rev(ma`), span_ix has no entry. Graceful degradation (return empty) or try pipeline-less partial eval? For MVP: graceful degradation.
- `run_pipelines` signature — does it need the `cursors_scratch` mutex plumbing, or can we return cursors directly from scan-loop callback? Refactor should clean this up.
- Harvesting strategy for cursors at the wildcard terminal: the wildcard is always a Pipeline::Op terminal after truncation, so Pipeline::run output stream is exactly those cursors. Confirms no per-op evidence-filter needed for completion (unlike hover).
