## Problem/Context
Five threads.
The staleness thread: the README is the reference for humans and agents, but
the relation table had not been updated since before the call-graph, dataflow,
doc_node, and changed_line work. Anyone reading it would miss 5 relation
families and the match op's id column.

The dogfood thread: doc_node shipped in session 4 as an island (no doc_ref
bridge to the code graphs). Comment space is NOT unified -- syn strips
comments, oxc replaces tree-sitter-typescript, so no adapter auto-emits
comment rows. The comment(open[,close]) op is a rule-driven region extractor
that runs at query time and produces no soup rows. The question was whether
the doc tools could be useful WITHOUT the bridge.

The perf thread: v3/v4 had a complete large-repo perf fixture pattern
(just fixture-linux shallow-clones torvalds/linux into a gitignored dir; a
whole v4-bench-linux* family runs the bench binary against it with
workers/trials/batch params). v5 had ZERO just targets and only a synthetic
closure_incremental_bench.rs. The work was a port, not invention.

The kwargs thread: source-op outputs must be variables (var_of rejects Wild,
engine.rs:4060), forcing dummy vars (l0, l1) for unwanted outputs. The user
wanted named outputs to skip positions entirely. Grounded in 20260618.1's
decisions: data model locked flat (no composite types), arity mitigation is
an authoring-layer concern ("the tax is paid in syntax, not storage"). So
kwargs are authoring ergonomics, not a type-system expansion.

The highlighting thread: vscode-dl shipped only the LSP client; .dl files
rendered as plain text. The grammar was the missing readability half.

## Solution/Approach
### S1: README refresh (`2867b7e`)
Surgical edits to the relations table (added changed_line, true,
type_entity/sig/link, call_def/site/edge/edge_rev/name, df_node/edge/loop_over/
allocates/nest, doc_node), the match op row (5-arg id), the typegraph "where
things live" entry (3 langs + ingest module), LOC 9k->14k, the engine.rs:25 line
ref -> const-family pointer, and Known gaps (doc island, no rs:/kt:/ts: literal,
closure-in-body literal-seeded).

### S2: gen-doc-index.dl dogfood (`2867b7e`)
A self-hosting program that builds a doc map of the repo: doc_node reads
markdown titles (the ingest::DocLang registry), the comment op reads Rust //!
module docs, and gen splices both into the file's own BEGIN:/END: markers.
This is the query-time doc/code unification -- the two ops share a rule, no
doc_ref edge needed. Converges on rerun (no write when bytes match). Hit two
real constraints shipping it: source-op outputs must be vars (forced dummy
l0/l1), and the comment op binds its named-group text to the label output slot
(not to a var matching the group name, unlike match).

### S3: perf stress fixture (`c0c8302`)
just targets mirror v4's convention: v5-fixture-rust shallow-clones rust-
analyzer into v5/tests/.fixtures/ (gitignored, provision once); v5-bench-rust/
v5-bench-self run stress.dl with --profile (release binary); v5-perf-test runs
the env-gated test. bench/stress.dl forces the type/call/dataflow refreshers
over the corpus + two closure() definitions (the SCC-condensation heaviest
op). tests/perf_stress.rs follows the oracle skip convention: skips clean when
no fixture, else measures cold tick + one --changed incremental tick and
prints the ratio. Verified on v5's own source (979 entities, 10694 call sites,
32247 df nodes). Hit the documented constraint shipping it: closure relations
can't be read unpinned from a rule body (literal-seeded only), so stress.dl
forces closure via the definition, not a count-over-closure query.

### S4: comment kwargs (`0d3b73b`)
Engine: opt_var (engine.rs:4064) accepts Term::Wild -> None; the comment arm
(engine.rs:3978) skips binding outputs whose var is None. Parser: two reusable
helpers in parse.rs -- parse_kwarg_terms (parses positional + `name: term`
pairs until RParen) and assign_outputs (assigns to a name slice, defaults
unmentioned to Wild, rejects unknown names). comment() uses them for its three
outputs (l0, l1, label). Forms: `comment(p, rev, /re/, label: lab)` (skip l0/l1),
`comment(p, rev, /re/, _, _, lab)` (wildcard), `comment(p, rev, /re/, l0, label: lab)`
(mixed). gen-doc-index.dl dogfoods both kwarg and wildcard forms. 4 new tests.

### S5: vscode-dl grammar (`a47f1e5`)
TextMate grammar at syntaxes/dl.tmLanguage.json: comments (#), keywords
(rel/scan/match/gen/comment/...), the <- rule arrow, double-quoted strings
with ${}/{} interpolation, regex literals (/.../ with (?<name>)/$hole sub-
highlighting via captures.1.patterns), fs:/glob: scheme literals (plain +
backtick-fenced), :lang tags, numbers, comparison operators.
language-configuration.json wires # for Ctrl+/ toggling and BEGIN:/END: marker-
pair folding. Wired via contributes.grammars + the language's configuration
field. Version 0.1.0 -> 0.2.0; vsix repackaged. Key gotcha: a `match` rule's
`patterns` field is silently ignored by VSCode -- captures.N.patterns is the
supported form for sub-tokenizing matched text.

### Addressing analysis (no code; the deferred type-system thread)
Before the doc work, worked the rs:/kt:/ts: symbol-literal question to a
decision-ready state. Three lowering depths mapped: A (name-only constant,
breaks at the sym-shape problem -- sym is file::kind::name, a bare rs:engine::tick
only joins the ambiguous name column), B (eval-time subquery, correct but needs
a UDF or a module_path column -- a schema migration, not a lowering tweak), C
(qualified literal pins file/kind, preserves the normalize-early invariant but
is verbose). Two general subagents deliberated: pragmatist picked C, purist
picked B; both eliminated A. The user's "if we do nothing, what do they do?"
cut through: the DSL already disambiguates via column conjunctions (rails.dl:33,40
is the living proof), so rs: is sugar (terseness + module-path stability across
file moves), not new expressiveness. Thread deferred.

## Key Insights
- doc_node + comment + gen unify doc/code at QUERY TIME without a doc_ref edge.
  gen-doc-index.dl reads markdown structure (doc_node) and Rust //! module docs
  (comment op) and splices both into one index. The two ops share a rule; no
  relation-level bridge needed. This is the working dogfood pattern and the
  answer to "how is doc_node useful before doc_ref ships."
- Comment space is NOT unified. syn strips comments; oxc replaces tree-sitter-
  typescript. The comment op is a rule-driven region extractor (query time, no
  soup rows). doc_node only emits for markdown. Source comments are reachable
  via the op in a rule body, not as joinable relation rows.
- The kwarg feature is an authoring-layer change, consistent with the locked
  flat data model (20260618.1: "no composite types"; "arity mitigation =
  authoring, not data model"). opt_var + the parser helper are the whole
  mechanism; sg/ast_yaml follow trivially. Constraint: `name: value` needs a
  space after `:` -- the scheme lexer (lex.rs:187) rejects unknown `name:value`
  adjacencies as "unknown scheme."
- The addressing thread has a clean prior-art grounding the user accepts:
  20260618.1 locked the data model flat and placed arity mitigation in
  authoring; 20260611.0 compared glean (schema-layer hub) and souffle
  (brands+ADTs, rejected) and concluded v5's novelty is value-space (canonical
  form + pattern values + anchors). The user explicitly dismissed v4's prior
  art (the ?+`:` desugar). rs: is sugar, not new expressiveness.
- v5's perf story now has a repeatable harness. The cold/incremental ratio is
  the headline number. The closure-in-body literal-seeded constraint means
  stress.dl forces closure materialization via the definition rule, not a
  count-over-closure query.
- vscode-dl shipped only the LSP client; the grammar was the missing half for
  readability. Regex literals need captures.1.patterns (a match rule's patterns
  field is silently ignored by VSCode).
- The slot-machine deliberation (two general subagents) surfaced a cost both
  the LLM and the user had underweighted: B (eval-time symbol resolution) can't
  call rspath::file_to_mod_path from inside SQLite's SQL -- it needs a
  registered UDF or a precomputed module_path column on type_entity/call_def/
  call_site. That schema migration is the real cost of terse addressing.
