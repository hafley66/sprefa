## Problem/Context
- v5 dl engine = reactive datalog-over-code, SQLite-welded. Daemon watches files, re-ticks.
- christmas list = friction routed-around during a dynamic repo/rev crawler project.
- Daemon today: repos re-read from ~/.config/sprefa/config.toml each start (memory-only Engine::repos); program_files memory-only; rev cursor is in-memory rev_cache CLEARED every tick; `.git` watched ONLY if program scans a non-WORK rev literal. So HEAD moves on WORK-only watches are invisible and nothing diffs old→new ref oid.

Parse gotcha: Call-leading body item dispatches as an atom, so write `0 < int(c)` not `int(c) > 0`. 3 tests in string_fns.rs.

Daemon design (approved, to build): 3 persisted meta-tables in same DDL block as `_file`/`_prov`:
- `_program(path PK, hash, mtime, loaded_at)` — loaded dl files, diffable on restart.
- `_repo(slug PK, root, url, registered_at)` — registered repo set snapshot.
- `_ref((repo,name) PK, oid, observed_at)` — the rev cursor, last-seen oid per watched ref.
Sigs: `observe_ref(repo,repo_root,name)->Option<(old,new)>`; `files_changed_between(repo,repo_root,old,new)->Vec<path>` (∩ `_file` path index); `Daemon::on_git_event()`. Always watch `.git/HEAD`+`refs`+`packed-refs` (not just on rev literal).
User decisions: track HEAD + program-scanned revs; detect+emit+broadcast (NO auto re-analysis); surface as `_`-tables + query rels (program, head, rev_advanced — note `ref`/`rev`/`repo` partly reserved/taken) + status RPC for dashboard.
