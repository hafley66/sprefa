Generator topology (locked):
  repos(:from_config|:from_cwd) > rev(:HEAD) > fs() > read() > re|ast|glob|...
  
  seed                  Coord::default()                      cursor.value=""
  repo()                Coord{repo: id}                       cursor.value=slug
  > rev(:HEAD)          Coord{repo, rev: id}                  cursor.value=oid_hex
  > fs()                Coord{repo, rev, fs: 0, lo: 0, hi: 0} cursor.value=path
  > read()              Coord{repo, rev, fs: id, lo, hi}      cursor.value=content bytes
  > re`fn $X`           Coord{repo, rev, fs, lo, hi}          cursor.value=match slice

fs() emits paths only (no store touch); read() pulls bytes and populates _files/_paths via intern_file. Forced by content-derived FileId — can't intern_file without bytes, so lazy-resolve.

## Key Insights
- Dual-mode Cursor is load-bearing, not a hack: SprfStore writes its OWN meta-table rows via Cursor::default() + raw row.set("id", ...). If Cursor stops being a bare-string Row carrier, the store's bootstrap recurses. raw_terms preserves the legacy bag specifically to keep this path working.
- Content-derived ids replace sequential id + RwLock<HashMap> with Mutex<LruCache> + Mutex<HashSet>. Same content → same id across processes/restarts. Sentinel rows at id=0 pre-inserted; intern short-circuits on empty/default inputs.
- Bloom filter is wrong for write-skip: false-positive on first sighting causes silent data loss because INSERT OR IGNORE never fires. HashSet at sprefa scale (~3M entries → ~24MB) is correct.
- `&.value` self-op is the focal-cursor reference; plan file's bare `${.value}` rows should be read as `${&.value}` everywhere. & is a recognized one-char stem distinct from IDENT.
- v4's repo()/rev()/fs()/read() generator topology unifies the cursor model: each layer adds one Coord field, cursor.value carries that layer's identity (slug → oid → path → bytes → match). v3's separate cursor.repo/cursor.rev/cursor.fs fields are gone; everything goes through cursor.value + Coord + terms.
- File-drift detection (Layer 3): write_cursor blake3-hashes on-disk content vs intern_file's stored content_hash; mismatch → write/file-drift diag and skip splice. Prevents clobbering external edits.
- write_cursor :NAME mode uses second-positional uppercase atom (memory project_v4_no_kwargs forbids kwargs); lowercase second atom errors at lower-time so future modifier-style atoms remain available.
