# V4 Lazy Semantic Graph Frontier Plan

Date: 2026-05-14

## Goal

Add a v4 semantic graph feature that can work across a 500-repo set without eagerly parsing or semantically indexing every repo. The system should use cheap search to find candidate files, materialize typed graph facts only for the reachable frontier, and then run graph algorithms over SQLite-backed node/edge rows.

## Thesis

The graph substrate should be generic. JS imports, Rust modules, closure captures, runtime facts, SQL table dependencies, route mappings, and user-defined relations should all become typed graph rows with source provenance.

Language-specific extraction is input data. Graph construction, reachability, path search, visualization, and rule-defined meaning are the reusable feature.

## Lazy Stack

| Layer | Tool | Role | License posture |
| --- | --- | --- | --- |
| Coarse text/symbol search | Zoekt | Candidate repo/file frontier over many repos | Apache-2.0 |
| Structural matching | ast-grep | Source-shaped structural extraction and rewrites | MIT |
| Parser substrate | tree-sitter | CST, byte spans, grammar-agnostic parsing | MIT |
| Name resolution substrate | stack-graphs style model | Scope/name-resolution graph rules | MIT/Apache-2.0, upstream repo currently unsupported |
| Rule/query inspiration | Semgrep | Pattern-language prior art, not a core dependency | LGPL-2.1; CE has cross-file/dataflow limits |
| Durable local substrate | SQLite | Persist frontiers, nodes, edges, provenance, query outputs | Already in v4 direction |

## Core Data Model

Source-backed identifiers should use v4 coord-space:

```text
identifier text -> _strings
identifier span -> _where_bytes / Ref
sem_node.at     -> Ref
sem_edge.at     -> evidence Ref
```

Synthetic or aggregate nodes still intern their label string, but use `Ref::SYNTHETIC`.

```sql
sem_node(
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,
  label_string TEXT NOT NULL,
  at_ref INTEGER NOT NULL,
  confidence REAL NOT NULL,
  source_kind TEXT NOT NULL,
  source_name TEXT NOT NULL
);

sem_edge(
  src TEXT NOT NULL,
  dst TEXT NOT NULL,
  kind TEXT NOT NULL,
  evidence_ref INTEGER NOT NULL,
  confidence REAL NOT NULL,
  source_kind TEXT NOT NULL,
  source_name TEXT NOT NULL,
  PRIMARY KEY (src, dst, kind, evidence_ref)
);

sem_frontier(
  seed TEXT NOT NULL,
  depth INTEGER NOT NULL,
  repo TEXT NOT NULL,
  path TEXT NOT NULL,
  reason TEXT NOT NULL,
  PRIMARY KEY (seed, repo, path, reason)
);
```

The fact relation version can start as:

```sprf
rule(:sem_node, ID, KIND, LABEL, AT_REF, CONFIDENCE, SOURCE_KIND, SOURCE_NAME);
rule(:sem_edge, SRC, DST, KIND, EVIDENCE_REF, CONFIDENCE, SOURCE_KIND, SOURCE_NAME);
rule(:sem_frontier, SEED, DEPTH, REPO, PATH, REASON);
```

## Purity And Provenance

Every graph row should preserve how it was produced.

| Source kind | Meaning |
| --- | --- |
| `parser` | tree-sitter or CST fact |
| `resolver` | deterministic scope/name resolver |
| `rule` | user-authored `.sprf` relation |
| `heuristic` | best-effort algorithm with confidence below 1.0 |
| `search` | Zoekt/text/symbol frontier result |
| `ai` | model-proposed edge or node, gated by confidence/provenance |

This lets users filter graph views:

```sprf
sem_edge > where(SOURCE_KIND == :resolver && CONFIDENCE == 1.0)
sem_edge > where(SOURCE_KIND == :heuristic && CONFIDENCE > 0.72)
```

## Initial Ops

| Op | Purpose |
| --- | --- |
| `frontier` | create or read a bounded candidate workset |
| `zoekt` | run a coarse query and emit frontier rows |
| `node(:kind)` | write a typed graph node from current cursor terms |
| `edge(:kind, FROM, TO)` | write a typed graph edge from current cursor terms |
| `neighbors(:kind?, :dir?)` | one-hop graph query |
| `reachable(:kind?, :dir?, max=N)` | BFS / blast-radius query |
| `paths(FROM, TO, max_depth=N)` | bounded path explanation |
| `scc(:kind?)` | strongly connected components |
| `graph(:json\|dot\|mermaid)` | render selected graph rows |

## 500-Repo Execution Model

Do not parse all repos first.

```text
1. User provides seed: symbol, import string, route, table, path glob, or selected span.
2. Zoekt finds candidate repos/files cheaply.
3. `sem_frontier` stores bounded candidates.
4. Extractors parse only frontier files.
5. Extractors emit source-backed nodes and edges.
6. Graph queries expand frontier by one or more edge hops.
7. Stop when frontier stabilizes or a user cap is reached.
```

This turns a large corpus into an on-demand graph expansion process.

## Example Surface

```sprf
zoekt`Foo file:\.(ts|tsx|rs)$`
  > frontier(:file, max_repos=30, max_files=500);

frontier
  > read
  > ast`export function ${NAME?}`
  > node(:export);

frontier
  > read
  > refs
  > edge(:mentions, FROM, TO);

node(:export, Foo)
  > reachable(:mentions, :reverse, max=200)
  > graph(:dot);
```

## Closure And Scope Analysis

The graph substrate should support compiler-style scope facts:

```text
scope_node(kind = module | function | closure | block | class)
binding_node(kind = import | param | local | function | class | export)
ref_node(kind = identifier_ref)
```

Edges:

```text
contains(scope -> child_scope)
declares(scope -> binding)
uses(scope_or_entity -> ref)
resolves_to(ref -> binding)
imports(binding -> exported_binding)
captures(closure_scope -> binding)
```

Closure capture algorithm:

```text
for each closure/function scope C:
  for each identifier ref R inside C:
    B = resolve(R)
    if B declared outside C and not global/builtin:
      emit captures(C, B)
```

Import-aware closure dependency:

```text
for each identifier ref R inside closure C:
  B = lexical_resolve(R)
  if B.kind == import:
    E = imported export target
    emit captures(C, B)
    emit depends_on(C, E)
```

Common names in other tools:

| Term | Use |
| --- | --- |
| lexical scope resolution | bind references to declarations |
| name binding / binding analysis | declaration-reference resolution |
| free variable analysis | refs used inside a closure but bound outside it |
| capture analysis | identify closure environment captures |
| def-use / use-def chains | declaration-use linkage |
| closure conversion | compiler transform making captures explicit |
| call graph construction | callsite-to-callable edges |

## Graph Algorithms

Once graph rows exist, these are plain algorithms over `sem_edge`.

| Feature | Algorithm |
| --- | --- |
| direct deps | outgoing edge scan |
| direct dependents | incoming edge scan |
| blast radius | reverse BFS |
| dependency closure | forward transitive closure |
| path explanation | shortest path / bounded BFS |
| cycles | SCC |
| layers | topological sort |
| dead exports | zero inbound import edges |
| choke points | dominators or articulation points, by graph shape |

## Visualization Target

Graph facts should feed a mechanical view of code:

| Code concept | 3D graph visual |
| --- | --- |
| modules/files | rigid bodies / plates |
| contains edges | nested assemblies |
| calls/imports | rods/cables |
| captures | tethers from closure to outer binding |
| mutation/write effects | force vectors |
| runtime/fact flow | particles along edges |
| changed node | stress point |
| blast radius | wavefront propagation |
| AI edit plan | ghost graph overlay |
| before/after diff | morph animation between graph states |

This requires graph rows to be appendable, typed, and provenance-preserving.

## Implementation Sequence

1. Add `sem_node`, `sem_edge`, and `sem_frontier` relation shape.
2. Add graph algorithms over hand-seeded rows: `neighbors`, `reachable`, `paths`, `scc`.
3. Add `graph(:json)` renderer.
4. Add `graph(:dot)` and `graph(:mermaid)` renderers.
5. Add `frontier` op backed by local rows only.
6. Add `zoekt` adapter as a frontier producer.
7. Add one pure structural extractor that emits source-backed nodes from a frontier file.
8. Add one edge extractor that emits source-backed `mentions` or `imports` edges.
9. Add provenance/confidence filters.
10. Add LSP surface for selected-span-to-node lookup after graph rows are stable.

## Non-Goals For First Pass

- No eager 500-repo parse.
- No mutation/rewrite actions.
- No mandatory language-specific resolver.
- No dependency on Semgrep core.
- No requirement that every edge be pure. Mixed purity is allowed when provenance and confidence are explicit.
