## Problem/Context
`diag` was a magic user-declared rel whose columns the engine mapped BY NAME in
Engine::diags(). Every rail carried its own `rel diag(...)` decl with a different
column subset (5/6/7/8-col), and the merged `.dl/` discovery namespace ERRORED
("declared twice with different columns") when two files declared it differently.
That collision is exactly why doc generators couldn't live in `.dl/` (gen-reference
declared diag 8-col vs rails.dl 7-col). User wanted this ripped out with no compat
fallback.

## Solution/Approach
1. diag is now engine-declared: `diag_rel_decls()` + `DIAG_RELS` reserve, fixed
   9-col schema (path,line,col,end_line,end_col,severity,code,msg,hint). path is
   TEXT so synthetic origins ("(engine)","(checked-notes)") survive the file check.
   `rel diag(...)` now errors. Engine::diags() rewritten to fixed positions,
   NULL-tolerant (NULL severity->"warn", NULL end_line->line, NULL ints->0).
2. Named args in rule heads: parser head_atom collects `named`; frontend
   resolve_atom runs on r.head; unnamed columns pad to Term::Wild -> NULL.
3. Head Wild->NULL in BOTH lowering paths: lower.rs (derived SQL) and the Rust
   source-rule head-projection (engine/mod.rs ~5605). Required adding
   ast::Value::Null (was only Text/Int) — rippled to db.rs param map, check_type
   (Null->true, skip), and the extract-rule row-key match.
4. Bare shorthand: fully-positional atom, count != arity, all terms column-named
   Vars -> all-puns (only rescues would-be arity errors, positional stays positional).
5. Positional literals (user's "mix like Python"): resolve_atom two-pass —
   name/pun bind FIRST, nameless literals fill leftmost-open columns in written
   order. Rule = "carries a name -> by name; nameless -> by position." Over-fill errors.
6. Mass-converted ~23 examples + 12 test .dl strings + .dl/rails.dl + assets/starter.dl
   + examples/lints/* via a python positional->named script (conv.py, per-file decl
   column order); stripped redundant `x: x` pairs on diag lines.
7. Wired doc generators into .dl/ via relative symlinks (op-table, builtin-rels,
   gen-reference, gen-skill-ref); renamed each generator's marker-region rel
   uniquely (block->op_block / rel_block) so the merge doesn't dedup them into one
   cross-contaminating rel (verified: perturb both README regions, one tick restores
   each, each header appears once). NOTE gen is suppressed under --lsp/--check.
8. smash migration: dl-self-lint.dl (8-col diag positional -> named) and
   lint-input-device.dl (8-col -> named); killed stale Jul-1 daemon.

## Key Insights
- diag being a built-in that USERS WRITE (head) is unlike other built-ins (engine-
  populated, read-only). It stays a DERIVED rel (rebuild_derived fills it from user
  rules); the built-in decl only pre-creates the table + reserves the name.
- resolve_atom's pun already existed (JS/Rust struct shorthand) but needed a `col:`
  anchor. The relaxation: fully-bare all-column-var atom with count!=arity -> puns.
  Only fires on would-be arity errors, so zero behavior change to positional atoms.
- Vars pun (by name), literals bind by position — clean split, no order surprise
  for bare vars (Python forbids positional-after-keyword; dl allows interleave).
- gen is suppressed under --lsp/--check, so wiring generators into .dl/ only regens
  under a plain `dl --root .` tick or a real --daemon, NOT the editor LSP process.
- Never `match(p,rev,/./,l)` scan-forcer; bare scan populates the corpus (carried
  from earlier this session, memory feedback_no_regex_scan_forcer).
