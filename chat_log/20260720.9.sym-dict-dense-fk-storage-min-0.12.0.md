## Solution/Approach
- CORRECTNESS PROOF (plans/2026-07-21-sym-dict-correctness-proof.md, committed):
  Theorem: substituting the identity preserves every equijoin IFF the new id
  reproduces the old partition, i.e. IFF enc is injective on the corpus.
  MEASURED on live 833MB db: (Check A) 0 syms fold >1 tuple -> enc injective, safe
  direction proven; (bijection baseline) distinct sym ids == distinct sym strings
  exactly (type_entity 6363, call_def 11737) -> hash64 collision-free -> a
  string-keyed dense dict is a perfect bijection. LANDMINE FOUND: the agent plan's
  schema keyed _sym_dict on stored (repo,file,kind,name,parent) COLUMNS, which are
  LOSSY (call_def has NO name col: 11737->1028; 5454 type_entity syms have empty
  parent col; 6018 closures carry coord in no col). Keying on columns silently
  MERGES symbols. RCA'd as failure-modes class 32.
- CHOSEN DESIGN (Option A, dispatched): _sym_dict(id AUTOINCREMENT PK, sym_hash
  INTEGER UNIQUE), keyed on the FULL sym string's hash (proven bijection). Resolve

  resolve_coord_surrogates, batched, N+1-safe). lower.rs sym_lit gains a dict

  column flips together or joins silently return empty. ACCEPTANCE = the bijection

  suite + before/after storage on 833MB.
- Trade accepted: dense breaks content-addressability (sym_lit needs a db lookup,

## Key Insights
- 41MB of source -> 809MB because facts are indexed 2-4x with 8-byte random hash
  keys; index (478MB) outweighs facts (260MB). Shrinking the key shrinks table AND
  every index copy -- that's the whole storage lever.
- A folded composite id's "separate columns" may be a LOSSIER decomposition than
  the folded value; MEASURE count(distinct folded)==count(distinct tuple) before
  keying a surrogate on columns, or you silently merge (failure-modes class 32).
- Resolve the surrogate from the id's MINT-TIME inputs (or the full string hash),
  NEVER from independently-populated rel columns. Mirror _df_node_dict.
- The bijection count-equality gate is un-cheatable and is the only thing that
  catches a silent merge (green suite won't). Join-parity probe catches a missed
  interned column (disjoint int space -> empty join).
