## Problem/Context
Two flow tiers existed but never joined:
- df_* lift (df_node/df_edge): intra-procedural, typed value nodes (param/
  var_read/binop/call_res/...), syn(Rust)/oxc(TS)/tree-sitter(Kotlin). Zero SCIP.
- scip_*/call_* graph: cross-proc/cross-lang symbol reachability, SCIP-resolved,
  but walks syms not values. Only scip_callee_type carries a type.
Neither connected a value in one fn to a value in another. type_link/type_sig is
the SCIP-resolved TYPE graph (not value dataflow).

## Solution/Approach
Built as pure-DL composition first (examples/flow-interproc.dl), then added the
engine assists. Key mechanics:
- flow_edge = df_edge UNION interprocedural hops; closure(flow_edge) walks across
  fns. All-derived so closure() is legal.
- Resolution rides call_edge (SCIP-preferred at engine.rs ~4158: scip_name_defs
  def_file else single-def name). Avoids the df_node line-base gotcha.
- Sym-space bridge: df_node.fn is BARE (file::kind::name, mint_sym typegraph.rs:468);
  call_edge/call_name/type_sig syms are repo-qualified. Bridge with suffix idiom
  `strip = replace(qual, bare, ""), strip != qual` (the strict dataflow test trick).
- FORWARD hop: arg feeding call_res -> resolved callee's params.
- BACKWARD hop: new `ret` df_node kind. Rust Expr::Return + block-tail (flow_block
  now returns Option<(id,line,col)>); Kotlin jump_expression + function_body tail;
  TS ReturnStatement + arrow expr-body. Edge returned-value -> ret. DL rule:
  callee ret -> caller call_res. End-to-end taint through a callee.
- TS arrow/fn-expression consts lifted as own fn scope via new ts_lift_fn
  (dispatched in VariableDeclaration arm; was the `_ => expr` hole).
- New builtin rel df_param(id, pos): param df_node positional index. Counts ONLY
  typed params (Rust receiver self skipped via explicit counter NOT enumerate) so
  it aligns with type_sig.pos (which also drops self). From DataflowFacts.param_pos
  (new Vec<(String,u32)>), populated at all 4 param-seeding sites. Powers
  node-level flow_node_type(node, callee, ty); function-level flow_param_type also.

## Key Insights
- GOTCHA: df_node line base is NOT cross-lang consistent — Rust 1-based
  (proc-macro2), Kotlin/TS 0-based (tree-sitter/byte). call_site.line is 1-based
  for ALL langs. So a (file,line) join df_node->call_site works for Rust, SILENTLY
  misses Kotlin by one. nest/loop tests never caught it (Rust-only). Resolve via
  call_edge (sym->sym, no line) instead.
- call_edge resolution is already SCIP-preferred, so the cross-fn hop is
  SCIP-resolved for free — no new wiring.
- type_sig(sym, slot, pos, ref) is keyed by param POSITION (slot in param/ret),
  df_node params by NAME with no position — hence df_param to bridge to node-level.
- Multiple ret nodes per fn (one per return point) is fine; the backward rule
  matches any; corpus-dedup by id collapses duplicates.
- Pure-DL composition over existing rels is the repo idiom for flow (bench/flow/*),
  zero engine risk; the engine assists (ret kind, df_param) are additive.
