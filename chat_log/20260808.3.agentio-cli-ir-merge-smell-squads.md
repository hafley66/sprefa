## Solution/Approach

### agentio: DECIDED (user, end of session)
**Build our own clap CLI in Rust.** One trait; centralize the trait into ONE registry; the CLI just routes to the interface for its data. Tiny and self-describing.
**Location: `v6/` as a sibling to `sprefa-extract` and `sprefa-store`.**

## Key Insights

**1. Sort already lowers to SQL, at the aggregate only.** `lower.pl:4326-4352`:
```
json_group_array(<value> ORDER BY <value>)      json_group_array(Value)
json_group_array(<value> ORDER BY <ordinal>)    json_group_array(Value, Ordinal)
group_concat(<value>, <sep> ORDER BY <value>)   group_concat(Value, Sep)
group_concat(<value>, <sep> ORDER BY <ordinal>) group_concat(Value, Sep, Ordinal)
```
All four live surface (`compile/registry.pl:169-172`), exercised in `golden-flex.dl6:376-392`. They sort correctly under interning because `compile_expr(Mode, value, ...)` resolves the dict id back to text before the ORDER BY. `group_concat/1` and `json_array/1` are registered REFUSED.
Rel-level order does not exist. Order is a BOUNDARY property: you cannot sort an unbounded delta stream, only a `toArray()`'d snapshot, and the only bounded points are `/idb/<rel>` and one tick's batch.

**2. `relplan/5` IS the relational IR.** `relplan(Ref, log|set, Columns, key(Ps)|none, ColumnTypes)`, 113 pattern-match sites (56 in plunit). Adding an order slot = `/6` = all 113. Threading a separate `rel_order(Ref, [Col,...])` beside `RelPlans` touches only the sites that need it, which is exactly what `Decls` already does.

**3. Site counts:** `col_type(` 661, `plan(` 292, `relplan(` 113, `type_decl(` 102, `type_def(` 10, `relstorage(` 8.

**6. The `refusal` jargon is a measured Zipf violation.** 6,427 in `v6/prolog`, 1,885 in `plans/`, 1,555 in `v6/tsv2`, 342 in `chat_log/`, **0 in 37 quoted user lines**. The thrown term is `unsupported_construct` (263). It hardened prose -> identifier (`compiler_refusal` 33, `engine_refusal` 31, `scan_refusal` 20, `refusal_source_module` 16, `refusal_inventory` 9) -> a 248-row inventory -> a standing law in CLAUDE.md that uses the word 10 times to warn about the word. Receipt: 72 of 101 named refusals were agent-decided with `evidence: none`. NOTE: comments and identifiers cost ZERO inferences, so this is a readability problem, NOT the compile-speed cause.

**7. `list(T)` is strictly a VALUE, never a rel.** One TEXT cell, canonical json array, `CHECK (json_valid(c) AND json_type(c) = 'array')`. T now ranges over `int text bool float json list(...)`. `list(RelName)` stays refused (`list_of_relation_refs`) because a struct element has an `__id` and ids in a list would enter the tick log. Rows -> list is `json_group_array(V)`; list -> rows is `decode(Tags, spread(Tag))` (surface `[... P]`). A collection of OBJECTS is a rel with an index column. Board: `plans/2026-08-08-list-of-t-map.d2` (3015 x 1393, 16 shapes).

**8. json already has BOTH array halves**: `spread/1` (read, live), `json_group_array/1,/2` (write, live), `json_array/1` (registered refused). So `list(T)` is a type annotation over json array machinery, which is why `json_list` is the accurate name.

**9. Datalog termination context (option A vs B).** Pure datalog forbids function symbols because that keeps the Herbrand base finite. dl6 buys termination three ways: no cons constructor in a rule body, aggregates stratified strictly above their sources (`analyze.pl:1624-1626`), and the `recursive_stratum` refusal (`strat.pl:98`). Option B (widen elements) was taken; option A (recursive term building) would cost the termination proof. Cousins: DDlog is the closest architecture (incremental + typed + ADTs + Vec + generics; keeps term construction OUTSIDE recursive cycles), Souffle takes the loss, Flix uses ACC lattices, Datafun uses monotonicity types, XSB uses tabling, DLV uses a finitely-instantiable check. Go = GCShape stenciling + dictionaries; Rust = full monomorphization + `dyn` vtables; TS = full erasure; Kotlin = erasure + `reified` on `inline fun`. The user's insight is real and is Go's: an enum is a closed sum over VALUES, a generic constraint is a closed sum over TYPES; `list_element_type/1` is already a hardcoded type set.
