## Problem/Context
v5 extraction: 4 span shapes, 3 kind representations (typed enums for type/call, free String for df, &str for edges), SPLIT node identity (mint_sym coordinate strings `file::kind::name` ~26.6% of dict; dense NodeIdx for df; salted WhereBytes for CST), two ASYMMETRIC traits (TypeLang Sync per-file vs ModuleResolver Send+Sync +&ProjectCx), SCIP bolted on as an engine overlay (scip_narrow), parse sharing opt-in (only Rust; others parse 3x), flow_edge (the interprocedural value-flow 5th family) stranded in std/flow.dl stringly-joined, eager whole-program ticks, resident memo+parse trees -> ~36GB. Async question resolved mid-session: sync CORE + async SHELL (mirrors Store/StoreHandle).

## Solution/Approach
The inversion: v5 mints coordinate strings inside the engine and writes rel tables; v6 emits span-addressed facts from a leaf and lets the store name them. Normalization kills the disease STRUCTURALLY: ONE Span, ONE typed-kind ordinal per family, node id = (family, span, kind). Two traits KEPT TWO (the one real distinction = cache key): FileExtract (content-addressed: blob+lang+mask -> nodes) / ProjectExtract (project-scoped: blob+project_digest+mask -> edges) — Stack Graphs index/query split. Tier model formalizes v5's implicit tiers: SCIP Tier-1 (shell-out, ground truth for call/type/module resolution), native AST Tier-2 (syn/oxc/tree-sitter; owns dataflow since SCIP has no CFG), tree-sitter floor. diet-SCIP keeps only symbol/range/role/relations. flow_edge promoted to typed FlowEdgeKind. Arena-per-file on rayon = the 36GB kill (peak RSS = biggest file). Async shell ReactiveExtract wraps the sync core via one spawn_blocking per batch (owned ProjectView inputs, futures 'static+Send); SCIP build = tokio::process. Kind vocabularies lifted verbatim from v5 decls.rs builtin_enum_brands (df_node_kind 23, type_entity_kind 9, type_edge_kind 7, CallKind 3, etc.).

## Key Insights
- Node identity = (family, span, kind) kills mint_sym/salt_rev/NodeIdx/WhereBytes at the type level, not by discipline.
- The two-phase FileExtract/ProjectExtract split is the ONE distinction worth preserving (cache key: content vs content+fileset). Everything else unifies.
- SCIP is a SOURCE tier, not a family/overlay. Tier 1 ground truth for resolution; AST owns dataflow.
- flow_edge (std/flow.dl:89) = df_edge ∪ arg->param ∪ ret->call_res over call_edge — v5's half-built 5th family, promoted to typed edges.
- salt_rev (cited in old plans) DOES NOT EXIST in current v5; live digest logic is extract_input_digest (engine/extract/mod.rs:861). Don't chase the ghost.
- v5 has NO ast-grep family extractor (ast-grep is the term-op `sg` only). Lifting families onto ast-grep is a v6 frontier (Epic 1.3 labs).
- Sync core + async shell: core has nothing to await (rayon); shell takes OWNED inputs (futures must be 'static+Send, can't hold &ProjectCx<'a>). Mirrors Store/StoreHandle.
- CodeQL: intra/inter is derivable from enclosing-scope equality — don't bake into edge kind. SVF: register def-use syntactic (emit), memory def-use points-to (downstream).
