## Problem/Context
v3 pre-14 state: fs/repo/rev/comment parsed raw paren-body strings via local classify_token + parse_capture helpers and inline glob::compile_str calls. `glob(...)` and `re(...)` were only pipe-step ops, not value constructors. Pattern was a central enum (Regex/Glob/Json/Ast) with match-self dispatch in as_raw_regex/bound_captures/apply/materialize_for — violating the ops-own-everything invariant (§14.1).

Design session before code:
- Locked: `:atom` ruby-style sugar for scalar filter literals; `str(...)` required for non-[A-Za-z0-9_$!?] bytes; no raw strings at host level ("everything is a sub-grammar"); nested op_invocation in paren_slot; glob dropped as pipe-step op (arg-only value constructor).
- Locked: rev($V) rejected with rev/unbounded-capture diagnostic; authors who want all-revs write rev(re($V)) explicitly.
- Locked: `$TERM` is sugar for term() op; `${body}` is term op with brace-slot body (one pipeline inside). Grammar-level `term_ref` stays as a fused token + `carveout_expr` for `${body}`/`&{body}`.
- Two-state term model (bound/unbound) not three (free-var is compile error at resolver, not a variant).
- Unification thesis filed as sprefa-x5b: Pattern IS Op; list-of-cursors -> list-of-cursors universal shape; tuples == Seq pipes; structs == allocation-Seq pipes; $TERM == term-op identity-with-bind.
- Carveouts inside pattern bodies (re/glob/ast/cst/json): Seg::Computed variant drives sub-pipeline per cursor, splices escaped bytes into materialized regex; side-effect-only pipelines collapse to Seg::Term + side-effects list (sprefa-aw5 card).

Three-layer trait model after q5a:
- Op (base, object-safe) — every op
- PatternOp: Op (compile-time sub-trait on op structs: GlobOp, ReOp, ...)
- PatternValue (run-time trait on matcher structs: GlobPattern, RegexPattern, ...) with Pattern = Arc<dyn PatternValue> type alias
- Value::Pattern carries Arc<dyn PatternValue>

## Key Insights
- Worktree isolation flag on the Agent tool did NOT produce isolated worktrees; sonnets wrote direct to main. Made integration trivial but surprised expectations; worth verifying future runs.
- Type-alias trick `pub type Pattern = Arc<dyn PatternValue>` let q5a land the trait flip without mass call-site churn — all existing `Pattern` references still compile.
- Pattern (matcher) vs PatternOp (op that produces matcher) is a meaningful split today but x5b argues for full collapse into a single Op trait with PatternOp extension.
- `$TERM` is sugar for term() op; `${body}` carveout is term op with brace-slot pipeline body. Grammar doesn't need to change to reflect this — lowerer-level desugar.
- Carveouts inside pattern bodies become Seg::Computed at compile time; at runtime each Computed segment drives its pipeline per cursor and splices escape-literal bytes. Side-effect-only pipelines collapse back to Seg::Term + deferred side-effects list (optimization, not correctness).
- Three-state term discussion (free/unbound/bound) collapses to two at the Pattern enum leaf; free-vs-unbound distinction lives at the resolver/scope layer, not on the enum.
- Sonnet A ran out of context at 128 tool uses; brief was long but the work was mostly done before the limit hit. For future big refactors, consider splitting into two smaller sonnets rather than one giant.

## Open Questions
- Should rev(re($V)) (the explicit all-revs opt-in) be gated behind a config flag or stay authored-only? Currently just legal.
- ArgSpec naming: value::ArgSpec (variant-picker enum) vs lower::ArgSpec (AcceptsMode struct). 4.9 proposes renaming the latter to TermSpec/TermArgSpec.
- Pattern IS Op collapse (x5b): do we commit to it or leave the two-trait split as the stable shape? Today's model is clean; x5b is more uniform.
- Carveouts in ast/cst (per-cursor tree-sitter Query recompile) will be expensive; LRU on spliced-text hash — is that the right cache shape or do we want something cheaper?
