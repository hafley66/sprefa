## Solution/Approach
The substrate as committed:

- `Next` trait: `Send + Sync + 'static + content_hash() -> [u8; 32]`.
  Primitive impls (i64/u64/String) provided.
- `NextKey([u8; 32])`: composed from `(parent_id, pipe_hash,
  instance_id, pc, batch_idx, drive_tick, path, content_hash)` via
  `next_key::compute_key`.
- `EventBus`: three event flavors (KeyDirty / PathDirty / DomainDirty),
  three subscription kinds (key direct / path prefix / domain), plus
  `BusListener` trait for cache reactions. Listeners fire outside the
  bus lock.
- `QueueBackend<N>` trait: `MemQueue<N>` and `SqliteQueue<N: Next +
  Codec>` interchangeable. SqliteQueue takes Arc<Mutex<Connection>>, not
  ownership — sprefa shares the connection.
- `Node<N>`: Done / Emit / Many / Suspense (pc+1) / Yield (same pc).
- `Component`: `type Next: Next; fn render(&self, ctx, c) -> Node<Self::Next>`.
- `EffectDispatch<T>` (saga): `dispatch(key, mutationFn)` collapses the
  spawn-write-dispatch boilerplate. `Spawner` trait: ThreadSpawner /
  TokioSpawner / custom.
- `MutationStore<T>` + `SqliteMutationStore<T>`: keyed by NextKey, holds
  Arc<T>. Mutation results land here, downstream pc reads them.
- `Memoize<C>` + `MemoCache<N>`: useMemo. Cache key =
  blake3(ident, content_hash). Domain tag → DomainDirty drops entries.
  `attach_cache_to_bus(cache, &bus)` wires it.
- `Query<N, F: QueryFn<N>>` + `QueryCache<N>` + `QueryStatus`: useQuery.
  EffectKey = blake3(ident, content_hash). Idle → spawn + Yield;
  Pending → Yield; Success → Emit. Domain → invalidateQueries.

## Key Insights
- **`Node::Yield` was the missing primitive.** react-query's
  pending→success state machine assumes the SAME component decides
  what to do based on cache state. `Suspense` advances pc and hands
  off to the next component. They're complementary, not redundant.
- **Wake and cache invalidation are one mechanism.** Both `EventBus`
  subscriber kinds (parker rows that wake on KeyDirty) and listeners
  (cache entries that drop on DomainDirty) come from the same
  dispatch call. Sprefa's "tag insert wakes parked SELECTs" and
  "writes invalidate downstream queries" are the same primitive.
- **Generic carrier is the right call.** ~10–15% LoC bloat vs a
  Cursor-specific runtime, plus the integer-carrier test catches every
  Cursor-specific assumption that leaks in. The substrate is
  domain-neutral and can move into v3 cleanly.
- **`Connection` sharing is the hinge for atomic transactions.**
  SqliteQueue takes Arc<Mutex<Connection>> rather than owning the
  file. When sprefa's relational store is wired in (Phase F.3 or
  later), one `BEGIN/COMMIT` covers queue mutations + fact writes +
  mutation_store puts. That's the redux-persist guarantee.
- **Crash-restart works WITHOUT transactional drive.** The crash-
  restart proof passes today because each individual statement is its
  own commit. The transactional variant is a sharpening: ensures
  partial-render states never persist. Useful, not load-bearing for
  the POC.
- **Event ordering: the bus snapshots listeners under the lock then
  fires them outside.** Lets a listener re-enter the bus during its
  handler (e.g. cache drop triggering further dispatches) without
  deadlocking.
- **Removing the duplicate runtime in v4 was a -1308 LoC change.**
  Net: -1308 src, +358 v4-bridge / docs / TODOs. The substrate is
  doing real load-bearing work in v4 now, not sitting in a lab.

## Open Questions
- **Phase E trigger**: when do we feel the orphan-rows pain enough to
  build cascade_delete? Likely first time a Memoize-wrapped pipe gets
  a DomainDirty in production — orphan rows accumulate until they're
  diffed away.
- **Idempotency keys for external effects**: HTTP POST / send-email
  effects need user-supplied keys. The current EffectKey is content-
  derived (idempotent by construction for pure functions); external
  effects need a contract.
- **In-flight effect cancellation on restart**: process dies with
  effect dispatched but not yet completed. Response cache shows no
  entry. Re-dispatch on restart. For long-running effects (LSP
  requests), is re-dispatch correct, or do we want a "pending" marker
  that persists?
- **EventBus subscriber GC**: when parker row is pulled or cache entry
  dropped, the subscription should be removed. Currently `forget(key)`
  is called by the driver after pulling a Wake::Key row, but path/
  domain subs are never explicitly forgotten. RAII guard pattern
  (like v3 YieldGuard) or explicit unsubscribe?
- **rusqlite version unification**: v4 still pinned to rusqlite 0.31,
  effect_runtime to 0.32. Currently dodged via `default-features =
  false` on the v4 dep. Bump v4 to 0.32 when convenient (small
  breaking change, ~8 sites).
- **cursor_codec::hash_u64 vs [u8; 32]**: hash_u64 currently truncates
  blake3 output to 8 bytes. The Next impl on Cursor uses the full 32.
  Eventually unify or document why two widths exist.
