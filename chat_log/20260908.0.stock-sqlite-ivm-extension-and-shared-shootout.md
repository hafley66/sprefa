## Current extension research and pending decision
Prior art found:
- electric-sql/d2ts: TypeScript differential pipelines with SQLite-persisted operators; does not directly give requested SQL-only stock extension.
- Turso DB experimental DBSP materialized views: SQLite-compatible rewritten engine, not stock extension.
- AhmedFaizanDev/ivm: Astra reports MIT July2026, SQL compiler but Python SqliteAdapter.flush() and in-memory Z-set outputs. Does not satisfy automatic persisted SQL relation contract.
- Rindle: graph/push open engine; SQL capture described as commercial controlled-writer runtime. Verify sources in Astra final artifact.
- No existing drop-in candidate verified yet; this is search status, NOT a claim none exists.

Astra proposed, NOT approved: C loadable installer SELECT sqlite_ivm_create(name, select_sql), existing MIT liteparser1.0.0 AST plus SQLite prepare/catalog checks, persistent AFTER-row delta triggers/result/support tables. First subset ordinary main-schema tables, explicit columns, inner equijoin, GROUP BY integer keys, COUNT and integer SUM, tested NULL and bag semantics. Reject recursion, outer joins, windows, subqueries, nondeterminism and real SUM. Need contracts for REPLACE/UPSERT/conflict modes/multi-connection/rollback/reopen. pg_ivm relies on PG Query AST, DefineRelation/CreateTrigger, SPI, transition tuplestores, MVCC snapshots, locks: not portable without SQLite lowering. Do not implement new substantial compiler before user decision.

Latest executed capability probes reported by Astra: stock Apple SQLite3.43.2 INSERT OR REPLACE emits only insert trigger with recursive_triggers off; emits delete+insert with ON. Transaction rollback removes base and trigger-log mutations. Persistent guard using pragma_recursive_triggers fails under trusted_schema=OFF ('unsafe use of virtual table'), creating writer/security setup boundary. These are built-in trigger probes, not IVM.
