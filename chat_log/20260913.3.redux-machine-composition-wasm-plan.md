## Key Design Findings and User Intent
- User wants statig prevented from becoming hidden impure mutation/I/O escape hatch. Slice is synchronous but Rust can still perform I/O/read clocks/spawn inside sync functions. Neither Slice nor Effect=Never proves purity. Restrict contexts/dependencies, review and replay-test. No silent discarded lifecycle effects to make restore pass.
- Statig blocking currently supplies child-first bubbling, common-ancestor entry/exit sequencing. Existing fighter uses flat Phase and Infallible superstate, rebuilding/initing transient machine each decide; no lifecycle hooks today. User has NOT decided to remove statig.
- StateMachine durable state can itself be Slice::State. Separate machine instances referenced by surrogate IDs, not nested duplicate phase ownership. Internal state hierarchy differs from player/entity ownership relations.
- ApplyImpulse belongs to shared PhysicsCommand addressed by BodyId; fighter owns when/why jump, physics owns execution. Reuse upstream Rapier/Parry/math types, no new generic physics interfaces without need.
- Shooter and fighter may share Grounded/Airborne transitions. Platform-fighter extension handles air jump with explicit precedence and jumps_remaining owner. Air jump may change velocity without lifecycle transition; must specify semantics.
- state!, event!, effect!, machine_slice!, graph!, executors!, game_tick! shown in chat are PROPOSED PSEUDOCODE, none implemented. game_tick intended lowering: ordered existing Slices + typed event/effect routing and library execution, not implicit magic scheduler.
- Inspectable transition metadata can hold source,event,guard/action IDs,target,parent. Arbitrary Rust guards/actions remain code, macro cannot infer all hidden dependencies. Graph declarations can check DAG, clocks, read/write conflicts, executor restrictions. Across-tick feedback explicit; same-clock cycles reject or require solver.
- Simulation/physics required work completes synchronously before snapshot publish. Physics may share simulation thread. Async host work returns owned request/scope-tagged completions at admission boundary. UI projection reads settled state; no mutation on selector reads. Physical threads host-selected, sequential browser possible.
- User wants Rust textbook examples, minimal words, no em dashes, no praise/reframing, no invented interfaces. Skill zoom used for pseudocode. No giant framework first. TypeSpec owns cross-boundary/referenced value contracts.
