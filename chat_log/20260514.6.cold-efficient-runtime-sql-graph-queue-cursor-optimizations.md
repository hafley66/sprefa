Stress file:

```text

```

Shape:

```sprf
rule(:hits, :FS, :LO, :HI) {
  fs(glob`**/*.{c,h}`) > ast(:c)`printk($$$)`
};

rule(:hit_pairs, :FS, :LO, :OTHER_LO) {
  hits?(FS?, LO?, HI?)
    > sql`
        SELECT input.__cursor_idx, input.FS, input.LO, other.LO AS OTHER_LO
        FROM input
        JOIN hits other ON other.FS = ${FS}
        WHERE other.LO != ${LO}
      `
};
```

Current bottleneck:


Prior measured variants:

```text

  materialize_input
```

### 2. Terminal SQL Fact Sink Should Bypass Cursor Batch Insert

Current terminal path in `v4/src/sql.rs`:

```text
run_sql_terminal_output_cursors_on_sqlite_fact_store
  query_sql_output_cursors -> Vec<Arc<Cursor>>
insert_terminal_fact_outputs
  store.insert_batch(table, outputs)
```

This removes a downstream `FactWrite` component, but still creates one `Cursor` per SQL output and sends those rows through `SqliteFactStore::insert_batch`.

Target shape:

```text
SQL output rows
  -> temp stage_raw(id_hex, col text...)
  -> bulk intern distinct strings with INSERT OR IGNORE INTO sprf_strings SELECT
  -> temp stage_ids(id_hex, col_id...)
  -> INSERT OR IGNORE INTO <table>_facts SELECT ...
```

Concrete candidate:

```rust
SqliteFactStore::insert_projected_ids_from_temp_select(
    table: &str,
    stage_table: &str,
    projected_cols: &[String],
) -> InsertSelectStats
```

Call site candidate:

```rust
run_sql_terminal_fact_on_sqlite_store(
    store: &SqliteFactStore<Cursor>,
    sql: &str,
    referenced_tables: &[String],
    batch: &[&Cursor],
    output_table: &str,
)
```

Put the first call in `v4/src/sql.rs`, behind `SqlQueryComponent::terminal_fact`.

`_id` options:

| Option | Notes |
| --- | --- |
| Rust computes `_id` while streaming SQL rows into stage | Lowest semantic risk. Still crosses Rust once, but no full `Cursor` retention. |
| SQLite UDF computes `_id` | Better final shape. Requires registering blake3/canonical-row UDF on the rusqlite connection. |
| Change identity hash | Reject for this pass. `_id = blake3(table || canonical(fields))` is already a cross-table contract. |

First version:

```text
Rust row reader computes id_hex and inserts raw stage rows with stable prepared statement.
SQLite performs set intern and final INSERT SELECT.
```


### 3. Prepared Statements Versus Dynamic Multi-Row VALUES

`SqliteFactStore::insert_batch` currently builds multi-row `VALUES` SQL chunks using `SQLITE_PARAM_BUDGET = 32000`. Local measurements show fewer `sqlite3_step` calls but slower wall than the prepared one-row loop in this workload.

Keep both modes behind an explicit strategy until `INSERT SELECT` replaces the hot path:

```text
SPREFA_SQLITE_FACT_INSERT=prepared_loop | multi_values | stage_insert_select
```

Default should be decided by measurements, not statement count. Inner statement count is telemetry, not the objective.

Telemetry already present:

```text
sqlite_insert_exec_calls
sqlite_insert_exec_rows
sqlite_insert_ms
```

Add:

```text
sqlite_insert_strategy
sqlite_insert_sql_text_bytes
sqlite_bind_param_count
sqlite_prepare_ms
sqlite_step_ms
```

The N+1 warning should use both layers:

```text
outer N+1:
  insert_calls high and insert_batch_calls low

inner N+1:
  sqlite_insert_exec_calls ~= sqlite_insert_exec_rows
  or avg_rows_per_exec below configured threshold
```

## Runtime Graph / Queue Hot-Cold Split

### Durable State

Keep durable:

| State | Reason | Current path |
| --- | --- | --- |
| fact tables and rule outputs | visible output and relation state | `SqliteFactStore`, `v4/src/fact.rs`, `v4/src/rule.rs` |
| `_strings`, `_files`, `_where_bytes`, `_paths`, repos/revs | stable ids, source provenance, coord resume | `v4/src/store.rs` |
| source subscriptions | restart wake targets | `v4/src/runtime_graph.rs` |
| continuations needed to rerun an owner | cold resume and external event replay | `RUNTIME_CONTINUATION`, compact side table |
| runtime events/jobs | pending work after source change | `runtime_event`, `runtime_job` |
| mounted SQL metadata when below threshold | replay mounted SQL against changed deps | `v4/src/mounted_query.rs` |

### Hot RAM State

Keep hot only:

| State | Reason |
| --- | --- |
| active immediate queue rows during one drain slice | replayable from source facts and continuations |
| parsed ASTs and source byte buffers | content-addressed by file/content hash, re-readable |
| component instances and lowered pipe objects | can be rebuilt from sprf source |
| cursor `Arc` values inside current dispatch batch | bounded by batch cap |
| LRU entries in `SprfStore` | rehydrated from fact store |
| memo caches for pure ops | invalidatable by content hash/table version |

### Replayable Rather Than Durable

Queue rows should be durable for parked waits and crash-proof drain tests, but large runnable frontiers should be replayable from:

```text
sprf source + rule table state + runtime continuations + source subscriptions
```

Cold resume strategy:

```text
1. Load sprf program and rebuild pipe instances.
2. Load runtime source subscriptions / compact continuations from SQLite.
3. Load unconsumed runtime events and pending jobs.
4. For each job, rerun owner from stored continuation cursor or mounted SQL snapshot.
5. Recreate only the active queue frontier needed for that owner.
```

Existing hooks:

```text
v4/src/runtime_replay.rs:
  GraphReplayRunner::drain
  rerun_continuation_owner
  run_tail_from

v4/src/runtime_graph.rs:
  pending_jobs
  continuation_for_owner
  record_source_subscriptions
  CompactSourceGraph::continuation_for_owner
```

### Avoid Retaining Huge Cursor Sets

Problem sites:

```text
query_sql_output_cursors -> Vec<Arc<Cursor>>
record_sql_outputs -> output_cursors -> persisted cursor blobs
GraphReplayRunner::node_seeds -> Vec<Arc<Cursor>>
SqliteQueue rows -> next_blob for every parked cursor
```

Existing guard:

```text
MAX_RUNTIME_SQL_SUPPORT_ROWS = 10000
```

Extend this pattern:

```text
terminal SQL fact sinks stream to table, not Vec<Cursor>
large mounted SQL output stores row ids/support edges, not cursor blobs
GraphReplayRunner tails stream seed batches instead of collecting all seeds
queue spills only parked waits or bounded runnable chunks
```

Cursor retention counters:

```text

cursor_vec_peak_bytes_est

terminal_output_streamed_rows
terminal_output_retained_rows
```

### Runtime Graph Compact Side Table

`CompactSourceGraph` currently stores:

```text
owner_id TEXT PRIMARY KEY
source_id TEXT
pipe_hash
instance_id
depth
input_cursor BLOB
generation
```

Good direction for cold efficiency:

```text
source subscriptions use compact rows instead of full generic graph expansion
input_cursor is binary, not hex text
lookups are indexed by source_id
```

Gaps:

```text
owner_descriptor from compact graph returns empty ast_uri/input_key

```

Candidate:

```text
compact runtime tables should be first-class for source subscription and continuation resume,
while generic runtime_node/runtime_edge stays for visible/debug graph views and smaller cardinality cases.
```

## Cursor Optimizations

### 1. Prefer Byte-Offset Refs Over File String Clones

Current cursor terms carry:

```text
name: Arc<str>
value: Arc<str>
cursor_value: CursorValue
value_id: StringId
at: Ref
```

Current stress rows still include text fields like:

```text
FS, LO, HI, OTHER_LO, value
```

Cold-efficient row should preserve:

```text
file/path/source identity: FileId/PathId/StringId
span: WhereBytesId or Ref
display text: StringId
```

Preferred source-backed cursor output:

```text
term.value_id = interned string
term.at = _where_bytes id
term.cursor_value = CursorValue::WhereBytes(id) for span refs, or String(id) for text
term.value text only materialized when display/query needs it
```

The plan already exists in code:

```text
v4/src/store.rs:
  _where_bytes(id, string_id, file_id, lo, hi, repo, rev)
  intern_where_bytes
  where_bytes_of

v4/src/lib.rs:
  CursorValue::WhereBytes
  Term.value_id
  Term.at
```

SQL views can expose both:

```text
human text columns for current SQL compatibility
*_id columns for joins and staged inserts
```

Example direction:

```sql
SELECT input.FS_id, input.LO_ref, other.LO_ref AS OTHER_LO_ref
FROM input
JOIN hits other ON other.FS_id = input.FS_id
```

Then final fact rows can be integer ids without rehydrating path strings.

### 2. `_where_bytes` Should Become The Join Payload

For AST hits:

```text
FS path string + LO/HI strings are currently sufficient but bloated.
WhereBytesId encodes string, repo, rev, file, lo, hi.
```

Store columns for source-backed hit facts:

```text
hits(fs_file_id, hit_ref, lo, hi)
```

or:

```text
hits(path_id, where_bytes_id)
```

For the join stress:

```text
JOIN by file id or path id
project where_bytes_id for hit span
```

This avoids:

```text
path string clone per output row
LO/HI decimal strings per output row
re-parsing u32 offsets from strings
string interning the same path 706778 times at write boundary
```

Compatibility layer:

```text
SQL temp input can expose text aliases FS/LO/HI and id aliases FS_id/LO_i/HI_i.
Existing sprf SQL keeps working; new lowered rules can use id columns.
```

### 3. Source And Content Hashes

Current `SourceReader` interns file content hash and path when reading source. `Cursor::content_hash()` re-encodes full cursor bytes each call.

Candidates:

```text
cache cursor content_hash with invalidation in Cursor::set/set_arc/unset/set_focal_at
for source-backed cursors, hash stable tuple (repo, rev, file, lo, hi, term ids) instead of text bytes
carry source content hash from `_files.content_hash` into query cache keys
```

Mount cache key today:

```text
sql + input cursor content_hashes + table versions
```

Better cold key:

```text
sql hash + input ids/refs + table versions + source content hash ids
```

This reduces encode/decode pressure in:

```text
v4/src/runtime_bridge.rs::content_hash
v4/src/cursor_codec.rs::hash_u64
v3/crates/effect_runtime/src/v2/sqlite_queue.rs::QueueInsertRecord::from
```

### 4. Blob / Cell / Ref Semantics

`CursorValue` already distinguishes:

```text
Null, Bool, Int, Float, String(StringId), WhereBytes(WhereBytesId), Blob(BlobId)
```

Use this split:

| Kind | Meaning | Storage |
| --- | --- | --- |
| `StringId` | display text or scalar string | `_strings` |
| `WhereBytesId` | source byte span, optionally with string id | `_where_bytes` |
| `BlobId` | page/blob handle, source page, rendered artifact, or large output | future `_blobs` / page table |
| `Int/Bool/Float` | typed scalar | cursor term payload, SQL INTEGER/REAL path |

Current SQL store maps every declared fact col through `sprf_strings`. That loses typed scalar benefits. For cold efficiency, add typed column families later:

```text
<col>_string_id
<col>_where_bytes_id
<col>_int
<col>_blob_id
```

First low-risk step:

```text
terminal stage can preserve integer ids as text-compatible columns while final schema remains current wide string-id shape.
```

### 5. Terminal Sinks And Streamed Sinks

Rules ending in terminal sinks should avoid constructing `Node::Emit` values that no downstream component reads.

Already partially present:

```text
SqlQueryComponent::terminal_fact
insert_terminal_fact_outputs
rule_ending_in_sql_fuses_terminal_fact_write test path from prior notes
```

Extend to:

```text
sql -> rule(:table)             stream stage into table
ast -> rule(:hits)              write projected source refs directly
render/page/blob sinks          write pages/chunks, emit small BlobId cursor or no cursor
graph/render sinks              streamed writer with row count, not Vec<String>
```

Add sink trait shape at component level only when needed:

```text
TerminalSink {
  begin(batch_meta)
  write_row(row_ref)
  finish()
}
```

No need to change sprf syntax for this pass; lower-time optimizer can fuse adjacent components as described in `chat_log/20260514.5.lowered-pipe-compile-time-lifting-agent-notes.md`.

### 6. Page Blobs / Streamed Output

For large render or mounted outputs:

```text
store page blobs keyed by content hash
store small row refs in fact tables
stream to file/LSP/http without retaining full Vec
```

Candidate tables:

```text
_blobs(id, content_hash, len, media_type, storage_kind, path_or_inline)
_blob_pages(blob_id, page_idx, bytes)
```

The rule output relation stores:

```text
blob_id
where_bytes_id
row_id
```

not full rendered text per support edge.

## Priority Order

1. Implement staged terminal fact insert for SQLite: temp stage, set intern, final `INSERT OR IGNORE INTO facts SELECT`.
2. Add strategy and timing telemetry around SQL workspace, terminal fact rows, inner SQLite execs, and index timing.
3. Make compact runtime source subscriptions carry enough descriptor data for cold replay, and add connection PRAGMAs.
4. Stream replay/tail seeds in chunks; avoid `Vec<Arc<Cursor>>` for high-cardinality SQL outputs.
5. Cache cursor content hashes with mutation invalidation.
6. Move AST/source hit facts toward `WhereBytesId`, `FileId`, `PathId`, and typed payload aliases while preserving text SQL compatibility.
7. Add page/blob streamed sinks for large rendered outputs and mounted-query support state.
