## Problem/Context
After the four DSL ports, conversation pivoted to the design of the join layer that will compose cst lib + effect_runtime (v2) + sprf bindings. The other claude is on session 5 (`v4-react-runtime-effect-bus-redux-persist-plan`) building the React-shaped runtime in `v3/crates/effect_runtime/src/v2/`. v4 IS the POC crate; sprf bindings live there too.

User's framing for v4 POC: lower everything to terms uniformly. Pipes + Cursors are the only traits getting tossed around. The lowering is the POC's finale — making it uniform/unified is the priority. `TERM` (uppercase Prolog-ish bareword) and `${pipe}` (ES6 template hole) both lower to ops, which lower to pipes.

Vocabulary shift this session (load-bearing): "carveout" → "template hole"; `${X?}` → `${<any pipe>}`; future holes accept arbitrary pipe expressions, not just identifiers. Distinction between sprf-host `${...}` (template-string interpolation, evaluated at lower time, never reaches lib) vs DSL-native `$NAME` (per-DSL grammar, parsed by lib, captures emerge at match time).

User's stance on bracket-arg `[rs]` / `[rust]` in `ast[rust](...)`: less necessary, "yet another pipe instance lol — ast.rs is the ast grep with rs set". Dot-dispatch / suffix-name / first-arg are interchangeable. Lib stays neutral; sprf decides keying scheme.

## Solution/Approach
Recommendation crystallized: **NO SComponent trait.** The two existing traits (cst::Dsl, effect_runtime::v2::Component) cover the surfaces. Sprf provides:
- `struct SOp { compiled: Box<dyn cst::Compiled>, ... }` impl `Component<Next = Cursor>`
- `fn s_op(dsl, body, body_off) -> Arc<dyn Component>` factory
- `fn lower_op(host_node, src) -> Arc<dyn Component>` dispatcher (registry of op_name + bracket → dsl factory)
- Host-level `${...}` interpolation pre-runs upstream pipes and substitutes bytes BEFORE `dsl.compile`, so DSLs never see `${...}`
- LSP path is fully orthogonal to runtime Component pipe — walks the source-level CST, dispatches to each op's `DslBodyLsp` for body queries

The "join" is just struct composition + a factory. No new trait.

## Key Insights
- **`${...}` is host-level, not DSL-level.** Sprf parses `${...}` (host grammar), evaluates the contained pipe expression at lower time, splices the resulting bytes into the body BEFORE handing to `dsl.compile`. The lib never sees `${...}`. Each DSL only knows its own native binding syntax (re's `(?<NAME>)`, glob's `$NAME` segment, json's brace captures, ast's `$NAME`).
- **declared_captures was the wrong concept.** Names emerge from match_into rows; pre-declaration is a leak of DSL internals. Each DSL still needs internal name tracking (ast's metavars drives env lookup) but that stays private.
- **No SComponent trait.** Trait inheritance over `effect_runtime::Component` would couple sprf into the runtime crate. Struct composition keeps the libs sprf-blind.
- **LSP and runtime are independent paths.** LSP walks source-level CST → dispatches to `DslBodyLsp`. Runtime walks pipe of Components → calls render. Same `Compiled` instance can be shared via Arc if memoization matters, but the paths don't share lifecycle.
- **Bracket-arg sugar is interchangeable.** `ast[rs]`, `ast.rs`, `ast_rust`, `ast(rs, body)` all map to `AstDsl::new(SupportLang::Rust)`. Lib's constructor is grammar-neutral; sprf picks the surface syntax.
- **The byte-rewrite shortcut for bound holes works for re/glob/json, breaks for ast.** Ast-grep needs MetaVarMatcher constraint at pattern compile time, not text substitution. POC can ignore this; full bindings-aware compile becomes a lib trait extension later.
- **Copy-then-adapt is the right port shape for non-trivial DSL ports.** Json port was 2500 LoC; needed only 2 import-path edits because the v3 walk+data crates were already crate-locally pure (didn't reach into pipeline-specific types beyond what we manually wrap). Faithful preservation > rewriting.
- **Linker miss after adding new TS-backed DSL:** `compile_grammars` only re-runs when build script is dirty. Adding a new dsl dir without touching build.rs leaves the new static lib unlinked → `Undefined symbols: _tree_sitter_sprefa_<name>`. Fix: `touch build.rs`.
- **ast-grep Pattern::try_new is permissive.** Patterns like `fn $NAME( {` parse without error. Don't write tests asserting compile-time failure for syntactically broken-looking patterns; use non-utf8 bytes for the fatal test.
- **sprf vocabulary distinction maintained:** `${X}` = template hole (host), `$NAME` = DSL-native capture (lib). Visually similar, semantically distinct. v3 had `${X?}` for "must-be-unbound"; v4 drops the `?` suffix entirely — binding context determines mode, no body-side declarative marker needed.
- **Prolog-ish all-caps semantics.** `TERM` (bareword) and `${TERM}` (template) both lower to ops. `term(:xyz)` defaults to assigning cursor.value. Lib doesn't enforce the convention; it's sprf grammar.

## Open Questions
- Where does `SOp` + `s_op` + `lower_op` live in v4? `v4/src/sprf/`? `v4/src/lower/`? `v4/src/op/`? No existing convention.
- How is the upstream binding context passed through the pipe at lower time? Per-op closure capturing prior op's declared output names? Static analysis pass over the host CST? The user wants this to be uniform — what's the carrier?
- `Cursor` definition in v4: does it follow v3's shape (byte_range + captures + content + fs/repo/rev) or simplify? Needed before SOp can impl Component<Next=Cursor>.
- For `ast.rs` style dot-dispatch: is the sprf host grammar going to parse `ast.rs` as a single op_name, or as `ast` op + `.rs` selector? Affects registry shape.
- When sprf wants to wire the byte-splice path for re/glob/json, does the lib expose a helper (`cst::splice_holes(body, ranges, replacements)`) or does sprf write its own? Probably sprf-side for now.
- How does `inspect` (find hole positions) work without lib support, given sprf needs to know hole byte ranges to splice? Answer (this session): sprf's host grammar parses `${...}` itself as part of host CST, gets positions natively. Lib doesn't need inspect.
