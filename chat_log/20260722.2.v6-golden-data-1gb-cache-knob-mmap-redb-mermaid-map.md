## Key Insights
- rust_peak ~0.16MB is NOT the footprint (Rust-heap high-water only; work is in
  SQLite C-heap + disk). Footprint = RSS/sqlite_hw. dd's memory is RESIDENT
  arrangements (non-evictable, OOMs); sqlite's is page cache over disk (bounded,
  TUNABLE via cache_size, evictable). That tunability is the whole win, not RSS
  magnitude (comparable at a given scale).
- CYC 11.5M: dd 2963ms/2276MB-resident vs sqlite-scc 28374ms/0.16MB-rust(2.7GB RSS).
  dd ~9.6x faster but OOMs under any real budget; sqlite is the sole finisher.
- retract_scc (SCC nested fixpoint) is cycle-correct and BEATS DRed ~6%, but the
  DAG early-out did NOT land (still 4.4x plain counting on acyclic cuts) = H4.
- G8 redb does NOT deliver flat RAM (climbs ~97 B/node); mmap win unproven.
- codex needs < /dev/null or it wedges on stdin. Never trust subagent output;
