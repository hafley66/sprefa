## Key Insights
- VS Code LSP server stickiness: extension reinstall + window reload do NOT kill the spawned LSP child. Cmd+Q on VS Code or explicit killall sprefa-lsp required. Any "rebuilt but bug persists" loop on the LSP path needs the kill step verified before re-debugging.
- Rule rows DO drain to SQLite (per-rule table + FTS5 trigram + sprf_meta cache + DROP/CREATE/DELETE policy from MetaDiff classifier); tag bags do NOT drain — pure in-memory in RelationStore::inner. The asymmetry is load-bearing for any "use SQLite to solve X" answer.
- rusqlite 0.32 bundled is already in v3/crates/pipeline/Cargo.toml. SQL grammar via tree-sitter-sql is available on crates.io; alternative is to skip the grammar and regex-find ${NAME?} tokens in the where[sql] body for capture-name binding (the SQL parser is rusqlite's anyway).
- The atom_literal lowering strips the leading `:` (registry.rs:308-312). So `rev(:HEAD)` → Value::Atom("HEAD") → glob::compile_str("HEAD") → matches cursor.rev exactly == "HEAD". The colon is a sigil for "atom not bare-ident", not an operator on the value.
- discover_config swallows from_path Err silently. Adding visible diagnostics for config parse errors (publish via LSP, log to stderr) would have caught this within minutes instead of multiple sessions.
- The `i:git-commit` skill's heredoc form chokes on backticks/$/\n inside the message. Use `git commit -F <file>` with Write to /tmp instead — observed twice this session.
