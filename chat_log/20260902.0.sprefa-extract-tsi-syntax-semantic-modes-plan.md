## Solution/Approach
- `FlatFact` stays closed; four envelope records (`protocol`, `run`, `witness`, `coverage`)
  plus ONE open `fact` record `{fact, relation, args}` validated by a registry table
  (`src/tsi/registry.rs`). Existing rows gain `fact=` only under `--witness`; goldens
  byte-identical with the flag off.
- Identity = TSI's four rules; run-local ids on the wire, canonical via v7 `intern/3`;
  natural key `(relation, canonical args)`; store mints INTEGER ids. Resolution results are
  never key parts; they are witnessed rows (`tsi.denotes`, `tsi.has_type`).
- Multi-witness fold replaces first-wins `resolution_origin` (kept as top rank for
  `hosts.rs:1041`).
- Reverse door `extract --ingest`: serde decode, registry check, id closure, coverage
  check, renumber, `sorted_lines` re-emit, idempotent. Build-vs-buy: serde + schemars +
  jsonschema (strict only).
- Semantic adapters: `ts_checker.mjs` tsi arm (getPropertiesOfType, getSignaturesOfType,
  typeArguments, ts.mapped/conditional); `rust_checker_ra.rs` hir walk (Adt fields,
  Trait items -> `rust.assoc`, Impl -> `rust.impl` + `tsi.conforms`, lifetimes, ownership).
- v7 loader `v7/src/0_reader/6_extract_loader.pl` with `accepted/1` verbatim from the
  reference; mirrors `0b_filesystem_grapher.pl` basement shape.
- Arcs A0..A8 mapped to the issue's nine acceptance criteria (PLAN.md section 2).
