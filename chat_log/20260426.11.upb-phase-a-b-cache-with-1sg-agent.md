### Phase A: pipeline::rule_hash (new) + Config.run (extended) + sprf_meta in dump_to_sqlite

```
pipeline/src/rule_hash.rs (NEW)
  RuleHashes { schema_hash: String, extract_hash: String }   [hex blake3]
  compute(defs: &HashMap<Arc<str>, RuleDef>, source: &[u8])
    -> HashMap<Arc<str>, RuleHashes>
  schema_hash  = blake3(name || params lengths || params bytes)
  extract_hash = blake3(name || body bytes from brace_range || sorted_producer_extract_hashes)
  cycle fallback = insertion-order append (cycle handling is sprefa-zcz)

pipeline/src/rule_def.rs (extended)
  RuleDef.body_op_names: Vec<Arc<str>>      [populated by walk_body, used by rule_hash]
  RuleDef.body_self_calls: Vec<Range>       [populated by walk_body, used by 1sg]
  walk_body(src, range, file, rule_name)    [returns (pipe_count, op_names, self_calls)]
  self_recursion_errors(defs) -> Vec<ParseError>   [1sg]

server/src/config.rs (extended)
  RunOpts { out_db: Option<PathBuf>, cache: bool }
  RunOptsWire { out_db: Option<String>, cache: bool }   [serde, [run] toml table]
  Config { seeds: Vec<Seed>, run: RunOpts }
  RunOpts::default = { out_db: None, cache: true }

server/src/bin/sprefa-run.rs (extended)
  CLI parse: --no-cache, --out (overlay onto cfg.run after config load)
  run(source, file, cfg)                     [no out_db/no_cache args; cfg.run is the surface]
  rule_hashes computed once before seed loop
  dump_to_sqlite(store, db, sprf, hashes, run: &RunOpts)
  enum MetaDiff { New, SchemaChanged, ExtractChanged, Unchanged }
  ensure CREATE TABLE IF NOT EXISTS sprf_meta (rule_name PK, schema_hash, extract_hash, last_scanned_at)
  per rule:
    classify (cache_off => SchemaChanged; no curr => SchemaChanged; no prev => New;
              schema differs => SchemaChanged; extract differs => ExtractChanged; else Unchanged)
    Unchanged   => skip DROP/CREATE/INSERT (just print + continue)
    New|SchemaChanged => existing DROP triggers/fts/table -> CREATE -> indexes -> triggers -> INSERT
    ExtractChanged    => DELETE FROM "{table}" then INSERT (no DROP/CREATE; FTS triggers re-mirror)
    UPSERT sprf_meta on commit

ParseErrorKind::RecursionForbidden { rule: Arc<str> }   [additive, sprefa_parse]
```

  blake3_of(bytes) -> Arc<[u8; 32]>

pipeline/src/ops/read.rs (refactor)

## Key Insights

1. **Config is the surface, not function args.** When a CLI flag fans out as parallel args through run() and dump_to_sqlite(), the LSP/HTTP equivalents will redefine the same shape twice. Collapse onto `Config.run: RunOpts`; CLI/toml/HTTP all overlay onto it. Mid-flight user correction; saved a lot of churn.

2. **rule_hash composition needs cross-rule producer edges.** The walker (pipeline::rule_def) already runs the brace body re-parse for body_pipe_count; extending it to record `body_op_names` is one extra Vec. Cross-rule edges = body_op_names ∩ rule_defs.keys(). No separate binding_graph traversal needed for upb Phase A.

3. **content_hash and reader-precomputed hash compose at one site.** ReadResponse threading lets a future git-backed source skip blake3 without changing ensure_content_loaded's downstream contract. Default-impl on FileSource means working-tree reads keep current behavior.

4. **rebase clears content_hash; narrow doesn't.** rebase replaces the underlying content blob (post-read), so old hash is invalid; narrow only reframes byte_range over the same content, hash stays valid. Today only narrow keeps the hash; downstream consumers that wrap content (ast/regex/json) call rebase or narrow accordingly.

5. **Phase C wants what Phase E gates.** Cross-run L1 cache requires stable op identity. Per Phase 0 lock, Op trait additive methods are Phase E (sign-off gate). Phase C without E is either pointer-keyed (single-run, low value) or eats the additive method early. Decision needed before starting C.

6. **Sub-agent commit semantics.** Asked agent to land 1sg with "no core changes" constraint. Agent honored constraint (additive ParseErrorKind variant only, no Op/RtCtx changes), but had to fold in parent-session WIP because the working tree was a buildable hybrid. Commit message attributes parent work transparently. Lesson: when dispatching parallel work, either commit pending work first, or expect the sub-agent's commit to bundle.

7. **Justfile location matters.** v3-only recipes belong in v3/Justfile, not the workspace-root Justfile. Otherwise every recipe accretes `cd v3 && ...` prefixes. Saved as feedback_justfile_in_subcrate.md.

## Open Questions

1. **Phase C design lock.** Pointer-keyed (single-run) vs early Op::cache_key additive trait method vs pause-until-E? Recommend (a) — additive default-None opt-in is the smallest move that buys cross-run benefit; ops that don't opt in get no caching but no break either. User has not weighed in.

2. **Hashing cost when cache is off.** Phase B always hashes. If `cfg.run.cache=false`, hashing is wasted work. Could gate on cache flag (plumb a bool through RtCtxBuilder), but adds runtime field. Open question: measure first, gate if needed. Filed as a follow-up implicit in Phase B card.

3. **`rebase` clears slots and content_hash; correctness unverified for ast/json paths.** Those ops rebase to a sub-byte range or different content (e.g., synthesized capture text). Need to confirm none of them depend on content_hash being preserved across rebase. Today no consumer reads content_hash, so the answer is "no impact" — but Phase C will surface this.

4. **Agent's _4_fs_glob_nested fixture change.** Restored unilaterally. Agent likely intended only the `$R` → `${R?}` grammar update; the glob change was incidental. Worth a memory entry: when accepting agent commits that touch fixtures, eyeball the diff.
