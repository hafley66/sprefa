## Solution/Approach

### Unification thesis
One IO contract: cursor[] -> cursor[]. Every composable thing impls Op. Args are tuples. Pipes are tuples. Patterns internally bag more ops. Making every value a Pipeline (or liftable to one) unifies host pipes and arg expressions — no two worlds.

### Value collapse target
Scalars stay (Atom/Str/Int/Float). Pattern + Pipeline + Term all fold into Value::Op(Arc<dyn Op>). $NAME is sugar for term-op; ${body} is term-op with sprf-body slot.

### Op capability surface
Op stays object-safe. Add optional methods with defaults absorbing PatternValue's slots: bound_captures(), try_raw_regex(), materialize_with(bindings). PatternValue trait deleted; concrete matcher structs (GlobPattern/RegexPattern) fold into their ops' compiled state. PatternOp extension trait stays for sub-grammar owners (compile/language/highlights/hover_match).

### Scan-pointer as op category
Three shapes distinguished by unbound-arg behavior:
- produce-or-filter (tag/fs/rev/repo) — has source to draw from
- filter-only (is_rev/is_repo/is_fs) — no source, asserts only
- pattern-with-embedded-term (re/glob/json/ast) — write/read dispatch already landed

Per-op arg-mode dispatch: each op reads cursor.captures for names in bound_captures() and chooses branch. Pipe order is goal order. Shallow prolog, forward-only, no backtrack.

Term-as-cursor-of-1-hashmap: a term IS a cursor with one capture slot entry. Three-state (unbound/bound/free) collapses to two — "free" is just slot-absent = resolver error at lower time.

Two equivalent compositions: json({ ${KEY > is_rev()}: _ }) and json({ ${is_rev($KEY)}: _ }) end with KEY bound iff is_rev approves. Composition shape is sugar.

### Lowerer trait fu
Object-safe Op can't hold constructors. Split:
- Op (dyn-safe runtime surface)
- OpCtor (Self: Sized; from_values + compile_from_tree + language_static)
- OpLowering (registry-facing factory with default impl DefaultLowering<O>)

DefaultLowering routes on language_static() presence: Some → compile sub-grammar; None → walk paren children to Vec<Value> + from_values. arg_spec() pre-validates slot shapes.

Registration: registry.register::<FsOp>("fs") for 90% of ops; registry.register_custom("tag", TagLowering) for ops needing raw CST inspection (per-slot arg-mode dispatch that can't be expressed via arg_spec).

## Key Insights
- The unification is at the TRAIT tier, not the ENUM tier. Value variants are syntax/storage; the IO contract is the shared trait surface.
- as_raw_regex / materialize_for are not dead weight; they're the intended bulk-inspection surface. Consumers haven't been migrated onto them yet. That migration IS the x5b work.
- Scan-pointer = op that writes cursor.captures from its pipe body. No framework machinery. bound_captures() is declared-intent contract; the op owns every read and write.
- Forward-only prolog: pipe order = goal order. No search, no re-ordering, no backtrack. Op-level bound/unbound dispatch via cursor.captures state.
- Term-as-cursor-of-1-hashmap collapses the three-state model to two. "Free" variable isn't a runtime state — it's a lower-time resolver error.
- Registry::register<O>() for default lowering; register_custom for ops that need raw CST (tag is the canonical consumer).
- First agent pass miscalibrated the scope. Letting the user correct "we WANT those things, migrate consumers" re-anchored the spike on the real work.
