## Solution/Approach
Converged on these design decisions:

### Cursor-as-state reactive model
- Everything is strings. No type distinctions between files/content/rows/captures.
- Cursor carries: repo, rev, folder, file, byteRange, line, content, captures (all string | null).
- Operators are uniform shape: `(input$, args, side) -> Observable<Cursor>`.
- Chain composition is `reduce` over operators.
- Scope blocks are recursive `mergeMap` (or switchMap).
- Cross-rule refs are `mergeWith` on upstream rule's output stream + `scan` to accumulate state, NOT `queryTable()`.
- Rule streams are `ReplaySubject<Cursor>` so late subscribers get all prior emissions.
- Daemon mode: streams stay hot, file changes push new cursors, downstream reacts.
- Batch mode = "all streams complete." No separate code path.

### Three-phase scan architecture
- Phase 1: pure extraction (fs/json/ast/line/comment). Zero side effects.
- Phase 2: shell cuts (sh/sh_mut). Reads phase-1 tables. Disallowed → pending_cuts side channel.
- Phase 3: checks + codegen. Consumes whatever tables are populated.
- sh tags never block phase 1.

### Side channel
- SideChannel: errors, warnings, cuts, metrics (all Subjects).
- Pending cuts are NOT errors. They're a side channel for gated shell execution.
- LSP hover shows "Would run N commands: [...] [Run now] [Add to allow] [Skip]".
- CLI: `sprefa cuts`, `sprefa cuts --approve <pattern>`, `sprefa cuts --run <pattern>`.

### Four sh forms
| Form | Reads | Writes FS | Per-row or batch |
|------|-------|-----------|------------------|
| sh() | stdout → downstream | no | per-file or per-row |
| sh_mut() | stdout logged | yes | per-file or per-row |
| sh_batch() | stdout → downstream | no | 1 call, all values |
| sh_mut_batch() | stdout logged | yes | 1 call, all values |

Cross-rule syntax:
- `${rule.VAR}` — single value, iterates per row (like existing cross-ref).
- `$$${rule.VAR}` — all values, space-separated (one call).
- `$$${rule.VAR:,}` — comma-separated. `$$${rule.VAR:\n}` newline. `$$${rule.VAR:"}` JSON-quoted array.
- Dots legal because bash disallows dots in variable names. No collision.

Permission model:
```toml
[shell]
allow = ["jq *", "git tag *", "npm view *"]
allow_mut = ["sed -i *", "prettier --write *"]
timeout_ms = 10000
max_batch = 500
```

Sanitization: shlex::quote each expansion, reject if value contains `; | & \` $( ${ \n`, reject >4096 bytes, log every expansion.

### Self-rendering codegen via comment scopes
Codegen block declares `source: <ref>`, `target: <tag chain ending in comment>`, `template: "string"`. Writes generated content between `<!-- sprf:codegen name -->` and `<!-- sprf:codegen-end -->` markers. Daemon keeps STATUS.md live: errors, violations, pending cuts, parse diagnostics all rendered as markdown.

Other self-rendering patterns: dep tables in README, API docs from openapi, env inventories from k8s configmaps, etc.

### Grammar: three disjoint levels
- Level 1: Statement. `rule(name) { body }`, `check(name) { sql }`, `codegen(name) { fields }`, `let NAME = "value"`. Top-level only, terminated by `;`.
- Level 2: Tag (inside rule body). `fs`, `json`, `sh`, etc. Chainable with `>`, can scope with `{}`, body is pattern language.
- Level 3: Pattern (inside tag body). `re:regex`, `$CAPTURE`, `{key: val}`, literal.

`check()` and `rule()` are already block-required statements. Adding `codegen()` and `let` is additive — same shape as existing statements, separate grammar level from tag chains.

### Operator metadata
Every operator declares:
```
block: "scope" | "tap" | "fields" | "forbidden"
chain_position: "driver" | "transform" | "terminal" | "any"
```
- `scope` block: cursors flow through (current sprf behavior)
- `tap` block: cursors branch off, don't affect `>` chain
- `fields` block: keyed structure (like codegen fields)
- `forbidden`: no block allowed
Only `scope` blocks can sit before `>`.

## Key Insights
- sprefa is fundamentally reactive: cursor threaded through operators, each emission is a potential table row. Batch vs live is just "streams complete or not."
- Cross-rule refs done right are NOT table queries, they're `mergeWith` on upstream rule's ReplaySubject. Daemon mode falls out naturally.
- Pending cuts are NOT errors. Side channel for gated execution with LSP hover UX.
- `${rule.VAR}` vs `$$${rule.VAR}` mirrors `$NAME` vs `$$$NAME` capture semantics (one vs many). Dots work because bash disallows them in var names.
- Statements (`rule`/`check`/`codegen`/`let`) and tags (`fs`/`json`/`sh`/`comment`) are disjoint grammar levels. No mixing.
- Block as trailing-lambda arg (Kotlin/Ruby style). Per-operator flag decides: scope/tap/fields/forbidden.
- Piping a body only makes sense if block produces cursors for downstream. `scope` blocks pipeable; `tap`/`fields` blocks terminal.
- Self-rendering codegen into comment scopes + daemon mode + `sprefa codegen --check` = STATUS.md always current, CI gates drift.
- USER'S AND/OR INSIGHT (not fully explored): labeled branches = OR (switchMap), semicolon-separated unlabeled branches = AND (combineLatest/merge). `mergeByKey` as mental primitive.
- 42k-token explore agents should be compressed into docs/ so future sessions skip re-exploring.
