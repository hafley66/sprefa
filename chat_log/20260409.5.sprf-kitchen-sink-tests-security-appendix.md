## Key Insights
- line_regex rules using (?P<name>...) named groups produce lowercase captures invisible to SCREAMING_CASE extractor -- captures happen at runtime via regex engine, not at parse time
- Empty json({ }) pattern produces no create_matches by design (vacuous object match)
- Array and quoted-key patterns nest inside Object entries, not at top-level select -- test assertions need recursive tree walking
- ast-grep nesting combinators (inside/has/follows/precedes) have type-level support via AstSelector.rule field but no .sprf surface syntax -- parked as low priority since cross-rule refs + SQL joins handle the scoping problem at data level
- .sprf DSL intent: personal research language exploring glob/bash + prolog-style declarative binding unification. Evaluated as experiment, not adoption vehicle.
