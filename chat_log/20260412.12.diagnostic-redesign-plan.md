# Session: diagnostic-redesign-plan

## Current State (Problems)
- LSP shows "JSON path doesn't match file structure" errors that are wrong
- Analyzer GUESSES what's wrong instead of scanner reporting it
- Extractor returns empty results with no explanation
- Multiple scan_file functions exist but are unused (dead code)

## Root Cause
The analyzer's `check_json_path_mismatch()` function samples files and guesses the issue:
```rust
if total_captures == 0 {
    let path_issue = check_json_path_mismatch(rule, &files, options);
    // Reports generic error without knowing actual problem
}
```

## Target Architecture

```
SPRF File → Parser → Lowerer → Extractor → (matches, diagnostics)
                                     ↑
                         Each matcher reports its own errors
```

## What User Wants
1. **LSP does NO parsing/analysis** - just displays what scanner reports
2. **Scanner reports specific diagnostics** with byte ranges
3. **No guessing** - either scanner knows what's wrong or it doesn't

## Implementation Plan

### Phase 1: Add Diagnostic Type to Extractor
```rust
pub struct Diagnostic {
    pub message: String,
    pub location: SourceRange,  // Byte range in source file
    pub severity: Severity,
    pub code: String,          // "json-path-not-found", "toml-parse-error", etc.
}
```

### Phase 2: Modify Extractor Return Type
Change `eval_raw()` from:
```rust
fn eval_raw(...) -> Vec<RawRef>
```
To:
```rust
fn eval_raw(...) -> (Vec<RawRef>, Vec<Diagnostic>)
```

### Phase 3: Implement Per-Matcher Diagnostics

#### JSON/YAML/TOML Matcher
- Parse error: "TOML parse error at line 5, col 10: expected '='"
- Path not found: "Path 'package.name' not found, available: package, workspace"
- Type mismatch: "Expected object at 'dependencies', got string"

#### AST Matcher
- Pattern parse error: "AST pattern '(foo' error: unclosed paren at byte 4"
- No matches: "Pattern 'ClassName' matched 0 nodes in file.ts"

#### Line Matcher
- Regex error: "Invalid regex '(abc': unclosed group at byte 4"

#### File Pattern Matcher
- Glob error: "Invalid glob '**/[abc': unclosed bracket at byte 6"

### Phase 4: Update Analyzer
- Remove `check_json_path_mismatch()` function
- Forward extractor diagnostics directly
- Only add parse/lower errors (from actual parser)

### Phase 5: Update LSP
- Remove all diagnostic generation from LSP
- Just convert `AnalysisDiagnostic` to LSP `Diagnostic`
- Use byte ranges from analyzer directly

## Key Insight
**LSP is a dumb pipe.** Parser → Lowerer → Extractor → LSP. No analysis in LSP.
