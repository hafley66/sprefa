## Key Insights
- **Compression ladder for cst lib**: 6 levels from hand-written (210 LoC × 4) → table → macro → grammar-driven → algebra → bootstrap (sprf defines its own DSLs) → type-level. Practical floor for now is Level 0 (current); Level 2 (proc-macro) when 5-6 DSLs; Level 3 (grammar-driven) when 8+; Level 5 (bootstrap) when sprf lowering is stable.
- **Maximum compression that preserves semantics**: collapse traits to function pointers. `Dsl` becomes a struct of fn pointers; `Compiled` becomes a Box<MatchFn>. Reason not to: discoverability + dyn searching in rustdoc beats byte-count win.
- **Cst lib has zero outstanding design pressure**. Streaming budget on match_into and bindings-aware compile (for ast) are the two near-term additive bends. Both are extra args, not redesigns.
- **Rederivable parsed-target state via effect_runtime memo + tick cache** dissolves the "structured target type" pressure. cst stays at &[u8]; sprf-side caches own the parsed JSON/YAML/TS-tree per content_hash.
- **Each Component = BehaviorSubject**. Single-action redux-store framing was wrong; effect_runtime's render-on-subscribe + Arc<Component> sharing IS the multi-subject locality model. No global store needed.
- **Demand scanning ($$ pointers in v3) is vestigial**. Facts subsume them: "rule fires when matching fact appears in fact relation" is the generic shape, no special token.
- **Slots collapse to PATH B only**. v2 had typed-slot-OR-content-OR-reader; v4 reduces to "parse cursor.content[byte_range]". One way to read bytes.
- **`effect_store` lives inside effect_runtime, not its own crate**. User correction: separation gets pedantic without insight when the store IS effect_runtime's own persistence.
- **Word "regime" forbidden**. Real-world residue + not in project lineage. Saved to memory.
- **v3 server fat (5425 LoC)** because backend.rs mixes lsp dispatch + state + diag publish. v4 fix: dispatch in sprefa_main; transport in shell; backend.rs disappears as a file.
- **v2 README is the structural reference for v4 shape**. Three-bin model (sprefa-server daemon + sprefa thin CLI + sprefa-lsp stdio↔WS proxy) is the right trinity. v4 maps to sprefa-cli + sprefa-lsp + sprefa-http.
