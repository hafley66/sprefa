## Problem/Context
- Started from checkpoint `60a000b8` ("bounded reactive storage and call-owner delta"). Its resume order treats 7 blockers as per-family work; the structural read is 2 failure classes: (1) memo self-reported freshness lies (blockers 1/3/4 — the alias gate's missing-dep), (2) propagation isn't atomic (blockers 2/5).
- Call family has owned `_call_*` tables (projection tier) — `_call_owner`, `_call_raw_site`, `_call_resolution`, `_call_edge_support`, `_call_def_bucket`, `_call_delta_marker`. Legacy `persist_call_family` writes public rels DIRECTLY from extracted rows AND writes `_call_*` in parallel (two sources of truth = drift surface = alias bug). The delta path (`apply_call_owner_delta` -> `reproject_sqlite_call_affected_keys`) reprojects affected public rows from `_call_*`.
- v4 history (`v3/crates/effect_runtime/src/v2/`, commits `be00eb04`..`3ab6c3c7`) tried a React/Redux/react-query port (`Component::render`, `Memoize`, `Query`, `EffectDispatch` saga, `EventBus`) AND a `DdStore` differential-dataflow impl. It leaked because the memo cached render trees (`Node<Next>`) while relation rows lived in a separate hand-synced artifact; DD was positioned as a storage backend under a React-shaped runtime (inverted layering). Lesson: the unit of memoization must be the derived collection with row-level reconciliation, not the render tree; dep capture must be dynamic (MobX/SolidJS `computed`) not static (React `useMemo` array — undercaptures = alias bug).
- `node` is the WRONG port target for this engine: it's extraction-tier (files -> node rows, no owned/public split), not projection-tier. The right generalization proof within projection tier = host the remaining call rels (`call_kind`, `call_edge_rev`, `call_name`, `call_def_rev`), all same `_call_*` inputs.

## Solution/Approach
- MobX/SolidJS-style auto-tracking: `Family::derive` reads inputs only through `Ctx::scan`/`Ctx::unique_def`, which record a `DepKey{rel, pk}` per row read. Deps captured, not declared — cannot forget a dep you never listed (deletes alias-bug class, once router consumes the deps).
- Host projection families as pure `derive` fns: `CallSite` (flat projection), `CallEdge` (aggregation: GROUP BY+COUNT over resolution⨝site⨝owner, then DISTINCT).
- Flip via env flag `DL_FAMILY_CALL=1`: after legacy `persist_call_family` lands, `family_overwrite_call_rels` wipes + re-derives `rel_call_site`/`rel_call_edge` from `_call_*`. Additive; flag off = zero change.
- Differential rail gates every step: family output must equal legacy SQL population on the same fixture. Final rail = real Engine over real .rs, flag off vs on, byte-identical public rels.

## Key Insights
- Two units, do not conflate: FAMILY = bundle of rels sharing owned tables + a delta path (the delta/ownership unit, real, existing in codebase via `CallFamilyWrite`/`persist_call_family`). RELATION = one derived public rel (the derive/trait unit). The `Family` trait is misnamed — each impl produces ONE relation.
- Legacy projection writes public rels AND owned tables from two code paths (drift surface); family path makes public rels pure views of owned tables (one source). This is the architectural win, NOT runtime perf — family path is currently COARSER on deltas (full rewrite S+E rows vs legacy's |Δ| affected) because the router that would scope via deps is unbuilt.
- Dep capture is MobX/SolidJS `computed` (intercepted reads), deliberately NOT React `useMemo` (declared dep array — undercaptures, the alias bug). `v4`'s `with_domain` was the static-tag version that couldn't be both correct and narrow.
- `_call_resolution` is WITHOUT ROWID composite PK `(site_id, callee_sid, kind_sid)` — dep-keyed by `site_id` (leading col), coarse-but-correct (a site's resolutions move together).
- Flag is inert to the test suite except the one integration test that sets it (no other test calls `refresh_call_rels`). `env::set_var` safe (edition 2021).
- The alias bug is NOT fixed by the family path: `_call_resolution` is populated by the same resolution logic, so the family INHERITS the bucket's contents. The fix is routing alias-context changes via deps (needs the router).
