# Session: unified-parse-scan-lsp-implementation

## Goal
Create a unified analysis pipeline that combines parse, lower, and extract phases with shared error recovery, enabling rich LSP features (goto-definition, diagnostics, hover) while keeping the LSP layer thin.

## Problem/Context
LSP was doing too much work inline - calling parse_program() separately, scan_file() separately, and doing its own diagnostic generation. This violated "parser as shell" philosophy and duplicated logic.

## Solution/Approach
Unified analysis pipeline with three phases:
1. parse_phase(): source → stmts + errors (with recovery at statement boundaries)
2. lower_phase(): stmts → rules + symbol_table (per-statement error handling)
3. extract_phase(): rules → extractions + diagnostics (per-rule extraction)

Each phase has error recovery so partial results are always available. LSP is now a thin protocol conversion layer.
