## The full type algebra

```haskell
-- atoms
type RepoId   = Arc<str>
type RevId    = Arc<str>
type FileId   = FilePath
type Bytes    = bytes::Bytes
type Range    = Range<usize>

data ByteRangeRef = ByteRangeRef { repo, rev, fs, byte_range }
data Capture      = { kind :: CaptureKind, ... }
data CaptureKind  = SpanBacked ByteRangeRef | Synthesized Bytes
data Cursor       = { coord :: ByteRangeRef, content, captures, slots, path, evidence }

-- effects (open family, each op adds its own)
class EffectKind e where
  type Response e

  -- examples (each in its own op file, not in core)
  ReadBytes      { at :: ByteRangeRef }                ~> Bytes
  ReadParsed     { at, kind :: ParserKind }            ~> Arc ParsedTree
  ListFiles      { repo, rev, pat :: CompiledPat }     ~> Vec FileId
  QueryStore     { expr, where_ :: Where }             ~> Vec Row
  WriteRows      { table, rows :: Vec RowInsert }      ~> ()
  WriteEdit      { edit :: FileEdit }                  ~> EditId
  ShellCall      { call :: ShellCall }                 ~> ShellReply
  Approve        { effect :: Arc dyn MutationEffect }  ~> EffectStatus
  TemplateRender { tmpl, ctx :: &Cursor }              ~> Bytes

-- runtime context (redux+saga core)
put    :: ∀e. EffectKind e => RtCtx -> e            -> Future (Response e)
select :: ∀s. SlotKey    s => RtCtx -> SlotKey s    -> Value s
emit   :: ∀d. Diagnostic d => RtCtx -> d            -> ()

state  :: watch::Sender State           -- BehaviorSubject
events :: broadcast::Sender Event       -- Subject

-- op
class Op where
  type Cap     :: *       -- capture slot type
  type Diag    :: *
  type Effect  :: *       -- effect family this op emits
  type Slots   :: [*]     -- list of SlotKey this op reads/writes
  pipe :: RtCtx -> Stream (Arc [Cursor]) -> Stream (Arc [Cursor])

-- batcher (one per EffectKind, keyed by TypeId)
class Batcher e where
  WINDOW_MS    :: u64
  MAX_INFLIGHT :: usize
  MAX_BATCH    :: usize
  LEADING      :: bool
  coalesce :: [e] -> BatchReq e
  dispatch :: BatchReq e -> Future (Vec (Response e))

-- pipeline composition
scan :: SprfFile -> Stream Cursor
scan  = parse |> lower |> seed |> runner
  where runner = fix (\loop c -> ops |> loop)

-- the one dyn boundary
BatcherRegistry = HashMap TypeId (Arc dyn BatcherEntry)
put rt e =
    TypeId.of e
  |> registry.get
  |> .submit (Box::new e)
  |> downcast_into (Response e)
```

Dyn boundaries, exhaustive — three:

1. `Captures :: Vec (Box dyn CaptureKind)` — one per cursor
2. `Slots    :: HashMap TypeId (Box Any)` — one per slot key
3. `Registry :: HashMap TypeId (Arc dyn BatcherEntry)` — one global

Everything else: associated types, monomorphized per op.

## Per-effect batching sweet spots (the real number table)

| effect | fixed cost | variable cost | window | max_inflight | max_batch | leading |
|---|---|---|---|---|---|---|
| ReadBytes(git) | 10–100µs (Mutex + syscall) | 0 | 4ms | 1/repo lock | 8 | yes |
| ReadBytes(wt mmap) | ~0 | byte copy | 0 | cores | 1 | — |
| ListFiles | 1–50ms (git_tree_walk) | 0 | 0 (one-shot per rev) | 1 | ∞ | — |
| Parsed | ~μs (parser alloc) | ∝ file size | 0 | rayon pool | 1 | — |
| AstGrepMatch | 0 (pattern cached) | ∝ tree size | 0 | rayon pool | 16 | — |
| QueryStore | ~100µs (plan) | row mat | 8ms | 1 | 64 | no |
| WriteRows | ~1ms (BEGIN/COMMIT) | row insert | 50ms (trailing) | 1/repo | 1000 | no |
| WriteEdit | 1–10ms (wt + index) | 0 | 100ms | 1/(repo,fs) | 32 | no |
| TemplateRender | 0 (pure) | ∝ segs | 0 | cores | identity-key | — |
| ShellCall | 1–10ms (fork/exec) | 0 | never batch | — | 1 | — |
| Approve | seconds (human) | 0 | 0 (fingerprint-coalesce) | 1 | 1 | — |

### The rule

```
batching pays iff:  (per-call fixed cost × N) ≫ (N × per-item variable cost)
```

- **wins**: fixed ≥ 10× variable, variable doesn't grow with batch size
  (syscalls, BEGIN/COMMIT, RTT, lock acquire).
  → WriteRows, ListFiles, QueryStore(IN rewrite), ReadBytes(git).
- **loses**: fixed ≤ variable, or batch holds tail latency hostage
  (mmap reads, pure CPU, already-parallel-via-rayon work).
  → Parsed, AstGrepMatch, ReadBytes(wt).
- **neutral**: wide flat region. Pick based on code simplicity.

### Space cost

```
inflight_ram ≈ MAX_INFLIGHT × MAX_BATCH × sizeof(E)  per kind
ReadBytes    ≈ 8 × 80B       = 640 B
WriteRows    ≈ 1000 × 300B   = 300 KB
ListFiles    ≈ 1 × 200B      = 200 B
QueryStore   ≈ 64 × 150B     = 10 KB
total inflight RAM for batching ≤ 1 MB
```

16 GB budget → inflight cost is noise.

## Incremental migration path (each step compiles green)

1. **add `RtCtx::put` next to existing calls.** New file
   `core/effect/mod.rs`. Ops keep calling `reader.bytes()`.
   `put` has zero callers. Core diff: +1 file.
2. **land one `EffectKind` impl: `ReadBytes`.** One batcher.
   Wire only through `ops/_4_read.rs`. Proof of shape.
3. **migrate one op per commit.** Each migration swaps
   `reader.X().await` for `ctx.put(E { ... }).await`.
   Reader trait stays intact during migration. When the last
   caller is gone, remove the method.
4. **collapse `Cursor` to `{ at: ByteRangeRef, ... }`** once
   `ByteRangeRef` exists. Mechanical sed:
   `c.repo, c.rev, c.fs, c.byte_range` →
   `c.at.repo, c.at.rev, c.at.fs, c.at.byte_range`.
5. **`CaptureKind` trait arrives last.** Variant-by-variant.

### Refactor bill

- **1500–2500 LoC** net change
- **20–30 commits**, each green
- compile time per commit: small

### Escape hatch

If v3 proves too large after step 2, early wins stand alone:
- batching at caller side via `buffer_unordered(N)`
- `ByteRangeRef` atom
- `CaptureKind` trait
- plural reader methods (`bytes_many`, `files_many`)

Any subset yields real perf wins without the rest.

## Priority closes for v2 today (no v3 commitment needed)

By blast radius, smallest-to-biggest win:

1. Replace `join_all(per_cursor_fut)` at `ops/_3_fs.rs:242`
   and `ops/_9_ast_grep.rs:310` with `buffer_unordered(N)` or
   a plural reader method. One commit per op.
2. Remove `block_on` inside async `pipe()` bodies at
   `ops/_0_rule.rs:268,275`, `_5_op.rs:221,1123`.
3. Cap `runtime.worker_threads` vs rayon pool explicitly;
   document the split.
4. Add one plural method to Reader (`bytes_many`, `files_many`).
   Rewriting the two fanout sites to use it locks in the
   plural-API discipline.

Steps 1 + 4 **are** the v3 design restated at the trait-method
level; you can land them without the effect-kind framework and
revisit the full v3 later.

## What does NOT simplify

- tree-sitter `Node<'r>: !Send`. Project to owned at source.
- git2 `Repository: !Send`. `Mutex<Repository>` or per-thread handle.
- LSP/HTTP/CLI transport — untouched.
- `.sprf` parser, walker, pattern compile — untouched.
- SQLite pool, DDL, UDF registration — untouched; called from
  `WriteRowsBatcher::dispatch`.
- reparse + cancellation spine — already effect-shaped.
- `captures`, `slots`, `path`, `evidence` cursor fields — untouched.

---

## What gets harder

- Monomorphization: binary size grows linearly with effect-kind count.
  Measured ~5–8% over trait-object baseline in Haxl-style ports.
- Stack traces inside batcher loop less readable than
  "op calls reader.bytes". Tracing spans around `put<E>`
  boundary become load-bearing.
- Test ergonomics: each effect needs `MockBatcher<E>` or
  per-test override via `RtCtx::register`. Absorbed by
  `RtCtx::for_test` the way `OpCtx::for_test` does today.
- Intra-op dependencies: sequential `.await` on two `put` calls
  works but loses collapse across ops. Applicative bundling
  (`put_many(&[e1, e2, e3])`) wins it back.

## v3 filesystem shape (proposed)

```
src/
  core/
    types/          atoms, Cursor, Capture, CaptureKind, Tri, Slots, SlotKey,
                    SprfPath, PathExpr, ByteRangeRef, ParseSite, OpEvidence
    effect/         Effect, Response, EffectKind, RtCtx::put
    store/          watch<State> + broadcast<Event>
    batcher/        SideEffectBatcher<E> window + leading/trailing + dispatch
    op_trait/       Op + associated types (CaptureKind, DiagKind, EffectKind)
    diagnostic/
    perf/           telemetry, rayon bridge, str_intern, hash
  effects/          read_bytes read_parsed list_files query_store
                    write_edit shell approve_mutation template_render
  parse/            grammar.rs lower.rs dag.rs template.rs
  runner/           seed.rs loop.rs state.rs parallel.rs
  ops/              per-op impls; pipe bodies yield effects only
  analysis/         hover + completion (pure queries)
  lsp/              JSON-RPC transport
  cli/              argv driver
```

Dag and lower live in `parse/` because they are syntactic.
Runner is a sibling of ops because it is the scheduler.
