The react_hook rule was the last silent rule. Chain of fixes needed to make it work:

1. **crates/sprf/src/_3_lower.rs** — ast() lowering for `use${ENTITY}Query($$$ARGS)` was emitting `AstSelector { pattern: Some(...), rule: None, constraints: Some(...), segment_captures: Some(...) }`. This hits Mode::Pattern in ast.rs which does NOT apply constraints. Fixed by wrapping into Mode::Rule when constraints or segment_captures are present:
   ```rust
   let use_rule_mode = constraints.is_some() || segment_captures.is_some();
   ast_selector = Some(AstSelector {
       pattern: if use_rule_mode { None } else { Some(pattern.clone()) },
       rule: if use_rule_mode { Some(serde_json::json!({ "pattern": pattern })) } else { None },
       ...
   });
   ```
   Also updated `lower_ast_braced_capture` unit test to assert against `ast.rule["pattern"]` instead of `ast.pattern`.

2. **crates/rules/src/ast.rs** — `collect_matches` was calling `env.get_match("ARGS")` for the `$$$ARGS` metavar, which returns None because multi-metavars live in `multi_matched`, not `var_matched`. Added `is_multi = metavar.starts_with("$$$")` branch that calls `env.get_multiple_matches(var_name)` and joins text/spans. Also relaxed the `if captures.is_empty() { return None }` guard: skip-bail when `selector.segment_captures.is_some()` so segment post-processing can still run.

3. **crates/sprf/src/_0_ast.rs** — `extract_captures_from_str` did not recognize `${NAME}` braced metavars, so `ENTITY` was missing from the rule's `all_captures()`, which meant `ENTITY` never made it into `create_matches`, which meant even though ast_match populated captures["ENTITY"], no RawRef was emitted for it. Added `${BRACED}` handling that walks to `}` and validates uppercase/digit/underscore.

After all three fixes, the snapshot shows:

## Key Insights
- ast-grep has two separate metavar lookup APIs: `env.get_match(name)` for single `$VAR`, `env.get_multiple_matches(name)` for multi `$$$VAR`. `trim_start_matches('$')` collapses all three dollars so the var_name string is the same either way — you dispatch on the prefix of the original metavar.
- `${BRACED}` metavars require escape hatches at three distinct levels: (1) the ast() body walker for `create_matches` population, (2) ast.rs segment_captures post-processing, (3) the lowering rewriter that emits `$SPREFAN` synthetic metavars. Missing any one layer silently drops the capture.
- Mode::Pattern in ast.rs ignores `selector.constraints`. Only Mode::Rule (via `SerializableRuleCore`) applies regex constraints. If a lowered rule has constraints, it MUST emit `rule: Some(json!({"pattern": ...}))` not `pattern: Some(...)`.
- The `rules_test.rs` suite has non-deterministic group counter ordering that happened to pass before — the snapshot "failures" after my changes are all a flip from random insertion order to alphabetical, which is strictly better. But the user's direction is to delete the whole file, not refresh it.
