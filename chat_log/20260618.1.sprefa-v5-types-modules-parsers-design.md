### Discovered / Decided
- **No composite types.** `Type { Text Int Path File Dir Repo Rev }` ast.rs:4 and
  `Value { Text(String) Int(i64) }` ast.rs:27 are the full data model. SQLite
  stores INTEGER or TEXT only. Wide arity is the tax of the SQL-IR commitment
  (plan 2026-06-01:11-17).
- **Arity mitigation = authoring, not data model.** CodeQL's class is the prior
  art: a class is a characteristic predicate + member predicates + supertypes.
  v5 has no class sugar, but `one base rel + one derived rel per member, joined
  by entity key` is the same shape. The tax is paid in syntax, not storage.
- **Imports stay strict.** Fallible `use?` would force optional rels through
  typecheck + lower + engine, inverting closed-world to open-world. The
  missing-codebase pain lives at the source-resolution seam
  (`resolve_repo` engine.rs:692 bails today), not the import layer.
- **Coordinator folder pattern fits the existing data model.** `--root` is the
  coordinator, repos are subdirs or `RepoConfig` paths, `scan("*", ...)` fans
  out, `repo/rev/file` carry the slug coordinate. Zero new layers.
- **GH not bound.** No `octocrab`/`reqwest` in Cargo.toml. Only `git` subprocess.
  `RepoConfig.url` is an opaque clone string. Multi-format inventory comes from
  manifest + lockfile crawling (Cargo/package.json/tsconfig today; k8s/docker/
  oci/helm/html/json/cargo lockfiles deferred per T8).
- **Parsers in dl is already mostly true.** `json` op dispatches on extension
  and handles JSON/YAML/TOML via tree-sitter (datapath.rs:17-23). Combined with
  `match` / `comment` / `sg` / `ast` / `cmd`, covers openapi/k8s/docker/helm/
  cargo/oci today with zero new Rust. The two extension seams are match arms:
  `ts_lang` engine.rs:3488 and `sg_lang` sg.rs:5.
- **scan 3-ary default WORK is cheap.** Arity dispatch at parse.rs:246 already
  keys on `terms.len()`. Adding a 3-ary `scan(glob, path, rev_out)` defaults
  repo=`.` and rev=`WORK`. Existing 4/5-ary programs unchanged.
- **Global "WORK = current ref" flag is a separate layer.** Per-call ergonomics
  (3-ary default) is authoring syntax. A global override of what WORK means
  (snapshot HEAD instead of live disk) is engine state, only load-bearing for
  LSP live-buffer support. Keep them split.

## Key Insights
- `true()` unlocked negation-only rules (carried over). The same minimal-add
  pattern applies here: the 3-ary scan and `allow_missing` flag are 2-line
  changes that unblock ergonomic and progressive-analysis stories.
- CodeQL classes and v5 derived rels are the same idea wearing different
  syntax. The relational storage is unchanged; the surface organizes it. v5
  ships without the sugar and accepts the verbose-but-uniform cost.
- The six source ops (`scan`/`match`/`ast`/`sg`/`json`/`cmd`) plus
  `comment` form the composition surface today. New formats are a `.dl` file;
  new grammars are a Cargo dep + match arm. New op variants are on the table
  when a real program needs a new query family (CSS/XPath is the candidate).
- The arity tax is the cost of refusing composite types. The buy-back is that
  types-as-rels compose by join, which is nesting at the query level. Modules
  (`use` + `def`) are how humans cohere the wide relations across files.
- "OpenAPI opname as cross-language call ref" is a special case of the general
  spine trick: any string that appears verbatim in two files is a join, no
  resolution logic. The spine already interns and locates. Cross-format
  linking is free once both formats reach the spine.
- Diet SCIP is mostly built: TYPE_RELS (type_entity, type_sig, type_edge,
  type_link) and MODULE_RELS (module_edge, module_import) cover the same
  shape SCIP carries, in a language-agnostic schema. The missing third is
  CALL_RELS, plus a unified symbol identity across the three graphs so a
  query like "every call on a type in this module" is a plain join.
- AI pattern observed in this session: prior-plan prohibitions get
  over-indexed as permanent walls. Plan 2026-06-01:16 ("if it cannot lower
  to existing BodyItems, it does not go in") was a reaction to v3/v4 runtime
  drift, not a decree that the language is done. Re-read prohibitions as
  defaults that yield to real program demand, not as frozen constraints.

## Open Questions
- The contract for new ops: "one variant per query-language family." Today
  four families (regex/S-expr/structural/pattern). CSS/XPath is the candidate
  fifth. Where does `rs:` symbol-literal scheme fit: as a new scheme arm in
  desc.rs, or a new BodyItem variant if it carries symbol-resolution semantics?
- Should the LSP hover rel be `info` (free-form) or a typed
  `hover(symbol, kind, text)`? Free-form matches `diag`'s shape and avoids a
  new built-in; typed risks proliferating special relations.
- Is the coordinator-folder pattern enough at scale (100+ repos), or does
  `--root` need to become a virtual root over multiple `RepoConfig.root`
  paths? Today `--root` is one directory.
- Symbol identity across the three graphs (modules, types, calls): is
  `file::kind::name` enough, or does it need a `(repo, rev, sym)` triple to
  survive cross-repo queries? Today repo/rev are separate cols on file/rev
  rels; symbols are local to a file.
