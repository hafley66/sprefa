  Delegated to a sonnet agent with a no-judgment-calls spec; verified independently.
- **Reconcile parity:** ported the resident salsa-crate oracle (`oracle::salsa::
  SalsaReconciler`) from the folded labkit (git `a7d5ad36^:v6/labs/labkit/src/reconcile.rs`)
  — same role as `dd::DdBfs` for cascade. `salsa = "0.28"` plain dep (mirroring dd).
- **The oracle found a real bug.** engine::reconcile's lazy one-hop `dirty()` frontier
  verifies nodes in HOP-DISTANCE-from-source order, which is NOT topological order on a
  DAG with diamonds. A node at hop 1 (reads an edited cell) that also reads a hop-2 dep is
  verified against that still-stale dep and never re-dirtied (one edit `rev`:
  `changed_at > verified_at` is false once both equal `rev`). Unit tests are all chains,
  which is why it hid (and why the family was tagged "parity unit only"). Diagnosis was
  deterministic: on n=32 the engine recomputed the right SET (missed=[]) but wrong VALUES
  for every node with a greater-hop dep.
- **The fix: `reconcile::propagate`** (engine.rs) — the labkit `SqlReconciler` shape: an
  ascending topological sweep over seeds + transitive readers. Ascending id is a valid
  topo order (rx_dep edges are parent->child, deps<node), so a node is recomputed only
  after its deps are current. `recompute(id, dep_digests)` closure returns the new digest
  from the caller's value + the deps' current digests (read from rx_memo; XOR fold is
  order-independent). Early cutoff: readers of an unmoved node are never enqueued. Returns
  the recompute count. tests/reconcile.rs drives the engine through it and is GREEN.

## Key Insights
- It is one digraph read three ways: ALIVE (cascade/Z-set), STALE (reconcile/salsa),
  REACHABLE (reach). DRed, early cutoff, SCC, namespaces are all consequences of that split.
- The reconcile oracle EARNED its keep: it caught a real correctness bug the unit tests
  (all chains) missed. Ground truth must exercise diamonds, not just chains.
- Hop-distance-from-source ≠ topological order whenever a node has deps at different hop
  distances. A lazy one-hop frontier is correct for chains and wrong for general DAGs.
  The fix is a topo (ascending) sweep; labkit's SqlReconciler was already the proven shape.
- The reconcile plane is granularity-agnostic already (key=rel·1e9+row, dirty/verify run on
  bare ids). Per-rel vs per-tuple is a seeding-contract change, not a schema/query change.
- Namespace mechanism is a NAME PREFIX, forced: SQLite TEMP working tables live in temp.
  and cannot be qualified to an ATTACH'd schema, so prefix is the only ns covering the
  working set. Not a fork; the graph theory is unchanged, only table names are prefixed.
- Build-vs-buy held: oracles use real libraries (differential-dataflow, salsa) or vendored
  pure-Rust (reach condensation), never bespoke ground truth.
