## Key Insights
- **THE ZERO-COLUMN DIAGNOSIS WAS WRONG IN THE PLAN DOC AND THE USER CAUGHT
  IT.** Proved by 3 probes. `option(text)` keeps its columns on the parent
  (`combo_pair("__id" PK, use_before INT, use_after INT, UNIQUE(...))`).
  `option(<rel>)` moves the column out to `combo_pair__use_before(combo_pair_id,
  combo_move_id) PRIMARY KEY(combo_pair_id)` -- KEYED ON THE PARENT'S __id, so
  parent association by id ALREADY WORKS. What breaks is lower.pl:2102 emitting
  `UNIQUE(<cols>)` unconditionally; with every column moved out that list is
  EMPTY and `UNIQUE()` means every row duplicates every other. A degenerate
  constraint, NOT a missing identity concept. Fix = emit
  `CREATE TABLE x ("__id" INTEGER PRIMARY KEY)` with no UNIQUE.
- **The 3VL ban cost 4 lines.** SQLite's IS/IS NOT is null-safe 2-valued AND
  uses the index identically (`EXPLAIN ... WHERE a IS 5` -> SEARCH USING INDEX,
  same as `=`). registry.pl:248-249 were the only two rows. Sweep held 283/0.
- **ONE DCG -> THREE ARTIFACTS IS ONLY TWO-THIRDS TRUE.** parser = the DCG run
  forward. tree-sitter grammar = emit_grammar.pl READING THE DCG AS TERMS.
  print_dl.pl (724 lines) is INDEPENDENT CODE held to the DCG by `just
  roundtrip`. ARCH.pl:815 records the one time they drifted (18 reds, one defect).
- **The tree-sitter emitter is MONOMORPHIZATION.** parse_dl_dcg.pl:447-450
  `sep(P, [X|Xs]) --> call(P, X), ...` takes a PARSER AS AN ARGUMENT.
  grammar.js has no parameterized rules, so the emitter collects every call
  site's concrete P and emits one specialized rule per pair. emitted-grammar.js
  :5 lists all 14, :6 states `unbound: "[args-A,sep-A]"`, :7 the 29 generated.
  The `unbound` line IS the 67-char `column` row of the 445 floor: the one slot
  monomorphization cannot reach, printed by the emitter every run.
- **Pretty printer from the DCG: not as written.** 69 cuts, 8 code_type guards,
  19 mark/peek position reads. All block reverse mode. The real path is a
  FOURTH consumer of the same term structure. Literature first per build-vs-buy:
  invertible syntax descriptions (Rendel & Ostermann 2010).
- **The LSP door already exists and needs zero new LSP code.**
  `hover_note(path,line,col,end_line,end_col,md)` at src/engine/decls.rs:294,
  read by lens.rs:294 hover_notes_at/3, merged at lsp.rs:857-863, and
  hover_provider already advertised at lsp.rs:73. Precedent = lsp-diags.sh: v6
  names tables by the bare rel name (lower.pl:156) so a .dl6 rel named

  raw HTML is stripped; markdown tables + fenced blocks are the path.
