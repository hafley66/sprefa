## Analysis

Graph-sitter is a substantial, **substantive** code manipulation framework, not a thin wrapper. At 56k LOC, it wraps tree-sitter but adds:

1. **Type-safe property graph** (PyDiGraph from rustworkx): nodes are Importable variants (Functions, Classes, Symbols, Imports), edges typed via enums.Edge. Storage is in-memory; no persistent store abstraction, though neo4j is listed as a dependency (pyproject.toml:65).

2. **Language extensibility via node class factories**: Rather than exposing tree-sitter queries, graph-sitter defines language-specific symbol and expression mappings. PyNodeClasses (python/), TSNodeClasses (typescript/) encode grammar-specific node types into class hierarchies. Parser.from_node_classes() bridges this (core/parser.py:60).

3. **Call extraction is localized and scope-aware**: FunctionCall (function_call.py) parses tree-sitter call_expression nodes, extracts arguments via field_name "arguments", and resolves parent function scope via find_first_ancestor(). No global call-graph indexing; queries happen via method traversal (function.usages property, etc.).

4. **Source order preservation guaranteed by Cython sort**: compiled/sort.pyx:25 sorts Editables by ts_node.start_byte. All traversal methods (children, statements, symbols) return sorted lists, ensuring deterministic order for refactoring safety.

5. **Cross-file resolution via Import objects**: SourceFile maintains filepath_idx; Import objects carry qualified names. ResolutionStack (codebase/resolution_stack.py) handles per-scope lookups. No AST-level qualified name tracking; relies on Python/TS import semantics.

6. **Auto-commit transaction wrapper**: core/autocommit/*.pyx (Cython-compiled) wraps property writes to sync graph state. Prevents inconsistency between AST mutations and graph edges.

7. **No explicit query DSL**: No tree-sitter .scm files in codebase; all extraction is imperative Python code. Symbol/Expression classes define child_by_field_name() accessors for tree-sitter field navigation.

8. **Incremental sync via DiffLite**: transaction_manager tracks pending_syncs (CodebaseContext:111). Allows graph updates without full re-parse on file changes.

9. **Await/promise chain awareness (TypeScript-specific)**: FunctionCall.is_awaited traces async context, useful for understanding control flow in Promise-heavy TS code (function_call.py:132-150, typescript/detached_symbols/promise_chain.py).

10. **LLM-driven code generation**: codebase_ai.py integrates OpenAI API to generate transformations based on Symbol/Function context. System prompt includes code snippet + user context for semantic guidance.
