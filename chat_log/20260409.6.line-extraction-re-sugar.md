## Key Insights
- Segment mode treats all non-$ text as literal. `\s+` and `\t` are literal backslash sequences, not regex metacharacters. Patterns needing regex escapes must use re: prefix.
- re: sugar rewrites $NAME to (?P<NAME>[^X\s]+) where X is the first char of the next literal segment. At end of pattern or before whitespace, uses \S+ (word boundary).
- Sugar patterns use search mode (full_match: false) since captures provide their own boundaries. Raw (?P<>) patterns keep full_match: true for exact-line matching.
- Extensionless files (Dockerfile, Makefile) were invisible to the scan pipeline: index dispatch returned None for files with no extension, and the Extractor trait had no opt-in mechanism.
- The from_ruleset_with_dir filter excluded line-only rules because they have no structural steps and no AST selector. Added r.value.is_some() to the filter.

## Open Questions
- Segment mode word-boundary ($TAG stopping at whitespace) is still unimplemented. Currently $TAG captures greedily to end-of-line in segment mode. re: sugar handles this case instead.
