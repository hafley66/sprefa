## Analysis

### Call Extraction Mechanism

Reference extraction is **lexical and heuristic-based**, not semantic or scope-aware. Entry point: `extract_references_from_content(content: &str, own_name: &str) → Vec<&str>` (graph.rs:848).

#### Processing pipeline (graph.rs:848-888):

1. **Comment/String stripping** (graph.rs:768-843): Byte-level state machine scans for Python triple-quotes (`"""`, `'''`), double-quotes, single-quotes, Python `#` comments, C-style `//` and `/* */` comments. Matched sequences replaced with spaces to preserve length/positions.

2. **Token extraction**: Content split on non-alphanumeric + non-underscore boundary to extract identifiers. Split done twice:
   - First on stripped version → `stripped_words: HashSet<&str>` (graph.rs:852-855)
   - Second on original content → candidate refs (graph.rs:860)

3. **Filtering** (graph.rs:861-884):
   - Skip self-reference (own_name)
   - Skip keywords (60+ hardcoded: if, class, fn, use, etc.; graph.rs:956-1000)
   - Skip very short identifiers (< 2 chars)
   - Skip lowercase < 3 chars (i, x, a, ok, id)
   - Skip 60+ common local names (result, data, config, value, item, error, etc.; graph.rs:890-905)
   - Dedup via `seen: HashSet<&str>` (graph.rs:858, 882)

4. **Cross-reference**: Only accept words found in stripped version (graph.rs:879) — filters out docstring/comment noise.

#### RefType Inference (graph.rs:914-954):

Three-way classification via `infer_ref_type(content: &str, ref_name: &str) → RefType`:

- **Calls** (RefType::Calls): If `ref_name` is followed by `(` with word boundary before (graph.rs:920-932). Byte-level matching avoids string allocation; checks `bytes[pos+len] == b'('` and verifies boundary by checking `bytes[pos-1]` is not alphanumeric/underscore.

- **Imports** (RefType::Imports): If ref_name appears in a line starting with "import ", "use ", "from ", or "require(" (graph.rs:942-950). Line-level scan; no structural AST.

- **TypeRef** (default; graph.rs:953): Catch-all for type references, field access, extends, implements, etc.

**Limitation**: Pattern matching is syntactic and multi-language. No language-specific validation (e.g., Python `def foo():` vs Rust `fn foo() {}`). Regex-free; relies on byte-level search.

### Graph Construction

Two-pass approach (graph.rs:91-248) inspired by arXiv:2601.08773 (Reliable Graph-RAG):

#### Pass 1: Entity Extraction (graph.rs:102-135)
- Parallel (rayon) per-file parsing via `ParserRegistry` plugin system
- Each plugin calls `extract_entities(content, file_path) → Vec<SemanticEntity>`
- Tree-sitter visitor (entity_extractor.rs:6-22) walks AST, extracts functions/classes/methods matching language-specific `entity_node_types` config
- Populates symbol_table: `HashMap<name, Vec<entity_id>>` (allows overloads/duplicates)
- Builds entity_map: `HashMap<entity_id, EntityInfo>`

#### Pass 2: Reference Resolution (graph.rs:157-219)
- **Parallel** extraction: `extract_references_from_content()` on each entity's content (graph.rs:162)
- **Import table** (graph.rs:657-726): Pre-built mapping `(file_path, imported_name) → entity_id`. Parses Python/JS style `from X import Y`, multi-line imports (parenthesized), and resolves Y to target entity.
- **Symbol table lookup**: For each ref_name in entity:
  1. Check import table first (cross-file explicit imports) — graph.rs:173-186
  2. Fall back to symbol_table, filter to same-file matches only (graph.rs:188-198)
  3. If no match in same file, try any entity with that name (graph.rs:593)
- **Edge deduplication**: Skip parent-child (class → method) edges via `parent_child_pairs` set (graph.rs:138-143, 166-167, 203-207)

#### Result Indexing (graph.rs:221-247):
- Edges stored as `Vec<EntityRef>` (no sort, source order preserved if insertion order matters, but VecDeque collection pattern suggests unordered)
- Bidirectional indexes: `dependents: HashMap<entity_id, Vec<from_ids>>`, `dependencies: HashMap<entity_id, Vec<to_ids>>`

### Cross-File Resolution

Import table (graph.rs:653-726) extracts import statements line-by-line:
- Regex-free; splits on keywords "from", "import", "require"
- Resolves `(file_path, imported_name)` pairs to entity_id in symbol_table
- Multi-line imports (parenthesized): joined into single logical line via paren tracking (graph.rs:675-715)

**Key scope rule** (graph.rs:189-190): Without explicit import, cross-file references resolve only to same-file entities. This prevents spurious edges from name collisions.

### Entity Extraction (Language-Specific)

Plugin architecture (plugin.rs:2-9) defines trait SemanticParserPlugin:
- `extract_entities(content: &str, file_path: &str) → Vec<SemanticEntity>`
- Optional: `compute_similarity(a, b) → f64` for diff matching (default: name+type+file heuristic)

Tree-sitter visitor (entity_extractor.rs:25-206+):
- **entity_node_types**: Function, class, interface, method, etc. (language-specific)
- **container_node_types**: Blocks containing nested entities (class_body, statement_block, etc.)
- **scope_boundary_types**: Suppress locals (arrow_function in JS/TS) to avoid false nested entities
- **Suppressed nested entities**: Exclude var declarations inside functions (JS_TS_SUPPRESSED_NESTED array, entity_extractor.rs:113-165)
- **Call entity identifiers**: For Elixir (def, defmodule); extracted from call node structure, not reference counting

Example (languages.rs:173-193): TypeScript extracts function_declaration, class_declaration, interface_declaration, type_alias_declaration, enum_declaration, method_definition, public_field_definition. Methods nested in classes; locals inside functions suppressed.

**Structural hashing** (entity_extractor.rs:41, 95, 164-170): `structural_hash(node, source) → String` strips comments/whitespace to enable content-addressed diff. Two entities with same structural_hash are logically identical (unison-inspired).

### Incremental Updates

`update_from_changes(changed_files: Vec<FileChange>, root, registry)` (graph.rs:390-496):
1. For each file: match on status (Deleted/Renamed/Added/Modified)
2. Remove old entities via `remove_entities_for_file()` (graph.rs:519-560) — prunes edges
3. Extract new entities (graph.rs:415-434)
4. Rebuild symbol table (graph.rs:457)
5. Re-resolve references for new entities (graph.rs:460-462)
6. (Optional) re-check unchanged files that referenced deleted entities (graph.rs:471-495, currently stubbed)

### Impact Analysis

Breadth-first transitive dependents (graph.rs:274-315):
- `impact_analysis(entity_id) → Vec<&EntityInfo>` caps at 10k nodes
- `impact_count(entity_id, max_count) → usize` for fast counting
- `test_impact(entity_id, all_entities) → Vec<&EntityInfo>` filters to test entities (name/path heuristics: graph.rs:617-651)

No semantic analysis; purely graph-traversal (BFS queue). Test detection: name patterns (test_, Test suffix), path patterns (/test/, /tests/, _test., .test., etc.), content markers (#[test], @Test, describe(), etc.).

**6 tools** (mcp/tools.rs:4-54):
1. **entities** (EntitiesParams): List entities in file
2. **diff** (DiffParams): Semantic diff between refs
3. **blame** (BlameParams): Who last changed each entity

### Notable Design Decisions

1. **Heuristic over semantic**: Reference extraction tokenizes by splitting on non-alphanumeric, filtering known keywords/locals. No scope resolution or type information; works across languages uniformly.

2. **Symbol table namespace**: Single global symbol table per build; entities with same name stored as Vec<id>. Same-file resolution prioritized; cross-file requires explicit imports.

3. **Common local name filtering**: 60+ hardcoded names (result, data, config, value, etc.) excluded from graph to reduce noise. Tradeoff: misses legitimate entity refs with colliding names.

4. **Structural hashing**: AST-based hash (semantic-preserving) enables diff granularity immune to formatting. Stored in schema for content-addressed retrieval.

5. **Fallback chunker**: Unsupported file types split into 20-line chunks (fallback.rs:7-49). Graceful degradation.

6. **Import table pre-pass**: Multi-line import parsing before entity resolution avoids spurious cross-file edges. Line-level parsing (not AST-based) means fragile on complex syntax (e.g., conditional imports, dynamic requires).

### Gotchas & Limitations

- **No scope resolution**: Refs extracted from entity content are string-matched against global symbol table. Local vars with same names as entities create false edges.
- **No language-specific call detection**: Calls detected by `identifier(` pattern regardless of language (e.g., Python `foo()` vs Rust `foo()`). No AST-based call expression visiting (e.g., CallExpr in tree-sitter terms).
- **No ordinal/position preserved in edges**: Graph traversal order is insertion order in Vec; no source-order field. Affects determinism if graph rebuilt differently.
- **Import table parsing is syntactic, not semantic**: Multi-line imports rely on paren counting; breaks on escaped quotes, nested parens, etc.
- **WASM status unclear**: Rust + tree-sitter are WASM-capable, but no explicit wasm feature, no wasm-pack setup observed. Likely compilable but untested.
- **No explicit locals.scm**: Scope suppression is hard-coded per language (suppressed_nested_entities list). Adding new scoped patterns requires code change, not declarative query.
- **Parallel extraction loses source order**: rayon par_iter collection is unordered by default. Graph edges not guaranteed to reflect source file order.

### Complexity & Performance

- **Entity extraction**: O(files * LOC) tree-sitter parsing (parallelized)
- **Reference extraction**: O(entities * content_len * symbol_table_size) string matching (parallelized)
- **Graph indexing**: O(edges) for building dependents/dependencies maps
- **Impact analysis**: O(transitive_deps) BFS, capped at 10k
- **Incremental**: O(changed_files * avg_file_size) re-extraction + O(symbol_table_size) rebuild

LOC: ~10.6k sem-core, ~15.4k total. Tight codebase; entity_extractor.rs dominates (tree-sitter visitor patterns for 22 languages).

### Interop

- **MCP server**: stdio transport; 6 tools (entities, diff, blame, impact, log, context)
- **JSON I/O**: All results serializable via serde; stdin mode accepts FileChange[] for non-git workflows
- **Incremental cache**: SQLite backend; mtime validation; WAL for concurrency
- **CLI**: git-aware (git2 crate); no-git modes (file comparison, stdin input)

### Extensibility

**Language addition**: Define LanguageConfig in languages.rs (entity_node_types, container_node_types, scope_boundary_types, suppressed_nested_entities) + register in plugin list. Entity extraction via tree-sitter visitor; reference extraction generic (same heuristic for all languages).

**Custom extractors**: Implement SemanticParserPlugin trait (id, extensions, extract_entities, optional compute_similarity). Fallback plugin (20-line chunker) kicks in for unsupported extensions.
