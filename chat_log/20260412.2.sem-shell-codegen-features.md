## Key Insights
- sem schema: 3 tables (files/entities/edges), zero indexes beyond PK, zero views, zero UDFs. Full nuke invalidation. Everything loads to memory, filtering in Rust.
- sem entity ID format: "{file_path}::{entity_type}::{name}"
- ${rule.VAR} dot syntax for cross-rule shell refs chosen because bash disallows dots in var names
- $$$ in sh context means "collect all values" (batch), $ means "iterate per row" — mirrors existing capture semantics ($NAME=one, $$$NAME=many)
- Pending cuts are not errors — they're a side channel for gated shell execution with LSP hover approval UX
- Three-phase scan: extract(safe) → shell(gated) → checks+codegen(dependent) — shell never blocks extraction
- 3 pre-existing LSP context test failures on this branch (unrelated, being fixed elsewhere)
- Partial parsing plan is solid; needs warnings side channel alongside errors in PartialProgram
