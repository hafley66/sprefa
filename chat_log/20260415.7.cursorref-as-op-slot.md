## CursorRef-as-op-slot (the landing target)

Grammar today:
```
<op><dots?>( <args?> ) [ <index_args?> ]? { <brace body?>? }?
```

Add `&` as a new op-head sigil. `&.$C` is a full pipe-step, produces
a `CursorRefOp` invocation in the pipeline AST:
```
json({code: $C}) > &.$C > line(re: /TODO/)
```

Why "op slot" is plug-and-play:
- `CursorRefOp` implements the normal `Op` trait — runner special-cases
  nothing. Grammar extension is one new sigil case in the pipe-step
  discriminator, not a structural rewrite.
- Ops are zero-change. No `redirectable_inputs()`, no opt-in. They
  always read from `cursor.content` + `cursor.byte_range` + `slots`;
  the CursorRefOp rewrites those upstream of them.
- Composable: `json > &.$A > md > &.$B > ast-grep` reads left-to-right.
- Reader sees redirection in the pipeline layout, not hidden in args.

CursorRefOp::pipe behavior per input cursor:
- Resolve `.$X` against `cursor.captures[X]` (self-scope, fast path).
- Or resolve `.$ROOT.fs[0].json[1].$X` against ResultStore (global).
- Two redirect modes by capture shape:
  - **byte-span-backed capture** (walker-emitted, points into
    `content`): narrow `byte_range = Some(capture.span)`. Preserve
    slots + content. Parse trees stay valid.
  - **synthesized string capture** (e.g. `$FS` filepath, computed):
    materialize `content = Arc::from(capture.value.as_bytes())`,
    `byte_range = None`. Clear slots (parse tree no longer applies
    to new bytes).
- Rule: slots survive iff content unchanged.

## Scan-pointer / CursorRef separation (taxonomy correction)

Scan pointer is NOT a generic predicate/assertion. It is a
traversal-extension primitive for bridging `(repo × rev)` frontiers
across lockfile-pinned deps. Example: main repo's package.json says
"dep X at repo B tag v2.1.4" → scan crawler extends to
`(B, v2.1.4, *)` as a new scannable frontier. Whole purpose is
cross-repo dep-graph crawling from fixed refs.

CursorRef is strictly local, intra-rule, acts on ONE cursor's content
inside ONE (repo, rev, file).

Two graphs, distinct consumers, both trigger reactive re-eval:
```
CursorRefEdge   (pipeline result graph)   runner consumes
ScanPointer     (cross-ref crawl graph)   scan crawler consumes
```

Bash mental model (load-in frame for readers):
```
bash  sprf
----  ----
|     >     forward pipe
$()   &.    cursor substitution
[[ ]] (n/a — scan pointer is a graph-crawl hook, no bash analog)
```

## Key Insights

- **Dual-tree model:** pipeline tree (SprfPath × captures) and content
  tree (AnyDataNode / MdTree / AstGrepTree). Captures are pipeline-
  tree leaves that point into content-tree nodes.
- **Span recursion rule:** `span(node) = anchor when walker-emitted
  with anchor; else union of iter-children.*; else union of
  captures.*`. True-anchor case is the walker touch.
- **CursorRef is the bash `$()` of sprf.** `>` is forward pipe (bash
  `|`). `&.$X` substitutes cursor state. Both are pipe primitives.
  Scan pointer is a separate dimension — graph-crawl hook with no
  bash analog.
- **Grammar plug-and-play:** `&` as pipe-head sigil + CursorRefOp
  implementing Op trait means zero runner changes, zero op opt-in,
  no special execution path.
- **Slots survive iff content unchanged.** CursorRef byte-range
  narrow keeps slots; materialize-new-content drops them. One rule,
  two behaviors.
- **Scan pointers are NOT assertions.** They're cross-repo traversal
  hooks for bridging lockfile-pinned dep graphs. Don't merge with
  CursorRef semantics even though both are addressable-by-path.
