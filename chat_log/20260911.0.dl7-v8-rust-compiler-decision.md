## Problem/Context
V7 models compiler data as Prolog lists, then repeatedly converts selected relations into dynamic predicates with `assertz/1,2` so SWI JITI can index reads. The compiler also tears these stores down with `retractall/1` or clause-reference erasure. A measured 4-file profile recorded 32,033 `assertz/1` calls and 13,643 `assertz/2` calls, 45,676 inserted clauses total.

The performance work repeatedly encounters the same storage mismatch:
- lists act as immutable relation batches
- `memberchk`, `include`, and `findall(member(...))` scan those batches
- dynamic fact arenas avoid read scans but charge construction, mutation, indexing, and cleanup
- inference counts can rise while wall time falls because SWI charges C-level list scans and builtins differently from Prolog predicate work
- compiler data gets rebuilt at lowering, checker, compiler-round, and evaluator-stratum boundaries

The user no longer wants continued effort spent tuning SWI storage mechanics or learning Prolog through AI-authored code. Rust is already familiar and makes storage, ownership, indexing, allocation, and profiling explicit.

## Compiler Contract To Preserve
```text
DL7 source
  -> Lisp reader and syntax graph
  -> macrotime fixpoint
  -> lowered relational program
  -> lexical, type, mode, key, and stratification checks
  -> comptime fixpoint
  -> compiler facts
  -> checked runtime IR
  -> Rust runtime / sqlite_ivm / emitter libraries
```

Language intent:
- Lisp-shaped foundation
- macros are an application of the DL7 kernel
- Datalog-style authored rules and checkability
- macrotime and comptime are separate fixpoint phases
- comptime facts produce a runtime program
- runtime implementation may be Rust and sqlite_ivm
- DL6 architecture and sprefa-engine-rs supply comparative application/runtime intent
- V7 fixtures and canonical output become the behavioral oracle for a possible V8

## Proposed V8 Rust Shape
```rust
fn read(source: &str) -> ReadResult;
fn expand(graph: &SyntaxGraph) -> MacrotimeResult;
fn lower(expanded: &ExpandedGraph) -> LoweredProgram;
fn check(program: &LoweredProgram) -> CheckedProgram;
fn evaluate_comptime(program: &CheckedProgram) -> CompilerFacts;
fn reify(facts: &CompilerFacts) -> RuntimeIr;
```

```rust
struct CompilerGraph {
    nodes: SlotMap<NodeId, Node>,
    edges: Vec<Edge>,
    edge_by_owner_label: HashMap<(NodeId, Symbol), EdgeId>,
    edge_by_owner_index: HashMap<(NodeId, u32), EdgeId>,
    parent_by_target: HashMap<NodeId, NodeId>,
    relations: IndexMap<RelationId, Relation>,
    rules_by_head: HashMap<RelationId, Vec<RuleId>>,
}
```

Storage libraries/types remain a design decision. The acceptance criterion is explicit indexed storage with measured construction/query costs and canonical output parity, rather than any specific crate choice.

## Solution/Approach
Freeze the V7 Prolog compiler as a behavioral reference once the current dirty experiment is resolved. Build V8 phase by phase in Rust behind an oracle harness:
1. Compile each fixture with V7 and V8.
2. Canonicalize path-sensitive identities.
3. Compare rows, diagnostics, rule order, edge indices, origins, phase products, and emitted runtime IR exactly.
4. Port one phase at a time, retaining the V7 implementation until its fixture surface matches.
5. Add scale differentials for each Rust phase from the first implementation, including allocations, bytes, indexed lookups, candidates visited, rows inserted, and fixpoint deltas.
