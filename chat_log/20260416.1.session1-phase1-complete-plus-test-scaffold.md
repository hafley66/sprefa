## Key Insights
- **Test scaffold principle (now in root CLAUDE.md)**: adding a field to `OpCtx` or `RuntimeConfig` means updating `for_test` / `test_default`, never patching test-sites. If compiler points at a test file when you add a field, the helper is where the fix goes.
- **Struct-update with ctor** is the idiomatic Rust scaling pattern for test fixtures when `Default` can't apply (trait objects, channels, non-Default fields). `Foo { field: override, ..Foo::test_default() }` moves the returned value in and replaces the specified fields. Works across crate boundaries.
- **Why not `tests/common/mod.rs`**: the `impl` approach is DRYer because `src/` unit tests that build OpCtx (e.g. `_5_op.rs:1021` `build_ctx`, `ops/_3_fs.rs`, `analysis.rs`) benefit from the same helper. Common mod would duplicate.
- **Agent delegation failure mode (carry-over from mid-session)**: wide surfaces with bulk-edit sweeps are brittle under interruption; next delegation should be narrow and disjoint; integration edits stay with coordinator.
- **cargo fix --tests --allow-dirty**: cleans unused imports automatically after a literal collapse. Ran once, cleaned 13 files.
- **No perl for multi-line Rust refactors** (user standing rule after this session). Edit per file is faster than debugging non-greedy regex against closures.
