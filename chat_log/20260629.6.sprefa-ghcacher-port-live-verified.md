## Solution/Approach
- effect_log builtin: thin query-rel view over pending_effect (the job table IS
  the call log); `? effect_log(id,kind,head,state,args,req_tx)`. Projected at tick
  start. Parity surface vs ghcacher call_log.
- gh-cache.dl: @async conditional GET, request args carry prior etag (@next
  carry), term-form jsonp normalizes the 200 body, @next-accumulated change_log.
  Cache = content-addressed pending_effect digest + etag carry; 304 carries old
  etag, lands no entity, change_log untouched.
- TEMPORAL BUG found+fixed: a carried @next rel that MOVES now rebuilds derived
  rules reading it. load_carry returns content-digest-diff (new rel_content_digest:
  per-row blake3 XOR-fold over declared cols; carry rows leave __src blank so the
  old __src-based rel_digest can't see them), tick ORs into `changed`. Without it
  a derived rule over a carried-in rel froze at its first value. Existing carry
  tests missed it (their carried rel feeds a STABLE derived rel).
- MATCHER bug found+fixed: datapath.rs walk_object multi-entry branch was
  leaf-only, so `{ number:$n, user:{ login:$a } }` (flat + nested descent) matched
  nothing. Replaced with frontier fold (continuation-passing): each entry walks
  its sub-pattern via walk_steps, threading binding-sets conjunctively. Now a
  /pulls JSON array normalizes into one pull_request row/element via one rule.
- LIVE RUN against real GitHub found the etag shell-quote gap: `W/"..."` in
  `-H "If-None-Match: {prev}"` broke shell quoting -> 200 not 304, cache silently
  dead. FIX: ShellEffectExec exports each hole as an ENV VAR too; `$prev` expands
  opaque values safely; `{k}` raw-substitution stays for clean values.

## Key Insights
- One faultline, many faces: dl is a deductive, set-valued, TIMELESS fixpoint;
  ghcacher's behaviors (recurring polls, latest-wins cells, event transitions) are
  all TEMPORAL/mutable-state. @next/@async/every are the bridge (reify time as
  data); each gap is that move applied again (carry + diff/reduce).
- Every rel IS a SQLite table — declaring a rel + one json rule IS the
  normalization. Adding entity types is .dl authoring, NOT engine work.
- Running LIVE is what finds real gaps. Mocks can't surface the etag-quote break.
- RxJS maps cleanly: switchMap=latest-wins/cancel, mergeMap=concurrent drain,
  shareReplay=pending_effect digest cache; A/B/C/D = interval/switchMap/expand/map.
- effect_log doubles as debug view AND parity surface.
