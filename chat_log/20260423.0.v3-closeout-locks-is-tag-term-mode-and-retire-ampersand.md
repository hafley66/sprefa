## Solution/Approach

### Thread 1 — dropped the Tri verification mechanic
User flagged scan-pointer Tri (Claimed/Verified) was "not a thing anymore, was from this being bespoke; we have bidir with unbound now". Three-mechanic primitive stands (park on missing term, bidir tag re-entry, parametric rule lazy unbound).

### Thread 2 — `is(:name, $A, $B, ...)` generic relation
Proposal: one relation primitive, N-ary, atom name. All bound = side-effect write. Any unbound = LSP flags as query + runtime fans out. Retires is_repo/is_rev/is_fs/is_repo_norm/is_rev_norm stdlib set — each becomes `is(:repo, $R)` etc.

### Thread 3 — `&` grammar exploration then death
Explored `&` as op with dot-chain body (parallel to re/glob/ast sub-grammars). Then user flipped to `&rule.$X` (adjacent, "and rule's $X"). Then flipped again to `_` Prolog wildcard + rule-call-with-unbound-args = xref query. `&` dies entirely. Dots leave the language.

### Thread 4 — rule = label/yield, tag = Subject
User split roles: rule becomes label/yield point (SprfPath anchor), tag is N-ary Subject-backed channel. Both share bound/unbound dispatch with `is` but differ in backing store (tag = BehaviorSubject last-value, is = append-log). Lock (B) for tag: read binds `$V?` on same cursor, no fan.

### Thread 5 — syntactic term-mode via `?` suffix
Locked: `$X` = bound-required, `$X?` = unbound-introducer (first occurrence), `_` = wildcard-discard. Repeat-the-name for referencing already-introduced terms (no `&`, no `$it`). BindingGraph becomes a lower-time static check, no runtime silent mode inference.

### Thread 6 — retire `&` + dots
`&.fs`/`&.repo`/`&.rev` replaced by reserved synthesized terms `$FS` / `$REPO` / `$REV` on every cursor. §9 host dotted access retires. `&{...}` dies or respins as separate brace-DSL op.

### Thread 7 — existing codebase term lowering analysis
Surveyed grammar.js / shared/tokens.js / ast.rs / value.rs / registry.rs / capture_write.rs / _0_cursor.rs. Current state: `term_ref = token(seq('$', /[A-Za-z_][A-Za-z0-9_]*/))`, no `?` suffix, no mode on `Value::Term(Arc<str>)` or `Seg::Term { name, unbound_re }`. Runtime probes `cursor.capture(name)` to decide read vs write. Diff surface sized at ~500 LoC pipeline + ~100 LoC parse + grammar regen; biggest addition is `binding_graph.rs`.

### Thread 8 — closeout framing
User wants v3 done. Current runtime: sprefa-run.rs drives fs/re/glob/comment/print/repo/rev/read/capture_write via RtCtx against disk. What's unbuilt: is/tag primitives, parametric rules with params, wait-set runtime, sh/sh_mut, BindingGraph, kitchen-sink runtime test. Filed sprefa-eet as meta-epic tying the closeout to a single shipping state.

## Key Insights
- Three-mechanic wait-set (down from four): park-on-missing-term, bidir tag re-entry, parametric rule lazy unbound. Scan-pointer Tri retired; bidir with unbound + wait-set subsumes it.
- `_` Prolog wildcard + rule-call-with-unbound-args = xref query. One mechanic replaces `&`-path, §9 dotted access, and the is_repo/is_rev family all at once.
- `is` and `tag` share bound/unbound dispatch but differ in backing: is = append-log (row history), tag = BehaviorSubject (last value). Keep as two primitives; collapsing into one hides the backing semantic.
- rule = label/yield (SprfPath anchor); not a function. Reframe means parametric rules with params become call-sites that thread args into the named yield point.
- Term-as-operator frame: `$TERM?` is sugar for `${TERM?}`, `${...}` carveout is the canonical production. Grammar stays lean by treating `$` as a shortcut lex rule, not a fundamental.
- Decoherence audit caught two stale sources pulling on the session: old scan-pointer-runtime memory (deleted) and sprefa-126 card's four-mechanic description (needs update).
- Mass-appeal is separable from prefix-vs-infix. sprefa's surface is already mainstream-adjacent. The actual risks are semantic legibility (invisible mode dispatch, rule-as-label violating function expectation, hidden wait-set parking) — mitigated by syntactic term modes and LSP decorations, not syntax overhaul.
- Prior art that matches sprefa's semantic combo: Oz / Mozart + dataflow variables (Van Roy & Haridi, *Concepts, Techniques, and Models of Computer Programming*, MIT Press 2004). Dataflow variables are the wait-set primitive by another name; chapters 4-5 show how streams / channels / futures / pub-sub all reduce to one primitive. Textbook for the "prolog + time-ordered pipe + reactive park" space.
- Current runtime reality: sprefa-run.rs drives a real RtCtx against disk with the stdlib; not just LSP-hover rendering. What's missing is the relational + reactive + sh surface the spec pledges.
- `&{...}` (address carveout) might stay as a separate brace-DSL op even after `&` sigil dies; decide at retirement-card time.
- BindingGraph was always going to be written; this session pushes it earlier (lower time, static check) instead of keeping the current runtime-probe-then-dispatch pattern.
