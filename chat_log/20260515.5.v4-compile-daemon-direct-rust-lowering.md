## User Intent

Compile a `.sprf` file by generating a temporary Rust crate, lowering the SPRF program into the concrete Rust objects the interpreter would have created, compiling that crate, and executing the generated daemon.

The generated daemon should avoid registry dispatch and avoid parsing `.sprf` at daemon startup for supported ops.

## Implemented Shape

```rust

    pub sprf_path: PathBuf,
    pub root: PathBuf,
    pub bind: String,

pub fn emit_rust_daemon(spec: &RustDaemonSpec) -> Result<RustDaemonArtifact, RustEmitError>;
```

Also exposed:

```rust
pub fn emit_rust_daemon_source(src: &str, spec: &RustDaemonSpec) -> Result<String, RustEmitError>;
```

for snapshot-style tests without running Cargo.

## CLI

Added to `sprefa-run`:

```bash
sprefa-run <file.sprf> --compile-daemon --bind 127.0.0.1:8787
```

Flow:

1. Parent `sprefa-run` reads source.
2. Parent runs `host_parse`.
3. Parent runs parse and binding diagnostics before Rust emission.
4. Parent emits a generated crate under `v4/target/sprefa-dyn/<hash>/`.
5. Parent runs `cargo build --release --offline`.
6. Parent execs the generated daemon binary.

Generated files:

```text
v4/target/sprefa-dyn/<hash>/Cargo.toml
v4/target/sprefa-dyn/<hash>/src/main.rs
v4/target/sprefa-dyn/<hash>/target/release/sprefa-script-daemon
```

## Direct Rust Lowering Coverage

The sidecar emitter currently lowers these paths into concrete Rust constructors:

- `str`, constant bodies
- bare `CAPS` and `CAPS?`
- `term`
- `term_bind`
- rule declaration
- declared rule writes using `FactWrite::new` or `FactWrite::projected`
- declared rule queries using `SqlQueryComponent::with_referenced_tables`
- `split`
- `fs`
- `glob`
- `read`
- `re`
- `json`

Unsupported ops emit a generated Rust compile error:

```rust
compile_error!("op `repo` has no direct Rust emitter yet");
```

## Notes

The first implementation keeps the direct Rust emitter centralized in `compile/rust_daemon.rs`.

A follow-up shape discussed during the branch was per-op ownership via an emitter trait, so each op can own its direct Rust constructor emission next to its normal lowerer. A possible shape:

```rust
pub trait RustOpEmitter {
    fn emit_rust(
        &self,
        call: &OpCall,
        slots: &ResolvedSlots,
        ctx: &mut RustEmitCtx,
    ) -> Result<RustStep, RustEmitError>;
}
```

That would let `rust_daemon.rs` remain mostly crate shell, parse once, sequencing, hash paths, file writes, Cargo build, and exec.
