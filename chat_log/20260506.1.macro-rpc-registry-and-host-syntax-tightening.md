# 20260506.1 · macro RPC registry + host-syntax tightening

Continuation from `20260506.0.v4-editor-experience-and-language-finish.md`.
That session ended with the app_host integration plan amended into the
chat_log; this session executed the plan, then pivoted to a different
abstraction when app_host's `Store` trait turned out to be wrong-shaped
for sprf service state.

## Session goal

Solve the protocol dance once. CLI, LSP, HTTP daemon should all consume
**one** call surface. Adding an RPC must be a single line of new code,
not edits across three shells.

## Trajectory

1. Built v4/src/app.rs against `app_host` (Store/Dispatch/Handler/App/
   Service/Transport). Slice 1 landed — InProcessClient round-tripped
   through a `tower::Service<Action, Reply>`.
2. Examined the abstraction. Found three grate points:
   - `Store` trait over-specifies for service state (6 assoc types,
     read/write/subscribe). Sprf state is multi-modal (doc map + own-
     trait FactStore + immutable Registry + probe buffer). Methods
     stubbed; trait was dead code.
   - Per-action `Reply` union balloons. Read paths reach `&store`
     directly in-process; daemon path forces type-erasure anyway.
   - `CTX: task_local Arc<dyn Any>` adds runtime downcasting for
     ambient context sprf doesn't yet need.
3. User reframed: HTTP-as-the-bus. CLI/LSP/web all become clients of a
   single `axum::Router`. Asked for codegen so adding endpoints is one
   line. Decided against `tower::Service` directly because its single-
   `Response` type forces the Reply union; HTTP-typed-client pattern
   keeps per-RPC return types.
4. Implemented `sprf_rpc!{ … }` `macro_rules!` that, from a single
   block declaring `(method_ident, ReqType, RespType, "/path")`,
   emits four artifacts:
   - `trait SprfHandlers`     — implement once on `SprfState`
   - `trait SprfClient`       — typed call surface
   - `pub mod _routes`        — per-route generic `async fn`s
   - `fn build_router<H>`     — `axum::Router` with all routes
   - `struct InProcessClient` — `tower::ServiceExt::oneshot` of the Router
   - `struct HttpClient`      — same trait via `reqwest`
5. Rewired all three shells against the macro:
   - `sprefa-run` (CLI): `InProcessClient` (default) or `HttpClient`
     via `--remote URL`. Same call sites either way.
   - `sprefa-lsp` (tower-lsp Backend): every LSP method shims into
     one RPC. Backend keeps a text cache only for byte→line/col
     conversion.
   - `sprefa-daemon` (new bin): `axum::serve(TcpListener, Router)`
     with graceful shutdown. The whole RPC surface is whatever's in
     the macro; no per-route wiring.
6. Smoke proven three ways for the same source file:
   - `./sprefa-run hello.sprf`                                 (in-process)
   - `./sprefa-run --remote http://127.0.0.1:8788 hello.sprf`  (HTTP)
   - `curl -X POST http://127.0.0.1:8788/run -d '{…}'`         (raw)
   All three return `greet: 1 rows`. 105/105 lib tests + 2 router
   smoke tests green.
7. Pivoted to TextMate grammar work. v3-era extension (`sprefa.sprf`)
   was conflicting with v4 — uninstalled it. New tmGrammar opens a
   per-DSL scope per `re` / `glob` / `ast[lang]` / `json` / plain
   backtick prefix. Universal `${X}` hole highlighting inside any
   backtick body.
8. User dictated three host-syntax rules:
   - **Strings = backticks only.** No `"..."`, no `r#"..."#`. Bare
     backtick at pipe-step lowers to `str`.
   - **`${X}` is template-literal interpolation only.** Valid inside
     backtick bodies; illegal at host arg position. Like JS:
     `\`hello ${name}\`` is a hole, `f(${name})` is not.
   - **No whitespace between op name and `?` / `[` / `(` / `` ` ``.**
     Only `{ … }` block slot may follow whitespace.
9. Implemented all three:
   - tree-sitter grammar.js: dropped `string_literal` and
     `raw_string_literal`; `?`/`[`/`(` use `token.immediate(...)`;
     `dsl_body` split into `dsl_body` (extras-allowed for bare-step)
     and `_dsl_body_attached` (immediate, aliased back to `dsl_body`)
     for the op-attached case. Regenerated parser via
     `tree-sitter generate` (ABI 14, no tree-sitter.json yet).
   - compile/walk.rs `classify_slot`: detect `${…}` in slot raw and
     emit `lang/host-hole-illegal` diag.
   - tmGrammar: removed `string` / `raw-string` rules; tightened
     op-name and predicate-suffix lookaheads to require zero
     whitespace before `?[(`` ` `` (brace still permitted).

## Locked design

### Protocol dance solved

```
sprf_rpc! {
    fn lsp_open       (LspOpenReq)      -> ()              => "/lsp/open";
    fn lsp_change     (LspChangeReq)    -> ()              => "/lsp/change";
    fn lsp_close      (LspCloseReq)     -> ()              => "/lsp/close";
    fn get_diags      (GetDiagsReq)     -> Vec<SprfDiag>   => "/lsp/diags";
    fn get_inlays     (GetInlaysReq)    -> Vec<InlayProbe> => "/lsp/inlays";
    fn run            (RunReq)          -> RunReport       => "/run";
    fn get_fact_table (GetFactTableReq) -> FactTable       => "/facts";
}
```

Adding the 8th RPC = one line + one method body in `impl SprfHandlers
for SprfState`. Every shell (CLI, LSP, HTTP daemon, web, curl, future
Slack/IDE/MCP) inherits it.

### Host syntax (v4-final-for-now)

| concept                        | syntax                                                  |
|--------------------------------|---------------------------------------------------------|
| string                         | `` `text` ``                                            |
| template interpolation         | `` `text ${X}` `` (inside backtick only)                |
| atom                           | `:foo`                                                  |
| bareword (term ref)            | `NAME`                                                  |
| op call                        | `op` `?`? `[flow]`? `(args)`? `` `dsl` ``? `{ block }`? |
| slot adjacency                 | no whitespace before `?` / `[` / `(` / `` ` ``          |
| block slot                     | `{ … }` may follow whitespace                           |
| pipe                           | `step > step > step`                                    |
| fork / stmt sep                | `;`                                                     |
| comment                        | `# …` to EOL                                            |

## Open follow-ups

1. **Op-def gaps surfaced by the demo file:**
   - `glob` declares paren-args, refuses dsl. Should accept dsl as
     pattern source (`glob\`**/*.rs\``).
   - `ast` lower-time errors with "Lang threading not yet wired."
     `[lang]` flow slot needs to thread through to `parse_dsl`.
   - `json` not registered as an OperatorDef. Wire from `cst::dsls::json`.
   - `fact` not registered (`fact_read` / `fact_write` are). User
     wants the bare `fact?(:t, k, …)` form.
2. **Term-ref desugar at host level.** A bareword in slot position
   currently classifies as `Value::Atom`. The user's intent was
   "barewords flow as term refs/binders." Need to revisit
   `classify_slot` to thread bareword → `term(:NAME)` op vs
   `term_bind(:NAME)` based on op-arg-spec position.
3. **`${X}` in DSL bodies must reach lower-time bindings.** Today
   the rule is enforced at the host but the lower-time substitution
   already works for `str`. Confirm cross-DSL (re/glob/json) path
   threads the same.
4. **app_host directory deletion.** Defer until the daemon transport
   resurfaces (`hyper-util` UnixSocket support is the candidate use
   case if the user wants UDS instead of TCP).
5. **`fromEvent` / external-source ops not started.** `from_position`,
   `fs_watch`, `gh_watch`, `tick` were discussed in the prior
   session's "everything is fromEvent" thread and are still pending.
6. **`from_position` + sub-pipe holes inside backtick** — the two
   primitives that unlock Direction 2 (type-as-query-seed) per
   llm-notes.md "Codegen plane" section.

## Author preferences reinforced

- ${X} interpolation is template-literal-only (JS-style); not a host
  carveout. v3 had it as a host sigil; v4 confines it to the backtick.
- Backticks are the universal string syntax. The host has one string
  kind, not three.
- Slot adjacency is a hard parser rule. Whitespace before slot openers
  fails to parse instead of warning at lint level.
- Macro-rules over proc-macro until the lower rung fights us.
- Per-RPC typed return; never a closed Reply union.
