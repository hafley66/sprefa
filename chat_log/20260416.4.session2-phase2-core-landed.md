## Key Insights
- **Scan loop vs init_cursors**: The Zoom 3 pseudo treats init_cursors
  as a drop-in for whatever ran pipelines. But real DocSession runs
  `run_scan_loop` which iterates pipelines up to `DEFAULT_DEPTH` times
  and grows `Config.repos/revs` from content-side scan-pointer claims.
  Without that loop, scan-pointer expansion won't happen. For Phase 2e
  to be a faithful rewire, either init_cursors grows scan-loop
  semantics, or DocSession keeps run_pipelines and init_cursors is
  only the CLI/stress-test entry point.
- **sqlite in-memory + pool**: each connection has its own DB. Must set
  `max_connections(1)` or switch to `mode=memory&cache=shared`.
  Chose the former — simpler, matches the single-session memory test
  use case.
- **async_stream + MutexGuard**: `async_stream::stream!` captures
  environment and the resulting future isn't Send when a MutexGuard
  lives across an await. Drain-to-Vec-before-await, or switch to
  mpsc+ReceiverStream. Chose the latter.
