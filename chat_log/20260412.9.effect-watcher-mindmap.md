### THE MAPPING (old → new)

| Old Component | New Component | Relationship |
|---------------|---------------|--------------|
| Change enum (FsChange, DeclChange) | Effect enum (RefactorMove, RefactorRename, RefactorFix, ShellExec, CodegenRender) | Effect = Change + metadata + discovered edits + safety + status + timestamps |
| Edit struct (file, span, value) | PendingEdit struct (file, span, value, safety, reason) | Same shape, adds safety level for approval routing |
| plan_rewrites() | effect_producer() | Planner runs eagerly to discover full impact, stores in effect.descriptor |
| rewrite::apply() (immediate) | effect_consumer() (gated by approval) | Same apply logic, just gated by effect.status |
| Store trait (flush_batch, etc) | EffectStore trait (insert_effect, approve_effect) | Extension, not replacement. Existing methods unchanged |
| (no equivalent) | CircuitBreaker | New global safety limits across all effect types |
| (no equivalent) | Effect journal | Append-only log of all proposed/approved/applied |

### KEY FLOW CHANGES

BEFORE (direct):
```
file changes ──▶ classify ──▶ plan ──▶ apply ──▶ files changed
                              (immediate, no persistence)
```

AFTER (effect saga):
```
file changes ──▶ classify ──▶ plan ──▶ EFFECT ──▶ DB ──▶ approve ──▶ apply
                              (eager)    │       │        │
                                         │       │        └─ LSP, CLI, auto
                                         │       └──────────── durability
                                         └──────────────────── audit trail
```

### SAFETY LEVELS (new concept)

| Level | Examples | Approval Behavior |
|-------|----------|-------------------|
| Pure | Import reordering | Auto-approve, no circuit breaker |
| Reversible | Rename variable | Auto-approve if circuit breaker OK |
| Destructive | Inline function | Require explicit approval |

### CIRCUIT BREAKERS (new concept)

| Limit | Action When Tripped |
|-------|---------------------|
| max_effects_per_minute | Queue effects, notify user |
| max_destructive_per_hr | Reject destructive, queue reversible |
| require_tests_pass | Run tests before apply, rollback on failure |

### LSP INTEGRATION (new capability)

Editor shows pending effects as:
- Code Action: "Apply: Rename Foo to Bar (3 files affected)"
- Hover: "Pending Effect: Move src/old.ts → src/new.ts
  Would update 5 imports
  [Preview] [Apply] [Ignore]"

## Key Insight

Three shifts:
1. **Change → Effect**: Same detection, wrapped with metadata (impact, safety, status)
2. **Direct apply → Gated consumer**: `rewrite::apply()` unchanged, just gets edits from approved effects  
3. **Ephemeral → Durable**: Effects table becomes the journal, enabling replay/rollback
