## Key Insights
- type_entity is 7 cols: (repo, sym, name, kind, parent, file, line). NOT the 6-col version in CLAUDE.md, and NO `ty` col. Verify via rel_catalog. (Got it wrong twice this session.)
- ast_yaml IS a builtin op (ast-grep RuleCore YAML, inside:/has: relational; parse.rs:561 -> sg.rs:80 run_ast_yaml; same span outputs as sg).
- Plain rel head does NOT interpolate {var} — that's a gen-sink-only feature; bind the var into the column instead.
- The commit-time lint = .githooks/pre-commit -> `dl --check` (core.hooksPath=.githooks) running .dl/rails.dl; the unwrap-budget rule warns on every .unwrap() span in a CHANGED file with >10 unwraps. engine.rs has 11 -> 11 warn squiggles, non-blocking (warn not error).
- `use` resolver (frontend.rs include_roots): program dir, $SPREFA_STD, CARGO_MANIFEST_DIR (dev), exe parent; disk always wins, embedded is last resort.
- stub embedder is token-overlap: sharp on scip/openapi (tokens in summaries), mushy on phrasings like "cross-repo lsp goto". --features embed-fastembed swaps a real ONNX model, same dl examples interface.
