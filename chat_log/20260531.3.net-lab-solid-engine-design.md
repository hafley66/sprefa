## Problem/Context
Continuation of the frame-anim session (saved as 20260531.0). frame-anim (v5/anim, React deck animator) was judged lightly-tested bespoke sprawl; pivoted to net-lab on Solid because the architecture is "one cursor, many lenses" = fine-grained reactivity + imperative SVG, which React fights. User is React-fatigued, knows rxjs theory deeply, wanted to LEARN Solid by reading it sewn. User dislikes the frame-anim git-log lens (boring/indecipherable) and the graph-transition flash. dl (the v5 Datalog-over-code engine) is NOT done and off-limits; it will later feed real type/usage graphs via the sql-graph SQLite seam.

## Solution/Approach
Solid + signals: cursor = createStore; lens = plain imperative fn over DOM/SVG (the "it's just a library" core); App.tsx sews them with createEffect (the subscription) + createMemo (derived). Lessons are data; lenses render over SOLVED layout engines (mermaid/d2/graphology — never reinvent layout). UNIFYING MODEL recorded: many trees -> one ls-la (or graph/sequence/fs) lens -> columns in sliding panes -> each its own clock -> FLIP per pane.

Tree-vs-graph model (the user's clarifying insight): ls/tree = nesting = ONE parent pointer. One node type: Node = { id, parent?, refs? } — parent = tree spine (render as ls, no layout lib), refs = graph overlay. Project a tree FROM a graph = compute parent via BFS/DFS spanning tree or dominator tree, with SCC condensation (Tarjan) folding cycles to one entry (what dl does).

## Key Insights
- Solid fits "one cursor, many lenses" because lenses are imperative SVG and React's VDOM is friction. Lens = vanilla fn; createEffect is the subscription; deps auto-discovered by reads (rxjs subscribe minus the wiring).
- DON'T reinvent solved rendering (sequence/graph layout) — generate mermaid/d2/graphology, post-fix the SVG. The hand-rolled ladder was the anti-pattern.
- No-flash transition = View Transitions API: render nodes as positioned DOM, view-transition-name=id, swap inside document.startViewTransition() -> shared ids interpolate, new fade in, gone fade out. SVG edge paths fall back to D3/GSAP Flip. (Same idea as shiki-magic-move/Slidev.)
- Prototypes are for harvesting a likes/dislikes list, then they die. Don't polish them (over-polishing curl.html was the waste).
- 3-agent panel (2 personality-vectors + 1 research): SHIPPER said build lesson 2 not the abstraction, cut ls-la/sliding-panes/git/TOC, riskiest assumption is the unifying model. VISIONARY said the real idea is ls-la-as-universal-projection (Victor-grade IF it holds — paper-test it) and the deep cut is per-column clocks (time x dependency space, both navigable) + "a diff is itself a tree" (closure property dissolves git-history). They AGREE: paper-test ls-la first; FLIP is the epistemics ("same world one fact changed" not "new diagram").
- RESEARCH: nobody has the whole vision; it's a union of three thirds (Slidev=animated presentation, tldraw=canvas substrate, Marimo/Observable=reactive editable). Sourcetrail (archived) is the only one that shipped one-cursor->synchronized-graph+code. The GAP = synchronized multi-lens cursor + polymorphic tree readout. STEAL: shiki-magic-move diff engine (has Solid wrapper), View Transitions pattern (Slidev), tldraw reactive store, Marimo dataflow-DAG cursor model.
- STACK DECIDED: graphology (graph model + algorithms incl. DOMINATORS + SCC + traversal; only lib with dominators, render-agnostic) + d3-hierarchy (trees) + elkjs/@dagrejs/dagre (layered) + own Solid DOM render + View Transitions (no-flash) + @hpcc-js/wasm or d2-wasm (runtime text->SVG) + Rete v2 core or @xyflow/system (only if draggable editing later; neither ships Solid). AVOID: Cytoscape (canvas/imperative, no dominator tree), Motion/Framer layoutId (React-first, no SVG), deprecated dagre/dagre-d3.
