## Problem/Context
- Panel presets query `rel_*` tables; derived rels (marks/diff/member/madge's old
  rel_module_node) only exist when their .dl is served -> `no such table` RED banner.
- `madge` preset queried derived `rel_module_node` (not builtin) -> the trigger bug.
- Graph drawing required bespoke per-preset SQL = "awful UX"; user wants builtin
  "this is a node / this is an edge" rels.
- Extension blank on another machine: GUI-launched VS Code (Finder/Dock) does NOT
  inherit shell PATH, so bare `dl` ENOENTs, `~/.cargo/bin` missing -> dead LSP bridge.
- A LIVE daemon (pid 4009) on ~/projects/sprefa ran the OLD (pre-graph) binary and
  kept re-splicing README from its stale catalog, reverting doc regen. Stopped it
  via `dl --stop --root .` (respawns on demand with new binary).

## Solution/Approach
Panel (flow-panel.html, host-agnostic webview, pure JS):
- madge preset -> synthesize nodes from builtin rel_module_edge endpoints (UNION
  src/dst), works on bare scan.
- run() catch: ANY `no such table: rel_X` -> render([],[]) + one-line grey note
  (errLine), never the red banner. (generalized the old diff-only special case)
- updatePresetAvailability(): parse each preset's rel_ tables, introspect live
  schema (refreshExistingRels via sqlite_master LIKE 'rel_%'), DISABLE presets
  whose tables are missing + label " - needs .dl". Wired into discoverLayers().
- emptyState overlay (#emptyState + CSS): render() shows it when nodeRows empty;
  builtin-preset case names the daemon/data cause + `dl --daemon --root .`.

graph_node/graph_edge builtin sink (mirrors diag pattern exactly):
- GRAPH_RELS const + graph_rel_decls() (group "graph"): graph_node(id,label,kind,
  file,line,parent) all TEXT/INT (id/file TEXT so non-path/NULL not row-dropped),
  graph_edge(src,dst,kind). Chained into decl list + declare_builtins + reserved-
  name guard (bails "head it directly like diag") + op_docs tuples.
- Head like diag with named args (subset works, rest NULL). rebuild_derived fills
  them from rules; tables always exist (empty until headed) -> always-available preset.
- Migrated .dl/git-graph.dl: dropped `rel graph_node/graph_edge`, heads now named
  form, `? graph_node(id,label,kind)` -> 6-arg. Renamed examples/madge.dl's
  1-ary `graph_node` (module node) -> `mod_node` (COLLISION: graph_node is a name
  users naturally grab - flagged to user).
- Panel: prGraph preset renamed -> `graph` "Graph (node/edge sink)", queries builtin
  rel_graph_node (6 cols)/rel_graph_edge, added to builtin-always list + help table.

Extension #3 (extension.ts): dlBinDirs()=[~/.cargo/bin,/opt/homebrew/bin,
/usr/local/bin]; resolveBinary(configured) probes disk, returns {command,found};
showErrorMessage + "Open Settings" when !found; spawnEnv prepends dlBinDirs to PATH
on both run/debug ServerOptions.

## Key Insights
- graph_node collides with names users grab (examples/madge.dl used it as module
  node). Reserving common names is disruptive; flagged. mod_node the rename.
- Live old-binary daemon silently reverts doc-regen (README splice) - ALWAYS check
  `ps aux | grep '[d]l --daemon'` + pid file when regenerated docs won't stick;
  `dl --stop --root .` to stop the fight (respawns with new binary).
- Diag builtin-sink pattern (DIAG_RELS const + *_rel_decls + chain + declare_builtins
  + reserved guard + op_docs) is the template for any new head-writable builtin.
- Doc regen: examples/builtin-rels.dl -> README block; examples/gen-reference.dl ->
  docs/reference/relations.md+syntax.md. gen is convergent; catalog table is
  rel_rel_catalog (not rel_catalog). First gen run had a convergence hiccup (missed
  graph rows); a clean rm-db re-run wrote them.
- GUI-launched editor PATH truncation is the classic "extension works in terminal,
  blank in app" cause - probe ~/.cargo/bin + augment spawn PATH.
