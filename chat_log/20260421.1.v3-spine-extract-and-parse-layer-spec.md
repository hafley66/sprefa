## Problem/Context

Pre-session state: sprefa/ was a 40+ file flat src/ with v2 verbatim. The
spec at parse.md was too narrow (parse-layer only, no Rust types). User
wanted v3 to move, types in a real core package ("spine"), and an honest
language spec with type snippets.

Recurring theme: "ops own everything" invariant lives intact. Host-level
errors are parse crate's concern (`ParseError { message, offset }` plain
data); op-owned diagnostics live per-op as `FooDiag` enums that impl
`spine::Diagnostic`. Runtime (`server/run.rs`) wraps parse errors into
diagnostics at the boundary.

## Solution/Approach

Crate split landed in two phases this session:

**Phase 0 — sprefa_parse extraction:**
- Moved parse.rs + ParseSite/ParseSeg (as `site.rs`) + OpInvocation + slot

- lib.rs aliases `pub use sprefa_parse as parse;` so `crate::parse::X`

**Phase 1 — spine extraction (semantic core):**

  new `mutations.rs` carrying just the trait surface.
- sprefa keeps each of those as a re-export shim.
- `EffectStatus`/`EffectOutcome`/`EffectResult` moved to spine; sqlite
  store re-exports. `EffectResult::from_str`/`as_sql_str` moved with them.

  `await_approval`, `spawn_handler` stay in sprefa because they touch
  the concrete Store.

Spec rewrite: `v3/crates/sprefa/src/parse.md` now 19 sections + §20

## Design locks reached this session

1. `$` is one op with two shapes: `$IDENT` ≡ `${IDENT}` shorthand.
   Brace body is recursive host_expr.
2. `> $X` is annotate-only — writes `captures[X] = cursor.byte_range`,
   leaves content/byte_range untouched. `&>` sigil dropped.
3. `last_bound: Option<Arc<str>>` added to Cursor; spelled `$$` at the
   reference side. `$$sigil` scan-pointer form retired with a diag.
4. Fork-to-void replaces `&>` for transforming side-effect taps.
   `void` is a regular op (`ConsumeOp`).
5. Carveout narrowing: only `byte_range` changes; content/captures/
   slots/last_bound/parent all inherit. Pattern sugar stays isomorphic
   to inline form.
6. `rule.$V` is ordinary dotted-access host_expr; `parse_cross_ref`
   deleted from v2.
7. Crate layout target (not yet executed beyond spine):
   - spine → effects → ops_core → backends → ops → sprefa
   - ShellCallEffect in effects; `sh` op in ops.

## Key Insights

1. **Parse crate deliberately does not depend on Diagnostic.** Parse
   errors are plain data (`ParseError { message, offset }`); runtime
   adapter (`sprefa::server::run::ParseErrDiag`) wraps them into
   `spine::Diagnostic`. Keeps parse leaf-level with only std deps.
2. **Host-level vs op-owned parse errors are two tiers.** 95% of errors
   are op-owned (JsonDiag, RuleDiag, etc., implementing Diagnostic).
   Host errors are the unattributable structural residue (unclosed
   brackets, top-level lex failures). Tree-sitter migration will shift
   some to op-owned via ERROR-node attribution.
3. **Cursor already IS a span.** captures store `Range<usize>` into
   `cursor.content` Arc; zero-copy is free. No Value/Scalar debate —
   byte_range is the universal binding type.
4. **Fork-to-void replaces `&>` proposal.** Side-effect taps that
   transform use `{ > norm > scan_pointer > void; > main_rest }`.
   Arms are cursor-independent by Arc::clone; no sigil needed.
5. **`last_bound` is TI-84's Ans slot.** Per-cursor field, updated only
   by CaptureWriteOp, inherited unchanged across carveouts, isolated
   per fork arm. Spelled `$$` at reference.
6. **Spine phase 2 is gated on two trait extractions.** `Store` and
   `RegistryHandle` must become spine traits before `op.rs` can move
   without pulling sqlite into spine. That's the real work before any
   ops-crate split makes sense.
7. **Tree-sitter experiment is not wasted motion.** It validates
   `set_included_ranges` injection at arbitrary depth. Migration path:
   port sprefa_parse's hand-rolled internals to a tree-sitter-sprefa
   grammar once the surface stabilizes; keep `host_parse` signature
   stable as a wrapper.
8. **Type transclusion dogfood is real target.** §20 of parse.md
   sketches `rule(doc_type_sync) > fs > marker > &{...} > ast[rust] >
   render_into_marker`. Every Rust snippet in the spec becomes
   auto-synced when this lands. Memory
   `project_type_transclusion_dogfood.md` records it.
