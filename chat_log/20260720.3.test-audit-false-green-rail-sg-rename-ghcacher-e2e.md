## Key Insights
- **Router stale-rel bug — the one genuine release concern.** `retraction_props.rs:499`, `#[ignore]`d with a reproducing seed in the attribute string. From the file's own comment (465-482): when a call-family input rel (e.g. `_call_def`) is EMPTY on the tick that first populates the router memo, `Ctx::scan` records no per-row deps, so the memo footprint OMITS it. Later inserts never trigger a rerun of `call_def`/`call_name`/`call_def_rev` and THE PUBLIC REL STAYS STALE. Core product relations. Seed persisted in `tests/proptest-regressions/retraction_props.txt`, which proptest scopes to the FILE not the test — so the non-ignored 20-case sibling at :487 shares the strategy and may already replay it.
- **Audit totals, 1,532 tests**: OK 1,484 / FALSE-GREEN 22 / SKIPPED-PROBLEM 2 / ENV-GATED 15 / NOT-A-TEST 8 / REDUNDANT 1 / STALE 0.
- **22 FALSE-GREENs, one dominant shape**: early exit on a missing external tool with NO `#[ignore]`, so it looks executed. `oracle_go.rs`/`oracle_ts.rs` module docs state this as INTENTIONAL — the documented rationale IS the anti-pattern.
- **Rail gap, deliberately not papered over**: `const_value.rs:153` is `Err(_) => {}` — an EMPTY arm. No `return` for arm 2, and arm 1 counts the `Ok` branch's asserts as covering the test. Needs per-path assertion reachability.
- **ONE `match` legitimately survives** in the rail: arm 3 predicates on the TEXT CONTENT of an `#[ignore]` reason. sg can match `#[ignore = $REASON]` but METAVARIABLES ARE NOT EXPORTABLE as output args (sg outputs = line/col/end_line/end_col/id only). Real engine gap; metavar outputs would close it.
- **`examples/gh-cache.dl` had ZERO coverage repo-wide.** 4 "hermetic" tests hand-wrote a parallel inline `.dl` string. FIXED: 5 fixture-driven e2e via `include_str!`, mutation-proven (I broke the `@next etag` carry independently — all 5 failed; reverted clean). Correct pattern already existed at `flow_ctor.rs:79`.
- **The new gh_cache tests were themselves a false green**: fixture template returned 404 on a missing fixture so "an unexpected extra poll degrades to no-new-200 instead of breaking the script" — structurally blind to effect N+1. The list endpoint is the sharp case: `pull_request` fans one body into many rows, so a per-row fetch would pass every existing assertion.
- **~/projects/ghcacher (116 tests) is a TEST ORACLE for the rewrite.** `MockGhClient` records `Vec<(String,String)>` of calls (not a bare counter), `assert_eq!(mock.graphql_call_count(), 1, "expected 1 batched GraphQL call, got {}")`, `== 0` for no-work paths, persisted `call_log` with `cache_hit`. CRUCIAL DIFFERENCE: its fallback `.unwrap_or((200, json!([])))` RECORDS THE CALL FIRST then falls back; sprefa's 404 masks AND never records. Rule: ALWAYS RECORD, then fall back.
- **Two likely real defects in gh-cache.dl** from the old repo's scenario list: (a) the 3-line `status\netag\nbody` stdout protocol breaks on any body containing a newline (live template papers over it with `tr -d '\n'`; old repo has 3 tests for this), (b) retraction — `resp` ACCUMULATES, so PRs [1,2,3] -> [1,3] may leave PR 2 lingering (`prunes_deleted_pull_request_heads`). Same shape as the router bug: stale rows surviving a change.
- `CLOCK_LOCK` (tests/it/clock_lock.rs) is a std Mutex that POISONS on panic, cascading PoisonError onto siblings — turns one honest failure into four misleading ones. Pre-existing.
- `src/activity.rs` `SLOT` global static races under the default harness; that is what "load-sensitive" meant for `lifecycle_round_trips`.
- Agent A's blind spot is the general lesson: file-ownership splits that keep concurrent agents from colliding are ALSO what let a design inversion land with its own spec test left behind in an unowned file.
