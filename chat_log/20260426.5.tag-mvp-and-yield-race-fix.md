## Problem/Context

### Race discovery (the central insight)
Designing tag-read against the bd card's plan (snapshot_or_subscribe
that registers a SubjectKey on the registry, then ctx.put(Yield).await)
exposed a primitive-level race in effect_runtime.

Old shape: caller allocates SubjectKey, calls ctx.put(Yield{key}). The
registry entry only gets created when YieldBatcher::run is polled by
the runtime. Window: producer holding `key` (e.g. tag's bag.waiters)
calls registry.next(key) BEFORE the batcher runs → entry not yet in
pending → silent no-op → wake lost → await blocks forever.

The original subjects.rs tests papered over this with spawn-then-sleep:
`spawn(async { sleep_10ms; reg.next(key) })`. The 10ms sleep guarantees
the YieldBatcher has registered before next fires. The race only
appears when the SubjectKey is shared across actors — exactly tag's
shape.

User framing locked: tag = "replay (Phase 1) + online (Phase 2)". Phase
1 is just snapshot under store mutex; can't choke. Phase 2 is the
subscribe handoff where the race lived.

## Solution/Approach

### effect_runtime (subjects.rs)
Added `pub fn subscribe(self: &Arc<Self>, key, lineage) -> BoxFuture`.
Synchronously inserts the pending entry before returning. Returns a
future with a built-in Drop guard (calls unsubscribe on future-drop).
YieldBatcher::run collapses to:
  let fut = registry.subscribe(req.key, req.lineage);
  select! { r=fut => r, _=cancel.cancelled() => Err(Unsubscribed) }
register() stays private; subscribe() is the public door.

Two new tests:
- subscribe_then_synchronous_next_resolves: allocate key, subscribe,
  reg.next(key) IMMEDIATELY (no spawn-sleep). Future resolves Ok. This
  is the test the original suite should have had.
- subscribe_drop_unsubscribes: drop the future, pending_count == 0.

### pipeline/effects.rs
TagStore (impl Store): `Mutex<HashMap<Arc<str>, Bag>>` where
`Bag { rows: Vec<Vec<Arc<str>>>, waiters: Vec<SubjectKey> }`. Atomic
snapshot_or_subscribe(name, last_idx, key, registry) under one
store-lock critical section: if rows past last_idx return Rows(tail);
else registry.subscribe(key) + bag.waiters.push(key) + return
Subscribed(fut). The lock-order discipline (store first, then registry
inside subscribe) matches the writer's lock order, so no deadlock.

TagWriteEffect { name, row } + TagWriteBatcher: lock store, push row,
drain waiters, fire registry.next(k, Arc::new(())) for each. Sentinel
NextValue (unit) since the wake just signals "rows changed"; reader
re-snapshots from last_idx.

### pipeline/ops/tag.rs (new)
TagOp enum:
  - Write { name, args: Vec<TagArg> }: per_cursor →
    materialize_row(args, cursor) → ctx.put(TagWriteEffect) → pass
    cursor through.
  - Read { name, holes: Arc<[Arc<str>]> }: pipe_flat_map override.
    upstream.flat_map(batch→cursors).flat_map_unordered(None, |c|
      subscribe_stream(...))
    subscribe_stream is a stream::unfold over State { last_idx, ... }
    that loops: snapshot or subscribe; on Rows emit and advance idx;
    on Subscribed select! { fut, ctx.root_cancel().cancelled() } and
    re-snapshot or terminate.

TagArg = Capture(name) | Literal(Arc<str>). Materialize_row: capture
refs read cursor.capture(name).bytes(...).utf8 (missing → empty
string, user discipline). Literals splat through.

OpCtor::from_values classification:
  - first must be Atom → tag/missing-name | tag/non-atom-name
  - rest classified per Value: Term::Read / Atom / Str / Int / Float
    = bound; Term::Unbound = unbound; Op = tag/op-arg-unsupported.
  - any bound + any unbound = tag/mixed-mode.
  - all unbound → Read with hole names.
  - else → Write with TagArg list (Int/Float coerced via to_string).

## Key Insights

1. **The Yield primitive had a producer-side wake race that the
   original tests structurally couldn't catch.** The test pattern
   `spawn(sleep+next)` always lets YieldBatcher::run register the entry
   before next() fires. The race only manifests when the SubjectKey is
   shared across actors. Tag is the first consumer that exercises that
   shape; it surfaced the gap. Fix: synchronous register inside a new
   pub `subscribe` method.

2. **Phase 1 (replay) vs Phase 2 (online) framing makes the race
   surface exact.** Replay can't choke — it's just memcpy under a
   mutex. The handoff to perpetual subscription is the only choke
   point. User read this immediately from the description; that
   framing should anchor any future tag-shaped op.

3. **Store-lock outermost, registry-lock inside subscribe — consistent
   across writer and reader.** Writer: lock store, snapshot waiters,
   drop store lock, then per-key acquire registry lock for next().
   Reader: lock store, call registry.subscribe (acquires registry
   lock), push key into waiters, drop store lock. Same nesting order,
   no deadlock.

4. **Identity-default `pipe` + selective `pipe_flat_map` override
   keeps the trait flat.** TagOp::Write inherits the default
   pipe_flat_map by manually inlining the mergeMap pattern; TagOp::Read
   overrides for perpetual subscription. No split traits, no Option,
   no unreachable! — same posture as last session's ports.

5. **flat_map_unordered(None, ...) over per-cursor BoxStreams is the
   merge primitive for "fan upstream cursors into per-cursor
   subscriptions".** Sequential flat_map would gate every upstream
   cursor on the first one's perpetual stream finishing (never).
   buffer_unordered doesn't apply because it operates on futures, not
   streams. flat_map_unordered runs them concurrently with no bound.

6. **Cancel must be wired EXPLICITLY for direct subscribe() use.**
   ctx.put(Yield) gets cancel-on-token via YieldBatcher's select!.
   Tag's subscribe_stream calls registry.subscribe() directly, so it
   has to capture ctx.root_cancel() at pipe_flat_map time and select!
   it against the subscribe future inside the unfold. Initial naive
   version omitted this and the runtime-cancel test hung; user
   reported "its hanging bro" before I caught it.

7. **sprefa-run's old print-after-collect pattern broke for perpetual
   ops.** Stream never ends → trailing println never runs → stdout
   silent until timeout SIGTERM. Fix: print rows incrementally inside
   the loop, emit trailing row-count when the stream actually ends.
   Existing smokes still pass because their grep patterns are anchored
   on the trailing line which still appears for finite ops.

## Open Questions
- The `tag_smoke.sprf` fixture (header: "DOES NOT PARSE TODAY") encodes
  the future spec: dotted carveout `${R.head?}`, variadic-write that
  re-fires on capture refresh, multi-tag join with combineWith
  semantics. Different shape from the MVP. Stays disabled until
  grammar (sprefa-p0m) + registry refresh (sprefa-465) + Pending
  primitive (sprefa-126) land. Not in scope this session.
- Sentinel-(`Arc::new(())`) NextValue for tag wakes is fine for v0
  (reader re-snapshots from last_idx), but if we ever want to ship
  the row through the wake (avoid the second snapshot lock), the
  payload type would be `Arc<Vec<Arc<str>>>`. Defer.
- TagOp::Read fan-out per upstream cursor uses unbounded
  flat_map_unordered. Many upstream cursors → many concurrent
  perpetual subscriptions. v1 perf rerun (sprefa-vyw) will tell us
  whether to bound it.
