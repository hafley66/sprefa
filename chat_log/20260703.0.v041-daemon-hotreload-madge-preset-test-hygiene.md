## Key Insights
- Discovery daemon exit-for-respawn was a design dead end: nothing respawns it. touches_program can never mean set-change in discovery mode (program_in_paths only matches known files; creation is handled by the later discovery block) so content-edit => reload_program is exactly right.
- used-gate reminder: a built-in rel's table can EXIST but stay empty until some program references it (rel_module_edge empty on the live db until flow-panel.dl gained module rules).
- Cross-program rel-name collisions in a shared db are silent (madge.dl `seen` vs flow-panel.dl `seen`); panel presets must read rels derived by .dl/ discovery programs, not example files.
- Orphaned child processes hold pipe write-ends: `cargo test | tail` hangs after cargo exits if any spawned child inherited stdout/stderr. Fix shape = RAII kill-on-drop guard + Stdio::null() at spawn. Also: `tail -N` of a suite run can show child chatter instead of the summary — trust exit codes through &&.
- macOS SUN_LEN (104 bytes) bites long tempdir socket paths — keep daemon-test sandbox tags short ("dischot").
- git worktree cannot ff a branch checked out elsewhere; `git push origin HEAD:main` from the worktree + later `git pull --ff-only` in the main checkout avoids stash-dancing another session's WIP. LATEST.md pointer conflicts resolve by taking origin (it's just a pointer, rewritten at next save).
- cargo install prints the replaced source (`?rev=7aa29be` -> `--path`); package name sprefa-dl, binary dl.
- Landing another session's WIP: read its session log first — it may contain its own commit instructions (suggested subject line, expected suite counts).
