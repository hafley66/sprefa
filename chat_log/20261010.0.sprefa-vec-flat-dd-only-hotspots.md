## Problem/Context
- Lists were cons chains: one engine call per depth, 8192 items crashed (TERM_BUDGET).
- `[ ]` macro cost ~23 macrotime rows per item.
- Agent's first vec used vec_item/vec_len tables (doubled terms).
- Profile showed: double reify, Prolog structural sorts, per-string round trips, term map rows seeded to DD (unread), SipHash/BTreeMap interner, rehashing terms on table growth.

## Solution/Approach
- intern_term_batch (BatchArg::Earlier) -> one engine call per bootstrap.
- `vec` replaces `[ ]` (call form only), vec.iter/len/get.
- Flat vecs: interner items array + offsets + content hash; Op::Vec Build/Iter/Len/Get in DD; dl8 flat_vec maps application(vec, list) to [vec](items) spec, children-first order, decodes back to cons list.
- DD only: ir:sqlite/ir:duckdb disconnected; ir-rxjs emit removed.
- Hotspots: check_terms (no row build), syntax rows integer sort, intern_texts (Arc<str>), forms_dispatch skips macrotime, stored term hashes, term map out of frontier, interner hashbrown/Vec/KeyRef.
- Kept canonical closure sort (output order must not depend on interning order).
