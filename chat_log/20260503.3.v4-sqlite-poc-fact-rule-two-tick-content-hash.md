## Pivot

User pushed back on DD necessity. Workload shape (file save / AI edit /
ghcacher sync) is bursty, not keystroke-frequency. With switchMap-on-
burst cancellation + content-hash op caching + write-through sinks,
DD's incremental-update advantage disappears. The remaining DD-shaped
problems (held in-memory aggregate updated under writes) are uncommon
in sprf's actual workloads (bulk indexer, debounced LSP rules).

Decision: park DdStore code as proof point, build SqliteStore + Fact
ops on top of the existing Store trait.

## React mental model (per human-goals.md)

```
React                          sprf
─────────────────────────────  ────────────────────────────────────
component                      op
props                          cursor terms (the live ones)
fiber.key                      cursor.lineage_hash (CONTENT_HASH today)
React.memo / bailout           OpCache hit on (op_ident, lineage)
render phase                   pipeline drain (tick 1)
commit phase                   Fact / sink writes (tick 2)
useEffect                      effect_runtime PureEffect
useTransition / Suspense       Pause / yield / next?()
concurrent mode                switchMap-on-burst, abort-and-restart
state                          Store (mem | sqlite)
context                        Hooks
```

CI mode = single tick (render). Reactive mode = render → commit, with
switchMap cancellation between events.

User noted cost asymmetry: React render is ~16 ms, sprf render can be
20+ s on cold corpus. Switchmap cancellation only safe with OpCache +
granular invalidation; otherwise it's a CPU furnace. POC is CI-only
so cost asymmetry is dormant.

## Three-layer caching design (locked, partly implemented)

```
Layer 1: sprf source check
  hash lowered pipeline source. unchanged + unchanged file set
  → entire run is no-op.

Layer 2: per-rule input set hash
  collect (file_path, content_hash) the rule's source ops touch.
  unchanged from last run → skip rule entirely.

Layer 3: per-op cache
  within an invalidated rule, cache by (sprf_path, input_lineage_hash).
  partial reuse for files that didn't change.
```

POC implemented Layer 3's anchor (CONTENT_HASH stamping). Layer 1 + 2
land later, drive against `is_pure` trait method.

## What landed (this session)

### SqliteStore against `:memory:`

- `rusqlite 0.31 (bundled)` added to Cargo.toml
- `pub struct SqliteStore { conn, schemas, pending, tele }`
- `open_memory()` constructor
- Write path: `insert_many` pushes to `pending: Mutex<HashMap<fact, Vec<Cursor>>>`,
  no SQL until `commit(gen)` runs `BEGIN; prepare_cached INSERT; ...;
  COMMIT`. Fsync on commit.
- Read path: `read_in(fact, key_col, key_values, project)` does
  `SELECT col_list FROM fact WHERE key_col IN (?, ?, ...)`, row-streaming.
- `ensure_schema(fact, &cols)` runs `CREATE TABLE IF NOT EXISTS`.
- Implements `Store` trait. `select(...)` returns empty stream
  (no diff broadcast yet).

### Store trait extension (additive, defaults preserve old impls)

```rust
fn ensure_schema(&self, _fact: &str, _cols: &[&str]) {}   // default no-op
async fn read_in(
    &self,
    fact: &str,
    key_col: &str,
    key_values: Vec<String>,
    project: Vec<String>,
) -> Vec<Cursor>;                                          // required
```

MemStore impl scans the HashMap. DdStore impl returns `vec![]`
(parked).

### FactWrite op (schema-aware sink)

```rust
pub struct FactWrite { pub name: String, pub cols: Vec<String> }
```

Calls `ensure_schema` on first batch (idempotent). Subsequent batches
go through `insert_many`. Distinguishes from legacy `Fact` which
inserts whatever cursor terms exist (works for MemStore/DdStore but
not SqliteStore).

### FactRead op (brute-force IN-batch join)

```rust
pub struct FactRead {
    pub fact:     String,
    pub key_term: String,
    pub project:  Vec<String>,
}
```

Per input batch:
1. Collect distinct `key_term` values from all input cursors.
2. ONE `store.read_in(fact, key, values, project)` call.
3. Group result by key.
4. Cross-product: for each input cursor, emit one output per matching
   row, with projected cols set on the output cursor.

N+1 query failure mode does not exist — one query per pipeline batch
regardless of cursor count.

### Rule struct (sqlite-shaped lift)

```rust
pub struct Rule {
    pub name: String,
    pub body: Vec<Arc<dyn Op>>,
    pub sink: RuleSink,
}
pub struct RuleSink { pub fact: String, pub cols: Vec<String> }

impl Rule {
    pub fn new(name, body, sink_fact, sink_cols) -> Self;
    pub fn into_chain(self) -> Vec<Arc<dyn Op>>;  // appends FactWrite
}
```

`RuleBody` enum kept — drives MemStore/DdStore today. The `Rule`
struct is the new shape that `into_chain()` lowers to ops + a
FactWrite tail. RuleBody-replacement deferred until POC proves shape.

### Op::is_pure trait method

Default `false`. Set to `true` on AstNm. Other ops unchanged
(default false). Marker drives Layer 2/3 cache eligibility later.

### CONTENT_HASH stamping in AstNm

Inside the rayon par_iter, after `std::fs::read(path)`:

```rust
let content_hash = blake3::hash(&bytes).to_hex().to_string();
let content_hash_arc: Arc<str> = interner_for_par.intern(&content_hash);
// stamped on every emitted child cursor:
child.set_arc("CONTENT_HASH", content_hash_arc.clone());
```

Anchor for downstream caches. Same content → same hash → same cursor
lineage → cache hit. Interner shares the 64-byte hex Arc<str> across
all cursors emitted from the same file.

### drive_two_tick

```rust
pub async fn drive_two_tick(chain, hooks, cap) {
    drive_with(chain, hooks.clone(), cap).await;     // tick 1: render
    hooks.use_store().commit(hooks.gen).await;       // tick 2: commit
}
```

Two-line wrapper. Tick separation is mostly enforced inside
SqliteStore (writes pend until commit). Mem store still rederives
inline; that's acceptable since two-tick is a driver-level promise,
not a store-level rule.

CommitOutcome struct cut from POC per user feedback. Add later when
something reads it.
