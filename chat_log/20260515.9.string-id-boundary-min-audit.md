# StringId ↔ String Boundary Minimization Audit

**Scope:** `v4/src/runtime_graph.rs` ↔ `v3/crates/effect_runtime/src/v2/runtime_graph.rs`  
**Merge base:** dedupe merge `15bb9bf` (slices 2–10 lifted)  
**Date:** 2026-05-15

---

## TL;DR (5 bullets)

1. There are **49 `StringId.0.to_string()` calls** and **13 `parse::<u64>` calls** in `v4/src/runtime_graph.rs` — all caused by the core's `String`-typed structs (`RuntimeNode`, `RuntimeEdge`, `RuntimeJob`, `RuntimeContinuation`, `RuntimeEvent`).
2. **FactRuntimeGraph** in effect_runtime is its sole non-test v2 consumer outside v4 — v3 production code uses v1 (`RtCtx`), not `FactRuntimeGraph`. This means Option A can land without breaking any active v3 consumers.
3. **Option A (parameterize by `I: NodeId`)** is the top recommendation: add a `NodeId` trait to effect_runtime, swap `String` fields in the five core structs to `I`, impl `NodeId for String` for existing callers, impl `NodeId for u64` for v4's `StringId`. Total LOC delta is approximately **+60 in effect_runtime, -80 in v4** (net -20).
4. All 49 `to_string()` conversions concentrate in eight structural clusters: `insert_node` (7 per call), `insert_edge` (5), `insert_job` (3), `run_to_quiescence` callback projection (3), `pending_jobs` projection (3), `unconsumed_events` (3), `mark_job_done` (1), and the `record_source_subscriptions` batch loop (~12 per subscription).
5. The `record_source_subscriptions` path is the only hot-but-bypassed path — it runs only when `compact_sources` is `None` (in-memory mode). The `insert_node`/`insert_edge` pair fires per subscription declaration; `insert_job`/`mark_job_done` fire per dirty wake. These are warm, not per-file-line hot paths; a bench should show measurable improvement only under high rule-fire throughput (hundreds of subscriptions per tick).

## Phase 3: Per-Option Ranking

### Option A: Parameterize by `I: NodeId`

Add to effect_runtime:

```rust
pub trait NodeId: Clone + Eq + Hash + Default + std::fmt::Display {}
// ^ Display is used for row.set() which takes &str
// Or: into &str via AsRef<str>

impl NodeId for String {}
impl NodeId for u64 {}   // StringId is a u64 newtype

pub struct FactRuntimeGraph<R: Row, I: NodeId = String> { ... }

pub struct RuntimeNode<I: NodeId = String> {
    pub node_id: I,
    pub kind_id: I,
    ...
}
```

v4 uses `FactRuntimeGraph<Cursor, u64>` (or wraps `StringId`). The `row.set()` calls inside the core need `I: AsRef<str>`. That requires `to_string()` once inside core, not at the boundary, unless we make `NodeId: AsRef<str>` impossible for `u64` — so this needs `I: Display` or `I: Into<Cow<str>>`.

**Fundamental tension:** `Row::set(&str col, &str val)` requires a `&str` at the storage layer. The conversion must happen somewhere. If `I = u64`, the core still calls `u64::to_string()` internally to write to the row. This moves the allocation from the boundary into the core — same allocation count, different location. The win is eliminating the `parse::<u64>()` in projections by storing `I` directly in the return structs.

| Metric | Value |
|--------|-------|
| LOC added to effect_runtime | ~60 (trait + 5 generic struct impls + type aliases) |
| LOC removed from v4 | ~80 (`to_string()` + `parse()` call sites + bridge locals) |
| Net delta | -20 LOC |
| Backward compat for v3 | `FactRuntimeGraph<R>` = `FactRuntimeGraph<R, String>` via default — unchanged |
| MemFactStore test updates | None — default type param keeps tests identical |
| Generic surface bloat | Low: one trait, default param hides it from simple callers |
| Eliminates `parse::<u64>()` calls | Yes — 13 sites gone |
| Eliminates `to_string()` in struct construction | No — moved into generic impl inside core |
| Eliminates `to_string()` in query arg positions | No — `Row::set(&str)` still requires conversion |

**Actual allocation savings from Option A:** eliminates ~13 `parse::<u64>()` calls per projection (cold decoding), and eliminates ~27 heap allocations in struct construction paths by substituting `u64` copy semantics. The `to_string()` calls feeding `row.set()` move inside the generic impl and remain present.

### Option C: Make StringId implement everything core needs

`StringId` adds `impl AsRef<str>` (formatting as its decimal u64). Core keeps `String`, v4 passes `StringId` where `impl Into<String>` or `impl AsRef<str>` is accepted.

| Metric | Value |
|--------|-------|
| LOC added to effect_runtime | 0 |
| LOC added to v4 (StringId impls) | ~15 |
| LOC removed from v4 | ~0 — boundary sites stay because structs return `String` |
| Eliminates parse() | No — `RuntimeJob.job_id: String` still returned, still needs `parse::<u64>()` |
| Backward compat | Trivial |

This only eliminates conversions on the input side of the boundary (`.0.to_string()` → direct pass). Projection sites (`pending_jobs`, `unconsumed_events`, `run_to_quiescence` callback) still parse. Partial win of roughly 27 `to_string()` calls, none of the 13 `parse()` calls.

---

### Option D: Don't fix it

**Quantifying the cost:**

Each `to_string()` on a `u64` allocates a heap string of ~1–20 bytes. At a warm allocation rate these are cheap but not free.

Path frequency analysis from callers:
- `declare_owner` / `declare_source` / `declare_row` / `insert_edge` / `subscribe`: called once per subscription declaration (startup/invalidation). Not on the per-match inner loop.
- `insert_job` / `mark_job_done` / `pending_jobs` / `run_to_quiescence`: called once per dirty-wake cycle per subscribed owner. With N files × M rules, this is O(N×M) per tick — can be thousands at scale.
- `incoming_subscribers` (site 17–18): called on every `dispatch_wake`. This is the hottest site: each wake scans all subscribe edges and does `source_id.0.to_string()` for the filter arg, plus `edge.from_id.parse::<u64>()` per result edge.

**Estimating impact:** At 500 files × 10 rules × 2 subscriptions each = 10,000 `insert_job` calls per full tick, each paying ~7 `to_string()` allocations. That is 70,000 temporary String heap allocations per full tick from struct construction alone, plus 30,000 `parse::<u64>()` calls from projections.

Under `v4-bench linux-join.sprf` (filesystem source, ~50–500 files), this is likely sub-1ms compared to parse/match time. At 500-repo scale (the target from `sprf-dd-memory-tiering-500`), with incremental ticks firing small deltas, the conversion overhead becomes more visible relative to a mostly-idle main loop.

**Verdict for D:** Deferrable but not ignorable at 500-repo polyglot scale. The `incoming_subscribers` path (hot, per-wake) is the credible benchmark target.

### After (Option A)

In effect_runtime — new trait and generic struct:
```rust
// v3/crates/effect_runtime/src/v2/runtime_graph.rs

pub trait NodeId: Clone + Eq + Hash + Default
    + for<'a> From<&'a str>   // construction from row read
    + AsRef<str>               // writing to row.set()
{}

impl NodeId for String {}      // existing callers unchanged

// u64 NodeId impl (lives in v4, not in effect_runtime)
// effect_runtime stays unaware of u64; v4 provides the impl

pub struct RuntimeEdge<I: NodeId = String> {
    pub edge_id: I,
    pub kind_id: I,
    pub from_id: I,
    pub to_id: I,
    pub label_id: I,
    pub generation: u64,
}

// FactRuntimeGraph gains a second type param:
pub struct FactRuntimeGraph<R: Row, I: NodeId = String> {
    facts: Arc<dyn FactStore<R>>,
    _id: PhantomData<fn() -> I>,
}

impl<R: Row, I: NodeId> FactRuntimeGraph<R, I> {
    pub fn insert_edge(&self, edge: RuntimeEdge<I>) {
        if self.has_row(RUNTIME_EDGE, EDGE_ID, edge.edge_id.as_ref()) {
            return;
        }
        let mut row = R::default();
        row.set(EDGE_ID, edge.edge_id.as_ref());   // AsRef<str> — one conversion inside
        row.set(EDGE_KIND_ID, edge.kind_id.as_ref());
        row.set(FROM_ID, edge.from_id.as_ref());
        row.set(TO_ID, edge.to_id.as_ref());
        row.set(LABEL_ID, edge.label_id.as_ref());
        row.set(GENERATION, edge.generation.to_string().as_str()); // generation still needs format
        self.facts.insert_batch(RUNTIME_EDGE, vec![Arc::new(row)]);
    }
    // edges_where returns Vec<RuntimeEdge<I>> — I constructed from row.get() via I::from(&str)
}
```

In v4 — `NodeId for u64` (or thin StringId wrapper):
```rust
// v4/src/runtime_graph.rs  (new impl block, ~15 LOC)

impl effect_runtime::v2::NodeId for u64 {}

impl AsRef<str> for u64 {  // can't — foreign trait on foreign type
    // Problem: AsRef<str> cannot be implemented for u64 (orphan rule)
```

**Orphan rule blocker:** `AsRef<str>` and `u64` are both foreign. This forces a newtype. `StringId` is already a `u64` newtype — it can implement `AsRef<str>` via `Display` if we carry a scratch buffer, but `AsRef<str>` returns a reference so it cannot be derived from a computed format without internal storage.

**Revised approach for Option A:** Use a trait with an owned method instead of `AsRef<str>`:

```rust
pub trait NodeId: Clone + Eq + Hash + Default {
    fn as_id_str(&self) -> std::borrow::Cow<'_, str>;
    fn from_id_str(s: &str) -> Self;
}

impl NodeId for String {
    fn as_id_str(&self) -> Cow<'_, str> { Cow::Borrowed(self.as_str()) }
    fn from_id_str(s: &str) -> Self { s.to_string() }
}

impl NodeId for u64 {
    fn as_id_str(&self) -> Cow<'_, str> { Cow::Owned(self.to_string()) }
    fn from_id_str(s: &str) -> Self { s.parse().unwrap_or(0) }
}
```

For `String` (v3 consumers): `as_id_str()` returns `Cow::Borrowed` — zero allocation.  
For `u64` (v4): `as_id_str()` returns `Cow::Owned` — one allocation per field write. Same as current. But `from_id_str` in projections replaces `parse::<u64>()?.ok()` scattered at every call site.

The net gain:
- Input side: **no change** — `u64::as_id_str()` still allocates once per field write inside core
- Projection/return side: **eliminated** — `RuntimeEdge<u64>` returned directly, `edge.from_id` is already a `u64`, no `parse()`

So Option A eliminates 13 `parse::<u64>()` calls (avoiding parse failure handling, improving readability) but preserves the 27 `to_string()` allocations inside core for writes. The write-side allocations move from the public boundary into the generic impl — same total count.

**Revised cost table for Option A (realistic):**

| Cost | Before | After |
|------|--------|-------|
| `to_string()` allocations (struct construction) | 27 at boundary | 27 inside core impl |
| `parse::<u64>()` calls (projection) | 13 at boundary | 0 (fields typed as `u64`) |
| Net allocation reduction | 0 (writes) + 13 (parse elim) | |

## Phase 5: Migration Order

### Slice 1 (smallest, reversible): Add `NodeId` trait to effect_runtime

Changes in effect_runtime only:
1. Add `pub trait NodeId` with `as_id_str`, `from_id_str` (7 LOC)
2. Add `impl NodeId for String` (6 LOC)
3. Add second type param `I: NodeId = String` to `FactRuntimeGraph` (1 LOC + `PhantomData`)
4. Parameterize `RuntimeJob`, `RuntimeEvent`, `RuntimeContinuation` ID fields with `I` (15 LOC)
5. Update method impls to call `as_id_str()` instead of `.as_str()` (25 LOC churn)

**All existing tests pass unchanged** — `FactRuntimeGraph<LabCursor>` resolves to `FactRuntimeGraph<LabCursor, String>` via default. `RuntimeJob { job_id: "owner".into() }` still works.

### Slice 2: Add `NodeId for u64` in v4 + wire `FactRuntimeGraph<Cursor, u64>`

Changes in v4 only:
1. Add `impl effect_runtime::v2::NodeId for u64` (8 LOC)
2. Change `core: FactRuntimeGraph<Cursor>` to `core: FactRuntimeGraph<Cursor, u64>` (2 LOC)
3. Update struct construction to pass `u64` directly instead of `StringId.0.to_string()` (remove ~27 `to_string()` calls from struct-building sites)
4. Update projection sites to receive `u64` fields, wrap with `StringId(field)` (simplify 13 `parse()` sites)

**Test impact in v4:** `v3_effect_runtime_v2_fact_store` dev-dependency uses `MemFactStore<Cursor>` — the test helper in `v4/crates/v3_effect_runtime_v2_fact_store`. These tests construct `FactRuntimeGraph<Cursor>`, not `<Cursor, u64>`. No changes needed — default type param.

### Slice 3 (optional): Parameterize remaining structs

`RuntimeNode` and `RuntimeEdge` still have `String` fields for non-ID data (`input_key`, `source_key`). These are not `NodeId` values; they hold hashes and key strings. Leave them as `String`.

### Bench verification

`v4/bench/linux-join.sprf` via `cargo run --release --bin v4-bench`:
- With 50-file fixture: boundary cost is noise vs parse+match; delta will be sub-0.5ms → not measurable
- With 500-file fixture (if available) or forced high rule-density test: delta should be measurable
- The `incoming_subscribers` path (per-wake, does 2 `to_string()` + N `parse()`) is the credible target for `perf record` or `cargo-flamegraph`

**Expected benchmark result:** At linux-join with 50 files, likely `<0.5%` wall_ms improvement. At synthetic 500-file multi-rule bench, plausibly `1–3%` on the runtime-graph phase. Not compelling on its own, but the correctness property (eliminating infallible `parse().ok()?` with silent discard) is the primary motivation.

## Summary

**Top recommendation: Option A**  
**Estimated LOC delta:** +65 in effect_runtime, -40 in v4 (gross), net ~+25 before the v4 `parse()` elimination cleanup makes it net negative  
**Bench delta:** sub-1% on current bench fixtures; measurable only at high rule-fan-out load  
**Compat risk:** None — default type param preserves existing v3 and effect_runtime test consumers

The primary win of Option A is not raw throughput but correctness at the boundary: replacing 13 sites of `some_string.parse::<u64>().ok()?` (silent discard on malformed data) with zero-parse `RuntimeJob<u64>` field access. That removes a class of silent failure and eliminates the implicit invariant that "every ID in core was placed there by v4 and will round-trip through `u64::to_string()` / `u64::parse()`".
