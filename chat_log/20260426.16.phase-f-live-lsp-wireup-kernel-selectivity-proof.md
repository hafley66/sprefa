## Key Insights
- Phase F primitives are correct as designed; only the live binary was missing
- Cache key per op is blake3(batch_fingerprint || op.cache_key). repo/rev have identical input batches across pipes so they cache-hit cross-pipe; fs differs per glob so it caches per-pipe; ast differs per input batch (different file) so caches per-pipe
- Reverse-index is keyed by OUTPUT batch leaf coords, not INPUT. So an ast op that emitted zero cursors (e.g. acct.c lacks printk) does NOT reverse-index — only the fs entry does
- For multi-pipe selectivity demos, predicted eviction count is hard to derive in shell because it depends on whether op.pipe emitted cursors; safer to use shape-based assertions (shrink>0, shrink<total, survivors >= half, log naming)
- LSP only drains the focused pipe's prefix [0..=focus_step] per hover; populating N pipes' cache requires N hovers
- Watcher canonicalizes through symlinks: spawn_fs_watcher took root=v3/tests/smoke/.fixtures/linux and emitted events under /v2/tests/smoke/.fixtures/linux. Eviction works because cursor.fs is repo-relative (kernel/acct.c) and the watcher strips its canonical root prefix; both ends agree on the relative path
- ast pattern grammar is strict: `${$$$VAR}` is rejected; correct form is `$$${VAR}` with the $$$ outside the carveout
- glob `kernel/*.c` is non-recursive in current impl; **/*.c needed for subdirs (deferred Phase F.2 issue notwithstanding)
- Watcher cleanup ordering still load-bearing: drop watchers before subject (they hold Sender clones) and use abort() not await on the drain task. Backend Drop impl handles this via _drain.abort()
