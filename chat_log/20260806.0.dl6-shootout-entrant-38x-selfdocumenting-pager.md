## Problem/Context
**Two defects, both invisible to every existing gate.**

(1) THE CLOSURE WAS NAIVE, one day old. e3997cec (committed 23:55 the night before) added the
in-tick closure loop for correctness. Each round re-ran the emitted delta insert, which reads
`__frontier_<rel>` under `_phase >= 0` — a filter that admits every row ever staged — and nothing
retired the frontier between rounds. So round N re-read everything rounds 1..N produced. Measured
on a 22x22 grid: round 1 derives 924 rows in 1.1 ms; round 43 derives **0 rows in 87.6 ms**, and
the frontier row count tracks the whole reachable table. W_actual = W_naive = O(k·|R*|·|E|).

(2) EVERY DERIVED ROW ROUND-TRIPPED THROUGH JS. `reconcileRefCountStatement` read deleted and
inserted rows out of `RETURNING`, built one DeltaEvent per row, `JSON.stringify`'d them TWICE
(delta copy + frontier copy), and shipped them back through `json_each`. Then `readBoundary` read
the same rows out again for a tick log nobody consumed.

**Two hypotheses measured and KILLED before the real cause was found:** the JS round trip (V8
cpuprofile put 91.1% self time inside the libsql native call, JSON.stringify sites under 0.1%)
and a missing index on `reachable(target)` (added via a new `--extra-ddl` lever, 3011→3330 ms, a
REGRESSION). EXPLAIN QUERY PLAN did show `SCAN b0`; the scan is real and is not what costs.

**Two false DNFs, both my error.** Gate 3 was called DNF twice and blamed on the engine. The
engine settled all 9,996,213 rows in 30,293 ms and printed it on stderr. The OOM came after, in
the driver's own `SELECT source,target FROM reachable`, holding 10M rows as JS objects to fold the
checksum. One stderr line between the tick and the read made it visible.

## Solution/Approach
**The fix was already emitted.** `supportSql` carries the closure as one `WITH RECURSIVE` CTE;
`retractionGuardSql` only let it run when a delta carried a retraction, so a purely additive tick
fell through to the round loop. `applyLevelsBeforeEdges` now runs `supportSql` once for a head on
a cycle of the level graph.

**level_ref_count_sql went 5 → 9 → 11 statements.** Both RETURNING clauses gone; the delta and
both frontier copies are written by SQL reading the same predicates the head mutation reads. The
two frontier copies carry phase as the ONE bind so they share a prepared shape.

**38.4x faster, 2.7x less memory.**

**d2715e9b's four statement rewrites, each priced on the probe bed first:**
  A shipped 2725 → B antijoin materialized once 2622 → C rowid instead of row_number 2169 →
  D OR IGNORE head fill 2144. The WINDOW FUNCTION cost more than the antijoin (453 vs 103 ms).

**Nested subqueries, measured against a head already holding 1,069,200 rows** (single-tick
benchmarks hide these): refcount UPDATE shipped 1710 / COALESCE-only 1680 / UPDATE..FROM 2092;
antijoin shipped 1621 / LEFT JOIN 1591 / EXCEPT 1693; retraction shipped 36 / partial index 19 /

TAKEN: `COALESCE(sub,0)` (x-(x-c) IS c), LEFT JOIN with null probe, PARTIAL index on
`"__refcount" <= 0`. REJECTED with numbers: UPDATE..FROM, EXCEPT, DELETE..RETURNING (faster but
re-crosses the seam), CTE arm reorder (noise).

**Two index families deleted.** Over 747 emitted modules a query plan chose
`__next_frontier_<rel>_phase` ZERO times and `__departure_frontier_<rel>_phase` ZERO times.
`__delta_<rel>_group` was chosen 2/747 so it stayed. `__delta_<rel>_sign` 747/747, keep.

**RSS answer, phase by phase:** SQLite holds the whole closure across five tables in 247 MB with a

object against ~20 bytes as a btree entry. The memory was never SQLite's.

## Key Insights
- **The fast lowering was already emitted and gated off.** The compiler had written the recursive
  CTE months ago; `retractionGuardSql` only let it run on retraction. 20.8x sitting unused.
- **A correctness fix bought a naive cost the same night.** e3997cec wrapped a loop around a
  statement written to run once. No test could see it because every recursive fixture fed one hop
  per tick.
- **The sweep grades END STATE, so a naive closure grades IDENTICAL.** Only a COUNT against depth
  sees it. Rail: `recursiveClosureCounts.test.ts`, fail-pre-fix 39/59/91 at depths 3/8/16 (slope
  4 per round) against 36/36/36 fixed. Non-vacuity: 6/36/136 rows derived.
- **Window functions can cost more than antijoins.** row_number() OVER () 453 ms vs the NOT EXISTS
  it was wrapping at 103 ms. A rowid scratch table replaced three window sorts.
- **Single-tick benchmarks hide every head-side subquery.** The refcount UPDATE and the antijoin
  measured ~0 from an empty head and ~1.7s from a populated one. Steady state is a different
  measurement and the Rust port needs the steady-state shape.
- **`d2 validate` is parse-only.** Gate with `d2 --layout=elk file.d2 - > /dev/null`. Multiboard
  refuses stdout entirely, so a book needs a real file target.
- **Both `|md ... |` and `|latex ... |` are terminated by pipes in their content** (table pipes,
  absolute-value bars). Use the tilde fence `|~md ... ~|` / `|~latex ... ~|`.
- **Per-container `direction:` is silently ignored by dagre AND elk.** Wrote seven, they did
  nothing, removed them.
- **D2 renders real LaTeX** through MathJax to glyph paths: 659 glyphs over 87 codepoints
  including bigcup, sum, Delta, Theta, subseteq, oplus, circ, setminus.
- **D2 `layers` + `.pdf` is a book** (11 pages), `.pptx` is slides, `steps` + `--animate-interval`
  is one self-playing SVG, and `link: layers."<board>"` makes a clickable index.
- Attributing a batch's wall time across its members invents numbers the driver never measured;
  one atomic batch gets ONE timing, and DL6_BENCH_UNBATCH=1 is the labeled diagnostic that splits
  it (and says so in its own output header).
- The harness rewrites STANDINGS.md from its own BINARY path, not cwd. It clobbered the banked
  ladder twice before bench.sh banked and restored it.
- **A refCount on a RECURSIVE head is not a derivation count.** lower.pl:2486 seeds it
  `SELECT cols, 1` under a `UNION` that already deduped, so it carries presence. Counting
  derivations is the OTHER arm, `counted_ref_count_seed_sql`'s `sum("__refcount") ... GROUP BY`,
  which serves non-recursive heads. Retraction still lands for the recursive case because the CTE
  is a full recompute. Found by expecting a 2 in the toy diamond's column and reading a 1.
- Bench numbers say what a statement COSTS and nothing about what it DOES. The pager runs the
  emitted sequence a second time on a four-edge diamond (1->2->4, 1->3->4, five closure rows) and
  renders the written table either side of every statement. The written table is parsed off each
  statement's own INSERT/DELETE/UPDATE target, so a new statement documents itself.
- Order visible only from that trace: the head is filled LAST, which is why the antijoin against
  it works.
