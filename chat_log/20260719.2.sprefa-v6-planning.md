# Session: sprefa-v6-planning

## Goal
Plan sprefa V6: extract V5's 89,151-line single crate into 7 crates with trait
boundaries, rails, a backend-neutral storage API, one fully-async server, and
cold-by-default (subscription-driven) evaluation. Planning only — first code is
hollow types, human-reviewed before any call site moves. MVP: the ghcacher
service as a served dl program with zero program-specific Rust.

## Current State
Planning complete, docs written, no V6 code. `v6/` contains: README (rules,
rulings, crate map), 5 plans in `v6/plans/`, 2 agent skills in
`v6/.agents/skills/` (v6-plan, v6-deps). Root `AGENTS.md` declares V6 underway.
Base SHA for all arcs: `8d7b6092` (branch `next`). Next step: owner answers the

## Problem/Context
V5 pain, owner's words: same problems re-solved every version; AI whiplash;
rusqlite/SQL diddled across ~40 files; daemon over-complicated by AI; hand-rolled
infra where libraries exist; 89K lines too big. Verified facts: 505 live tables,
only 86 (17%) have repo/rev columns — repo identity smuggled in sym strings;
engine/ is 32,060 lines incl. ~4.9K of storage code (meta/declare/staged_delta/
cold_stage/symbols); 3 JSON-RPC dialects + duplicated in-proc fallbacks
(Pump::Local, in-proc LSP, DL_NO_DAEMON); every client call builds a private
tokio runtime. Owner is RxJS-flavored: BehaviorSubject + combineLatest is the
complexity ceiling; hates DI/crate-per-cell Rust culture; will use any library
or even foreign (Go) tools behind a boundary.

## Solution/Approach
7 crates, deps strictly downward: lang → store → graph, rels → engine → server
→ cli. Ceilings ratchet down only (lang 5.5K, store 9.5K, graph 12.5K, rels
3.7K, engine 26K, server 8.5K, cli 2.5K). Extraction order: lang → store →
graph → rels → engine → server+cli. Five owner rulings recorded in the
crate-map plan: practicality (concrete types until 2nd impl; seam ruling from
.dl/no-new-rusqlite.dl generalized), backend-neutrality (BackendConfig at open,
API names no driver type, sea-query for ALL SQL generation, dialect = config),
demand (rels are cold observables; refcounted (root, query rel) subscription
activates the static dependency cone incl. cross-repo cut; last unsub → cold),
sync/async (server 100% async incl. async StoreHandle w/ reader pool + writer
channel; tick hot path sync; no spawn_blocking per request), file-size law
(pre-existing, extended to crate ceilings). Daemon: one process — axum on UDS +
ephemeral TCP, rmcp StreamableHttpService at /mcp, tower-lsp-server over UDS +
stdio lsp-proxy shim; versioned socket filename deletes both build-mismatch
hacks; anonymous ephemeral servers for one-shots. Language: @in/@out port
classes become an open registry in sprefa-server (http/ws/rpc/lsp/mcp/hook/
clock) — pluggable routes & websockets declared in dl; language changes allowed
but land only in sprefa-lang w/ spec update. Graph: petgraph::Csr snapshots per
(rel, rev); reachability/closure stays in dl (petgraph has none).

## Key Insights
- Ports/effects are ALREADY generic engine-side (src/engine/tick.rs:369-376,
  784-789); only transport serve loops are bespoke Rust. V6 fix = port-class
  registry, one generic serve loop per class shape.
- EffectExec (src/effect.rs) is the effect seam and already multi-impl — the
  "trait on 2nd implementation" rule working as intended.
- sea-query =1.0.1 covers CTEs/windows/upsert/INSERT-SELECT/RETURNING; WITHOUT
  ROWID via .extra(). SKIP sea-query-rusqlite (RC pin + rusqlite 0.38 vs 0.40) —
  write ~40-line Value adapter in-crate.
- rusqlite_migration is append-only but rel_* DDL is generated → hash full
  generated DDL as synthetic step or user_version as schema-hash guard (todo).
- petgraph tarjan_scc is RECURSIVE (stack overflow on deep call graphs at 1M
  edges) — big-stack thread or keep iterative tarjan. No reverse traversal on
  Csr → transposed 2nd Csr. condensation/toposort don't run on Csr → build
  condensation from node_component_index (~5 lines).
- tracing WorkerGuard: drop early = logs silently die. Guards in daemon struct,
  dropped last.
- rmcp 2.2: use rmcp::schemars re-export (schemars 1.0 rewrite); CancellationToken
  or SSE workers outlive shutdown; pin minor, expect churn.
- tower-lsp-server 0.23 (NOT dead tower-lsp): switched to ls-types — import
  tower_lsp_server::ls_types only. lsp-proxy shim = pure copy_bidirectional, no
  LSP crates.
- axum 0.8 UDS traps: remove stale socket pre-bind, chmod 0600 post-bind,
  unlink on shutdown, sun_path ~104B.
- The other AI's census numbers were all verified accurate (wc -l @ 8d7b6092).
- Identified deletions only ~730 lines (0.8%) — ceilings+ratchet are the real
  size control; duplication census is a todo (dogfood dl).
