## Goal
Make the daemon the global rootless serving daemon: ONE singleton (not per-root),
multi-root via config repos, that you load scripts into — either one-time query
scripts (eval, ephemeral) or watched scripts (join the program, reactive). The
payoff: AI writes code → the daemon watches → docs auto-regenerate. Immediate
dogfood: a `gen` rule that keeps the README op table fresh from `parse.rs`.

## Problem/Context
- v5 dl engine, reactive datalog-over-code, SQLite-welded. Daemon model has TWO
  namespaces (daemon.rs:50-61): `Some(root)` → per-root auto-attach at `<root>/.dl`;
  `None` → singleton rootless serving daemon at `$XDG_STATE_HOME/sprefa`. User's
  intent: ONE global rootless daemon (the `None` singleton), multi-root via config
  repos ("folders in view"). NOT per-root (per-root collides).
- The running global daemon was a TRAY daemon (`~/.local/state/sprefa/daemon.sock`,
  tray.log) since Jun 23, but a STALE binary (no `status` RPC) running
  `examples/*.dl` rootless — its scan("WORK") hit empty XGD → "(0 rows)" for 2304
  ticks. Effectively a no-op daemon.
- `gen` runs on every daemon tick (engine.rs:1589 tick / :1853 tick_paths →
  run_gens). NOT suppressed (only --lsp/--check suppress gen). gen converges
  (bytes-match → no write), so gen-writes-watched-file is stable for ONE daemon.
- The divergence was MULTI-daemon collision, confirmed by analysis: a single
  daemon's gen is idempotent by design; two daemons with desync'd engine states
  ping-pong README and the stub-migration 2-tick dance interleaves → growth.

## Solution/Approach
- **op-table.dl**: extract-then-join split (source rule `readme_row_raw` scans +
  matches; derived `readme_op_row` joins block + line-range — source rules can't
  join derived rels, README:108). 4 gen rules into one splice block: header
  (constant), separator (constant), pass-through `{row}` verbatim, stub for
  dispatch ops missing from README (`!readme_op_row(op,_)`). Regex anchored:
  `/if s == "(?<op>\w+)" \{ return self\./` (excludes item keywords), `op != "closure"`.
- **load RPC**: mode=once delegates to existing `run_eval` (throwaway engine,
  daemon.rs:908). mode=watched pushes canon path to `program_files` (dedup) +
  `reload_program()` (re-parses ALL program_files, swaps Program, re-ticks) +
  `save_program_meta`. Client `daemon::load()` sends the RPC. CLI flags +
  print helper.
- **Rootless serving start**: `resolve_programs(...).unwrap_or_default()` tolerates
  empty `.dl/`; empty files → `(Program{items:[]}, [], "<serving>")` skipping
  prepare_paths (which would panic on `paths[0]`, lib.rs:71).

## Key Insights
- **Daemon = global rootless singleton**, NOT per-root. Per-root `.dl/daemon.sock`
  daemons are auto-attach one-shot helpers that COLLIDE with the singleton + each
  other (the divergence root cause). The `None` home (XDG) is the global daemon.
- **gen convergence is per-daemon-idempotent**, NOT cross-daemon. Two daemons
  watching the same file ping-pong. One daemon writing a watched file re-ticks
  → converges (stable). This is why discovery (per-root) diverged but in-process
  + single-daemon would be fine.
- **`touches_program` → respawn (non-tray) / reload (tray)** (daemon.rs:607-621).
  A loaded watched script IS a program file → editing it trips this. For the
  serving daemon (no startup program to respawn from), must be no_respawn=hot-reload.
  Respawn would lose loaded scripts (run_daemon re-resolves from discovery/args,
  NOT from save_program_meta).
- **`scan("WORK")` → single `self.root`** (engine.rs:1690-1719). Rootless daemon's
  self.root = XGD (empty) → WORK scans return nothing. Slug scans
  (`scan("selfv5","WORK",...)`) resolve to config repo roots but only via the FULL
  tick (tick_paths skips non-self paths). So rootless daemon can't reactively scan
  real repos today without #4 + #6.
- **Source rules can't join derived rels** (README:108) — the extract-then-join
  split (readme_row_raw source → readme_op_row derived) is required.
- **gen splice accumulates across rules** into one block (engine.rs:4245, apply at
  :4383 bottom-up, `lines.splice(l0..l1-1, rows)`). Multiple gen rules targeting
  the same (path,l0,l1) concat in program order. ORDER BY all vars → deterministic
  (alphabetical here). Convergence = bytes-match → no write (engine.rs:4402).
- **`match` named groups bind automatically** by name alongside positional line
  (`match(p, rev, /if s == "(?<op>\w+)"/, _)` binds `op`; string-fns.dl:18 precedent).
- **comment op** finds `<!-- BEGIN/END -->` pairs in markdown (marker detection by
  prefix incl `<!--`, README:104). Returns l0/l1 = 1-based marker line numbers.
- **eval RPC** (run_eval, daemon.rs:908) = throwaway engine, splices snippet onto
  d.prog, ticks quiet, returns snippet's `?` queries. Persists nothing. The model
  for `load once`.
