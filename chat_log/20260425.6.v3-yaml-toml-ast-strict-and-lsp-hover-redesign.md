## Solution/Approach

### sprefa-bh5 — ast strict mode
Rejected bare $NAME / $$$NAME at lower-time via `reject_bare_metavars`
pre-scan returning `ast/bare-metavar-illegal`. Deleted `scan_metavars`
(no longer needed). Rewrote `lower_sugar` to handle both single-form
${VAR} (collapses surrounding identifier-char run → $SPRFSLOTN + named
regex) and multi-form ${$$$VAR} (legal only with no identifier-char
neighbours; rewrites to $$$SPRFSLOTN; Synthesized capture from joined
get_multiple_matches). Sub-token multi rejected via
`ast/multi-sub-token-illegal`. Added `multi_slots: Vec<(slot_name,
cap_name)>` to AstGrepOp; pipe() iterates it and emits joined text via
`Capture::synthesized`. Smoke fixture rewritten to strict surface and
green.

### sprefa-8sy — ${NAME?} Unbound suffix
Walker patch: `parse_capture_or_wildcard` strips trailing '?' off the
inner name in the ${...} branch (semantically identical to ${NAME} for
the v0 walker). Same strip in ast `lower_sugar`. Smoke 6 went green
immediately (before the user's later print() edit broke it again).

### sprefa-1vi — yaml/toml + json() ext-dispatch
Ported v2/src/data/_2_yaml.rs and _3_toml.rs to v3/crates/pipeline/src/
data/{yaml,toml}.rs (Arc<Bytes> → Arc<[u8]>; same dig_to_value /
unwrap_node mechanics; toml flat-doc with table-section grouping
preserved as TODO). Extended AnyDataNode with Yaml + Toml variants;
parse_by_ext now dispatches "json" / "yaml"|"yml" / "toml". JsonOp
pipe() inspects cursor.fs extension and routes to the right parser
(falls back to JsonNode when no fs / unknown ext, so inline json()
over content still works). Workspace Cargo.toml gains opt-level=3
profile overrides for the new tree-sitter crates. New smoke
_8_json_toml.sh exercises Cargo.toml end-to-end and is green.

### Hover redesign — per-cursor blocks
Replaced the 8-column table in `render_enriched_hover` with per-cursor
blocks: header line with file:// link first, then `repo@rev` and byte
range, optional match preview as a blockquote, captures as a bullet
list. Each SpanBacked capture wraps its value text in
`file://abs/path#L<line>` pointing at the capture's start line; line
number is computed via `line_of_offset(&c.content, byte_range.start)`.
Synthesized captures (ast multi joins) render inline tagged
`_(synthesized)_`. last_bound and SprfPath only render when populated.
User confirmed this works in their VS Code session.

### sprefa-s81 — Op::term_positions() slot
Added `TermPosition { name: Arc<str>, range: Range<usize> }` and
`fn term_positions(&self) -> &[TermPosition]` (default `&[]`) to the
Op trait. Brace parser's `parse_capture_or_wildcard` and `parse_key`
now record (name, body-relative range) for every $NAME / ${NAME} /
${NAME?} token; `parse_body` returns positions as a third element.
JsonOp lifts them to absolute (paren_origin + body offset) and stores
in a new `term_positions: Arc<[TermPosition]>` field. ast `lower_sugar`
records the full ${...} carveout span per metavar; `lower_ast_paren`
lifts to absolute the same way.

Server side: HoverPlan grew `hover_offset: usize` and PlannedOp grew
`paren_origin: usize`. `lower_plan_keeping_ops` returns both the
Pipeline AND `Vec<Arc<dyn Op>>` so the renderer can call
`term_positions()` on the focus op. Caveat: registry's
build_from_node returns a Box, so the lower path runs build twice per
op (once for the shared Arc view, once for the Pipeline::Op Box).
Synth source is `name(body)` so positions come back relative to that;
a `RebasedOp` wrapper rebases each TermPosition from synth-paren-origin
to host-paren-origin so the renderer sees host-source coordinates.
Renderer resolves focus_capture by checking each TermPosition.range
against hover_offset; when matched, prepends a "Focused capture:"
banner and marks the matching bullet across every cursor row with `▶`
+ bold. New test `json_op_exposes_term_positions_for_brace_captures`
locks the registry path end-to-end.

## Key Insights
- ${NAME?} ≡ ${NAME} at the v0 walker level. The Unbound suffix is a
  declaration-vs-reference marker for the binding graph; the walker
  doesn't need to distinguish.
- Multi-form sub-token capture (${$$$X} adjacent to identifier chars)
  has no defined ast-grep semantics. Reject at lower-time with
  ast/multi-sub-token-illegal rather than emit a confusing pattern.
- For the multi case with no neighbours, emitting native $$$SPRFSLOTN
  + get_multiple_matches → joined Synthesized capture is the most
  faithful translation of the v2 OR-form intent.
- json() ext-dispatch via cursor.fs.extension() keeps the brace
  pattern grammar uniform across formats. JSON fallback when no fs
  preserves the inline-content use case.
- The 8-column hover table escape problem disappears when each row
  becomes a per-cursor block: blockquote for the match preview avoids
  pipe-cell escape, bullet captures avoid joining with commas, and
  conditional last_bound / SprfPath drop the empty noise.
- file://abs/path#L<line> links inside markdown work in VS Code's
  hover popup; the user confirmed it lands on the right file at the
  right line.
- term_positions absolute coordinates require careful re-basing
  through the synth lower path. Keeping the wrapper inside the
  renderer (RebasedOp) localizes the gymnastics.
- Print op accepts only literal Str/Atom — needs a separate spike if
  we want `print($N)` to actually print bound capture text.
