## Solution / Approach

### String-shaped registry keeps pipeline parse-agnostic

Factory signature `Fn(&str, &str) -> Result<Box<dyn Op>>` takes
`(op_name, paren_body)` not `&OpInvocation`. `sprefa_parse` is not a
Cargo dep of `pipeline` (§1.6 invariant). Drivers extract paren body
from the CST node and dispatch.

### Comment op is NOT a pattern op yet

v2 `marker` had no sub-grammar either. v3 lands it as a single-file op
under `ops/comment.rs` with ad-hoc top-level comma split + regex
compile. A future `comment` tree-sitter sub-grammar can drop in without
changing the public surface (arg_spec stays `[Str]`).

### PrintSink enum beats Arc<dyn Fn>

Enum `PrintSink::Stdout | Buffer(Arc<Mutex<Vec<String>>>)` keeps
`PrintBatcher: Clone + Send + Sync` without wrapping every call in a
trait object. Tests use `PrintBatcher::buffer()` for captured output.

### Backend owns one Registry shared by every DocSession

Construction happens once at `Backend::new()`. `DocSession::new` takes
a `Registry` clone (cheap Arc inside). Per-URI sessions share doc
lookups with zero duplication.

### Hover walks host CST, stops at op-name

Innermost descendant at offset → ascend to `op_invocation` →
`child_by_field_name("name")` → registry doc. Injected-body hover (per
§14.6) is the next step; requires reaching `InjectedTree` by
`host_node.byte_range` and dispatching to `PatternOp::hover_match`.
Framework pieces are in place.

## Key Insights

1. **Registry string-shape pays off immediately.** No `sprefa_parse`
   dep in `pipeline`, no friction adding new ops. Factory registration
   lines read like a directory. Two consumers (sprefa-run CLI + LSP
   Backend) share one registry construction.

2. **`PrintSink` as enum > Arc<dyn Fn>.** Keeps `PrintBatcher: Clone
   + Send + Sync` without boilerplate and gives tests a
   zero-redirection path to observe output. Pattern generalizes to
   future write effects.

3. **Ops own effect domain names; effect runtime stays neutral.**
   `pipeline::effects` is the seam; `effect_runtime` has zero
   domain-specific types. This matches §2.1 (ops own everything) and
   made the "which crate do I put this in" question self-answering.

4. **Content contract bites early.** comment+print can't run end-to-
   end without a `read` op. Unit tests cover each op independently;
   integration smoke is session-2 work. Good to surface rather than
   fake it with a fixture that would only "accidentally work."

5. **Hook noise ≠ hook blocking.** Every Write/Edit triggered
   `No SEMGREP_APP_TOKEN found` trace but writes committed (verified
   by each subsequent compile passing). Same pattern as the prior
   session's log.

## Open Questions

1. **Registry crate location revisited.** Locked as `pipeline::registry`
   with string-shaped factory. Future: does the LSP want a richer
   factory that also returns metadata (expected slot count, sub-
   grammar kind) without building the op? Currently metadata comes
   from Op trait methods after building.

2. **`comment` grammar.** Should the paren body eventually get a
   sub-grammar? Simplest shape: two comma-separated regex slots with
   `re`'s existing grammar as the body language. Lands when a real
   need appears (e.g., regex highlighting inside `comment(...)`).

3. **WriteFileEffect authorship.** Which op drives the first write?
   Candidates: `write_file($PATH)` (simplest), `render_into_marker`
   (§32 transclusion), `append($PATH)`. Pick before writing the
   batcher.

4. **MutationEffect §25 approval UX.** Auto-approve vs prompt.
   Default should be auto-approve in sprefa-run CLI and prompt via
   LSP code-actions. Same effect, different gate.

5. **`read` op vs auto-load on `fs` bind.** Two shapes: explicit
   `> fs(**/*.rs) > read()` OR implicit `fs($P)` loads bytes into
   content. Explicit is clearer but adds one step. V2 had explicit
   `read`.

6. **Label-capture fallback correctness.** Current synthesizes
   label from trimmed post-match tail when no named group exists.
   V2 behavior — preserved. Open: should it bind to
   `last_bound` slot as well, so `comment > is_section_label($L)`
   works without naming?
