## Solution/Approach
SCIP cost IS per-rev (indexer = full semantic pass; no incremental-SCIP format).
Lever = content-address by commit OID (index = f(OID), share across worktrees).
Reframe for AI parallelism (RECOMMENDED combo, sequence 1->4->2):
  1. Base-OID shared cache (~/.cache/sprefa/scip/<oid>.scip): N worktrees off one
     base = 1 cost. Trigger reindex on daemon `rev_advanced`. No indexer changes.
  2. dl as LSP CLIENT to warm rust-analyzer/tsserver = the TRUE incremental
     oracle (salsa/incremental program); batch `rust-analyzer scip` throws that
     away. Best for high edit rate.
  3. Partial reindex + per-Document merge (needs indexer cooperation) - skip.
  4. Per-Document content-addressed SCIP INGESTION in dl (key scip_def/scip_ref
     by (file,content-hash), retract per file like other source rels) = highest-
     leverage dl-native change, unblocks 1 & 3.
Key enabler: SCIP monikers are STRUCTURAL (descriptor paths), so body edits ripple
only that Document; API edits ripple along module_edge (dl HAS this graph) =>
bounded blast radius = reverse-import-closure(changed file).
Running scip: dl has cmd op + sh/@async effect runtime + head/rev_advanced; option
B = config-driven `scip="scip-typescript index"` per repo, auto-run keyed to OID
cache. Don't BUNDLE indexers (npm/JDK/binaries), shell what's installed.
Dynamic skills = gen-skill.dl emitting SKILL.md from target repo's type_entity/
call_def/rel_catalog, daemon-regenerated (same gen machinery, skill output path).
