## Problem / Context
User articulated desired semantic: rx combineLatest. `${base_rule.$TAG}` in `derived_rule`:
- Unbound VAR (new name in derived_rule) → own-capture rebind, no filter
- Bound VAR (declared in target) → forward join/filter
- Each input cursor × each target value produces one output cursor
- If target value set is empty → combineLatest gate closed, zero cursors emitted, Hint diag at xref byte range

Same machinery should cover $$repo / $$rev provenance. User's self-correction: both xref and provenance are runtime-late-bound (value set unknown until upstream runs). DAG is the static skeleton; values fill in at runtime per-cursor.

Needs common code because cross-ref is default syntax for all ops. Walker had to relearn it; host parser had to relearn it; ops shouldn't have to.

## Solution / Approach (plan)

### Layer 0 — SlotRef representation
- New `SlotRef` enum in `_0_types.rs`:
  ```rust
  enum SlotRef { Literal(Arc<str>), Capture(Arc<str>), CrossRef { rule, var, site: Arc<ParseSite> } }
  ```
- `_8_parse.rs` adds `parsed_slots: Vec<SlotRef>` on OpInvocation alongside raw `src`.
- `walk/_4_brace_parse.rs` adds `SelectStep::CrossRef { rule, var, site }`. `walk/_2_compile.rs` passes through as `CompiledStep::CrossRef`.
- Covers scalar slots, LeafPattern position, key position.

### Layer 1 — rule DAG
- Scan parsed_slots + walker CrossRef across every rule's invs at lower time. Edge `rule → target`. Store in `ProgramCtx.rule_deps: HashMap<Arc<str>, HashSet<Arc<str>>>`.
- Parse-time diag `xref/cycle` (Kahn sort fail).
- Runner consumes topo order; independent rules parallel (tokio), cross-refed ones block deps.

### Layer 2 — combineLatest expansion adapter
- New stream adapter in `_5_op.rs`, applied in `Pipeline::run_with_step` before `op.pipe`:
  ```rust
  fn expand_xrefs(input, ctx, op) -> BoxStream<Cursor>
  ```
- For each input cursor, gather op's CrossRef slots. For each `{rule, var}`:
  - Look up `ctx.result_store.cursors_by_rule[rule]`
  - Extract distinct values of var
  - Cartesian-product: one output cursor per combination
  - Pre-seed `cursor.captures[var] = value` before handing downstream
- Downstream op unchanged. Walker LeafPattern already handles pre-bound-as-constraint + unbound-as-capture via existing `leaf_pattern_constrains_with_prebound_capture` path.

### Layer 3 — empty-join diag
- During expansion, if any CrossRef's target value set is empty:
  - Hint `xref/empty-join` at the slot's byte_range
  - Message: ``` `${target}.$VAR` has produced no values — this reference contributes 0 cursors (combineLatest gate) ```
- Cursor dropped (zero cartesian). One Hint per (rule, ref_site) dedup to avoid per-cursor flood.
- Rule-level roll-up: rule emits zero rows AND xrefs hit empty-join → Warn at rule name site: ``` rule `derived_rule` produced no rows because `base_rule.$TAG` was empty ```. Kills cascade noise.

### Layer 4 — $$repo / $$rev provenance
- `SlotRef::Provenance { kind: RepoOrRev, norm: bool }` — same expansion hook.
- Values read from `c.repo` / `c.rev` at expansion time instead of ResultStore.
- Same pre-seed path.

### Layer 5 — OpCtx wiring
- Add `result_store: Arc<ResultStore>` to OpCtx.
- ResultStore = thread-safe `cursors_by_rule` populated by runner as each rule finishes.
- DocSession already has this map; promote to own struct, share via Arc.
- Extend parse-time xref/unknown-capture to walker SlotRef refs (today only catches paren-slot refs).

### Layer 6 — shared code
- Common adapter = one function in `_5_op.rs`. Every op inherits xref + provenance for free.
- Walker: one new CompiledStep handler (pre-bound Capture check already exists).
- Zero per-op code growth.

## Key Insights
- Cross-ref is UNIVERSAL syntax, not json-specific. Needs a framework adapter, not N per-op impls. That's the whole payoff.
- combineLatest is the right mental model: cursor × each ref's distinct value set = cartesian-product. All refs must produce ≥1 value or the gate closes.
- DAG gives static skeleton (topo order). Value sets fill in at runtime. Same for $$repo/$$rev — user's observation that both are late-bound is correct; the DAG only schedules when you look, not what values arrive.
- The `leaf_pattern_constrains_with_prebound_capture` test was the existing hook. Walker already does bound-as-constraint / unbound-as-capture — framework just needs to seed the map before op.pipe runs.
- Empty-join diag at byte_range is key UX. Without it, derived_rule silently emits nothing and user can't tell which ref killed the join.

## Open Questions
- ResultStore lifecycle: in LSP (DocSession) vs CLI runner, who owns it? Probably a trait + two impls.
- Fork arms and xrefs: if one arm of a Fork has xrefs and the other doesn't, does expansion happen per-arm or before the fork? Probably per-arm (each arm is independent pipeline).
- Ordering of pre-seed vs framework evidence push: seed must happen before op.pipe, evidence push after. Straightforward but pin it down when coding.
- `${target.$KEY}` in walker KEY position (not value): key matching uses different machinery (KeyMatcher). Needs its own seed path or lower to KeyMatcher::Capture with pre-bound text.
