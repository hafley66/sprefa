## Solution/Approach

### Table design (v6-table-design.md + v6-schema.sql)
- Surrogate spine, no hashed ids: repo, rev, file, blob, rev_file, str, dir, worktree, tree/tree_entry/rev_root, rev_parent
- NO `REFERENCES` clauses (user ruling); `_id` suffix is the contract, orphan-scan rail checks
- Composite PKs where genuinely composite, all WITHOUT ROWID; surrogate only where something points at the row
- **Nodes key on blob_id** (extraction is a pure function of content, so identical bytes anywhere share one node set); **edges key on rev_id** (resolution depends on the file set)
- Dirs recurse, files do NOT (globs must never walk the 1M-row table)
- Files owned by nothing; repo membership = ancestry; `worktree` first-class; WORK is `rev.kind = 1`
- `file_head` holds mutable state so `file` is never UPDATEd
- History stored git-shaped (tree/tree_entry content-addressed); `rev_file` materialized ONLY for subscribed revs (else rows = revs x files = 200M)
- Z-set `weight INTEGER` column: retraction is subtraction, no separate code path, no DRed
- Tier is SYNTAX not policy: `rel foo(...) save.` Default transient (in-memory for the subscription's life)
- `trace_dep` (dense rel ids, WITHOUT ROWID, 8-byte digest) read DOWN for demand cone, UP for wake set
- `subscription` table: refcount is COUNT(*), never a stored counter
- Views cover the awkward normalizations: v_dir, v_file, v_rev, v_rev_ancestor, v_work, v_demand, v_cone, v_wake, v_why_computing

### Inter-crate math (v6-delivery.md)
- Two extraction shapes, kept as TWO traits because the CACHE KEY differs: `FileExtract` (pure, key = blob_hash) and `ProjectExtract` (key = blob_hash + project_digest)
- The typed core ALREADY EXISTS in v5: `TypeLang` (typegraph/mod.rs:417) and `ModuleResolver` (modgraph/mod.rs:171). `AnalysisMask`/`AnalysisBundle` is already the demand cone at extraction level. `ProjectCx.reader` closure is already the IO seam.
- Crate ceilings: lang 5.5K, store 9.5K, extract 16.8K, graph 1K, rels 3.7K, engine 23K, server 8.5K, cli 2.5K
- Slices 0-2 are ADDITIVE (parallel store + importer, V5 keeps shipping); both falsifiable claims answered by end of slice 3

## Key Insights

### Graph libraries: measured, five labs
- **petgraph**: `tarjan_scc` IS recursive (src/algo/scc/tarjan_scc.rs:96, doc says so twice), crashes at N=74,529 on default stack, needs ~108MB for 1M. `depth_first_search` (the halt-predicate mechanism) is ALSO recursive and crashes EARLIER at ~43,500, 192.6 bytes/node. `kosaraju_scc` is iterative and safe (22ms at 1M) but does NOT compile against `Csr` (needs IntoNeighborsDirected, E0277). Csr 17.4 bytes/edge vs Vec<Vec<u32>> 42.5. `from_sorted_edges` 6ms vs `add_edge` 120.4 SECONDS per 1M. GitHub #399 closed as by-design 2021; #727 still open.
- **ultragraph**: REJECTED. `freeze()` copies (preallocates 4 vecs at full size before consuming old lists), peak RSS 1.85x stable across scales -> ~21GB at 130M on a 16GB machine. Real dual-CSR, `inbound_edges` is a true transposed index (0.0ms over 2M calls on a 0-in-degree node). SCC iterative, 34.2ms at 1M. Bus factor: 4,193 commits by one account vs three humans at 1 each.
- **GraphBLAS**: masks DO express "reach but don't expand" (naive {1,2,3} vs halt-aware {1,2}), no stack at all. BUT both Rust bindings are CC-BY-NC-4.0 (LICENSE files byte-identical via diff); C lib is Apache-2.0; pathrex-sys is MIT but too narrow; a from-scratch binding is 27-30 FFI declarations. TRAP: `GrB_Vector_assign` with no mask/ALL/no REPLACE SILENTLY DELETES prior entries; fix is LogicalOr eWiseAdd. Transpose descriptor 12-23x faster than a materialized reused transpose (unexplained).
- **SQLite (THE WINNER)**: plain `WITH RECURSIVE` CTEs cover 4 of 7 ops (reaches_from, reached_by, multi_source_walk, multi_source_halt_bfs), SUB-MILLISECOND on the real 261,704-edge table, ZERO dependencies. Halt predicate = WHERE clause on the recursive term, verified against ALL 7 of walk.rs's own tests. Reproduced `rel_port_reach` BYTE-FOR-BYTE across 10 ports incl 22,601 rows. Same pattern already ships in `.dl/flow-panel.dl`.
- SCC, build_condensed, count_pairs STAY in Rust. Our iterative tarjan handles 283,127 nodes where petgraph's dies at 74,529.

### The CTE traps (measured)
- Dedup key decides termination: 363-node reachable set converges in 6ms deduped on node alone; SAME set deduped on `(node, depth)` gives 12,802 rows by depth 200 and keeps growing. Code graphs are cyclic, so a depth column is a termination hazard.
- `count(*)` over a depth-capped CTE over-counts multi-path nodes: 311 rows vs 291 distinct at depth 3.
- No merge-by-key: `multi_source_walk` needs min-depth-wins, plain UNION keeps every depth. DuckDB's `USING KEY` (1.5.0) closes exactly this gap.
- A seeded CTE costs what it REACHES, not what the table holds: `rel_df_edge` is WITHOUT ROWID with PK (from,to), so the recursive join is a PK prefix seek. Table growth costs a logarithm, not 500x.

### Dead ends found by checking rather than assuming
- `ext/misc/closure.c` is DEAD CODE: its own header says "Experimental and obsolete", and `sqlite3_closure_init` gates `sqlite3_create_module` behind `#if defined(SQLITE_TEST)`. Confirmed empirically (loads silently, does nothing).
- Kuzu (embedded graph DB, Cypher, 4,014 stars) is ARCHIVED, last push 2025-10-10.
- CozoDB (embeddable Rust datalog+graph, closest match to sprefa's model) STALLED: last push 2024-12-04, unanswered "is cozo still maintained?" thread with ten candle-emoji replies.
- graphqlite builds and works (`RETURN scc()` verified) but creates its own 14-table property-graph schema on load = ETL migration, not a query layer. macOS Bison 2.3 cannot build its grammar.
- igraph is GPL-2.0 (distribution blocker for a shipped tool).
- SNAP last pushed 2023-12-10.

### Process lessons
- I asserted library capabilities from documentation prose and was WRONG three times (petgraph predicate traversal, petgraph reverse traversal, "no library has halt predicates"). Source code and running tests are evidence; docs prose is not.
- Launched 7 agents at once each targeting 100M-edge graphs on a 16GB machine and made it swap. Own standing law: "nothing seizes the machine". Requeued at 3 concurrent, 10M-edge cap, ~2GB RSS budget, vm_stat check before large allocations.
- LICENSE must be read from the actual file, never package metadata: a permissive C library reached through a NonCommercial binding is still NonCommercial. License text also varies across releases of the same project.
