## Problem/Context
v1 did write-time provenance stamp + external demand-scan driver (`unscanned_repos/revs/pairs`). v2 inherits forward-pass stamp but must run the discovery loop *inside* the runner since walker captures can claim new repos content-side. Tri state needed for streaming soundness (can't drop Missing rows mid-pass; scan set still growing).

## Solution/Approach
Shared ResultStore hoisted up in `ensure_run`. Closure passed into `run_scan_loop` re-builds pipelines' OpCtx each pass with updated Config. `store.clear()` between passes so stamps reflect latest Config generation. Only final pass's cursors + diags kept.

## Key Insights
- **Shotgun surgery fix = builder pattern.** Adding Capture fields nuked 13 call sites. Introducing `Capture::new(v) / with_*` collapsed them to 0. Rule: when a struct has >3 call sites, construct via fn; pub fields for reads only.
- **Check fn should take `&` not `&mut`.** Interior-mutable Mutex fields make `&mut` artificial; blocks wiring into Arc-shared store. Fix was one-line.
- **Loop algo: clear + rerun + compare Config size.** Not a seen-set. Fixed-point on Config not growing is simpler than tracking what claims have been seen. Extending with same values is dedup'd by the `!any(==)` check.
- **fs doesn't grow config.** Only repo/rev sigils extend Config. fs Missing stays Missing; runner doesn't synthesize fs paths into a known set.
- **Diamond test shape**: all rev sigils naming each other converge in 2 passes; no special-case handling needed. User said "many git tag pointers from deploy or diamond chaining" — covered by rev-only sigils rather than mixing in cross-repo tags.
- **No git stash to triage.** User rejected stash as a way to confirm a failure pre-existed the branch. Policy saved to memory as `feedback_no_stash_solve`.
- **Stop looping on same trace.** User called out back-and-forth reading of the same failing-test output. Eprintln added, trace read, **escalate or escape after 2 iterations of same signal.** Should have handed off to agent with sem MCP far earlier instead of drilling myself.
- **sem MCP exists** for fast entity-level orientation (`sem_entities`, `sem_context`, `sem_impact`, `sem_log`, `sem_blame`). Use for big-codebase triage instead of grep-bashing.
- **ensure_run closure must capture by reference, not clone.** `Vec<(Arc<str>, Pipeline)>` isn't Clone because `Pipeline` isn't Clone. `run_scan_loop<F>` has no 'static bound on F, so borrowing works.
