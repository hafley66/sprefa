## What landed

### Telemetry baseline against MemStore (55597c9)

- `MemStore` carries optional `Telemetry` via `OnceLock + attach_tele()`.
- New spans: `v4::Mem::ins`, `Mem::commit`, `Mem::rederive`. Cursor
  bytes estimated as sum of (term name + value + 16 / entry).
- `MemStore::stats()` returns per-fact `(rows, bytes)` + rules /
  channels counts.
- `CommitEvery` op (pass-through; calls `store.commit` every N batches).
- Bench flags `--commit-every N`, `--rules N`. These exercise the
  reactive shape (LSP-edit per commit) and rule fan-out an end-of-run
  commit hides.

Cost model from sweep: rederive ≈ 220 ns/row × rules × commits ×
rows-at-each-commit. RSS scales at ~540 B/row effective (3.7× over
accounted cursor bytes, HashMap probe + Arc<str> overhead).

### DdStore (0b03be6, then edbca59 fix)

Single-worker timely runtime, single fact "matches" hardcoded, N
copies of GroupCount rule pre-built at construction. Async store API
marshals commands across `std::sync::mpsc::SyncSender<DdCmd>` into
the worker thread. `Arc<Mutex<Receiver>>` because
`timely::execute_directly` requires Send + Sync closures.

DdCmd: `Insert {fact, rows, gen}` / `Commit {gen, ack}` / `Stop`. ack
returns `DdAck { derived, advance_ns, step_ns }` so the async caller
can synthesize child spans for advance + step phases via
`push_synthetic_span()`.

Cursor (Vec<(Arc<str>, Arc<str>)>) ↔ DdRow conversion at the store
boundary because Abomonation (DD's serializer) bans Arc<str>. First
landed as `Vec<(String, String)>`; later upgraded to `Vec<(u32, u32)>`.

#### Time-domain bug found via parity probe

Bench passes `Hooks.gen = trial_number` — fixed across all commits in
one trial. DdStore was calling `input.advance_to(gen+1)` on commit
and `input.advance_to(gen)` on insert. After the first commit, input
frontier was past the trial's gen; subsequent inserts at the same gen
were silently dropped.

**Symptom**: under `--commit-every 1`, mem snapshot 2334 rows, dd
snapshot 9 rows. Single end-of-run commit was fine because only one
advance.

**Fix**: DdStore maintains its own monotonic `dd_time: Gen`. Each
Commit bumps; each Insert routes to current. Caller's gen is
preserved on outgoing Diff records for downstream subscribers.

### Interner (af45b4a)

Layer 1 of the v0 strings/refs schema. `HashMap<Arc<str>, u32>` fwd
+ `Vec<Arc<str>>` rev. Lives on `Hooks`. Wired into Fs (interns path
at file emit) and MultiAstNm (clones pre-shared pattern label via
`set_arc`). Cursor gains `set_arc(name, Arc<str>)` to skip `Arc::from`
re-allocation when the value is already an interned Arc.

### u32-keyed DdRow (bb41e6d)

DdRow = `Vec<(u32, u32)>` instead of `Vec<(String, String)>`. 8
bytes per term regardless of column content. `Interner::intern_id`
and `lookup` round out the API. DdStore::new takes `Arc<Interner>`;
shared between caller and worker thread.

GroupCount reduce closure now keys by u32 id, writes output rows as
u32 pairs, interns the count's decimal value on the worker thread.

DD now lighter than mem at large scale. Rule work 12× less at medium
scale (where commits-per-row is high). Tied at large scale (where
delta IS most of the input).

## Cost model (locked)

```
  MEM rederive:    ~220 ns / row-touch
                   row-touches = rules × commits × rows-at-each-commit
  MEM RSS:         ~540 B / row effective (3.7× over accounted cursor bytes)

  DD step:         ~µs at small delta, ~ms scaling with delta size
  DD RSS post-u32: ~500 B / row at large scale (matches mem now)

  Crossover (mem wins):  rules × commits × rows < ~2k
  Crossover (dd wins):   reactive shape with frequent small commits
```

## What's pending — next session pickup

User said: **a + b**, in this order, before sqlite or sprf-parse:

### (a) Lift RuleBody enum to Rule = Vec<Op> body + sink fact name

Today `RuleBody::{Filter, Antijoin, GroupCount}` is a static enum.
Each rule body is a hardcoded recipe. The unification thesis says
rule = pipeline that emits cursors into a sink fact. Lift to:

```rust
pub struct Rule {
    pub name:  String,
    pub body:  Vec<Arc<dyn Op>>,
    pub sink:  String,             // target fact name
}
```

Rewrite GroupCount / Filter / Antijoin as concrete Op compositions
instead of enum cases. The Mem and DD backends consume a Rule and
emit the right operator chain (DD: `.map().reduce().inspect_batch()`;
Mem: scan-and-aggregate over `facts.get(src)`).

Approach: keep `RuleBody` enum as sugar at the call site so existing
bench code works, but internally compile each enum case to a Vec<Op>
body. New rule kinds (Join, Iterate) become more enum cases that
compile to compositions.

~150 lines.

### (b) Multi-fact DdStore

Today `DdStore::new(fact_name: String, rules: Vec<...>, interner)`
hardcodes single fact "matches". To support the indexer schema
(strings + refs + files + repos_files), needs:

```rust
pub fn new(facts: Vec<String>, rules: Vec<Rule>, interner: Arc<Interner>) -> Arc<Self>
```

Worker maintains `HashMap<String, InputSession<Gen, DdRow, isize>>`.
Insert routes by fact name. Rule subgraphs read from one or more
inputs (`reduce` for single-input GroupCount, `join_map` for
fact+fact joins).

`Filter` and `Antijoin` rule bodies need DD operator parity:
- Filter → `.filter(closure_over_dd_to_cursor(row, &interner))`
- Antijoin → DD's `.antijoin()` over arranged-by-key sides

~100 lines for multi-fact framework + Filter; +~50 for Antijoin.
