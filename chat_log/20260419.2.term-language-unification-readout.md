# Session readout: term language unification (2026-04-19)

Brief readout, not a plan. The session iterated through four
framings of one question and the surface kept shrinking.

## Arc of the session

The question: how should `${...}` work beyond identity-bind?

Four framings, each dissolving into the next:

1. **Constraint chain.** `${X > pred > pred}`, predicate-only,
   regex/glob/etc as gates. Wrote this up in `_0_term-language.md`.
2. **Recursive pipeline at expansion site.** `${...}` body is the
   host expression grammar, recursive at every nesting. Constraint
   vs predicate vs transform collapse into "ops compose, each one
   gates or rewrites per its own behavior."
3. **Expression-as-matcher.** First expression in `${...}` IS the
   match condition. Walker delegates leaf-position evaluation to
   host exprs; backtracks on empty stream. `&` (bare) means "current
   input cursor at this position," distinct from `&{...}` structural
   address. `;` Fork carries through to expansion sites alongside
   `>` Seq.
4. **Three realms collapse.** Op pipelines, capture chains, and
   var/let bindings are one realm. Bind = "name a stream-producing
   expression." Use = "invoke it with current cursor as input."
   Lowercase = ops, UPPERCASE = bound names. Prolog casing
   convention disambiguates verb from noun without sigils.

Each iteration grew expressive power and shrank surface.

## Open at session end

The collapse-to-one-realm is provisional. Five points need to hold
for it to land:

1. casing-as-syntax (lowercase ops vs UPPERCASE binds)
2. `&` semantics per host op
3. slot access (`&{...}`) vs binding access (`${...}`) stay distinct
4. named pipelines as compiled values, not macros
5. core ops (`repo`/`fs`/`rev`) mutate slots, never auto-bind

Casing is the load-bearing yes/no. Other four follow from it.

The doc was not rewritten under this collapse. The exploratory
section in `_0_` reflects framing 2 (recursive pipeline), not
framings 3 or 4. Update is on hold pending the casing decision.
