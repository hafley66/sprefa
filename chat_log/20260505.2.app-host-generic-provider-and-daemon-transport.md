## Problem/Context
v3 server crate is 5425 LoC (backend.rs alone 2166) mixing LSP dispatch + state + diag publishing. v2 had right structural shape (thin CLI, sprefa-lsp stdio↔WS proxy, daemon) in fewer LoC. v4 partition plan locked in 11 crates, but the central `Session` struct still felt overweight; user pushed back on the word ("session" as useless as "the"), then pushed back on consumer-trait theatre ("just thread locals lets not get silly"), then asked for axum/tower/clap-idiomatic generic shape with typed redux dispatch. Daemon-mode vs in-process must be modeled, not duplicated. App<S,D> generic over Store + Dispatch (assoc-typed action/reply/error) is the answer.

## Solution/Approach
- Provider = `App<S, D>` holds `Arc<dyn Handler<S, D>>` + concrete Store. Dispatch is shell-side; one impl per shell (CliDispatch/LspDispatch/HttpDispatch); each owns its own typed Action/Reply/Error enums.
- AppService<S,D> is the tower::Service<D::Action> adapter. axum/lsp_server/clap all consume Service-shaped values directly.
- Transport<D> trait gives a `service()` factory: InProcess<S,D> holds `Arc<App>`; DaemonProxy<D> opens UnixStream per call. Same Service<Action> surface = shell code transport-blind.
- Wire format: 4-byte LE length prefix + bincode body. WireResponse<R> = Ok(R) | Err(String) so non-Serialize D::Error stays at server boundary; client side requires `D::Error: From<WireError>` so WireError::Server(stringified server error) flows back.
- Daemon-side: `serve_unix(app, sock)` removes stale socket, binds UnixListener, spawns task per accept, decodes Action / dispatches / encodes WireResponse / writes back. Single connection per request; no pooling.
- Stable-Rust limitation: where-clause supertrait bounds (Action: Serialize, etc.) don't propagate through `D: DaemonDispatch`, so impl sites repeat the bounds inline. DaemonDispatch left as documentation marker, not load-bearing.
- Sprf-side fills (separate work, NOT done in this session): impl Store for SqliteFactStore + MemFactStore; impl Handler for SprefaHandler (3× per Dispatch); CliDispatch/LspDispatch/HttpDispatch enums; Sprefa context payload for CTX scope; DaemonProxy wire codec already done.

## Key Insights
- **Two libs floor**: cst + effect_runtime are the only generic libs sprefa needs; everything else is sprf-specific. Decohesion test: would another project want this without sprf? cst yes, effect_runtime+writes+facts yes, compile/ops/main no. The 11-crate plan was already right.
- **Writes belong in effect_runtime, not their own crate**: WriteEffect = Effect variant, WriteBatcher = Batcher impl (groupBy target → buffer → sort_desc → splice atomic). Sprf-specific (repo,rev,fs) target resolution lives behind a `Target` trait that effect_runtime exposes; sprefa_main impls. ~200 LoC inside effect_runtime, not a new crate.
- **Rule engine = `expand` operator**: rxjs-style. No separate RuleEngine lib needed. expand handles recursive fan-out; fact diff stream feeds the Subject; rule-as-Component is one Subject per rule. User correction.
- **Provider = singleton like React Context Provider**, but task_locals carry context inside (not a Consumer trait). cli=mem store, lsp/http=sqlite. Daemon vs in-process = Transport choice.
- **Redux mapping locked**: Store=union of fact tables+Components, slice=`<file>_<name>_facts` table, Action=FactWrite{insert|retract,gen}, Reducer=INSERT/DELETE on slice, Selector=rule body bound to facts, Subscribe=Component diff$, Saga=expand, Provider=App, dispatch=run/lsp_notify, normalizr=strings_intern. gen_id column = redux DevTools time-travel for free.
- **tower::Service is the universal adapter**: axum natively wants Service<Request>; lsp_server adapter is ~10 lines; clap drives synchronously via `.ready().await?.call()`. Lib code disappears into already-paid-for ecosystem crates.
- **Stable Rust gotcha**: where-clause bounds on a marker supertrait don't propagate. Workaround = inline bounds at each impl site. Three sites, livable.
- **Daemon shape complete in ~200 LoC** because bincode + Unix sockets + tower::Service framing absorbs everything except framing + serve loop. WireResponse<R> wraps the server-side error path so D::Error doesn't need to be Serialize.
- **Lowering recall** (relevant for next session): CST → ir::Program (3 passes per rule: build, schema, mode-infer) → bind → Bound. Op trait owns pipe + pipe_flat_map. Two-door registry: OpFactory::Values | OpFactory::Pattern{dsl,build}. ArgDescriptor carries ArgDiag (struct, not trait) + complete fn pointer (no central enum). cst owns pattern grammars; sprefa_compile knows nothing about regex/glob/ast specifics.
- **Compiler = Laplace transform**: lower=L{·}, runtime=L⁻¹{·}. CaptureSlot=pole (impulse at intro site σₖ), op=transfer fn H(s), Chain=∏H, Fork=ΣH, AcceptsMode intersect=stability check, pattern body = un-transformed sub-signal awaiting cst::Dsl::compile. LSP lives in s; runner round-trips. One equation: `c(t) = ℒ⁻¹{ ⊗_𝓡 ⨁_rules R(s) }` where R(s) = chain product · fork sum · pole impulses.
- **Sprefa-side line count for full sprf-able stack ≈ 2000 LoC**, of which app_host generic = 220 (11%). Right ratio — library tax low.
