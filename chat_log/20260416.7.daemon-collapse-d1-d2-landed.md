## Problem/Context
User wants to collapse CLI + LSP into one always-on HTTP server. No backward-compat constraints (prototype). Uniform architecture:
- `sprefa-server` owns state, tokio runtime, SQLite, ResultStore, LspLayer, watcher (later), auto-run rules (later).
- `sprefa-lsp` thin stdio↔WebSocket proxy (~80 LOC, D3).
- `sprefa` thin HTTP CLI (D3).

Key locked decisions:
1. BufferOverlay interior-mutable API confirmed (has `set_buffer(BufferKey, Arc<Bytes>)` / `clear_buffer(&key)`). No API change.
2. ResultStore keyed globally by (scanner_hash, expr_name). NOT workspace-scoped. Workspace is LSP/CLI surface only; nothing under run_pipeline knows the concept. scanner_hash already composes source+config+repo-rev set.
3. CLI runs always AutoApprove. MutationPrompt routing is LSP-only, follows DocSession's originating WebSocket.
4. No idle shutdown. Server is always-on supervisor.
5. TCP default 127.0.0.1:7417.
6. Logs to $XDG_STATE_HOME/sprefa/server.log.
7. Multi-client LSP fan-out via `subscribers: HashMap<Url, Vec<mpsc::Sender<LspOutbound>>>`.

Corrected crate versions after user push:
- axum 0.8.9 (was 0.7)
- hyper 1.9, hyper-util 0.1.20, tower 0.5, tower-service 0.3
- tokio-tungstenite 0.29 noted for D3

axum 0.8 `serve` is TCP-only. Unix sockets hand-rolled via `hyper_util::server::conn::auto::Builder` accept loop in `_5_transport_http.rs::serve_unix`.

## Solution/Approach
### D1 — server/ module skeleton
- `ServerState` holds: runtime_cfg, store (SqliteStore), results (ResultStore), registry, workspaces (RwLock<WorkspaceRegistry>), lsp (LspLayer), cancel_root, info_path.
- `WorkspaceRegistry` keyed by root PathBuf → Arc<WorkspaceCtx>. `resolve(hint)` does three-branch resolution: .sprefa.toml (ConfigLocator), .git walk-up (InMemoryLocator HEAD), fallback MemReader. All wrapped in BufferOverlay. Port of original `resolve_reader` from bin/sprefa_v2_lsp.rs.
- `LspLayer` with `open_or_replace`/`close`/`publish`/subscriber fan-out. Per-URI LspSession holds DocSession + overlay_keys set for precise teardown.
- `shadow_into_overlay` is a no-op stub; real (repo, rev, path) mapping deferred to D3 (the .sprf file itself rarely needs shadowing; target files get overlay writes via editor text sync of their own URIs).
- Default path helpers: `default_info_path`, `default_unix_socket_path`, `default_log_path`, `default_store_path`, all with env var overrides.

### D2 — sprefa-server binary + /status
- `ServerInfo::write_atomic` (temp + rename) / `ServerInfo::read`.
- `bin/sprefa_server.rs` with clap argv: `--store-path`, `--http-unix`/`--no-unix`, `--http-tcp`/`--no-tcp`, `--info-path`, `--log-path`, `--foreground`. `#[tokio::main(flavor = "multi_thread")]` (required by DocSession::run_sync block_in_place).
- `serve_http` spawns one task per listener. TCP uses `axum::serve` with graceful shutdown on cancel_root. Unix uses `serve_unix` hand-rolled accept loop with per-connection AutoBuilder.
- HttpInfo.tcp stored as String ("127.0.0.1:7417") to dodge SocketAddr serde gymnastics.

## Key Insights
1. **axum 0.7 was outdated; user caught it.** Training cutoff bias. Check crate versions via `cargo search` / `cargo info` before committing. Same vigilance applies to tokio-tungstenite for D3.
2. **axum 0.8 `serve` is TCP-only.** Unix sockets need hand-rolled hyper-util accept loop. Not a blocker; cleanly isolated in `serve_unix`. WebSocket upgrade in D3 routes through axum's ws extractor on both transports.
3. **Workspace is UI-surface only.** run_pipeline and ResultStore don't know about workspaces. Path hint → WorkspaceCtx resolution happens ONCE per run/LSP-open at the transport boundary. scanner_hash is the actual cache dimension.
4. **BufferOverlay key is (repo, rev, path).** LSP editor buffers shadow specific (repo, rev) pairs. shadow_into_overlay stub in _2_lsp_layer.rs deferred because the mapping from Url → (repo, rev, path) requires workspace lookup + URI-to-repo-relative-path, which lands in D3.
5. **Multi-thread runtime non-negotiable.** DocSession.run_sync uses block_in_place. sprefa-server must use `#[tokio::main(flavor = "multi_thread")]` or LSP hovers will panic.
6. **SIGTERM gap.** D2 only catches SIGINT; killing with SIGTERM leaves server.json behind. Fix in D5 alongside auto-spawn work (add SignalKind::terminate arm).

## Open Questions
- D3: LspAdapter over WebSocket — use tower-lsp's Socket abstraction with a WebSocket↔duplex-stream bridge, OR hand-roll JSON-RPC dispatch straight into async methods? Hand-roll is simpler, ~200 LOC; tower-lsp reuse preserves all existing LSP method wiring. Decide at D3 start.
- D3: run_pipeline's file_arc when source is POSTed without source_path. Currently init_cursors expects a FilePath for the .sprf. Use `<memory>` sentinel or require source_path? CLI always has a file; HTTP-only clients (hypothetical) might not.
- Unix + TCP listening simultaneously: server.json lists both. Should clients ever prefer TCP over unix? No — always prefer unix when present. TCP is an escape hatch (remote agents, containerized tooling).
