## Findings needing Chris's word
1. #742 names product tables `"<p>.rel<id>_a<arity>"` because the runtime program carries no relation names (identity is `ref(owner(file, reader_node))`). To get `"<p>.fetch_json"` the program JSON must carry names through from compile. Also every cell is `const(<scalar>)` on this corpus, so typed columns all land as `c<n>_term`; the term table persists all six kinds since ids are IndexSet positions.
2. #741: `Key` is arity 3 in the prelude, so the spelling is `(Key "url" KeyOptions)`; a keyless host is refused with `hosted_relation_without_key` (the `timer` shape needs a language call). Key check lives in `_4_comptime/_4_host.rs` by phase order. Four-item Host form kept for oracle parity.
3. The v7 compile oracle pins every compiler row byte for byte: `effect` cannot be a prelude declaration, `int_add`/`term_lt` sit outside `KERNEL_RELATIONS` via a `kernel_arity` fallback (`_3_check/_5_kernel.rs:15`). Retiring that oracle for dl8-native goldens is the cleanup lever.
4. `sum`/`min`/`max` are aggregates only in head position; `2_interned_storage.dl7` uses `sum` as a body relation.
5. sqlite_ivm assessment: correct across 64 shapes x 174 states, 3 to 16x slower than requery at 400 rows, CI red on `verify` for two runs, cause unread.
