## Analysis

### CFG Construction Algorithm

The CFG builder (CFG_java.py) operates in four phases:

**Phase 1: Node Extraction (lines 792-876)**
Tree-sitter recursively visits all named nodes matching statement types defined in java_nodes.statement_types["node_list_type"]. Each statement gets assigned a unique index via self.index[(start_point, end_point, type)]. Non-control statements (assignments, method calls, declarations) add straight-line edges to the next sibling using handle_next().

Entry point: CFG_java() method at line 792 invokes java_nodes.get_nodes() to populate node_list (dict mapping node keys to AST nodes) and CFG_node_list (list of tuples: (index, line, text, type_label)).

**Phase 2: Control-Flow Edge Construction (lines 884-1300)**
Iterates node_list again and emits control-flow edges based on statement type:

- **if_statement (line 937):** edge_to_body() adds pos_next edge to consequence block; if alternative exists, adds neg_next edge; both branches rejoin at next statement after if via handle_next()
- **while/for/enhanced_for loops (line 970):** edge_to_body() adds pos_next to loop body; add_edge() creates loop_control back-edge from last statement in body back to loop node; loop exit via neg_next to statement after loop
- **do_statement (line 991):** body flows to parenthesized_expression (while condition); while condition has loop_control back-edge to do node and neg_next to exit
- **switch_expression (line 1111):** case nodes extracted from switch_block_statement_group children; each case block flows to next case or to switch_child_map redirect if break statement present; default case flows to exit if no break
- **try_statement, try_with_resources_statement:** Try body flows to first statement; catch clauses reachable from throw statements; finally block always executes (explicit edges from all exit paths)
- **break_statement (line 1055):** Target depends on parent: if in labeled statement, jumps to label_statement_map entry; otherwise jumps past loop/switch exit node
- **continue_statement (line 1028):** Jumps back to enclosing loop node (loop_control)
- **lambda_expression (line 1108):** edge_to_body() adds lambda_next to lambda body; tracked in lambda_map for later return-edge linking

Each control edge triple is (src_index, dest_index, edge_type_string) appended to self.CFG_edge_list.

**Phase 3: Basic Block Clustering (line 875)**
get_basic_blocks() computes weakly_connected_components on the intermediate NetworkX graph to group nodes that must execute together. Each component gets a block_index; basic_blocks dict maps block_index → [node_indices].

**Phase 4: Graph Materialization (line 37)**
to_networkx() creates nx.MultiDiGraph(); for each CFG node, adds node with label (line_number + text) and type_label; for each CFG edge, adds directed edge with controlflow_type metadata. Constructor/method calls get additional data dict (e.g., target_constructor reference).

### Node/Edge Types Emitted

**Edge Types (controlflow_type field):**
- Sequential: `next_line N`, `first_next_line`
- Branch: `pos_next` (if true), `neg_next` (if false or loop exit)
- Loop: `loop_control` (back-edge), `loop_update` (for-loop increment)
- Call: `method_call|{call_site_index}`, `constructor_call|{call_site_index}`, `lambda_invocation`
- Return: `method_return`, `class_return`, `lambda_return N`
- Jump: `jump_next` (break/continue to label)
- Synchronization: `sync_next` (synchronized block exit)
- Special: `yield_exit`, `next`

**Node Types (in statement_types):**
- Control: if_statement, while_statement, for_statement, do_statement, switch_expression
- Jump: break_statement, continue_statement, return_statement, yield_statement
- Blocks: local_variable_declaration, expression_statement, field_declaration
- Declarations: method_declaration, constructor_declaration, class_declaration
- Exception: try_statement, catch_clause, throw_statement
- Functional: lambda_expression
- Sync: synchronized_statement

### Call Edge Model

Calls are extracted in two passes:

**Extraction Phase (CFG_java lines 380-470):**
During initial tree walk, method_invocation nodes are identified. For each call, extract the function signature (parameter types) and store in function_calls dict:
```
function_calls[signature] = [(call_site_ast_index, statement_parent_index), ...]
```

For object_creation_expression (constructor calls), store in object_instantiate:
```
object_instantiate[class_name] = [(call_site_ast_index, statement_parent_index), ...]
```

**Linking Phase (add_method_call_edges at line 632):**
For each call in function_calls:
1. Lookup matching method in method_list (dict keyed by signature → method_index)
2. Add edge (statement_parent_index, method_index, "method_call|{call_site_ast_index}")
3. Find all return statements in that method via return_statement_map[method_index]
4. Add return edges (return_index, statement_parent_index, "method_return") back to call site

Constructor calls additionally encode target_constructor in edge additional_data dict via get_matched_constructor() to disambiguate overloads.

**Call Order Preservation:**
Calls are ordered via statement position in parent block. Call sites are tied to their enclosing statement node, preserving statement-level sequencing. Intra-statement call nesting (e.g., foo(bar())) is not split; the statement node absorbs the entire expression.

### DFG / Reaching Definitions Analysis

DFG is built by SDFG_java (1257 lines) via reaching definitions analysis (RDA) on top of the CFG. Key pieces:

**Identifier Class (SDFG_java lines 56-150):**
Wraps variable references with:
- name: canonical variable name (handles this., class. prefixes)
- scope: list of scope IDs from symbol table scope_stack
- line: source line number
- declaration: boolean (true for def sites)
- method_call: boolean (true for method receiver)

Two Identifier instances unify iff name, scope, line, and method_call all match (line 130). This enforces reaching-definition precision at statement granularity.

**RDA Algorithm (dfg_java function):**
Traverses CFG in topological order. At each node:
1. Apply gen_set: assignments/calls generate new definitions for modified variables
2. Apply kill_set: overwrite prior defs in scope
3. Apply meet operator at join points (union of all predecessor defs)
4. Emit DFG edge from reaching def to current use

DFG nodes are Identifier objects; edges are (def_identifier, use_identifier) with edge_type "data_flow".

Last-use and last-def tracking can be enabled via properties DFG.last_use / DFG.last_def to mark terminal uses/defs (used by ML models).

### Storage Format

**Graph Structure:**
- Nodes: index (int) → attributes dict (label, type_label, etc.)
- Edges: (src_index, dest_index, key) → attributes dict (controlflow_type, edge_type, additional_data, color)
- MultiDiGraph to allow multiple edges between same node pair (e.g., both method_call and return on same pair)

**Serialization:**
- NetworkX JSON: networkx.readwrite.json_graph.node_link_data() produces {nodes: [...], links: [...], multigraph: true, directed: true}
- DOT: nx_pydot converts to Graphviz format; optionally renders PNG via dot command
- No custom serialization; delegates to networkx

### Languages Supported

**Java:** Full support via CFGGraph_java and dfg_java; tested against 40+ Java patterns in tests/data/CFG, tests/data/DFG

**C#:** Parallel implementation in CFGGraph_csharp and dfg_csharp; shares same algorithm but handles C#-specific syntax (no lambda support currently per README)

**Extensibility:**
New language requires:
1. Subclass CustomParser (tree_parser/custom_parser.py) with language-specific check_declaration(), get_type(), scope logic
2. Subclass CFGGraph with language-specific CFG construction
3. Implement dfg_language function in SDFG/
4. Register in parser_map and CFG_map dicts

No query-based extensibility; statement types must be hand-coded.

### Known Limitations (from README)

- **No cross-file resolution:** Single-file analysis only; no inter-procedural linking
- **Java:** No function call nesting in arguments (e.g., foo(bar()) loses nesting structure); limited inheritance support
- **C#:** No lambda/arrow functions, no compiler directives, incomplete operator overloading, limited abstraction
- **Code integrity:** Requires syntax-error-free input; non-compileable code fails silently

### Unique Architectural Decisions

1. **Symbol Table Scoping:** Scope tracking via scope_stack at parse time (java_parser.py:100-117) ensures reaching-definitions precision. Each token maps to its scope chain; variable lookups use longest-scope-match (java_parser.py:45).

2. **Basic Block Extraction:** After emitting all control edges, weakly_connected_components groups related statements into basic blocks (CFG_java.py:50-59). These are used downstream for code understanding (e.g., finding entry/exit of blocks).

3. **Edge Type Encoding:** Control-flow semantics (pos_next, neg_next, loop_control) are distinct from call edges (method_call, constructor_call), allowing downstream tools to separate control from data flow. Call edges additionally encode call-site index in the edge label for disambiguation.

4. **Statement-Level Granularity:** DFG operates at statement granularity (not expression level), aligning CFG + DFG on the same statement nodes. This simplifies join-point computation but loses fine-grained intra-expression data flow.

5. **Lambda Scope Isolation:** Lambda bodies are treated as separate scope domains with explicit invocation edges (lambda_invocation) and return edges (lambda_return). Returns from lambda bodies rejoin at the calling statement.
