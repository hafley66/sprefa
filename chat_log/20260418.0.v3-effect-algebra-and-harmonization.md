## Problem/Context
User is upset at earlier suggestions to delete/unroll traits. Reader/Store/MutationHandler are boundary abstractions meant to stay swappable. User renamed "scope" (prior transclusion sketch) to ByteRangeRef. User renamed Coalescer → SideEffectBatcher. User model:
- RxJS observables are unidirectional coroutines; async generators + Subject/chan are the power tool.
- CSP doesn't scale past a certain point; batching is the compensation.
- All boundary work is `yield put`; every put returns something. Transactional. No void-to-void-to-void.
- Store reads are themselves effects (cache warmups, fs touches).
- Sagas = side-effect pipeline operators in the runner; ops yield effects, batcher coalesces, dispatches, returns.

Performance signal from the prior session still stands: real bottleneck is Mutex<git2::Repository> inside Reader::bytes / blob_oid called per file. N+1 surfaces all happen inside op pipe bodies that do `for c in batch { reader.bytes(...).await }` or `join_all` over per-cursor futures. Targets still ~3x gap to biome.

## Solution/Approach
Three-layer naming locked in:
- **Store** = redux core. `watch::Sender<State>` (BehaviorSubject-shape: last-value + subscribe) + `broadcast::Sender<Event>` (Subject-shape: event fanout). This is rxjs `scan + shareReplay(1)` folded into tokio primitives.
- **Sagas** = any side-effect pipeline operator in the runner.
- **SideEffectBatcher** = per-effect-kind batcher. Has window (Duration, throttleTime analogue), max_size, dispatch closure. All rayon / ast-grep walks / spawn_blocking / mutex acquisition lives inside dispatch, never in op bodies.

Effect surface uses associated types (no central Response enum):
```
trait EffectKind: Send + 'static { type Response: Send + 'static; }
fn put<E: EffectKind>(&self, e: E) -> impl Future<Output = E::Response>;
```

Effect kinds enumerated: ReadBytes, ReadParsed, ListFiles, QueryStore, WriteEdit, Shell, ApproveMutation, TemplateRender.

Filesystem layout (v3 target):
```
src/
  core/
    types/         atoms, Cursor, Capture, CaptureKind, Tri, Slots, SlotKey,
                   SprfPath, PathExpr, ByteRangeRef, ParseSite, OpEvidence
    effect/        Effect, Response, EffectKind, RtCtx::put
    store/         watch<State> + broadcast<Event> (redux core)
    batcher/       SideEffectBatcher<E> window/leading/trailing/dispatch
    op_trait/      Op + associated types for CaptureKind, DiagKind, EffectKind
    diagnostic/
    perf/          telemetry, rayon bridge, str_intern, hash
  effects/
    read_bytes.rs  read_parsed.rs  list_files.rs  query_store.rs
    write_edit.rs  shell.rs        approve_mutation.rs  template_render.rs
  parse/
    grammar.rs  lower.rs  dag.rs  template.rs
  runner/
    seed.rs  loop.rs  state.rs
  ops/
  analysis/
  lsp/
  cli/
```

`dag.rs` and `lower.rs` move to `parse/` (they analyze the parsed tree; no runtime data). `runner/` is explicitly the scheduler (2111 LoC today across 8 files); state.rs holds ResultStore + Registry + pass counter.

Cursor slot policy: hard-code a field iff ≥3 ops read it (run_id, repo, rev, fs, byte_range, content, path, evidence). Everything else = SlotKey<T> extension. `SlotKey<T>` is the type-indexed heterogeneous map pattern (http::Extensions / anymap / typemap).

`&.$X` grammar is shared by cursor_ref op (rebase) and TemplateString (inline render). TemplateString has segs Literal(Bytes) | Ref(PathExpr), renders to (Bytes, Option<ByteRangeRef>). Anonymous content has None ref.

MutationEffect + WriteCommentScopeEffect (Phase 2) carry ByteRangeRef as their dst coord. Marker op renames to `comment` (markers ARE comments).

Harmonization table (what v3 collapses):
- Reader 11 methods × 4 impls → 5 effect kinds + 5 batchers
- Writer 14 methods × 1 impl → 8 effect kinds + 8 batchers
- Store 7 methods × 2 impls → 2 effect kinds (Query, Persist) + 2 batchers
- MutationHandler 3 impls → 1 ApproveMut effect with policy-enum variant
- Ops stop importing reader/writer/store; only import RtCtx::put + EffectKind
- Scattered mpsc/oneshot/MutationRequest → one batcher pattern
- Per-method tracing → one put-level span
- `Mutex<git2::Repository>` held per file → held once per batcher dispatch
- `join_all` / `par_iter` inside pipe bodies → disappears; batcher owns rayon entry

Dissonances left open: enum growth vs trait-method growth (linear either way), store-read-as-effect adds awaits (mitigate via watch::Receiver::borrow() sync snapshot for hot paths), saga transactions are sequential by nature (separate axis from batcher coalescing), rayon-inside-batcher is convention-enforced not type-enforced (lint rule: no `use rayon` in ops/*.rs), one dyn boundary remains inside RtCtx's `TypeId -> dyn BatcherEntry` registry.

## Key Insights
- Communication rules encoded as word blocklists cause the model to over-bias on those tokens and corrupt post-training intent. Positive-posture rules generalize; blocklists overfit. Saved as feedback_no_banned_word_lists.md.
- The `SlotKey<T>` pattern already present in Cursor is the Rust ecosystem's "type-indexed heterogeneous map" idiom (http::Extensions, anymap, typemap, frunk). Generalize it for per-op extension without leaking op types into Cursor struct.
- `ByteRangeRef { repo, rev, fs, byte_range, id: Arc<str> }` is the natural atom across the graph. Captures, effects, write-edits, transclusion dst all converge on it. FileEdit is a ByteRangeRef + replacement.
- `&.$X` as shared primitive — same PathExpr parse node serves cursor_ref rebase + template interpolation + xref keying. Three consumers of one grammar piece.
- "All is put" reduces the framework to `put :: Effect -> Future<Response>`. Store reads included. Transactions = chained puts; batching = per-batcher window. Two independent axes. No void-to-void.
- RxJS observables map to Rust `BoxStream<Arc<[Cursor]>>`. Async generators with next(x) input are absent in stable Rust; `async-stream!{}` gives gen-syntax but still yields forward. Redux-saga's `yield put(Effect)` translates to `ctx.put(e).await` with typed Response.
- `throttleTime(16ms, {leading, trailing})` = SideEffectBatcher window config. Leading fires immediately on first put; trailing drains on window close. Kept as config field.
- Runner is 2111 LoC across 8 files; it is the scheduler, deserves sibling-of-core status not subfolder. Internal split: seed/loop/state/parallel. `dag.rs` and `rewrite.rs` move to `parse/` because they analyze the parsed tree.
- analysis/ vs lsp/: analysis is pure semantic queries (DocSession, hover/completion by position, no protocol). lsp/ is JSON-RPC transport + lifecycle + drives analysis. cli/ drives runner directly, skips analysis unless subcommand wants hover.
- Op plug slots: grammar (parse), algebra (type_algebra), pipe (runner), diags (core/diagnostic), hover (analysis), effect (mutations). Each op bundle has one entry per slot; framework never matches on op kind.
- dyn question: today `Arc<dyn Op>` with many trait methods. Alternatives are closed enum (violates ops-own-everything), generic monomorphization (works only deep inside one op), associated-type trait family (sprf-v2-op-trait-family direction; stays dyn at boundary, static per-op), codegen/macro (largest investment). v3 sketch picks associated types on `EffectKind`.
