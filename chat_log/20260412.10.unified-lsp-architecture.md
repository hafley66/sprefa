# Session: unified-lsp-architecture

## Goal
Unify LSP state management around the parser/analyzer as a single source of truth. Create an Operator trait system where each operator (fs, json, ast, etc.) self-parses and validates.

## Current State
- ✅ Hover works repeatedly with DocumentSnapshot (fast, <10ms)
- ✅ Cross-ref resolution for derived rules implemented
- ⚠️ Two diagnostic paths: analyze.rs generates diagnostics, LSP has duplicate pattern detection
- ⚠️ "0 files matched" points to rule name, not the fs() pattern
- ⚠️ TOML/JSON path mismatch errors don't show available paths

## Problem/Context
The LSP currently has fragmented state and duplicated logic:
1. `doc_state` - legacy doc parsing for completions
2. `analysis_state` - unified analysis cache  
3. `snapshots` - pre-computed captures/rules for hover
4. `workspace` - workspace config
5. `hover_provider` - DB access

Multiple Mutex fields cause lock contention. LSP has `find_pattern_at_position()` which duplicates parser functionality.

## Solution/Approach
### Reactive Architecture
```
Events → analyze.rs (single reducer) → PartialAnalysis → LSP (thin adapter)
```

### Operator Trait System
```rust
pub trait Operator {
    fn name(&self) -> &'static str;
    fn parse(&self, input: &str) -> Result<(Self, Vec<ParseDiagnostic>), ParseError>;
    fn validate(&self, ctx: &ValidationContext) -> Vec<RuntimeDiagnostic>;
    fn execute(&self, ctx: &ExecutionContext) -> OperatorResult;
}

pub enum OperatorError {
    InvalidPattern { pattern: String, reason: String },
    FileSystem { path: PathBuf, io_error: std::io::Error },
    DataFormat { path: PathBuf, format: String, error: String },
    PathNotFound { attempted: String, available: Vec<String> },
}
```

## Key Insights
1. LSP should be a thin adapter - parser is source of truth
2. All operators should implement common trait for consistency
3. Single state container eliminates lock contention
4. Parse diagnostics (syntax) vs Runtime diagnostics (execution) are separate phases
