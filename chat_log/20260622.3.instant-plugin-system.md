# Session: instant-plugin-system

## Goal
Make `~/projects/instant` extensible so sprefa (and other plugins) can register panels, activity-rail buttons, and Tauri commands without touching hardcoded union types or index.html.

## Problem/Context
Instant's panels (sessions, worktrees, activity, files, preview, config) were hardcoded everywhere:
- `PanelId` was a union type in `state.ts`
- Panel DOM lived in `index.html` `<div id="panel-pool">`
- Activity-rail buttons were hardcoded `<button>` elements
- `reactdock.tsx` had a hardcoded `TITLES` map
- `wireChrome()` bound toggle handlers by hardcoded id strings
- `onPanelShown()` was a big switch/case
- No way for an external module to add a panel

Approach: keep existing vanilla DOM rendering functions working, but make the registration layer dynamic.

## Solution/Approach

### TS plugin system (`src/plugin.tsx` — new)
```ts
export interface PanelDef {
  id: string;
  title: string;
  icon: string;
  iconLabel: string;
  html: string;       // inner content injected into #panel-pool
  component?: ComponentType<IDockviewPanelProps>;  // custom React component (optional)
  onShow?: () => void;  // lazy-load callback
}

export interface Plugin { id: string; panels: PanelDef[]; }

// Registry: Map<string, PanelDef>
registerPlugin(p)  // adds panels to map
getPanel(id)       // lookup
allPanels()        // all PanelDef[]
panelIds()         // all id strings
dockComponents()   // builds Record<string, ComponentType> for DockviewReact
injectPanelHtml()  // injects <section id="panel-{id}"> into #panel-pool
buildActivityRail() // creates #actbar-panels span with buttons from registry
```

Key design: `dockComponents()` generates per-panel React component types. Each is a thin wrapper that adopts the DOM node from `#panel-pool` on mount and returns it on unmount (same lifecycle as the old `HostPanel`). This preserves all existing vanilla DOM rendering functions that query by ID.

2. Rust: add `#[tauri::command]` fns in `sprefa_plugin/commands.rs`, add to `generate_handler![]` in `lib.rs`

## Key Insights
- Pool-adoption pattern (inject HTML into hidden `#panel-pool`, adopt on mount, return on unmount) preserves all existing vanilla DOM rendering functions without touching them. The only change to panel content code is where the HTML strings live.
- `dockComponents()` dynamically creates React component types — each panel gets its own component type from the registry, not a single generic `HostPanel`.
- `onPanelShown` switch becomes per-panel `PanelDef.onShow` — each panel controls its own lazy load.
- Activity rail built via `buildActivityRail()` which injects `<span id="actbar-panels">` before `.actbar-spacer`. Toggle bindings iterate `allPanels()`.
