# Session: v4-op-row-bench-parity-and-tracing

## Goal
Land enough of the v4 op surface to lower the demo, port the linux-bench shape into a `.sprf` file driven by sprefa-run at parity with v4-bench, and add conditional tracing so perf is debuggable without paying when off.

## Current State
112 → 115 lib tests + every integration suite green. Demo `examples/highlight-demo.sprf` lowers clean. `bench/linux.sprf` runs `fs(:c) > ast(:c)\`printk($$$)\` > fact(:hits, FS, LO, HI)` against the kernel fixture in ~4s release with 16,329 rows (within ~2% of v4-bench's 16,627). Tracing is opt-in via SPREFA_LOG, zero cost when off.

## Problem/Context
Started in continuation from `20260506.2.term-runtime-introspect-and-binding-graph.md`. User asked whether v4 was finally back to v3 parity. After a re-eval it became clear effect_runtime/v2 already had FactStore + MemoCache + EventBus + expand driver — what was missing was the language-surface op row, not the runtime. ## Solution/Approach
Op row first (compile-time work):
  - `ast(:lang)\`pat\`` — paren-arg atom, parsed to SupportLang, threaded into AstNmComponent
  - `json(:fmt)\`{ key: $V }\`` — JsonDsl::compile_typed bypasses `Box<dyn Compiled>`; JsonComponent uses match_grouped to preserve row boundaries
  - `fact(:t, ARG, ARG?, ...)` — single op dispatches by arg binding-mode at lower time (Atom or Pipe(term:N) = bound, Pipe(term_bind:N) = unbound; pure-bound → FactWrite, mixed/unbound → FactRead with first bound as key + unbound names as projection)
  - `lsp_error/warn/info/hint` — single file v4/src/lsp.rs holds Component + four OperatorDefs; emits Diag with cursor LO/HI span
  - glob accepts both dsl body and atom (added `dsl_required` defaulting true; glob overrides to false)

Universal ${pipe} carveout (#7 phase 1 only): partition the host-grammar `${X}`/`${X?}` interps from per-dsl `$X` binders. `default_plain_dsl_parse` now returns `DslInterp { name, range, mode: Read|Bind }`. binding_graph routes Read → reads, Bind → binds. json's binders_in_dsl tightened to bare-$ only.

Turnkey LSP: added `completions(body, byte) -> Vec<CompletionItem>` to DslBodyLsp trait. impl DslBodyLsp for JsonDsl: byte-scan semantic_tokens (capture/string/number/structural/keyword), hover (capture / wildcard / structural roles), completions (`**`, `*`, `...`, `$` + already-declared $NAME captures from earlier in the body).

Op-author cursor declaration: `OperatorDef::cursor_binds() -> &'static [&'static str]` so fs/glob declare ["FS"], ast declares ["LO","HI"], re declares ["LO","HI","MATCH"]. binding_graph sees them so downstream `FS`/`LO`/`HI` reads don't false-positive use-before-bind.

Bench port + n+1 audit: bench/linux.sprf runs end-to-end. Initial 8s wall surfaced two cliffs:
  - MemFactStore.insert had O(n) dedup scan per row → swapped to MemTable { rows, seen: HashSet<String> }; added FactStore::insert_batch trait method (default falls back to per-row); MemFactStore impl takes ONE lock for whole batch; FactWrite::render_batch wraps it
  - default ExpandOpts batch_cap=256, v4-bench uses 4096; bumped sprefa-run's run path to 4096
  - content_id used per-byte `write!("{:02x}", b)` → swapped to blake3 `to_hex().to_string()`
  - ast `:c` atom mapped to L::C (stricter); v4-bench uses L::Cpp for both. Updated map.

Conditional tracing: instrumented expand.rs at the comp.dispatch site with a `render_batch` debug span (op=kind, depth, n) + debug event with wall_us/emitted. Gated on `event_enabled!(target: "expand", DEBUG)` so when no subscriber is installed the runtime skips Instant::now() and span allocation entirely. sprefa-run only initializes a tracing-subscriber when SPREFA_LOG env var is set.

## Key Insights
- effect_runtime/v2 was already at v3 parity for runtime mechanics; the gap was language-surface op definitions. Earlier session-end framing of "FactStore + ChangeSubject + OpCache + FsWatcher port from v3" was wrong — all of those exist as MemoCache + EventBus + FactStore.
- Bracket `[...]` slot is source-pipe with default `&.value`, not a discriminator. Lang for ast is paren-arg atom (`ast(:rs)`).
- v4 has no kwargs (deferred). Configuration goes in dsl bodies (yaml-shaped if needed). Wide surfaces like LSP are multiple ops, not one mega-op with atom discriminators.
- `${X}` inside a dsl body is a HOST pipe-hole. Per-dsl `$X` (no braces) is the dsl's own grammar. Both can coexist; binders_in_dsl scans only the dsl-internal form. The ${X?} sugar = ${term?(:X)}; runtime semantics = pump cursor.value at the hole position through the sub-pipe.
- 10-point n+1 checklist saved as feedback memory. Bench against linux fixture is a gate before claiming any new per-cursor op is ready.
- tracing is "zero-cost facade" only if subscriber not installed AND your timing code is gated. Always gate Instant::now() with event_enabled!.
- ast-grep's C grammar is stricter than C++; v4-bench picks Cpp for both. Match that.
- MemoCache + EventBus + CacheCascadeListener replace v3's OpCache + ChangeSubject + spawn_invalidator. Same shape, different names.

## Open Questions
- Should ast LSP support the metavar overlay via target-lang tree-sitter directly (#8)? Or wait for the universal hole pump (#10) to land first since it changes how ast bodies are tokenized?
- Sibling top-level pipes don't share scope today. When fork lands, do siblings share? Today binding-graph treats each top-level pipe as independent.
- FactRead's "all-unbound args" SELECT * surface (drain+subscribe) not yet wired; needs ChangeSubject hookup.
- LSP backend dispatch from the host op call site to per-DSL `Dsl::lsp()` for hover/completion/tokens — wired structurally but not exercised in a backend e2e test.
