## Solution/Approach
- **Unifying frame (strengthened)**: every kernel = (feature extractor, similarity
  function). The generic `matching_runs<T: Eq+Hash>` matcher finds maximal runs
  of identical consecutive items appearing ≥2 times. What differs between kernels
  is ONLY the feature extractor (what each "item" in the sequence is):
    - verbatim: raw source lines
    - ast-shape: normalized leaf kinds (ID/LIT/punct)
    - tree-iso: u64 Merkle hash of statement subtree
    - cfg-shape: u64 hash of control-flow skeleton
    - symbol-shape: resolved SCIP moniker per leaf token
    - call-seq: u64 hash of per-statement symbol set
- **subtree_hash**: recursive Merkle hash. ident→constant(1), lit→constant(2),
  interior node→hash(kind ⨁ child_hashes). Comments excluded entirely. Two
  subtrees with identical structure but different names hash equal.
- **statement_ranges refactor**: block_statements was returning pre-hashed
  (u64, lo, hi) tuples. Refactored to `statement_ranges<'a>(tree) ->
  Vec<(Node<'a>, usize, usize)>` so each kernel applies its own hash function.
  tree-iso uses subtree_hash, cfg-shape uses cfg_skeleton_hash, call-seq uses
  symbol-set hash.
- **cfg_skeleton_hash**: DFS collecting control-flow node kinds in pre-order
  (if/for/while/loop/match/match_arm/break/continue/return), hashed as a
  sequence. match_arm included so different arm counts produce different hashes.
- **Validation harness (kernel_compare.rs)**: union-find clustering of all
  proposals across kernels by line-range overlap. Per-cluster: distinct kernel
  count, max gain, representative range. Multi-kernel consensus = natural
  precision ranking (≥4 kernels = high confidence).
- **SCIP data probe**: verified RA's SCIP carries ZERO per-expression type info.
  signature_documentation empty (0/2775), syntax_kind all 0 (0/18366), only
  Definition role set (no ReadAccess/WriteAccess). type-shape kernel is blocked
  on a different data source (LSP hover or RA analysis-stats).

## Key Insights
- **6 graph/tree shapes now cover the code-analysis space**: lexical (verbatim),
  syntactic-leaf (ast), tree-structure (tree-iso), control-flow (cfg), semantic
  (symbol), dataflow (call-seq). Each catches a distinct duplication class.
- **tree-iso is a precision filter**: consistently 2-14% of ast-shape's proposals
  across all 6 test files. Nearly 1:1 block-to-range ratio (no window redundancy).
  Catches genuine consolidation candidates (per-hit scaffolding, refresh pipelines).
- **cfg-shape catches ALGORITHMIC similarity**: 0-param=0 means every match has
  different data (same logic, different inputs). Catches memoization patterns
  (22 occ) and guard clauses (40 occ). No other kernel has this profile.
- **symbol ⊆ ast confirmed by overlap matrix**: 548/567 of symbol's ranges overlap
  ast. The CST⨝symbol join refines, doesn't add noise.
- **Multi-kernel consensus is the precision signal**: 6-kernel agreement =
  L5590-5615 (the per-hit scaffolding, gain=160). ≥4-kernel agreement filters
  out ast+symbol-only RelDecl boilerplate noise.
- **ast/symbol are recall engines, precision-poor**: 629/567 ranges but dominated
  by RelDecl declaration boilerplate (2 lines × 24 occ = gain 897, all from one
  function). Low mean_params (1.9-2.0) = catching trivial dups.
- **SCIP carries zero per-expression type data**: verified by probing index.scip.
  signature_documentation empty, syntax_kind all 0, only Definition role set.
  RA computes types internally but doesn't emit them. type-shape needs LSP hover.
- **statement_ranges refactor**: returning Node (not pre-hashed u64) lets each
  kernel choose its hash function. The feature extractor is the only thing that
  differs; the matcher (matching_runs) is shared.
- **matching_runs is kernel-agnostic**: T: Eq+Hash. Works for &str (verbatim/
  ast/symbol) and u64 (tree/cfg/call-seq). The ≥3-distinct-items filter prevents
  trivial repetition; seed controls minimum block size.
