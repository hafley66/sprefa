# Learning notes: Lloyd-Topor, free variables, time aggregates (2026-07-23)

Session-derived study doc. Context: designing v6 nesting (`latest()`, body groups)
without breaking datalog's termination guarantee.

## 1. The one-line frame

Datalog bodies are flat conjunctions on purpose. Every nicer surface (disjunction,
grouped negation, aggregates with their own mini-body, `latest()`) compiles down to
flat rules by ONE mechanical move: mint an auxiliary rel per nested group. That move
is the Lloyd-Topor transformation (Lloyd & Topor 1984, "Making Prolog More
Expressive"). SQL does the same thing internally and calls it subquery unnesting /
decorrelation.

## 2. Free variables — the load rule of the whole thing

A variable inside a nested group is:

- **free** if it also appears outside the group -> it is the group's INTERFACE
- **local** if it appears only inside -> it is existential ("some value exists"),
  and it vanishes during the lift

The minted rel's columns = exactly the free variables. Nothing else to decide.

```
ok(x) <- a(x), !(b(x), c(x, y)).
                       ^     ^
                       x free (appears outside)   y local (inside only)

lift:  __g1(x) <- b(x), c(x, _).     -- y became _ : "there exists some y"
       ok(x)  <- a(x), !__g1(x).
```

Read `!(b(x), c(x,y))` as: "there is NO pair where b holds and some c-partner
exists." The lift preserves that reading exactly because y was existential.

## 3. The transformation, case by case

### Disjunction in body
```
ok(x) <- a(x), (b(x); c(x)).
==>
__or1(x) <- b(x).
__or1(x) <- c(x).
ok(x) <- a(x), __or1(x).
```
Two rules with the same head IS datalog's union; the group syntax is sugar for it.

### Negated group
```
ok(x) <- a(x), !(b(x), c(x, y)).
==>
__g1(x) <- b(x), c(x, _).
ok(x) <- a(x), !__g1(x).
```
Negation stays over a single flat atom, which is what stratification knows how to
check. Nested negation depth N = N minted rels, each in its own stratum.

### Aggregate with its own body (soufflé-style)
```
busy(endpoint) <- count(bucket : resp(endpoint, bucket, _, _, _)) > 10.
==>
__c1(endpoint, count(bucket)) <- resp(endpoint, bucket, _, _, _).
busy(endpoint) <- __c1(endpoint, n), n > 10.
```
Free variable: endpoint (grouping key). Aggregated variable: bucket. The minted
rule is a plain v5-style head aggregate.

### Value-position aggregate (`latest`)
```
resp_current(endpoint, etag, body) <-
    resp(endpoint, latest(bucket), 200, etag, body).
==>
__t1(endpoint, max(tick)) <- resp(endpoint, _, 200, _, _).      -- find the tick
resp_current(endpoint, etag, body) <-
    resp(endpoint, bucket, 200, etag, body), __t1(endpoint, tick).  -- fetch row
```
This is the argmax join-back pair, automated. `latest` differs from `max`:
it ranks rows by TICK and returns the value column from the winning row
(argmax); `max` ranks by the value itself and destroys the rest of the row.

## 4. Why heads never nest

A head is a column list — it DEFINES a table. Nesting means "compute through
intermediate structure", and the intermediate structure of rules is other rules.
So all nesting lives in bodies and value positions; heads stay flat forever.

## 5. Why this is safe (the Herbrand argument)

Two kinds of nesting, only one is dangerous:

- term constructors `f(g(x))` build NEW values -> infinite universe -> no
  termination guarantee. This is the datalog/prolog boundary (function-freeness).
- query nesting (subqueries, aggregates, groups) only SELECTS from existing rows.
  The domain never grows. Lloyd-Topor output is plain datalog, so every guarantee
  (finite fixpoint, stratification checks) applies to the minted rules unchanged.

Inherited restriction: a minted aggregate/negation rel must sit in a lower stratum
than its reader — no recursion through it. The transformation does not weaken
stratification; it makes nested syntax checkable BY it.

## 6. The time-agg family (design candidates, not ruled)

All the same minting machinery, all stratified-only, all over the store's
implicit tick column (they REQUIRE the store stamping tick on every row):

| word | meaning | sql window twin | rx twin |
|---|---|---|---|
| `latest(x)` | x from newest tick | FIRST_VALUE(x) ORDER BY tick DESC | BehaviorSubject value |
| `earliest(x)` | x from oldest tick | FIRST_VALUE(x) ASC | first emission |
| `prev(x)` | x from tick - 1 | LAG(x) | scan's previous accumulator |
| running folds | sum/count up to now | SUM() OVER unbounded preceding | scan |

The SQL OVER clause (PARTITION BY key ORDER BY tick) is exactly the info the
store already holds ambiently: partition = the rel's key columns, order = tick.
That is why one word suffices where SQL needs a clause.

LEAD note (correction from this session): over stored history LEAD is a legal
plain offset read — every row is data, only the newest row lacks a successor.
"Cannot read the future" applies to rx stream-time (the next emission does not
exist yet), never to table-time.

## 7. Why not clock(300, latest(bucket))

`clock` is the time SOURCE, not a stored table. It has exactly one row at any
moment (current bucket = now/300) and no history. `latest` aggregates the tick
column of stored rows; pointing it at the clock asks "newest value of the axis
ordered by the axis" — identity. `clock(300, bucket)` already means the latest
bucket. `latest(clock(...))` is additionally a category error: latest takes a
value position, an atom is truth-valued.

Rule of thumb: `latest` reads history; `clock` mints the present.

## 8. Vocabulary acquired

- **free / local (existential) variable** — interface vs vanishing
- **Lloyd-Topor transformation** — nested formula -> flat rules via minted rels
- **subquery unnesting / decorrelation** — SQL's name for the same move
- **argmax vs max** — rank by one column, return another / rank-and-return same
- **function-freeness** — no term constructors; the finite-universe guarantee
- **Herbrand universe** — all ground terms buildable from constants + functors
- **stratification** — negation/aggregate readers live in higher strata
