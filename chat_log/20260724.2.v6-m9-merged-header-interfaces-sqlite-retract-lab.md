## Solution/Approach
**One sqlite interface**: `open_db(url)` added to the store's `lib.ts` beside `SqliteDb`. All 5 dl sites route through it; **zero `@libsql/client` imports in dl src+tests**. Documented exception: `scripts/dbstat_report.mjs` (plain-node diagnostic with sqlite3-CLI fallback). The `as unknown as Db` cast at `DlRuntime.boot` dropped as a side effect.

**Headers**: `v6/sprefa-store/js/src/engine/types.ts` (new, ~500 lines) + `v6/dl/src/0_types.ts` (extended). Pattern per class: interface `IStore`, class `Store implements IStore`, plus an `I*Statics` interface for the side `implements` cannot see, bound by `export type StoreStaticsHold = AssertTrue<typeof Store extends IStoreStatics ? true : false>`. `AssertTrue<Holds extends true> = Holds` with a **`false`** branch, never `never` (`never extends true` is TRUE, so a never branch proves nothing).

**Import direction flipped**: implementations import types from the header, never from each other. Was: `lib.ts` imported runtime from `engine.ts`/`spine.ts` while those imported types back from `lib.ts` (type-only, never cycled, but no base file to read first). Header imports nothing package-local; its one outside import is `type Client` (erases at build), so `lib.ts` stays the sole runtime `@libsql/client` site.

**Dataflow sections** (the "interfaces express dataflow" ask): namespace surfaces `ICascadeApi`/`IReachApi`/`IReconcileApi`/`IRelTableApi` + standalone `OpenDb`/`Stamp`/`CreateAllTables`/`IngestJsonl`; dl gets `Ddl`/`IngestFile`/`ShHost`/`StartServer` + binds the pre-existing `Bridge`/`ToFactLines`. The framing made explicit: **the connection and namespace are ARGUMENTS, not fields** — state lives in SQLite, functions borrow the handle.

**Every rail was broken on purpose before being trusted**: `alive_keys` -> `string[]` fails TS2416; extra arg on `RelStore.attach` fails TS2344 on the statics proof; extra arg on `reach.count_pairs` fails `ReachApiHolds`. All restored.

## Key Insights
- **Rust was never slower than TS.** Same cells, same machine: TS 2-7% faster in every cell. Cause is the bundled C library, not the language: Rust ships vanilla SQLite **3.51.3** (libsqlite3-sys 0.37), @libsql/client ships a **3.45.1** fork. Reran the Rust harness today and it reproduced the July report within 1-2%, ruling out machine state. `rust_peak_mb=0.12` in every store cell: the retract runs entirely inside SQLite's C engine, so the host language is a rounding error. If it ever matters, the lever is pinning the C build.
- **The lab's two winning levers were both probe-count, not SQL cleverness**: `INSERT OR IGNORE` replacing `SELECT DISTINCT` (killed `USE TEMP B-TREE FOR DISTINCT` from every plan; this was scc's entire edge over dred, they now tie), and frontier ping-pong (`std::mem::swap` of two table names instead of `DELETE frontier; INSERT frontier SELECT FROM next` per round).
- **Prior art nearly got re-measured.** `c1c40709` (July 22, exp/g3-knob-sweep) had ALREADY profiled "where does the 2s go": zero disk I/O, 100% single-core CPU in SQLite's bytecode VM, every access path an optimal index seek, and it NAMED the one removable cost (`USE TEMP B-TREE FOR DISTINCT` on 3 hot frontier joins) without ever collecting it. `FINDINGS-AND-GAPS.md` had already recorded "CTE-is-faster was a wrong assumption; measured and rejected". Relaying both as a mid-flight amendment is what pointed the lab at the one real lever.
- **Declared-but-unbound types rot silently.** `0_types.ts` declared `IngestFile = (path: string) => Promise<TickReport>` while the real `ingestFile` has taken `(rt, filePath)` since M3. Wrong for the whole arc because nothing was ever checked against it. Nothing in TypeScript binds a free function to a declared type; the `AssertTrue` aliases are what make a header a contract instead of a comment.
- **`export import X = Y.Z`** is TS's import-equals alias (pre-ES-modules, namespace-only). It carries EVERY meaning of a symbol (value + type + namespace) where `const` copies only the value. It is TS's `pub use`, which is exactly why it existed here (`lib.rs:610`). Both instances had zero readers and were deleted.
- Four lab rejections with receipts: covering index (WITHOUT ROWID secondary index ALREADY stores `(child_key, parent_key)`, proven via `index_xinfo`); ANALYZE (no-op for CROSS JOIN engines, makes dred-cte 7.8% slower); page_size (within 1.5% at 960k, though 8-15% at 60k where the b-tree loses a level); CTE join-order pin (6-8% slower — when the cone is ~the whole graph, one sequential covering-index scan beats ~1M cone-driven descents, which sharpens the older CTE finding: its deficit is row-at-a-time recursion, not its base plan).
- dred's residual 4x vs counting is the cone (960k-node cone for a 160k dead set): algorithmic, unreachable by SQL shaping.
- A barrel cannot export an interface and a class under one name (TS2308). The I-prefix deleted BOTH workarounds it forced: the `Contract` import aliases AND the explicit named re-export in `index.ts`.
