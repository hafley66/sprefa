## Key Insights
- The §14–§18 ambiguities in chat_log/20260425.2 are a multi-year language-design horizon. The verification harness use case the user actually cares about needs maybe 10% of it — primarily `json()` and `tag()` ops, plus the existing two-pass diff pattern.
- LSP work (hover, completion, go-to, BindingGraph warnings) is the user-visible reward from v3 work. Easy to understate in the bd ledger because each piece is small, but cumulatively this is what makes the language feel alive.
- Source-op arg-pipe contract sounds like a small unification but sits on top of a 180° flip in cursor-state ownership, requires new Subject machinery, requires source-ops to own enumeration (currently the runner does), and depends on tag op which doesn't exist yet. Right call to freeze.
- The kitchen-sink fixtures decay quietly when grammar locks land. Fixture updates should ride with the lock commits, not be left as follow-ups.
- Small audit cards (4m7.11.2-style) catch real violations and convert into clean trait const additions. Worth doing more of these as a regular sweep.
- "Ops own everything" invariant has a sharp test: grep `match name` / `name == "..."` in server/ — anything that survives needs to migrate to a trait const.
