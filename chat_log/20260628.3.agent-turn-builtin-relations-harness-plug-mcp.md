## Solution/Approach
TWO complementary capabilities, both harness-agnostic:
1. FILE EDITS (built-in, Rust): AgentHarness trait + agent_harnesses() registry,
   mirroring type_langs(). Two adapters read newest session for repo_root, return
   latest turn's edits repo-relative. Engine projects into:
     agent_edit(harness, session, idx, path)  -- every edit, fully tagged
     agent_touch(harness, session, path)      -- max(idx) turn, still tagged
   TAGGED union (not broadcast). Policy = one rule:
     diag(p) <- changed(p), agent_touch(_, _, p).
   Gated on use + refreshed in BOTH full and incremental tick paths (like changed).
   Reactivity insight: the agent's own repo edit triggers the tick; by then the
   harness artifact already records it -> no need to watch ~/.
2. TURN TEXT (dl example, not builtin): banned-word-guard.dl scans transcript
   JSONL for banned word in assistant records (turn text) + ExitPlanMode bodies
   (plan tool), exact byte spans, latest-turn-scoped. Catches what agent_touch
   can't (text, not file paths).

Adapter mechanics learned:
- Claude Code: slug = abs repo path, non-alnum -> '-'; newest *.jsonl by mtime;
  line = record, idx = line; assistant tool_use Edit/Write/MultiEdit input.file_path.
- opencode: ~/.local/share/opencode/opencode.db (SQLITE); session WHERE
  directory=repo ORDER BY time_updated DESC; part.data JSON {type:tool, tool:
  edit|write, state.input.filePath}; idx = message rank (siblings share idx).
- Store paths overridable: SPREFA_CLAUDE_PROJECTS / SPREFA_OPENCODE_DB (testable).

## Key Insights
- match is a SOURCE op (needs its own scan); can't join a file bound from another
  rel. So word-detection lives WITH scan, not in the generic policy.
- one-rel-one-rule-kind: a rel headed by both source(scan/match) and derived rules
  bails. Adapters that scan must head their own rel; union via derived-only rules.
- ${} regex hole does NOT desugar in match() position ("repetition quantifier"
  error). Hardcode the banned alternation /(?i)(?<w>nuke)/ like .dl/rails.dl.
- text capture coerces to file/Path and joins changed() cleanly -- no engine change.
- agent_touch keeps (harness,session) = tagged union, NOT broadcast; project labels
  away (agent_touch(_,_,p)) only if you WANT uniform treatment.
- ACP = Zed+JetBrains, not Anthropic; consuming it never needed Anthropic. Trait
  makes it one optional impl; at-rest tier is robust to harness-field churn.
- MCP = transport not capability; query power is in the engine already.
- authorship/similarity query ~80% expressible NOW (call_edge fan-in +
  propose_clone + scan glob); only missing the author dimension.
