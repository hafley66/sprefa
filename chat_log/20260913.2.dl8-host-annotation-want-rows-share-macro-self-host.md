## Solution/Approach (the settled vocabulary)
- **Host is a node annotation.** A hosted relation is an ordinary product whose declaration label is the constructor application `Host`: `(: fetch_json (Host (* (: (Key "url") text) (: body json))))`. Same shape as `(: PairUser (Pair User))` currying in `5_curry.dl7` and `(Host ...)` in `11_host_source_sink.dl7:15` with the second product dropped. No `mode`, no `host` keyword, no clock, no template.
- **Key columns are the mode.** `(Key "url")` on the edge label marks inputs; the checker requires them bound, refuses a hosted relation as a rule head, places readers above the stratum that binds the keys. Currying a host = a Subject with a fixed key: `(: fetch_github (fetch_json "https://api.github.com"))`.
- **`want` rows.** When a hosted goal runs with its keys bound and no row exists, the evaluator writes `(want ?Host ?Key ?Rule)` instead of failing. It is the pending row = v6 `__demand_` = React's effect-list entry (deps array = key, fiber = rule/scope). Runner drains pending minus settled, matches on name like `Kernel::of`, Live/Cached/Replay, writes settled rows; delta re-runs only readers. Alternative spelling with no name: the host relation's own key-only row (loses the rule column / refcount).
- **Cancellation is retraction.** Parent row replaced -> derived `want` rows retract -> runner aborts; late settled rows with no live want are dropped. switch/merge fall out of derivation + keys; only `exhaust`/`concat` need a policy word. Nesting = scope column = parent key. Reconciler = the `apply` half of `reduce_then_apply`, one module in dl8, state `HashMap<(Kind, Scope), Vec<Key>>` + task handles, the only impure component.
- **rx operators = rule shapes**; `share({resetOnRefCountZero: () => timer(60_000)})` = five prelude rules over `want`: `readers` (count), `idle_since` (pre + now, carried while idle), `grace` (deadline via a `timer` host with `(Key "at")`, `not` fired), `keep` (readers or grace). Generic over `?Host`. Surface `(share fetch_json 60000)` is a macro emitting those rules through the same `syntax_claim` protocol as `<+` (`0_standard.dl7:81-95`, `_1_macrotime/_2_protocol.rs`, fixture `15_standard_plus.dl7`, ported).
- **Key on the whole edge**: via kernel `edge_ref` (owner,label -> ref(edge)), spelling `(Key (: account int) Opts)` lowered to the edge plus `(Key (edge_ref Owner "account") Opts)`; `keyed_edge` becomes a join on `edge_ref` + `Key`. Label keys are structural (shared interned node), edge keys are nominal (per product); type algebra must read both or pick one.
- **Server codegen** = emitter rules producing `emits` text rows from `route` rows + hosted relations (`render_rust.dl6` shape); the reconciler is the runtime loop. **Self-host** = stage0 dl8 Rust -> stage1 compiler-as-dl7 (reify, then check, then lower as rules over syntax rows) -> Rust emitter -> stage2 must equal stage1 on 46 cases. Kernel (~3k lines: term store, semi-naive+demand, reconciler, reader) stays Rust.
- Term kinds today: Int, Atom, Str, Compound; floats/bools needed for a runtime; null never (v6 ruling 2026-07-30).

## Key Insights
- Every invented keyword collapsed into something already in the language: Effect -> hosted relation, Clock -> source relations, Policy -> retraction + keys, mode -> Key columns, host keyword -> Host constructor on the node.
- `edge_ref` exists in the kernel with no fixture using it; whole-edge annotation is its job.
- The evaluator's only new branch is "Host node: write the goal down instead of failing".
- Macros (`<+` protocol) are the rx surface; prelude rules are the semantics; `want` is the one evaluator-level row under both.
