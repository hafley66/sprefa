## Key Insights
- SQLite can't ALTER a PK -> table rebuild for migration; gate with column_exists
  (pragma_table_info). Fresh dbs get new schema from CREATE TABLE IF NOT EXISTS;
  old dbs keep cols -> rebuild. Stamp self_slug so next reconcile prev/current keys
  match (no false churn).
- Per-repo isolation (own Engine per root) sidesteps module-graph-union WITHOUT
  threading repo through the whole module graph. That's why repo-aware --move
  shipped without module-repo-awareness. A single-pass cross-repo move needs the
  module graph repo-aware.
- rev.id PK collides on shared "WORK" across repos (dedup by id keeps first);
  committed revs are unique shas. Acceptable residual.
- Rust use-paths are crate-local, so cross-repo rename mostly = pick which repo;
  --repo slug/"*" is the right shape, not byte-span cross-repo threading.
- repo relation contract preserved: config-when-present (test asserts exactly N),
  else distinct-from-_file/self. Don't list self when config loaded.
- Verified live: two repos sharing src/lib.rs -> 2 distinct file rows; warm run no
  churn; old-schema db migrates; scan("*") returns both; --repo ra --fix rewrites
  ra only; --repo "*" fans out; unknown slug + star-no-config error.
