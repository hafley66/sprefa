## Key Insights
- VS Code's LSP server process is sticky: extension reinstall + window reload do NOT kill the spawned LSP child. Only Cmd+Q on VS Code or explicit killall sprefa-lsp forces a respawn from the on-disk binary. Any "I rebuilt but the bug persists" loop with the LSP needs the kill step verified before assuming the fix is wrong.
- DiskFileSource docstring vs code contradicted itself: doc claimed all revs short-circuit to worktree, code gated on rev == self.rev. Either the doc was forward-looking (predicted post-fix behavior) or the gate predates the doc and was a bug from day one. git blame on the gate would tell us which; a recent fingerprint of bug-from-day-one would be that the user said "this _did_ use to work" -- meaning something else regressed, not the gate.
- 1ms LSP hover total time is a strong "did not actually walk the filesystem" signal even before reading the cursor counts. Bake this into pattern for diagnosing "ran but did nothing" cases.
- ANSI escape codes in VS Code's LSP output channel appear literal because the channel is a plain string sink, not a terminal. Force with_ansi(false) on tracing_subscriber when the writer is not a TTY.
