## Problem/Context
v5 is declarative, file-reactive, SQL-fixpoint over sqlite. ghcacher is effectful/stateful/time-driven/external-IO. Seven primitives needed (decomposed from ghcacher src): row-driven cmd, structured capture (status+headers+body), a carry relation (read-last-tick/write-this-tick), a guard, a clock/interval source, change_log-as-relation, stable named output tables. Only the carry relation changes evaluation semantics. v4 already built an rxjs-shaped version (cursors + `>` pipe + generations + dirty-bus + support-count retraction + gh.* mounted-query + change_log wake) which v5 deliberately dropped (no DD/runtime_graph/support machinery, per memory feedback_no_dd_vocabulary).

## Solution/Approach
Prior-art survey landed on Path B "time-as-data" (Datomic tx-column + Bloom @next/@async modifiers) as the cheapest principled add that rides v5's existing `rev` spine and incremental tick WITHOUT resurrecting DD machinery. Other paths: Path A threaded-token (Mercury io.state/Haskell IO — fights datalog set semantics, reintroduces imperative spine); Real IVM (DBSP z-sets — months, reintroduces delta runtime); demand-tabling (extend --changed — what v5 already half-is). Bloom gives two rule modifiers: `@next` (head staged to next tick = carry state) and `@async` (body fires effect, response lands later = poll IO).

Implemented @next as: `_carry_meta(k,tx)` generation clock; `_carry_<rel>(cols..,tx)` buffer PK(cols..,tx); `lower_rule` refactored to `lower_rule_to(rule,rels,target,extra)` so carry reuses exact body lowering redirected to carry table + constant tx col; tick() partitions @next out of all_derived, loads carry@cur into live rel before reconcile/derive, stages bodies into carry@cur+1 after convergence, advances tx. Guards: carry rel headed by source/derived too = bail; @async = bail loudly (next slice).

## Key Insights
- The one semantic delta is "carry reads as EDB for this tick": a @next head rel has no source-op body yet must read from carry before rebuild_derived, and must be excluded from derived_rels so the `DELETE FROM rel` doesn't wipe it. This routes around the existing source/derived collision bail (engine.rs ~1981).
- @next stratifies the `p <-@next not p` paradox by construction: head lands at tx+1, negation reads tx, never the same generation.
- `@` was completely unused in the lexer (default arm bails "unexpected char"); `<-` lexes as Tok::Arrow independent of what follows, so `<-@next`/`<- @next` lex identically. Modifier is a standalone Tok::At(String) after Arrow, NOT fused with the neck.
- v5 today = Path B by hand (SQL fixpoint + rev + --changed + LSP-on-demand = Salsa-over-SQL with a Datomic-ish rev column). @next + @async are the named declarative form of what's already hand-rolled.
- The self-hosted agg gate (tests/it/agg.rs) asserts exact fan-out over sprefa's OWN type graph; adding a type/variant drifts it (Tok 28->29 from Tok::At) — re-pin expected, it's designed to.
- Style: user wants dry/data/tables, no em dashes, no provenance/substrate/load-bearing/regime; N+1 = never per-row write (insert_rows once); one rel = one rule kind.
