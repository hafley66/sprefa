## Problem/Context
**THE FIXPOINT BUG (real cause, not what the last session recorded):** the
applied diff called `applyLevelStatement(..., afterEdges=true, ...)` inside
`applyLevelsBeforeEdges` (1_incremental.ts:834). `levelFrontierCopies(true)`
writes nextFrontier, and `promoteFrontiers:1128` reads carry as
`EXISTS(nextFrontier)`, so every closure round minted a whole extra TICK. The
suite was 9 red (not 6), and the failures were tick-boundary breaks
("5 files in one window must be 1 tick, got 2"), never stale goldens. Fix =
`afterEdges=false`, rounds stay on the frontier at phase 2.

**THE CATALOG COLLISION (my brief's defect, not the lane's):** a rule naming
`__catalog_rel` puts it in AllRefs, so `rel_ddl/6` built a guessed table with
columns named after the caller's variables (a,b,c,n,e,f all TEXT) AND the
catalog code built the real one. Two `CREATE TABLE "__catalog_rel"` in one DDL
array; boot dies on the second. Verified by compiling a reader program.

**THE EMITTER DEFECT (found by 3 of 4 fork lanes, verified by me):** a rel name
with a dot compiled clean and emitted `orchard.tree: ["col1"],` into
`const relColumns` -- an unquoted object key, a JS syntax error, so the module
cannot be imported and NOTHING refused it anywhere on the path.

## Solution/Approach
- **Fixpoint:** rounds repeat while a head on a CYCLE of the level graph writes
  rows (`recursiveHeads/2`), staged frontier-only. Fail-pre-fix fixture
  `flagship_flow_reach_over_batched_resolved_edges` feeds both hops in ONE tick;
  stashed runtime loses `flow_reach(app,entry,sink,persist)`, fixed matches oracle.
- **Catalog g1:** `compile.pl:131 materialize_catalog_rel/2` injects the
  contract's col_type decls when a rule names the catalog, so the ORDINARY
  `rel_ddl/6` path builds the table with INTEGER/TEXT storage; `compile.pl:175`
  subtracts it from ArrivalTargets; `lower.pl` mints only the child-walk index
  plus one `INSERT OR IGNORE` carrying every row. End-to-end receipt: a rule
  derived `__catalog_rel` and `rel_named`, EXPLAIN says
  `SEARCH __catalog_rel USING COVERING INDEX __catalog_rel_parent`.
- **Emitter:** `js_object_key/2` leaves a plain identifier bare and quotes
  anything else. 7 sites route through it. First attempt double-quoted
  `struct_ref_column_entries/2` (which already quoted) and moved 21 modules;
  reverted that one site.
- **Killed `__catalog_instance`:** a declared type ALREADY compiles to
  `CREATE TABLE ... ("__id" INTEGER PRIMARY KEY, ..., "__refcount" ..., UNIQUE(cols))`
  plus a `__ref_<Type>` TEMP view (lower.pl:766-782). The digest is a constraint
  SQLite enforces and the id is a rowid it mints. TS needs its instantiations map
  because it instantiates lazily in memory; this compiler emits DDL ahead of time.

## Key Insights
- nextFrontier IS the carry signal. Writing it mid-tick does not add a round, it
  adds a TICK. Any future in-tick loop must stay on the frontier at phase 2.
- The compiler auto-invents a table for ANY rel name it sees, guessing column
  names from the caller's variables. Declaring the name first is what stops it.
- `table_name(Name/_Arity, Name)` at lower.pl:162 DROPS ARITY. Corpus scan says
  `fixtures=302 refs=1074 same_name_two_arities=0`, so it has never fired. It
  still emits two `CREATE TABLE "edge"` for edge/2 + edge/3 in one program.
- Two programs booted into one server database collide on catalog ids: ids are
  positional per compile and `serve/4_http.ts:156` opens ONE connection for the
  server's life. Demoed rel_id 6 existing twice.
- typescript-go (`internal/checker/types.go:673`) gives every type ONE struct
  with id + kind mask + variant pointer, and interns instantiations by an xxh3
  hash of type IDS with a discriminator byte per key kind. Go seeds primitives as
  ordinary Universe-scope objects. TS `boolean` is a union of two literals in
  BOTH the JS checker and the Go port.
- d2 `sql_table`: `style.stroke` paints the ROW BACKGROUND. Never style one.
- d2 aspect ratio is set by direction+engine ahead of content: same 40-shape
  diagram measured 7.06 at right+elk and 1.15 at down+dagre.
- A clean d2 compile says nothing about readability. Every unreadable version
  exited 0. Render a PNG and look at it.
- opencode/tmux lanes emit NO completion events. Every lane brief must end with
  `bus hail --to <coordinator>`; I omitted it from all 9 briefs today and used a
  Monitor instead (which also fires if a lane dies with no REPORT.md).
- Flash lanes stopped correctly on a missing node_modules rather than installing.
  Both opus lanes caught that my SPEC cited an UNTRACKED plan doc absent from
  every worktree; both flash lanes worked around it silently.
- Nobody has built session-path recording+replay over a knowledge graph. The
