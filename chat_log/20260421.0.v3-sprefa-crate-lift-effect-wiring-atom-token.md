# Session: v3-sprefa-crate-lift-effect-wiring-atom-token

## Goal

Pivot from lang_prototype experimentation to a real `v3/crates/sprefa`
prod crate. Bulk-lift v2 as reference substrate, wire v3 `effect_runtime`
under it, start aligning parser with v3 language locks.

## What landed this session

### Crate scaffold

- New workspace member `v3/crates/sprefa/`. Added to `v3/Cargo.toml`
  members. Builds green: `cargo check -p sprefa --lib`.
- `v3/crates/sprefa/src/` is a verbatim copy of `v2/src/` minus `bin/`.
- All numeric file prefixes stripped (per the 2026-04-21 feedback):
  `_0_types.rs` → `types.rs`, `_5_op.rs` → `op.rs`,
  `ops/_0_rule.rs` → `ops/rule.rs`, etc. 62 files renamed.
- `store/_1_trait.rs` → `store/api.rs` (can't name a module `trait`).
- All `crate::_N_name` references rewritten to `crate::name` by
  scripted substitution (sed-by-python). Missed a few residuals in
  `store/sqlite.rs`, `store/migrations.rs`, `init_cursors.rs`; caught
  and fixed.
- `Cargo.toml` rewritten: package `sprefa`, strip v2 binaries,
  keep all deps, add `effect_runtime = { path = "../effect_runtime" }`.
- `lib.rs` header rewritten — this is not a v2 port, it's where
  op-plugin × language × core converges. v2 is substrate.

### Effect-runtime wiring (first seam)

- `OpCtx.rt: effect_runtime::RtCtx` added. Every op can now
  `ctx.rt.put::<E>(effect).await`.
- New module `crates/sprefa/src/effects/` with:
  - `read_bytes.rs` — `ReadBytes { repo, rev, fs } → Bytes`
    EffectKind; default `ReaderBackedBatcher` (Passthrough-style,
    delegates to the `Reader` stack).
  - `mod.rs::build_default_rt(reader)` — registers default batchers.
    One-line op authoring: add new effect = one file + register in
    `build_default_rt`.
- `OpCtx::for_test` and `init_cursors::spawn_mutation_handler` both
  auto-wire `rt` via `build_default_rt`. Test sites never edited.

### Rule op slim (v3 semantic model)

- `RuleOp::pipe` no longer auto-seeds the cartesian of
  `reader.repos() × reader.revs()`. v3 rule = named Pipeline; the
  body owns enumeration (`repo`, `fs`, nested `rule`, etc.).
- Seed is one empty cursor. Body runs. Post-body:
  - `writer.create_rule_table(&spec)` + `writer.write_rows(...)`
  - `ctx.result_store.append(rule_name, captures)` — "the global
    sprf path table" for xref consumers.
  - `result_store.mark_complete(rule_name)` on stream end.
- Parse-time responsibilities (unchanged): derive `RuleTableSpec`
  from body captures, register rule handle in `ProgramCtx.rules`,
  lower body into `Pipeline::Op/Seq/Fork`.

### Language core: `:atom` value type

- `TokenClass::Atom(AtomRef { name })` added to `parse.rs`.
- `parse_atom(":foo") -> Some(AtomRef)`; `classify_token` routes.
- Exported from `lib.rs`.
- `rule(:name)` now required. Previously rule accepted `rule(name)`
  raw ident; v3 has no unprefixed-ident value type. Rule op
  delegates to `classify_token`; any non-Atom token yields
  `rule/name-must-be-atom` diagnostic.
- Initial commit had the atom-parse logic inlined inside `rule.rs`;
  pushed down into the language core after user correction
  ("none of this is rule specific and needs to be in language core").

## What did NOT land this session (explicitly acknowledged)

| lock | status |
|---|---|
| `:atom` is the only way to write an atom | token class added; op rejection pending |
| `rule(:name, $P1, $P2)` parametric rules | paren is still opaque `paren_src`; no param parser |
| Retire `$$sigil` scan-pointer class | still `TokenClass::ScanPointer`, still parsed |
| `${any_pipeline}` generalized carveout | only `${rule.$VAR}` xref form parsed |
| `> $X` capture-write station | chain-step must be op-call today; bare `$X` would fail parse |
| `&.field` / `&.$X` | works via cursor_ref op |
| `&{computed}` | absent |
| `assert(...)` as a Decl | absent |
| Casing-as-syntax (lowercase=op, UPPERCASE=term) | convention; no enforcement |
| Sub-grammar bare bodies `glob{foo/$X}` | walker handoff exists; no `${{...}}` escape |
| Balanced-brace carveout pre-pass | absent |
| tree-sitter grammar.js | hand-rolled parser unchanged |
| `@recursive(N)` attribute | **explicitly deferred this session** |

## Next session plan: parser v3 merge + lowering

Priority order (user said "go hard at wiring language parsing v3
merge and its lowering changes"):

1. Close the open match-site compile errors from `TokenClass::Atom`
   and `RuleDiag::NameMustBeAtom` additions. Each op that matches on
   `TokenClass` gets an `Atom` arm; those that accept atoms use them,
   those that don't emit their own diagnostic.
2. **Parametric rule params**: parse `rule(:name, $P1, $P2)` in
   `rule::parse`. Split paren_src on commas; first token must be atom,
   rest must be captures. Extend `RuleHandle` with `params: Vec<Arc<str>>`
   (it already has `captures` — keep distinct).
3. **Retire `$$sigil`**: `parse_scan_pointer` stays as a parser primitive
   but returns a warning diagnostic at lower time. Tag-ops
   (`is_repo($R)`, `is_rev($T)`) become the replacement. Keep the
   `classify_token` arm so parser is tolerant; emit deprecation diag.
4. **Generalized `${...}` carveout**: v2's `parse_cross_ref` only handles
   `${rule.$VAR}`. Extend the `${...}` lexer carveout to capture any
   balanced brace range, return `CarveoutCarveout { raw: Arc<str>, range }`
   alongside the existing `CrossRef` shape. The lowerer decides which
   is which based on content. Balanced-brace pre-pass runs before
   sub-grammar walker.
5. **Capture-write station `> $X`**: in chain parse, accept a bare
   `$X` token at chain-step position; lower to a new
   `CaptureWriteOp { slot: Arc<str> }` that copies current cursor
   active bytes (or the upstream value) into `$X`.
6. **`assert(:name) { ... }` decl**: add as a second `Decl` kind
   alongside `Rule`. Lowers to a named Pipeline with a trailing
   violation-emit op. Shares the rule-table machinery.
7. **Casing enforcement**: at classify time, a bare ident starting with
   a lowercase letter is a legal op name; an uppercase-led ident is
   rejected unless preceded by `$`. Two diagnostics, symmetric.

### Lowering changes (follow-on)

- `ProgramCtx.rules` table keyed by Atom-valued name (already is).
- `RuleHandle` gains `params: Vec<Arc<str>>`, `param_modes:
  Vec<AcceptsMode>`, `schema: RowSchema` (columns = `arg_<param>` +
  `<capture>`).
- `Pipeline::OpCall` gains a path for rule calls with args:
  `rule_name(:other_atom, $X)` lowers to
  `Pipeline::Op(RuleCallOp { name, args: Vec<ArgValue> })`.
- `ArgValue` enum lives in `op.rs` or `lower.rs`; initial variants
  `Atom(Arc<str>)`, `Capture(SlotKey)`, `Pipeline(Arc<Pipeline>)`
  (for carveouts).
- `TermMode::{Bound(Scalar), Unbound(SlotKey)}` computed per-cursor
  at op entry; `OpCtx::resolve_term_modes(cursor, &[ArgValue])` helper.
- `ArgSpec { accepts: AcceptsMode }` declared by op `Operator` trait.

## Open questions parked for next session

- Should parametric rule args use `(:atom, $CAP)` positional syntax or
  `(:name | $P1, $P2)` separator to distinguish rule-name from params?
  Semantic-model §3.4 uses `rule(used_by, $CLASS)` — first positional
  is rule name, rest are params. In v3 with atoms: `rule(:used_by, $CLASS)`.
- Capture-write `> $X` — does `$X` bind the active bytes as a string,
  or the whole cursor's emit value (captures)? Lock says upstream
  primary term; clarify at implementation time.
- `${...}` carveout at lex vs parse — pre-pass in lexer extracts a
  balanced-brace raw-range which then parses as host-expr. Decide
  ownership: lexer returns tokens + holes, or parser re-enters.
