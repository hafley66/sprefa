## Key Insights
- User explicit: annotation inner is bare capture ONLY, not a pattern. `$$repo($REPO)` captures AND annotates same token. Walker stays annotation-unaware; annotation is pure sidecar metadata on JsonOp for future Pass A discovery.
- `json({...})` body lives in `paren_src` with `BraceMode::Forbidden` — the brace is syntactically inside the paren delimited section, not a separate brace arg. Reviewing `_4_read.rs` + spec initially suggested BraceMode::Required which was wrong. Fixed by agent inline.
- `glob_match("**/foo", "foo")` returning false was a real bug, not an fs convention issue. Fix strip_prefix("**/") + recurse on suffix. Narrow — doesn't regress repo/rev callers since they don't use `**/` prefix.
- Writing integration tests BEFORE the implementation gives sonnet a concrete spec and forces the auditor (me) to think through shape decisions upfront. Continue this pattern.
- Two parallel sonnet agents = fine when scoped to disjoint files. Both edited `sprefa_v2.rs` to drop `.message()`/`.rule_name` for the same API reason — converged on identical fix without collision. Would not be safe if scopes overlapped more deeply.
- `pipe.ops[0].paren_src.src` is how to recover a rule's name from a Pipeline in the current API — Pipeline itself doesn't carry it. Worth promoting to a helper if a third caller appears.
