## Solution/Approach
One Hopp-shape topology composes all three axes via trait objects. Each
axis has a parser (parse_effect / parse_arrival / parse_policy / parse_ext_filter).
CLI flags: --effect --arrival --policy --ext.

Spec grammar:
- kvs use `,` separator
- values inside kvs use `/` separator (so `:` stays shape-reserved)
- --effect synthetic:flat:200,fixed=50,work=fixed/0
- --effect sqlite-real:journal=MEMORY,sync=OFF,scan=true
- --effect git-odb-real:repo=PATH,oid_cap=N,scan=bool
- --arrival sine:period=500,amp=200,base=20
- --policy windowed:2000  (US)

TSV output added policy column — field extractors in validate_v2.sh
shifted by 1.

## Key Insights
1. Opportunistic batching under paced arrival structurally collapses to
   batch=1 — consumers outrun producer, try_recv always empty. This is
   the batching-jutsu red flag manifesting end-to-end.
2. Throttle-time buffer (windowed:US) fixes it by decoupling batch size
   from instantaneous arrival rate. B8 shows 31-item batches vs 1.
3. Real sqlite :memory: amortization (4.4×) is much smaller than
   sleep-model (23.8×) — :memory: per-tx cost is dominated by prepare
   + COMMIT bookkeeping, not the 500µs sleep the model assumed.
4. Git ODB under Mutex<Repository> at high W with sub-µs work per read
   hits thread-parking storms. scan=true hides this because scan work
   dominates parking overhead.
5. Per-sleep floor on this macOS box: ~270µs (consistent with v1 calibration).
6. v2 TSV adds `policy` column between `arrival` and `seed` — v1 sweep.sh
   parsers must be rewritten, not reused.

## Open Questions
- Why does windowed-trailing batch_p50 land at 31 when fixed:50µs across
  2000µs window predicts 40? Platform sleep floor eats into the window.
- Does real git2 ODB benefit from per-worker Repository handles (Send but
  !Sync)? Scaffold uses shared Mutex; per-worker would trade contention
  for open-file cost.
- Sleep-model B4 predicts 23.8× amortization; real sqlite-real B6 shows
  4.4×. Which do real sprefa workloads look more like? Probably depends
  on whether the write path is file-backed + fsync or :memory:.
