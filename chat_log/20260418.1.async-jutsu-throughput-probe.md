## Findings (swc corpus, 8-core Apple Silicon)

**At 2k files:**
- A sequential: 3,900 f/s (per-core ceiling)
- All parallel variants: 18-20k f/s, within 10% of each other
- Batching HURTS: Cbatch/Dbatch are 5-15% slower than their unbatched siblings
- RAM: sequential 19 MB, rayon-dam 40-50 MB, tokio 55-65 MB, hold-all 48 MB

**At 10k files:** best throughput cluster (~32-33k f/s), RAM 70-90 MB

**At 40k files (full corpus): throughput COLLAPSES to 13-15k f/s**, RAM climbs to 900-1200 MB. All parallel topologies converge — dam/batch/tokio/hold-all all within 10% of each other. **Sequential scales best in efficiency** (1.56× vs 2.0-2.5× sub-linear for parallel) because it never holds more than one parse tree.

## The real lesson

The throughput knee between 10k and 40k is not a topology problem. It's the "scan all, hold results" shape itself. Any version that retains parse trees and source across files pays linear RAM — bounded channel, tokio stream, batched, not batched, they all end up at ~1 GB RSS at 40k because the in-flight parse trees dominate.

**This validates sprefa v2's architecture**: `Op::pipe` returning `BoxStream<Arc<[Cursor]>>` where cursors carry content only transiently. Streaming results OUT breaks the RSS linearity that all these probe variants share.

## Glossary (for future-self / compaction)

Perf-stat terms referenced in the aggregator output:

- **p50 / p95**: 50th / 95th percentile wall time (sorted). p50 = typical run. p95 = bad-case.
- **stddev (σ)**: spread of samples around mean, same units as the metric.
- **CV%**: coefficient of variation = stddev / mean × 100. Unitless. <5% tight, 5-10% fine, >10% noisy, >20% don't trust.
- **IQR, Q1, Q3**: interquartile range = Q3 - Q1. Middle 50% of data.
- **Tukey fence**: drop samples above Q3 + 1.5 × IQR (and below Q1 - 1.5 × IQR). Standard outlier rejection.
- **RSS (max / resident set size)**: physical RAM held by the process at peak. From `/usr/bin/time -l` on macOS (bytes), Linux `time -v` (KB).
- **warm-up vs cold**: warm = steady state (caches, JIT, allocator all hot). Cold = first run. Always measure warm unless cold-start is the question.

## Step 4 — variant F (streaming sink, the RSS-flat thesis)

**Purpose:** prove that the 10k→40k knee disappears when the pipeline never materializes per-file results.

**File:** `v2/examples/throughput_probe.rs`

Add `variant_f_stream` AND drop-variant `variant_f_drop`. Both should produce flat RSS vs file count — testing complementary mechanisms (streaming vs explicit drop).

```rust
// F: streaming sink. Producer emits (bytes, matches) into a bounded channel
// where the consumer folds on the fly. Zero Vec<Item> at any point. This
// should show RSS flat across 2k/10k/40k — the knee is about accumulation,
// not parallelism.
fn variant_f_stream(paths: &[PathBuf], pat: Arc<Pattern<SupportLang>>, lang: SupportLang, cap: usize) -> (u64, u64, u64) {
    use std::sync::atomic::{AtomicU64, Ordering};
    let files   = Arc::new(AtomicU64::new(0));
    let bytes   = Arc::new(AtomicU64::new(0));
    let matches = Arc::new(AtomicU64::new(0));

    let (tx, rx) = mpsc::sync_channel::<(u64, u64)>(cap);

    // Consumer: fold on receive, no Vec.
    let consumer = {
        let files = files.clone();
        let bytes = bytes.clone();
        let matches = matches.clone();
        std::thread::spawn(move || {
            for (b, m) in rx.iter() {
                files.fetch_add(1, Ordering::Relaxed);
                bytes.fetch_add(b, Ordering::Relaxed);
                matches.fetch_add(m, Ordering::Relaxed);
            }
        })
    };

    paths.par_iter().for_each_with(tx.clone(), |tx, p| {
        // Explicit scope so src + grep drop before the send. Belt-and-braces
        // with variant_f_drop below — here we rely on inner-scope drop.
        let r = {
            let Ok(src) = std::fs::read_to_string(p) else { return };
            let grep: AstGrep<StrDoc<SupportLang>> = lang.ast_grep(&src);
            let m = grep.root().find_all(&*pat).count() as u64;
            (src.len() as u64, m)
            // src and grep drop here
        };
        let _ = tx.send(r);
    });
    drop(tx);
    consumer.join().unwrap();

    (
        files.load(Ordering::Relaxed),
        bytes.load(Ordering::Relaxed),
        matches.load(Ordering::Relaxed),
    )
}
```

Register in `run_once`:
```rust
} else if let Some(cap) = variant.strip_prefix("Fstream:") {
    let cap: usize = cap.parse().expect("Fstream:<cap>");
    variant_f_stream(paths, pat, lang, cap)
```

Add to harness variant list: `Fstream:256`.

**Acceptance for the thesis:**
- `Fstream:256` RSS at 2k ≈ RSS at 10k ≈ RSS at 40k (within ±50 MB). All three in the 40-80 MB band.
- `Efat` RSS grows roughly linearly (2k: 48 MB → 10k: 93 MB → 40k: 1000 MB).
- If Fstream does NOT stay flat, the thesis is wrong — the cost is in the parse trees being GC-delayed, not in the Vec holding them. Then the fix is somewhere else (per-file `drop(grep)`, smaller tree-sitter arenas, or arena reset).
