## Solution/Approach

### What landed (architecturally)

```
RelationStore
  inner:  Mutex<HashMap<Name, Bag>>
  bodies: Mutex<HashMap<Name, Arc<Pipeline>>>   # rule bodies, unused yet

Bag
  rows:      Vec<Row>
  broadcast: Vec<SubjectKey<RelationWake>>      # QueryOp parks here
  keyed:     HashMap<Vec<Arc<str>>, Vec<SubjectKey<>>>   # ProbeOp Reactive parks here

ops/relation/
  mod.rs    — RelationArg, materialize_row, rows_to_batch
  write.rs  — WriteOp (BATCH: one WriteEffect per pipe-batch)
  query.rs  — QueryOp (drain + perpetual subscribe via broadcast waiter)
  probe.rs  — ProbeOp Static (batched probe_keys) + Reactive (per-cursor lookup_or_subscribe)
  join.rs   — JoinOp (snapshot once + cursor×row fan-out)

ops/tag.rs
  TagOp { Write, Query, Probe, Join }    — enum, registered as "tag" + "tag?"
  TagPredicateOp(TagOp)                  — newtype facade for "tag?"
```

- `OpCtor` trait surface (per user instruction).
- `RtCtx` / `RtCtxBuilder` surface.
- `SubjectKind` / `SubjectRegistry` API (RelationWake just renamed TagWake).

## Key Insights

1. **Grammar `?` suffix added cleanly.** `optional(field('predicate', '?'))`
   sits between identifier and bracket/paren slots; no conflict with
   `${X?}` (which is inside paren_slot body, different scope). One
   `tree-sitter generate` run produced a working parser.c. ABI 14
   warning (no tree-sitter.json) is harmless.

2. **Registry name aliasing handles `?` without trait churn.** Two
   OpCtor impls (TagOp, TagPredicateOp) under names "tag" and "tag?".
   Server lowerer flips name based on `inv.predicate`. No registry API
   change, no OpCtor signature change.

3. **lookup_or_subscribe closes the keyed-probe race.** Static probe
   uses probe_keys (no race). Reactive needed an atomic lookup-then-
   subscribe; calling lookup_by_key followed by snapshot_or_subscribe
   has a window where a write between the two calls would fire and
   then we'd subscribe under a key the writer already drained.
   `lookup_or_subscribe` does both under one bag lock.

4. **N+1 fix preserves SQLite shape.** WriteEffect's Vec<(name, row)>
   maps to one INSERT-many. probe_keys maps to one
   `SELECT WHERE key IN (...)`. The runtime layer's per-effect dispatch
   was the wrong granularity for relation hot paths; ops should batch
   over the pipe-batch, not the row.

5. **Reactive ProbeOp is fundamentally per-cursor.** Each cursor's wait
   is independent — can't share a future. Acceptable today: reactive
   probes only fire when a cursor actually needs to park. Filed audit
   card to revisit if hot loops show up.

6. **Stream surface is `BoxStream<Arc<[Cursor]>>` everywhere.** User
   pushed back on per-cursor stream surfaces; verified that all ops
   carry Arc<[Cursor]> batches. Internal per-cursor decomposition only
   inside reactive subscribe (necessary because each parks independently).

## Open Questions

1. **Rule body terminal-cursor sink.** The body sub-pipeline emits
   terminal cursors. We need to drain that BoxStream and convert each
   cursor to a row in the rule's bag. Open: how to represent "row" from
   a cursor? Probably `cursor.captures.iter().filter(matches param
   names).map(bytes).collect::<Vec<Arc<str>>>()` against the rule's
   parameter names.

2. **Rule call argument binding.** `foo($X, $Y)` at call site needs to
   bind body's `X` param to caller's `$X` capture value. Probably emit
   a wrapper: rename caller's $X to body's X under a per-call cursor
   transformation.

3. **Two-pass lower scoping.** Does pass 1 walk `program.pipes` only?
   Or also recurse into brace_slots (rule bodies can define nested
   rules)? Punt: top-level only for v0.

4. **Recursion deadlock.** Card says "not disallowed in impl, not tested."
   Reactive probe parks on Yield<RelationWake>. Recursive call cycle
   can park indefinitely. Document; don't fix.

5. **Cardinality fan-out.** JoinOp + drain query both fan out per row.
   Punted from kcl per chat_log/20260426.7. No lever picked yet.

6. **Mixed predicate empty-args edge case.** TagPredicateOp::from_values
   when both have_bound and have_unbound are false (empty arg list)
   currently builds JoinOp with no slots — passes everything. Probably
   the right behavior; flag if a user surface emerges.
