# JSON `$$$` Nested-Path Audit

Date: 2026-05-15  
Scope: read-only; no code edits.

---

## TL;DR (5 bullets)

1. v1/v2 had `**` in key position as recursive descent; it lowered to `SelectStep::Any` and was a PARTIAL implementation — single entry only, no `PATH` capture, no depth control.
2. v4's json walker is a faithful 1:1 port of that mechanism via `brace_parse.rs` lines 152-168 and `walker.rs::CompiledStep::Any`; nothing new was added.
3. No version has ever had `$$$` in a json body; the feature did not ship in any generation.
4. Recommended surface: **Option C** — `$$$` bare at key position as recursive descent, composing with `${X?}` for path capture.
5. Walker LOC delta is estimated at ~40 lines: 15 in `brace_parse.rs`, 20 in `walker.rs`, 5 in `compiled.rs`.

## Phase 1 — v1/v2 Archive: Prior Art

### Grammar (v1 / archive `crates/rules/src/types.rs` + `crates/sprf/src/_2_pattern.rs`)

The grammar comment in both `v2/src/walk/_4_brace_parse.rs:1-17` and
`crates/sprf/src/_2_pattern.rs:1-15` (the v1-era version) states identically:

```
key = "**" | "$" SCREAMING | "$_" | "re:" REGEX | glob_str
```

The `**` is in the key position of an `entry` (`key ":" pattern`), not in
value position and not a standalone sigil.

### `**` lowering (v2 — `v2/src/walk/_4_brace_parse.rs:132-148`)

```rust
// ** key means recursive descent: lower to Any + sub-pattern
if matches!(&key, KeyMatcher::Exact(s) if s == "**") {
    ...
    let mut steps = vec![SelectStep::Any];
    steps.extend(value_steps);
    return Ok(steps);
}
```

`SelectStep::Any` is the single recursive-descent primitive.

### `CompiledStep::Any` walker behavior (v2 `crates/rules/src/walk.rs:219-238`)

```rust
CompiledStep::Any => {
    let mut results = vec![];
    results.extend(walk_inner(node, rest, state)); // match at current depth
    match node {
        Value::Object(map) => {
            for (k, v) in map {
                let child_state = state.descend(Some(k));
                results.extend(walk_inner(v, steps, &child_state)); // recurse
            }
        }
        Value::Array(arr) => { /* same pattern */ }
        _ => {}
    }
    results
}
```

`steps` (not `rest`) is passed to the recursive call — this is the "keep
trying `Any` at each level" pattern: unbounded recursive descent.

### What `**:` actually meant in v1/v2

| Property | Value |
|----------|-------|
| Position | Key position of an object entry only |
| Syntax | `{ **: <pattern> }` |
| Constraint | Must be the **only** entry in its `{}` block (lone-entry constraint enforced) |
| Path capture | Not possible; `**` carried no variable binding |
| Depth | Unbounded; visits all reachable nodes |
| Lowered to | `[SelectStep::Any, ...value_steps]` |
| Tested in archive | Yes: `walk.rs:220-238` and brace_parse tests line 516-520 |

### v1 comment text (types.rs:219)

```rust
/// Descend through any number of levels (like CSS `**` or jq `..`).
Any,
```

### Gap between v1/v2 intention and reality

The user recall of "`**:` in the key position meaning 'any subobject'" is
accurate. But there was no path-capture form — `**:` was a depth shortcut,
not a recursive-search-with-binding. The v2 variant (`$$sigil($VAR)`) was a
different mechanism: it wrapped the leaf capture with a scan annotation
sigil (repo/rev), not a depth modifier.

### Brace-pattern grammar (brace_parse.rs:4-12)

```
pattern    = annotation | object | array | capture | wildcard | value_glob
annotation = "$$" IDENT "(" "$" SCREAMING ")"
object     = "{" (entry ("," entry)*)? "}"
entry      = key ":" pattern
key        = "**" | "$" SCREAMING | "$_" | "re:" REGEX | glob_str
array      = "[" "..." pattern "]"
capture    = "$" SCREAMING
wildcard   = "$_"
value_glob = (not , } ] )+
```

### Key matching (brace_parse.rs parse_key, compile.rs compile_key_matcher)

| Surface key | `KeyMatcher` variant | Compiled to |
|-------------|---------------------|-------------|
| `exact-string` | `Exact(s)` | `CompiledKeyMatcher::Exact(s)` |
| `glob*pattern` | `Glob(s)` | `CompiledKeyMatcher::Glob(matchers)` |
| `$K` (SCREAMING) | `Capture(name)` | `CompiledKeyMatcher::Capture(name)` |
| `$_` | `Wildcard` | `CompiledKeyMatcher::Wildcard` |
| `**` | `Exact("**")` — special-cased | `CompiledStep::Any` (not an entry) |

`**` is special-cased in `parse_object` (brace_parse.rs:152-168) before
going through normal entry processing: it bypasses `KeyMatcher` entirely and
emits `SelectStep::Any` directly.

### Descent mechanics (walker.rs:112-131)

```rust
CompiledStep::Any => {
    let mut out = walk_inner(node, rest, ctx, caps);    // match at depth
    match node.kind() {
        DataKind::Object => {
            for (k, v) in node.entries() {
                let child_ctx = ctx.descend_key(&k_text);
                out.extend(walk_inner(&v, steps, &child_ctx, caps)); // re-apply *steps*
            }
        }
        DataKind::Array => { /* same */ }
        _ => {}
    }
    out
}
```

`steps` (the full remaining chain starting at `Any`) is passed to the child
— unbounded depth, same as v2.

### "Match at any depth" primitive: exists as `**`

There IS a recursive-descent primitive already. It descends through objects
AND arrays. It carries no path capture variable.

### `${X?}` / `${X}` bind interpolations (brace_parse.rs:231-283)

`parse_capture_or_wildcard` handles:
- `$NAME` → `CaptureAny { capture: Some("NAME") }` — any value, any shape
- `${NAME}` → same
- `${NAME?}` → same (trailing `?` stripped at parse time, line 263)
- `${rule.$VAR}` → cross-ref Leaf (constraint form, not bind form)

There is no `$$$` handling anywhere in the json brace_parse or walk system.

### No "match at any depth" with path binding

The current `**` yields no capture for the path that led to the match.
`walker.rs::Ctx` tracks `depth: u32` and `parent_key: Option<Arc<str>>` but
neither is exported to the capture map.

## Phase 3 — Triple-Dollar Semantics for JSON

### Option comparison matrix

| Option | Surface | Boundary crossed | Path capture | Runtime cost | Conflicts |
|--------|---------|-----------------|--------------|--------------|-----------|
| A | `$$${PATH?}:` in key position | Object nesting depth | Yes — dotted path string | O(N nodes) | None |
| B | `$$${X?}` in value position | Object nesting depth | Yes — subtree value | O(1) per site | None |
| C | `$$$` bare (no braces) in key position | Object nesting depth | No (descent only) | O(N nodes) | None |
| D | `$$$ ${PATH?}:` combined | Object nesting depth | Yes — path string | O(N nodes) | None |

### Option A: `$$${PATH?}` at key position

```
json`{ $$${PATH?}: { name: ${N?} } }`
```

The `$$${PATH?}` key matches ANY path prefix (including multi-level descent),
binds the dotted path string (e.g. `"a.b.c"`) to `PATH`, and then the value
pattern `{ name: ${N?} }` applies at that node.

**Walker splice:** brace_parse must recognize `$$${X?}` in key position. It
lowers to a new `SelectStep::RecurseCapturePath { path_capture: Option<String> }`.
The walker for this step does a DFS over the whole subtree, at each node
trying `rest` — binding the accumulated path segments into `path_capture`.

**Compose with grammar:** the `$$` prefix currently belongs to
annotation sigils (`$$sigil($VAR)`). Using `$$${...}` would require the parser
to distinguish `$$sigil(...)` from `$$${ ... }`. At `*pos` the difference is:
after `$$`, if next byte is `$` then it is triple-dollar; if next byte is
`[a-zA-Z_]` then it is a sigil annotation. Unambiguous.

**Runtime cost:** O(N) where N = total node count in the subtree rooted at
the current walk position. Each DFS step tries the remaining `rest` chain,
which may itself be O(M). Worst case O(N*M). Acceptable for config-file
scale; inadvisable for 1MB JSON blobs.

**Coherence with `$$$` rule:** crosses the nesting-depth boundary, which is
the consistent meaning across DSLs (see Phase 4 table).

### Option B: `$$${X?}` at value position

```
json`{ users: $$${ALL?} }`
```

`ALL` binds to the entire subtree at `users`. This is already nearly possible
with the existing `$VAR` / `${VAR?}` brace-capture form since `CaptureAny`
captures any value including objects/arrays. The distinction of `$$$` here
would be semantic sugar for "I know this is a deep/complex subtree" — but
the behavior is identical to the current `$VAR` at value position.

**Verdict:** redundant with existing `CaptureAny`. Does not add power.

### Option C: `$$$` bare (no braces) at key position

```
json`{ $$$ name: ${N?} }`
```

`$$$` is a bare keyword at key position meaning "any nesting depth before
the next key match." It descends recursively until it finds an object with a
`name` key, then applies the value pattern.

This is identical in semantics to `**:` but under the `$$$` sigil convention.
The difference from current `**` is purely surface-level: `**` already exists
and works. If `$$$` is chosen, it is an alias for the existing `**` primitive.

**Walker splice:** trivial — `$$$` in key position lowers to `SelectStep::Any`,
same as `**`.

**No path capture.** To bind the path: `$$$` alone is the descent, and a
separate `${PATH?}:` in value position or a new `$$$${PATH?}:` compound form
handles the capture.

### Option D: `$$$ ${PATH?}` compound form

```
json`{ $$$ ${PATH?}: { name: ${N?} } }`
```

Two tokens: bare `$$$` descent + capture key `${PATH?}` as the key-capture
at the landing node.

**Walker splice:** `$$$` lowers to `SelectStep::Any`; the following
`${PATH?}:` lowers to an entry with `CompiledKeyMatcher::Capture("PATH")`.
The capture records the IMMEDIATE parent key at the landing level, not the
full path.

This is already expressible today as:
```
json`{ **: { ${PATH?}: { name: ${N?} } } }`
```
... which chains `Any` with a captured-key entry. So Option D is also
redundant, at least for single-level capture.

## Phase 4 — Comparison to Other DSLs

| DSL | Tight default | Boundary crossed by tight | `$$$` looser form | Boundary `$$$` crosses |
|-----|--------------|--------------------------|-------------------|------------------------|
| ast | single tree-sitter node | node kind | `$$$VAR` = sibling sequence | sibling list boundary |
| glob | `[^/]*` single segment | path separator `/` | `$$${X?}` = `.*` multi-segment | path segment count |
| re | `\w+` word chars | non-word chars | `$$${X?}` = `.*?` lazy any | character class boundary |
| json (proposed) | exact key match at current depth | nesting depth | `$$${PATH?}:` or bare `$$$` | object nesting depth |

The analogy holds:
- glob `$$$` crosses **path segments** (the `/` separator is the boundary)
- re `$$$` crosses **character classes** (the `\w` vs `.` boundary)
- json `$$$` crosses **object nesting levels** (the `{...}` depth boundary)

All three cases match the pattern "tight default stays within one unit of the
dominant structure; `$$$` expands to cross multiple units." For json the unit
is depth level; `**` already implements this crossing; `$$$` would be the
surface alias consistent with the per-DSL convention.

## Phase 5 — jq, XPath, JsonPath References

### jq `..` (recursive descent)

From the jq manual (https://jqlang.org/manual/):
> `..` — Recursive descent. Recursively descends `., .[]`, producing every
> value. This is the same as `recurse` without arguments. This is intended to be
> used on the left-hand side of a `,` to iterate over deeply nested values.

Grammar: `..` is a postfix operator applied to the current input. It
generates every node in the tree in a depth-first traversal order.

Usage: `.. | .name? // empty` finds all `name` fields at any depth.

The path is NOT captured by `..` itself; jq's `path(..)` or
`getpath`/`leaf_paths` functions handle path extraction as a separate step.

### XPath `//` (descendant-or-self axis)

From XPath 1.0 spec (W3C, section 2.5):
> `/descendant-or-self::node()/` — abbreviated as `//`. Selects the context
> node, all descendants, and all descendants of all descendants.

Usage: `//name` selects all `<name>` elements anywhere in the document.
The axis is: descendant-or-self. Combined with a step, it becomes a recursive
search. The `//` precedes a node test.

Path in XPath is an axis: the document structure. `//` crosses the depth
axis; `/` crosses one edge.

### JsonPath `$..` (recursive descent)

From the Goessner JsonPath spec (https://goessner.net/articles/JsonPath/):
> `$..` — Recursive descent, available anywhere a name is required.

Usage: `$..name` finds all `name` properties at any depth. `$..[*]` is all
values at any depth. Path elements before or after `..` continue to apply.

The `..` is always preceded by `$` or another selector step, making `$..name`
the idiomatic form.

### Mapping to v4 proposed `$$$`

| System | Syntax | Crosses | Path capture |
|--------|--------|---------|--------------|
| jq | `..` | depth | Via `path(..)` (separate op) |
| XPath | `//` | depth (descendant-or-self) | Via `//preceding-sibling::node()` etc. |
| JsonPath | `$..` | depth | Via `$..[*]` produces all paths |
| v4 proposed | `$$$` (key position) | depth | Via `$$${PATH?}:` optional capture |

The v4 proposal is closest to JsonPath's `$..`: a recursive-descent marker in
the path/key position that can optionally bind the accumulated path.

The existing `**` maps directly to jq `..` and XPath `//` semantically. The
addition `$$$` would preserve that semantic, adding optional path binding
aligned with JsonPath's approach.

## Phase 6 — Recommended Surface + Grammar Sketch

### Recommendation: Option A, with Option C as syntax

**Recommended surface:**

```
key_extended = "$$$" ("${" NAME "?}")? | ... (existing key forms)
```

Two forms:
1. `$$$ name: ${N?}` — bare `$$$` descends, next token is a normal key match at the landing node.
2. `$$${PATH?}: { ... }` — descent AND path capture into `PATH`; the value pattern applies at the landing node.

The `$$${PATH?}` form at key position is a compact encoding of "recurse AND
capture the path that led here." The bare `$$$` form (without braces) is the
no-capture descent alias for `**`.

### Three concrete usage examples

#### Example 1: Find any `image` field at any depth

Input:
```json
{
  "services": {
    "web": {
      "container": {
        "image": "nginx:1.21"
      }
    }
  }
}
```

Pattern:
```
json`{ $$$ image: ${IMG?} }`
```

Expected captures: `IMG = "nginx:1.21"`

How it works: `$$$` emits `SelectStep::Any`; walker descends recursively;
at each object it tries `{ image: ${IMG?} }`; match at depth 3.

#### Example 2: Capture the path alongside the value

Input:
```json
{
  "dev": { "image": "node:18" },
  "prod": { "image": "nginx:1.25" }
}
```

Pattern:
```
json`{ $$${ENV?}: { image: ${IMG?} } }`
```

Expected captures (two rows):
- Row 1: `ENV = "dev"`, `IMG = "node:18"`
- Row 2: `ENV = "prod"`, `IMG = "nginx:1.25"`

Note: this is ALREADY achievable with `{ $ENV: { image: $IMG } }` since
`$ENV` in key position is a `KeyMatcher::Capture`. The `$$$` form would add
depth-crossing: `{ $$${ENV?}: { image: ${IMG?} } }` would additionally match
`dev` or `prod` at any depth in the document, not just at the root level.

#### Example 3: Recursive dependency version extraction (k8s-style)

Input:
```json
{
  "containers": [
    { "name": "app", "image": "myrepo/app:v1.2.3" },
    { "name": "sidecar", "image": "myrepo/proxy:v0.9" }
  ]
}
```

Pattern:
```
json`{ $$$ image: "$REPO:$TAG" }`
```

Expected captures (two rows):
- Row 1: `REPO = "myrepo/app"`, `TAG = "v1.2.3"`
- Row 2: `REPO = "myrepo/proxy"`, `TAG = "v0.9"`

Note: this chains `$$$` descent with the existing `"$REPO:$TAG"` leaf
pattern (via `LeafPattern { segments }`) — no new walker machinery for the
leaf; only the descent path changes.

### Walker change pseudo-code

```
// brace_parse.rs: parse_key extension

fn parse_key(input, pos, positions) -> Result<KeyMatcher> {
    skip_ws(input, pos);
    
    // NEW: detect $$${ ... } or bare $$$
    if input[*pos..].starts_with("$$$") {
        if input[*pos + 3..].starts_with('{') {
            // $$${NAME?} form: descent + path capture
            // parse the ${NAME?} interior using existing brace-capture logic
            *pos += 2;  // advance past $$, leave at third $ for existing parse_capture_or_wildcard
            let cap_steps = parse_capture_or_wildcard(input, pos, positions)?;
            let capture_name = extract_capture_from_steps(&cap_steps);
            return Ok(KeyMatcher::RecurseDescent { capture: capture_name });
        } else {
            // bare $$$ : descent only, no capture
            *pos += 3;
            return Ok(KeyMatcher::RecurseDescent { capture: None });
        }
    }
    
    // ... existing key forms unchanged
}
```

```
// compile.rs: KeyMatcher::RecurseDescent

KeyMatcher::RecurseDescent { capture } => {
    // Lower to the new step form (not a KeyMatcher in CompiledObjectEntry;
    // must be handled before compile_object_entry, as ** is today).
    // Handled in compile_steps special case via brace_parse pre-processing.
}
```

The cleanest approach mirrors how `**` works today: `RecurseDescent` is
detected in `parse_object` (not just `parse_key`) and emitted as
`SelectStep::Any` (no capture) or the new `SelectStep::AnyPath { capture }`.

```
// compiled.rs: new variant

pub enum CompiledStep {
    ...
    /// Recursive descent, optionally capturing the dotted key-path that led
    /// to the match site.
    AnyPath { path_capture: Option<String> },
}
```

```
// walker.rs: CompiledStep::AnyPath arm

CompiledStep::AnyPath { path_capture } => {
    let mut out = try_rest(node, rest, ctx, caps, path_capture, "");
    walk_any_path(node, rest, ctx, caps, path_capture, &mut path_buf, &mut out);
    out
}

fn walk_any_path<N: DataNode>(
    node: &N, rest, ctx, caps, path_capture, path_buf: &mut String, out: &mut Vec<MatchResult>
) {
    // At each object: try rest; then recurse into children
    match node.kind() {
        DataKind::Object => {
            for (k, v) in node.entries() {
                let k_text = scalar_text(&k);
                let prev_len = path_buf.len();
                if !path_buf.is_empty() { path_buf.push('.'); }
                path_buf.push_str(&k_text);
                
                // bind accumulated path if path_capture is Some
                let mut next_caps = caps.clone();
                if let Some(cap) = path_capture {
                    next_caps.insert(cap, WalkCapture { text: Arc::from(path_buf.as_str()), ... });
                }
                let child_ctx = ctx.descend_key(&k_text);
                
                // try rest at this level
                out.extend(walk_inner(&v, rest, &child_ctx, &next_caps));
                // recurse deeper
                walk_any_path(&v, rest, &child_ctx, &next_caps, path_capture, path_buf, out);
                
                path_buf.truncate(prev_len);
            }
        }
        DataKind::Array => { /* same pattern, path_buf uses "[N]" */ }
        _ => {}
    }
}
```

#### Notes on path format

- Dot-separated key path: `"a.b.c"` — mirrors jq path syntax.
- Array indices: `"users[0].image"` — consistent with JsonPath.
- Root: path is empty string `""` if match is at the root level.

The `path_buf` can be a `String` allocated once per `AnyPath` invocation and
passed by `&mut`, avoiding O(N) allocations per descent step.
