# Session: lsp-unification-complete

## Goal
Unify LSP state management around the parser/analyzer as single source of truth. Create Operator trait system where each operator self-parses and validates.

## What Was Accomplished

### 1. Fast Hover with DocumentSnapshot ✅
- Pre-computed document snapshots with captures, rules, cross-refs
- Hover < 10ms (no parsing in request path)
- Fuzzy capture matching for better cursor detection

### 2. Cross-Ref Resolution ✅
- Hover on derived rule captures shows upstream values
- Cross-ref info stored in snapshot
- Parameter binding display in hover

### 3. Operator Trait System ✅
- `Operator` trait in `crates/sprf/src/ops/mod.rs`
- `FsOperator` - handles fs/file/folder patterns
- `JsonOperator` - handles json/yaml/toml extraction
- LSP uses operators from sprf (NO parsing in LSP)

### 4. Removed Parser Code from LSP ✅
- Deleted `find_pattern_at_position()` from LSP
- Deleted regex-based pattern detection
- LSP calls `snapshot.fs_op_at()` / `snapshot.json_op_at()`

### 5. Hover Works After Save ✅
- `did_save` now recomputes snapshot
- Previously: snapshot only computed in `on_change`

### 6. Git Root from Subdirectories ✅
- `Workspace::from_directory()` finds git root
- Fixes "0 files matched" when editing files in fixtures/
- `**/Cargo.toml` now works from any subfolder

## Architecture
```
Events → analyze.rs (single reducer) → PartialAnalysis → LSP (thin adapter)
                                        ↓
                              Operators (fs, json, etc.)
```

## Key Insight
Parser is the single source of truth. LSP is a thin adapter that converts analysis results to LSP types.
