## Problem/Context
- Op-level kwargs already existed on source ops (scan/match/ast/sg/ast_yaml/comment)
  via `parse_kwarg_terms` + `assign_outputs` (fixed output slots). Relation atoms and
  `?` queries were positional-only. Language-level = extend to arbitrary atoms.
- Atom schema (column names) comes from `rel` decls, which can FORWARD-reference — so
  named->positional resolution must be a POST-parse pass once all decls are known,
  not inline in the parser.
- User asked mid-arc for field punning (`rel(a: A, b, c)` where bare `b`/`c` pun to
  their own columns, JS/Rust-struct shorthand). Clarified Kotlin doesn't actually
  pun (named args only); the shorthand is the JS object / Rust struct model.
- User asked "do we have good errors so we arent just saying random shit" -> audit
  surfaced ONE real leak: undeclared head rel dumped raw `no such table: rel_X`.

## Solution/Approach
1. `Atom` gained `named: Vec<(String, Term)>` (ast.rs:117); 2 constructors updated.
2. `atom()` (parse.rs) now calls shared `parse_kwarg_terms()` -> (pos, named) + expect(RParen).
   `head_atom()` rejects `Ident Colon` clearly (agg-permutation deferred), builds named:vec![].
3. New frontend pass `resolve_named_args` (frontend.rs), called after expand_program,
   BEFORE desugar_effects (which reads positional body terms), in BOTH load_program
   and load_program_set. Builds schema = all_builtin_decls() + user RelDecls.
4. `resolve_atom`: no-op if named empty (positional untouched). Named mode: positional
   bare `Term::Var(v)` PUNS to column v; non-var bare = ambiguous error; explicit
   `col:` fills by name; unfilled cols -> Term::Wild. dup/unknown-column/no-schema errors.
5. Undeclared-head fix: check_and_normalize (typecheck.rs:617) flags any rule/query
   head rel not in prog_rels AND not builtin_rel_names() as `unknown-relation` diag
   (dedup'd). Tables are decl-only (engine mod.rs:2710 create_rel_table), so safe.
6. Docs: edited op_docs() atom/query rows (engine/mod.rs:480,492); regen via
   `dl examples/gen-reference.dl --root ..` (writes v5/docs/reference/syntax.md).
   Also regen README builtin-rels/op-table zones (op-table.dl/builtin-rels.dl).
7. Examples converted to show shorthand: debug_type.dl, auto-doc.dl, doc-coverage.dl.
8. Softened `--no-daemon` advice in src/setup.rs:26 + skill SKILL.md:59.

## Key Insights
- WORKSPACE TARGET IS AT REPO ROOT (`../target/debug/dl`), NOT `v5/target/debug/dl`
  (root workspace added for cargo install --git). Burned time running a stale v5/target
  binary. Always use ../target/debug/dl from v5/.
- gen-reference.dl / op-table.dl / builtin-rels.dl globs are `v5/...` — run them with
  `--root ..` (repo root). Running with `--root .` (v5) creates a nested v5/v5/docs
  (rm -rf it). [gen] paths print relative to root.
- Punning disambiguation = JS `{a:A, b, c}` model: positional mode (no `col:`) stays
  positional; ONE `col:` flips the whole atom to named mode where bare idents pun.
  Pure positional atoms untouched = zero breakage for existing programs.
- Resolution must run BEFORE desugar_effects (it reads positional body terms) but the
  schema (RelDecls) exists post-expand, so a standalone pass works.
- Undeclared head rel was a genuine raw-SQL leak; body rels were already checked
  ("unknown relation X") but heads weren't. Query heads under --check are silent (? is
  skipped under --check), so the typecheck diag is the only place it surfaces there.
- Error msg hygiene: Debug `{:?}` on Term leaks `Int(5)`/`Str("x")` — render friendly
  (matched Str/Int/Wild). parse_kwarg_terms bail leaked `Some(Plus)` (Option) — split
  Some(t)/None arms.
- `_` (don't-care): everywhere. kwargs: source ops + now relation atoms/queries (NOT
  rule heads yet). This is the incremental cons/calling-unification, not the whole epic.
