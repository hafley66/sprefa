## Solution/Approach

### json (sprefa-lpk)
Created v3/crates/pipeline/src/data/ as plain semantic-named modules
(no `_N_` prefix, per v3 rule):
- types.rs: DataKind, DataNode trait, ParseError, AnyDataNode (single-
  variant Json today; trait shape preserves the YAML/TOML slot)
- json.rs: JsonNode wrapping tree-sitter-json with Arc<[u8]> source
  to match v3 Cursor.content (v2 used Arc<Bytes>)

Created v3/crates/pipeline/src/walk/:
- pattern.rs: Segment, PatternMatcher, compile_pattern,
  parse_segment_pattern, match_segments_with_bindings. Ported v2 verbatim
  with anyhow_lite shim to avoid pulling anyhow as a workspace dep.
- compiled.rs: CompiledStep, CompiledKeyMatcher, WalkCapture (text +
  byte_start + byte_end; jq-path field DROPPED — v3 Capture has no
  path)
- compile.rs: SelectStep + compile_steps. Context steps (Repo/Rev/
  Folder/File) dropped since v3 has separate ops for those.
- walker.rs: walk() + walk_with_captures + WalkOutcome. Object-entry
  row-split semantics ported including the partial-match fallback.
- brace_parse.rs: parse_body. ScanAnnotation parsing kept for fidelity
  but ignored at compile time.

ops/json.rs: full rewrite. JsonOp { steps, bound_caps, _annotations }.
from_paren_node slices paren body bytes, runs parse_body + compile_steps.
pipe() parses content as JsonNode, calls walk(), turns each MatchResult
into one Cursor with Capture::span_backed entries (absolute byte ranges
= cursor.byte_range.start + walker offset). Empty body short-circuits
to json/empty-body diagnostic before parse_body.

### ast (sprefa-4m7.2.11)
ops/ast_grep.rs: AstGrepOp { lang, pattern, slot_regexes, bound_caps, _src }.
from_paren_node reads BOTH bracket field and paren field in one pass:
- bracket arg → parse_lang dispatches rust|rs|typescript|ts to
  SupportLang
- paren body → lower_sugar (verbatim v2 algorithm: ${VAR} collapses
  surrounding identifier-char token run to $SPRFSLOT<N> + named regex)
  + scan_metavars for native $VAR/$$$VAR

pipe() runs SupportLang::ast_grep() locally per cursor (no rayon, no
reader.parsed cache), iterates find_all, pulls native captures from
env.get_match / get_multiple_matches, runs slot_regexes against
$SPRFSLOTN nodes to extract sub-token captures. Span-backed when the
match has a node range; Synthesized fallback for joined multi-matches.

Cargo.toml: ast-grep-core 0.36 + ast-grep-language 0.36 (default-
features=false, builtin-parser + tree-sitter-rust + tree-sitter-
typescript). Profile dev opt-level=3 overrides moved to workspace
root.

## Key Insights
- The `from_paren_node` escape hatch made both ports straightforward.
  Bracket+paren both available off the host CST `op_invocation`, no
  sub-grammar regen needed.
- v3 Capture model is leaner than v2 — no `path`, no `evidence`, no
  per-capture metadata beyond name+byte_range+kind. The walker port
  stayed almost-verbatim by stripping the path field.
- v2 `lower_sugar` does the right thing even when `${VAR}` is isolated:
  empty prefix/suffix in the regex degenerates to identity capture.
  No need for a special-case "non-adjacent" branch.
- Profile overrides for ast-grep crates HAD to land at workspace root,
  not in pipeline/Cargo.toml. Cargo emits a warning if a non-root
  member declares profiles.
- ast-grep-core's StrDoc<SupportLang> is created per cursor and never
  crosses an await boundary, sidestepping the Send issues called out
  in the rx:rxrust-x-ast-grep skill.
