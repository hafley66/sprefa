## Problem/Context
df_node only lifts the `--root` repo in Chris's "run of sprefa in ai." Root
cause: NOT the extractor (refresh_dataflow_rels already fans over
extract_file_set() × repo_roots(), reading each file from roots.get(repo), and
stamps df_node_repo(id,repo)). The gap is UPSTREAM: `extract_file_set()` = SELECT
FROM _file, and a repo is in _file only if it was SCANNED, which requires it be a
registered repo (config [[repos]]/[[org]], repo() sink, or scan("*")). A sibling
dir the AI cares about but never registered → never scanned → zero df. Deeper:
the whole model privileges ONE root (repo_roots() inserts self_slug->self.root
FIRST; resolve_root always mints a concrete root; the "rootless" daemon fakes a
"benign self" at the XDG home). For a daemon a parent process spawns and points
at N peer repos, the privileged self is backwards.

## Key Insights
- df_node fans over _file × repo_roots ALREADY; the gap is corpus population
  (a repo must be registered+scanned to enter _file), not the extractor.
- repo_roots() = {self_slug->self.root} FIRST, then config repos — the privileged
  self is the root-anchoring to kill.
- "rootless" daemon EXISTS but fakes a self at the XDG home ("benign self");
  root=None -> XDG singleton. resolve_root always mints a concrete root.
- Daemon RPC surface has NO add_root/serve_path — a parent can't hand it a peer
  repo except via config file or repo() clone. That RPC is the missing piece for
  daemon-as-child.
- `repo` is the precedent for a catalogued, head-writable builtin sink whose rows
  trigger IO (cloning) — the pattern demand sinks now follow.
- A demand sink is conceptually v5's name-bound extension seam (v4 custom-op role)
  but mechanically thinner (builtin rel + post-tick RelKind reader, no
  OperatorDef/Component); closest primitive is the EFFECT (sh/@async).
- CI prior "failures" (vscode-repackage, v0.6.0 Release) were runner INFRA flakes
  (disk I/O error 1034, artifact-upload ENOTFOUND) — re-runnable, self-recovered.
- Pre-commit/PostToolUse hook runs the INSTALLED dl; cargo install --path .
  --force after any catalog change or the hook/CI break.
