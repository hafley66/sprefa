## Key Insights
- `true()` is the ISO-standard Prolog true/0 as a datalog relation: always succeeds, identity for conjunction, existential seed. Citation: https://www.swi-prolog.org/pldoc/doc_for?object=true/0
- The "checked patterns / bottoms out" feature is pure datalog: `diag <- true(), !rel(_,_,_).` No AST flag, no parser token, no engine post-pass. The negation + diag + LSP channels already existed; true() just unblocks the safety check.
- The empty-match design went through 3 iterations: (1) default-on for source rules [rejected: false-positives on diffs], (2) ! postfix token [rejected: engine machinery not datalog], (3) true() + negation [accepted: pure datalog]. The user's key insight: "if no match found on diff, it's not a problem, it's good."
- v5's incremental caching: `_file` content hash (skip re-parse), `_reldigest` source rel digest (skip rebuild when bytes move but rows don't), `closure_cache` SCC condensation (reuse unaffected edges). The full-wipe offender is refresh_builtin_rels (DELETE+INSERT every tick for repo/rev/content/file/true).
- Query bodies are single atoms (where clause removed); multi-atom joins need derived rels.
- sg metavar names must be UPPERCASE (sg.rs:22); match named groups can be any case.
- ref rel file column is file_id (hash), not path; engine's string_spans resolves for LSP.
