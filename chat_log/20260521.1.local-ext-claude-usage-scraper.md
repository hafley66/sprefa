## Solution/Approach
- inject_main.js (MAIN world, document_start) wraps fetch/XHR, stashes any "usage" response JSON onto
  document.documentElement[data-le-usage]; isolated-world scraper reads it.
- OPSEC: field names are NOT hardcoded. Extraction is config-driven via `meterPaths` (lodash dot-paths +
  scale + enabled), set in extension Options (chrome.storage), never in repo. No eval (MV3/page CSP forbids).
  getByPath + metersFromConfig in background.js.
- Server: zero-dep std Rust, lib.rs (serve) + main.rs (bin); viewer embeds server on a thread so one
  `cargo run` does both. Appends each POST to a JSON array via string-splice. CORS headers + OPTIONS.
- Shared config.conf (key=value) at ~/.local/local-ext/; data at claude_usage.json. config.conf + *.json gitignored.
- Viewer (eframe 0.29 + chrono): claude-dark palette, 3-col aligned meters (LABEL_W/VALUE_W, uniform bar),
  custom thin-pill usage_bar_c(fill,track), live "Resets in", relative "updated ago" (first hour then clock),
  extension-health status, "Open usage page" button, two extra-usage toggles, color pickers (mini_bg/bar/text/track),
  MINI MODE: borderless always-on-top strip, MinInnerSize lowered so it can be short (560x44), no-wrap (Extend),
  per-meter div (bar + secondary line: percent->reset, money->"% used"), vertical separators, "checked Nago" info div,
  horizontal ScrollArea (drag_to_scroll false, scrollbar hidden) with × exit pinned OUTSIDE scroll area (always visible),
  drag strip to move / double-click to exit.
