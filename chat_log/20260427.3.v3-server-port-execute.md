## Problem/Context
The v3 hover hung after running ast/ast_yaml on ~413 .rs files. Root cause was per-hover BoundedWorkSteal::new spinning up an 8-thread rayon pool whose Drop joined synchronously, blocking the tokio worker. Cancellation was not threaded; switchMap-style cancel-and-restart did not exist; no buffer overlay so editor edits to scanned files were invisible until save; two LSP processes against the same workspace shared zero state. v2/src/server/* had solved every one of these so this was a mechanical port not a redesign.

User explicitly said "no go the whole way v2 is a complete reference" and later "fix all of it directly do not dupe then undupe" — that drove me away from incremental slices toward shipping ServerState + transports + binaries together so backend.rs would not be left as the runtime-wiring hub.

## Solution/Approach
Plan-order port from chat_log/20260427.1.v3-server-port-zoom3.md, executed in one slice:
1. BufferOverlay reader + tests
2. state.rs / workspace.rs / run.rs (single RtCtxBuilder site; verbatim port of sprefa-run body)
3. ast_parse_batcher lifted to ServerState; bounded_work_steal honors cancel; blanket Batcher for Arc<B>
4. transport_http.rs + transport_lsp.rs + sprefa-server bin
5. sprefa-lsp rewritten as WS proxy
6. sprefa-run rewritten as HTTP client
7. switchMap on hover via per-uri in_flight slot

Coupling concern (raised in /i:map mid-session): backend.rs imports 8 things from pipeline::effects + 1 batcher; sprefa-run independently knew the same registration list. After this slice, run.rs is the canonical RtCtx-build site for /run. render_enriched_hover still has its own copy — that is sprefa-veq.

## Key Insights
- E::Response: Default bound on BoundedWorkSteal is the cheap path to honor cancel without changing the Batcher trait. AstParseEffect::Response is Option<Arc<...>> so default = None lines up exactly.
- blanket impl Batcher<E> for Arc<B> means the long-lived rayon pool clones into per-hover RtCtx without any new register_arc method — the existing register::<E,_>(arc.clone()) just works.
- BufferOverlay::set computes blake3 of bytes eagerly so OpCache batch_fingerprint distinguishes overlay reads from disk reads automatically — no separate cache keying needed.
- async_stream::stream! macro turns the Send error from sqlx (Box<dyn StdError> not Send) into a future-not-Send compile error; coercing the drain Result to Result<(), String> at the await site fixes it.
- pre-existing test failure tree-sitter-sprefa::spec_fixtures_parse::future_fixtures_do_not_parse_yet (render_md_smoke.sprf moved from "fails to parse" to "parses cleanly") is a positive trip wire unrelated to this port.
