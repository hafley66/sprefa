## Solution/Approach

### Pass B sequencing (landed)

Knobs locked up front by user (Q&A): const NAME/DOC, Shape A landed in full (OpCtor + PatternCtor + OpLowering + register_custom door even with no consumer yet), fold op_languages into registry, skip Op::name() blanket, move *_DOC consts onto each op.

1. **op_ctor.rs NEW** — three sibling traits:
   - `OpCtor: Op + Sized` — const NAME/DOC, fn from_values(Vec<Value>) -> Result<Self, ...>
   - `PatternCtor: Op + Sized` — const NAME/DOC, fn language() -> Language, fn highlights() -> Option<&'static str>, fn compile_from_tree(&Tree, &[u8]) -> Result<Self, ...>
   - `OpLowering: Send + Sync + 'static` — const NAME/DOC, fn lower(node, src, registry, diags) -> Value (escape hatch for raw-CST inspection; tag is canonical future consumer)
   - pub(crate) op_factory::<O: OpCtor>() -> Arc<OpFactory> bridge to the erased registry storage shape

2. **registry.rs rewrite** — Builder.register::<O>() / register_pattern::<O>() / register_custom::<L>() replace per-op closure hand-rolling. Registry now stores languages: HashMap<&'static str, Language> and highlights: HashMap<&'static str, &'static str> typed by registration. lower_nested_op_invocation calls registry.pattern_language(op_name) instead of crate::op_languages::language_of(op_name). Custom-lowering door consulted FIRST in lower_nested_op_invocation so future ops like tag own their whole CST walk.

3. **Per-op impl OpCtor** for RepoOp, RevOp, FsOp, VoidOp, StrOp, CommentOp, PrintOp, ReadOp. The five non-trivial ones (repo/rev/fs/comment/print) keep inherent from_values as source of truth and trait impl delegates via Self::from_values(values) — relies on Rust's inherent-method-priority rule when called from inside a trait impl block. Tests still call inherent paths so no test refactor needed.

4. **Per-op impl PatternCtor** for GlobOp, ReOp. Inherent compile_from_tree retained as source of truth; trait delegates. language() / highlights() impls call op_languages module directly (the build-script-generated extern C linkage stays as a thunk module; only the by-name lookup function is no longer used by the registry). Disambiguated <O as PatternCtor>::language() in Builder::register_pattern to avoid collision with Op::language(&self).

5. **DOC consts moved** off registry.rs onto each op as const DOC: &'static str inside the OpCtor/PatternCtor impl blocks. registry.rs net -22 lines after the move.

6. **with_stdlib() collapsed** to ten one-liners:
```rust
Builder::new()
  .register::<RepoOp>()
  .register::<RevOp>()
  .register::<FsOp>()
  .register::<VoidOp>()
  .register::<StrOp>()
  .register::<CommentOp>()
  .register::<PrintOp>()
  .register::<ReadOp>()
  .register_pattern::<GlobOp>()
  .register_pattern::<ReOp>()
  .finish()
```

7. **lib.rs export** OpCtor, PatternCtor, OpLowering. op_ctor module declared.

8. **#[allow(dead_code)] on register_custom** — comment notes "Escape hatch for ops needing raw CST access at lower time (canonical: tag). Intentional unused-until-tag." Documented dead code, not warning noise.

9. **parse.md §14.5m reconciled** — title flipped from "Pass A landed, Pass B deferred" to "Pass A + Pass B both landed". §14.5m.6 Pass B section rewritten: 4 steps marked [x] with concrete prose covering what landed (NAME/DOC on type, register::<O>() ergonomics, register_custom door pre-built, registry stores languages directly).

### Synthesis spike (filed sprefa-126)

User asked about scan-pointer / tag / re-enterable-blocking-terms / xref. After reading parse.md §12, §14.5m.3, §19.2, §21, §22, §24.1, §24.2 + memory project_v3_tag_op_prolog_posture + project_no_ans_ref + project_scan_pointer_runtime + bd sprefa-4m7.7.2 / sprefa-4m7.5.6 / sprefa-4m7.7.9 / sprefa-4m7.2.14, surfaced that four separately-described mechanics are the SAME primitive at different layers:

1. §19.2 cursor park on missing term (locked but unimplemented; no shape for what holds the cursor)
2. tag-op unbound-mode re-entry / xref semijoin (no reactivity wire designed; current memory is synchronous HashMap)
3. parametric rule lazy unbound-param suspension (sprefa-4m7.5.6 = "sprefa's function-def mechanism")
4. scan_sigil Tri verification flip (Claimed → Verified at the capture layer)

Unifying primitive: WaitKey discriminator over { Term(name), Tag(kind, value), TagAny(kind), Capture(path, value), RuleParam(rule_id, idx) }. Cursor parks against one or more WaitKeys; any op writing under matching keys fires the wake. xref-callers = subscribe with TagAny wildcard. Rules-with-unbound-terms = subscribe on RuleParam.

Card carries 7 concrete questions: WaitKey shape collapse, park-handle candidate A/B/C (Notify vs mpsc vs WaitSet<K> indexed), subscription lifetime, replay-vs-re-entry semantics (BehaviorSubject mapping per §22), static analysis vs runtime-only detection, fork intersection interaction (§20.1), implementation seam (effect_runtime crate vs pipeline crate — leaning effect_runtime).

## Key Insights
- Inherent-method priority rule: trait impls can call Self::method(args) and resolve to the inherent same-name method, not the trait method. Lets us keep inherent from_values as source of truth + have trait delegate by one-line forward, no test refactor. Fragile-looking but well-defined Rust semantics.
- Disambiguation cost: trait method names that collide with Op trait defaults (language, highlights) require <O as PatternCtor>::language() at the call site inside Builder::register_pattern. One-line cost; clean enough.
- The op_languages build-script module survives Pass B — only its language_of(name) function is no longer called by the registry. PatternCtor::language() impls still use it as the C-FFI thunk. Build-script-generated extern declarations are the right home for that linkage; deleting the module would mean inlining the extern fns into each pattern op.
- register_custom door has zero stdlib consumers but lands now anyway because the spike requirement was "tag plugs in without re-shaping the registry". Documented as #[allow(dead_code)] with comment, not warning suppression noise.
- LoC delta: registry.rs net -22 (factory closures + DOCs removed, Builder methods + language storage added). Per-op DOC strings moved (~80 lines), not added net.
- The "tag deferred Pass B" reasoning in the prior session was conservative — landing Pass B now costs nothing for the 10 existing ops AND pre-builds the door for the next 4-5 ops queued (line, json, ast, sh, render, tag). Good ergonomics tax on the next ops.
- The big synthesis: scan-pointer / tag re-entry / lazy parametric rules / scan_sigil Tri verification are FOUR descriptions of ONE mechanic. The keyed wait-set primitive is the missing runtime piece that §19.2 promised but didn't specify. Filing it as a spike rather than a P0 because the design space is non-trivial (7 concrete questions in the card) and other work is unblocked without it.

## Open Questions
- WaitKey discriminator collapse: do Term / Tag / TagAny / Capture / RuleParam reduce to 2-3 cases? Likely (kind, optional value) covers everything but RuleParam.
- Park handle implementation: tokio::sync::Notify (broadcast wake) vs bounded mpsc per key (fan-out fan-in) vs WaitSet<WaitKey> indexed primitive on runtime. Needs a perf-and-ergonomics tradeoff session.
- Where the wait-set lives: effect_runtime (clean: park-on-key is runtime-shape, not pipeline-specific) vs pipeline (avoids new effect_runtime dependency on cursor-shaped concepts).
- Static-time detection of unsatisfiable waits: works for rule params via BindingGraph; harder for tags (only known at runtime). May need a will-write annotation on tag ops.
- Fork intersection × parked cursors: §20.1 says downstream sees only intersection; if arm A parks on $X and arm B doesn't bind $X, intersection is empty so downstream can't ref X anyway. Probably proceed-without-arm-A; needs spike confirmation.
- Replay semantics: BehaviorSubject mapping (§22) implies an unbound-mode tag read sees BOTH currently-stored rows AND future writes. Confirm subscription lifetime (per-cursor vs per-rule).
