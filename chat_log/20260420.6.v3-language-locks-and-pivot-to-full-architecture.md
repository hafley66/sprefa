# Session: v3-language-locks-and-pivot-to-full-architecture

## Goal

Close out language-level design ambiguity, scrub doc poison, audit the
lowering-validator prototype, then pivot out of validator-only mode and
scale up to the full v3 architecture (perf + plugin + parsing + core +
cli/lsp shells).

## What landed this session

### Doc scrub (v3/docs)

Removed three poison patterns that kept re-biasing responses:

1. `(name) body` leading-paren shorthand (axed in 20260420.5) →
   `rule(name) > body` canonical. 5 instances in
   `v3/docs/v3-semantic-model.md` (§3.2, §3.3, §3.4). Also 3 instances
   in `v3/experiments/parse_experiment/src/bin/unified.rs` (doc comment
   + two `const SRC` strings).
2. `==` infix comparison → `eq(...)` relation op.
   v3-semantic-model.md line 23 (prose), lines 200/203
   (assert_inline example and its lowered form).
3. `filter(cond)` as a control-flow primitive → bare-`$X` semijoin +
   relation ops (`eq`, `gt`, `lt`, `in`). Fix at
   v3-unified-language-locks.md §7 line 284.

Flagged but left alone: `v2/docs/_b_v3-unified-language.md:917` still
has the axed form (pre-v3 teaching doc, out of scope).

### Language locks tightened

| item | lock |
|---|---|
| `$VAR` ≡ `${VAR}` | one AST node (`Dollar`) with body = recursive Ast. `$X` is shorthand for `${X}`. Compound bodies fit as `Dollar(Call{...})` etc. The §14 term-annotation lane lands as `Dollar(Call{head: ":", ...})` without new enum variants. |
| Sub-grammar bodies | bare body, no quotes. `glob{proto/$SRC.proto}`. `${{var}}` escape for literal brace-dollar inside body. Balanced-brace pre-pass extracts `${...}` carveouts before sub-grammar parser runs. |
| `Value` floor | `{ Atom, Str }`. Pattern variant killed (sub-grammar bodies are Pipeline sub-content, not values). Strings/regex/glob bodies are all Str-shaped at AST level; engine is the op's business. |
| Relation ops | `eq`, `gt`, `lt`, `in` replace infix `==`/`>`/`<`. Bidirectional per `ArgSpec`. No infix tier in the grammar. |
| Capture write | `> $X` station replaces `let $X = expr`. Writes upstream primary term into `$X` slot. Re-bind in the same scope is a diagnostic. |
| First-define-wins | slot allocation is lexical: first syntactic occurrence of a name in a scope allocates its `SlotKey`. Subsequent uses resolve to that slot. |
| Runtime binder | distinct from slot allocator. Either caller (bound-call) or earliest chain-stage with `Unbound`-dispatch on that slot (unbound-call). |
| Rule head | inputs only. Captures the rule wants to export are inferred from body `> $X` write stations. Auto-export on first use in body. |
| Cross-ref | `${rule.$VAR}` carveout projection — already locked in
v3-semantic-model.md §3.2. Rule-as-stage (`> rule_name >`) is the other
mechanism, for piping full cursors through. Two orthogonal use cases. |
| Directionality at rule boundary | `rule(name, $A, $B)` + call site
bindings — bidirectional falls out of op-level mode dispatch inside the
body, not from rule-head syntax. Parametric rules enumerate when params
unbound, filter when bound. |
| Atoms | scalar-only. The one exception to "everything is an op." |
| Infix | none. `>` is pipe only. `;` distributes parent. |

### Min enum set (Opus floor, 45 variants / 11 enums)

Converged after three parallel subagent passes (sonnet lambda-calc,
sonnet bash+haxl, opus prolog+react+ast-grep).

```rust
// AST tier
enum Ast {
    Value(Value),
    Dollar(Box<Ast>),              // $X ≡ ${X}; body is recursive Ast
    Amp(Box<Ast>),                 // &.fs, &.$X, &{...}
    Ident(Atom),                   // casing rule determines op/rule vs term
    Call { head: Atom, args: Vec<Ast> },
    Sub { lang: SubLang, body: Arc<str>, carveouts: Vec<(Range, Ast)> },
    Chain(Vec<Ast>),
    Fork(Vec<Vec<Ast>>),
    Decl { kind: DeclKind, name: Atom, params: Vec<Atom>, body: Box<Ast> },
}
enum DeclKind { Rule }
enum SubLang { Re, Glob, Ast(Atom), Sh, Json, Yaml, Toml, Md }
enum Value { Atom(Atom), Str(Arc<str>) }

// Lowered tier
enum Pipeline {
    Op  { op: Arc<dyn Operator>, args: Vec<ArgValue> },
    Chain(Vec<Pipeline>),
    Fork(Vec<Pipeline>),
}
enum ArgValue {
    Value(Value),
    Pipe(Arc<Pipeline>),           // carveouts, sub-pipelines, higher-order
    Term(TermRef),
    Addr(AddrExpr),
}
enum AddrExpr { Field(CursorField), Term(TermRef), Computed(Arc<Pipeline>) }
enum CursorField { Fs, Repo, Rev, ByteRange, Content }

// Runtime dispatch
enum TermMode { Bound(Value), Unbound(SlotKey) }
enum AcceptsMode { BoundOnly, UnboundOnly, Either }

// Compile-time only
enum BindingSource { Param, StageEmit, ForkArm, ParametricCall, WalkerBody }
```

Drops from prior lockfile:
- `Pipeline::Group` (parser-only, zero runtime semantics)
- `EntityRef` as a runtime enum (moved to `ProgramCtx` symbol table)
- `OpAction` enum (stream events subsume all four cases)
- `PathSeg::Anon { file, hash }` (collapses to `Named(Atom)`)

Hot-path runtime variants: 19 across Pipeline(3) + ArgValue(4) +
AddrExpr(3) + CursorField(5) + Value(2) + TermMode(2).

### Traits (not enums, do not count toward variants)

```rust
trait Operator: Send + Sync {
    fn signature(&self) -> &[ArgSpec];
    fn pipe(&self, ctx: OpCtx, args: &[ArgValue], upstream: CursorStream)
        -> CursorStream;
}

trait EffectKind: Send + Sync + 'static {
    type Request;
    type Response;
    type Key: Hash + Eq;
    fn key(req: &Self::Request) -> Self::Key;
    fn batch(reqs: Vec<(Self::Request, oneshot::Sender<Self::Response>)>)
        -> impl Future<Output = ()>;
}
```

`EffectKind` is the applicative-batching surface (haxl `DataSource`
shape). Three `re{}` ops firing from the same fork on the same file
collapse to one mmap + three PCRE2 passes via `Key` dedup.

### Prototype audit (v3/experiments/lang_prototype)

Existing skeleton 694 LoC, compiles and — after a one-line fix —
4/4 smoke tests pass.

- Fixed `runtime.rs::run_op_call` bug: when input is empty but rule has
  params (bound call with pre-seeded args), the old code iterated empty
  input and produced nothing. New branch seeds a cursor, binds params,
  runs body once.

Drift from current locks (not acted on per user direction):
- `Pipeline::Group` still present
- `Scalar` at 6 variants (Null, Bool, Int, Float, String, Atom) vs
  floor of `{ Atom, Str }`
- Separate `tags` op (should collapse into `tag` with both unbound)
- `Term::Carveout` not implemented; `Term::Xref` is a stub
- No AST / parser / resolver (front-end missing entirely)
- Sub-grammar bodies not wired (`fs`/`re` take plain string args)

## Pivot

Validator-only prototype retired. Scope expands to the full v3
architecture:

- **parsing**: tree-sitter-sprefa grammar, sub-grammar injection
  (re, glob, ast[lang], json, yaml, sh), `${...}` and `&{...}`
  carveout pre-pass
- **core**: AST → resolver → BindingGraph → StageDeps → Lowered
  Pipeline, Cursor runtime, ParseSite cache, in-memory + SQLite stores
- **perf**: parallel scan across repos, reader dedup, applicative
  batching via `EffectKind`, rxRust-on-top topology, arena allocators
  where they pay
- **plugin**: `Operator` trait registry, op folders, sub-grammar
  registration, diagnostic/hover/fix owned per-op, zero framework enum
  touching when adding an op
- **cli**: thin client over daemon/runner, SQLite read path for
  already-computed tables
- **lsp**: completion on op names, hover on `$X` / `&.` / `${rule.$V}`,
  progressive-bind decoration (bound vs unbound), go-to-binder, live
  cursor-cardinality stats per stage

## Key insights carried out of this session

- **"Fuck it, no more validation"** — the lowering-validator scope was
  a useful forcing function for clarifying the enum set, but running
  it as a separate binary was not going to teach anything the real
  runtime wouldn't teach better.
- **Doc poison is real.** Three separate times this session I regressed
  on a previously-locked decision because a stale doc got scanned and
  biased the reply. Scrubbing the docs is infrastructure work, not
  polish.
- **Cross-ref was already solved.** `${rule.$VAR}` has been in
  v3-semantic-model.md §3.2 the entire time. Re-deriving it from call-
  site param bridging was wasted motion.
- **Rule head = inputs only.** Body `> $X` stations auto-export. This
  collapses the "declare + write is redundant" confusion.
- **Three unification lenses agreed** on dropping `Pipeline::Group`,
  keeping `Pipeline` at 3 cases, unifying `Dollar` as a single AST
  node with recursive body, `Value = { Atom, Str }`, effects on a
  separate tier. The opus-prolog lens added the biggest finding:
  `EntityRef` and `OpAction` are mis-tiered and should not exist at
  runtime.
- **Section 14 term-annotation grammar fits for free.** `$X:kind`,
  `$X[mode, link]` all lower as `Dollar(Call{head: ":", ...})`
  recursively. Zero new enum variants when that lane eventually lands.

## Open questions for next session

1. Tree-sitter grammar.js vs hand-rolled — decision deferred to the
   pivot plan. Tree-sitter wins for incremental reparse + LSP if the
   scope is full-architecture.
2. Workspace layout for perf + plugin + parsing + core + cli + lsp.
   Prior layout has `crates/{effect_runtime, pipeline}` plus
   `experiments/*`. The pivot probably wants `crates/{parse, core, ops,
   runtime, store, daemon, cli, lsp}`.
3. Relationship between the existing `v3/crates/effect_runtime` and the
   Opus-floor `EffectKind` trait — are they the same thing renamed, or
   is the existing crate a superset that needs trimming?
4. Plugin author ergonomics: `inventory::submit` per op folder vs
   manual registry, proc-macro attributes for ArgSpec, auto-generated
   hover/diagnostic scaffolding.
5. Parsing strategy for sub-grammar bodies — one balanced-brace pass
   that splits outer sprf text from opaque bodies, then per-op
   sub-grammar parsing on demand.
6. Incremental reparse boundary for fs-watch invariant use case —
   mergeByKey on `(rule_path, term_path)` noted but not designed.
