## Problem / Context
- v5 is a lab, not viable long-term. Its `@next`/`@async`/`@in`/`@out` +
  `clock`/`http`/`lsp`/`mcp` were four symbols + four IO kinds = eight spellings
  of three ideas, duct-taped together.
- The unification reached this session:
  - **rel = named delta-stream over a Z-set.** Materialized = shared replay
    (`shareReplay(all)`) is the DEFAULT; lazy/cold is the opt-in. `share` is free
    in datalog because rels are global named tables.
  - **mixing rules on one rel is allowed** = `merge` of arms (weights add, SQL
    UNION). v5's "one rel = one rule kind" ban was a full-rebuild artifact.
  - **`@next` = `scan`/BehaviorSubject = argmax-by-gen channel** (CSP), not a primitive.
  - **`@async` = sugar**: `await` = `yield Call(kind,args)`; the interpreter is
    the host hole. The durable saga IS the compiled generator (switch-reducer
    over spilled-local state). IO kinds are interpreter parameters, not grammar.
  - **yield exchanges `Put`/`Take`/`Call`** — the composable primitive triple.
  - **RAM bound = SQLite page-cache discipline** (data on disk; streams carry
    deltas/keys, not rows), language-agnostic. Rust enforces it; TS requires it
    by hand. This is why the runtime choice is NOT a RAM decision.
- Prolog is a future THIRD SURFACE (goal/demand layer) over the same relation
  store, not a second engine. SLG tabling + magic-set = the bridge. SWI EDB is
  RAM-resident (`library(persistency)` = file journal; no first-party SQLite),
  so a SWI spike prototypes the LOGIC, not the store.

## Key Insights
- The type system is not greenfield: it is the formalization of the isomorphism
  spec's rel kinds. Open spec question #5 is the bootstrap.
- v5's four-symbol duct tape collapses to `Put`/`Take`/`Call` + the rel kinds.
  The type system's job is to make illegal combinations (e.g. seeding a cold
  derived rel, or asserting into a port-out) type errors.
- `share` is free in datalog (rels are global materialized tables); laziness is
  the opt-in. This inverts rx and is the type system's default-vs-opt-in split.
- RAM bound is a discipline (data in SQLite, streams carry deltas), not a
  language property, so Rust-vs-TS is not a RAM decision.
- Prolog is a query surface over the same store (SLG/magic-set bridge), not a
  second engine. Type the relations once; serve three surfaces.
