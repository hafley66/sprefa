# Chrome-Style Budgeted Runtime Plan

## Problem

The v4 runtime can now deterministically resume from SQLite, but large fanout still pushes too much cursor payload through RAM.

Measured stress points:

- `linux-antijoin.sprf`: about `392MB` RSS after mounted-output caps.
- `linux-join.sprf`: about `1.17GB` RSS for `706,778` output rows, even after join-only SQL chunking.
- Remaining join RSS is mostly real queue/fact flow: SQL outputs become cursors, queued rows, fact-write batches, then terminal rows.

## Chrome Analogy

Chrome does not keep every derived artifact hot just because identity exists.

Chrome-like layers:

- DOM identity stays durable while layout/paint payloads are recomputed or discarded.
- Work is sliced by task/frame budget.
- Style/layout dirty bits describe what must rerun.
- Paint/compositor caches are priority-based and evictable.
- Visible or near-visible work stays hot; cold work is represented by stable handles.

SPRF equivalent:

- DOM node: cursor, row, owner node.
- Dirty bit: wake event, source invalidation, support delta.
- Layout tree: runtime graph dependency state.
- Paint tile: materialized output batch.
- Disk cache: SQLite facts and cursor spill.
- Frame budget: RSS/time budget.

Core rule:

```text
identity is retained
payload is budgeted
work is chunked
derived state is discardable
```

## Current Queue Shape

Current runtime scheduling is breadth/chunk-first by depth.

```text
depth 0 fs
  emits many depth 1 rows

depth 1 ast
  consumes depth 1 batch
  emits depth 2 rows

depth 2 sql
  consumes depth 2 batch
  emits depth 3 rows

depth 3 FactWrite
  drains depth 3 rows
```

For join fanout:

```text
sql creates many depth 3 rows
FactWrite drains after those rows exist
```

That allows large intermediate runnable payloads.

## Target Queue Shape

Queue becomes a scheduler over durable handles, with a hot cursor cache.

Row states:

```text
Hot runnable
  full Cursor in RAM
  only active frontier / current batch

Cold runnable
  QueueRow metadata plus spill id
  cursor body in SQLite

Parked
  wake key plus spill id
  decoded only when wake fires
```

Value shape:

```rust
enum QueueValue<N> {
    Hot(Arc<N>),
    Cold(SpillId),
}
```

Queue row shape:

```rust
struct QueueRow<N> {
    id: QueueId,
    parent_id: Option<QueueId>,
    batch_idx: u32,
    path: Vec<u32>,
    pipe_hash: u64,
    instance_id: u64,
    depth: u32,
    value: QueueValue<N>,
    wake: Wake,
    expand_tick: u64,
}
```

Spill table:

```sql
runtime_cursor_spill (
  spill_id INTEGER PRIMARY KEY,
  cursor_key BLOB NOT NULL,
  cursor_blob BLOB NOT NULL,
  ref_count INTEGER NOT NULL DEFAULT 1,
  last_used_generation INTEGER NOT NULL
)
```

Queue table:

```sql
runtime_queue (
  queue_id INTEGER PRIMARY KEY,
  parent_id INTEGER,
  batch_idx INTEGER,
  path_blob BLOB,
  pipe_hash INTEGER,
  instance_id INTEGER,
  depth INTEGER,
  cursor_key BLOB,
  spill_id INTEGER,
  wake_kind TEXT,
  wake_key BLOB,
  generation INTEGER
)
```

Spill ids are storage handles only. Deterministic identity remains:

```text
pipe_hash
instance_id
depth
path
cursor content hash
source uri
owner uri
```

## Memory Policy

Use approximate byte accounting rather than exact allocator introspection.

Policy:

```rust
HybridQueueConfig {
    hot_runnable_bytes: 180 * MB,
    hot_parked_bytes: 40 * MB,
    dispatch_batch_bytes: 32 * MB,
    spill_sweep_rows: 4096,
}
```

On enqueue:

```text
estimate row bytes
if hot budget has room:
  keep QueueValue::Hot
else:
  encode cursor
  write runtime_cursor_spill
  store QueueValue::Cold(spill_id)
```

On pull:

```text
pull runnable handles
decode until dispatch batch byte budget is full
dispatch component
drop decoded cursors after dispatch
```

This gives a soft RSS cap:

```text
hot queue budget + dispatch batch budget + current operator scratch + SQLite cache
```

## Streaming Runtime Direction

Current component API returns full output trees:

```rust
fn render_batch(&self, ctx, batch: &[&Cursor]) -> Vec<Node<Cursor>>
```

Large `Node::Many(Vec<Node<Cursor>>)` forces payload accumulation.

Future API:

```rust
trait EmitSink<N> {
    fn emit(&mut self, value: Arc<N>);
    fn yield_on(&mut self, value: Arc<N>, wake: Wake);
}
```

Component shape:

```rust
fn dispatch(&self, ctx, rows, sink)
```

The sink decides:

```text
run downstream depth-first
enqueue hot
spill cold
write directly into terminal fact sink
```

Operator declaration:

```rust
enum FlowMode {
    RelationBatch,
    Streaming,
    Barrier,
}
```

SQL is often `RelationBatch` for evaluation because it needs a temp `input` relation, but SQL outputs can still stream into downstream sinks.

## Depth-First Variant

Depth-first streaming shape:

```text
take one input row/chunk
run sql
for each sql output:
  run FactWrite immediately
  drop cursor
move to next input row/chunk
```

For deterministic paths:

```text
parent path + monotonically assigned child ordinal
```

Example:

```text
parent [12]
children [12, 0], [12, 1], [12, 2]
```

Depth-first execution does not change durable identity if child ordinals are assigned from deterministic output order.

## Practical Next Step

Implement fused terminal materialization first.

Lower:

```text
sql`...` > fact(:hit_pairs)
```

into:

```text
SqlWriteComponent {
  sql,
  table: hit_pairs,
  assignments
}
```

Execution:

```text
for input chunks:
  run SQL
  collect output cursors up to 8192
  store.insert_batch(table, rows)
  clear batch
```

This deletes:

- SQL output queue rows.
- Huge `Node::Many` trees.
- Downstream `FactWrite` queue pull.
- Some terminal-row churn.

Then generalize:

1. Add `CursorSpillStore`.
2. Extend hybrid queue to spill runnable rows, not just parked rows.
3. Add memory accounting and dispatch batch byte limits.
4. Add `EmitSink`.
5. Let operators declare `FlowMode`.
6. Use depth-first delivery where downstream is streaming or terminal.

## Expected Effect

For `linux-join.sprf`, fused SQL-to-fact should reduce RSS below current `1.17GB` by removing the 706k-row runnable frontier.

For `linux-antijoin.sprf`, budgeted queue should preserve current good behavior while enforcing a ceiling when output grows.

The target runtime invariant:

```text
SPRF can always pause by replacing payload with a durable handle.
The graph keeps identity.
SQLite keeps cold payload.
The scheduler keeps only the hot frontier.
```
