## Goal of Phase 0

Remove hardcoded op-name matching from core grammar. After this phase, adding a new `$$sigil` requires zero edits to core parser, walker brace parser, or any central enum. The `Operator` trait gains a `scan_pointers()` slot; factories register their own sigils. `.norm` suffix grammar is flipped to `_norm` sibling-sigil form in the same cutover.

No codegen. No marker()/render(). No effect bus. Trait shape set up so Phase 1+ slot in without churning op files.

### Task 6 — Simplify `ProvRef`; rewrite `parse_provenance` to return sigil only

**Files touched**

- `v2/src/lib.rs` (re-exports; drop `ProvKind` from the `pub use` list)

**Shape of change**
Drop the `ProvKind` enum. Collapse `ProvRef` to:

```rust
pub struct ProvRef { pub sigil: Arc<str> }
```

Rewrite `parse_provenance`:

```rust
pub fn parse_provenance(s: &str) -> Option<ProvRef> {
    let rest = s.strip_prefix("$$")?;
    let name = rest
        .strip_prefix('{')
        .and_then(|r| r.strip_suffix('}'))
        .unwrap_or(rest);
    if name.is_empty() { return None; }
    if !is_ident_start(name.as_bytes()[0]) { return None; }
    if !name.bytes().all(is_ident_byte) { return None; }
    Some(ProvRef { sigil: Arc::from(name) })
}
```

Parser is permissive — accepts any `$$<ident>`. Unknown-sigil validation happens at lower time (Task 8).

**Test**
- Unit test `v2/src/_8_parse.rs::tests::parse_provenance_sigils`:
  - `parse_provenance("$$repo")` → `Some(sigil = "repo")`
  - `parse_provenance("$$repo_norm")` → `Some(sigil = "repo_norm")`
  - `parse_provenance("$${repo}")` → `Some(sigil = "repo")`
  - `parse_provenance("$$rev_norm")` → `Some(sigil = "rev_norm")`
  - `parse_provenance("$$bogus_sigil")` → `Some(sigil = "bogus_sigil")` (validation deferred)
  - `parse_provenance("$$")` → `None`
  - `parse_provenance("$$1invalid")` → `None` (ident-start rule)
  - `parse_provenance("$R")` → `None` (single `$`)

## Success criterion

Phase 0 narrow gate: zero edits to `_8_parse.rs`, `_4_brace_parse.rs`, or any central enum when adding a new op that exposes scan_pointers. Verify during Task 11 by writing a throwaway factory (pick any name) declaring a `$$foo` + `$$foo_norm` scan_pointer inside the test file, registering it in the test-local registry, and confirming a sprf snippet using `$$foo($X)` parses and lowers cleanly against that registry.

Phase 0 is a stepping stone. The real measurement is downstream: adding each of the queued ops must require only per-op file creation + whatever codegen rerun has landed by then.

Queued op backlog (each substantial on its own):
- `ast[rs]` — tree-sitter per-language AST matching (and `ast[ts]`, `ast[py]`, etc.)
- `line` — regex / literal line matching
- `md` — markdown heading, code block, list, link, table-row patterns
- `comment` — point-match comment capture
- `comment_scope` — comment-bounded region scope (rename from `marker`; old name is a trap for future readers)
- `codegen` — generator op; requires the write-saga effect bus
- `render` — template emission between marker-bounded regions
- `assume` — assumption pinning; LSP warns on drift when working tree no longer matches

The dogfood loop that makes adding each of these cheap:
1. Phase 0 lands (grammar-level plugin-ability).
2. Phase 1 lands (marker/render via saga write model).
3. Phase 2 lands (codegen Cursor/Config from per-op slot declarations).
4. From there, each op in the backlog = one file with slot decls + trait impls + scan_pointers; `sprefa codegen` regenerates aggregates; no central edits.

Critical dependency chain: saga write model must land before codegen dogfood can begin, because `render` is the op that edits files. Without the effect bus + runner write path (Layer 5), codegen stays a hand-maintained aspiration and every new op still requires central edits to `Cursor` / `Config`.
