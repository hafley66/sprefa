## Key Insights
- **CLEAN-ROOM DCG BAKEOFF, THE ANSWER: one DCG does NOT give three artifacts.**
  Two flash4 lanes, same brief, isolated. BOTH hit 397/397 parse, 397/397
  round-trip (term equality after re-parse), 397/397 tree-sitter. BOTH
  hand-wrote the printer after reverse mode failed to terminate. Lane A leaned
  on cuts (6 vs 1), lane B on if-then glue (173 lines vs 131); style changed
  nothing. Non-reversibility comes from guarding character terminals, so our
  own 69 cuts are NOT our mistake. Emitted-rule counts diverged 4/38 vs 21/39
  purely because the brief left "emitted" underspecified. PR #204.
- **numlist(1,0,_) FAILS in SWI and silently deleted every zero-arity rel.**
  Three sites: analyze.pl:291, analyze.pl:529 (both fixed, PR #206),
  lower.pl:867 (left to the surrogate lane). `rel zed().` used to fail rc=1
  with NO message. Corpus never contained a 0-ary rel because they all vanished.
- **A top-level enum rel IS a reusable named type, because it has no keys.**
  Probed: `rel body(page(view:text) ; redirect(to:text)).` +
  `rel response(id:int, payload: body).` compiles rc=0, emits body_page,
  body_redirect, body_tag, response.payload=enum id.
- **Three-state absence works TODAY with zero language change**:
  `rel maybe_text(absent() ; none() ; some(value: text)).` compiles, emits
  maybe_text_absent/_none/_some/_tag. It is literally `__opt_text`
  (0_option_expand.pl:78 = `(none ; some(value:T))`) plus one nullary variant.
  No 3VL, no `??`, and match exhaustiveness already forces all three.
- **`option(<enum>)` is a PHASE-ORDER ACCIDENT, not a design.**
  1_expansion.pl:28-29: option is phase 5, enum is phase 10. At phase 5 `body`
  is still enum_decl/2 with no col_type rows, so 0_option_expand.pl:43 throws
  before declared_rel_element/2 can succeed. Plain `payload: body` works only
  because it survives to phase 10's retarget_enum_column_types.
- **Rust/Go do NOT use 3VL for null-vs-absent.** Rust composes
  (`Option<Option<T>>`, serde double_option) but professionals use a named
  3-variant type (async-graphql `MaybeUndefined`). Go uses a (value, Valid bool)
  pair (`sql.NullString`) because zero values eat the distinction.
- **v6's serve IS the fused cli+http+lsp server the user tried in v3/v4/v5.**
  serve_tsv2 = `(config) => Observable<IServeEvent>` (4_http.ts:526); channels
  merge at :196 (ticks/effects/bind/watch/loaded/served); main.ts is 35 lines
  with THE one .subscribe(), ratcheted by `just one-subscribe`. Adding LSP is
  one more source in that merge, which is why the recon's buy verdict was
  vscode-jsonrpc (bare wire) over vscode-languageserver (own connection).
- **PR #202's hover could never have worked.** v5 has `--diag-db` for
  diagnostics (lsp.rs:102, literal SELECT FROM diag_v5 at :633) but NO
  `--hover-db`; hover_notes_at reads `txt_tbl("hover_note")` = `rel_hover_note_txt`
  (lens.rs:295, lower.rs:9-11), never the bare table v6 emits. The bare-name
  trick works for exactly ONE feature. Net no-v5 cost is one feature, not a suite.
- **dl_view is a LOSSY COMMITTED render.** It drops `: type` and whole rel
  decls; out/text-door (gitignored, .gitignore:66) is faithful. All 3 red
  bench-cli cells trace to cases.json pointing at the lossy one. Of 9 dl_view
  cases, 6 render identically and the 3 that differ ARE the 3 red cells.
