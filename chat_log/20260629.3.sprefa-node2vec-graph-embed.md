# Session: sprefa-node2vec-graph-embed

## Goal
Add an internal (no shell-out) graph-embedding capability to the v5 dl engine —
node2vec over any dl edge relation — so structural "what's wired in like this"
queries run inside dl alongside the existing text `similar` rel. Then plan the
reactive-perf follow-on (keep the embed off the hot path under git-checkout
re-ticks) + a static recompute-guard rail.

## The reactive-perf plan (the reason we paused)
plans/2026-06-29-node2vec-reactive-perf.md. Problem: eval_node2vec_rule recomputes
the whole embed unconditionally, synchronously, under daemon eng.lock(); node2vec
is GLOBAL (not cheaply incremental); every git checkout re-ticks -> full re-embed.
Workstreams (ordered W1->W5):
- W1 digest-skip (~25 lines, engine.rs): blake3 XOR-fold the edge rows, store in
  _reldigest as "node2vec:<edge>", skip embed+knn when unchanged. MIRRORS the
  scc/closure ConditionCache.digest recondense-guard (engine.rs:1214/1269). Most
  checkouts don't move the graph -> no-op. DO FIRST.
- W2 recent-digest vector cache: _node_embeddings keyed by edge_digest + LRU side
  table, so branch A<->B thrash is a hit both ways. SPREFA_N2V_CACHE=4.
- W3 switchMap async tier (daemon, env-gated SPREFA_N2V_ASYNC): recompute on a
  worker OFF the eng lock, serve last-good vectors meanwhile. MUST be switchMap-
  CANCELLABLE: gen:AtomicU64 bumped per graph change; worker checks gen between
  skip-gram epochs (cooperative cancel) AND result-drain re-checks gen (only
  latest commits). One-shot CLI stays synchronous (would exit before worker).
- W4 warm-start incremental training: DEFERRED, measured-need only.
- W5 STATIC recompute-guard rail (the user's idea): catch the anti-pattern at
  coding time. Marker convention ("// @recompute unguarded: <reason>" or a digest
  guard) in CLAUDE.md next to the N+1 rule; dl rail examples/recompute-guard.dl
  via sg/ast matching fns that call embed_graph without load_rel_digest, diag ->
  --check exit 2 (Claude blocking-hook). First row it flags = today's
  eval_node2vec_rule; W1 clears it, proving the rail. Start fn-level (not
  loop-level) for low false-positive. doc_tag may need a regex arm for Rust
  `// @` line comments (CHECK; regex form needs no engine change).

## Key Insights
- node2vec embeds a node by GRAPH POSITION (walks+skipgram), orthogonal to text
  `similar` (content). Two axes; concatenating them = the refactor-cluster signal.
- The KNN half was already generic over Vec<(id,vec)>; node2vec only swaps where
  the vectors come from. knn_rows is now the single chokepoint -> wiring sqlite-vec
  ANN once fixes both rels.
- node2vec(edge) rides the EXACT closure/scc seam: a BodyItem naming a derived
  edge rel, excluded from rebuild_derived (can't lower to SQL), evaluated after
  the edge materializes. node_sim is USER-named (not reserved) like reach/scc heads.
- scc/closure already solved "expensive global graph op on a reactive rule" via a
  per-edge content digest (recondense only when rows moved). W1 copies it.
- Stale release binary gotcha (again): target/release/dl predated df_param; had to
  cargo build --release. Rebuild before running examples after engine edits.
- Tree-wide closure(flow_edge) (386k edges) never returns in 400s; node2vec
  closure-free but its O(n^2) KNN has the same cap warning (>2000 nodes).
