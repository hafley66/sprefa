## DB NORMALIZATION — SETTLED BY MEASUREMENT, READ BEFORE RE-LITIGATING
User proposed: FK dimension tables + views, "repo/rev don't belong in the string table", "nested select is insane", "rev is repo".
Measured answers:
- **The nested-select `_txt` views are CORRECT and must NOT be rewritten as JOINs.**
  Same plan shape, but timed on a 283k-row scan: correlated-subquery view **0.01s** vs LEFT JOIN **0.80s** — the subquery is ~**80x FASTER**. Reason: the subquery is LAZY (evaluated only for columns actually consumed); LEFT JOINs are eager. `src/lower.rs:25-32` (`sym_decode`) documents this: "used only where a text value is actually consumed; sym = sym joins and literal filters never decode." I initially agreed the view was bad — that was wrong, and agreeing under frustration instead of measuring was the worse error.
- **Physical tables ALREADY store interned integer ids**, `_txt` is a view. e.g.
  `CREATE TABLE rel_call_def ("repo" INTEGER, "sym" INTEGER, "kind" INTEGER, "file" INTEGER, "line" INTEGER, "end" INTEGER, __src TEXT DEFAULT '', PRIMARY KEY(...))`.
  So repo/rev/path are already stored once. Dictionary encoding is done.
- Cardinality shows dimension tables would change the lookup target, not the bytes: repo=1 distinct, kind=23 distinct, file=506 distinct, over 283,127 df_node rows. Each row already carries a 1-2 byte int.
- **"rev is repo" is WRONG.** Orthogonal: one repo has many revs (WORK/HEAD/shas) — the basis of the `_rev` twins and graph-diff. This db shows only `rev=WORK` because its program scans only WORK. The CORRECT form of the instinct: `rev` is meaningless without `repo`, so intern the PAIR as ONE snapshot id instead of two columns.
- Legit smell (clarity not size): `repo` on a rel is an interned string id while `rel_repo` is a separate table — two representations of "what is a repo".
- **The real 25MB of waste**: 314,892 dead salted rows (15MB, no `_strings` GC exists) + 128,216 minted syms `file::kind::name` (10MB). Neither is view shape.

## Key Insights
- **PER-ROOT DBs BLOCK CROSS-REPO.** Daemon registers a root PER DIRECTORY; instant/smashy/sprefa are 3 separate SQLite files. sprefa's db has exactly ONE repo (`SELECT DISTINCT repo` -> `sprefa`) while every rel carries `repo` as a first-class column and `scan("*")` fans across config repos — machinery built and unused. **`_strings` is PER-DATABASE, so interned ids are dictionary offsets local to each db; id 4711 in two dbs are unrelated strings. ATTACH+join is meaningless.** Same defect class as salt_rev: an identifier whose meaning depends on hidden context. GOOD NEWS: since `repo` is already an interned id column, ONE db holding many repos needs NO schema work — only the per-directory registration assumption blocks it. No ATTACH needed.
- **Router stale-rel bug — the one genuine release concern.** `retraction_props.rs:499`, `#[ignore]`d with the reproducing seed IN the attribute string. Per the file's comment (465-482): when a call-family input rel (e.g. `_call_def`) is EMPTY on the tick that first populates the router memo, `Ctx::scan` records no per-row deps, so the memo footprint OMITS it; later inserts never trigger a rerun of `call_def`/`call_name`/`call_def_rev` and THE PUBLIC REL STAYS STALE. Seed persisted in `tests/proptest-regressions/retraction_props.txt`, scoped to the FILE not the test — the non-ignored 20-case sibling at :487 shares the strategy and may already replay it.
- **Salt: gone from src (0 hits); live dbs SELF-HEAL by accident.** `extract_digest_key` = `format!("extract:{:032x}:{family}:{rev}", exe_stamp())` — the binary stamp namespaces skip-state so a new binary does one cold rebuild. That keying exists to stop daemon/CLI digest ping-pong, NOT for id-derivation changes; covers this by luck. Does NOT self-heal: 314,892 orphaned `_strings` rows, because `_strings` has no GC.
- **mint_sym is salt_rev's bigger twin, detected but SILENCED** by `composite_key_baseline("src/graph/typegraph/mod.rs", 4)`. 128,216 rows / 10MB. Agent dispatched.
- **Audit totals, 1,532 tests**: OK 1,484 / FALSE-GREEN 22 / SKIPPED-PROBLEM 2 / ENV-GATED 15 / NOT-A-TEST 8 / REDUNDANT 1 / STALE 0.
- **22 FALSE-GREENs, one shape**: early exit on a missing external tool with NO `#[ignore]`. `oracle_go.rs`/`oracle_ts.rs` module docs call this INTENTIONAL — the documented rationale IS the anti-pattern.
- **sg vs match receipt**: same rail, same intent. `match` (line regex) found ZERO — not even the incident that motivated it (spans 3 lines). `sg` pattern `"return;"` found 39, catching every FALSE-GREEN all five auditors named independently. sg also sees inside `#[cfg(test)]`, which `call_def` does NOT (between src/ast.rs:548 and :650 the only call_def row is `SpliceMode.tag` at :643 — the 617-test unit layer is invisible to ANY call_def-based rail).
- **sprefa CANNOT structurally refactor its own language**: no `dl` grammar for match_ast; `.dl` is reachable only by line regex; `--move` is a Rust/TS/Kotlin symbol mover. That's why the rename wasn't `dl --move`.
- **Rail gap, not papered over**: `const_value.rs:153` is `Err(_) => {}` — an EMPTY arm. No `return` for arm 2; arm 1 counts the `Ok` branch's asserts as covering the test. Needs per-path assertion reachability.
- **ONE `match_line` legitimately survives**: rail arm 3 predicates on the TEXT CONTENT of an `#[ignore]` reason. sg matches `#[ignore = $REASON]` but METAVARIABLES ARE NOT EXPORTABLE (outputs = line/col/end_line/end_col/id). Real engine gap.
- **gh-cache.dl real defects** (found via the old repo's scenario list): (a) the 3-line `status\netag\nbody` stdout protocol silently JOINS a body containing a newline via `tr -d '\n'` (`"weird/multiline\nname"` -> `"weird/multilinename"`), now a known-gap canary; (b) `fetch` never passes `--paginate`, so list endpoints beyond page 1 silently truncate; (c) `pull_request` retraction CHECKED AND FINE — plain derived rule over `resp_current`, retracts for free.
- **~/projects/ghcacher (116 tests) is a TEST ORACLE for the rewrite.** `MockGhClient` records `Vec<(String,String)>` (not a bare counter); `assert_eq!(mock.graphql_call_count(), 1, "expected 1 batched GraphQL call, got {}")`; `== 0` for no-work paths; persisted `call_log` with `cache_hit`. CRUCIAL: its fallback `.unwrap_or((200, json!([])))` RECORDS THE CALL FIRST then falls back; sprefa's 404 masked AND never recorded. Rule: ALWAYS RECORD, then fall back.
- gh-cache request digest is `(head_rel, kind, {ep, prev})` with NO bucket salt (`src/effect.rs:508-653`) — once an (ep, prev) resolves it never re-fires on a later bucket. "N per bucket" is really "N once, ever, per distinct (ep, prev)".
- `effect_log` dedups by request digest so it CANNOT count actual shell executions; counting must happen at the point of execution.
- `_write_ledger` gap: `resp`'s writes happen off-tick in `drain_effects` and never land under their own name (that table only flushes inside `tick()`).
- `CLOCK_LOCK` is a std Mutex that POISONS on panic, cascading PoisonError onto siblings — turns one honest failure into four misleading ones. Pre-existing.
- `src/activity.rs` `SLOT` global static races under the default harness; that is what "load-sensitive" meant for `lifecycle_round_trips`.
- Agent A's blind spot, the general lesson: file-ownership splits that stop concurrent agents colliding are ALSO what let a design inversion land with its own spec test stranded in an unowned file.
- Recurring pattern: an agent making a test "robust" by smoothing over an unexpected signal (the 404 fallback) is indistinguishable from suppressing evidence. 3x today.
