## Problem/Context
Two threads.
The kwargs thread: session 5 shipped `opt_var` (engine.rs:4067) and
`parse_kwarg_terms`/`assign_outputs` (parse.rs) for `comment()`'s three
outputs. sg/ast_yaml had four span outputs (line/col/end_line/end_col) still
in the old shape: `line` mandatory positional, col/end_line/end_col as
`Option<Term>` chained "each only parsed if prior is present." This forced
`sg(p, rev, :rust, "pat", l, _, _, _)` to bind a later slot and made the
zero-output file-filter form impossible. The helper pair was generic;
sg/ast_yaml were the remaining ~4-lines-each callers.

The grammar thread: session 5 shipped the TextMate grammar (a47f1e5). Three
gaps were visible on ban.dl: (a) `path: file` in rel decls rendered the
type name as a plain variable (no type scope); (b) `end_col: ec` kwarg
names had no distinct scope; (c) `"dbg!($X)"` ast-grep metavars inside
strings were not sub-tokenized (only regex literals had `$NAME`). A fourth
gap surfaced when the user opened ban.dl with the installed extension:
`diag(` in head position rendered as a plain lowercase variable, not a
relation/function name.

## Solution/Approach
### S1: sg/ast_yaml kwargs (`420879c`)
ast.rs: dropped `Option<Term>` on Sg/AstYaml col/end_line/end_col. All four
span outputs are now `Term` (Wild = unbound), matching Comment's shape. The
engine arm conditionally binds via `opt_var` for all four (was `var_of` for
line, `.as_ref().map(var_of).transpose()` for the three Options).

parse.rs: sg()/ast_yaml() now call `parse_kwarg_terms` + `assign_outputs`
after the pattern/yaml string, guarded by a comma check (zero outputs is
valid -- the file-existence filter form). The helper pair is unchanged from
session 5. assign_outputs defaults unmentioned slots to Wild.

engine.rs: both arms switched to `opt_var(line/col/end_line/end_col)` and
`if let Some(v) = &slv { ext.insert(...) }` conditional binding. Captures
($NAME metavariables from ast-grep) are unaffected -- they still insert
unconditionally.

typecheck.rs + frontend.rs: the normalize/rewrite arms flattened from
`[path, rev, line]` + `[col, end_line, end_col].into_iter().flatten()` to
a single `[path, rev, line, col, end_line, end_col]` slice (no more Option
wrapping). normalize_term/rewrite_term on Term::Wild are no-ops (early
return on non-PathLit / non-Var).

### S2: grammar relation-call + annotations + metavars (`420879c`)
dl.tmLanguage.json: four new/updated rules.

relation-call: `\b[a-z_]\w*(?=\()` scoped `entity.name.function.dl`. Placed
after keywords so scan(/sg(/match(/etc. keep their keyword scope; this catches
diag(/sec(/hit( and aggregate calls like count(. Covers decl names, rule
heads, body atoms, and queries in one rule.

rel-annotation: `([a-z_]\w*)\s*:\s+(text|int|path|file|dir|repo|rev)` with
capture 1 = `variable.parameter.dl`, capture 2 = `storage.type.primitive.dl`.
The space after colon is the dl convention (lex.rs rejects the no-space form
as an unknown scheme). Type set from Type::parse in ast.rs.

kwarg-name: `([a-z_]\w*)\s*:\s+` with capture 1 = `variable.parameter.dl`.
Placed after rel-annotation so known types take priority; catches everything
else (end_col: ec, label: lab).

string metavars: new sub-pattern in the string rule matching `\${3}[ident]`
(variadic $$$X) and `\$[ident]` (single $X), scoped
`constant.other.placeholder.dl`. Mirrors the regex-literal $NAME sub-tokenizer.

## Key Insights
- The kwargs mechanism is now uniform across all three source ops with
  multi-output spans (comment, sg, ast_yaml). The pattern: ast struct holds
  bare Term fields (Wild = unbound), parser calls parse_kwarg_terms +
  assign_outputs with the field-name slice, engine arm uses opt_var and
  conditionally inserts. Adding a new op with span outputs follows this
  template mechanically.
- Zero-output sg is a file-existence filter: the engine produces one bind
  per match with nothing new inserted, and the relation's set semantics
  dedup to one row per file. `hit(p) <- scan(...), sg(p, rev, :rust, "dbg!(_)").`
  emits one row per file containing the pattern. This fell out of the
  opt_var refactor for free -- not a special case.
- TextMate rule ordering: keywords must precede relation-call (so scan/sg/
  match keep keyword scope); rel-annotation must precede kwarg-name (so
  `path: file` scopes the type, not just the param); both must precede
  variable (so the ident isn't consumed as a plain variable first). The
  `ident(` lookahead in relation-call is zero-width, so the `(` is left for
  other rules (currently unscoped punctuation).
- vsce package includes syntaxes/*.json and out/extension.js automatically
  (referenced in package.json contributes). No manual file list needed.
