# Session: v3-tiny-lowering-core-prototype-scope

## Goal

Narrow the v3 min-prototype to a lowering/semantics validator. The
prototype is not a perf bench, not a plugin framework exercise, and not
a runtime-reactor proof. It is a harness for:

- tree-sitter host parse
- env + resolver + BindingGraph + StageDeps
- cross-rule refs
- rule DAG construction
- diagnostics surface (parse, lower, run)
- arg-mode dispatch (Rust-side only)
- core algorithm of the tag operator
- prolog-max posture: "query all tags" as a first-class capability

Everything outside that lane is out of scope for the prototype.

## Prototype scope (revised)

### In scope

1. tree-sitter-sprefa grammar.js (minimal surface enough to exercise
   lowering)
2. Host parse → AST → env build → resolver → BindingGraph + StageDeps
   → lowered Pipeline form
3. Three Pipeline cases implemented: Op, Chain, Group. Fork parsed but
   can short-circuit if test programs do not use it.
4. Cursor Shape C end-to-end
5. Built-in ops:
    - `fs(glob)` — file source
    - `re(pattern)` — regex match
    - `tag($X, :kind)` — **the focal op**. Writes a relation row keyed
      by (term_path, kind) at bind time. Readable back by another tag
      read.
    - `rule` — declaration form
6. Arg-mode dispatch harness (Rust-side ArgSpec)
7. In-memory stores:
    - `HashMap<SprfPath, Vec<Row>>` for evidence
    - `HashMap<TagKey, Vec<TagRow>>` for relation rows (the prolog-style
      queryable substrate)
8. Diagnostics: parse, lower, run phases each produce typed diagnostics
   to a collecting sink. Validation is "given program X, expect
   diagnostics set Y."
9. Cross-rule reference: one rule references another's captured term in
   a chain stage. Validates resolver + DAG.
10. Query-all-tags capability: one op (or one query form) enumerates
    every tag relation row. Exercises prolog-style retrieval.

### Out of scope

- SQLite (HashMap only)
- LSP
- Op registry via inventory + folders (hardcoded in one crate)
- Higher-order control ops
- Mutation effects + approval handlers
- `@recursive` + Tarjan cycle detection (reject self-refs bluntly)
- Perf / benches / RSS / throughput
- Reactor / streaming backpressure (run-to-completion, bounded channels)
- Incremental reparse + cancellation
- LSP diagnostics routing (diagnostics collected to Vec, asserted in test)
- Term-annotation grammar (Section 14)
- Strings-are-ops collapse
- Scalar-as-Op collapse
- Subscribe policies (Cold only)
- `sh` op

### What the prototype proves

- **Lowering correctness.** AST → Pipeline enum for the four cases.
- **Resolver correctness.** Cross-rule refs resolve to the right
  EntityRef. BindingGraph catches statically-unresolvable cases.
- **StageDeps correctness.** Per-stage reads/writes computed, ordering
  respected at run time.
- **Arg-mode dispatch correctness.** Each built-in op's ArgSpec is
  respected; mismatch produces lower-phase diagnostic.
- **Tag operator algorithm.** `tag($X, :repo)` binds relation row; a
  second read enumerates by kind; prolog-style query returns matching
  rows.
- **Diagnostics model.** Each phase emits typed diagnostics collectible
  for assertion.

### What the prototype does not prove

- Runtime performance under load
- Plugin author ergonomics
- Incremental parse behavior
- Multi-repo orchestration
- SQLite schema correctness
- LSP hover/completion

## Test shape

Each test is a `(program_text, expected_diagnostics, expected_rows,
expected_tags)` tuple. Harness:

1. Parse `program_text`.
2. Collect parse diagnostics.
3. Lower to Pipeline.
4. Collect lower diagnostics.
5. Run subscriber.
6. Collect run diagnostics, evidence rows, tag rows.
7. Assert all four collections match expectation.

No timing, no RSS, no throughput. Correctness only.

## Tag op — focal design

```rust
// pseudocode
struct TagOp;

impl Operator for TagOp {
    fn signature(&self) -> Vec<ArgSpec> {
        vec![
            ArgSpec { name: "term", accepts: AcceptsMode::Either },
            ArgSpec { name: "kind", accepts: AcceptsMode::BoundOnly },
        ]
    }

    fn pipe(&self, ctx: OpCtx, input: CursorStream) -> CursorStream {
        // for each cursor:
        //   resolve TermMode for arg 0
        //   kind is always literal atom from arg 1
        //   match (term_mode, kind):
        //     (Bound(v), k)   -> write TagRow { term_path, kind: k, value: v }, pass cursor
        //     (Unbound, k)    -> read TagStore by kind, emit one cursor per row with term bound
        //   diag on kind not an atom
    }
}
```

Query-all-tags variant: an op `tags()` or a rule form that enumerates
`TagStore` without filtering by kind. Returns one cursor per row with
both term and kind bound.

This gives prolog-style bidirectional `tag` relation. The unification
machinery is the op's per-cursor dispatch; no global SLD or backtrack.

## Example test programs

```sprf
# Program 1: write then read
rule(seed) > fs(r"examples/*.txt") > tag(&.fs, :file)

rule(readback) > tags() > filter(kind == :file)
```

```sprf
# Program 2: cross-rule ref
rule(sources) > fs(r"src/**/*.rs")

rule(audit) {
  > sources
  > tag(&.fs, :source)
}

rule(list_sources) > tags() > filter(kind == :source)
```

```sprf
# Program 3: bound vs unbound dispatch
rule(find_by_kind, $K) > tags() > filter(kind == $K)
# call: find_by_kind(:source)
```

Each exercises a different arm of arg-mode dispatch and the DAG.

## Key insights

- **Prototype is a language-semantics validator, not a runtime proof.**
  Correctness assertions only; no timing, no RSS.
- **Tag op is the focal algorithm.** Bidirectional dispatch
  (bound → write, unbound → read) gives the prolog flavor without
  needing a solver.
- **Query-all-tags is the prolog-max driver.** Makes the relation tier
  user-reachable, validates the "shallow prolog" stance works in
  practice.
- **ArgSpec stays in Rust.** Section 14 is a later concern. Derivation
  plus Rust-side `AcceptsMode` covers the prototype.
- **Diagnostics are first-class test output.** Each phase emits typed
  diags collectible by the harness; "given program, expect diagnostics"
  is the main assertion shape alongside emitted rows.
- **LoC budget forces discipline.** Under 1500 means any design
  tangent routes around the prototype, not through it.
