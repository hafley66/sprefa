## Key Insights
- The 4.3hr count_pairs is an EXTRAPOLATION (measurements.md:89), never run, on
  ONE pathological relation (rel_flow_edge, max SCC 22,257 / mean reach 15,653).
  On the normal relation (rel_df_edge) it was ~4s. "No published SQL SCC" prior-
  art came from lite-ddg after WebSearch budget died (3 CAPTCHAs). Don't trust the
  corpus - re-measure.
- count_pairs COUNTING is already efficient (condensation bitset, ncomp^2/64, v5
  verbatim, 9dacb0d7). Only `scc_labels` materializes the full V^2 closure - the
  lone lever. INSIGHTS S1 already said "production must avoid materializing the
  closure."
- cascade (assert/retract/retract_scc/retract_dred/retract_dred_cte) is the
  GENESIS + most oracle-covered family (agreement.rs: oracle==counting==DRed==dd
  byte-identical; referee=oracle_survivors; yardstick=dd). Reconcile is the only
  real oracle gap (salsa not ported).
- The salsa lesson transfers symmetrically: reconcile::dirty is a FRONTIER
  (one-hop, early cutoff, O(delta)), NOT a full closure. scc_labels recomputing
  the full closure from scratch VIOLATES the arc's own thesis. Fix = derive SCC
  labels from maintained frontier state, not a from-scratch closure CTE.
- UNIFICATION MATH (settled): retraction (dd) and salsa are ONE machine over
  DIFFERENT semirings. Instance A (dd): v_k in Z, +=, delta_k=Sum m*delta_i,
  carry=zero-crossing, no code. Instance B (salsa): v_k=(dirty,val), recompute
  CODE_k, carry=digest-changed, cutoff. Converge when CODE_k is linear; diverge
  when non-linear/external (docker run, parse). engine.rs already embodies both
  (cascade=A, reconcile=B). The ONLY difference: is the value a SUM (dd) or a
  COMPUTED OBJECT (salsa).
- Theory mapping: salsa=deps/react->Reconcile; dd=derived-reactivity-graph->
  Cascade; values=mat-view-nodes->Reach. SQLite masters all three under a RAM
  budget (state on disk, RSS=page cache, Rust heap ~0).
- Execution model: Souffle/datalog run-to-completion (eager); we want
  async/lazy-by-default frontier (demand/subscribe, external events/rx,
  resumable). reconcile::dirty is the primitive. Goal: general reactivity
  language, datalog -> prolog.
- Temporal = bitemporal FACT plane (versioned Z-set, same weight arithmetic as
  cascade + history); NOT a graph-parity family; substrate for the resumable
  frontier (run/pause/resume = revision-stamped facts = the event log).
- Native async-fn-in-trait works (no async_trait dep needed); silence the lint
  with `#[allow(async_fn_in_trait)]`.
- engine.rs is already ONE SQLite file (cascade/reach/reconcile/temporal); don't
  consolidate, add the trait layer.
