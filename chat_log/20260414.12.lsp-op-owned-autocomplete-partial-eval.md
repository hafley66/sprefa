# Session: lsp-op-owned-autocomplete-partial-eval

## Goal
Add op-owned LSP autocomplete to sprefa v2 so each op describes its own suggestions inside its paren/brace slot. Initial target: see real values for repo/rev/fs in the editor via partial pipeline evaluation.

## Current State
- **Committed**: `7372ed0` op-owned LSP completion scaffolding + wildcard_instance.
- **Build**: green (lib + bin), 10 unrelated warnings only.
- **Pending refactor (NOT yet started)**: collapse `scan_partial` shadow path into the existing runner via Pipeline rewrite. The current `scan_partial` is a parallel shadow path and was committed as WIP per the note in the commit body — to be deleted in the next session.

## Problem/Context
User's central correction: "why cant we make it so that the runner is partial by default... the whole thing is supposed to be reactive and partial falls out from that." I had built `scan_partial` with its own seed_cursors + fresh config + fresh MemWriter alongside `run_scan_loop` + `Pipeline::run`. Two universes to keep consistent. Wrong.

The correct shape: partial evaluation is the existing runner evaluating a TRUNCATED + SUBSTITUTED Pipeline through the SAME ctx/config/reader. Same machinery, different input.

User principle: "min entity, least entity, keep entropy low." Saved as `feedback_min_entity.md`.

Architectural alignments locked earlier in session:
- DocSession is a READ-MOSTLY cache/client. Today daemon is in-process (so "read" = function call); tomorrow daemon is a separate process and DocSession holds an RPC stub. Same API both ways.
- ResultStore is the in-memory precursor to daemon SQLite store.
- Buffers never write. Writer NoOp during LSP runs. Ops suffixed `_write` short-circuit under LSP ctx (convention, future enforcement).
- Stable identity is a separate track (tier 0 byte_range / tier 1 structural_path / tier 2 SCIP / tier 3 semantic). Not a prerequisite for completion.
- 3-layer Reader stack (Blob/WT/Buffer via CheckoutLocator) is the substrate for cross-layer EntityId matching.
- Completion kind is `kind_hint: Option<Arc<str>>` (op-authored free-form tag), no central enum.

## Solution/Approach

**Design that's agreed and committed:**
1. Wildcards legal in repo/rev (committed: `repo/no-op-glob` and `rev/no-op-glob` Errors dropped).
2. ONE new slot on `Operator`: `wildcard_instance(parse_site) -> Option<Arc<dyn Op>>` (committed: implemented for RepoFactory/RevFactory/FsFactory).
3. Completion flow:
   - `locate_paren_op(source, pos)` → textual find of enclosing op name + partial (committed).
   - Use `span_ix` to resolve op_path for the enclosing parsed op (TODO).
   - **REWRITE the rule's Pipeline**: replace target op with `wildcard_instance`, truncate Seq downstream (TODO).
   - Call `run_pipelines(&[(rule_name, rewritten_pipeline)])` — extract from `ensure_run` (TODO).
   - Harvest `RunReport.cursors_by_rule[rule]` = wildcard op's output (TODO).
   - Map cursors through `wildcard_op.witness()`, dedup, filter by partial, cap at 1000.

**Concrete refactor for next session (top-priority):**
1. DELETE `scan_partial` + `seed_cursors` from `src/_14_scan_loop.rs`.
2. Extract `ensure_run` core in `src/analysis.rs` into `fn run_pipelines(&self, pipelines: &[(Arc<str>, Pipeline)]) -> RunReport`. `ensure_run` calls it with `self.pipelines`. Completion calls with a singleton rewritten pipeline.
3. Add Pipeline rewrite helper: `truncate_and_substitute(p: &Pipeline, at: &[usize], wildcard: Arc<dyn Op>) -> Pipeline`. Handles Op/Seq/Fork variants per the op_path encoding in span_ix (`[i, 0]` = rule op i; `[i, 0, fork_idx, j]` = inner op j in fork arm fork_idx of rule i).
4. Rewrite `complete_in_paren` in analysis.rs:
   a. Find op_path via span_ix OpName entry whose range lies just before the located open paren.
   b. Build rewritten pipeline.
   c. Call run_pipelines.
   d. Harvest witnesses via `wildcard_op.witness()`.
5. Manual smoke test: open .sprf in LSP, hit completion inside `repo(|)`, `rev(|)`, `fs(|)` — see real values.

## Key Insights
- **Min entity, low entropy**: extract and reuse, never build parallel shadow paths. Reactivity/partial-eval falls out of running truncated inputs through the same runner. Saved to feedback_min_entity.md.
- **DocSession is a client, not a computer**: holds cache mirror + RPC stub. Today's in-process runner is tomorrow's daemon RPC. The API doesn't change. Buffers never write.
- **Completion = hover-before-value-exists**: both are filtered views of the cursor collection. One substrate, one machinery.
- **wildcard_instance is the only new Op slot needed**: framework handles splicing, running, harvesting. No `complete_sync`, no `complete_async`, no `candidate_witnesses`, no `CompletionKind` enum.
- **Kind is free-form Arc<str>**: bin does best-effort icon mapping, falls back to generic. New ops never edit a central enum.
- **Future vision (mentioned for context)**: doc assembly via queries + reverse-index hover from comment-authored notes. Requires stable EntityId (structural path), separate track.
- **Writer invariant**: LSP ctx = no writes. Buffers never persist to store. Ops ending `_write` short-circuit in LSP mode.

## Open Questions
- When op at cursor doesn't parse (e.g. mid-typing `rev(ma`), span_ix has no entry. For MVP: graceful degradation (return empty). Future: synthesize a fragment parse.
- `run_pipelines` signature — does it need the `cursors_scratch` mutex plumbing, or can we return cursors directly from scan-loop callback? Refactor should clean this up.
- Harvesting strategy: wildcard is always a Pipeline::Op terminal after truncation, so `Pipeline::run` output stream IS exactly those cursors. Confirms no per-op evidence-filter needed for completion (unlike hover).
- workspace_root is a field on DocSession but no caller sets it — bin should call `session.set_workspace_root(...)` in `open_or_replace`.
