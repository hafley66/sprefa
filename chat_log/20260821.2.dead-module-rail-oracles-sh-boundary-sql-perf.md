## Problem/Context
Rail v3 was reporting LIVE code as dead. `soopy/src/_3a_files.rs` was flagged
against 19 live calls to `snapshot`. Root cause: a receiver call
(`directory.snapshot(...)`) carries NO `callee_path`, and only 24% of sites in a
real crate carry one, so a call site offers a NAME and nothing else. The
`unique_name` guard therefore can never mark an ambiguous name live.

## Solution/Approach

### 1. Two oracles, opposite blind spots (this is why both fixtures exist)
- **rustc `dead_code`** cannot see a `pub` item in a lib crate (assumed used
  downstream). `dead_pub.rs` is that case.
- **knip** cannot see a module that IS imported but whose exports nothing ever
  CALLS, because an import is a use to a module graph. `importedNeverCalled.ts`
  is that case.
- The rail reads called names, so it sees both. Every fixture file is labelled
  with what BOTH tools must say. Both gates sabotage-tested and shown RED.
- **The rail runs on TypeScript UNCHANGED.** sprefa-extract emits the same
  node/site records for `.ts`; zero rules needed porting.

### 2. Three buckets instead of a guess
`unique_name` as a guard -> false positives. Dropping it -> false negatives
(`chat.rs` really is dead, goes silent because `snapshot`/`project_line` name
four other files). So:
- `rail_dead_module` -- no call site anywhere names any def here
- `rail_unproven_module` -- reached ONLY through a name several files define
- `rail_unreachable_module` -- the crawl from declared roots never arrives

hafley-rs: **0 dead, 13 unproven, 0 false positives.** Both `chat.rs` (truly
dead) and `_3a_files.rs` (truly live) land in unproven, which is the true state
of knowledge from call-family data alone.

Also: roots from `cargo metadata` (9 entry points) instead of one hand-typed
`main.rs`. Def-class plane (free/inherent/trait, owner spans, qualified calls)
DELETED -- every class reached the same rule.

### 3. `sh` gone from extract/soopy paths (`sh_spawn` count 0)
- `SoopyFilesExecutor` replaces the `files` host's `sh -c` + `mktemp` + `paste`
  + a second `ls-files` with `soopy::enumerate`.
- THREE extract hosts were missing from `.adapters.json`, so they spawned the
  48MB binary through `sh -c` 246 times a run AND failed `is_applicative`, so
  the runner could not group them.
- `ShellExecutor` now has `warn_span!("sh_spawn")`; `linked_twin_for` warns BY
  NAME when a command a linked executor answers reaches the shell.

### 4. The engine had NO tracing at all
No dependency, no span. That is why THREE guesses in a row were wrong. Added
`tracing` + `tracing-subscriber`, stderr only, silent unless RUST_LOG asks:

    RUST_LOG=sprefa_engine_rs=info emit_rust_harness <prog> <sched> --live-hosts
    DL_SEAM_SHAPES=1 ...   # per-shape inert/live SQL breakdown

### 5. cfg(test) defs marked and subtracted
`record=cfg_scope family=call span={start,end} cfg=<predicate>`, emitted ONLY
for guarded defs so no golden moved. Predicate split on non-word chars and
compared whole: `any(test, feature="x")` matches, `feature="testing"` does not.
Needed a `registry.pl` row because `host_input_contract` is keyed on hardcoded
host NAMES (**ARCH.pl D1**).

## Key Insights

- **A host output column you never read is a ROW MULTIPLIER, not a wasted
  field.** `span` made all 17929 call sites distinct where 5310 distinct
  (file, callee) pairs exist. Deleting one word: tick-2 arrivals 21194 -> 3501.
- **`soopy::discover` walks the filesystem for `.git` and costs 28ms.** Called
  per FILE it was 2.29s of a 3.55s run. Now memoized per directory, 82 -> 10.
- **Extraction was never the cost.** 0.14s of 8.7s. Nor decode (0.09s). Nor a
  response memo (never hit once, removed).
- **Inert SQL is cheap.** 741 of 1787 statements (41%) return nothing and change
  nothing, but the largest inert group costs 5ms. Skipping them is not a win.
- **MEASURED AND REJECTED, do not retry blind:**
  - per-tick `BEGIN/COMMIT`: 1.65 -> 1.71s. The seam is `open_in_memory()`, so
    there is NO fsync for a transaction to amortize.
  - one group per (rel, sign) instead of consecutive runs: 1787 -> 1027
    statements but 1.63 -> 1.72s. One IN-list of 15000 placeholders costs more
    than the fifty small statements it replaces. **Statement count is not the
    thing to minimize.**
  - a per-(content-address, mask) extraction memo: never hit, cost an Arc copy.
- **Real latent bug found and fixed:** `apply_arrivals` expands one placeholder
  per column per row; a big enough run exceeds SQLITE_MAX_VARIABLE_NUMBER
  (32766) and panics `too many SQL variables`. Now chunked at the write.
- **Indexes are NOT the problem** (I implied they were, then measured): max 2
  per table, 12 tables have none, 117 total across 33 tables.
- 181 lines of dl6 -> 32 rels, 33 tables, 361 DDL statements. Each rel gets a
  base table plus `__delta` and `__frontier` twins.
- The sonnet lane's generic-arrow fix was CORRECT; my earlier `_ReturnAlias`
  worry was wrong (`relation_arrow_alias/3` only fires on a `type`-typed column,
  which a template already refuses). Its conformance fixtures ran pre-parsed
  ASTs and passed with the parser fix reverted, so I added 3 parser-door tests.
