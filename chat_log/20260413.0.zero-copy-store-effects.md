## Key decisions

- **Naming**: Reader (reads), Writer (writes), Operator (factory), Op
  (instance), Extractor (Js/Rs/Sprf), Runner (orchestrator), Config (signal).
  Sprefa is the app; SprefaCLI and SprefaLSP each own one.
- **Streams**: `cursor$ = Stream<Cursor>` scalar tuples, not `Stream<Vec>`.
  Batching lives at sinks (`.bufferTime`/`.bufferCount`). Prolog/SQL
  semantics come from stream topology, not payload shape.
- **Reader coalesce**: `bytes$(repo,rev,fs)` is shareReplay(1); one read per
  tuple per scan depth. Daemon re-emits on file change; immediate emits once
  and completes. Same trait, mode-agnostic.
- **Writer bulk-only**: every method `&[T]`, prefixed `write_*` /
  `rewrite_*` / `shell_*`. SQLite perf + clarity.
- **SQL stays inside** forever. Memory-only files indistinguishable from
  disk at the Reader boundary (LSP buffers win without ops knowing).
- **Reference classes**: `$NAME` (output capture) / `$$repo|$$rev|$$fs`
  (scan provenance, reserved) / `${rule.$V}` (cross-ref, FK + DAG edge).
  Framework-classified at parse.
- **Tables**: preserve v1 (repos/revs/files/strings/refs/rev_files/rule_data
  with `_ref`/`_str` dual columns). Add cross-ref FK columns + one-hop view
  per rule. No `_expanded`/`_deep`; transitive is user-SQL.
- **Op trait**: `fn pipe(input$, ctx) -> output$`. One method. Immediate and
  daemon collapse here.
- **Lispy aliases**: `fs`/`fs?`/`!fs` route to same factory, flag-driven.
- **Pipeline enum**: Op/Seq/Fork/Switch. Seq is default brace lowering;
  Fork preserves v1 denormalization via groupBy on provenance key.
- **Rule as operator**: no special construct. `$rule[name](args){body}` is
  just an op whose factory registers a RuleHandle in ProgramCtx. Same for
  `$check`, `$render`, `$namespace`, `$let`, `$include`.
- **Cursor.path**: `SprfPath` trail of op segments (Arc<[PathSeg]>).
  Framework-populated, not op-touched. Enables awk-style conditionals and
  auto-sprf_loc on diagnostics.
- **Diagnostics sink**: channel on OpCtx, fire-and-forget. Runner
  multiplexes to RunEvent stream + batched effect_log writes.
- **Provenance + audit**: repo_rev_provenance, run_visits, effect_log —
  every selection, every effect logged. Replays debuggable.
- **Extractors unified**: Js/Rs/Sprf all implement the same trait. Sprf is
  data-driven parity with hardcoded ones.
- **Scan modes**: immediate / daemon / check / rewrite — pick Reader impl +
  Runner lifecycle. Same Pipeline per rule.
- **Cycle prevention**: run_visits keyed on (run_id, op_id, path_hash,
  cursor_hash). Router-side check before dispatch.

## Additional design passes (added after initial save)

### ParseSite — parse-time coordinate
See `v2/README.goals.md` §25. Every OpInvocation and every pattern leaf
gets an `Arc<ParseSite>` with structural path (`Top[2]/BraceChild[0]/
PatternLeaf["a.x"]`) + file + byte range. Back-linked from runtime
`PathSeg` for both coordinates on one structure.

### Implicit tree branching in patterns (1-many)
See `v2/README.goals.md` §26. v1's `json({a:{x:$X}, b:{y:$Y}})` sugar
handled by op-internal fan-out: factory decomposes pattern into
`Vec<LeafPattern>`, pipe emits N cursors per input (one per leaf), each
tagged `PathSeg::LeafArm{key, parse_site}`. Default sink = one row per
cursor (OR / monomorph semantics). Explicit `$join_by($$fs)` op for
users who want merged rows. Same decomposition strategy for ast/toml/yaml.

### v1 file reference map
See `v2/README.goals.md` §27. Canonical "don't rediscover" table of v1
crate paths and what to reuse / kill for v2. Covers backbone DDL, rule
table DDL, Store trait, SqliteStore, FTS5 patterns, cross-ref resolution,
discovery loop, incremental scan, rule-change hashes, JS/RS extractors,
watcher, CLI, LSP. Also lists what NOT to copy (analyze.rs guesser,
1498-LOC lower.rs, LSP pattern-finder duplicate).

### Open questions for next pass
See `v2/README.goals.md` §28. Ten items including check SQL rewrite
heuristic, $join_by semantics, negation syntax, multi-hop flatten,
$include semantics, pattern decomposer sharing, shell permission locus,
Stream-await vs coroutine upgrade, test harness shape, LSP token dogfood
bootstrap order.
