LSP retraction runtime

A generated map for the v4 design: content keys identify rows, owner keys identify output slices, dirty deps rerun only subscribed owners, and visible deltas decide whether downstream work wakes.

Core invariant
owner_key = H(pipe_hash, instance_id, depth, op_path, input_key) row_key = H(table_name, canonical_row_payload) visible = support_count(table_name, row_key) > 0

Foundation Layers

01
foundation Content ids

SQLite rows already get content-derived _id values. That gives the reconciler a stable row key, independent of insertion order.

02
missing core Owner slices

Every materialized op needs an owner key: pipe hash, instance id, depth, op path, and input key.

03
missing core Replace outputs

Rule rows, diagnostics, hovers, mounted SQL, git diff rows, and poll rows should all write through one replace-slice API.

04
partly live Dirty deps

Reads park continuations on table, file, git, poll, or external dirty keys. Dirty keys rerun owners, not whole worlds.

05
core bailout Visible delta

If a rerun produces the same content row ids, no downstream dirty event fires.

06
runtime loop Completion boundary

A run drains immediate work until only parked subscriptions remain. Watchers and polls schedule future epochs.

Replace Slice API

Type signatures
replace_outputs(owner, table, rows) -> VisibleDelta VisibleDelta { inserted_row_ids, retracted_row_ids }
Instance timeline
  • LSP save or watcher emits a dirty key.
  • Parked rows subscribed to that key rerun.
  • Each materialized op writes a new output slice for the same owner.
  • Store diffs old support rows against new support rows.
  • Empty visible delta stops propagation.
Storage reads and writes
  • Read old supports by owner key.
  • Hash new output rows by content.
  • Insert added supports and visible rows idempotently.
  • Delete removed supports.
  • Delete visible rows whose support count reaches zero.

LSP Save Flow

LSP save -> file dirty

save dispatches FILE_DOMAIN for the changed path

file dirty -> read rerun

parked read continuations wake by file key

read rerun -> owner rerun

stable owner key runs against new bytes

owner rerun -> replace outputs

old owner slice is diffed against new rows

replace outputs -> visible delta

shared rows keep support; stale rows retract

visible delta -> downstream wake

only real visible changes publish table or row dirty

Unstaged HEAD Rule Shape

The git diff source should be a materialized relation. Its owner key stays stable for a repo and mode, so changing the unstaged file set replaces the relation slice.

rule(:unstaged_head_file, FS?, STATUS?); git.diff(:unstaged) > unstaged_head_file(FS, STATUS); unstaged_head_file?(FS?, STATUS?) > path`${FS}` > read > ast[rs](...) > lsp[warn](message = `unstaged change: ${FS}`);
