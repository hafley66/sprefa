# DfF wire drops node kind, so span-keyed df_edge consumers merge distinct Rust value nodes

## Description

## Summary

`sprefa-extract`'s Rust DfF lift declares df node identity as `(span.start, kind)`
(`v6/sprefa-extract/src/lang/rust.rs:2067`) and pushes every value node with
`len: 0`. The flat wire's edge arm (`v6/sprefa-extract/src/types.rs`
`FlatFact::Edge`) carries only `from` / `to` spans and NO kind, so a consumer
keyed on the span cannot recover the second half of that identity. Distinct
value nodes at one byte offset merge, and the merge manufactures cycles in a
graph that should be a DAG.

TS is unaffected: its df nodes carry real spans.

## Repro

```bash
EB=v6/sprefa-extract/target/release/extract
$EB --family df v6/sprefa-extract/src/dispatch.rs
```

Two spans in that 15-node file carry two kinds each:

| span | kinds |
|---|---|
| `865,865` | `call_res`, `ret` |
| `892,892` | `var_read(src)`, `ret` |

The edge list then contains `(865,865) -> (882,882)` and `(882,882) -> (865,865)`,
a 2-cycle that exists only because `ret` and `call_res` collapsed.

## Measured

Top-level `v6/sprefa-extract/src/*.rs` (18 files), raw JSONL:

| measure | value |
|---|--:|
| df node facts | 5999 |
| zero-width spans | 5999 / 5999 = 100% |
| distinct spans | 5032 |
| facts aliasing a span another node holds | 967 (16.1%) |
| aliases carrying a DIFFERENT kind | 878 |
| non-trivial files whose df_edge graph is cyclic | 11 / 11 |
| value nodes inside a cycle | 30-75% per file |

Whole-corpus figures and the per-file table are in `docs/extract-dataflow.md`,
generated by `v6/dl/dataflow/report_extract.dl6` through the linked
`SprefaExtractExecutor`: 21830 df node rows over 33 files, 2144 aliased spans,
2548 self-reaching value nodes over 89463 reachable pairs.

## Why it bites

`v6/dl/fixtures/flagship-flow.dl6` states "node identity is its file plus span",
which is the same assumption from the consumer side. Any span-keyed reachability
over `df_edge` therefore over-approximates: the closure merges chains the
extractor's own node vec keeps apart, and a depth ladder over the edges does not
terminate without an artificial cap.

## Fail-pre-fix test

A conformance or snapshot case over `src/dispatch.rs` asserting that no two
`family=df` `record=node` rows share a `span`, or that the `df_edge` graph of one
Rust file is acyclic. Both fail today.

## Candidate fixes (not decided here)

1. Carry `kind` on `FlatFact::Edge`'s endpoints, so the wire spells the whole
   declared identity.
2. Give Rust df nodes real spans (`len` = the expression's extent) the way the
   TS lift already does.
3. Emit a dense per-file node ordinal on both the node and the edge arms, and let
   span stay presentational.

## Ownership note

Filed by the `report_extract.dl6` consumer arc, which owns `v6/dl/**`,
`docs/extract-dataflow.md` and its wrapper only. No extractor or wire source was
touched; the rail degrades around the defect and names it in section 5 of the
generated report.

The df fix direction (real extents on Rust df nodes, mirroring ts.rs) is confirmed.
