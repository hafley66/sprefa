## What each file is

| file | role |
|---|---|
| `expand.pl` | the lab-local expander for M1 `scan`, M2 `seq`, M3 `~>` (the stand-in glyph for `\|>`). Term in, term out. Touches no compiler, oracle, registry or parser file. |
| `emit.pl` | reads a sugar term file, expands it, renders `.dl6` with the SHIPPED printer (`compile/print_dl.pl`). Also `show_refusal/1` and `counts/1`. |
| `sugar/*.sugar.pl` | the WITH-MOVES spelling of a corpus program, as a prolog term, with its `.dl6` spelling and its rx lowering in the header comment. |
| `today/*.dl6` | the SAME program written by hand in the shipped surface, independently (different variable names, different arm order, literal seeds), plus its schedule. This is what the expansion is graded against. |
| `out/*.dl6` | generated by `emit.pl`. Not hand-edited. |
| `break/*` | the break rules: a sugar file that must earn a named refusal, plus the skipped-refusal expansion and the program it claims to be sugar for, so the divergence is a receipt and not an assertion. |
| `probe/*` | one-question measurements: can a `__` rel name parse, is `\|>` claimed, does `not(pre(head))` differ from `not(head)`, what does pairwise do with an idle tick. |
| `receipts.sh` | the runnable grade, seven legs. Exit 0 means every receipt held. |
| `run.sh`, `check.sh`, `checkall.sh`, `refusals.sh` | authoring helpers, not receipts. |

## The one thing to read first

`expand.pl`'s module header. It states the expansion order (pipe → seq → scan)
and why it is forced, which is the same fact as the Q5 minimality answer: `seq`
emits a cursor rule whose head carries a `scan`, so `seq` is `scan` plus a
minted rel plus two read arms.
