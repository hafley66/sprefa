0.5 · two clocks — the tick vs the fixpoint rounds underneath

Every marble on this page shows only what crosses the tick boundary. Underneath, each tick drives the semi-naive fixpoint to quiescence: an inner loop the outside world never sees. Two nested clocks — outer tick = EDB commit (a macrotask, the C++/libuv world); inner round = one semi-naive iteration (a microtask, run-to-completion).

Round n = map(state, n) indexed by the fixpoint iteration; the recurrence is IDB(n+1) = IDB(n) ∪ F(Δ(n)) until Δ = ∅. Only the net crosses the boundary, so the clean per-tick marble is the drain's result, never its rounds.

4 · the fight-back — ?/! are presets, not primitives

The marble lanes show the sigils are property bundles. Every property collapses onto one axis: read (query / coeffect) vs write (command / effect). The bundle is derived, so the sigil should be shorthand for a type-level effect classification, and the { } arms are an algebraic-effect handler matching a Notification<A> sum type.

Proposal shape (theory, not to build): both desugar to effect<Mode, Card> where Mode ∈ {read, write} and Card ∈ {0, 0..1, 0..N}; flatten / reversibility / replay are functions of Mode, so illegal combinations (switchMap over write, retry over write) are type errors. Prior art: algebraic effects & handlers (Plotkin–Pretnar, Koka/Eff), quantitative / linear multiplicity for Card, comonad vs monad for read vs write, CQRS for the command/query split. rxjs core = pattern matching over the Notification ADT (materialize) with carried state (scan); the { } block IS that match.
