# V6 daemon — one process, every protocol, library-first

## Context

V5's daemon is already close: one axum router on UDS + ephemeral TCP
(`src/daemon/shell/http.rs:63-72,117-139`, commit `dc774375`), singleton with
flock (`src/daemon/mod.rs:432-447`), idle self-reap
(`src/daemon/shell/timers.rs:15-40`), and the OS perf-budget stack
(`src/daemon/budget.rs:43-169` — nice/QoS/IOPOL with the launchd-label gate).

What's wrong is everything *around* it:

- **LSP is a separate stdio process** with its own in-proc engine
  (`src/lsp.rs:51,130`) and locally mirrored RPCs (`lsp.rs:532,547,591`).
- **MCP is a separate stdio process** over hand-rolled NDJSON
  (`src/channel.rs:29-70`), every tool call written twice via
  `Pump::Daemon`/`Pump::Local` (`src/mcp.rs:71-180`).
- **Ad-hoc runs force in-proc** (`DL_NO_DAEMON=1`, `src/cli/mod.rs:394-397`).
- Every client call builds a private tokio runtime
  (`src/daemon_client.rs:32-58`).
- Three JSON-RPC dialects, two hand-rolled framings; the retired
  Content-Length codec still ships (`src/rpc.rs:22-78`).
- Build-mismatch restart exists twice (`client.rs:91-111`,
  `budget.rs:187-212`).

## Prior art (what serious projects do)

| project | what we copy |
|---|---|
| **biome** | versioned socket filename (`biome-socket-<ver>`); `lsp-proxy` stdio shim; tower-lsp over UDS |
| **atuin** | one binary, daemon+client crates; UDS daemon; `$XDG_RUNTIME_DIR` socket |
| **reth** | many transports, one process — and the cautionary tale: jsonrpsee has no UDS listener, they hand-roll with `interprocess` |
| **watchman** | `get-sockname` — prints the socket path, spawns on demand |
| **docker rootless** | `$XDG_RUNTIME_DIR/<name>.sock` as the discovery convention |

Sources and crate details live in the research notes below.

## Decisions

**One process, one tokio runtime, three endpoints.** The top-level assembly
(N listeners, `Arc` state, ~50 lines) is the one thing no library sells —
biome, atuin, and reth all wire it by hand too. Everything *inside* is a crate:

- **JSON-RPC/query API:** axum, UDS primary + ephemeral TCP (V5's shape;
  axum 0.8's `Listener` trait makes UDS first-class).
- **MCP:** official `rmcp` SDK, `StreamableHttpService` mounted on the same
  router at `/mcp`. Kills the hand-rolled NDJSON channel and the `Pump` enum.
- **LSP:** tower-lsp `LspService` per accepted UDS connection (its transport
  takes any `AsyncRead + AsyncWrite`). Editors keep spawning stdio via a tiny
  **`dl lsp-proxy`** shim — the biome pattern. Kills the in-proc LSP engine
  and the mirrored RPCs.
- **Anonymous servers** for one-shot runs (singleton math in the crate-map
  plan). `DL_NO_DAEMON` and every in-proc fallback are deleted.

**Subscriptions are first-class RPCs.** `subscribe` / `unsubscribe` join the
method surface; standing subscriptions push diffs over the existing SSE
`/watch` channel. One-shot queries are subscribe + `take(1)` internally —
no second code path. LSP sessions hold subscriptions for open documents;
MCP tool calls hold them for the call duration. What subscriptions *mean*
(cold-by-default evaluation, dependency cones) is the demand plan.

Rejected:

- **jsonrpsee** — no UDS transport; reth hand-rolls ~200 lines for it, and
  axum already does JSON-RPC-over-POST fine.
- **tonic/gRPC** — a proto toolchain for zero external clients.
- **Per-editor stdio LSP processes** — that is V5's duplication.
- **`daemonize`, pidfile liveness** — connect-probe is liveness; nobody
  double-forks anymore.

**Keep from V5, unchanged:** the `budget.rs` OS perf stack (nice/QoS/IOPOL,
launchd-label gate), `service_manager` supervision, apalis job queue (pending
the jobq decision in the crate-map plan).

**Observability: one stack, `tracing`.** Facade in every crate; init exactly
once (a module in `sprefa-server`): `EnvFilter` + stderr fmt +
`tracing-appender` rolling files (guard held for process life — the classic
silent-log-drop gotcha). V5's file trails (`events.jsonl`, `why.jsonl`,
`invocations.db`, access log) become subscriber layers and stay file-based,
so they answer while the daemon is wedged. Rejected: the `log` crate
(already tracing), journald (mac-first tool).

## Verification

- **One-socket e2e:** RPC call, MCP `list_tools`, and LSP `initialize` all
  answered by the same process on the same socket.
- **No in-proc engines:** `sprefa-cli` has no `sprefa-engine` dependency
  (dep rail); `dl run` trace shows client → anonymous-server only.
- **Self-heal test:** an old build's daemon on the old versioned socket is
  ignored; client spawns its own version.
- **LSP concurrency:** two LSP sessions over UDS, one engine per root.
- **Subscription lifecycle:** LSP didOpen creates a subscription and its cone
  starts ticking; didClose drops it and the cone goes cold (demand plan's
  tests).
- **Telemetry:** init-once test; file layer written during `daemon serve`;
  guard flushed before exit.

## Research notes

- axum UDS listener: axum 0.8 `Listener` trait, official
  `unix-domain-socket` example (tokio-rs/axum#3172).
- tower-lsp: community-maintained as `tower-lsp-server`; biome runs LSP over
  UDS in production with it.
- rmcp: github.com/modelcontextprotocol/rust-sdk; streamable-HTTP is the
  current spec transport; mounts as a tower service into any axum router.
- biome daemon: versioned UDS + `lsp-proxy` (biomejs/biome#3965).
- atuin daemon: tonic-over-UDS, `$XDG_RUNTIME_DIR/atuin.sock`
  (docs.atuin.sh/cli/reference/daemon).
- reth IPC: jsonrpsee lacks UDS; accept loop hand-rolled via `interprocess`
  (paritytech/jsonrpsee#5).
- watchman `get-sockname`: facebook.github.io/watchman/docs/cli-options.
