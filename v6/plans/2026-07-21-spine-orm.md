# V6 spine — the 6 tables, one ORM, hard boundaries

Owner-dictated schema (2026-07-21). This file records it; it does not invent
it. The six tables and their columns are law. Names are the owner's.

## The six tables (the entire identity + coordinate spine)

Nothing else is added to the spine. Fact/graph families (nodes, edges, rels)
reference these by integer FK and add no repo/rev/path/coordinate columns of
their own.

```
repos        one row per configured repo
repo_revs    a rev, OWNED BY a repo (repo determines rev; a rev without a repo
             is meaningless). repo_id is not optional and not denormalized-away.
files        content, addressed once by content hash. A file IS its content.
revs_files   the junction: one content (file_id) appears at many (rev, path)
             places. This is where path lives.
strings      the interned dictionary. Dense ids. Vocabulary + paths.
file_bytes   a byte span into physical file content (was `where_bytes`):
             (file_id, string_id?, start, end). string_id optional.
```

Ownership / reference chain:

```
repos ──1:N──> repo_revs ──1:N──> revs_files ──N:1──> files ──1:N──> file_bytes
                                                  ^                        |
                                          content-addressed         span into content
```

`revs_files.file_id` and `file_bytes.file_id` both point at `files` (content),
never at a location. A byte span shared across places is stored once, because
it is a region of content, not of a place.

## Storage layout (columns, keys, uniqueness)

```sql
CREATE TABLE repos (
  repo_id  INTEGER PRIMARY KEY,          -- dense, u16 range in practice
  slug     TEXT NOT NULL UNIQUE,
  root     TEXT NOT NULL DEFAULT '',
  url      TEXT NOT NULL DEFAULT ''
);

CREATE TABLE repo_revs (
  rev_id   INTEGER PRIMARY KEY,          -- dense
  repo_id  INTEGER NOT NULL,             -- -> repos.repo_id. NOT NULL. owner.
  git_sha  BLOB NOT NULL,                -- 20 raw bytes, never 40 hex chars
  UNIQUE (repo_id, git_sha)              -- same sha in two repos = two revs
);

CREATE TABLE files (
  file_id       INTEGER PRIMARY KEY,     -- dense
  content_hash  BLOB NOT NULL UNIQUE,    -- 16 raw bytes (blake3 truncated)
  size          INTEGER NOT NULL DEFAULT 0,
  lines         INTEGER NOT NULL DEFAULT -1
);

CREATE TABLE revs_files (
  rev_id          INTEGER NOT NULL,      -- -> repo_revs.rev_id
  path_string_id  INTEGER NOT NULL,      -- -> strings.string_id (the path)
  file_id         INTEGER NOT NULL,      -- -> files.file_id (the content)
  PRIMARY KEY (rev_id, path_string_id)
) WITHOUT ROWID;
CREATE INDEX revs_files_by_file ON revs_files(file_id);

CREATE TABLE strings (
  string_id  INTEGER PRIMARY KEY,        -- DENSE. assigned sequentially.
  content    TEXT NOT NULL UNIQUE
);

CREATE TABLE file_bytes (
  file_id    INTEGER NOT NULL,           -- -> files.file_id (content, not place)
  string_id  INTEGER,                    -- -> strings.string_id, OPTIONAL (NULL ok)
  start      INTEGER NOT NULL,
  end        INTEGER NOT NULL,
  PRIMARY KEY (file_id, start, end)
) WITHOUT ROWID;
```

Laws satisfied:
- **Integer surrogate FKs only.** Every reference is a dense integer id.
- **A string lives in exactly one row.** `strings.content` UNIQUE; paths,
  vocabulary, span text all intern here. Nothing repeats a string on a fact.
- **No denormalized twin.** `repo_revs` carries `repo_id`, never `repo` text
  beside it. `revs_files` carries `file_id`, never a content-hash beside it.
  `file_bytes` carries `file_id`, never repo/rev/path beside it (the v5
  `_where_bytes` pollution — `repo TEXT, rev TEXT, path TEXT` — is deleted).
- **No all-columns PK.** Junctions are `WITHOUT ROWID` composites; entities
  have a single surrogate PK that IS the rowid. Zero duplicate-copy indexes.
- **rev owned by repo.** `repo_revs.repo_id NOT NULL`, `UNIQUE(repo_id,
  git_sha)`. There is no repo-less rev.

## ORM decision (owner picks; SeaORM is the recommended default)

The owner directive: a pure storage repo built on an ORM, with specific
boundaries — no hand-rolled SQL leaking into the engine.

Candidate analysis (build-vs-buy, per standing law):

| ORM | model | async | SQLite | verdict |
|---|---|---|---|---|
| **SeaORM 1.x** | Entity + ActiveModel, `Related` relations, sea-orm-migration | native async | yes, dialect = config | **recommended.** Built on sea-query (v6 rule 3 already committed to it). ActiveModel is a clean single write boundary. Backend swap is free. Cost: ActiveModel boilerplate, async throughout. |
| Diesel 2.x | `table!` compile-time schema.rs | sync | best-in-class perf | runner-up. Compile-time-checked, fastest. Cost: sync under a tokio/axum daemon needs `deadpool` + `spawn_blocking`; dynamic queries are harder. |
| sqlx | query builder, compile-checked raw SQL | async | yes | rejected: not an ORM, no entity/relation mapping — fails the ask. |
| ormlite / welds | derive-on-sqlx / newer async ORM | async | yes | rejected for now: smaller ecosystem, maturity risk for the one crate all persistence lives in. |

Recommendation: **SeaORM.** Reasons: (1) async matches the fully-async server
ruling; (2) it sits on sea-query, which v6 rule 3 already mandates, so the
fixpoint codegen and the ORM share one SQL builder and one dialect config;
(3) ActiveModel gives exactly the write-side boundary the owner is asking for.
Diesel is the reasoned alternative if sync + compile-time schema + max perf
outweigh the async-fit friction. **Owner rules before any entity is written.**

## Crate boundary

`sprefa-store` owns all six tables and is the only crate that speaks the ORM
or SQL. Public API speaks rels/rows/ids, never a SeaORM type, never SQL text.

```rust
// entity modules (SeaORM DeriveEntityModel), one per table, generated once:
//   repos::Model, repo_revs::Model, files::Model,
//   revs_files::Model, strings::Model, file_bytes::Model

pub struct Store { /* one writer conn (async), dialect chosen at open() */ }

impl Store {
    pub async fn open(cfg: BackendConfig) -> Result<Store>;

    // repo / rev identity
    pub async fn repo_upsert(&self, slug: &str, root: &str, url: &str) -> Result<RepoId>;
    pub async fn rev_upsert(&self, repo: RepoId, git_sha: [u8;20]) -> Result<RevId>;

    // content-addressed files + the (rev, path) -> content junction
    pub async fn file_upsert(&self, content_hash: [u8;16], size: u64, lines: i64) -> Result<FileId>;
    pub async fn place_file(&self, rev: RevId, path: StringId, file: FileId) -> Result<()>;

    // the dictionary (dense ids, batch-interned — never per-row)
    pub async fn intern_batch(&self, contents: &[&str]) -> Result<Vec<StringId>>;

    // spans into content
    pub async fn put_bytes(&self, rows: &[FileByteRow]) -> Result<()>; // batch, N+1 banned
}
```

Rails on the boundary (greppable, per v6 style):
- no `sea_orm::` / `sea_query::` / raw SQL string outside `sprefa-store/src/**`
- no per-row insert: writes take slices, one statement (the N+1 law)
- orphan-ref check per `_id` column (replaces declared FK enforcement)
- dense-id gate: `MAX(string_id)` within 1.05x of `COUNT(*)`
- no denormalized twin: schema-introspection rail asserting no table carries
  both an `_id` FK and a text column naming the same dimension

## Read/write sequence (one tick, one file changed)

```
write:
  1. hash content -> files: SELECT by content_hash; INSERT if absent -> file_id
  2. revs_files: UPSERT (rev_id, path_string_id) -> file_id
  3. if file_id unchanged for this (rev, path): STOP  (nothing re-derives)
  4. intern_batch the vocabulary + path names ONLY
  5. file_bytes: batch put spans for the new content
  (fact families then reference file_id / rev_id / string_id, add no columns)

read (a value needing text):
  file_bytes row -> (file_id, start, end) -> files content -> slice
  line/col       -> derived from byte offset via lazy line index, never stored
```

## Uniqueness conditions

| table | uniqueness | why |
|---|---|---|
| `repos` | `slug` | one row per configured repo |
| `repo_revs` | `(repo_id, git_sha)` | a rev is per-repo; same sha in two repos = two revs |
| `files` | `content_hash` | identical bytes anywhere = ONE row |
| `revs_files` | `(rev_id, path_string_id)` | one content per path per rev |
| `strings` | `content` | the dictionary invariant |
| `file_bytes` | `(file_id, start, end)` | a span is a region of content |

## Instance lifetimes

| type | lifetime | owner |
|---|---|---|
| `Store` | process | the writer task |
| string id cache `HashMap<String,u32>` | process, bounded LRU | `Store` |
| line index per `file_id` | per query burst, LRU-capped | `Store` reader |

## Decision log

- **ORM = SeaORM** (owner, 2026-07-21). Async fit, sits on sea-query per v6
  rule 3, ActiveModel is the single write boundary, backend = config at open().
  Diesel considered and set aside (sync friction under the async daemon).

## Open decisions (owner)

- `file_bytes.string_id` optional: keep the interned text of a span, or always
  recompute from `(file_id, start, end)`? Optional column allows both.
- `repo_revs`: keep `observed_at` / topological `seq`, or add later on demand.
