## The audit protocol, run every check on every target

### 1. Sabotage every grader

For each test or grader in the targets, introduce ONE deliberate defect in the
code under test, rebuild, and confirm the grader goes red AND exits nonzero.
Restore. Record a table: grader, what you broke, cells that went red, exit code.

A grader that stays green under sabotage is the headline finding of this lane.

Known already, re-verify rather than trust: breaking `graphClosure` to be
reflexive turns 12 of 110 cells red and exits 1. `demand/probes` prints FAIL but
exits 0.

### 2. Find self-certifying assertions

Grep every probe and test for strings that print PASS unconditionally, assertions
that compare a value to itself, and tests whose expected value is computed by the
same code path being tested. `demand/probes/src/Probe/Sugar.hs:21` is one known
example; find the rest.

For each, say whether the check has ANY teeth and what it would take to give it
teeth.

### 3. Check the oracles are independent

`graph/fixtures/Golden.hs` claims to hold SWI ground truth. Verify a sample
directly: run `v6/prolog/0_graph.pl` under swipl for at least four shapes,
including `cycle_with_tail` and `flagship_shaped`, and compare to the Golden
values. An oracle that was generated by the code it grades is worthless, so state
plainly which oracles you confirmed independent and which you could not.

### 4. Hunt accidental complexity

Look for quadratic or worse behavior hiding behind innocent-looking code. `nub`
is O(n^2) and appears in `graph/src/Graph.hs`; the coordinator measured graph
construction at 757 ms for 16,000 nodes against 13 ms for the actual algorithm.
Find every other instance of this class across all targets: `nub`, `union`,
`\\`, repeated `elem` over a list inside a loop, `lookup` on an association list
in a hot path, list concatenation in an accumulator.

For each, say whether it is on a hot path and what the fix is (usually
`Data.Set`). Measure at two sizes to prove the shape before calling something
quadratic.

### 5. Inappropriate couplings

Look for modules reaching across seams they should not:

- Does anything in `demand/` or `idioms/` depend on `graph/`, or vice versa? They
  were built by separate lanes and should share nothing.
- Does any probe reach outside its own package to read repo files, invoke swipl,
  or shell out, in a way that makes it non-hermetic? Note every process spawn and
  file read outside the package.
- Does the `idioms/starter` actually use the libraries its own report recommends,
  or does it import something else and describe the recommendation only in prose?
- Does anything import a module purely to make a claim look supported?

### 6. Claim-to-code drift

Each target has a REPORT.md written by its lane. For each, pick the three most
load-bearing factual claims and verify them against the code and by running it.
`idioms/REPORT.md` cites `file:line` in cloned repos under `/tmp/hs-refs/`; if
those clones still exist, open at least four citations at the cited line and say
whether they are exact. If the clones are gone, say so rather than guessing.
